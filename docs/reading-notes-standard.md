# RN-001：读书笔记共同标准

版本 v1.7，代码折叠约定更新于 2026-10-21；初版生效日期 2026-10-14。本文件是 Reading Notes 跨书伴读方法的权威来源，由 Durrett、Weiss、CS:APP 的现有实践提炼。目标是让读者跟着原书理解问题、推演机制、完成习题，并能复现有计算价值的例子。

新增书籍和后续修订先遵循本标准，再读取该书 `agent.md`、`notes/README.md`。书级文件补充版本、模型、范围和具体实现约定；现有更细的要求继续生效。三本书的页数、题数、摘录数量和某次检查结果属于各书事实，不是新书的指标。涉及调整既有范围或降低既定标准时，先在问题单说明理由及影响，再按任务授权处理。

操作顺序见[新书接入](adding-a-book.md)，待填文件见[模板说明](templates/reading-notes/README.md)。公式与算法本身由正式正文及[规则职责索引](rules/README.md)指向的书级文件维护；这里规定讲解和验证方法。

## 1. 先确定原书，再建立全书地图

先确认书名、作者、版次、改编版/国际版、出版信息以及实际使用的资料。PDF 记录仓库相对路径、SHA-256、总页数、印刷页与 PDF 页序的对应关系；缺页、扫描/OCR 问题和前言罗马页码单独登记。页序可能分段变化，不能默认一个固定偏移。其他来源记录可定位的章节/页面、版本和访问日期。完整原书能否随站点发布单独确认。

先从原书枚举目录、编号定义/定理/原理、示例和习题，形成覆盖清单，再写正文。完成数量从这份清单核对，不能用生成页面中的数量反推“原书全部”。网络资料和其他版次仅作标明来源的补充；摘录与公式回看实际原页，文本提取用于定位。

先通览目录、序言、各章开头与结尾，说明全书要解决什么问题、章节如何递进、依赖什么基础、哪些内容适合先读或回读。依赖图标明是笔记作者的归纳。只有实际逐页阅读过的范围才能记为通读；资料不完整时明确缺口。

`notes/book_overview.html` 是全书入口，包括阅读主线、章节关系和当前完成范围，集中提供环境与程序说明。序言按原书讨论的目标、受众和组织方式释读。章节沿原书层级与顺序展开，保留原编号和可追溯位置。可以分批交付，全书地图说明原书范围和当前可阅读内容；逐层完成状态由维护记录保存。

有编号定义、定理或原理的书，在全书或章内提供可跳转索引，正式陈述仍放在对应正文。程序、图表和共享基础材料按阅读需要建立入口，让读者能从使用位置回到定义、实现和来源。

## 2. 围绕问题展开讲解

每个纳入范围的小节都要有实质解释。叙述沿“遇到什么问题 → 为什么采用这个办法 → 中间如何运作 → 得到什么结果 → 条件与局限”展开，用连续中文把因果讲通。这是写作检查线索，不要求把五个短语机械地做成每节标题。

关键机制使用一个能够算完或走完的小例子：列出输入、初始状态、关键步骤、结果和验算。图、表、公式与程序尽量围绕这个例子互相对应。例如解释链表删除，应让读者看见节点关系、指针更新顺序、释放对象以及查找前驱是否计入成本；只有结果图或一句复杂度结论不能完成机制解释。

定义和定理先给完整条件与结论，再解释符号、关键推导及适用边界。计算题展示从条件到方程、代入和结果检查；证明交代关键引理和使用前提，尤其是收敛、可积性、极限交换等必要条件。使用外部结果时给来源，解释它承担哪一步；引理详证可以通过明确链接延后阅读。推导的长度由理解所需决定。

重要原理和有辨识度的论述保留必要的短原文及原书位置，区分原文、中文译义和作者解释。摘录集中登记页面、锚点、来源页及实际摘录范围；组合片段注明省略与范围。以原创分析为主体，引用多少由解释需要与资料使用条件决定。

发现疑似错误，重新核对原页和上下文，保留“原书说法、修正结论、推导依据”。不确定的内容登记为待核实，不能通过换一道题、删掉条件或重写历史审阅来消除矛盾。数学模型、语言标准、平台接口、模拟器及宿主实测分别标明。

## 3. 习题先保全题目，再完成解答

默认覆盖本次交付章节的全部原书习题；如果用户指定选题范围，先在阅读计划和覆盖清单写清。原书题与原创自测分开计数、分开标识。题号沿本版顺序排列，保留全部小问、条件、公式、输入、提示及所需图表和代码；每题列原书题号、印刷页与 PDF 页序。

使用 `details.exercise`，展开后先是 `div.exercise-question`，再是 `div.answer`；原题材料与教学实现有明确标记。题干校注单列，标题可以用于定位，但不能代替完整题干。保留稳定锚点，依赖的共享输入链接到确切位置。

解答给出确定答案、可跟随的推导或可执行方法，并逐项回应小问。证明题写清假设和关键步骤，编程题给算法、实现、边界与复杂度，实验题给复现方法和实际结果。只给解题方向、定理名称、伪造运行结果或“类似可得”而略过关键步骤，均不能标为完成。

## 4. 程序和图表服务于理解

接入时选定代码的唯一维护源，并在 `books/catalog.json` 登记：新书默认使用 `standalone_sources`，在 `code/` 维护并同步 HTML 阅读副本；使用 `html_code_blocks` 时，正式 HTML 就是维护源，测试从最终页面提取。两种方式都须核对读者所见与实际执行的代码一致，提取件只放忽略目录。

可比较的算法与数值例子默认提供 C11/Python 3，算法、输入、平局规则、失败语义和复杂度前提相对应。代码旁解释数据结构、状态、不变量、关键分支和结果；共享定义只维护一次并精确链接。给出完整运行入口、必要依赖、输入输出及下载或提取方式。纯证明和不需要计算的段落按学科特点表达；平台代码或其他语言的使用在书级计划说明，涉及技术栈变化再走治理联动。

C 的整数、内存与平台边界，Python 的整数、容量与异常行为须显式说明。算法操作及必要自测独立执行，不能只藏在断言表达式中。编译通过后仍要实际运行，并用解析值、小规模穷举、独立参考或不变量验证正常、边界和失败情形；两版相同输出也可能来自同一错误。C 指针/内存操作配合 ASan/UBSan，具体命令和平台范围由书级检查器记录。

实验保留实际输入、规模、随机种子、重复次数、计时范围、单位与环境；数值近似写清精度和误差。图表从可核对的数据产生，保留数据表和来源链接，写明轴、单位、图例及缺失值。理论预测、原书历史测量、本机实测和模拟结果分别注明。有限样本不能扩展成一般证明。

## 5. 沿用已有阅读结构

正式交付为全书地图、序言及逐章独立 HTML；正文只维护一份。登记书籍在 `src/content/books/` 维护受控 HTML，旧章节路径为检查镜像，维护和同步见 [Astro 说明](astro-authoring.md)；静态成品仍为单文件。CSS、导航 JS、静态 MathML、SVG 和代码阅读副本内嵌，使用相对资源路径和系统字体，使正文离线可读。复用现有页面组件，避免外部运行时成为阅读前提。

新书默认沿用纸色 `#fffefa`、强调绿 `#285a4e`、17px 正文、1.9 行高、最大 860px 正文主栏和 240px 左目录。1100px 以下采用原生折叠目录；1440px 起统一预留 280px 右栏，正文按剩余空间收缩。阅读注解在宽屏使用该栏，较窄页面回到对应小节；没有注解或关闭脚本时仍保持同一版心。书级文档记录选用的实际样式来源。既有书籍的封面/页头、章节拓扑、文件名、锚点和阅读结构按原约定保持。

四类教学组件共用 `src/styles/reading-components.css`，每个受控页面通过 `RN:include` 内联一次并在 body 标记 `rn-components`。正式陈述用 `rn-statement`，保持可见，标题、浅底和左边线统一；独立例题用 `rn-example`，正文默认可见，以轻分隔线区分。证明使用 `details.rn-proof[open]`，首项 summary，正文放 `rn-proof-body`，默认展开，可原生折叠。习题继续使用 `details.exercise`，默认收起，题干与答案分别在 `exercise-question`、`answer`，标签保留各书准确用语并共用字号、颜色和间距，答案前显示细分隔线。来源统一为辅助文字；原来的题号、图、代码、条件和锚点按顺序保留。

陈述标题后统一使用 `div.statement-body`；标题层级由所在小节决定。题干与答案首项使用 `p.rn-exercise-label`，已有 `question-title`、`answer-title` 可保留为定位类；标签不增加章节标题层级，题解内部的实质分段仍可使用小标题。每章原书习题达到 20 题时，在习题区开头提供顺序题号索引；索引逐题链接到稳定锚点，并有明确的导航及“习题 章.题”可访问名称。原创自测保留单独标识。代码折叠标题和例题分类说明使用共同的辅助字号、颜色与键盘焦点样式。

表格使用与数据方向相符的 `th[scope]`。已有 caption 保留；图注、习题摘要或小节标题能准确说明表格上下文时，使用 `aria-labelledby` 关联该文字，不重复添加同义标题。原书在节内重新编号的例子保留原编号，全书索引补齐章、节限定。证明摘要在单独跳转后仍应能辨认对应陈述；跨两条陈述的说明明确列出两者。

标题检查覆盖全部书籍。每道题的题干与答案独立继承所在小节的标题级别；前一道题的内部标题不能作为后一道题的父级。同级分段采用同级标题，嵌套推演保留下一级，视觉字号由共同样式控制。正文引用习题时，链接文字明确写“习题”及题号，包括跨章引用和题号范围；紧凑索引可继续显示题号，并提供完整可访问名称。表格名称应说明题目、小问与数据用途，单独的“(a)”不能标识一张表。例子的原书编号覆盖、未编号来源实例与伴读补充实例分别说明；书级采用分类行时，该书每个独立例子都应标明准确类型。

普通叙述中的短例子、定义解释及证明路线不因出现关键词而自动套框；独立论证与例题须按明确的段落边界标记。跨书组件清单见 [组件清单](reading-components-inventory.json)，检查器同时覆盖原书编号类与已标记的补充块。证明依赖外部引理时写清引理、使用条件及具体承担的步骤；仅有证明路线时保留“路线”标签与完整解答入口。

阅读页面的文字围绕学科内容、原书来源、阅读路径和程序使用组织。章节表列出主题、页码和习题数量，内容范围用具体章节及入口说明；维护进度、检查结论、修订批次与审阅记录入口放在维护文档。实验保留输入、环境、实际结果和适用边界，明确区分模型推演、程序执行与浏览器观察；验证过程的工作总结不进入教学叙述。

阅读注解补充模型理解、条件解释、额外推导或验算；正文中的关键论证和完整解答仍留在原位置。注解与对应小节绑定，展开控件服务于分层阅读。

公式使用静态 MathML，图用可读 SVG 或语义表格；代码、宽表、长公式只在各自容器滚动，窄屏整页不能横向溢出。图与图注、代码与解释相邻。目录标记当前节，页头和页尾有全书地图及已有相邻章入口，发布页另能返回书架。深链接要展开目标祖先 `details`；关闭 JavaScript 仍可读正文与使用原生展开控件。

英文字母与数字统一使用 Times New Roman，覆盖正文、导航、表格、代码阅读副本、普通数学字母数字及 SVG 文字；中文使用系统中文字体。每页最后一个 head 样式块末尾只引入一次 `src/styles/reading-typography.css`，使书级旧字体不再覆盖共同约定。字体取自读者设备；没有 Times New Roman 时按声明回退，不分发专有字体。数学运算符、伸缩定界符及有语义区别的双线体、花体、哥特体保留数学字体支持；不能为视觉一致而把实数集或花体集合改成普通字母。实际字体验收读取浏览器使用的字形字体，不能只看 CSS 声明。

叙述中的变量、下标、幂、映射和关系式与独立公式同样使用静态 MathML；例如环境 E 的下标 3 使用 `msub`，映射用 `mo`。可保留 TeX 来源或等价的可访问标签。复合底数必须整体放入 `mrow` 后再加上下标，不能只把幂挂到右括号；`msub`、`msup`、`msubsup` 的参数数目应合法。程序标识符、路径、文件名、题号与来源页码按其真实用途保留，程序文本和缩进不能被数学转换改写。SVG 文字的上下标使用定位的 `tspan`，并提供完整图注和可访问名称。

流程图和概念图采用浅蓝节点、浅琥珀强调节点、细灰连线与统一圆角，节点内文字和边缘保持充分间距。箭头、虚实线和色彩承担的含义在图注说明；共享样式只作用于明确标记的节点与连接边。坐标图的数据系列、群生成元颜色、图例、数值与拓扑关系保留。节点布局改变后检查文字边界、连线终点与交叉，桌面和窄屏分别读图；宽图在图内横滚，避免为了挤入屏幕而缩成无法阅读的小字。

正文中的程序关键字、调用、赋值和指令使用完整的行内 `code`。函数名和实参、汇编指令和操作数放在同一个代码元素内；语言语法不与数学排版片段交错。行内代码采用浅灰蓝底、细边线、少量留白，继续使用 Times New Roman；短表达式保持整体，长语句在正文宽度内换行。完整程序仍放在 `pre`，缩进和字符保持逐字可执行的阅读副本。

完整程序的阅读副本使用原生 `details.code-details`，语言代码对沿用 `details.code-version`。第一个元素为有明确语言或用途名称的 `summary`，程序放在摘要之后；点击、键盘和无脚本环境均可展开、收起。独立完整程序默认收起，既有双语实现遵循书级默认状态。至少 12 行的讲解代码或命令片段同样提供独立控件，默认展开以衔接正文。原题输入代码随完整题干显示；短片段保持就地阅读；明确的运行结果可置于 `div.program-output`，与程序区分。代码折叠不更改原代码字节、锚点、下载与深链；验收需实际开合代码控件，习题折叠测试不能代替代码折叠测试。

图中节点先依据标签长度、行数与角色决定大小。同类流程节点采用接近的高度和留白；长元组节点应扩大到能容纳完整标签，单字节点无需套用长说明卡片的宽度。数组格子、字段宽度、柱形面积等数据编码按图意保留。节点边界修改时同步连接端点，实际测量文字内边距，并读回箭头和分支含义；静态尺寸检查不能替代目视读图。

先制作全书地图和一章具有代表性的完整样章，实际检查叙述、题解、代码、图表及阅读效果，再扩展后续章节。较厚的书按部分或章节批次推进，每批同步地图和覆盖清单，避免到最后才发现共同版式或讲解方式不合适。

## 6. 分层验收，按实际证据标记完成

| 层次 | 必须回答的问题 | 留存依据 |
|---|---|---|
| 来源与内容 | 是否为同一版？条件、原式、题干和推导是否完整正确？ | 原书清单、逐项读回、校注和未闭合问题 |
| 静态结构 | 链接、题号、锚点、公式结构、代码同步及来源绑定是否一致？ | 检查器命令、退出码、报告 |
| 程序与计算 | 程序是否实际执行？独立基准、正常/边界/失败情形是否符合说明？ | 平台、输入、编译选项、输出、回归结果 |
| 阅读体验 | 读者能否看清、跟上推导并走通阅读路径？ | 最终页面版本、浏览器、视口、实际操作、看过的截图及发现 |
| 本地集成 | 正式包中的页面、资源、来源转换和导航是否一致？ | release ID、清单、哈希、包检查及本地预览 |
| 线上发布 | 授权发布后，线上是否确实提供该版本并可读？ | 发布/恢复记录、公网响应及实际浏览器路径 |

新书的最终阅读页逐页检查 1800、1440、1024、390px；后续局部修订至少覆盖受影响页面的桌面与 390px，布局或公共组件变更补全相关断点。实际阅读正文、推导、长公式、图表、展开题解与代码，操作目录、深链接、章间跳转、返回书架及下载。无 JS 阅读也在样章及相关组件变化时验证。自动几何检查、HTTP 200 和截图生成分别是辅助证据，须打开查看最终渲染；浏览器不可用时记录未验收范围。

每次审阅记录实际对象、原书位置、文件 SHA-256、时间、工具/环境、范围、发现、修复和剩余问题。内容变化后重新读回，再更新当前绑定；历史哈希与历史执行时间保留。复用旧证据时说明未变的对象与哈希，以及这次重新检查的范围。结构、内容、程序和浏览器的结论分别填写，某一层通过不自动覆盖其他层。

本批只有在承诺内容完成、必要问题闭合且上述适用层均有实际证据时才标为 `completed_locally`；不可用能力或待核实结论保持待完成。后续章节继续列在地图中。本地完成、提交推送和线上生效分别记录，外部写入依据用户的实际授权执行。

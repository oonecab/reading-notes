# RN-002：阅读呈现、导航与检查规范

版本 v1.0.1，2026-10-22。本规范是 Reading Notes **六书阅读页面的呈现、导航与检查方法**的权威来源。它补充而不取代 [RN-001 读书笔记共同标准](reading-notes-standard.md)：RN-001 管来源、讲解、题解、程序与内容质量；本规范管读者看到的页面骨架、阅读路径、检索入口、题干语言策略，以及“一次检查究竟证明了什么”。

新书接入、既有页面修订和全站复查都先读本规范，再读书级 `agent.md` 与 `notes/README.md`。本规范定义的规则由 `docs/reader-presentation.json` 登记，由 `tools/check-presentation-contract.mjs` 执行。**规则与登记不一致时以本规范为准，先改登记再改检查。**

## 1. 阅读页的页面族

每本书的阅读顺序由 `docs/reader-presentation.json` 的 `books.<id>.pages` 明确登记，不按文件名临时推断。页面族只有四种：

| 族 | 典型文件 | 作用 |
|---|---|---|
| `overview` | `book_overview.html` | 全书入口；说明主线、章节关系、范围与程序入口 |
| `preface` | `preface.html` | 原书序言/导读的伴读 |
| `chapter` | `chapterNN_*.html` | 一章正文与习题 |
| `appendix` | `appendix_*.html` | 附录或补充材料 |

一本书可以没有 `preface` 或 `appendix`；`chapter` 的 `number` 与 `label` 必须在登记中写明。未登记的阅读页不得发布。

## 2. 唯一阅读路径与导航

### 2.1 每一页的“下一步”必须直接可走

读者从任何一页都应能直接走到阅读顺序中的上一页、下一页和全书入口，而不是先回到地图再找入口。

- 每页页头、页脚各有一组 `p.chapter-nav`；源文件里两组链接集合相同（页脚另加 `返回页首 ↑`）。发布时门户阅读栏会在两组导航最前面各加一个统一的 `笔记首页`/`← 笔记首页` 返回入口，这是声明过的壳层元素，不算页面差异；构建检查必须同时验证它在两组中都只出现一次、标签一致。
- 章节/序言/附录的导航顺序固定为：`全书地图` → `← 上一页` → `下一页 →`；页脚末尾为 `返回页首 ↑`。
- `overview` 的导航只放 `开始阅读：序言 →`（无 `preface` 时放 `开始阅读：第 1 章 →`），页脚另加 `返回页首 ↑`。
- `preface` 的下一页必须是 `chapter` 第一页，标签写 `第 N 章 · 标题 →`。
- 最后一页（最后一章或附录）只保留 `全书地图` 与 `← 上一页`，不得用地图锚点冒充“下一章”。
- 未写的后续章节不得出现在 `下一章` 导航中。确有规划时，在正文范围说明或全书地图中写“第 N 章尚在计划中”，不放进导航链接。
- 任何文字为“第 N 章”的链接都必须指向该章的正式 HTML 文件。指向 `book_overview.html#chapter-N` 的链接只能出现在全书地图的章节介绍里，不能出现在 `chapter-nav` 中。
- 标签统一使用：`全书地图`、`← 序言`、`← 第 N 章 · 标题`、`第 N 章 · 标题 →`、`附录 A · 标题`、`返回页首 ↑`。编号统一使用阿拉伯数字与间隔号。

### 2.2 侧栏

- 侧栏标题统一为 `目录`。
- 章内页面先列 `全书地图`、`序言`（存在时），再列本章小节；`本章索引`（若存在）放在所有正文小节之后。
- 侧栏链接必须全部落在本页真实锚点，且顺序与正文阅读顺序一致；不得出现指向地图段落的“章节入口”。

## 3. 章首：先进入正文

`</header>` 与第一个 `<section>` 之间只允许空白、注释，以及**最多一个** `p.chapter-lead` 导语段落。不得放：

- `details`、`ul/ol`、`table`、`nav`、`figure`、标题；
- 任何形式的定义/定理/原书摘录/题号索引；
- 多段“本章将讲……”的说明（这类内容放全书地图或页头 `p.intro`）。

章首页头统一为：书目行（`p.overline`）→ 章标题（`h1`）→ 一句话副题（`p.intro`）→ 来源/范围行（`p.source` 或 `p.small`）→ 导航（`p.chapter-nav`）。导语段落可紧随其后，但不得包含列表或折叠块。

## 4. 检索入口：集中、后置、可预期

- **章首不放定义/定理/原书摘录的长列表。** 读者打开一章应先看到本章讲解，而不是整章索引。
- 一本书需要章内检索时，索引放在**本章正文和习题之后、页脚之前**，标题写明 `本章索引：定义与定理`、`本章索引：原书摘录` 等；对应侧栏链接排在所有小节之后。
- 一本书也可以只在 `overview` 放全书索引；两种方式都可以，但同一本书内必须一致。
- 习题题号索引是习题区的一部分，放在习题区标题之后、第一题之前，默认折叠，标签明确写 `本章习题题号索引`；它不受“章首禁索引”限制。
- 不要求每本书都有索引。**有索引时按上述位置，没有索引不构成缺陷。**
- 禁止为了“看起来统一”给其他书补章首长索引。

## 5. 习题语言与来源

中文伴读的题面以**完整中文题干**为主，英文原文只用于消除歧义，不逐题重复。

- 每题先给完整中文题干（保留小问、条件、公式、输入、提示、图和共同题设），再给解答；默认折叠。
- **禁止**逐题保留完整英文原题（`details.original-question`、整段 `.original-source` 或等价的中英双份）。英文原题不是阅读页的必需内容。
- 需要说明术语或翻译歧义时，可在中文题干内附**短原文摘录**：`blockquote.original-excerpt[lang="en"]`，必须带 `data-excerpt-reason`（说明歧义的词或句），不超过 2 句且不超过 400 字，并给来源页。整题原文、整段程序说明和可独立成题的英文内容都不属于“短摘录”。
- 每题的来源页 PDF 链接仍必须保留；完整英文原题如用于维护核对，保存在 `books/<book>/notes/original_questions.json` 等维护文件，不进入阅读页。
- 中文题干不得只有“见英文”“证明略”或纯公式；无法翻译的代码/标识符保留原样，但任务动词、条件与小问必须用中文说清。

## 6. 统一页面骨架

所有阅读页共用同一套骨架，书级差异只允许出现在 `overview` 的封面/书目区和正文内容中：

- `body.rn-components`；`main#top`；`aside.chapter-sidebar`；页头、页脚、可选注解栏。
- 必须内联共享的 `reading-components.css` 与 `reading-typography.css`；代码字体由共享代码排版样式提供。书级样式只能补充，不能另起一套版心、字体或组件外观。
- 页头、页脚、侧栏、导航使用本文规定的元素与类名；不得引入书级专用导航类来绕过检查。门户阅读栏的 `笔记首页` 是唯一允许在发布时注入 `chapter-nav` 的链接，源文件不重复写它。
- 注解栏是可选能力：有注解的书在宽屏显示、窄屏和无脚本回到小节；没有注解的书保持同一版心，不得因为没有注解而改变正文起点。
- 版心、字号、颜色、行高、表格、图、代码、折叠、MathML 与无障碍要求沿用 RN-001；本规范只决定它们的**位置与阅读顺序**。

## 7. 检查规范

### 7.1 三层检查，分别声明

| 层 | 能证明 | 不能证明 |
|---|---|---|
| 契约检查（静态，全量） | 阅读顺序、导航目标、章首结构、索引位置、题干语言策略、页面骨架与登记一致 | 页面实际渲染、文字内容正确、读者能否理解 |
| 呈现检查（浏览器，抽页+全量断点） | 版心、字号、颜色、组件样式、折叠、深链、每页导航实际可点击 | 内容正确性、所有页面的主观阅读体验 |
| 内容抽查（人工读回） | 抽到的章节/题目讲得清、算得对、来源一致 | 未抽到的题目；不能外推为全书内容通过 |

三层都完成才可写“本轮阅读呈现检查通过”。任何一层缺失，必须在结论中写明缺的是哪层、覆盖哪些页、为什么没做。

### 7.2 命令与证据

```sh
python3 tools/project.py check                 # 含契约检查
node tools/check-presentation-contract.mjs     # 只跑呈现契约，输出 JSON
node tools/check-presentation-contract.mjs --book eopl
node tools/check-presentation-contract.mjs --dist   # 构建产物导航/侧栏
python3 tools/project.py check --book eopl
```

- 契约检查必须覆盖 `docs/reader-presentation.json` 登记的全部页面；某页缺失、跳过或异常都算失败。
- 每次检查记录：命令、退出码、报告路径、对象版本（commit/构建 ID）、页面数、失败页与原因。
- 浏览器检查另记：浏览器与视口、实际点击路径、截图是否打开查看、未覆盖的设备/浏览器。
- 不允许把“生成了多少张截图”“检查了多少项”“HTTP 200”当作内容或阅读体验通过。

### 7.3 反向回归

每条新增规则至少有一个**必须失败**的反例测试，保存在 `scripts/presentation-contract.test.mjs`：

- 章节导航指向 `book_overview.html#chapter-N`；
- 序言/章末缺少直接下一页；
- 章首出现索引或长列表；
- `statement-index` 位于第一个 `<section>` 之前；
- 阅读页出现完整英文原题；
- 侧栏标题不是 `目录`；
- 导航标签与登记顺序不一致；
- 最后一页伪造“下一章”。

反例必须断言失败，不能用“允许通过”代替。

### 7.4 结论写法

必须分开写，不得合并成一句“统一通过”：

```text
范围：六书 60 页；提交 <sha>；构建 <id>；视口 1800/1440/1024/390；无脚本 <是/否>
契约：通过/失败（页数、失败页）
呈现：通过/失败（浏览器、实际点击路径、截图读回数量）
内容：抽样章节/题号；发现与未覆盖
发布：未执行/本地包/线上；线上版本与哈希
限制：未做的浏览器、设备、屏幕阅读器、未重证的题目
```

“样式已统一”只能表示契约检查覆盖的页面全部通过且呈现检查抽页一致；不能表示所有内容已经重读，也不能代替发布验收。

## 8. 例外与变更

- 例外必须在 `docs/reader-presentation.json` 的 `exceptions` 中逐页登记：规则、原因、范围、到期复核版本。无登记即失败。
- 默认没有例外。不得用书级检查器各自放行来代替登记。
- 修改本规范时同步更新：`docs/reader-presentation.json`、契约检查器、负向测试、RN-001 的相关引用、`docs/README.md`、`AGENTS.md` 与 `.project-governance.json`。
- 本规范变更记录只追加，不重写历史检查结果。

本章研究的对象始终是有限长度的位串。一个位只能区分两个状态，但把位串与解释规则结合，就可以表示数、字符、指令和地址。作者先把内存看作按字节寻址的数组，再规定哪些位构成一个对象；到整数和浮点部分，同一个位串才被赋予不同的权值。阅读时先画出位和字节的位置，再计算它们的意义。

2.1.1 · 十六进制记法（Hexadecimal Notation）

一个十六进制位恰好对应四个二进制位，因为 16=24。因此从 0x173A4C 到二进制，只需逐位替换为 0001 0111 0011 1010 0100 1100，不必经过十进制。从二进制返回时从右向左分四位，最左组不足四位才补前导零。前导零不改变无符号数值，却可能用来声明表示宽度。

十进制转换揭示了位权。314156=19634×16+12，再把商反复除以 16，余数从低到高是 C、2、B、C、4，反向写成 0x4CB2C。反算为 4×164+12×163+11×162+2×16+12。对二的幂更直接：写 n=4j+i、0≤i≤3，则 2n 由十六进制首位 1、2、4、8 中的一个和 j 个零构成。

2.1.2 · 数据大小（Data Sizes）

机器字长、指针宽度与每种 C 类型的长度必须分别确认。w 位地址能编码 2w 个地址，按字节寻址时这是表示能力的上限；操作系统实际提供的地址空间可以更小。64 位机器运行 32 位程序时，程序使用的 ABI 和对象布局也可能是 32 位的。书中表格的典型 ILP32 是 int、long、指针均 4 字节；LP64 是 int 为 4 字节而 long、指针为 8 字节。

C11 用 sizeof 给出对象占用的 C 字节数，CHAR_BIT 给出一字节的位数。这里采用 8 位字节。sizeof(char) 总是 1，但 plain char 是否有符号由实现决定；signed char 和 unsigned char 才明确。固定宽度的 int32_t 等类型只在实现能够提供所要求的表示时存在。把指针塞进 int 的代码，在 LP64 下会丢失高位；宽度是接口的一部分。

2.1.4 · 字符串表示（Representing Strings）

C 字符串是一串字符编码字节，后接一个值为零的终止字节。ASCII 的 "12345" 是 31 32 33 34 35 00；strlen 返回 5，若要显示终止字节就必须读取 6 字节。这里每个 ASCII 字符只占一个字节，因此整数字节序不会倒转字符顺序。中文 UTF−8 则可能用多个字节编码一个字符；字节数、字符数与屏幕列数不能混用。

2.1.5 · 代码表示（Representing Code）

函数在内存中同样是字节序列。原书把求和函数编译到 IA32、SPARC 和 x86-64，得到不同的字节序列；指令集和 ABI 决定这些字节怎样被执行。可移植的 C 源程序并不意味着可执行文件能跨机器直接运行。第二章给出表示基础，第三章才解释操作码、寄存器和地址计算如何把字节变成动作。

2.1.6 · 布尔代数（Introduction to Boolean Algebra）

单个位上，AND 只在双方为 1 时为 1，OR 在至少一方为 1 时为 1，XOR 在两位不同的时候为 1，NOT 则翻转该位。把同一运算独立应用到每一个位置，就得到位向量运算。

2.1.7·C 中的位级运算（Bit−Level Operations in C）

掩码用 1 指定要关注的位置：x & 0xFFu 取最低字节，x | mask 置位，x & ~mask 清位，x ^ mask 翻转。替换一段字段必须先清除旧字段，再并入已经定位的新字段；否则旧的 1 可能留在结果里。第 2.60 题会把这一过程落实为按字节替换。

C 的位运算还受整数提升约束。对 unsigned char 取反时，通常先提升为 int，再对整个 int 取反；所谓“字节取反得到 0xBE”，指最终保留低八位。用无符号常量与显式宽度能把位模型写清，不能把一幅八位图自动当作表达式的实际类型。

把掩码看成逐位开关：AND 遇到掩码 0 会输出 0，遇到 1 会保留原位；OR 遇到 1 会强制输出 1，遇到 0 会保留原位。因此“取某些位”用 AND，“把某些位置 1”用 OR。要把旧字段 1010 换成 0101，直接 OR 会得到 1111，仍带着旧的 1；先用清零掩码把旧字段抹成 0000，再 OR 新字段，才得到 0101。

2.1.8·C 中的逻辑运算（Logical Operations in C）

!、&&、|| 先把整个操作数解释为零或非零，结果只能是 int 的 0 或 1。0x69 & 0x55 得到 0x41，而 0x69 && 0x55 得到 1。逻辑运算还会短路：a && 5/a 在 a 为零时不计算除法；逐位 AND 会求值两边。条件保护的意义来自求值规则，而非结果恰好为零。

2.1.9 · 移位（Shift Operations in C）

左移丢掉左端移出的位，在右端补零；逻辑右移在左端补零，算术右移复制符号位。八位 10010101 左移四位保留为 01010000，逻辑右移为 00001001，算术右移为 11111001。后两者分别适合无符号除法和补码向下取整。

在 C11 中，无符号右移是逻辑右移；负有符号数右移由实现定义。移位量必须非负且小于整数提升后左操作数的宽度；负数左移，以及有符号左移得到不可表示的值，均不能作为正常 C 运算。处理器可能把计数取模，但这不能补救非法 C 表达式。由于加减优先级高于移位，1<<2+3<<4 等价于 (1<<5)<<4，得到 512；表示两个量相加应显式加括号。

2.2.1 · 整数类型（Integral Data Types）

先选位宽 w，再选解释。对于本章的 w 位无符号与补码模型，范围分别是 0≤U≤2w−1 与 −2w−1≤T≤2w−1−1。C11 的普通类型只承诺最低范围，不承诺 int 一定 32 位，也不普遍承诺补码；本文把教材模型和运行条件写在程序入口中。

2.2.3 · 补码编码（Two’s−Complement Encodings）

原理 · 补码编码的定义

Definition of two’s-complement encoding

For vector x→=[xw−1,xw−2,…,x0]:

B2Tw(x→)≐−xw−12w−1+∑i=0w−2xi2i

对同一 w 位向量，补码把最高位的权值改成负数：

B2Tw(𝐱)=−xw−12w−1+∑i=0w−2xi2i.

当 w=1 时，后面的空和为零。由此得到 TMinw=−2w−1、TMaxw=2w−1−1；最高位为 1 表示负数，为 0 表示非负数。

推导要点：低 w−1 位最多贡献 2w−1−1，不足抵消符号位的负权值。这也说明负数范围比正数多一个值。 接着看本节推导与例子。

原理 · 补码编码的唯一性

Uniqueness of two’s-complement encoding

Function B2Tw is a bijection.

映射 B2Tw:{0,1}w→{TMinw,…,TMaxw} 是双射；其逆函数 T2Bw 为每个范围内整数给出唯一的补码位串。

推导要点：最高位为 0 的位串一一覆盖非负区间，最高位为 1 的位串则把相同的低位数值整体减去 2w−1。两个区间相邻且互不重叠。 接着看本节推导与例子。

补码只改变最高位的权值：T=−bw−12w−1+∑i=0w−2bi2i。最高位为 1 时，它的负权值绝对值超过低位能够贡献的最大值，所以结果必为负。最高位为 0 时则非负。最小值是 100…0，最大值是 011…1；零占掉一个非负编码，使负数比正数多一个。

例如 16 位 −12345 的编码是 65536−12345=53191，即 CFC7；按补码权值读回，53191−65536=−12345。补码的定义是权值，不是“先取反加一”；取反加一将在加法逆元的推导中得到。原码和反码都有两个零，补码只有一个零，这使整个位空间恰好覆盖连续的 2w 个整数。

把两个权值式相减，低 w−1 位全部抵消，得到 U−T=bw−12w。于是补码转无符号的位保持模型为：非负时保留 x，负数时取 x+2w；反向在 u≤2w−1−1 时保留 u，否则取 u−2w。这两张映射表是随后所有转换推导的基础。

C11 的“转到无符号”确实按目标类型的模数调整数值；但把超出有符号范围的无符号数转成有符号数，其结果或信号由实现定义。书中的常见补码实现保持位模式，本文需要此约定的函数会明确使用它。用 printf 时还应给出与参数类型匹配的格式，不能把格式不匹配当作一种通用转换方法。

用四位 1011 逐个解释公式的符号：w=4，b3=1、b2=0、b1=1、b0=1。无符号的最高位贡献 +8，补码贡献 −8，其余共同贡献 0×4+1×2+1×1=3，所以分别为 11、−5。两者相差的是“+8 换成 −8”带来的 16。负数转无符号时加 16，正是补回这一个权值变化，而不是任意选了一个修正常数。

2.2.5·C 中的有符号与无符号（Signed versus Unsigned in C）

类型转换不只发生在强制转换处。比较或算术前，先做整数提升，再做通常算术转换。书中同秩 int/unsigned int 混合时，有符号数被转成 unsigned。因此 -1 < 0U 比较的是 232−1 与 0，结果为假；-1 < 0 则为真。较宽有符号类型若能容纳较窄无符号类型的全部值，转换方向可以不同，所以判断必须从实际类型出发。

INT_MIN 常写成 (-INT_MAX-1)，因为负号是作用在正整数字面量上的运算符。十进制正数 2147483648 的类型可能已经不是 int；十六进制常量的候选类型序列也不同。写边界测试时，优先使用标准头文件的范围宏。

2.2.6 · 扩展位表示（Expanding the Bit Representation of a Number）

原理 · 无符号数的零扩展

Expansion of an unsigned number by zero extension

Define bit vectors u→=[uw−1,uw−2,…,u0] of width w and u→′=[0,…,0,uw−1,uw−2,…,u0] of width w′, where w′>w. Then B2Uw(u→)=B2Uw′(u→′).

令 w′>w，把 w 位向量 𝐮 高端补上 w′−w 个零得到 𝐮′，则：

B2Uw′(𝐮′)=B2Uw(𝐮).

这条结论保持的是无符号数值；补在高端的零不改变原有任何一位的位权。

Let C variables x and k have two’s-complement value x and unsigned value k, respectively, such that 0≤k<w. The C expression (x + (1 << k) - 1) >> k, when the shift is performed arithmetically, yields the value ⌈x2k⌉.

⌈x2k⌉=⌊x+2k−12k⌋.

2.4.1 · 二进制小数（Fractional Binary Numbers）

二进制小数点左边的权值为 1、2、4……，右边为 2−1,2−2,2−3,…。因此 101.112 是 4+1+12+14=5.75。小数点右移 k 位乘以 2k，左移则除以 2k。有限二进制小数都能写成 a2n，所以约分后分母含有其他质因子的数不能精确表示。

例如 110 的二进制是 0.0001100110011…2。重复部分来自“余数乘二、取出整数位”的长除法；余数状态重复，后续位也重复。有限精度只能截断或舍入。单次误差很小不代表累计误差小：第 2.46、2.51 题把表示误差乘以计时器的读数，精确算出 100 小时后的偏差。

2.4.2 · IEEE 表示（IEEE Floating-Point Representation）

IEEE 二进制格式把位分为符号 s、k 位指数域 e 和 n 位小数域 F，数值为 V=(−1)sM2E。小数域的数值为 f=F2n，偏置为 B=2k−1−1。指数域决定解释类别，不能把所有编码统一按“隐藏 1”读取。

指数域小数域解释
0<e<2k−1任意正规：E=e−B，M=1+f
e=0F≠0非正规：E=1−B，M=f
e=0F=0带符号的零
e=2k−1F=0带符号无穷

正规数通过调整 E，使 1≤M<2，最高的 1 总是存在，可以省略存储，因此 n 个小数位带来 n+1 位有效精度。非正规数保留最小指数但撤掉隐藏的 1，让有效数字能够逐渐趋近零。零也属于 e=0 的编码：+0 与 −0 比较相等，编码不同，在 IEEE 除法中分别可产生正、负无穷。

无穷用于表示范围溢出等结果，NaN 用于无有效数值的运算结果。NaN 与自己比较也不相等，大小比较为假。位操作练习约定 NaN 原样返回，保留其符号和载荷；这与要求某次硬件算术保留所有 NaN 位并非同一件事。

这里 e 和 E 是两种量：e 是指数域那 k 个位按无符号读出的编码，E 才是数值中的二次幂指数。以 binary32 的 1.5 为例，1.5=1.12×20，所以真实指数 E=0；为了把负指数也装进无符号字段，存储 e=0+127=127，写成 01111111。有效数 1.1 的开头 1 按正规数约定省略，小数域只保存 .1 后补零，符号位为 0。解码时先认出这是正规数，再补回 1 并从 e 减去偏置。

舍入是把精确结果映射到可表示网格。向下、向上、向零分别给出下界、上界和绝对值不增的近似；默认最近偶数先选距离最近者，仅在恰好中点时检查保留部分的最低位，选它为 0 的候选。比如以 1/4 为步长，1.125 位于 1.00 与 1.25 的中点，选 1.00；1.375 位于 1.25 与 1.50 的中点，选 1.50。

“选偶数”检查的是网格编号。例如步长 1/4 时，1.00、1.25、1.50 分别是第 4、5、6 个格点。1.125 到第 4、5 格同样远，选偶数编号 4；1.375 到第 5、6 格同样远，选编号 6。因此第二个结果 1.5 本身可以不是整数；偶数说的是保留有效位的最低位为 0，并非要求舍入后的十进制数一定是偶整数。

2.4.5 · 浮点运算（Floating-Point Operations）

经典表述 · 每一步舍入会破坏结合律

The lack of associativity in floating-point addition is the most important group property that is lacking.

浮点加法的数值模型是 x+fy=Round(x+y)。每次加法都可能丢掉低位，改变括号就改变了先丢掉哪一部分信息，因此通常不满足结合律：

(x+fy)+fz≠x+f(y+fz).

这个不等式表示可以构造反例，并非声称任意三个输入都不相等。重排累加次序时，须同时考虑性能和允许的数值误差。

IEEE 基本算术的抽象规则是“先得到精确数学结果，再舍入到目标格式”。每一步都可能丢掉信息，所以结合顺序能够改变结果。binary64 中令 a=1016,b=−1016,c=1：先算 a+b 得到 0，随后加 c 得到 1；先算 b+c 时，1 小于该位置的间隔而被舍去，再与 a 相加得到 0。

乘法同样可能因舍入、上溢或下溢而失去结合律与分配律。单精度中先乘两个巨大数会溢出为无穷，再乘一个小数不能恢复原来有限的结果。浮点加法在固定另一个加数时保持单调；乘法在固定非负因子时保持单调，固定负因子时反转顺序。这些结论必须排除过程中产生 NaN 的情形；例如包含无穷时，0×∞ 和 ∞−∞ 不能纳入普通实数不等式证明。

         first++,last--)

}

  1. 证明精确积 xy=p+t2w，且 t≠0 当且仅当乘法溢出。
  2. 证明 p=xq+r，其中 |r|<|x|。
  3. 证明 q=y 当且仅当 r=t=0。

    int p = x*y;
    return !x || p/x == y;
}

第三版 Global Edition；印刷 135 页 / PDF 136 页。

解答

  1. x=0 时积为零，不溢出，并由短路避免除零。对 x≠0，p 是 xy 在补码代表区间中的同余代表，故 xy−p 是 2w 的整数倍，写成 t2w；t=0 恰表示精确积未被改变。

  4. 最终只写入 sig 的低 23 位，隐含首 1 不存储，再并入符号和指数。完整 C 驱动将每个 unsigned 位模式安全解码为 int，故穷举覆盖全部 232 个整数，和本机 (float)i 的位模式比较全部通过；Python 驱动已运行同一边界与伪随机集合。

自测 2-1 · 扩展与解释

问题

四位 1011 分别零扩展和符号扩展到八位；各自无符号和补码值是多少？

解答

四位无符号是 11，补码是 −5。零扩展为 00001011，两种解释均为 11；符号扩展为 11111011，无符号是 251，八位补码为 251−256=−5。保留哪一种值由扩展规则决定。

自测 2-2 · 溢出检测的位置

问题

为什么 int s=a+b; if(s<a) 不能作为通用的有符号加法溢出检查？

解答

如果 a+b 超出 int 范围，第一条语句已经触发未定义行为；后面的结果检验无法恢复其语义。且 s<a 对负加数本来就可能成立。应先按 b 的符号和 INT_MIN/INT_MAX 检查，或使用已定义的更宽范围/检查接口。

自测 2-3 · 非规格化边界

问题

binary32 的最小正非规格化数为什么是 2−149？

解答

指数域为 0 时 E=1−127=−126，最小非零尾数字段给出 f=2−23，没有隐藏的 1。相乘为 2−23·2−126=2−149。这也解释它如何细分接近零的区间。

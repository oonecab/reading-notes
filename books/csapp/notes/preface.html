一、程序员视角怎样决定全书的选材A Programmer’s Perspective

原书：印刷 19 页 / PDF 20 页

原书摘录以程序员能写出怎样的程序为尺度

Preface · A Programmer’s Perspective · 印刷 19 页 / PDF 20 页

Our aim is to explain the enduring concepts underlying all computer systems, and to show you the concrete ways that these ideas affect the correctness, performance, and utility of your application programs. Many systems books are written from a builder’s perspective, describing how to implement the hardware or the systems software, including the operating system, compiler, and network interface. This book is written from a programmer’s perspective, describing how application programmers can use their knowledge of a system to write better programs.

译文。我们的目标，是解释各种计算机系统共同依赖的持久概念，并具体说明这些思想怎样影响应用程序的正确性、性能与用途。许多系统书籍从构建者的视角出发，讲解怎样实现硬件或系统软件，包括操作系统、编译器和网络接口。本书则从程序员的视角出发，讲解应用程序员怎样运用系统知识写出更好的程序。

接着读：同一目标如何贯穿十二章 · 理解编译系统能解决什么问题

这三个词给整本书设定了尺度。正确性意味着程序在规定条件下产生应有结果；性能意味着它用多少时间与资源实现结果；用途则关系到它能否利用系统提供的能力，完成文件、网络、并发等现实任务。作者跨越硬件、编译器、操作系统与网络，是因为同一个应用会同时受到这些层次影响。

以数组求和为例。先要知道元素的整数范围或浮点精度，才谈得上结果是否正确；再要理解编译出的指令依赖和内存访问，才解释得了速度；若数组来自文件或网络，还要处理输入、资源与失败路径。把各层放在一起，问题才能闭合。

因此本书讲汇编时，经常从C编译结果进入；讲硬件时，关注一条指令怎样获得输入和写出结果；讲操作系统时，沿着应用能调用的接口解释行为。每次学习都可以用一个问题判断理解是否落地：这一机制会怎样改变我写程序、判断结果或定位错误的方式？

作者还把这种学习定位为进一步构建系统的基础。先明白系统向程序承诺什么，再理解内部如何实现，才能在以后学习编译器、体系结构或操作系统时区分外部契约与内部选择。

阅读注解
理解

用程序问题组织知识

一个错误比较式可以引出位宽、转换与条件码。先保留具体问题，再沿书中的机制逐层回答。

读法

每章都检查三个维度

得到什么结果、付出什么代价、能完成什么任务，是比只记术语更稳定的阅读坐标。

二、作者的机器背景也是例子的前提Assumptions about the Reader’s Background

原书：印刷 19 页 / PDF 20 页

原书摘录例子的机器和软件环境

Preface · Assumptions about the Reader’s Background · 印刷 19—20 页 / PDF 20—21 页

This book focuses on systems that execute x86-64 machine code.

We consider how these machines execute C programs on Linux.

The machine-language examples were all generated by the GNU gcc compiler running on x86-64 processors. We do not assume any prior experience with hardware, machine language, or assembly-language programming.

译文。本书集中讨论执行 x86-64 机器代码的系统，并考察这些机器怎样在 Linux 上执行 C 程序。机器语言例子均由运行在 x86-64 处理器上的 GNU gcc 编译器生成。作者不假定读者已经具有硬件、机器语言或汇编语言的经验。

以上三段分别摘自该节的相关说明。它们把“可观察的具体实现”和“无需预先掌握汇编”放在一起：学习入口可以低，但结论的环境不能省略。下面按语言、编译器与机器三层拆开这些条件。

接着读：程序编码与编译环境 · 本机实验的条件

序言明确选用在Linux上执行C程序的x86-64系统。这个选择把讨论固定到可以编译、运行和观察的对象：整数尺寸、寄存器名字、调用约定、目标文件和系统调用都有具体含义。作者不假定读者已学过汇编或硬件，但假定能进行基本编程并使用终端与文件。

对从Java或Python进入的读者，真正需要补上的常常不是循环语法，而是C如何表达对象和存储：指针保存地址，数组访问依赖类型与步长，动态分配需要管理寿命，格式化I/O依赖参数类型。变量看起来相同，语言为溢出、别名和对象生命周期规定的行为可能不同。

遇到的结论需要确认的前提在笔记中怎样使用
整数加法只留下低位明示位宽的机器模型或无符号C运算与C有符号溢出的语言规则分别解释
long和指针均为8字节书中的x86-64/Linux LP64环境用sizeof观察宿主，不当成所有平台定律
前六个整数参数放寄存器相应System V ABI及参数类别用调用实例追踪；聚合与浮点按各自规则
某段代码的CPE是3原书参考机器、运算和编译条件作为历史测量解释依赖关系，实测另记环境

这里尤其要分清“源语言规则”“编译器输出”“机器执行”三层。C程序可由不同编译器变成不同指令，某份汇编也可能只在指定ABI下成立。自己的机器输出不同，不一定是原理失效；先核对输入、类型、编译选项与目标机器，再寻找不一致。

书中例子具有明确时代背景。读者今天使用其他处理器时，可以先在本机运行可移植C/Python模型，再用明确目标的工具观察x86-64汇编；只有实际执行了目标指令，才据此描述目标运行行为。

例如 long x=2; long *p=&x; 中，x 是存放数值 2 的对象，p 存放的是 x 的地址；*p=5 沿这个地址把 x 改成 5。复制 p 只是多得到一条访问 x 的途径，不会自动复制一个新的 x。以后看到“别名”“共享”“间接寻址”，都可以先把名字画到具体对象上。第 5 章的逐句推演会说明这个区分为何直接限制编译器优化。

理解

可复现需要连同条件一起保存

输入和源码之外，编译器选项、目标体系结构与数据类型同样影响观察结果。

边界

语言相似不代表算术相同

Python整数可增长；C无符号整数按位宽取模；C有符号溢出另有规则。跨语言验证必须先对齐模型。

三、把阅读变成一轮可检验的推演How to Read the Book

原书：印刷 20 页 / PDF 21 页

原书摘录学系统要亲手推演和运行

Preface · How to Read the Book · 印刷 20—21 页 / PDF 21—22 页

Learning how computer systems work from a programmer’s perspective is great fun, mainly because you can do it actively. Whenever you learn something new, you can try it out right away and see the result firsthand. In fact, we believe that the only way to learn systems is to do systems, either working concrete problems or writing and running programs on real systems.

When a new concept is introduced, it is followed in the text by one or more practice problems that you should work immediately to test your understanding. Solutions to the practice problems are at the end of each chapter. As you read, try to solve each problem on your own and then check the solution to make sure you are on the right track.

译文。从程序员的视角学习计算机系统很有趣，主要原因是你可以主动参与：每学到一点新东西，就能立即尝试，亲眼观察结果。作者认为，学会系统的途径就是亲手做系统相关的工作，包括解具体问题，以及在真实系统上编写、运行程序。正文介绍新概念后，会安排一道或多道随文练习，应当立即动手以检验理解；答案在章末。阅读时先独立解题，再核对答案，确认思路是否正确。

这里摘录同节的两段相关文字，中间的过渡句省略。作者把“试出来”与“自己先解”同时作为学习动作。读者先留下预测，才有机会根据实际差异修正理解。

接着读：从 Amdahl 定律的两道原题开始 · 各章可留下什么推演结果

序言的建议并不是读完一章再顺手运行程序，而是在新概念出现时立即做一道practice problem。先自己写下状态或结果，再读章末解答。这样才能发现自己究竟遗漏了一个条件、一个中间值，还是对整个机制理解错误。看懂别人已经写好的终点，和能够独立走到终点，是两种不同活动。

可以把一次练习分成四个连贯动作。先固定条件，例如“8位补码”“数组按行存放”“缓存初始为空”；接着画出中间状态或列出方程；然后运行模型或核对题解；最后解释差异来自哪一步，并用一个边界输入重试。关键是保持预测记录，否则运行结果很容易被误当成自己早已理解的结论。

材料作者安排的用途阅读时的动作
随文练习 practice problem刚学一个机制就测试理解先解，再与章末答案比较条件与每一步
章后作业 homework组合多个知识点，难度按◆标记保留全部小问和输入，完成推导或程序
正文程序及文件路径可实际编译运行的具体材料追踪数据与控制，记录本机与书例的差异
旁注 aside历史、易混概念、真实案例在当前问题需要时吸收，再回到主线
Web aside补充更深或更专门的内容理解正文后按明确问题延伸

书中一到四个◆大致表示从几分钟题目到完整实验的工作量，它不是知识点的重要性等级。一个短小的指针题也可能暴露关键误解。遇到长题，可以拆分验证局部不变量，但最后仍要把各部分重新连成完整解法。

原书摘录书中的程序来自实际源文件

Preface · How to Read the Book · 印刷 21 页 / PDF 22 页

Each code example in the text was formatted directly, without any manual intervention, from a C program compiled with gcc and tested on a Linux system. Of course, your system may have a different version of gcc, or a different compiler altogether, so your compiler might generate different machine code; but the overall behavior should be the same.

译文。正文中的每个代码例子，都直接从经过 gcc 编译、在 Linux 系统上测试的 C 程序排版而来，中间没有手工改写。读者的系统可能使用另一个版本的 gcc，甚至完全不同的编译器，因此生成的机器代码可能不同，但整体行为应当一致。

“整体行为一致”以同一个定义良好的程序、有效输入和相应环境为前提。它不保证两次编译的寄存器分配、指令数或执行时间相同。读第 3 章时，应先追踪参数、内存与返回值，再比较指令选择；读第 5 章时，才进一步分析这些选择的成本。

接着读：从 C 到机器代码 · 源码、阅读副本与运行方式

序言还说明正文代码从实际编译并测试过的源文件自动排版而来。这一点说明代码与文字应保持联系：读代码要知道输入是什么、哪一行维护哪个不变量、输出怎样核对。编译器版本变化可以改变具体指令选择，原题或书后答案也仍可能有笔误，因而最终依据应包括明确的语义推导与可重复观察。

阅读注解
方法

预测要具体到可判定的状态

“会变快”过于模糊；写出哪条依赖链缩短、哪次访问从失效变命中，才能用观察纠正理解。

边界

运行成功只核对一个范围

一个程序输出正确，并不自动覆盖溢出、空输入、非法移位、别名或所有舍入情形；结论需带验证范围。

四、十二章围绕同一个程序逐渐扩展Book Overview

原书：印刷 22 页 / PDF 23 页

第1章先让hello走一遍系统，后面的三部分分别放大程序内部、它所在的运行环境、以及它与别的程序之间的关系。这个顺序先建立一个可以追踪的对象，再逐步增加约束，避免一开始同时面对所有复杂性。

第一部分：从值的含义走到执行的代价

第2章解释有限位串为何不同于数学中的无限整数和实数；第3章把C的条件、循环、过程和数据结构翻成机器状态变化；第4章用较简单的Y86-64构造能执行这些状态变化的硬件；第5章以依赖、吞吐和编译器障碍解释优化；第6章再引入分层存储与局部性。性能问题由此分成“工作怎样组织”和“数据怎样到达”两个互相连接的方面。

第二部分：让一个程序进入操作系统

第7章把分离的目标文件组合成能够装入的程序，回答名字和地址怎样相接；第8章让控制流面对异常、进程、信号和切换；第9章解释虚拟地址如何支持缓存、保护、共享与动态存储。这里把第1章的进程、地址空间等抽象展开为机制。

第三部分：从单次执行走到交互与协作

第10章建立可靠的文件读写与缓冲，第11章将字节流延伸到网络并构造Web服务，第12章允许多个活动同时推进，同时处理共享状态、线程安全和同步。一个网络服务既需要前面的小整数和地址计算，也需要后面的I/O与并发约定。附录A把失败返回与错误处理方式集中起来。

这条顺序并不意味着每个后续主题只有一个前置章节。虚拟内存同时联系第3章的地址、第6章的缓存和第8章的异常；网络程序会再次用到第2章的字节序、第10章的短读写与第12章的并发。全书地图按原书三部分给出阅读顺序，图后的说明再展开这些跨章联系。

五、版次、课程和实验怎样塑造这本书New to This Edition · Origins · Courses · Labs · Acknowledgments

第三版的变化应如何影响阅读

序言列出的最大调整是从IA32与x86-64并讲转到以x86-64为主，第4章也相应采用64位Y86模型。第3章新增浮点机器代码，性能章节更新了参考处理器与更充分的指令级并行。第2章加强数学段落的引导，允许先建立直觉，再回来补完整推导。

后半书更新包括位置无关代码与库打桩、信号处理的严格约束、协议无关且线程安全的名字/地址接口，以及多核上的线程级并行。这些变化说明版本一致性不仅是页码问题：寄存器宽度、代码模式、接口和题目都会变。本文依据本地第三版Global Edition；题号和输入以该PDF为准。

课程来源解释了实践主线

本书源于作者在1998年秋于Carnegie Mellon开设的15-213系统导论课。出发点是多数学生日常都要使用和编程计算机，课程因此从应用程序员可见的问题组织系统知识。经历课堂、实验、批改和读者反馈之后，这些材料形成了书。这里叙述的是序言记录的历史，而非当前课程安排。

序言给出ORG、ORG+、ICS、ICS+、SP五种课程组合。ORG侧重组织与硬件，ORG+加入优化与更多存储知识，ICS强调运行环境，ICS+再扩展I/O、网络和并发，SP侧重系统编程。组合表的作用是帮助分配学习重心：可以按目标调整阅读路径，但每一条路径仍要完成所依赖机制的理解。

原书摘录用同一个模型连接分析与优化

Preface · Lab Exercises · Cache Lab · 印刷 30 页 / PDF 31 页

In this alternative to the performance lab, students write a general-purpose cache simulator, and then optimize a small matrix transpose kernel to minimize the number of misses on a simulated cache. We use the Valgrind tool to generate real address traces for the matrix transpose kernel.

译文。作为性能实验的另一种选择，学生先编写通用缓存模拟器，再优化一个小型矩阵转置核心，使它在模拟缓存上的失效次数尽可能少。作者使用 Valgrind，为矩阵转置核心生成真实的地址轨迹。

这项实验把三件事连成闭环：程序产生地址，模型把地址变成命中或失效，代码变换再改变地址次序。它同时检验第 3 章的地址计算、第 5 章的合法程序变换和第 6 章的缓存机制。比较优化前后，应保持缓存参数、输入与初始状态一致；只改变代码的访问次序，才便于判断收益来自哪里。

接着读：地址怎样进入组相联缓存 · 用访问次序改善局部性

实验是知识的交汇点。例如矩阵转置既要从第3章得到地址公式，又要用第6章分析缓存映射，还可能受第5章的循环组织影响。笔记中的小程序将这些机制缩小到可手算的输入；完整实验则需要把它们重新组合成较大的可运行系统。

致谢所呈现的知识形成过程

序言末尾保留三版的致谢，涵盖授课教师、学生、实验贡献者、勘误读者、技术讨论者与制作团队；Global Edition另列本版审阅者。它提醒读者，这本书的稳定性来自不断用具体问题、真实程序和课堂反馈校正说明。对有疑问的公式或答案，沿原条件复核并留下依据，也延续了这种工作方式。

阅读注解

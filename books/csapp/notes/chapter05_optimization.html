5.1 · 编译器必须保留程序实际表达的语义Capabilities and Limitations of Optimizing Compilers

原书：印刷 534 页 / PDF 535 页

本章沿一个数组归约循环追问：同样的数学运算，为什么能从每元素十多个周期降到不足一个周期？先要划清优化的边界。编译器转换的是 C 程序允许的行为；它不能假定两个合法指针一定指向不同位置，也不能把会修改状态的函数当作纯数学函数。理解这些约束，才能知道哪些信息必须由程序员表达。

原书原则 · 安全优化的语义边界

Compilers must be careful to apply only safe optimizations to a program, meaning that the resulting program will have the exact same behavior as would an unoptimized version for all possible cases the program may encounter, up to the limits of the guarantees provided by the C language standards.

中文陈述。在 C 语言标准提供保证的范围内，优化必须保留程序对所有可能遇到情形的行为。证明一次变换安全，需要考虑合法的别名、可观察副作用和数值语义；未定义行为不提供可供承诺的原有结果。

别名怎样阻止“看起来相同”的改写

本例改写自原书 twiddle1/twiddle2：将函数改名，并为第二个指针增加 const，以进一步说明访问限制与别名的区别。计算语句保持同一含义。原书见印刷 535 页 / PDF 536 页。

先分清“指针”和“指针指向的数”。假设调用者有一个变量 long n = 2，&n 表示它的地址；把这个地址同时传给 xp 和 yp，两个指针就都指向同一个变量 n。*xp 的意思是“通过 xp 访问 n”，*yp 的意思是“通过 yp 访问 n”。它们是访问同一个存储位置的两条途径，并不是各自保存了一份 2。这种多个访问途径指向同一对象的情况叫作别名。

下面两段代码都想把 yp 所指的数加到 xp 所指的数上两次。若它们指向不同对象，且运算没有溢出，把“两次相加”合成“一次加两倍”看起来合理；现在检查它们指向同一个对象时是否还成立。这里的 *xp += *yp 可以按“读取当前的 *xp 和 *yp，相加，再把结果写回 *xp”来理解。

void twice(long *xp, const long *yp) {
    *xp += *yp;
    *xp += *yp;
}
void once(long *xp, const long *yp) {
    *xp += 2 * (*yp);
}

先执行 twice(&n, &n)。第一句执行前，两个读取都得到 2，所以计算 2+2，把 4 写进 n。第一句结束后，n 已经是 4；因此第二句里的 *yp 也会读到 4，它不会记住函数刚进入时的 2。第二句读取的是 4 和 4，写回 8。

再做一次独立实验，把 n 重新设为 2，执行 once(&n, &n)。这次只有一个赋值：读取的 *xp 是 2，读取的 *yp 也是 2，右边的两倍是 2×2=4，最后把 2+4=6 写进 n。在这一个赋值完成前，没有前一句先把 n 改成 4。这里不需要规定乘法与左边读取谁先求值，只需要知道这次写入发生在取得相应旧值并完成运算之后。

也可以对照没有别名的情况：让 x=2、y=2，传入 &x、&y。twice 第一次把 x 改成 4，y 仍为 2；第二次计算 4+2=6。once 计算 2+2×2=6。区别恰好在于：第一次写入 x，会不会同时改变下一次通过 yp 读取的对象？编译器若无法排除同址调用，就必须保留同址时的结果 8，不能擅自改成得到 6 的版本。

const long *yp 又为什么没有排除这种情况？它只规定函数不能写 *yp = 4 这种通过 yp 修改对象的语句。调用者的 n 本来是可修改的 long，函数仍可以通过 xp 修改它；修改后，经 yp 读取自然得到新值。const 没有复制对象，也没有冻结其他指针能访问的内存。如果对象本身被定义为 const，则强行通过其他指针修改它属于另一种非法用法。上述 2、4、6、8 都在 long 范围内；讨论一般输入时还要保证每个中间值都可表示，不能把有符号溢出当作正常整数运算。

函数调用也要追踪“除了返回值，还改变了什么”。假设 f() 的函数体是 ++calls; return 7;，calls 从 0 开始。连续执行四次 sum += f()，sum 共增加 28，calls 增至 4；改成一次 sum += 4*f()，sum 同样增加 28，calls 却只增至 1。只比较算术结果会漏掉这个可观察差异。编译器需要足够的定义或接口信息，证明取消调用不会丢掉这种效果，才可以合并；内联和全程序分析可以帮助它取得这些信息。

从生成代码检验假设

使用 -O1、-O2 或 -O3 是选择转换策略，不是性能等级的保证。内联和展开可能扩大指令体积；编译器也可能已有与你手写等价的变换。每次比较应固定输入、编译器版本、选项和数值约束，再查看热点内循环是否仍在重复调用、读取内存或依赖同一寄存器。对浮点表达式尤其要说明是否允许重结合和融合乘加。

5.2 · 用斜率区分固定开销与每元素成本Expressing Program Performance

原书：印刷 538 页 / PDF 539 页

原书表述 · CPE 是随元素数增加的斜率

The slope of the lines indicates the number of clock cycles per element (CPE).

中文陈述。在运行周期数随元素个数近似线性增长的区间，直线斜率表示每增加一个元素需要多少周期。固定启动成本由截距表达；改变每轮处理的元素数后，仍应按元素比较成本。

下面把同一规模范围写成 T(n)≈a+bn，用三种截距和斜率的交点说明“小输入更快”与“大输入每元素更省”如何同时成立。

原书 §5.2，图 5.2，印刷 539 页 / PDF 540 页。

运行时间受输入规模影响。归约 n 个元素时，可以用 T(n)≈a+b·n 描述一段规模范围内的测量：a 是调用、初始化和收尾等固定成本，b 是随每个元素增加的成本。以处理器周期为时间单位，斜率 b 称为 CPE（cycles per element）。一次测量的 T(n)/n=a/n+b，在 n 很小时仍混入明显固定开销。

小规模 A 的低启动成本占优，中间 B 最快，n≥8 时 C 的低斜率胜出。习题 5.2 会求出准确区间。比较算法时应观察一组规模，检查曲线是否出现拐点；例如数组超出缓存后，原来线性段的斜率可能变化。

现代机器的频率可能变化，墙钟时间还包含调度影响。笔记的本机实验使用 ns/element，原书表格使用参考机器的 CPE；两种单位分别标明。没有可靠的周期计数与频率依据，就不把纳秒直接换成“周期”。

斜率公式为什么要先相减？若同一版本在 n=100 和 n=200 时分别用 536、936 周期，第二次只多处理了 100 项，却多花 400 周期。因此每个新增元素平均花 400/100=4 周期。两次都有的启动开销被 936−536 抵消了；再代回 536−4×100=136，才得到固定开销。这组数取自上表的版本 B，用来说明怎样由时间反推模型。

5.3 · 把抽象接口写成可以追踪的归约循环Program Example

原书：印刷 540 页 / PDF 541 页

原书的向量抽象把长度和数据地址封装在 vec_rec 中。get_vec_element 检查索引并通过指针返回元素；combine1 使用统一的数据类型 data_t、单位元 IDENT 和运算 OP，因此可实例化为整数或浮点的求和、乘积。抽象有助于复用，但读一次元素要经过多少步骤，必须从循环内部展开看。

typedef struct { long len; data_t *data; } vec_rec, *vec_ptr;
void combine1(vec_ptr v, data_t *dest) {
    *dest = IDENT;
    for (long i = 0; i < vec_length(v); ++i) {
        data_t val;
        get_vec_element(v, i, &val);
        *dest = *dest OP val;
    }
}
表达式一次迭代可能承担的工作后续小节要消除什么
vec_length(v)取得长度；若未内联还有调用5.4 把循环不变量移到外面
get_vec_element调用、范围检查、取数据指针与元素5.5 在验证边界后直接访问

代码中的 data_t、OP、IDENT 是原书用于比较的编译时选项：求和单位元 0，乘积单位元 1。完整实验选择 uint64_t 求和与内积，其算术按模 264 定义；Python 每次对应取低 64 位。这样可以把“改变分组是否正确”与“改变浮点舍入是否可接受”分开验证。空向量返回单位元，是每个变体共同需要保留的边界。

把抽象记号换成一次求和就能逐句跟踪：取 data，其内容为 [2, 3, 5]，把 OP 换成加号、IDENT 换成 0。循环前结果是 0；i = 0 时取出 2，写回 0+2=2；i = 1 时写回 2+3=5；i = 2 时写回 5+5=10。每轮开始时，结果应恰好等于已经处理的前 i 项之和。这个始终成立的事实叫作循环不变量；下面所有优化都要说明它怎样继续成立。

5.4 · 把不变的工作移出循环Eliminating Loop Inefficiencies

原书：印刷 544 页 / PDF 545 页

combine2 把 long length = vec_length(v) 放到循环外。若循环不会改变向量长度，这个调用从 n+1 次降为 1 次。真正关键的是找到不随 i 改变的工作；“循环体很短”并不意味着每次迭代便宜。

long length = vec_length(v);
for (long i = 0; i < length; ++i) {
    /* 处理第 i 个元素 */
}

strlen 藏在条件中，怎样把线性工作变成平方工作

for (size_t i = 0; i < strlen(s); ++i)
    s[i] = lower_one_ascii(s[i]);

strlen 从头扫描到零字节，长度 n 的字符串要读 Θ(n) 个字符。循环判断执行 n+1 次，于是条件部分总扫描量为 Θ(n2)，字符变换本身反而只有 Θ(n)。若 lower_one_ascii 保证不会产生零字节、不会改变终止位置，可先求长度再遍历；也可沿指针扫描到零字符。条件能外提的根据是终止位置不变。

W(n)≈(n+1)n+n=n2+2n

这类代码移动不需要知道目标机器有几个乘法器。先减少算法实际执行的工作，再讨论每个操作怎样重叠，通常更容易解释收益。习题 5.3 用函数调用次数训练这一判断。

例：重复求字符串长度的工作量

例如字符串为 ABC，长度 3。判断 i=0、1、2 时进入循环，判断 i=3 时退出，共判断 4 次；若每次 strlen 都重新检查 A、B、C 和结尾的零字节，就为求长度做了 4×4=16 次字节检查。先求一次长度只需 4 次。这里把终止字节也计入；上面的 W(n) 则是忽略这类常数差异的数量级模型。把字符转小写没有改变终止位置，才允许复用第一次求得的 3。

阅读注解
推导

同时数循环次数和每次成本

n 次循环乘上每次 Θ(n) 的隐式扫描，得到 Θ(n2)。

边界

外提需要不变量证明

若循环能改变长度或调用有副作用，预计算一次可能改变程序行为。

5.5 · 在可信边界内减少过程调用Reducing Procedure Calls

原书：印刷 548 页 / PDF 549 页

combine3 先取得数据首地址，再直接用 data[i]。与 combine2 相比，它取消每个元素的函数调用、参数传递和范围检查。边界并没有凭空消失：循环已经用 i < length 控制，仍需保证 length 与实际分配的数据一致。

long length = vec_length(v);
data_t *data = get_vec_start(v);
*dest = IDENT;
for (long i = 0; i < length; ++i)
    *dest = *dest OP data[i];

原书中这一改变并非总带来明显加速，因为剩下的每轮读写 *dest 可能成为更强的限制。这里给出一个重要的实验方式：实现一个变化，读生成的循环，再看它究竟取消了什么指令和相关。源码少写一层调用，与机器少做一层调用也不是同一事实；内联器有时已经完成这一步。

阅读注解
设计

边界检查可以移动，契约仍在

先集中验证长度和地址，再进入内循环，是保留安全条件与减少重复工作的常用组织方式。

测量

一个瓶颈会遮住另一个

取消调用后性能不变，可能说明内循环已受另一条更长的依赖链限制。

5.6 · 用局部累积器缩短读改写链Eliminating Unneeded Memory References

原书：印刷 550 页 / PDF 551 页

data_t acc = IDENT;
for (long i = 0; i < length; ++i)
    acc = acc OP data[i];
*dest = acc;

combine4 把中间值放在局部变量 acc，最终只写一次 *dest。汇编中 acc 往往保存在寄存器；每一轮不再需要从结果地址载入、算术、再存回。加速的原因应在这条依赖链上解释，而不仅是“局部变量更快”。

但两段代码在允许 dest 指向 data 内部时可能不等价。以乘积、data 的内容为 [2, 3, 5]、dest=&data[2] 为例，先把 *dest 设为 1 后，逐轮写回的版本把末项改为 2、6，最后又读到 6，结果成为 36；局部累积且结束才写入的版本读取原始 2、3、5，得到 30。该优化需要调用契约排除这种重叠，或由调用者明确选择新的语义。

习题 5.4 展示编译器怎样在每轮仍写内存的同时，把下一轮要用的累积值保存在 xmm0。它避免冗余载入，但保留会影响别名读取的存储，因而比简单删掉全部中间存储需要更细致的判断。

把别名反例逐轮展开：两个版本各自从一份新的 [2,3,5] 开始。逐轮写回版先把末项设成单位元 1，数组成为 [2,3,1]；读取 data[0]=2 后，末项变 2；读取 data[1]=3 后，末项变 6；到 i=2，读的已经是这个 6，所以写回 6×6=36。局部版只改 acc，数组在整个读取过程中仍是 [2,3,5]，故 acc 依次为 1、2、6、30，最后才把 30 写到末项。要省掉中间写入，就必须先证明以后不会通过另一条路径读到那些写入。

阅读注解
正确性

把别名情形列入例子

最后一个元素被中途改写，下一轮乘数就改变了。

数据流

寄存器化没有消除算术相关

acc 的新值仍依赖旧值；下一步优化将围绕这条相关展开。

5.7 · 从数据依赖预测性能下界Understanding Modern Processors

原书：印刷 553 页 / PDF 554 页

5.7.1 · 总体操作：顺序的结果，重叠的执行

现代乱序处理器前端预测取指、译码并分派操作；执行单元在输入准备好时发起运算。不同操作可以同时飞行，完成顺序也可能不同。退休阶段按程序顺序提交可见状态，使异常和分支恢复仍能对应顺序程序。寄存器重命名给不同版本的寄存器分配不同内部位置，从而消除“碰巧用了同一名字”的假相关；它不能消除一个加法真正需要上一次加法结果的相关。

5.7.2 · 功能单元：延迟与吞吐是两个问题

原书原理 · 功能单元给出吞吐下界

The throughput bound gives a minimum bound for the CPE based on the maximum rate at which the functional units can produce results.

中文陈述。即使各次运算完全独立，有限的执行单元也限制单位时间能够产出的结果数。若有 C 个同类单元、每个单元的发射间隔为 I 周期，每元素需要一次该运算时，其资源下界为 CPE≥IC。

把下界写成“完成 n 项至少要多久”更容易看清除法。k 条链均分 n 次归约，每条有约 n/k 次串行运算，一次需 L 周期，故时间至少约 (n/k)L；再除以 n 项，得到 L/k。另一方面，C 个单元每 I 周期一共接收 C 项，完成 n 项至少约 nI/C 周期，除以 n 得 I/C。实际时间要同时满足这些限制，所以取最大值。它们会在执行中重叠，不能把两个下界再相加。

5.9.1 · 多个累积器

中文陈述。当所用运算满足结合律和交换律时，可以把输入分组，各组独立归约，最后合并结果。这样改变了分组与执行顺序，所以这些代数性质必须在实际采用的数值模型中成立。

下面按奇偶下标建立两条乘积链，每条约处理一半元素，使相关下界降为 L2。本页的无符号模运算满足所需性质；有符号 C 运算须保证变换前后的中间值均可表示，浮点另见后面的舍入反例。

原书 §5.9.1，印刷 572 页 / PDF 573 页。

data_t a0 = IDENT, a1 = IDENT;

    a0 = a0 OP data[i];
    a1 = a1 OP data[i+1];
}

*dest = a0 OP a1;

若有 k 条均衡的独立链，理想相关下界为 Lk；浮点乘法 L=5，两个单元每周期各接一项，吞吐下界是 0.5，所以 5k≤0.5 要求至少 10 条链，才有机会触到该运算的吞吐限制。继续增加链数还可能让寄存器溢出。

用四个数看“独立”：乘积 [2,3,5,7] 分给 a0 和 a1，a0 依次做 1×2=2、2×5=10；a1 依次做 1×3=3、3×7=21；最后做 10×21=210。计算 3×7 不需要等待 2×5 的结果，因而两条链可以交叠。所谓并行机会来自这种输入独立性；它不要求程序显式创建两个线程，也不保证编译后真的同时执行。

5.9.2 · 重结合：把旧累积值移到较浅的位置

/* 左结合：旧 acc 经两次乘法才能进入下一轮 */
acc = (acc * data[i]) * data[i+1];
/* 重结合：右侧乘积可提前准备 */
acc = acc * (data[i] * data[i+1]);

第二个式子的内部乘积不依赖旧 acc，可以与上一轮的工作重叠；跨迭代反馈只通过最后一次乘法，每两项的相关代价由 10 降为 5。总乘法次数没有减少，改变的是最长依赖链。习题 5.8 将三项的五种合法括号形状逐一比较。

5.11.1 · 寄存器溢出

每条累积链都要长期保存一个值，循环还需要指针、界限和临时值。可用寄存器不够时，编译器把一部分值放到栈槽，导致额外载入和存储。于是增加累积器虽降低 L/k，却同时增大访存与指令开销；曲线可能反向变慢。应看循环汇编中是否出现对栈地址的反复读写，而不是只看源代码有多少变量。

5.11.2 · 分支预测与错误预测代价

规则循环的退出分支通常易预测；合并两个随机交错的有序数组时，“哪边当前元素小”的分支则难预测。猜错后机器丢弃错误路径工作并从正确位置重新取指，因此同样 n 次比较可能有很不同的时间。

long x = src1[i1], y = src2[i2];
int take = x < y;
dest[k++] = take ? x : y;
i1 += (size_t)take;
i2 += (size_t)(1-take);

这里先读两个合法元素，再让条件决定值和索引增量。编译器有机会使用条件传送，具体是否生成 cmov 要检查汇编。这个变换必须保留 while(i1<n && i2<n) 的外层保护，不能为了少一个分支而提前读取已耗尽数组。若候选分支包含昂贵计算或无效地址，条件传送也未必适合。

5.12 · 理解载入、存储以及它们之间的相关Understanding Memory Performance

原书：印刷 589 页 / PDF 590 页

5.12.1 · 载入性能

顺序数组的地址由基址和索引产生，后续地址不依赖前一次载入的内容，可以提前发起多次读取。链表遍历 p = p->next 的下一地址就藏在本次载入结果里，即使每次都命中缓存，载入延迟也串成相关链。因此“全部在 L1”只消除了较慢层级的缺失等待，没有消除地址依赖、端口限制和载入延迟。

5.12.2 · 存储性能与存储转发

存储需要地址和值两个输入，通常先进入存储缓冲区。随后对同一地址的载入，必须看到先前存储的新值；机器可能从缓冲区转发，但这一相关仍有代价。若地址暂未明确，处理器还需要推测并检查两个访问是否冲突。

for (long i=0; i<n; ++i) dest[i]=src[i];

对 a=[0,1,…,999]，copy(a+1,a,999) 总是从尚未覆盖的后一项读，结果为 [1,2,…,999,999]；copy(a,a+1,999) 则让第一步写出的 0 成为第二步读取的输入，最终全为 0。后者每轮“存储→下一轮载入”串起来，原书测为 5.0 CPE，前者为 1.2。这段前向循环与 memmove 的重叠保证不同，不能互换语义。

前缀和也有类似问题：每轮读 p[i-1] 再写 p[i] 会形成存储与载入相关；把上次和留在寄存器中，可把反馈链缩为浮点加法本身。习题 5.11、5.12、5.19 依次分析这两层限制和进一步重结合的机会。

这里 copy 的参数顺序约定为 copy(src, dest, n)。用短数组 [0,1,2,3] 手推即可区分两种调用。copy(a+1,a,3) 先做 a[0]=a[1]，得 [1,1,2,3]；再做 a[1]=a[2]，得 [1,2,2,3]；最后得 [1,2,3,3]。反过来 copy(a,a+1,3) 依次写 a[1]、a[2]、a[3]：每次读取的前一项刚被改成 0，于是得到全零。参数顺序、下标和被修改的对象必须一起看。

double polyh(double a[],double x,long degree) {

    return result;
}

原书：印刷 566—567 页 / PDF 567—568 页

void merge(long src1[],long src2[],long dest[],long n) {
    long i1=0,i2=0,id=0;
    while(i1<n && i2<n) {
        if(src1[i1]<src2[i2]) dest[id++]=src1[i1++];
        else dest[id++]=src2[i2++];
    }
    while(i1<n) dest[id++]=src1[i1++];
    while(i2<n) dest[id++]=src2[i2++];
}

原书：印刷 589 页 / PDF 590 页

解答

static void merge(const long *a,const long *b,long *d,size_t n) {
    size_t i=0,j=0,k=0;
    while(i<n && j<n) {
        long x=a[i],y=b[j]; int take=x<y;
        d[k++]=take?x:y; i+=(size_t)take; j+=(size_t)(1-take);
    }
    while(i<n) d[k++]=a[i++];
    while(j<n) d[k++]=b[j++];
}

take 为 0 或 1，决定要写出的值和哪个索引增加。相等时 take=0，保留原程序先取第二个数组的行为。外层边界判断确保两个候选读取均有效；两个尾循环照旧。C 源表达的是选择，具体编译器可能使用条件传送，也可能生成分支，应以汇编确认。

例如当前两项为 x=3、y=7，比较 x<y 得 take=1，输出 3，i 加 1、j 加 0；若 x=9、y=7，则 take=0，输出 7，i 加 0、j 加 1。用 1−take 正好让另一侧执行相反的增量，确保每轮只消费一个输入。只要两数组各自有序，较小的头元素就是尚未输出元素中的最小值，因此这个选择保持归并的正确性。

void psum2(const float *a,float *p,size_t n) {
    if(n==0) return;
    float last=a[0];
    p[0]=last;
    for(size_t i=1;i<n;++i) {
        last=last+a[i];
        p[i]=last;
    }
}

last 是上一前缀的寄存器候选，每轮从旧 last 经一次加法得到新 last；存储 p[i] 不再位于下一轮反馈路径上。依赖下界缩到 3 CPE。这里保留 p[0]=a[0]，连有符号零的位模式也按原式初始化；实验中的从 +0 开始版本用于有限普通值，应注意 −0 的初值差别。a 与 p 可以完全相同而原地计算；任意部分重叠的契约仍需单独说明。

static uint64_t dot6x1(const uint64_t *u, const uint64_t *v, size_t n) {

        r += u[i]*v[i]; r += u[i+1]*v[i+1]; r += u[i+2]*v[i+2];

5.15 · 六路展开、六个累积器

原题（中文翻译）

static uint64_t dot6x6(const uint64_t *u, const uint64_t *v, size_t n) {
    uint64_t r0=0,r1=0,r2=0,r3=0,r4=0,r5=0; size_t i=0;

        r0+=u[i]*v[i]; r1+=u[i+1]*v[i+1]; r2+=u[i+2]*v[i+2];
        r3+=u[i+3]*v[i+3]; r4+=u[i+4]*v[i+4]; r5+=u[i+5]*v[i+5];
    }
    for (; i<n; ++i) r0+=u[i]*v[i];

}

r0—r5 独立，各自只承担约六分之一的加法；末尾将余数加到 r0，最后合并所有累积器。浮点相关下界降为 3/6=0.5，但每对仍需两次载入，资源下界为 1，所以 1.01 与载入吞吐限制相符。整数也受同一输入供给限制。浮点合并改变求和顺序，应用需接受相应误差。

C：八路多项式求值
static double split8(const double *a,double x,size_t degree) {
    double x2=x*x,x4=x2*x2,x8=x4*x4,r[8]={0};
    size_t count=degree+1,blocks=count/8,tail=count%8;
    for(size_t j=0;j<tail;++j) r[j]=a[blocks*8+j];
    while(blocks>0) {
        --blocks;
        for(size_t j=0;j<8;++j) r[j]=a[blocks*8+j]+x8*r[j];
    }
    double result=r[7];
    for(size_t j=7;j>0;--j) result=r[j-1]+x*result;
    return result;
}

将次数加一得到系数数目，再分成 blocks 和 tail；最高不完整块只初始化存在的余数位置，其他位置从零开始。这里假定 degree+1 可表示且数组足够大。参考模型无 FMA 时，一条 Horner 链反馈 8 周期，八链摊到每系数 1 周期；每系数还需要一次加法、一次乘法和一次载入，参考机加法吞吐也给出 1 的下界。

5.19 · 增加局部加法，缩短前缀反馈

原题（中文翻译）

练习 5.12已把前缀和降到浮点加法延迟限制的 3.00 CPE，简单展开仍不能突破。结合展开与重结合，写出低于本机加法延迟的版本。原书两路展开每轮三次加法、四路每轮五次，最佳实现为 1.67 CPE。分析吞吐和延迟如何约束最低 CPE。

原书：印刷 609 页 / PDF 610 页

解答

一种清楚的构造是先独立计算三项内部前缀 b0=ai，b1=ai+ai+1，b2=b1+ai+2，再把上一块总和 s 分别加到它们。两次局部加法和三次加 s，共五次/三项；新 s 只依赖 s+b2，因此跨块反馈每三项只有一次加法。

static void prefix3(const float *a,float *p,size_t n) {
    size_t i=0; float s=0;
    for(;n-i>=3;i+=3) {
        float b0=a[i],b1=b0+a[i+1],b2=b1+a[i+2];
        p[i]=s+b0; p[i+1]=s+b1; s=s+b2; p[i+2]=s;
    }
    for(;i<n;++i) { s=s+a[i]; p[i]=s; }
}

这段程序要求输入与输出的 n 个元素互不重叠，或 a==p 完全同址。完全同址时，每组三项都在任何写入之前读完，因此就地写回安全；部分重叠则会改变后续读到的输入。例如初始数组 [1,2,3,4]，让 p=a+1、n=3，串行版依次读到刚写入的值，输出 [1,2,4]，三项预读版输出 [1,3,6]。这组小整数没有舍入误差，差异来自访问次序。若接口要求保持任意部分重叠下的串行行为，应对这种情况使用串行实现。配套程序分别检查独立输出与完全同址的 0—130 长度。

参考机加法 L=3、吞吐每周期一次，延迟下界 3/3=1 CPE，操作数给出吞吐下界 5/3≈1.67；所以合并下界为 5/3，而不是把所有五次加法延迟串起来。载入、存储与地址生成还可能提高实际时间。

题目提及的两路形式可写 t = a[i] + a[i+1]; p[i] = s + a[i]; s = s + t; p[i+1] = s;，共三次加法。四路五加法的一种安排为 t0 = s + a[i]; t12 = a[i+1] + a[i+2]; t2 = t0 + t12; t3 = t2 + a[i+3]; p[i+1] = t0 + a[i+1];，并写出 p[i] = t0、p[i+2] = t2、p[i+3] = s = t3。它的反馈经过三次加法，给出 9/4=2.25 CPE；说明“更多展开、更少每项加法”不必然更快。

三项版本机观测中位数 0.258ns/element，串行版 0.721。以同机串行加法链作比较，确实降低了每元素反馈成本。数值上它改变浮点前缀的结合顺序，实验同时保留最终结果 1 与 2 的反例；若要求和原来的顺序前缀逐位一致，应保留串行关联。

多项式：指数分组与精确参考

split8 将 a[j+8k] 组成以 x8 为自变量的八条 Horner 链。先处理最高处不足八个系数，再逐整块向下；最后用 x 把八个余数组合。Python 用 Fraction 求出精确有理数参考，覆盖 129 个次数与 5 个 x，共 645 例。测试容差是绝对误差 10−12，输入和范围随程序固定。

    double x2=x*x,x4=x2*x2,x8=x4*x4,r[8]={0};
    size_t count=degree+1,blocks=count/8,tail=count%8;

按字填充：对齐、有效类型与边界

fill 先按字节走到对齐边界，中段每次写 sizeof(unsigned long) 字节，最后补余数。GNU/Clang 的 may_alias 类型明确允许访问其他有效类型的对象；在没有该扩展的编译器上，程序退回合法的字符访问。这个区别与硬件是否接受未对齐地址是两件事。当前目标采用 8 位字节、无填充位的 unsigned long，并提供 uintptr_t。Python 验证区间内容；真正的地址对齐与越界由 C 程序和内存检查器验证。

自测 5-1 · 别名

问题

xp、yp 都指向初值为 2 的同一个 long，做两次 *xp+=*yp，与一次 *xp+=2*(*yp)，分别得到多少？

解答

两次更新为 2→4→8；一次更新读到原值 2，写入 2+2·2=6。两种写法对这一合法小值输入不同，说明排除别名是变换前提。

自测 5-2 · 展开与依赖

问题

展开四项，但所有项仍依次加到同一个 acc，为什么可能仍受运算延迟限制？

解答

展开减少循环控制次数，数据图里却仍有四个连续依赖同一 acc 的操作。它们不能在前一个结果出现前完成；分为独立链才会缩短最长依赖路径。

自测 5-3 · 吞吐下界

问题

某操作 L=6 周期、I=1 周期，只有一个功能单元，用三个独立累积器时模型的 CPE 下界是多少？六个时呢？

解答

三个时 max(6/3,1/1)=2；六个时 max(6/6,1/1)=1。继续增加链数不能越过 1 的单元吞吐下界，还可能触及载入或寄存器限制。

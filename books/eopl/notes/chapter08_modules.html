8.1 简单模块系统：先固定公开边界

原书 §8.1，印刷 p.276 / PDF 299。

前几章的词法作用域已经能避免许多名字冲突，但一个大系统还需要回答：哪些名字是公开承诺，哪些只是内部辅助？两个实现能否互换？如何把一组必须协同工作的操作作为可复用单位？模块把这些问题带到程序语言本身，而不是只靠开发者记住约定。

本章程序先定义一列模块，再计算一个主表达式。简单模块是一组绑定；接口列出公开成员及其类型。检查器先验证模块体确实提供这些成员，随后客户端只根据接口检查。参数化模块则把“依赖哪一个模块”改成参数，使实现可以在不同上下文中复用。

公开视图

隐藏名字与隐藏表示是两件事

一个模块可以不导出辅助名字 x，却仍公开所有值都是 int。此时客户端不知道 x，但仍知道可对公开整数做减法。抽象类型将在8.2再隐藏“它是整数”这条信息。

作用域

边界不会自动带来递归

模块定义按先后顺序进入环境，模块体内部的值定义也按先后顺序可见。模块不能通过自己的限定名字递归引用自身；递归值应在模块体内显式使用 letrec。

8.1.1 例子：名字、顺序与可见性

原书 §8.1.1，印刷 p.276 / PDF 299。

Alice、Bob、Charlie 可以在各自实现中使用相同的辅助名字。其他人只依赖各模块发布的接口，不把对方的内部辅助函数也引入自己的作用域。图8.1所表达的这种可见性，可用下面的表读成三个位置的不同知识：

位置可以依赖的内容
模块体内部此前定义的内部值、私有辅助过程、此前模块的公开接口
模块声明接口自己已经声明的类型名字及外部公开类型
后续模块与主程序该模块接口承诺的限定成员，不包括私有定义

例 8.1 · 逐项求值与限定名字

类型：原书编号例子

印刷 p.277 / PDF 300。

module m1
 interface [a:int b:int c:int]
body [a=33 x=-(a,1) b=-(a,x) c=-(x,b)]
let a=10 in -(-(from m1 take a,from m1 take b),a)

定义依次得到 a=33、x=32、b=1、c=31。内部 x 参与计算，公开接口却只有 a、b、c。主程序的局部 a=10 与 m1.a 不同，最终先算 33−1，再减10，得到22。把最后一个 a 改成限定的 m1.a 会改变结果，说明两种引用走的是不同查找。

例 8.2 · 未使用的接口也必须正确

类型：原书编号例子

印刷 p.278 / PDF 301。

module m1
 interface [u:bool] body [u=33] 44

主程序虽然只返回44，接口把 u 声明为 bool，而模块体给出33。模块声明本身不成立，因此程序在执行前拒绝。

例 8.3 · 承诺的成员不能缺失

类型：原书编号例子

印刷 p.279 / PDF 302。

module m1
 interface [u:int v:int] body [u=33] 44

模块没有提供 v。额外成员允许隐藏，缺少公开成员却无法兑现接口；它们是不同方向的问题。

例 8.4 · 原书匹配保留顺序

类型：原书编号例子

印刷 p.280 / PDF 303。

module m1
 interface [u:int v:int] body [v=33 u=44] from m1 take u

实际声明顺序是 v、u，期望顺序是 u、v。原算法找到 u 后已经越过 v，不能倒回去，所以拒绝。习题8.8和8.17通过无序匹配模式接受该式，运行得到44。

例 8.5 · 模块依赖按声明顺序进入作用域

类型：原书编号例子

印刷 p.280 / PDF 303。

module m1
 interface [u:int] body [u=44]
module m2
 interface [v:int] body [v=-(from m1 take u,11)]
-(from m1 take u,from m2 take v)

m2 的 v=44−11=33，主程序再算44−33=11。反过来先定义m2时，它看不见尚未声明的m1；模块列表采用 let* 式作用域，并不隐含互递归。

module m2
 interface [v:int] body [v=-(from m1 take u,11)]
module m1
 interface [u:int] body [u=44]
-(from m1 take u,from m2 take v)
阅读注解
使用位置

限定名与局部名可以并存

例8.1中的外层 a=10 不改变 m1.a=33。限定引用先找模块，再找成员；普通 a 只查普通值环境。二者没有互相覆盖的名字竞争。

检查时机

未使用的坏接口也不能放行

例8.2的主程序只是44，仍必须拒绝模块把整数作为布尔值导出的承诺。模块检查器验证所有定义和承诺，而不是只检查执行时碰巧读取的成员。

8.1.2 实现：模块环境与接口满足

原书 §8.1.2，印刷 p.281 / PDF 304。

运行环境对模块名字保存模块值，对普通变量保存表达值；类型环境对模块名字保存接口，对普通变量保存类型。解释器计算限定引用时先找模块，再在它的公开绑定里找成员；检查器沿同一条名字路径，取回成员的类型。

处理一个定义序列时，每个右侧都使用已经扩展过的内部环境，随后才加入当前名字。结果模块仅收集本次定义建立的绑定，不把它计算时借用的外部环境整个导出。一个公开闭包可以保存该内部环境，因此隐藏辅助名字不会破坏闭包。

    [(module-proxy? fn)

(define (evaluate-module d env)
  (hash-update! (current-evaluations) (mdef-name d) add1 0)
  (define body-env (if (and (eq? (current-dependencies) 'imports) (not (eq? (mbody-kind (mdef-body d)) 'scope)))
                       (runtime-scope env #f) env))

静态过程先从模块体推得实际接口，再与声明的期望接口比较。这里的满足关系含义是：任何满足左接口的模块，也能满足右接口的全部承诺。更多公开能力的模块可以被用在只要求较少能力的位置。

Iactual<:Iexpected

原书简单接口的比较是有序子序列扫描。期望列表为空时已经满足；实际列表先耗尽则缺项；名字相同就比较类型并同时前进，不同就只跳过实际声明。这允许私有字段夹在公开字段中，却保留例8.4的顺序限制。

(define (body-interface b env)
  (match (mbody-kind b)
    ['scope (body-interface (second (mbody-args b)) (scope-tenv env (first (mbody-args b))))]
    ['defs
     (define local env)
     (simple-iface

                                (set! local (bind-type local n t)) (decl 'type n t)]

                         (begin (set! local (bind-module local n (fresh-key n) t)) (decl 'module n t))
                         (begin (set! local (bind-value local n t)) (decl 'value n t)))])))]
    ['let (match-define (list bs rest) (mbody-args b))
          (define ts (map (lambda (x) (value-type (cdr x) env)) bs))
          (body-interface rest (for/fold ([v env]) ([p bs] [t ts]) (bind-value v (car p) t)))]

    ['local (body-interface (second (mbody-args b)) (check-module (first (mbody-args b)) env))]
    ['var (module-type-iface (lookup (tenv-modules env) (car (mbody-args b)) 'module-unbound))]
    ['proc
     (match-define (list ps rest) (mbody-args b)) (define local env)
     (define normalized
       (for/list ([p ps])
         (define k (fresh-key (parameter-name p))) (define i (normalize-interface (parameter-iface p) local k))
         (set! local (bind-module local (parameter-name p) k (seal-view i)))

     (proc-iface normalized (body-interface rest local))]

     (match-define (list f args) (mbody-args b))

     (unless (proc-iface? fi) (type-error 'module-kind b "attempt to apply a simple module"))
     (unless (= (length args) (length (proc-iface-params fi))) (type-error 'arity b "module argument count differs"))

     (for ([p (proc-iface-params fi)] [i is] [index (in-naturals)])
       (define expected (instantiate-result (parameter-iface p) (take (proc-iface-params fi) index) (take is index)))

(define (check-module d env)
  (when (assq (mdef-name d) (tenv-modules env)) (type-error 'duplicate d "module name already in scope"))
  (define key (fresh-key (mdef-name d)))
  (define expected (normalize-interface (mdef-iface d) env key))
  (define b (mdef-body d))
  (when (and (eq? (current-dependencies) 'depends-on) (not (eq? (mbody-kind b) 'scope)))
    (type-error 'dependencies d "module body needs dependency clause"))
  (define actual (body-interface b (if (and (eq? (current-dependencies) 'imports) (not (eq? (mbody-kind b) 'scope)))
                                     (scope-tenv env #f) env)))
  (unless (interface-subtype? actual expected) (type-error 'interface d "module body does not satisfy interface: ~a" (mdef-name d)))
  (bind-module env (mdef-name d) key (seal-view expected)))

习题 8.1 · ★

原题

修改检查器，使它能检测并拒绝在同一个程序中定义两个同名模块的情况。

印刷 p.289 / PDF 312

解答与执行

为当前模块声明序列维护一个已见名字集合；检查一个新模块时，先检测名字是否已出现，再检查模块体并插入。若只检查最后构造的环境，后来的绑定可能已经遮蔽先前绑定，重复就被丢掉了。

check-module(definition, environment):
  reject if definition.name already belongs to this module scope
  actual = interface-of(definition.body, environment)
  require actual <: definition.interface
  return extend-module(environment, definition.name,
                       sealed(definition.interface))

实现位于本章检查器的 check-module。同一声明作用域内重复模块名被拒绝；不同模块体内互不相干的局部名字仍可分别使用。定义列表有 n 项，用散列表检测名字的期望成本为 O(n)；本实现为便于读环境链采用关联表，最坏为 O(n2)。这不计每个模块体自身的检查成本。两个空接口同名模块的程序也会报 duplicate，与导出成员是否使用无关。

习题 8.2 · ★

原题

过程 add-module-defn-to-env 还不完全正确：它把模块体定义的全部值都加入了环境，而不只是接口中声明的那些值。修改该过程，使加入环境的模块只含接口声明的值。add-module-defn-to-tenv 是否也有同样的问题？

印刷 p.289 / PDF 312

解答与执行

求值时先在内部环境执行全部定义，再按接口筛出公开成员。不能先删掉私有定义再求值，因为公开闭包可能依赖私有辅助过程。以例 8.1 为例，内部必须先有 x=32 才能计算 b 和 c，但对外只留下 a、b、c。

project(module, interface):
  for each value declaration name in interface:
    keep name -> lookup(module, name)
  for each module component name in interface:
    keep name -> project(lookup(module, name), component-interface)
  ignore type declarations at runtime

本章 project-module 实现该筛选；模块过程还用包装值筛选实参和结果。即使绕过静态检查直接调用 run 并传入 #:check? #f，读取隐藏成员也报 runtime-hidden。不过这仍是教学求值接口，不是把未检查程序变成安全程序。

类型环境没有相同的泄漏：add-module-defns-to-tenv 添加的是声明的 expected interface，而不是模块体推得的 actual interface。客户端查限定变量时只能在前者中找。两种环境都要保存抽象边界，但保存的对象不同。

习题 8.3 · ★

原题

修改语言语法，让限定变量引用写成 m.v，而不再写成 from m take v。

印刷 p.289 / PDF 312

解答与执行

把限定引用的文法改为 Expression ::= Identifier "." Identifier；词法器把点单独读出，解析器构造与旧写法相同的限定引用节点。类型查找和求值规则不变，所以无需重写接口满足关系。

module m
 interface [a:int b:int] body [a=4 b=-(a,1)]
-(m.a,m.b)

该程序检查为 int，运行得 1。为便于逐页运行原书输入，本实现同时接受 m.v 与 from m take v；多层成员采用同一条路径表示。类型中的限定名字也能用相同的点号记法，但静态值名字和类型名字仍分别查找。

习题 8.4 · ★

原题

按照习题 7.24 扩展表达式语言，使其支持同一个 let 中的多个声明、多参数过程，以及同一个 letrec 中的多个声明。

印刷 p.289 / PDF 312

解答与执行

参数、实参和递归声明都由单项改为列表。一次调用必须同时比较参数数量与各位置的类型，不能把“一个多参数过程”误当成“返回另一个过程”。多绑定 let 的各个右侧在旧环境检查和求值；把所有结果一次加入新环境。letrec 则先把整个递归组的过程签名预绑定，再逐个检查正文。

let x=7
in let x=1 y=x
   in -(y,x)

letrec bool even(x:int)=if zero?(x) then zero?(0) else (odd -(x,1))
       bool odd(x:int)=if zero?(x) then zero?(1) else (even -(x,1))
in (even 12)

第一式得到 6，说明 y=x 使用外层 7；第二式得到真，说明 odd 在 even 的定义中已经可见。本章解析器、检查器和运行器均支持这些形式；重复形参、重复 let 名字和调用实参数量错误分别拒绝。

习题 8.5 · ★

原题

允许在模块体中使用 let 与 letrec 声明。例如，应当能够写出：

module even-odd
 interface
  [even : int -> bool
   odd : int -> bool]
 body
  letrec
   bool local-odd (x : int) = ... (local-even -(x,1)) ...
   bool local-even (x : int) = ... (local-odd -(x,1)) ...
  in [even = local-even
      odd = local-odd]

印刷 p.290 / PDF 313

解答与执行

让模块体成为递归语法：除定义序列以外，还可有 let ... in ModuleBody 与 letrec ... in ModuleBody。它们只扩展用于继续分析、执行模块体的局部环境，最后仍只导出方括号序列中的公开成员。完整版本如下：

module even-odd
 interface [even:(int -> bool) odd:(int -> bool)]
body letrec bool local-odd(x:int)=if zero?(x) then zero?(1) else (local-even -(x,1))
            bool local-even(x:int)=if zero?(x) then zero?(0) else (local-odd -(x,1))
in [even=local-even odd=local-odd]
(from even-odd take even 12)

输入 12 得到真；输入 13 时 even 得到假。local-even 与 local-odd 共享递归环境，所以互相调用正常；客户端只能取得 even、odd，不能取得 local-even。递减到零的这份奇偶程序要求非负整数；类型检查不会证明该终止条件。

习题 8.6 · ★★

原题

允许在模块体中出现局部模块定义。例如，应当能够写出：

module m1
 interface
  [u : int
   v : int]
 body
  module m2
   interface [v : int]
   body [v = 33]
  [u = 44
   v = -(from m2 take v, 1)]

印刷 p.290 / PDF 313

解答与执行

局部模块定义也返回一个扩展过的模块环境，但这个环境只用于其后面的模块体。实现上对局部定义递归调用与顶层相同的模块检查/求值过程，再处理剩余 ModuleBody。

module m1
 interface [u:int v:int]
body module m2
 interface [v:int] body [v=33]
 [u=44 v=-(from m2 take v,1)]
from m1 take v

内部 from m2 take v 得 33，所以 m1.v 得 32；程序体中的 from m2 take v 被拒绝。局部模块 m2 不是 m1 的普通值成员，也不会因为参与计算而自动导出。

原题

习题 8.8 · ★★

原题

在当前语言中，模块体必须按照接口中的顺序产生各个值，但这个限制很容易去掉。请修改实现，去掉这一顺序限制。

印刷 p.290 / PDF 313

解答与执行

先按原顺序检查所有定义，再用“名字到声明”的索引比较接口。期望接口中的每个名字都必须在实际接口中出现，且对应声明类型相容；匹配成功后不删除早先出现过的其他名字。与原书双列表扫描不同，比较不再要求期望列表是实际列表的有序子序列。

本章通过 #:unordered? #t 启用这个扩展。例 8.4 在原书顺序模式中被拒绝，启用后检查为 int、运行得到 44。接口名字在本实现中必须唯一，因此每次查找没有“选哪一个同名成员”的歧义。建立散列表并逐个查找可做到期望 O(a+b)；目前教学版本使用列表查找，最坏 O(ab)。

习题 8.9 · ★★

原题

我们曾说模块系统应当记录模块之间的依赖关系。请给 SIMPLE-MODULES 增加这种能力：要求每个模块体和程序体都有一个 depends-on 子句。模块 m 中不再能看见此前的所有模块，只有在它的 depends-on 子句中列出的先前模块才在作用域内。例如，考虑程序：

module m1 ...
module m2 ...
module m3 ...
module m4 ...
module m5
 interface [...]
 body
  depends-on m1, m3
  [...]

在 m5 的模块体中，只有来自 m1 或 m3 的限定变量在作用域内。即使 m4 导出了值 x，引用 from m4 take x 也应判为类型不正确。

印刷 p.290 / PDF 313

解答与执行

依赖声明限制的是可见的模块环境：从先前已经检查的模块中选出列出的名字，值环境、类型别名与命名接口按各自词法规则保留。模块体和主程序都在这个受限环境中检查，运行时也选出同一批模块。没有声明的模块即使已经求值，也不能被当前代码引用。

module m1
 interface [x:int] body depends-on [x=7]
module m2
 interface [y:int] body depends-on m1 [y=from m1 take x]
depends-on m2
from m2 take y

以 #:dependencies 'depends-on 运行得到 7。叶模块写空依赖子句；删去 m2 的 m1 依赖，或删去主程序的 m2 依赖，均在静态检查时失败。重复依赖、未知或尚未声明的依赖也拒绝；单纯列出依赖不会使模块递归。

习题 8.10 · ★★★

原题

也可以用类似 depends-on 的机制控制模块体何时求值。请给 SIMPLE-MODULES 增加这种能力：要求每个模块体和程序体有一个 imports 子句。它与 depends-on 类似，但还要求：只有当某个其他模块通过 imports 子句导入该模块时，模块体才求值。

因此，假如语言中有 print 表达式，下面的程序应先打印 2、3、1，再返回 33。这里各模块都使用空接口，因为我们只关心模块体的求值顺序。

module m1
 interface [] body [x = print(1)]
module m2
 interface [] body [x = print(2)]
module m3
 interface []
 body
  import m2
  [x = print(3)]
import m3, m1
33

印刷 p.291 / PDF 314

解答与执行

模块定义先登记“模块体、定义时环境、求值状态和结果缓存”，不立即运行。导入一个模块时先导入它列出的依赖，按从左到右的顺序强制求值；完成后缓存整个公开模块值。此后再导入同一模块复用缓存，副作用只发生一次。状态可取 new、busy、done；busy 的重复强制报告导入环。当前模块仍只能依赖先前定义的模块，正常语法下依赖图已经无环。

题面叙述写 imports，示例写 import，本实现接受两种拼写。示例的叶模块没有子句，按空导入处理；这意味着它们看不见此前模块，并不意味着默认导入全部模块。运行输出单独保存在 execution-output，测试不会把宿主日志当成语言输出。

习题 8.11 · ★★★

原题

修改检查器，使用 INFERRED 作为表达式语言。本题需要修改 <:-decls，比较类型时不能再直接使用 equal?。例如，下面模块中的 f，类型推导引擎可能报告为 (tvar07 -> tvar07)，但这个模块应当被接受：

module m
 interface [f : (int -> int)]
 body [f = proc (x : ?) x]

另一方面，即使推导引擎同样报告 (tvar07 -> tvar07)，下面的模块也应被拒绝：

module m
 interface [f : (int -> bool)]
 body [f = proc (x : ?) x]

印刷 p.291 / PDF 314

解答与执行

为同一次程序检查保留一份合一状态。每个缺省类型位置分配鲜变量；同一个变量绑定的后续使用共享这份类型。检查模块体得到实际类型后，把实际类型与接口要求合一，而不是直接比较尚含未知量的语法树。

恒等过程的参数、结果共享同一个未知量。要求 int→int 时，两次约束都把它定为 int，成功；要求 int→bool 时，先得到 int，随后又要求 bool，冲突。不能为每次成员比较重建合一器，否则一个共享过程可能在不同成员处被误当成不同的类型。

module m
 interface [f:(int -> int) g:(bool -> bool)]
body [f=proc(x:?) x g=f]
0

该式必须拒绝：f 与 g 是同一个单态绑定。运行接口使用 #:inferred? #t；默认模式仍要求 CHECKED 的具体标注。发生检查同第七章，未知量不能被绑定到包含自身的有限类型。组合到模块过程时，还要先应用已经求得的替换，再对齐参数身份；否则未知量里保存的旧参数身份可能逃过重命名，使合法的接口被误拒绝。

8.2 声明类型的模块：把表示藏在边界内

原书 §8.2，印刷 p.292 / PDF 315。

第二章用接口约定区分数据类型的实现者和使用者，但单靠值名字的封装还不能阻止使用者依赖表示。假如接口把 point 公开为整数序对，客户端仍能自行拆对、交换坐标，破坏实现者维护的几何不变量。

透明类型声明把一个名字公开地等同于另一种类型；抽象类型声明只公开这个类型的存在和可用操作。模块体里仍可把它实现成整数或序对，但客户端没有获得这条等式。抽象性由检查器执行，运行器无需在每个整数外面再套一个特殊盒子。

阅读注解
类型身份

相同表示不构成相同抽象类型

两个模块即使都把 t 定义为 int，客户端看到的两个 t 仍不同。可以共享的等式必须由 transparent 声明明确公布，不能从相同运行位模式推断。

表达能力

接口保证类型关系，不证明算术定律

succ:t→t 和 pred:t→t 只说明输入输出如何组合，不证明它们互为逆。表示关系与整数代数律需要另行给出；一个满足类型接口的错误算术实现仍可能算错。

8.2.1 例子：透明类型与抽象类型

原书 §8.2.1，印刷 p.293 / PDF 316。

Alice 的 point 若声明为 transparent point = pairof int * int，确实缩短了注解，但 Bob 仍能 unpair 后只改 y，不顾 x 与 y 的约束；把 point 改为 opaque，Bob 只能通过 initial-point、increment-x、get-x 操作点。不能合法拆对，自然也不能借某个坐标位置猜测表示。

原题

解答与执行

原样移动不行，因为 and、not、to-bool 的原定义都对表示值使用了整数操作；模块外只知道抽象 t，不知道 t=int。不过“不能原样搬动”不等于“无法在外部实现同样操作”。若仍保留公开观察器 to-bool，可以在模块外重写 and 和 not：

let and=proc(x:from mybool take t) proc(y:from mybool take t)
         if (from mybool take to-bool x) then y else from mybool take false
in let not=proc(x:from mybool take t)
         if (from mybool take to-bool x)
         then from mybool take false else from mybool take true
in if (from mybool take to-bool
        ((and (not from mybool take false)) from mybool take true))
   then 11 else 22

两种布尔表示都得到 11。反过来，移除 to-bool 后，仅用 true、false、and、not 不能实现 t→bool 的观察器：这些操作只产生或继续传递 t，没有把 t 转为原生 bool 的消去操作。比如 proc(x:from mybool take t) zero?(x) 会被检查器拒绝。

习题 8.14 · ★

原题

考虑下面对 mybool 的另一种定义（见例 8.13）：

 interface
  [opaque t
   true : t
   false : t
   and : (t -> (t -> t))
   not : (t -> t)
   to-bool : (t -> bool)]
 body
  [type t = int
   true = 1
   false = 0

在本章纯 PROC-MODULES 的语言中，不存在这样的良类型 int 程序。用如下关系连接两种内部表示：

true 与 false 的对应值属于该关系。逐项代入可见：not 把对应的真/假同时翻转；and 在对应输入上得到对应输出；to-bool 在对应输入上得到相同的原生布尔值。客户端的抽象 t 值只能由公开常量和操作构造，不能对它使用整数运算。

对良类型客户端的求值推导归纳：整数、原生布尔与分支保持相同观察；抽象值按上述关系对应；闭包在对应环境中接收对应实参；递归调用的任何有限终止推导也保留这一关系。因此若程序返回 int，两边返回相同整数；不是只说某几个例子恰好相同。对不终止的递归可按有限展开层数说明同样的不可区分性。

把抽象值直接作为最终结果交给宿主打印，确实可能看到 13 与 0，但那时程序结果类型是抽象 t，已经不满足题目的 int 条件。加入表示反射、类型强制转换或其他能破坏抽象边界的机制后，必须重新检查结论。

习题 8.15 · ★★

原题

编写一个实现简单表抽象的模块。表应当类似于环境，不过它把整数关联到整数，而不是把符号关联到 Scheme 值。接口提供表示空表的值，以及两个过程 add-to-table 和 lookup-in-table，分别类似于 extend-env 和 apply-env。由于本语言只有单参数过程，要用 Currying（见习题 3.20）获得相当于多参数过程的能力。可以用一个对任何查询都返回 0 的表表示空表。下面给出使用该模块的例子：

module tables
 interface
  [opaque table
   empty : table
   add-to-table : (int -> (int -> (table -> table)))
   lookup-in-table : (int -> (table -> int))]
 body
  [type table = (int -> int)
   ...]

let empty = from tables take empty
in let add-binding = from tables take add-to-table
in let lookup = from tables take lookup-in-table
in let table1 = (((add-binding 3) 300)
                 (((add-binding 4) 400)
                  (((add-binding 3) 600)
                    empty)))
in -(((lookup 4) table1),
     ((lookup 3) table1))

该程序应当具有类型 int。表 table1 把 4 关联到 400，把 3 关联到 300，因此程序值应为 100。

印刷 p.301 / PDF 324

解答与执行

把表表示为整数到整数的过程。空表忽略键并返回 0；扩展表产生一个新过程，查询键相同时返回新值，否则把查询交给旧表。相同键的最新绑定自然遮蔽旧绑定，旧表仍然可用。

module tables
 interface [opaque table empty:table add-to-table:(int -> (int -> (table -> table)))
   lookup-in-table:(int -> (table -> int))] body [type table=(int -> int)
 empty=proc(key:int) 0
 add-to-table=proc(key:int) proc(value:int) proc(old:table)
               proc(query:int) if zero?(-(query,key)) then value else (old query)
 lookup-in-table=proc(key:int) proc(tab:table) (tab key)]
let empty=from tables take empty in let add-binding=from tables take add-to-table
in let lookup=from tables take lookup-in-table
in let table1=(((add-binding 3) 300) (((add-binding 4) 400) (((add-binding 3) 600) empty)))
in -(((lookup 4) table1),((lookup 3) table1))

查询 4 先越过最外层的键 3，命中 400；查询 3 立即命中最外层的 300，而不再取旧的 600，差为 100。建立一层表只建立闭包，成本 O(1)；查询最坏经过 d 层，成本 O(d)，闭包链占 O(d) 空间。空表对负键同样返回 0。

习题 8.17 · ★★

原题

像习题 8.8 一样，去掉模块体必须按照接口顺序产生值的限制。但要记住，定义仍须遵守作用域规则，尤其是类型的作用域规则。

解答与执行

module m
 interface [transparent t=int x:t]
 body [x=7 type t=int]
from m take x

8.3 模块过程：让依赖成为参数

原书 §8.3，印刷 p.311 / PDF 334。

如果 to-int 的正文中固定写 from ints1 take pred，它就绑定在 ints1 上，不能直接复用到 ints2。模块过程把整个算术模块作为参数，一起接收 t、zero、succ、pred、is-zero 的约束。这样既能替换实现，又不会把不同表示的操作混装成一个接口。

模块过程的接口类似函数类型，却还给参数模块一个名字，因为结果接口可以引用它的类型成员。普通过程的结果类型不包含值形参名字，这里结果中的 from ints take t 却必须在应用后解释为具体实参的 t。

阅读注解
复用单位

模块参数携带一组相互关联的操作

不能分别随意给出 zero、succ、pred，因为这些值必须共同使用同一个 t。模块接口把这组依赖及其类型等式一起作为参数。

闭包

模块过程仍在定义位置找自由名字

应用提供的是形参模块，其他依赖来自模块过程创建时保存的环境。若改用调用位置环境，就变成动态作用域，模块复用会随调用位置悄悄改变行为。

      else (loop -(up,1) -(down,-1) (s a) (p b))

习题 8.20 · ★

原题

补全下面模块的定义，构造一个模块过程：它接收一个算术实现，为该实现产生求和与求积过程。plus 使用印刷 p.33 的定义，times 使用类似方法。

module sum-prod-maker
 interface
  ((ints : [opaque t
            zero : t
            succ : (t -> t)
            pred : (t -> t)
            is-zero : (t -> bool)])
   => [plus : (from ints take t
               -> (from ints take t
                   -> from ints take t))
       times : (from ints take t
                -> (from ints take t
                    -> from ints take t))])
 body
  [plus = ...
   times = ...]

印刷 p.316 / PDF 339

解答与执行

印刷 p.33 的递推是：零加 y 得 y；非零 x 加 y，先把 x 取前驱，递归后再对结果取后继。它在非负 x 上计算加法；若把负 x 不断取前驱，就永远到不了零。下面保留这个逐步移项的正向递推，同时用相反方向的分支补全负数情况。

查看完整模块实现
module sum-prod-maker
interface ((ints:[opaque t
  zero : t
  succ : (t -> t)
  pred : (t -> t)
  is-zero : (t -> bool)]) => [plus:(from ints take t -> (from ints take t -> from ints take t))
                        times:(from ints take t -> (from ints take t -> from ints take t))])
body module-proc (ints:[opaque t
  zero : t
  succ : (t -> t)
  pred : (t -> t)
  is-zero : (t -> bool)])
 let z=from ints take zero in let s=from ints take succ in let p=from ints take pred
 in let z?=from ints take is-zero
 in [negate=proc(x:from ints take t)
      letrec from ints take t loop(up:from ints take t, down:from ints take t, a:from ints take
        t, b:from ints take t)=
       if (z? up) then a else if (z? down) then b
       else (loop (p up) (s down) (p a) (s b))
      in (loop x x z z)
     plus=proc(x:from ints take t) proc(y:from ints take t)
      letrec from ints take t loop(up:from ints take t, down:from ints take t, a:from ints take
        t, b:from ints take t)=
       if (z? up) then a else if (z? down) then b
       else (loop (p up) (s down) (s a) (p b))
      in (loop x x y y)
     times=proc(x:from ints take t) proc(y:from ints take t)
      let negative-y=(negate y)
      in letrec from ints take t loop(up:from ints take t, down:from ints take t, a:from ints
        take t, b:from ints take t)=
       if (z? up) then a else if (z? down) then b
       else (loop (p up) (s down) ((plus y) a) ((plus negative-y) b))
      in (loop x x z z)]

plus 的两份计数器从 x 出发，分别取 pred 与 succ；两份累积值从 y 出发，分别取 succ 与 pred。若 x 非负，第一份到零时累积值是 x+y；若 x 负，第二份到零时得到同一个和。

times 同样同时把 x 向两侧推进，每轮分别累加 y 与其相反数；先到零的一侧决定返回正向还是负向累积。私有 negate 也用相同的双向方法构造相反数。因而不仅自然数，正负整数与零都可处理；没有观察抽象值的具体整数编码。

在抽象算术操作为常数成本的条件下，plus 需要 O(|x|) 次操作；这份重复加法的乘法需要 O(|x||y|+|y|) 次操作。两个整数表示各自运行时，还原后的 3+4 均为 7、3×4 均为 12；负数的表示结果也按同一表示关系验证。类型接口只保证这些操作如何组合；succ/pred 真正满足整数代数律，仍需由算术实现本身证明。

解答与执行

若只让 x、y 同时不断取前驱，两个负整数可能永远到不了零。可以同时跟踪向前驱和向后继走的两组 x、y，哪组 x 先到零，就在同一组检查 y 是否也为零：

查看完整模块实现
module equality-maker
interface ((ints:[opaque t
  zero : t
  succ : (t -> t)
  pred : (t -> t)
  is-zero : (t -> bool)]) => [equal:(from ints take t -> (from ints take t -> bool))])
body module-proc (ints:[opaque t
  zero : t
  succ : (t -> t)
  pred : (t -> t)
  is-zero : (t -> bool)])

  letrec bool loop(xp:from ints take t, xn:from ints take t, yp:from ints take t, yn:from ints
    take t)=
   if (z? xp) then (z? yp) else if (z? xn) then (z? yn)

每轮两组分别都移动一步，因此每组中 x 与 y 的整数差保持不变。无论 x 正、负还是零，总有一组在 |x| 轮到零；这时对应 y 为零当且仅当原来两数相等。在后继、前驱和零判定满足整数表示定律且每次调用终止的前提下，该算法对所有由这些操作建立的整数表示均成立，需要 O(|x|) 次接口操作，并未使用宿主对内部表示值的相等比较。

8.3.2 实现：依赖结果与接口逆变

原书 §8.3.2，印刷 p.318 / PDF 341。

模块过程值保存形参、模块体和创建环境。模块变量查环境；模块过程应用先求操作符与实参，再把实参加入保存环境。这个运行结构与第三章的词法闭包相同，只是被绑定的是模块值，不能与普通表达值混为一类。

静态应用分三步：确定操作符是过程接口；检查实参接口满足形参接口；将形参的类型身份替换为实参实际导出的身份，得到结果接口。原书先限制实参为模块标识符，正是因为限定类型需要一个模块路径。习题8.24–8.26再把一般模块体纳入应用。

判断两个过程接口是否可替换时，实参要求逆变，结果承诺协变。假设左边的模块过程要被放在右边要求的位置：右侧调用者可能提供的任何实参，都必须够左侧过程使用，所以右侧参数接口必须满足左侧参数接口；左侧实际产生的结果，则必须满足右侧结果要求。

P2<:P1R1<:R2⇒(P1⇒R1)<:(P2⇒R2)

上式省略了结果中的参数名字。实际比较前，必须先把两边不同的形参绑定对齐到同一个鲜身份，再比较依赖结果；否则只是把 A 改成 B 的拼写差异，也会被误判为类型不同。若参数接口给出额外的透明等式，还要把比较中得到的同一类型关系带到结果中。

查看实现 · interface-subtyping
(define (interface-subtype? actual expected)
  ;; Normalize solved variables before alpha-renaming bound module identities.
  (set! actual (map-interface resolve actual))
  (set! expected (map-interface resolve expected))
  (define equations (make-hash))
  (define (subst t)
    (define current (resolve t))
    (cond [(hash-has-key? equations current) (subst (hash-ref equations current))]
          [(ty? current) (map-type subst current)] [else current]))
  (define (equal-types? a b)
    (equate! (subst a) (subst b) (list a b)) #t)
  (define (match-decl a b)
    (match* ((decl-kind a) (decl-kind b))
      [((or 'type 'opaque) 'opaque)
       (define x (subst (decl-payload b))) (define y (subst (decl-payload a)))
       (unless (equal? x y) (hash-set! equations x y)) #t]
      [('type 'type) (equal-types? (decl-payload a) (decl-payload b))]
      [('value 'value) (equal-types? (decl-payload a) (decl-payload b))]
      [('module 'module) (go (decl-payload a) (decl-payload b))]
      [(_ _) #f]))
  (define (go a b)
    (match* (a b)
      [((simple-iface as) (simple-iface bs))
       (let loop ([rest as] [needs bs])
         (cond [(null? needs) #t] [(null? rest) #f]
               [(current-unordered?)
                (define hit (findf (lambda (d) (eq? (decl-name d) (decl-name (car needs)))) as))
                (and hit (match-decl hit (car needs)) (loop as (cdr needs)))]
               [(eq? (decl-name (car rest)) (decl-name (car needs)))
                (and (match-decl (car rest) (car needs)) (loop (cdr rest) (cdr needs)))]
               [else (loop (cdr rest) needs)]))]
      [((proc-iface aps ar) (proc-iface bps br))
       (and (= (length aps) (length bps))
            (let ([left ar] [right br] [arename '()] [brename '()])
              (define (renames iface pairs)
                (for/fold ([out iface]) ([p pairs]) (rename-key out (car p) (cdr p))))
              (and (for/and ([ap aps] [bp bps])
                     (define common (fresh-key 'parameter))
                     (set! arename (append arename (list (cons (parameter-key ap) common))))
                     (set! brename (append brename (list (cons (parameter-key bp) common))))
                     (define ai (renames (parameter-iface ap) arename))
                     (define bi (renames (parameter-iface bp) brename))
                     (set! left (rename-key left (parameter-key ap) common))
                     (set! right (rename-key right (parameter-key bp) common))
                     (go bi ai)) ; arguments contravariant
                   (go left right))))] ; results covariant
      [(_ _) #f]))
  (with-handlers ([exn:fail:typing? (lambda (_) #f)]) (go actual expected)))

习题 8.24 · ★

原题

目前，模块应用只允许用于标识符。如果尝试检查 (m1 (m2 m3)) 这样的应用，现有的应用类型规则会出什么问题？

印刷 p.323 / PDF 346

解答与执行

原应用规则把实参模块名替换进结果接口。(m2 m3) 是一个模块体，不是模块路径，不能直接放进 from ... take t 的限定名位置。因此问题不仅是解析器不认识括号：即使递归算出内部应用的接口，也还缺一个能在结果依赖中稳定引用该实例的名字。

可在内部给这个结果分配鲜模块身份，先检查并记录它的接口，再用这个身份实例化外层结果。这个身份对应一次实际模块值，不能把两个语法相同的模块构造一律看成同一实例，也不能为了给类型找名字而在运行时重复求值。习题 8.26 的实现采用这一方法。

习题 8.25 · ★

  (set! actual (map-interface resolve actual))
  (set! expected (map-interface resolve expected))

          [(ty? current) (map-type subst current)] [else current]))

       (define x (subst (decl-payload b))) (define y (subst (decl-payload a)))
       (unless (equal? x y) (hash-set! equations x y)) #t]
      [('type 'type) (equal-types? (decl-payload a) (decl-payload b))]
      [('value 'value) (equal-types? (decl-payload a) (decl-payload b))]
      [('module 'module) (go (decl-payload a) (decl-payload b))]

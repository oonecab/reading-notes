一个程序为什么会得到这个结果

我们平时用语言写程序，通常把变量查找、过程调用、赋值和异常当成已经规定好的规则。EOPL 把这些规则本身变成研究对象：同一个变量名究竟指向哪次绑定？过程返回以后，它创建的局部变量为什么还能被另一个过程使用？赋值改变了名字、值，还是存放值的位置？异常发生以后，原本剩下的计算去了哪里？

作者的办法是设计一系列足够小的语言，为它们写解释器。解释器接受程序的抽象语法树，按照明确规则逐步求出结果。这样，“这个语言采用词法作用域”就能落到一个具体选择上：调用过程时，使用过程创建时保存的环境。把这一处改为调用者的环境，就得到另一种作用域规则；序言的闭包例子会把两种结果算出来。

全书不断重复同一种研究动作：先分清要描述的行为，再选一种表示，把规则写成可运行的程序，最后用小程序检验差异。第 1、2 章让我们能够处理语法树和抽象数据；第 3、4 章建立“名字、值、位置”的运行模型；第 5、6 章把控制过程显式化；第 7 章在运行以前推断一些性质；第 8、9 章把这些工具组合成模块和对象系统。

因此，读这本书最有用的收获，是能从一个语言特性追到它的规则和实现位置。词法分析、语法分析在附录 B 中提供必要工具，控制变换、名字消除和类型分析也涉及编译思想；完整编译器后端、机器码生成与工业优化不在本书的主讲范围内。

先走共同基础，再分成两条路线

九章各向前推进了什么

下面沿原书顺序说明每章解决的问题。页码给出实际内容范围，章间空白页另见来源清单。每一项的“读完应能解释”是伴读归纳的学习目标。

1 · 归纳定义的数据集

Inductive Sets of Data · pp.1–30 / PDF 24–53 · 习题 1.1–1.36

解释器要处理的是层层嵌套的程序，因此先要知道“合法的数据怎样构造”。作者从归纳定义、推理规则和语法产生式出发，展示数据结构怎样给出递归程序的骨架：处理列表时区分空表与非空表，处理语法树时按构造分支，递归调用对应更小的子结构。

结构归纳同时解释这种程序为什么正确。辅助参数用来记录当前子问题之外的上下文，例如元素编号的起点；它的含义需要独立说明，才能看懂递归调用怎样保持约定。

读完应能解释：为什么每个递归分支都对应合法构造，为什么子问题确实变小，以及 occurs-free? 如何区分自由出现与被绑定的变量。

原书小节：1.1 递归定义数据（1）；1.2 导出递归程序（12）；1.3 辅助过程与上下文参数（22）；1.4 习题（25）。

2 · 数据抽象

Data Abstraction · pp.31–55 / PDF 54–78 · 习题 2.1–2.31

同一种数据可以有不同表示。自然数可以用整数或一元结构表示；环境可以用带标签的数据结构，也可以用接收变量名并返回绑定值的过程表示。只要构造和查询操作满足相同规格，使用它们的解释器就能保持不变。

环境由此成为后续全书的第一个核心抽象：empty-env、extend-env、apply-env 规定空环境、增加绑定与查询的行为。再用递归数据类型、构造器和模式分支表示 AST，解释器就能直接处理结构，而不必反复辨认字符串。

读完应能解释：“抽象接口不变”和“内部表示不变”有什么差别；为什么具体语法中的括号、关键字不必全部出现在 AST 中。书中的 define-datatype 与 cases 是配套工具，不能直接当作所有 Scheme 实现都内置的语法。

原书小节：2.1 用接口规定数据（31）；2.2 表示策略（35）；2.3 递归数据的接口（42）；2.4 数据类型工具（45）；2.5 抽象语法（51）。

阅读第 2 章完整笔记与习题解答 →

3 · 表达式

Expressions · pp.57–101 / PDF 80–124 · 习题 3.1–3.44

LET 先引入整数、差、零测试、条件、变量和局部绑定。表达式的意义由它的结构和当前环境决定：let 的右侧在旧环境求值，主体在加入新绑定的环境求值。PROC 再把过程变为可以传递和返回的值，过程体的自由变量由闭包保存的创建环境解释。LETREC 则让过程在自己的主体里找到自身，形成递归绑定。

章末进一步问：既然变量绑定由程序文本决定，能否在运行前把名字换成位置？词法地址翻译器用静态环境计算位置，运行时环境只保存值。这里既要保持绑定关系，又要区分“翻译时的名字表”和“运行时的值表”。

读完应能解释：为什么调用点附近的新同名变量不会改写旧闭包的自由变量；为什么删除变量名以后还能得到相同结果。这里的“环境”是名字与绑定的关系，尚不需要第 4 章可变的存储。

原书小节：3.1 规格与实现（57）；3.2 LET（60）；3.3 PROC（74）；3.4 LETREC（82）；3.5 作用域与绑定（87）；3.6 消除变量名（91）；3.7 实现词法地址（93）。

4 · 状态

State · pp.103–138 / PDF 126–161 · 习题 4.1–4.42

纯表达式中，求值主要产生一个值；加入赋值后，还会改变之后计算能观察到的状态。作者用存储把“位置”和“位置上当前的值”分开。EXPLICIT-REFS 让引用作为值显式出现，通过 newref、deref、setref 操作；IMPLICIT-REFS 则让变量绑定到位置，普通变量读取自动取出该位置中的值。

这种分离使别名与共享可以被追踪。两个名字若最终指向同一位置，修改其中一个就可能影响另一个；过程若捕获同一个位置，多次调用便能共享计数器状态。随后，原书比较可变对、按值/按引用传参、按名/按需传参，重点是参数何时求值、传入什么，以及求值结果是否缓存。

读完应能解释：遮蔽新建绑定与赋值更新位置的区别。按值传递可变对象仍可能共享对象，这不等于把调用者的变量位置按引用传入；按需对结果缓存，在存在副作用时也不能简单视为按名的等价优化。

原书小节：4.1 计算效果（103）；4.2 EXPLICIT-REFS（104）；4.3 IMPLICIT-REFS（113）；4.4 MUTABLE-PAIRS（124）；4.5 参数传递变体（130）。

5 · 传递续文的解释器

Continuation-Passing Interpreters · pp.139–191 / PDF 162–214 · 习题 5.1–5.58

求 -(e1,e2) 的左操作数时，后面还要保存左值、求右值并做减法。普通递归把这些待办工作藏在宿主语言的调用链里；续文（continuation）把“拿到当前值之后做什么”表示成显式参数。它可以是过程，也可以是带标签的数据结构。

待办工作一旦成为数据，解释器就能决定什么时候恢复、丢弃或保存它。异常沿续文寻找处理器，线程调度保存可恢复的计算，蹦床由循环驱动下一步；寄存器化又把参数变为显式寄存器，展示离低层控制结构更近的实现。

读完应能解释：尾位置复用同一个续文，非尾位置为什么需要保存额外工作。控制栈不继续增长，不等于所有数据都只占常量空间；显式续文仍可能形成长链。书中线程是在解释器内调度的模型。

原书小节：5.1 续文解释器（141）；5.2 蹦床（155）；5.3 命令式解释器（160）；5.4 异常（171）；5.5 线程（179）。

6 · 续文传递风格

Continuation-Passing Style · pp.193–232 / PDF 216–255 · 习题 6.1–6.40

上一章是把一个熟悉的解释器改为 CPS；这一章把同样的方法推广为一个程序变换：输入 CPS−IN 的 AST，输出 CPS−OUT 的 AST。变换器为非尾位置的中间结果引入名字，把后续计算装进新的续文，再将调用组织为尾形式。

读变换规则时，要追踪求值顺序、生成名字的新鲜性和每个结果交给谁。加入打印、存储等效果后，某些原先可直接使用的表达式也必须按顺序处理；控制效果则解释为何有些跳转直接使用先前捕获的续文。

读完应能解释：解释器运行一个程序与变换器输出另一个程序的差别。阶乘的续文链能进一步化为累乘器，依赖乘法组合的特殊结构；一般 CPS 变换本身不会自动获得这种空间压缩。

原书小节：6.1 写 CPS 程序（193）；6.2 尾形式（203）；6.3 转换为 CPS（212）；6.4 计算效果（226）。

7 · 类型

Types · pp.233–274 / PDF 256–297 · 习题 7.1–7.30

如果不运行程序，能否排除“对过程做减法”“调用一个整数”等错误？类型系统给表达式分配类型，并用规则约束子表达式的组合。CHECKED 要求过程参数等位置写出类型；类型检查器使用类型环境，检查过程体与调用是否一致。

INFERRED 把部分类型留成未知量，从程序结构生成等式，再以合一和替换求解。occurs check 排除某个类型变量必须等于包含自身的有限类型表达式的情况。这里的类型变量是求解中的未知量，和程序中取值的变量属于不同层次。

读完应能解释：类型检查如何保守地排除规定的错误，以及为什么“通过检查”不保证终止或满足业务目的。正文的推断器并未完整实现 let 多态；多态绑定、Algorithm W 和赋值下的限制在习题 7.28–7.30 中继续展开。

原书小节：7.1 值与类型（235）；7.2 给表达式分配类型（238）；7.3 CHECKED（240）；7.4 INFERRED（248）。

8 · 模块

Modules · pp.275–324 / PDF 298–347 · 习题 8.1–8.27

程序变大以后，需要把一组绑定组织成单元，并说明外部可以依赖哪些名字与性质。SIMPLE-MODULES 用接口限定可见成员；OPAQUE-TYPES 再把类型表示隐藏起来，让客户只能通过接口操作值。例如两种内部整数编码都能实现同一组自然数操作，客户不应依赖编码细节。

PROC-MODULES 接着把模块作为参数，构造可复用的模块过程。类型检查必须验证实际模块符合参数接口，并把结果接口中依赖参数的类型名字替换成实际模块对应的名字。接口由此成为可以执行检查的抽象边界。

读完应能解释：透明类型与不透明类型怎样改变客户能做的操作；为什么“实现都用整数”不足以说明两个抽象类型可混用。模块过程的参数兼容方向和结果方向不同，也为下一章理解函数子类型做了铺垫。

原书小节：8.1 简单模块系统（276）；8.2 声明类型的模块（292）；8.3 模块过程（311）。

9 · 对象与类

Objects and Classes · pp.325–371 / PDF 348–394 · 习题 9.1–9.42

对象把一组需要协调变化的状态与操作它们的方法放在一起。CLASSES 用类描述字段和方法，通过继承共享实现，并在发送消息时按对象的实际类选择方法。字段位置、方法所属类、接收者 self 与 super 的查找起点需要分别保存，才能解释遮蔽和重写。

TYPED−OO 再组合类型检查、接口和子类型。一个对象只有一个创建它的类，却可以满足多个类型。过程子类型在结果方向协变、参数方向逆变，原因是替代后的过程必须接受调用者原来有权传入的每一个参数，并返回原来承诺的结果种类。

读完应能解释：普通方法调用为什么动态分派，而 super 从当前方法所属类的父类开始查找，接收者仍是原对象。原书检查器的保证有边界：p.358 明确保留未初始化字段及显式调用 initialize 的问题，转换失败也可能是运行时错误。

原书小节：9.1 面向对象编程（326）；9.2 继承（329）；9.3 语言（334）；9.4 解释器（336）；9.5 带类型语言（352）；9.6 类型检查器（358）。

附录是两种不同的回读入口

附录 A· For Further Reading（pp.373–378 / PDF 396–401）追溯归纳、语义、续文、类型与对象等思想的文献来源。遇到“这个方法从哪里来、还能怎样形式化”时回到这里；文献年代与历史判断按原书 2008 年语境理解。

附录 B· The SLLGEN Parsing System（pp.379–391 / PDF 402–414）把文本分成 token，再按语法产生 AST。它介绍 LL(1) 约束、扫描规格、arbno 与 separated-list，附习题 B.1–B.5。完成第 2 章抽象语法后就可以并行阅读，帮助第 3 章解释器接收文本输入。参考文献在 pp.393–400，索引在 pp.401–410。

始终分清这四种对象

很多难点来自把不同对象都笼统叫作“上下文”。读解释器时，可以在纸边写出下面四项，并问当前函数到底接收了哪几项。它们逐章引入，不要求每一种语言都同时使用四项。

对象回答的问题一个具体内容主要位置
环境 Env这个名字当前绑定到什么？PROC 中 x↦10；IMPLICIT-REFS 中 x↦ℓ第 2—4 章
存储 Store这个位置现在装着什么？ℓ↦10；赋值后同一位置装着 20第 4 章起
续文 Cont当前结果出来以后还要做什么？“拿到右操作数后，用已保存的 25 减它”第 5、6 章
类型环境 TEnv静态分析时，这个名字应有什么类型？x : int，f : int → int第 7—9 章

还要留意 ExpVal 与 DenVal：前者是表达式能求出的值，后者是变量绑定所指的东西。在 PROC 中两者都可以是整数、布尔值或过程；在 IMPLICIT-REFS 中，变量绑定到位置，因此 DenVal 是引用，而普通表达式返回的 ExpVal 不包含引用。这一处区分能解释为什么读取变量要经过环境和存储两步。

相同接口不等于相同成本

把环境从列表换为过程表示，或把续文从过程换为数据结构，可以保持目标语义；时间、空间、调试方式却可能改变。行为等价与性能判断需要各自的依据。

第一次怎样读，之后回到哪里

第一次建议先读两篇序文，再按 1 → 2 → 3 → 4 建立共同基础。不要急着同时实现所有语言：先能给一个递归过程写出输入输出约定，画出一个 AST，再手算嵌套 let 和闭包调用。到第 4 章，用一张环境表和一张存储表记录每次赋值，避免凭熟悉语言的直觉猜规则。

接下来，想理解异常、调度和控制变换，就沿 5 → 6；想理解静态检查和程序组织，就先读 7，再分别读 8、9。这里的路线沿用原书依赖，学习重点由伴读归纳。无论从哪条分支出发，遇到“变量为什么取到这个值”都回到第 3 章；遇到“改了一处为什么另一处也变了”都回到第 4 章。

需要的基础是数据结构、递归、基本归纳，以及至少一种命令式语言和一种支持过程作为值的语言的经验。不熟悉 Scheme 时，先认清前缀调用、lambda、列表操作、条件分支和局部绑定；再把书中 define-datatype/cases 理解为构造与按变体分支。Scheme 阅读能力直接关系到能否分辨宿主机制与被定义机制。

每读一个新构造，选一个能手算完的程序，先预测结果，再执行，再改动一条规则观察差异。习题穿插在正文中，其中常包含另一种设计；本书全部编号题的入口清单在原书定位清单中，序言题的完整题干与解答见习题 0.1。

从一个闭包实验开始

序言的闭包例子在外层把 x 绑定为 10，创建 f，再在调用处把另一个 x 绑定为 20。词法规则得到 15，动态规则得到 5；页面逐步展示为什么取到不同的 x。

配套 Python 3.10+ 程序显式保存环境，接受六种 AST 构造。它是伴读原创实验，完整源代码可在序言展开，也可下载 scope_demo.py。程序用标准库即可运行；整数为精确整数，递归深度受宿主限制。

python3 books/eopl/code/scope_demo.py
# 预期输出：
# lexical: 15
# dynamic: 5

上面命令从 Reading Notes 仓库根目录执行。若单独下载文件，进入下载目录运行 python3 scope_demo.py。完整接口、错误条件和模型边界见程序说明。

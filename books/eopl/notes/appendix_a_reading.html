从数据定义走向递归与证明

原书印刷 p.373 / PDF 396。

附录 A 记录了作者写作本书时受到的影响。原附录没有编号小节；这里按学习问题组织，并保留原书的作者与年份。读完九章之后，可以带着一个具体解释器问题回到相应来源，先弄清它要证明什么，再扩展自己的实现。

递归与符号计算的入门路线包括 Friedman 与 Felleisen 的 The Little Schemer（1996）、Felleisen 与 Friedman 的 The Little MLer（1996），以及 How to Design Programs（2001）。它们与第一章相接的地方，是从数据的构造方式确定过程分支，再为递归调用选择更小的输入。

原书把自底向上定义和推理规则联系到 Plotkin（1975、1981），把自顶向下的观察联系到余归纳传统；“Follow the Grammar”则联系到 Burstall（1969）的结构归纳。Morris 与 Wegbreit（1977）的子目标归纳适合递归调用没有直接沿语法子结构下降的情况。附加参数所携带的上下文，又与 Knuth（1968）的属性文法相连。

例如给树上每片叶子加上深度时，树是递归下降的结构，深度是随调用向下传递的上下文。需要分别证明“每个子树都被处理”与“传入子树的深度恰好增加一”；只验证几棵树不能替代这两个归纳步骤。回读第一章时，可以据此区分递归形状和辅助不变量。

阅读注解
证明对象

先确定对什么做归纳

沿语法递归时，归纳假设对应直接子结构。带累加器或上下文参数时，往往要先加强命题，使归纳假设包含这些参数的含义。

定义与性质

规则枚举不自动等于全部语义

归纳定义给出允许构造的对象；证明解释器对这些对象满足某个性质，还需要检查每条构造规则和每次递归调用。

解释器怎样成为语言的数学说明

原书印刷 p.374 / PDF 397。

第二章的 define-datatype 与 cases 受到 ML 数据类型与模式匹配设施的启发。第三章的无名表示使用 de Bruijn（1972）的索引；词法轮廓图则联系到 Johnston（1971）。这些来源分别回答“语法树有什么形状”和“一个变量出现应指向哪个绑定”。

作者从 Turing 的通用机器、von Neumann 机器和 McCarthy（1960）的元循环解释器讨论解释器的历史。元循环的困难是：用一种语言定义自身时，读者仍须先理解用来解释的那部分语言。本书把解释器视为等式规格或大步操作语义的转写，让求值关系与实现步骤相互对应。

另一条路线是指称语义：将程序映射为描述行为的数学对象。原书列出 Plotkin（1977）、Winskel（1993）以及 Milne 与 Strachey（1976）。读者可以拿第三章的一条 let 规则比较：操作语义写出右侧求值与环境扩展的步骤，指称语义给出环境到表达值的数学映射；两种表述需要通过适当的对应关系连接。

Scheme 的历史、IEEE 标准与 R6RS 在原附录中另有来源。实际运行伴读程序时，应按程序说明使用 Racket 与 eopl 包；教材使用的构造、宿主实现设施和被解释语言仍需分清。

阅读注解
语法与含义

解析完成后还没有得到程序结果

抽象语法树是解释器的输入。环境、存储或续文如何改变，仍由语言的语义规则决定。

宿主依赖

用最少的宿主机制表达目标机制

显式构造环境或存储，能把依赖暴露出来。若直接借用宿主所有行为，就难以看出哪些性质来自目标语言的设计。

存储、参数传递与效果的共同问题

原书印刷 p.375 / PDF 398。

第四章的显式引用模型与 ML 的存储模型有关；隐式引用更接近具有可变局部变量的传统语言。Strachey（1967）的左值、右值及环境—存储模型，帮助解释为什么变量绑定的位置与位置中的值应分别讨论。

原书将按引用传递联系到 Fortran，将按名传递联系到 Algol 60，并将 thunk 与 Ingerman（1961）相连。按需在按名的延后计算上保存强制后的结果，接近记忆化；这个保存动作本身是一种效果。因此参数策略的差别既涉及结果，也涉及副作用发生的次数和次序。

Moggi（1991）与 Wadler（1992）的单子工作，为效果提供了系统组织方式。回读第四章时，可以先把解释器看成“输入表达式、环境和旧存储，返回值及新存储”的过程：每一步把新存储交给下一步，这已经暴露出顺序组合需要保存的信息。

阅读注解
别名

位置相同才产生相应的共享更新

两个变量当前数值相同，不等于它们共享位置。比较参数策略时，先画位置关系，再跟踪写入。

惰性效果

强制一次与反复强制可能得到不同观察

纯表达式可能只改变成本；带输出、赋值或异常的表达式还会改变可观察行为。

从续文到线程，再到编译

原书印刷 p.375 / PDF 398。

Reynolds（1993）整理了续文被多次独立发现的历史；Reynolds（1972）把元循环解释器变为 CPS。Landin 的 J 操作符与 Scheme 的 call-with-current-continuation 又把控制上下文暴露给程序。第五章的续文解释器与第六章的程序变换器，是沿这条路线完成的不同任务。

Wand（1980a）把续文用于轻量进程；原书线程讨论近似 POSIX，习题 5.56则以 Erlang 消息传递为背景。控制上下文被表示成数据后，暂停、恢复与调度才有了可明确操作的对象。

原书还追溯 RABBIT、ORBIT 与 Standard ML of New Jersey 编译器对 CPS 的使用。第六章采用 Danvy 与 Nielsen（2003）的一阶组合式算法；习题 6.30联系 Danvy 与 Filinski（1992）的高阶算法，习题 6.34讨论 A-normal form 这条替代路线。变换需要同时保持返回值、效果次序和变量绑定，不能只看目标程序是否处于尾位置。

阅读注解
两种CPS任务

解释器改写与源程序变换分别建立对应关系

第五章解释目标程序时显式传递续文；第六章产生另一份程序。它们的输入输出不同，正确性命题也不同。

控制与资源

尾调用不自动让所有空间开销消失

宿主调用栈、显式续文链及保留的环境应分别计量；数据化以后仍可能有随输入增长的堆对象。

类型、信息隐藏与对象的来源连接

原书印刷 p.376 / PDF 399。

附录把类型推导联系到 Hindley（1969）、Morris（1968）和 Milner（1978），把“先生成方程再求解”的分离联系到 Wand（1987）。第七章的单态约束推导、习题 7.28的 Hindley–Milner 多态，以及可变状态下的值限制，应作为不同层次理解。

信息隐藏的接口边界联系到 Parnas（1972）；抽象数据类型还可以用构造历史的树或观察行为的过程来表示。Reynolds（1975）、CLU、Standard ML 模块和 Leroy（1994）的工作，接上第八章通过类型身份约束客户端观察的做法。接口满足检查保证可见的类型与操作相容，表示定律仍需要另外论证。

对象路线从 Simula、Smalltalk、Actors 延伸到 Scheme 的对象表示与 CLOS。第九章的对象模型以 Java 为基础；原附录另列 Abadi 与 Cardelli（1996）的对象演算、Flatt 等（1998）的形式化子集以及 Featherweight Java。若要理解继承与子类型，适合先固定一个小模型，分别说明字段身份、方法选择和可替换性，再增加真实语言的其他机制。

阅读注解
静态结论

类型检查证明的性质取决于规则覆盖的范围

终止、表示不变量与字段初始化并不会因有类型就自动成立。回到相应规则检查前提，才能判断一个安全论证是否适用。

抽象边界

行为一样与类型身份一样是两件事

不同模块可以有同一表示却导出不同抽象类型；不同类可以实现同一接口。运行观察与静态身份需要分别跟踪。

带着全书主线回到文献

原书印刷 p.378 / PDF 401。

附录最后列出设计模式、语言史会议，以及 POPL、ICFP、PLDI 和相关期刊，构成原书写作时的研究背景。书目条目的作者、题名、年份可继续在原书 Bibliography，PDF 416–423核对。

收束本书时，可以用同一个小程序完成一次综合回读：先写数据定义与解析器，再解释变量的词法环境；加入引用时跟踪位置，加入控制时跟踪续文；最后给程序建立类型约束，并用模块或对象组织实现。每增加一种机制，先说明它改变了哪些观察，再决定需要怎样的规则和验证。

需要把字符串转换为这些数据结构时，继续阅读附录 B · SLLGEN 解析系统。这样，第一章从文法设计程序的起点，与最后从输入构造语法树的工具形成了完整的回路。

阅读注解
研究入口

用明确问题筛选文献

例如先问“为什么覆盖方法的参数逆变”，再找相应类型规则与证明，比把所有历史引用都当作下一轮必读清单更容易形成连续理解。

综合回读

每一层都保留可独立观察的对象

字符、token、AST、环境、存储、续文和类型各有职责；把它们分开，错误也就能定位到具体阶段。

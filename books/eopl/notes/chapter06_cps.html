6.1 手写 CPS：从上下文到参数

原书 §6.1，pp.193–203 / PDF 216–226。

第五章改写的是解释器，第六章把相同办法用于任意程序。关键不是把所有 return 换成一个 k 调用，而是给每处“等子调用返回以后继续”的工作起一个明确名字，并把它作为参数传给子调用。这个参数就是续文。

(define (fact/k n k)
  (if (zero? n) (k 1)
      (fact/k (- n 1) (lambda (v) (k (* n v))))))

读法是：如果 n=0，把 1 送给 k；否则先求 n−1 的阶乘，等结果叫 v，再把 n*v 交给旧 k。递归调用在尾位置，乘法被保存在新闭包里。与直接递归 fact 相比，这个版本显式化了待乘工作，却没有减少它的总量。

辅助过程的规格要对任意续文成立

fact/k(n,g) = g(fact(n))。这里 g 不是固定的恒等函数；归纳时递归调用使用新构造的续文，所以规格必须同时覆盖所有 g。这个条件连接了第一章的上下文参数与“No Mysterious Auxiliaries”：不能只验证 fact/k(n,identity)，却不给额外参数独立意义。

手工转换的四步可沿具体表达式读：过程增加 k；直接产生值就送给 k；尾调用沿用 k；非尾调用用新续文命名结果再继续。例如 +((f x),33,(g y)) 先 f(x)，再 g(y)，最后把两个结果与 33 相加交给原 k。后续工作的位置正是求值次序的显式说明。

f(x,lambda(a)
  g(y,lambda(b)
    k(a+33+b)))

fib 的两次递归需要两个阶段：先保存 n−2 和 k 等左值，再保存左值等右值。CPS 不把指数次重复计算自动变成动态规划；它改变控制表示，不改变算法复用策略。

特殊情况下续文可以压缩。阶乘里的续文都形如“把 v 乘一个数”，所以只保存这个数即可：单位续文用 1，新增乘 n 的帧变成更新 acc*=n，最终应用是 acc*v。由此得到 fact-iter。这依赖精确乘法的结合律与单位元，不适用于任意闭包或带舍入的数值语义。

阅读注解
控制等价

CPS 不是累加器的同义词

一般 CPS 能表达任意待续工作，通常要形成闭包链。只有某个程序的续文族具有封闭的代数表示时，才可压成一个或几个累加器。阶乘与求和是特别清楚的例子；树遍历和任意异常目标通常需要更丰富的数据。

原语边界

哪些调用仍能留在简单式里

书中把固定的算术、zero? 等当作无用户调用的已知原语，允许在 k 的实参中计算它们。未知 f/g/p 必须接续文，并被提升到尾调用。若某个“原语”会输出、修改存储或调用用户过程，就不能按相同理由视为简单。

习题 6.1 · ★

原题

考虑图 6.2：从 fact/k 中删掉 (set! pc fact/k)，从 apply-cont 中删掉 (set! pc apply-cont)。为什么程序仍能工作？

印刷 p.200 / PDF 223

解答与执行

删掉的是留在当前块的自跳转：驱动器进入 fact/k 时 pc 本来就是 fact/k，非零分支仍需下轮执行它；进入 apply-cont 时同理。真正从 fact/k 基例转到 apply-cont、从 end 转到 #f 的写入必须保留。

此结论以图 6.1/6.2 的累乘遗漏已经修正为前提。修正版省去这两个自跳转后，n=0…11 的实测都与独立阶乘一致；照原图未修正的代码会终止，却错误地返回 1。

习题 6.2 · ★

原题

对 n 作归纳，证明任意 g 都有 (fib/k n g) = (g (fib n))。

印刷 p.200 / PDF 223

解答与执行

定义域取非负整数，fib(0)=fib(1)=1。n=0、1 时 fib/k 直接执行 g(1)，即所需结论。设对小于 n 的参数和任意续文均成立，n≥2 时先把 fib(n−1) 交给一个新续文；该续文再求 fib(n−2)，最后执行 g(a+b)。

fib/k(n,g)
= fib/k(n-1, lambda(a) fib/k(n-2, lambda(b) g(a+b)))
= fib/k(n-2, lambda(b) g(fib(n-1)+b))
= g(fib(n-1)+fib(n-2))
= g(fib(n))

归纳假设必须量化“任意续文”，因为递归调用用的不是原 g，而是新构造的 lambda。有限验证用恒等、加一、乘三三种 g 与 n=0…11 对照直接 fib；它支持实现正确性，归纳才给出一般结论。

习题 6.3 · ★

原题

把下面每个 Scheme 表达式改写成 CPS。假定所有未知函数也已经改成 CPS。

  1. (lambda (x y) (p (+ 8 x) (q y)))
  2. (lambda (x y u v) (+ 1 (f (g x y) (+ u v))))
  3. (+ 1 (f (g x y) (+ u (h v))))
  4. (zero? (if a (p x) (p y)))
  5. (zero? (if (f a) (p x) (p y)))
  6. (let ((x (let ((y 8)) (p y)))) x)
  7. (let ((x (if a (p x) (p y)))) x)

印刷 p.201 / PDF 224

解答与执行

以下续文参数统一叫 k；第 1、2 项是新过程定义，其余是在现有上下文 k 中转换。算术和 zero? 是已知的简单原语，未知 p/q/f/g/h 都接额外续文参数。

  1. (lambda (x y k)
  (q y (lambda (v) (p (+ 8 x) v k))))
  2. (lambda (x y u v k)
  (g x y (lambda (a) (f a (+ u v) (lambda (b) (k (+ 1 b)))))))
  3. (g x y (lambda (a)
  (h v (lambda (b)
    (f a (+ u b) (lambda (r) (k (+ 1 r))))))))
  4. (if a
  (p x (lambda (r) (k (zero? r))))
  (p y (lambda (r) (k (zero? r)))))
  5. (f a (lambda (b)
  (if b
    (p x (lambda (r) (k (zero? r))))
    (p y (lambda (r) (k (zero? r)))))))
  6. (let ((y 8)) (p y (lambda (x) (k x))))
  7. (if a (p x (lambda (x) (k x)))
      (p y (lambda (x) (k x))))

第 6 项先在内层把 y 绑定到 8，再将 p(y) 的结果绑定到外层 x；两个 let 都要按各自的作用域理解。第 7 项右式中的 x 是外层 x，lambda 参数 x 只在后面的 k(x) 中遮蔽它。第三项先调用 g 再 h，最后 f；它是下一题比较求值顺序的关键例子。

习题 6.4 · ★★

原题

把以下过程分别改成 CPS：先用数据结构表示续文，再用过程表示，再把过程表示内联，最后写寄存器化版本。每种版本都使用下述 end-cont，测试整个尾递归计算中结束信息只出现一次。

(apply-cont (end-cont) val)
= (begin
    (eopl:printf "End of computation.~%")
    (eopl:printf "This sentence should appear only once.~%")
    val)
  1. remove-first（§1.2.3）。
  2. list-sum（§1.3）。
  3. occurs-free?（§1.2.4）。
  4. subst（§1.2.5）。

印刷 p.201 / PDF 224

解答与执行

chapter06_algorithms.rkt 提供四种可切换的完整表示，数据域沿用原书 Scheme 符号表与 λ 表达式。四个过程所需帧可明确枚举：remove-first 用 cons(head)；list-sum 用 add(head)；occurs-free? 的应用式用“若左边未找到则查右边”；subst 用“首部替换完再做尾部”和“把两部分 cons”。

remove-first(s,cons(a,ds),k):
  if s=a then k(ds)
  else remove-first(s,ds,lambda(v) k(cons(a,v)))
list-sum(cons(a,ds),k): list-sum(ds,lambda(v) k(a+v))
occurs-free?(s,app(a,b),k):
  occurs-free?(s,a,lambda(v)
    if v then k(true) else occurs-free?(s,b,k))
subst(new,old,cons(a,d),k):
  subst(new,old,a,lambda(v1)
    subst(new,old,d,lambda(v2) k(cons(v1,v2))))

空表、符号与 lambda 的边界分别在源码列出：遇到绑定了目标变量的 lambda 立即返回假；subst 只按 s-list 替换符号，不做捕获规避的 λ 替换。过程表示用 make-k 生成闭包，内联表示直接写上述 lambda；数据表示用标签列表分派；寄存器版把 task/k/v/pc 放入循环，visit/apply 之间跳转。

实际四版都检查了空输入、首个匹配、重复匹配、绑定遮蔽和嵌套表；每个独立调用的 end-count 都为 1。计数与题给打印承担相同观察职责；该性质是尾调结构检查的辅助，单靠“只打印一次”并不能证明所有调用均在尾位置。

习题 6.5 · ★

原题

把表达式改写成 CPS 时会选择其中过程调用的求值次序。把前面的各例改写成所有过程调用都按从右到左求值的 CPS。

印刷 p.201 / PDF 224

解答与执行

对习题 6.3，只有第 3 项有可以交换的独立未知调用：先 h(v)，再 g(x,y)，最后 f；其他六项的未知调用顺序受依赖或分支选择固定，沿用该题对应式。

(h v (lambda (b)
  (g x y (lambda (a)
    (f a (+ u b) (lambda (r) (k (+ 1 r))))))))

对 fib 改为先求 n−2，再求 n−1；对章首 cond 的双调用行先 g(y) 再 f(x)。对习题 6.4 的单递归 remove-first/list-sum 无变化；subst 先递归尾部再首部，最后仍按原顺序 cons。occurs-free? 的应用节点可以先查右再查左，但须保留短路，不应无条件计算两边。

subst(new,old,cons(a,d),k):
  subst(new,old,d,lambda(v2)
    subst(new,old,a,lambda(v1) k(cons(v1,v2))))
fib/k(n,k):
  if n<2 then k(1)
  else fib/k(n-2,lambda(b) fib/k(n-1,lambda(a) k(a+b)))

若过程含输出、异常或发散，更换次序可能更换效果和终止行为；这题是在明确选择另一种调用次序，不能据相同数值结果宣称效果等价。转换器的 right 模式实际用输出日志验证了右到左次序。

习题 6.6 · ★

原题

表达式 (lambda (x y) (+ (f (g x)) (h (j y)))) 中的过程调用有多少种求值次序？逐一写出按该顺序调用的 CPS 表达式。

印刷 p.201 / PDF 224

解答与执行

必须满足 g 在 f 之前、j 在 h 之前；两条长为 2 的链共有 6 种交错。外层加法必须等两边数值取得，不另产生可独立移动的未知调用。

  1. g → f → j → h

    (lambda (x y k) (g x (lambda (gx) (f gx (lambda (fx) (j y (lambda (jy) (h jy (lambda (hy) (k (+ fx hy)))))))))))

  2. g → j → f → h

    (lambda (x y k) (g x (lambda (gx) (j y (lambda (jy) (f gx (lambda (fx) (h jy (lambda (hy) (k (+ fx hy)))))))))))

  3. g → j → h → f

    (lambda (x y k) (g x (lambda (gx) (j y (lambda (jy) (h jy (lambda (hy) (f gx (lambda (fx) (k (+ fx hy)))))))))))

  4. j → g → f → h

    (lambda (x y k) (j y (lambda (jy) (g x (lambda (gx) (f gx (lambda (fx) (h jy (lambda (hy) (k (+ fx hy)))))))))))

  5. j → g → h → f

    (lambda (x y k) (j y (lambda (jy) (g x (lambda (gx) (h jy (lambda (hy) (f gx (lambda (fx) (k (+ fx hy)))))))))))

  6. j → h → g → f

    (lambda (x y k) (j y (lambda (jy) (h jy (lambda (hy) (g x (lambda (gx) (f gx (lambda (fx) (k (+ fx hy)))))))))))

六条次序均由可运行例子逐项记录调用日志。测试取 g(x)=x+1、f(x)=3x、j(y)=2y、h(y)=y+4，x=2、y=5 时六式均为 23，而日志各自严格匹配所列次序。

习题 6.7 · ★★

原题

写出图 5.4、5.5、5.6 的解释器对应的过程表示及内联表示。

印刷 p.201 / PDF 224

解答与执行

过程表示把每种帧映射成接 v 的闭包，value-of/k 继续调用构造器；内联表示把这些构造器的定义展开到使用处，同时把 apply-cont(k,v) 换成 k(v)。

;; procedural builder form
(eval left env (diff1-cont right env k))
(define (diff1-cont right env k)
  (lambda (v1) (eval right env (diff2-cont v1 k))))
(define (diff2-cont v1 k) (lambda (v2) (k (- v1 v2))))
;; inlined form
(eval left env
  (lambda (v1) (eval right env (lambda (v2) (k (- v1 v2))))))

(eval rator env (lambda (p)

习题 6.8 · ★★★

原题

把 §5.4 的异常解释器改为过程表示和内联表示。难点是有 apply-cont 与 apply-handler 两个观察器。提示：修改前面 §6.1 的方法，给每个过程增加两个参数，分别表示这两个观察器下的续文行为。

印刷 p.202 / PDF 225

解答与执行

给 eval 和 invoke 都传正常 k 与异常 h。普通帧的异常行为直接继承 h；try 的异常闭包负责把异常值绑定到处理器环境，用外层 k/h 求处理器；raise 的正常续文则调用 h。内联后规则如下。

eval(try body catch(x) handler,env,k,h)
 = eval(body,env,k,
        lambda(exn) eval(handler,extend(x,exn,env),k,h))
eval(raise e,env,k,h)
 = eval(e,env,lambda(exn) h(exn),h)
invoke(closure(x,body,saved),arg,k,h)
 = eval(body,extend(x,arg,saved),k,h)

过程表示把这两个行为包成一对观察器，内联表示在每个分支直接传 lambda。chapter05_cps.rkt 是完整实现；重抛走外层 h，正常返回走外层 k，不会重新进入同一个 handler。异常处理器的动态生存期与过程的词法捕获环境分开维护。

习题 6.9 · ★

原题

乘法的什么性质使前面的续文压缩优化成为可能？

印刷 p.203 / PDF 226

解答与执行

结合律让一串 v ↦ k·(n·v) 合并为 v ↦ (k·n)·v，单位元 1 表示 end。于是用一个数就能表示这类闭包链；并不需要交换律，因为相乘顺序可保持原样。

还需要封闭性和相同的数值语义：原书的精确整数满足条件；浮点乘法因舍入通常不满足严格结合律，有界整数的溢出策略也要单独检查。这个压缩只适用于“全部剩余工作都是乘一个数”的特殊续文，不能把任意控制上下文压成一个累加器。

习题 6.10 · ★

原题

为 list-sum 的续文设计一个像前面 fact/k 那样简洁的表示。

印刷 p.203 / PDF 226

解答与执行

把“加上已经遇见的这些数，再交给 end”压成它们的和 acc，空续文对应 0，新加法帧把 acc 改成 acc+a，应用续文为 acc+v。

(define (list-sum xs)
  (let loop ((xs xs) (acc 0))
    (if (null? xs) acc
        (loop (cdr xs) (+ acc (car xs))))))

对精确整数，结合律和单位元保证与递归求和相同；列表只扫描一次，控制记录和累加器个数有界。数字本身的大小与列表输入仍不属于这个常数控制空间结论。

6.2 尾形式：用语法约束控制行为

原书 §6.2，pp.203–212 / PDF 226–235。

要自动转换，先把目标语言的形状说清。CPS-IN 是多参数、多过程 LETREC；CPS-OUT 区分 SimpleExp 与 TfExp。SimpleExp 不执行用户调用，TfExp 才能含调用，而且它的运算符和实参都必须已经是 SimpleExp。由语法约束，把“求调用之后还得回来做事”的形状排除。

构造操作数位置尾位置
-(a,b)a、b无
zero?(a)a无
if t then a else bta、b
let x=e in beb
letrec f(xs)=p in b无立即求值的操作数过程正文 p、整体正文 b
proc(xs) b无立即求值的操作数将来执行的正文 b
(f a b)运算符 f 与全部实参调用本身在其外部上下文决定的位置

尾位置是语义关系，不是代码的“最后一行”。if zero?(x) then (f y) else (g z) 的分支各是尾位置；把整个 if 放进 +(if...,37) 的操作数后，分支取得的结果仍欠相加，就不再是整体的尾结果。proc 创建一个值，不运行正文；所以它可以简单，但目标语法仍要求它保存的正文为尾形式。

伴读例：简单式、尾形式与类型正确性

本章语法判定的对照

let f = proc(x) x in (f 3)
-((f 3),1)
let x = proc(y) (y x) in -(x,3)

第一式不是简单式，却是尾形式；第二式的调用在减法操作数中，不是尾形式；第三式按语法是尾形式，却把过程 x 当数字相减，会运行失败。SimpleExp/TfExp 是控制形状的分类，不能承担类型系统的职责。

目标解释器求简单式时只创建闭包、查变量和执行已知原语；遇到 call，把实参值一次绑定到闭包定义环境，直接进入过程正文。解释器层 k 从来不变，因而可以删去。目标程序中的显式 k 仍是普通过程值，不能因删去解释器 k 而删掉它。

查看实现 · target-simple
(define (value-of-simple s env)
 (match s
  [`(num ,n) n] [`(var ,x) (lookup env x)]
  [`(prim ,op . ,ss) (primitive op (map (lambda (a) (value-of-simple a env)) ss))]
  [`(list . ,ss) (map (lambda (a) (value-of-simple a env)) ss)]
  [`(proc ,xs ,b) (target-closure xs b env)]
  [_ (error 'simple "not simple")]))

原书也指出，递归求深的简单表达式仍可能占用宿主栈。若要求这一层也非递归，可先把每个嵌套原语结果用 let 命名，使差值/zero? 只接常量或变量。另一个边界是判定能力：语法尾形式是可检查的充分条件，不负责判断某个非尾调用是否永远不会执行，后者一般不可判定。

阅读注解
三种问题

简单、尾形式、类型各管一层

if 不是简单式，即使两支都只是数；调用不是简单式，即使它只返回实参。尾形式允许这些构造，只约束调用结果不会再被外层等待。类型正确性另外检查数值、布尔和过程的角色，所以一个通过尾形式检查的程序仍可因类型不符而失败。

递归深度

无用户调用不代表完全不用宿主栈

value-of-simple 按语法树递归下降，与调用用户过程是两种递归。固定输入大小下这部分栈有界，但输入可以是一棵任意深的原语树。6.18 的原子化使运行阶段每个原语只读固定数量的值，把嵌套结构的次序移到显式 let 链。

习题 6.12 · ★

原题

判断下列每个表达式是否为简单表达式。

  1. -((f -(x,1)),1)
  2. (f -(-(x,y),1))
  3. if zero?(x) then -(x,y) else -(-(x,y),1)

八项逐一转换的核心规则如下，所有递归调用都把后续工作放到 k 中。removeall 的原子匹配分支直接尾调删除尾表；保留分支先求 tail，再把 car cons 回去；嵌套分支先求 head、再 tail。occurs-in? 找到时 k(1)，未找到才继续。remfirst 先用 occurs 判断子表，命中后只改该子表并保持其后缀原样，避免删除多个。

depth 原版在比较及返回中重复求子深度，按原程序逐次转换会保留重复；depth-with-let 则把两个结果各求一次，再比较。map 先用转换后的 f 求首个元素，再递归尾表；f 也是 CPS 过程，不能仍按直接风格调用。every 的谓词失败立即 k(0)，不求其余元素。

map/k(f,l,k):
  if null?(l) then k(emptylist)
  else f(car(l),lambda(a)
         map/k(f,cdr(l),lambda(d) k(cons(a,d))))
fnlrgtn/k(s,n,yes,no):
  if null?(s) then no()
  else if number?(car(s))
    then if car(s)>n then yes(car(s))
         else fnlrgtn/k(cdr(s),n,yes,no)
    else fnlrgtn/k(car(s),n,yes,
           lambda() fnlrgtn/k(cdr(s),n,yes,no))

fnlrgtn 的失败续文负责“本子表没找到时查后缀”；成功续文不再触碰后缀。本实现用空表标记整个输入无匹配，避免与任意整数答案冲突。实际测试结果依次是 ((1) 2)、1、(1 (3) 3)、3、3、(1 4 9 16 25)、7、1。每项均先跑原 AST，再把转换输出序列化，经独立 CPS-OUT 解析器重读后运行。

对应目标转移步数是 34、31、26、109、53、30、31、25；depth 与带 let 版同为 3，但后者避免重复计算。这些步数是本解释器的状态转移计数，不是原书宿主的时间测量。

6.3 CPS 转换：给中间结果命名并固定次序

原书 §6.3，pp.212–226 / PDF 235–249。

转换器本身在编译时运行；它的输入和输出都是语法树。cps-of-exp(e,K) 中 K 是一棵目标 SimpleExp，表示运行时将被调用的续文过程；K 不是此刻就要调用的宿主函数。相反，cps-of-exps 的 builder 是转换时的宿主函数，用来组装最后一块目标 AST。先分清这两个阶段，就不会把生成代码与执行代码混起来。

最简单的规则是常量/变量直接生成“把值交给 K”；proc 给形参追加 fresh k，再转换正文；letrec 的每个过程也追加 k。复杂操作数要先提升成尾调用，用一个新形参接住结果，再重新组装外层表达式。

C(number,K) = (K number)
C(proc(xs) body,K) = (K proc(xs,k) C(body,k))
C((f args),K) = evaluate f and args to simples;
                generate (simple-f simple-args K)
C(-(e1,e2),K) = evaluate e1,e2 to a,b;
                generate (K -(a,b))

伴读例：从中间结果走到完整目标程序

原书 §6.3 规则的短例

let f = proc(x) -(x,1)
in -((f 5),(f 2))

% one alpha-equivalent CPS-OUT result:
let f = proc(x,k) (k -(x,1))
in (f 5 proc(a)
     (f 2 proc(b)
       -(a,b)))

目标先调用 f(5) 得 4，承接续文把它叫 a；再调用 f(2) 得 1，承接续文把它叫 b；最后直接返回 a−b=3。两次 f 都是目标尾调用。原程序的外层减法并未丢掉，而是移动到第二个续文正文里。

查看实现 · cps-exps
 (define (exps es builder h [call? #f])
  (define operands (list->vector es))
  (define indices (range (vector-length operands)))
  (define positions
   (cond [(eq? order 'right) (reverse indices)]
    [(and call? (eq? order 'operands-first) (pair? es)) (append (cdr indices) '(0))]
    [else indices]))
  (define (walk positions converted)
   (if (null? positions) (builder (map (lambda (i) (hash-ref converted i)) indices))
    (let* ([i (car positions)] [arg (vector-ref operands i)])
     (if (simple? arg #f)
      (walk (cdr positions) (hash-set converted i (simp arg h)))
      (let ([v (fresh 'v)])
       (cps arg `(proc (,v) ,(walk (cdr positions) (hash-set converted i (V v)))) h))))))
  (walk positions (hash)))

cps-of-exps 决定哪一个操作数先被提升，同时保持 builder 最终看到的参数位置。右到左模式应改变计算次序而非把减法的两侧互换；先实参后运算符也是另一种明确策略。当前转换器先给所有绑定 α 重命名，生成的新名带源前端不能输入的 %，防止 fresh k、临时值和用户名字相互捕获。

查看实现 · cps-main
 (define (cps e k h)
  (match e
   [(? (lambda (a) (simple? a #f))) (send k (simp e h))]
   [`(prim ,op . ,es)
    (exps es (lambda (ss) (send k `(prim ,op ,@ss))) h)]
   [`(list . ,es) (exps es (lambda (ss) (send k `(list ,@ss))) h)]
   [`(call ,f ,es)
    (exps (cons f es) (lambda (ss) `(call ,(car ss) ,(append (cdr ss) (list k) (if exceptions? (list h) '())))) h #t)]
   [`(if ,t ,a ,b)
    (exps (list t) (lambda (ss)
     (if (and share-if? (not (eq? (car k) 'var)))
      (let ([name (fresh 'join)]) `(let1 ,name ,k (if ,(car ss) ,(cps a (V name) h) ,(cps b (V name) h))))
      `(if ,(car ss) ,(cps a k h) ,(cps b k h)))) h)]
   [`(let ,xs ,es ,b)
    (cond [(and fuse-let? (= (length xs) 1) (not (simple? (car es) #f)))
           (cps (car es) `(proc (,(car xs)) ,(cps b k h)) h)]
     [else (exps es (lambda (ss)
      (foldr (lambda (x a rest) `(let1 ,x ,a ,rest)) (cps b k h) xs ss)) h)])]
   [`(letrec ,ns ,pss ,bs ,b)
    (define ps (map (lambda (xs body) (simp `(proc ,xs ,body) h)) pss bs))
    `(letrec ,ns ,(map cadr ps) ,(map caddr ps) ,(cps b k h))]
   [`(begin ,first . ,rest)
    (if (null? rest) (cps first k h)
     (let ([v (fresh 'discard)]) (cps first `(proc (,v) ,(cps `(begin ,@rest) k h)) h)))]
   [`(print ,arg) (exps (list arg) (lambda (ss) `(printk ,(car ss) ,(send k '(num 38)))) h)]
   [`(newref ,arg) (exps (list arg) (lambda (ss) `(newrefk ,(car ss) ,k)) h)]
   [`(deref ,arg) (exps (list arg) (lambda (ss) `(derefk ,(car ss) ,k)) h)]
   [`(setref ,a ,b) (exps (list a b) (lambda (ss) `(setrefk ,(car ss) ,(cadr ss) ,(send k '(num 23)))) h)]
   [`(letcc ,x ,body) `(let1 ,x ,k ,(cps body (V x) h))]
   [`(throw ,v ,dest) (exps (list v dest) (lambda (ss) `(call ,(cadr ss) (,(car ss)))) h)]
   [`(try ,body (,x) ,handler)
    (unless exceptions? (error 'cps "enable dual continuations"))
    (define err (fresh 'handler))
    `(let1 ,err (proc (,x) ,(cps handler k h)) ,(cps body k (V err)))]
   [`(raise ,arg)
    (unless exceptions? (error 'cps "enable dual continuations"))
    (exps (list arg) (lambda (ss) `(call ,h ,ss)) h)]
   [_ (error 'cps "unsupported expression: ~s" e)]))

默认转换还作两项行政化简：已知一元续文的立即应用改成 let；非简单 let 的 RHS 直接由源绑定名承接。if 则先把复杂 K 绑定到 fresh join，让两支共享它，避免把之后整段计算复制两遍。实际线性嵌套 8 层时，朴素输出 AST 大小为 61,911，共享后为 729。

下一步可以把续文闭包改成整数标签与自由变量列表，用统一 applyData 分派；再把全部用户过程作相同处理，就得到可编译成 PC 标签程序的形式。完整流水线实际运行了递归 n=100：全部过程数据化后产生 18 个代码标签，返回 100。这里没有借助宿主 eval 解释生成文本，而是由独立目标语法解析后运行。

ANF 走另一条路线：仍按次序给中间调用结果起名，但把这些名字放进 let，不增加运行时续文参数。它保留直接调用/返回语义，所以不自动具有迭代控制行为；同一组 α 重命名和 let 合并规则下，再把 ANF 转成 CPS 可与直接 CPS 对齐。

阅读注解
分阶段

K 是目标代码，builder 是宿主过程

转换时看见 proc(v) 的 AST，不代表此时执行了运行时过程。builder 接收已经转换好的简单 AST，构造一个新 TfExp；它的宿主调用栈属于编译器执行。目标 K 则会保存在生成程序里，等待程序运行时才接到真实值。把这两类“续文”区分开，是理解机械转换与高阶转换器的关键。

等价条件

变量提升也有作用域和效果前提

源 let 的各 RHS 都在旧环境下求。先全局改名再生成嵌套 let，才能避免早安装的目标绑定捕获后面的 RHS。隐式引用中的读变量是效果，不能按纯变量任意延后；带副作用的源表达式必须先求值并命名，再用于构造目标简单式。

习题 6.34 · ★★

原题

CPS 不只把控制上下文显式化，还决定操作次序，并给中间结果起名，这叫顺序化。若不要求迭代控制行为，可以改为 A-normal form（ANF）。下面是一个例子。

(define fib/anf
  (lambda (n)
    (if (< n 2)
        1
        (let ((val1 (fib/anf (- n 1))))
          (let ((val2 (fib/anf (- n 2))))
            (+ val1 val2))))))

CPS 用续文形参给中间结果命名，ANF 用 let。修改 cps-of-exp，让它输出 ANF；非尾位置的条件式可借鉴习题 6.23。说明转换 fib 如何得到上面的 fib/anf，并证明输入已经是 ANF 时输出只可能改变绑定变量名。

印刷 p.226 / PDF 249

解答与执行

把转换时的 context 当作宿主函数；需要一个简单值时，先规范化 e，再生成 let v=e in context(v)。尾位置直接返回规范化表达式，不额外传 k。非尾 if 先把整个条件表达式绑定到一个名字，再把名字送入 context，避免复制 context 到两支。

normalize(call f args): name f and each arg left-to-right, then call
name(complex,ctx): let v=normalize(complex) in ctx(v)
normalize(if t a b): name(t,lambda(s) if s then normalize(a) else normalize(b))

fib 的加法两个操作数都是调用，依次生成 val1、val2 的 let，尾部只剩相加，正好得到题给结构。输入若已经是 ANF，每个需要简单值的位置都已简单，name 不再引入 let；已有 let 的 RHS 和正文分别归纳保持，因此仅 α 重命名。可执行 anf 给出这一构造，测试同时比较求值与规范化后的绑定结构。ANF 的 val1 调用仍有“再求 val2 并相加”的待续工作，所以它没有自动变成常数控制栈。

习题 6.35 · ★

原题

6.4 计算效果：让打印、存储和控制流显式化

原书 §6.4，pp.226–232 / PDF 249–255。

计算效果包括打印、修改存储、异常和非局部跳转。即使两个表达式最后返回相同的数，它们也可能打印不同内容、改写不同位置或根本不终止。本节继续使用一个准则：SimpleExp 不执行这些效果；效果放在 TfExp 中，和下一步控制明确连在一起。

print(e) 先把 e 转成简单值，再生成 printk(simple); body，打印完成以后才继续 body。原书给 print 任取返回值 38；因此把 print(e) 的结果交给 K 时，传的是 38，而不是被打印值。

C(print(e),K)
 = evaluate e to v;
   printk(v); (K 38)

显式引用也按三步接入：输入增加 newref/deref/setref，目标增加 newrefk/derefk/setrefk，转换器把效果连接起来。newrefk 把新引用交给给定续文；derefk 把读取值交给续文；setrefk 写完再执行后继 TfExp，源 setref 的任取结果仍为 23。

伴读例：顺序化一次分配、写入与读取

原书 p.230 存储效果例的缩小版

newrefk(33,proc(loc)
  setrefk(loc,22);
  derefk(loc,proc(value)
    -(value,1)))

先得到装 33 的位置，再把同一位置改成 22，最后读得 22 并返回 21。derefk 即使不修改位置，也是在特定时刻读取当前内容，不能移到 setrefk 之前当成永远相同的简单值。目标解释器在每次 run 隔离存储，旧运行的引用不能混进新运行。

隐式引用的转换器要主动插入位置操作：绑定值要 newref，读变量要 deref，赋值要 setref。先按词法身份找出会被赋值的变量，还能让不可变绑定直接保留为简单值，减少分配和解引用。查的是绑定身份，不能把所有叫 x 的变量混成一类。

letcc/throw 不必再扩展目标语法：当前 K 已是可传递的目标过程，捕获它只需绑定；throw 最后直接调用目标续文，忽略即时 K。异常也可用普通目标过程表达，只需给转换器和用户过程增加成功/失败两个续文，try 临时替换失败通道，raise 把异常值送入它。

阅读注解
读取时刻

deref 也是需要固定位置的动作

纯环境里的变量同一绑定总得同一个值；隐式引用变量实际读取 store，结果取决于此前发生过哪些写入。把它简单地留在稍后的算术式里，可能读到新值。先 derefk、用 fresh 名保存结果，才能固定这次读取的时刻。

两条续文

习题 6.37 · ★★★

原题

给 CPS-IN 增加 §4.3 的隐式引用。CPS-OUT 继续使用显式引用版本，转换器须在必要位置插入分配和解引用。提示：有隐式引用后 var-exp 会读存储，因此不再是简单表达式。

印刷 p.231 / PDF 254

解答与执行

先把变量绑定改成位置绑定，再作 CPS。读 x 译为 deref(x)，写 x 译为 setref(x,v)；let 的 RHS 按旧环境依次求完，再为每个新变量 newref。过程形参先接收实参值，再为每个形参分配位置；递归组先分配所有位置，再安装闭包。

let x = e in b
=> let value = lower(e)
   in let x = newref(value) in lower(b)
proc(x) b
=> proc(arg) let x = newref(arg) in lower(b)
x => deref(x)
set x=e => begin setref(x,lower(e)); 27 end

#:implicit? #t 执行完整降级，随后 newref/deref/setref 分别成为 newrefk/derefk/setrefk。赋值源结果 27 与显式 setref 的 23 分别保留，不能因只关心效果而改变作为子表达式时的值。共享捕获和互递归程序已与第五章隐式机器逐例对照。

习题 6.38 · ★★★

原题

如果一个变量从不出现在 set 的左边，它就是不可变的，可以当作简单值。扩展上一题，让所有这种变量都按简单值处理。

印刷 p.232 / PDF 255

解答与执行

先按词法绑定做 α 重命名，再收集所有赋值左侧的绑定身份。只对这个集合中的变量分配位置、读时 deref；其余绑定直接存表达值，读变量仍简单。不能只按字符串判断：内外两个同名 x 可能只有一个会被赋值。

#:immutable? #t 开启该优化。过程的不可变形参直接接值，可变形参才 newref；一个闭包捕获可变变量时仍共享原位置。互递归组的过程名若不可变，可继续使用纯递归绑定；若允许给其中名字赋值，则先给整组统一分配位置。优化前后回归检查相同结果，并可比较位置分配计数。

习题 6.39 · ★

原题

在 CPS 转换器中实现 letcc 和 throw。

印刷 p.232 / PDF 255

解答与执行

C(letcc x in body,K)
 = let x = K in C(body,x)
C(throw value to target,K)
 = cps-of-exps([value,target],lambda([v,k]) Call(k,[v]))

习题 6.40 · ★★

原题

把 §5.4 的 try/catch 和 throw 加进 CPS 转换器。CPS-OUT 不应需要新语法；把 cps-of-exp 改成接两个续文，分别为成功续文和错误续文。

印刷 p.232 / PDF 255

解答与执行

§5.4 实际使用的异常关键字是 raise；题目末条写 throw，本题按该节的异常抛出解释，与上一题“throw 值到捕获续文”的形式分开。

C(try body catch(x) handler,K,H)
 = let h = proc(x) C(handler,K,H)
   in C(body,K,h)
C(raise e,K,H) = C(e,proc(v) (H v),H)
C(call f args,K,H) = ... (f args K H)
C(proc(xs) b,K,H) = send(K,proc(xs,k,h) C(b,k,h))

关键是所有用户过程都增加 k/h 两个参数，调用时传入当前处理器；不能让过程闭包固定捕获定义时的动态异常通道。#:exceptions? #t 完成这套转换，handler 再抛时使用外层 H，正常结果走外层 K。无处理器的程序以终结错误通道报告。正常 try/raise 不需要 CPS-OUT 增加异常构造；运行器的 uncaught 仅承担无处理器错误报告。

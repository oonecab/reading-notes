1.1 数据怎样由有限规则长出来

原书 §1.1，pp.1–12 / PDF 24–35。

这一章从数据开始，是因为递归程序的分支不应凭直觉拼出来。先说清输入由哪些基本值和构造组成，再问每种构造应返回什么，程序结构就有了依据。最简单的例子是从 0 开始，每次加 3；反复应用有限次规则，恰好得到 0,3,6,…。合法对象都带着一段有限的构造历史，递归计算则沿这段历史反向拆解。

定义 1.1.1–1.1.2 · 同一个集合的两种方向

自顶向下：自然数 n 属于 S，当且仅当 n=0，或 n−3 属于 S。自底向上：S 是包含 0 且对加 3 封闭的最小自然数集合。

“当且仅当”提供拆解方式，“最小”排除额外成员。要判断 6，沿 6 → 3 → 0 结束；要判断 7，沿 7 → 4 → 1 后不能再用规则生成，故不属于 S。若只写“0 在内、加 3 还在内”，全部自然数也满足，定义就没有锁定目标集合。

定义 1.1.3–1.1.5 · 整数表的归纳定义

空表是整数表。整数 n 与已有整数表 l 可以构成点对 (n . l)，它仍是整数表。只有有限次使用这两种规则构成的值才属于 List-of-Int。文法写作：

List-of-Int ::= () | (Int . List-of-Int)

点号不是装饰：(3 . (14 . ())) 明确显示 car 为 3、cdr 为 (14 . ())。常见的 (3 14) 是同一个列表的简写。(3 . 14) 则以整数结尾，不是 proper list。沿 cdr 走到空表，是列表程序终止和合法性的共同依据。

文法的非终结符命名一类数据；终结符规定实际出现的符号；“|”给出备选构造。Kleene 星号允许零个或多个重复项，加号要求至少一个；分隔符记号还规定重复项之间如何分开。这些简写可以展开成基础的递归规则。文法管形状，但不一定表达所有约束：搜索树的整数排序条件，需要在形状文法之外另外说明。

定义 1.1.6–1.1.8 · 嵌套表、二叉树与 λ 表达式

S-list ::= ({S-exp}*)
S-exp  ::= Symbol | S-list
Bintree ::= Int | (Symbol Bintree Bintree)
LcExp ::= Identifier
        | (lambda (Identifier) LcExp)
        | (LcExp LcExp)
Identifier = any symbol other than lambda

S-list 中只有符号和同类子表；Bintree 的叶子是整数，内部节点有符号标签与两个孩子；LcExp 有变量、抽象、应用三种构造。应用必须恰好有操作符和一个操作数。

例如 '(a (b c) ()) 是 S-list，而 '(a 7) 不是，因为 7 既不是符号也不是 S-list。'(lambda (x) (x y)) 是一个 lambda 节点，其过程体是应用节点，x 和 y 是变量节点。相同的括号外观可以属于不同数据类型；必须先选定契约，才能决定如何拆它。

定理 1.1.1 · 每棵这样的二叉树都有奇数个节点

这里每个内部节点恰有两个子树，并且整数叶子也计作一个节点。结论不适用于随意允许单孩子的树。

证明：顺着树的构造归纳

叶子有 1 个节点，是奇数。内部节点的左右子树严格小于整棵树；归纳假设允许分别把它们的节点数写成 2a+1 与 2b+1。整棵树再加上当前根，得到：

(2a+1)+(2b+1)+1=2(a+b+1)+1

所以内部构造也保持性质。叶子/内部节点覆盖全部生成方式，证明完成。不是先相信所有树都成立，而是在严格更小的两棵子树上使用归纳假设。

阅读注解
归纳定义与证明

成员资格是一段有限的构造历史

判断 (-7 3 14) 是否属于 List-of-Int，可以先从空表开始，依次把 14、3、−7 接到表头；也可以逐次检查表头是整数，再把问题交给表尾，最后到达空表。这两条路线使用的是同一段构造历史，只是方向相反。因而证明“每个整数表都具有某性质”时，空表是起点，cons 构造是唯一需要证明的保持步骤。

这里控制递归深度的是列表中 cons 的个数。整数标签可以为负、重复或非常大，都不会改变沿 cdr 到达空表的步数。归纳定义要求有限次构造，这也解释了为什么循环指向自身的点对链不属于这里的整数表：它无法给出一段以空表结束的有限构造证据。

习题 1.1 · ★

原题

印刷 p.5 / PDF 28

为下列集合写出归纳定义。每个定义都要分别采用自顶向下、自底向上和推理规则三种写法，并使用你写出的规则，展示每个集合中若干示例元素的推导过程。

  1. {3n+2|n∈N}。
  2. {2n+3m+1|n,m∈N}。
  3. {(n,2n+1)|n∈N}。
  4. {(n,n2)|n∈N}。规则中不得使用平方运算。提示：回想等式 (n+1)2=n2+2n+1。

解答与执行

设每个集合都取满足规则的最小集合。四个小问不能只写“基例 + 闭包”，还须排除凭空加入的元素。下面每一行同时给出自顶向下、自底向上和推理规则三种写法。

集合自顶向下：成员当且仅当自底向上推理规则
①m=2，或 m−3 已在集合内包含 2，且对加 3 封闭的最小自然数集无前提得 2∈S；由 m∈S 得 m+3∈S
②m=1，或 m−2∈S，或 m−3∈S包含 1，且对加 2、加 3 封闭的最小自然数集无前提得 1∈S；由 m∈S 分别得 m+2∈S、m+3∈S
③(n,k)=(0,1)，或 n≥1 且 (n−1,k−2)∈S包含 (0,1)，对 (n,k)↦(n+1,k+2) 封闭的最小集无前提得 (0,1)∈S；由 (n,k)∈S 得 (n+1,k+2)∈S
④(n,k)=(0,0)，或 n≥1 且 (n−1,k−2n+1)∈S包含 (0,0)，对 (n,k)↦(n+1,k+2n+1) 封闭的最小集无前提得 (0,0)∈S；由 (n,k)∈S 得 (n+1,k+2n+1)∈S

四条样本推导分别为：2 → 5 → 8；1 → 3 → 6；(0,1) → (1,3) → (2,5)；(0,0) → (1,1) → (2,4) → (3,9)。② 中按加 2 走 n 次、按加 3 走 m 次，恰好生成题目中的数；反过来，每次推导只可能增加这两个计数，因此没有多生成元素。③ 的第二坐标每次增加 2。④ 的规则本身只用加法；证明其正确时才用恒等式 (n+1)2=n2+2n+1。自顶向下的负数候选不属于自然数域，不能继续递归。

习题 1.2 · ★★

原题

印刷 p.5–6 / PDF 28–29

下列每一对规则分别定义了什么集合？请说明理由。

  1. (0,1)∈S；由 (n,k)∈S 可推出 (n+1,k+7)∈S。
  2. (0,1)∈S；由 (n,k)∈S 可推出 (n+1,2k)∈S。
  3. (0,0,1)∈S；由 (n,i,j)∈S 可推出 (n+1,j,i+j)∈S。
  4. [★★★] (0,1,0)∈S；由 (n,i,j)∈S 可推出 (n+1,i+2,i+j)∈S。

解答与执行

四个集合依次为 {(n,7n+1)}、{(n,2n)}、{(n,Fn,Fn+1)}、{(n,2n+1,n2)}，其中 n 遍历自然数，F0=0、F1=1、Fn+2=Fn+Fn+1。

证明必须有两个方向。先对推导步数归纳，说明规则生成的每个元组满足上述公式；再对 n 归纳，说明公式列出的每个元组都能从基例走 n 步得到。① 的递推是 7n+1 再加 7；② 是 2n 再乘 2；③ 将相邻 Fibonacci 数 (Fn,Fn+1) 移到 (Fn+1,Fn+Fn+1)。④ 中 i 的递推给出 i=2n+1，而新 j=i+j=2n+1+n2=(n+1)2。所有初值都分别符合原基例，因此两个方向成立。

核对前几项：① (0,1),(1,8),(2,15)；② (0,1),(1,2),(2,4)；③ (0,0,1),(1,1,1),(2,1,2)；④ (0,1,0),(1,3,1),(2,5,4),(3,7,9)。尤其④ 第三坐标用的是旧 i，不能误写成更新后的 i+2。

习题 1.3 · ★

原题

印刷 p.6 / PDF 29

找出一个自然数集合 T，使 0∈T，并且只要 n∈T，就有 n+3∈T；同时要求 T≠S，其中 S 是定义 1.1.2 所定义的集合。

解答与执行

取 T 为全部自然数。它包含 0，且任何自然数加 3 仍是自然数；但 1∈T，而定义 1.1.2 的 S 只包含 0,3,6,…，所以 T≠S。这说明“包含基例、对规则封闭”还不足以唯一规定集合；定义中“最小”一词负责排除这些多出的元素。

习题 1.4 · ★

原题

印刷 p.8 / PDF 31

写出从 List-of-Int 到 (-7 . (3 . (14 . ()))) 的一次推导。所用的整数表文法见定义 1.1.3–1.1.5。

解答与执行

每次只替换一个非终结符，完整推导为：

List-of-Int
⇒ (Int . List-of-Int)
⇒ (-7 . List-of-Int)
⇒ (-7 . (Int . List-of-Int))
⇒ (-7 . (3 . List-of-Int))
⇒ (-7 . (3 . (Int . List-of-Int)))
⇒ (-7 . (3 . (14 . List-of-Int)))

习题 1.5 · ★★

原题

印刷 p.12 / PDF 35

证明：若 e∈LcExp，则 e 中左括号与右括号的数量相同。LcExp 的文法见定义 1.1.8。

解答与执行

令 P(e) 表示表达式 e 的左右括号数相等。对 LcExp 的构造作结构归纳。变量没有括号，两边都是 0。若 e= (lambda (x) b)，归纳假设给出 b 内两边相等；外层括号和形参括号各增加一对，因此仍相等。若 e= (f a)，由两个归纳假设，f、a 各自平衡；再增加外层一对，仍平衡。三种构造互斥且覆盖文法，所以结论对所有合法表达式成立。

这里证明的是总数相等。任意字符串即使左右括号总数相等也未必是合法 LcExp，例如 )(。我们从“已由文法生成”的前提出发，不能倒用结论充当解析器。

1.2 从数据分支推导递归程序

原书 §1.2，pp.12–22 / PDF 35–45。

写递归程序时，先给函数一个独立契约，再在更小输入上使用这个契约。比如 list-length 接受任意有限正规列表（proper list），返回顶层元素个数。空表长度 0；非空表的长度是尾部长度加 1。这里不需要先进入 car 内部，因为嵌套列表也只是一个顶层元素。

调用向下走，待办的加法在回程完成

list-length '(a (b c) d)
= 1 + list-length '((b c) d)
= 1 + (1 + list-length '(d))
= 1 + (1 + (1 + list-length '()))
= 1 + (1 + (1 + 0))
= 3

每次下降减少的是 cdr 链的长度；每次返回解决一个等待的加 1。源码中递归调用虽然只有一处，它并非尾调用，因为结果回来以后还要加 1。输入不可变，并不等于执行过程不需要保存待办工作。

nth-element 仍沿 cdr 走，但同时携带剩余索引。取索引 2 时，参数依次为 ((a b c),2)、((b c),1)、((c),0)，此时返回 c。先判断空表保证错误路径不会非法取 car。remove-first 则多一个决策：找到目标时直接返回尾部；未找到时递归，然后用 cons 接回当前项。这个 cons 就是“保留前缀”的实现，不是可随意删除的包装。

remove-first 怎样保留没删掉的部分

remove-first 'b '(a b c b)
= cons 'a (remove-first 'b '(b c b))
= cons 'a '(c b)
= '(a c b)

第一次命中后不再递归，因此后一个 b 保留。若始终没有命中，每层都会接回自己的 car，最终得到相同的元素序列。新的前缀与可共享的尾部要分开理解。

自由变量判断把递归对象换成 LcExp。变量节点比较名字；lambda 节点若绑定的就是目标名字，整个过程体中这个名字的出现都被本层挡住，返回假，否则递归 body；应用节点检查 rator 或 rand。对 '((lambda (x) x) (x y)) 查询 x，左边因绑定而返回假，右边的 x 返回真，整体为真。这个过程在分析语法，并没有调用里面的 lambda。

嵌套替换需要两个方向的递归

把 '((a b) (c (a))) 中的 a 替换为 x：外层第一项是子表，递归得 (x b)；外层第二项也是子表，其 c 保留，内部 (a) 变成 (x)。最后重建得到 '((x b) (c (x)))。一个方向进入 car 子结构，另一个方向处理 cdr 的后续元素；只有 cdr 递归会漏掉嵌套处。

原书的“跟随文法”方法是：每个非终结符配一个处理过程，每个产生式配一个分支，产生式右侧的递归非终结符配递归调用。它帮助我们覆盖全部情况；真正的终止论证仍要指出下降的对象或秩。下面同一维护源包含列表长度、删除首项、自由变量、嵌套替换和辅助参数示例。

(define (list-length xs)
  (if (null? xs) 0 (+ 1 (list-length (cdr xs)))))

(define (remove-first s xs)

        [(eqv? s (car xs)) (cdr xs)]
        [else (cons (car xs) (remove-first s (cdr xs)))]))
;; Symbol * LcExp -> Bool; LcExp = symbol | (lambda (symbol) LcExp) | (LcExp LcExp)
(define (occurs-free? v e)
  (cond [(symbol? e) (eqv? v e)]
        [(eqv? (car e) 'lambda)
         (and (not (eqv? v (caadr e))) (occurs-free? v (caddr e)))]
        [else (or (occurs-free? v (car e)) (occurs-free? v (cadr e)))]))

(define (subst new old xs)
  (define (in-sexp x)

跟随语法分支

自由出现要在当前位置判断

考虑 '(lambda (y) (x (lambda (x) x)))，询问 x 是否自由出现。外层绑定的是 y，因此继续检查过程体；过程体是应用，左侧变量 x 立即给出真。右侧 (lambda (x) x) 中的 x 则受该层绑定，独立检查右侧会得到假。整个应用只需任一子表达式为真，故外层表达式仍有自由的 x。

同一个拼写在不同位置可以具有不同的绑定关系。检查一个 lambda 分支时，参数名字是否等于查询名字，决定了能否继续进入其过程体；这项判断来自 LcExp 的构造与绑定规则。被检查的表达式始终是数据，查询过程无需执行其中的应用，也无需知道 x 将来会绑定到哪个过程。

(define nth-element

       (report-list-too-short n)

(define report-list-too-short

习题 1.7 · ★★

原题

印刷 p.16 / PDF 39

nth-element 给出的错误消息提供的信息不够充分。请改写 nth-element，使它产生信息更充分的错误消息，例如 (a b c) does not have 8 elements.（“(a b c) 没有 8 个元素”）。题目所用的原过程见习题 1.6 的原书程序。

本题引用的原过程见习题 1.6 前的原书代码。

解答与执行

递归中的剩余列表和剩余索引会改变，因此不能用出错那一刻的局部参数解释原请求。外层保留原表 xs 和原索引 n，内层 walk 只移动 rest、k。索引 7 表示第 8 个元素，故错误消息使用 n+1。调用 (nth-element '(a b c) 7) 时，walk 依次收到 ((a b c),7)、((b c),6)、((c),5)、((),4)，最终仍报告原表与 8。

代码另外明确拒绝负索引；它是伴读的输入检查，不改变原题合法输入上的行为。

查看实现 · ex-1-7
;; Listof(SchemeVal) * Nat -> SchemeVal, or an informative bounds error.
(define (nth-element xs n)
  (define (walk rest k)
    (cond [(null? rest)
           (error 'nth-element "~s does not have ~a elements." xs (+ n 1))]
          [(zero? k) (car rest)]
          [else (walk (cdr rest) (- k 1))]))

1.3 上下文向下传，结果怎样向上传

原书 §1.3，pp.22–25 / PDF 45–48。

有时“递归处理尾部”得到的信息不够直接使用。number-elements 的尾部默认又从 0 开始编号，所以最外层需要知道当前已经走过几项。把函数推广成 (number-elements-from xs n)，契约变为“把 xs 从 n 开始编号”，原问题就是 n=0 的特例。

上下文参数不必变小

number-elements-from '(a b c) 0
→ cons '(0 a) [number-elements-from '(b c) 1]
→ cons '(0 a) [cons '(1 b) [number-elements-from '(c) 2]]
→ cons '(0 a) [cons '(1 b) [cons '(2 c) '()]]
→ '((0 a) (1 b) (2 c))

n 不断增加，但待处理列表严格缩短，终止性看的是后者。n 表示进入本调用时已经处理过的元素数；这个含义使每一步 n+1 都有依据。

树的编号还需要反向的信息流。仅告诉两个子树“从 0 开始”不够；右子树要等左子树编号结束，拿到新的起点。习题 1.35 的辅助过程因此返回“新树与下一个编号”。相比之下，红祖先计数只依赖上方路径，可以把相同更新后的计数独立交给左右子树。判断信息来自祖先还是前一个子问题，往往比先挑递归语法更重要。

向量求和说明另一种上下文：向量对象不缩小，但边界 n 缩小。(partial-vector-sum v n) 只承诺对 0≤n< (vector-length v) 工作，返回第 0 项到第 n 项的和。递归把 n 减一；当 n=0 时直接取第 0 项。完整 vector-sum 先处理空向量，避免把 −1 作为合法边界交下去。辅助函数有独立契约，外层函数才有可靠的调用依据。

阅读注解
辅助过程的契约

归纳假设要覆盖每个合法起点

number-elements-from 的契约需要说明任意非负起点 n 的行为。例如 (number-elements-from '(b c) 4) 应得到 '((4 b) (5 c))。当当前元素标为 n 后，尾部以 n+1 为起点；只有归纳假设也适用于这个新起点，才能据此断言尾部编号正确。

因此证明应对列表的长度归纳，同时让起点保持为任意非负整数。空表对任何起点都返回空表；非空表使用较短尾部的契约，再接回当前编号与元素。若只证明“起点为 0 时正确”，递归中起点变成 1 的调用就超出了已经证明的范围。辅助参数扩大了规格，也让归纳步骤能够闭合。

递归尾部的编号从 0 开始，因此 g 要先把尾部每一对的第一项加 1，再把当前的 (0,元素) 接在前面。对 (a b c)，底层得到 ((0 c))；回一层把它平移成 ((1 c))，接上 (0 b)；最外层再把整个尾部平移，得到 ((0 a) (1 b) (2 c))。

结果正确，但长度为 n 的列表需要平移 0+1+…+(n−1) 对，时间为 O(n2)。正文的 number-elements-from 把上下文向下传，只给每个元素编号一次，因此线性。两种写法的差别来自是否在回程反复修正已经生成的结果。

查看实现 · ex-1-36
(define (g first numbered-tail)
  (cons first (map (lambda (p) (list (+ 1 (car p)) (cadr p))) numbered-tail)))
(define (number-elements/g xs)
  (if (null? xs) '() (g (list 0 (car xs)) (number-elements/g (cdr xs)))))

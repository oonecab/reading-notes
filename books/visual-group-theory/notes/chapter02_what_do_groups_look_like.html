2.1 制作地图：把“怎么走”变成可查的关系

第 1 章把群看成一套可以连续执行、可以撤销的动作。本章的问题是：当动作组合越来越长，怎样知道自己在哪里，怎样找到回去的路？作者设想给魔方的每种配置编一页，把一次基本转动所到达的页码写在旁边。翻页就等于做动作；逆向找路就等于复原。

这本“大书”本质上是状态转移表。把每页改画为一个点，把“做某动作到某页”画成带标签的箭头，就得到地图。这里必须固定魔方的参考方向，并标记可区别的部件；否则把整个魔方转一个方向，可能只是改变观察方式，不应另算内部配置。

原书用超过 4×10¹⁹ 个魔方配置说明逐页记录的不现实。这个数量级服务于地图思想；书中存储容量的比较是出版时的背景。我们实际使用四节点的矩形例子，把建图、去重、补边和最短路径完整走一遍。广度优先搜索的层数表示使用所选生成元的最少步数；更换生成元或给不同动作不同费用，距离问题也会改变。

来源：印刷 11—13 / PDF 26—28

2.2 一个简单玩具：固定位置中的矩形

在桌面上划定一个长方形轮廓，将四角按上排 1、2，下排 3、4 标记。允许动作 h 把左右两列交换，v 把上下两行交换，每次动作结束都回到同一个轮廓。这里的“水平翻转”指左右互换的效果；它的转轴是竖直方向，别把运动名称误读成轴的名称。

从同一个标记矩形出发；第一列是动作说明
动作上排下排
开始 e1 23 4
h2 14 3
v3 41 2
hv4 32 1

h 和 v 都可以在任一配置执行，结果唯一，各做两次又撤销。左右、上下交换不会把点带出四个角，所以任意有限序列仍是合法动作。题目研究的是完整标记的刚体动作：不能只盯着某一个角，因为不同动作可能把一个角送到相同位置，却移动其他部分不同。

来源：印刷 14—15 / PDF 29—30

阅读注解
理解与边界

标签辨认的是整个动作

只看一个角的终点，可能把不同动作混为一谈。本例用四个不同标签记录完整排列；从同一起始矩形比较四角的像，才能据此判定动作是否相同。

2.3 系统探索：新状态入队，旧状态只补边

先在起点 e 试 h，到达新状态 h；再试 h 回到 e，记录这条双向边。回到 e 试 v，得到第三个状态 v。从 h 做 v，得到第四个状态 hv。此时不能因为“看起来有四种”就宣布完成：还要从每一个已发现节点分别执行 h、v，检查是否有新状态。

补全后，e 的邻点为 h、v；h 的邻点为 e、hv；v 的邻点为 hv、e；hv 的邻点为 v、h。特别地，先 h 后 v 与先 v 后 h 都把 12/34 变成 43/21，因此 hv=vhhv=vh；这里四角全都标记，比较整个排列足以确定刚体动作。

h²=e，v²=e，hv=vh；任意字词 = hⁱvʲ，i,j∈{0,1}。h²=e，v²=e，hv=vh；任意字词 = hⁱvʲ，i,j∈{0,1}。

为什么没有第五种？任意长字词都能利用 hv=vhhv=vh 把 h 移到前面，再用 h2=v2=eh²=v²=e 删除成对出现的字母，剩下 e、h、v、hv 中一个。另一种等价证明是归纳：空字词在四节点内；若前 k 步仍在图内，第 k+1 步的 h 或 v 边也已补齐，因此仍在图内。再检查这四个标记排列确实不同，才得到“恰好四个”。

这也给出建图算法的不变量：队列中每项都可从起点到达；已处理节点的每种生成元边都已记录。有限时队列耗尽，就覆盖所有生成元字词的效果。无限群的队列可能永不耗尽，不能把跑到某个上限当作穷尽。

来源：印刷 15—18 / PDF 30—33

阅读注解
理解与边界

队列耗尽为什么能证明完整

检查到四个节点还不够；每个节点的 h、v 后继都必须已经在这四个节点内。这样，任意长路径都可用长度归纳留在图中；再用四种不同排列排除重名，才得到恰好四个动作。

2.4 Cayley 图：沿路径读动作

Cayley 图用节点表示群元素或与其一一对应的完整配置，用固定颜色的有向边表示追加一个生成元。先固定起点，再沿 h、v 两色走，路径的字词就表示一个动作。两条路径到达同一节点，表示它们给出同一个群元素；节点画在哪个位置不参与运算。

图中去掉箭头尖端表示双向：本例 h、v 是自身的逆。若生成元是 120° 转动，逆向走表示 −120°，不等于再沿正向边走一次；需走两次正向边。一般生成集允许逆元，绘图时可以只画正向箭头，但读者必须知道逆动作对应反向走。

“每个点每种颜色各有一入一出”只是必要条件。一般的群作用图可以出现非恒等动作固定某个点；真正的 Cayley 图要求一个字词的关系在所有起点一致。第 4 章习题 4.16 会展示局部箭头都齐全、却不能把节点当作动作的反例。

来源：印刷 18—19 / PDF 33—34

阅读注解
理解与边界

无箭头表示什么

同色边画成双向线，是因为该生成元做两次还原。从节点 x 走一条 g 边到 xg，再走同色边应回到 x。三阶旋转需要有向循环，不能沿用这个省略箭头的画法。

2.5 抽去外观：矩形与双开关是同一个结构

两个独立开关的状态用 00、10、01、11 表示，左开关翻转记 h，右开关翻转记 v。对应 e↔00、h↔10、v↔01、hv↔11，每条同色边的连接关系都保持。矩形的几何外形消失了，但“各翻两次还原、两个翻转可交换”完全保留。这个四元素群叫 Klein 四元群 V₄。

别把它与四节点有向圆环 C₄ 混同。V₄ 的每个非恒等元素做两次都还原；C₄ 有一个动作必须做四次才还原。元素数相同并不足以说明结构相同。

图 2.10 预览了 C₃、S₃、C₃×C₃、C₂×C₂×C₂、16 阶准二面体群和 A₅。此时不必背图形；先识别生成元颜色、箭头方向、节点数，再观察短路径的关系。下章会把同一种结构放进不同的实际对象。

来源：印刷 19—22 / PDF 34—37

阅读注解
理解与边界

比较图时先比较连接

节点的位置和图的外形可以改变。比较两幅 Cayley 图时，应检查元素对应、生成元对应以及每条有色边的起终点；换一种画法不会改变同一动作合成的结果。

2.6 全部习题：从边的含义走到一般证明

2.6.1 基础

习题 2.1 · 矩形的生成元与其余动作

题目（中文转述）：

对 §2.2 的矩形玩具，哪些动作是生成元？群中还有哪些动作？

来源：印刷 21 / PDF 36

解答与推导

生成元为 h、v。加上不动 e 和合成 hv，共四个元素；vh=hv，hh=vv=e，不另计。所谓“其余动作”是其余效果，而非无穷多个指令字词。

习题 2.2 · 双开关的生成元

题目（中文转述）：

在两个独立灯开关的群中，生成元是哪两个动作？群中其余动作是什么？

来源：印刷 21 / PDF 36

解答与推导

分别翻左开关 L、翻右开关 R 是生成元。其余效果是都不翻 N，以及两个都翻 LR=RLLR=RL。把状态写成二位 0/1，任意字词只留下 L 与 R 出现次数的奇偶性，因此没有其他效果。

习题 2.3 · 箭头能否回到自身

题目（中文转述）：

Cayley 图中的一条箭头能否从某节点指回它自身？解释。

来源：印刷 21 / PDF 36

解答与推导

可以，恒等元若被选作生成元，会在每个节点画一个自环。若 xg=x，则左乘 x⁻¹ 得 g=e，因此非恒等生成元不能只在个别节点出现自环。一般作用图中固定点很常见，但它不一定是把群元素逐一画出的 Cayley 图。

2.6.2 制图

习题 2.4 · 两枚硬币的地图

题目（中文转述）：

为习题 1.1 中两枚不同硬币的交换群画 Cayley 图：起始次序 AB，动作 s 交换两枚硬币。

来源：印刷 21 / PDF 36

解答与推导

节点有 AB、BA；s 各执行一次到对方，所以是 C₂。由原位置标记可把这两个节点分别命名为 e、s。

习题 2.5 · 三幅画的地图

题目（中文转述）：

为习题 1.4 中三幅不同画作画 Cayley 图。a 交换左、中位置，b 交换中、右位置；保留全部可达排列与两种边。

来源：印刷 21 / PDF 36

解答与推导

六个排列沿一圈依次为 ABC —a— BAC —b— BCA —a— CBA —b— CAB —a— ACB —b— ABC。每条边双向，每个节点各接一条 a、一条 b；这已经补全所有生成元边。完整图和逐步状态在第 1 章三幅画图。三个不同标记共有 3·2·1=6 种排列，而图已到达全部，因此这是六元素的 S₃。

习题 2.6 · 整数平移的无限地图

题目（中文转述）：

为习题 1.13 的整数平移群画图，再为习题 1.14(a) 的偶整数平移群画图，并比较。前者允许平移任意整数，后者只允许平移偶整数。

来源：印刷 23 / PDF 38

解答与推导

前者用 +1 为生成元：…→−2→−1→0→1→2→…；逆向走是 −1。后者用 +2：…→−4→−2→0→2→4→…；逆向是 −2。将第一幅的节点 k 对应到第二幅的 2k，边一一对应，所以结构相同。必须保留两端省略号；截出七个节点不表示群只有七个元素。

习题 2.7 · 乘以正负一

题目（中文转述）：

为习题 1.14(d) 的群画图：允许对数施加“乘以 1”或“乘以 −1”的动作。

来源：印刷 23 / PDF 38

解答与推导

取 s 为乘以 −1，s2=es²=e。乘以 1 是恒等元，无需另画恒等自环。选输入 1 可以区分两动作，选输入 0 却不能；这再次说明一个特殊状态可能隐藏不同动作。

习题 2.8 · 正方形增加四分之一转

题目（中文转述）：

把矩形玩具换成四角编号的正方形，除水平、竖直翻转外还允许顺时针四分之一转。

  1. 画出所得群的 Cayley 图。
  2. 为什么四分之一转不属于原来非正方形矩形玩具的合法动作？

来源：印刷 23 / PDF 38

解答与推导

(a) 以 r 为四分之一转、f 为一条固定轴的翻转，图列出 e,r,r²,r³,f,rf,r²f,r³f 八个元素。原来另一个翻转等于 r²f，因此它没有被丢弃：若要保留三种原动作的边，只需额外把每个节点 x 连到 xr²f。具体双向配对为 e↔r²f、r↔r³f、r²↔f、r³↔rf。上图选两个生成元以避免重叠。

四个旋转保持朝向，四个翻转改变朝向；每一类由第一个角的四种去向区分，因此恰好八个。(b) 长、短边不等的矩形转 90° 后，所占轮廓变了，不再符合“动作结束占据同一空间”的规则；正方形四边等长才允许这一步。

习题 2.9 · 更换 V₄ 的生成元

题目（中文转述）：

把矩形四动作记作 n（不动）、h、v、b（先 h 后 v），对应上图的 e、h、v、hv。

  1. 在原图加上 b 的箭头。
  2. 去掉所有 h 箭头，余下两种箭头是否仍生成整个群？
  3. 改为去掉所有 v 箭头，结果怎样？

来源：印刷 23 / PDF 38

解答与推导

(a) b 把 e 与 hv、h 与 v 分别互换，即蓝色两条对角线。

(b) v、b 仍连接全部四节点；vb=v(hv)=h，故原 h 能被恢复。

(c) h、b 也能连通，hb=h(hv)=v。每次都同时检查了连通路径及缺失生成元的表达式。

2.6.3 从图找情景

习题 2.10 · 反向找一个二元素例子

题目（中文转述）：

给定两个节点 A、B，被一条双向边连接。找出一个不是前面硬币例子的物理情景，并解释为何得到这幅图。

来源：印刷 23 / PDF 38

解答与推导

取一枚只有“亮、灭”两态的理想开关，动作 s 切换一次。s 把两态互换，s2=es²=e，所以节点分别代表 e、s。模型把亮灭当作精确的逻辑状态，不把等待时间、磨损算入动作。

习题 2.11 · 反向找一个四元素例子

题目（中文转述）：

给定 A、B、C、D 四节点：蓝边 A↔B、C↔D，红边 A↔C、B↔D。找一个区别于矩形与双开关的情景，解释其地图。

来源：印刷 23 / PDF 38

解答与推导

在平面上操作坐标，u:(x,y)↦(−x,y)，v:(x,y)↦(x,−y)。由起始点 (1,1) 得到 (1,1)、(−1,1)、(1,−1)、(−1,−1)，依次标为 A、B、C、D。u 是蓝边、v 是红边；u²=v2=ev²=e、uv=vu。四个变换作为整个平面的函数确实不同，因此又得到 V₄。

习题 2.12 · 反向找一个三循环

题目（中文转述）：

给定三个节点沿同色有向箭头构成三循环。找出一个情景并说明生成元。

来源：印刷 24 / PDF 39

解答与推导

给等边三角形标上三个不同角标，只允许绕中心顺时针转 120°。e、r、r² 三个效果由角标去向区分，r3=er³=e；不把翻转加入动作表，因此得到 C₃。

2.6.4 规则与箭头

习题 2.13 · 为什么生成元特别

题目（中文转述）：

生成元在 Cayley 图中享有什么特别待遇？

来源：印刷 24 / PDF 39

解答与推导

每个选定生成元有一种单步箭头。其余群元素也有节点，但通常通过多步路径实现，不另设一种颜色。比如 V₄ 的 hv 有自己的节点，从任意起点先走 h 再走 v 就能执行 hv。

习题 2.14 · 固定动作表怎样画出来

题目（中文转述）：

把规则 1.5“合法动作表在各状态相同”翻译成对 Cayley 图的要求。

来源：印刷 24 / PDF 39

解答与推导

各节点应能使用相同的生成元颜色：不能在一个节点提供 h，到另一个节点突然改为不允许 h。它尚未说明同色箭头是否唯一、是否可逆，后两题分别补充这些条件。

习题 2.15 · 可逆性怎样画出来

题目（中文转述）：

把规则 1.6“每个动作可撤销”翻译成箭头要求，并画一幅违背该要求的示意图。

来源：印刷 24 / PDF 39

解答与推导

同色动作必须是节点集上的双射，故每个节点恰有一条该色入边和一条该色出边。图中 A、B 都去 C，撤销时无法判断原来是哪一个。示意图用于指出违反可逆性的地方；它并非声明其余所有群条件都已满足。无限节点时还须检查满射，只有不相撞仍可能漏掉前驱。

习题 2.16 · 确定性怎样画出来

题目（中文转述）：

把规则 1.7“动作的结果可预测”翻译成箭头要求，并给出违反它的图。

来源：印刷 24 / PDF 39

解答与推导

在已知起点、给定颜色后，终点必须唯一。图中的两条同色分支使“从 A 做 g”产生歧义。实际 Cayley 图还要求每色动作处处有定义；唯一性与存在性应分开读。

习题 2.17 · 任意合成仍合法

题目（中文转述）：

规则 1.8 说动作的任意组合也是合法动作。这对 Cayley 图有什么要求？

来源：印刷 24 / PDF 39

解答与推导

从起点沿任何合法字词抵达 P 后，再追加任一生成元 A 仍必须有路可走。因此每个可达节点都必须有每种颜色的出边。否则“到 P 的字词，再做 A”就是一个被禁止的组合。复合动作通常是一段路径；封闭性不要求把每个复合另画一条单边。

2.6.5 形状

习题 2.18 · 等边三角形的全部对称

题目（中文转述）：

把矩形玩具改为等边三角形，允许所有把它送回同一轮廓的刚体操作。画出群的 Cayley 图。

来源：印刷 24 / PDF 39

解答与推导

r 为 120° 转动，f 为沿一条对称轴把薄片翻面的半转。六个元素为 e,r,r²,f,rf,r²f。三个旋转与三个翻转各不相同；选一个角的像有三种，选相邻角在其左侧还是右侧有两种，第三角就被确定，故至多 3·2=6，图正好达到这个上界。

习题 2.19 · 一般正 n 边形

题目（中文转述）：

对 n>2 的正 n 边形玩具，研究所有保持原轮廓的动作。

  1. 猜测群的大小随 n 怎样变化。
  2. 画正五边形的 Cayley 图。
  3. 在 Group Explorer 中查三角形、正方形、正五边形等例子：(i) 比较图；(ii) 检查猜测是否符合找到的数据。
  4. 给出支持猜测的一般理由。

解答与推导

(c) 本章软件实查记录列明实际使用的版本与检查范围。比较时先对应生成元和边的连接关系，不能按节点屏幕位置判断；阶数为 6、8、10，更多正多边形也符合 2n。任何有限数量实验都只支持猜测。

(d) 一个固定顶点有 n 个可能的像；与它相邻的固定顶点必须映到像点的两个相邻顶点之一。两点的去向和保持距离的要求确定所有其他顶点，至多 2n 种。转动 k·360°/n（k=0,…,n−1）给 n 种；先作这些转动再翻面给另外 n 种，且两类对环绕次序的保持/反转不同，所以互不重复。这给出恰好 2n 的证明。数字是观察标签，用于区分部件，不是要求每个数字必须留在原处的额外限制。

程序：枚举正多边形的全部动作

把正 n 边形顶点编号 0,…,n−1，动作表示为 x↦sign·x+shift（模 n），其中 sign=±1。r 是 x↦x+1，f 是 x↦−x。当前动作后追加 r，只把 shift 加 1；追加 f，则 sign、shift 同时取反。这正是按时间从左到右执行的复合。

队列初始只有 (1,0)。每次按 r、f 的固定顺序扩展，第一次出现的二元组入队并保存最短字词；重复二元组只记录目标编号。两个参数各有 2、n 种可能，最多 2n 项；n≥3 时这 2n 个函数不同。先看 x=0 确定 shift，再看 x=1 区分正负号，所以“参数不同”确实等于“动作不同”。

程序接受十进制 n=3,…,12，默认 n=4；上限是教学用容量边界，不是数学限制。Python 用字典查重，期望 O(n) 次常数规模查找；C 为直观起见线性扫描，O(n²)，两者空间 O(n)，保存最短字词使总字符空间至多 O(n²)。C 固定 24 项，每个字词最多 24 字符并检查容量；取模先规范到非负数。非法参数退出码 2，C 内部容量违约为 3。

默认输出八项；列 r、f 是目标节点编号。沿每个 r 连走四步或沿 f 连走两步均回原点，沿 fr 与 r⁻¹f 也到同点。程序是对有限 n 的核查，一般 2n 结论来自习题 2.19 的证明。

"""Enumerate D_n by breadth-first search; words execute left to right."""
import sys


def enumerate_group(n):
    if type(n) is not int or not 3 <= n <= 12:
        raise ValueError("n must be an integer from 3 through 12")
    # (sign, shift) means vertex x goes to sign*x + shift modulo n.
    states, words = [(1, 0)], [""]
    index = {states[0]: 0}
    edges = []
    head = 0
    while head < len(states):
        sign, shift = states[head]
        destinations = []
        for letter, target in (("r", (sign, (shift + 1) % n)),
                               ("f", (-sign, (-shift) % n))):
            if target not in index:
                index[target] = len(states)
                states.append(target)
                words.append(words[head] + letter)
            destinations.append(index[target])
        edges.append(tuple(destinations))
        head += 1
    return states, words, edges


def main(args):
    if len(args) > 1 or (args and args[0] not in [str(i) for i in range(3, 13)]):
        raise ValueError("usage: cayley.py [3..12]")
    n = int(args[0]) if args else 4
    states, words, edges = enumerate_group(n)
    print(f"D{n}: {len(states)} actions")
    print("id word sign shift r f")
    for i, ((sign, shift), word, (r, f)) in enumerate(zip(states, words, edges)):
        print(i, word or "e", sign, shift, r, f)


if __name__ == "__main__":
    try:
        main(sys.argv[1:])
    except ValueError as error:
        print(error, file=sys.stderr)
        sys.exit(2)

/* D_n, 3 <= n <= 12. Temporal words: r then f is written rf. */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

enum { CAPACITY = 24 };
typedef struct { int sign, shift, edge[2]; char word[CAPACITY + 1]; } State;

static int modulo(int x, int n) { return (x % n + n) % n; }

int main(int argc, char **argv) {
    int n = 4;
    if (argc > 2) { fputs("usage: cayley [3..12]\n", stderr); return 2; }
    if (argc == 2) {
        n = 0;
        for (int candidate = 3; candidate <= 12; ++candidate) {
            char expected[4];
            (void)snprintf(expected, sizeof expected, "%d", candidate);
            if (strcmp(argv[1], expected) == 0) n = candidate;
        }
        if (n == 0) { fputs("usage: cayley [3..12]\n", stderr); return 2; }
    }
    State states[CAPACITY] = {{0}};
    states[0].sign = 1;
    int count = 1;
    for (int head = 0; head < count; ++head) {
        for (int g = 0; g < 2; ++g) {
            int sign = g == 0 ? states[head].sign : -states[head].sign;
            int shift = modulo(g == 0 ? states[head].shift + 1 : -states[head].shift, n);
            int dest = 0;
            while (dest < count && !(states[dest].sign == sign && states[dest].shift == shift)) ++dest;
            if (dest == count) {
                if (count == CAPACITY) { fputs("capacity exceeded\n", stderr); return 3; }
                states[dest].sign = sign;
                states[dest].shift = shift;
                size_t length = strlen(states[head].word);
                if (length >= CAPACITY) { fputs("word too long\n", stderr); return 3; }
                memcpy(states[dest].word, states[head].word, length);
                states[dest].word[length] = g == 0 ? 'r' : 'f';
                states[dest].word[length + 1] = '\0';
                ++count;
            }
            states[head].edge[g] = dest;
        }
    }
    printf("D%d: %d actions\nid word sign shift r f\n", n, count);
    for (int i = 0; i < count; ++i)
        printf("%d %s %d %d %d %d\n", i, states[i].word[0] ? states[i].word : "e",
               states[i].sign, states[i].shift, states[i].edge[0], states[i].edge[1]);
    return 0;
}

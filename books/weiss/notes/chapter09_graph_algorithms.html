一、§9.1：图的语义决定数据表示

树为每个非根节点指定一个父亲；图允许多个入口、回路和不能互达的区域。写成 G=(V,E) 时，边可以有方向，也可以带费用或容量；“一条边”在这些问题中承担不同意义。机场的直飞线路天然有方向，票价与飞行时间又是不同权值；道路网络中的车道容量则为后面的流量模型做准备。先确定这些含义，才知道应求边数最少、费用最低，还是可通过的总量最大。

原书把路径长度定义为边数，把带权长度定义为边权之和；允许从一个点到自己走零条边。无向边往返一次用的是同一条边，因此 u→v→u 不构成普通无向简单图的环；两条不同的平行边却可以形成长度 2 的环。无向连通、有向强连通以及忽略方向后的弱连通，要分别判断。简单路径不重复顶点，欧拉路线则不重复边，它们会在本章末尾引出截然不同的算法。

邻接矩阵占 Θ(|V|2) 空间，检查一条指定边方便；邻接表占 Θ(|V|+|E|) 空间，遍历某个顶点的出边只付出与实际出度相称的时间。原书的街区示例有 3000 个路口和约 12000 条有向邻接记录，矩阵却有 9000000 格。存储比例直接解释了为什么这章的大多数线性算法都要求邻接表。

二、§9.2：只保存新变为可选的顶点

课程先修图要求每条边的起点排在终点之前，这就是拓扑顺序。图 9.4 只有 v1 最初入度为零；删除它后 v2 可选，删除 v2 后 v5 可选，接着 v4，最后剩余的可选点可以有不同顺序。若有环，环上的每个点都依赖前一个点，便不可能排出合法顺序。

图 9.5 每轮扫描全部顶点寻找零入度者，把选择成本推到 O(|V|2)；图 9.7 改为队列，只在一条边删除后检查其终点是否刚好变为零。每个顶点入队一次，每条边减入度一次，包括初始入度计算在内，时间为 O(|V|+|E|)。图 9.6 给出 v1、v2、v5、v4、v3、v7、v6；栈也能保存候选点，改变的是可选点之间的顺序。

下面的 Topsort 返回实际处理数量，调用者据此区分完整顺序和环造成的残余。原图并不被修改，减少的是本次调用的入度副本；重复边会各自贡献一次入度，也各自减去一次。空图有空的合法顺序。相同代码块还包含 BFS 和二分图染色，供后面按层搜索与习题 9.13 使用。

/* FIFO by default; lifo != 0 selects a stack. Returns processed vertices. */
static int topsort(const Graph *g, int lifo, int *order) {
    if (!g->directed) fail("topological sort needs a digraph");
    int *deg = alloc((size_t)g->n, sizeof(int));
    int *q = alloc((size_t)g->n, sizeof(int)); int head = 0, tail = 0, count = 0;
    for (int i = 0; i < g->m; ++i) ++deg[g->e[i].v];
    for (int v = 0; v < g->n; ++v) if (!deg[v]) q[tail++] = v;
    while (head < tail) {
        int u = lifo ? q[--tail] : q[head++]; order[count++] = u;
        for (int i = g->off[u]; i < g->off[u + 1]; ++i)
            if (--deg[g->a[i].to] == 0) q[tail++] = g->a[i].to;
    }
    free(deg); free(q); return count;
}

def topsort(g, lifo=False):
    if not g.directed:
        raise ValueError("topological sort needs a digraph")
    deg, q = [0] * g.n, []
    for _, v, _ in g.edges:
        deg[v] += 1
    for v in range(g.n):
        if deg[v] == 0:
            q.append(v)
    head, order = 0, []
    while head < len(q):
        if lifo:
            u = q.pop()
        else:
            u = q[head]
            head += 1
        order.append(u)
        for v, _, _ in g.adj[u]:
            deg[v] -= 1
            if deg[v] == 0:
                q.append(v)
    return order

def bfs(g, s):

        u = q[head]
        head += 1
        for v, _, _ in g.adj[u]:
            if d[v] == INF:

    if g.directed:
        raise ValueError("bipartite test needs an undirected graph")
    color = [-1] * g.n
    for s in range(g.n):

三、§9.3.1–9.3.2：从按层搜索走到最小距离

无权最短路从源点向外扩展：所有距离 0 的点先处理，再处理距离 1、2、……。原书先用反复扫描全表模拟这些层，图 9.17 的长链显示扫描浪费；随后图 9.18 用 FIFO 队列把下一层自然接到当前层之后。第一次发现一个顶点就确定其距离，它只入队一次；不可达点保持无穷大，前驱保持 −1。

图 9.10 使用同一方向结构而忽略权值，从 v3 出发得到距离 (1,2,0,2,3,1,3)。前驱记录“最后一条路径边来自谁”；还原时从目标沿前驱倒走，再逆序输出即可。每个点至多走一次，既能避免递归栈，也不会把不可达目标误当成一条从自身开始的路径。

带权情形不能在第一次看见顶点时就确定最短路。Dijkstra 每次取当前距离最小的未确定顶点，才把它标为已确定；沿其出边尝试松弛。图 9.20–9.28 从 v1 依次确定 v1、v4、v2，再确定距离同为 3 的 v5、v3，最后 v7、v6。v6 的候选值经历 9→8→6，正好说明一个前驱可以被更短路线替换。

正确性的关键是非负边：设刚选出的 u 还存在更短路，在那条路上取第一个尚未确定的顶点 y。它的前驱已确定，所以松弛已经给 y 一个不大于该路前缀的候选值；后续边非负，y 的候选不大于到 u 的那条更短路，便会比 u 更早被选出，矛盾。这个证明容许零权边，却不容许负权边。

扫描全表选择最小者需要 O(|V|2+|E|)；二叉堆把选择和降低键值降为 O(log(|V|+1))，总时间为 O((|V|+|E|)log(|V|+1))。原书还给出允许同一顶点多个旧候选的实现，队列可长到 O(|E|)；本页用索引堆保存每个顶点的位置，交换节点时同步更新 pos，一点至多一项，辅助空间为 O(|V|)。本页同距离时选编号小者，和原书先选 v5 的手算顺序可以不同，最终距离相同。

/* At most one entry per vertex; keys are external and may only decrease. */
typedef struct { int size, *h, *pos; Cost *key; } Heap;
static int heap_less(const Heap *h, int u, int v) {
    return h->key[u] < h->key[v] || (h->key[u] == h->key[v] && u < v);
}
static Heap heap_make(int n, Cost *key) {
    Heap h = {0, alloc((size_t)n, sizeof(int)), alloc((size_t)n, sizeof(int)), key};
    for (int i = 0; i < n; ++i) h.pos[i] = -1;
    return h;
}
static void heap_swap(Heap *h, int a, int b) {
    int t = h->h[a]; h->h[a] = h->h[b]; h->h[b] = t;
    h->pos[h->h[a]] = a; h->pos[h->h[b]] = b;
}
static void heap_update(Heap *h, int v) {
    int i = h->pos[v];
    if (i < 0) { i = h->size++; h->h[i] = v; h->pos[v] = i; }
    while (i && heap_less(h, h->h[i], h->h[(i - 1) / 2])) {
        int parent = (i - 1) / 2; heap_swap(h, i, parent); i = parent;
    }
}
static int heap_pop(Heap *h) {
    int v = h->h[0]; h->pos[v] = -1; --h->size;
    if (h->size) {
        h->h[0] = h->h[h->size]; h->pos[h->h[0]] = 0; int i = 0;
        for (;;) {
            int j = 2 * i + 1;
            if (j >= h->size) break;
            if (j + 1 < h->size && heap_less(h, h->h[j + 1], h->h[j])) ++j;
            if (!heap_less(h, h->h[j], h->h[i])) break;
            heap_swap(h, i, j); i = j;
        }
    }
    return v;
}
static void heap_free(Heap *h) { free(h->h); free(h->pos); }
static void heap_build(Heap *h, int n) {
    h->size = n;
    for (int i = 0; i < n; ++i) h->h[i] = h->pos[i] = i;
    for (int start = n / 2 - 1; start >= 0; --start) {
        int i = start;
        while (2 * i + 1 < n) {
            int j = 2 * i + 1;
            if (j + 1 < n && heap_less(h, h->h[j + 1], h->h[j])) ++j;
            if (!heap_less(h, h->h[j], h->h[i])) break;
            heap_swap(h, i, j); i = j;
        }
    }
}

class Heap:
    def __init__(self, n, key):
        self.h, self.pos, self.key = [], [-1] * n, key

    def less(self, u, v):
        return (self.key[u], u) < (self.key[v], v)

    def swap(self, a, b):
        self.h[a], self.h[b] = self.h[b], self.h[a]
        self.pos[self.h[a]], self.pos[self.h[b]] = a, b

    def update(self, v):
        i = self.pos[v]
        if i < 0:
            i = len(self.h)
            self.h.append(v)
            self.pos[v] = i
        while i and self.less(self.h[i], self.h[(i - 1) // 2]):
            parent = (i - 1) // 2
            self.swap(i, parent)
            i = parent

    def pop(self):
        v = self.h[0]
        self.pos[v] = -1
        last = self.h.pop()
        if self.h:
            self.h[0], self.pos[last] = last, 0
            i = 0
            while 2 * i + 1 < len(self.h):
                j = 2 * i + 1
                if j + 1 < len(self.h) and self.less(self.h[j + 1], self.h[j]):
                    j += 1
                if not self.less(self.h[j], self.h[i]):
                    break
                self.swap(i, j)
                i = j
        return v

    def build(self, n):
        self.h, self.pos = list(range(n)), list(range(n))
        for start in range(n // 2 - 1, -1, -1):
            i = start
            while 2 * i + 1 < n:
                j = 2 * i + 1
                if j + 1 < n and self.less(self.h[j + 1], self.h[j]):
                    j += 1

static void dijkstra(const Graph *g, int s, int scan, Cost *d, int *p) {
    for (int i = 0; i < g->m; ++i) if (g->e[i].w < 0) fail("negative Dijkstra edge");
    paths_init(g, s, d, p);
    int *done = alloc((size_t)g->n, sizeof(int)); Heap h = heap_make(g->n, d);
    if (!scan) heap_update(&h, s);
    for (;;) {
        int u = -1;
        if (scan) {
            for (int v = 0; v < g->n; ++v)
                if (!done[v] && d[v] != INF && (u < 0 || d[v] < d[u])) u = v;
        } else if (h.size) u = heap_pop(&h);
        if (u < 0) break;
        done[u] = 1;
        for (int i = g->off[u]; i < g->off[u + 1]; ++i) {
            Arc a = g->a[i]; if (done[a.to]) continue;
            Cost nd = plus(d[u], a.w);
            if (nd < d[a.to]) {
                d[a.to] = nd; p[a.to] = u;
                if (!scan) heap_update(&h, a.to);
            }
        }
    }
    heap_free(&h); free(done);
}

static int negative_paths(const Graph *g, int s, Cost *d, int *p) {
    paths_init(g, s, d, p);
    int *q = alloc((size_t)g->n, sizeof(int)), *in = alloc((size_t)g->n, sizeof(int));
    int *pops = alloc((size_t)g->n, sizeof(int));
    int head = 0, tail = 0, count = 1, ok = 1; q[tail++] = s; tail %= g->n; in[s] = 1;
    while (count) {
        int u = q[head]; head = (head + 1) % g->n; --count; in[u] = 0;
        if (++pops[u] > g->n) { ok = 0; break; }
        for (int i = g->off[u]; i < g->off[u + 1]; ++i) {
            Arc a = g->a[i]; Cost nd = plus(d[u], a.w);
            if (nd < d[a.to]) {
                d[a.to] = nd; p[a.to] = u;
                if (!in[a.to]) {
                    q[tail] = a.to; tail = (tail + 1) % g->n; ++count; in[a.to] = 1;
                }
            }
        }
    }
    free(q); free(in); free(pops); return ok;
}

若一个负环从源点可达，再从环可达某目标，就能不断绕环降低费用，该目标的最短路没有有限值。图 9.9 的 v2→v5→v4→v2 总费用是 −6。图中有一个与源点无关的负环，并不会破坏源点到其余可达点的答案；“图里有负环”和“本次查询受负环影响”必须分开。

五、§9.4：反向残余边让增广可以撤销

流量先满足每条边的容量限制，再满足所有中间顶点的流入量等于流出量。只寻找“尚未装满的正向边”会把早期决定固定住：图 9.44 先沿 s→a→d→t 送 3，便误以为无路可走。正确残余图为一条容量 c、当前流量 f 的原边同时保留正向容量 c−f 和反向容量 f。反向走过这条边，表示撤销其中一部分流。

六、§9.5：最小生成树的两种安全边选择

最短路最小化一个源点到各目标的路径费用；最小生成树最小化把全部顶点连起来的总边权。图 9.48 使用无向边，而且 v4—v5 的权重为 7，与最短路例图的有向边权 2 不同。保留这些差异，才不会把图 9.55 的总费用 16 算错。

安全性由割性质支撑：设一棵最优树包含已经选定的边，而某条跨越当前分量边界的最轻边 e 不在树内；加入 e 形成环，环上必有另一条跨越同一割的边 f，其重量不小于 e。以 e 换 f 仍是一棵树，费用不增加，也保留此前选择。因此至少有一棵最优树包含新边。这个交换论证与权值是否为负无关。

Prim 保持一棵树，key[v] 是从已选顶点到 v 的最轻单边；更新用边权本身，而不是 d[u]+w。图 9.49 从 v1 开始得到边 v1—v4、v1—v2、v4—v3、v4—v7、v7—v6、v7—v5，总重 16。

Kruskal 保持森林，按边权非降序取边，只有端点属于不同并查集时才接纳；并查集维护的正是“在当前森林中是否已经连通”。图 9.56 的权重 3 的 v2—v4、权重 4 的 v1—v3 被拒绝，因为各自闭合一条环。原书用线性 BuildHeap，再逐次 DeleteMin，本页也这样做；达到 N−1 条后提前结束，断开的图则耗尽候选并返回最小生成森林。

Prim 用索引二叉堆，时间 O((|V|+|E|)log(|V|+1))；Kruskal 的堆选择最坏 O(|E|log(|E|+1))，并查集合并另计 O((|V|+|E|)α(|V|+|E|,|V|))。简单图可用 |E|≤|V|2 简化对数；多重图不应无条件把 logE 改成 logV。代码还给出题 9.19 的整数桶版本，后面说明整数条件。

        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def set_union(parent, size, u, v):
    u, v = set_find(parent, u), set_find(parent, v)
    if u == v:
        return False
    if size[u] < size[v]:
        u, v = v, u
    parent[v], size[u] = u, size[u] + size[v]
    return True

def prim(g):
    if g.directed:
        raise ValueError("MST needs an undirected graph")
    key, done, best = [INF] * g.n, [False] * g.n, [-1] * g.n
    heap, selected, total = Heap(g.n, key), [], 0
    for s in range(g.n):
        if done[s]:
            continue
        key[s] = 0
        heap.update(s)
        while heap.h:
            u = heap.pop()
            done[u] = True
            if best[u] >= 0:
                selected.append(best[u])
                total = plus(total, key[u])
            for v, i, w in g.adj[u]:
                if not done[v] and w < key[v]:
                    key[v], best[v] = w, i
                    heap.update(v)
    return selected, total

def kruskal(g, buckets=False):
    if g.directed:
        raise ValueError("MST needs an undirected graph")
    parent, size = list(range(g.n)), [1] * g.n
    if buckets:
        count, order = [0] * (g.m + 1), [0] * g.m
        for _, _, w in g.edges:
            if not 1 <= w <= g.m:
                raise ValueError("bucket weight out of range")
            count[w] += 1
        total_count = 0
        for w in range(1, g.m + 1):
            c, count[w] = count[w], total_count
            total_count += c
        for i, (_, _, w) in enumerate(g.edges):
            order[count[w]] = i
            count[w] += 1
    else:
        heap = Heap(g.m, [w for _, _, w in g.edges])
        heap.build(g.m)
    selected, total = [], 0
    for j in range(g.m):
        i = order[j] if buckets else heap.pop()
        u, v, w = g.edges[i]
        if set_union(parent, size, u, v):
            selected.append(i)
            total = plus(total, w)
        if g.n > 0 and len(selected) == g.n - 1:
            break
    return selected, total

七、§9.6：一次深入访问，保存进入与退出时的信息

DFS 是树的先序遍历推广：先标记顶点，再深入尚未访问的邻点；遇到未到达的区域就开一棵新树，得到完整森林。下面用显式调用帧保存“当前顶点、下一条邻接项”，在进入时写 tin，在所有出边结束时写 tout，并收集完成顺序。每个邻接项只扫描一次，空间 O(|V|)，时间 O(|V|+|E|)。

有向边可按进入／完成区间分成树边、回边、前向边与交叉边。指向正在处理的祖先的回边闭合环；没有回边时，逆完成顺序是拓扑顺序。判断树边必须保存精确的父边号，平行于树边的另一条边不能也被叫作树边。完整判定见习题 9.25。

图 9.74–9.77 先在 G 中做 DFS，按完成次序编号，再在转置图中按完成次序的逆序启动 DFS；每棵新树就是一个强连通分量。原书结果为 {G}、{H,I,J}、{A,B,C,F}、{D}、{E}。把每个分量缩成一点得到 DAG；若 G 中有分量 C→D，C 的最大完成时刻大于 D 的，因而转置图中的第一棵树不会误闯尚未归类的其他分量。

Kosaraju 包含两遍搜索和线性构造的转置图，总计 O(|V|+|E|)。同一程序块也给出习题 9.28 的 Tarjan 单遍算法：DFS 帧栈和“尚未归入已完成分量”的活跃顶点栈具有不同职责，后者的 on 标志不能换成普通 visited。

    for (int v = 0; v < g->n; ++v) { tin[v] = -1; parent_edge[v] = -1; }

无向 DFS 中，非树边只连接祖先和后代。Num 是发现序号，Low 是从当前子树沿树边下降、再至多走一条回边能到达的最小序号。进入节点时 Low=Num，遇到通向祖先的非父边时取 Num 的最小值，孩子返回时取孩子 Low 的最小值。

        ok &= len(odd) == 0 or (not circuit and len(odd) == 2)
        if odd:
            start = odd[0]
    if s < 0:
        s = start if start >= 0 else next((v for v in range(g.n) if degree[v]), 0)
    g.source_check(s)
    if start >= 0 and ((s != start) if g.directed else degree[s] % 2 == 0):
        ok = False
    if not ok:
        return None
    cur, used, stack, order, edge_order = [0] * g.n, [False] * g.m, [(s, -1)], [], []
    while stack:
        u, incoming = stack[-1]
        while cur[u] < len(g.adj[u]) and used[g.adj[u][cur[u]][1]]:
            cur[u] += 1
        if cur[u] == len(g.adj[u]):
            order.append(u)
            if incoming >= 0:
                edge_order.append(incoming)
            stack.pop()
        else:
            v, eid, _ = g.adj[u][cur[u]]
            cur[u] += 1
            used[eid] = True
            stack.append((v, eid))
    if len(edge_order) != g.m:
        return None
    return order[::-1], edge_order[::-1]

八、§9.7：归约解释哪些问题共享困难

欧拉问题访问每条边一次，Hamiltonian 回路访问每个顶点一次；无权最短路逐层扩展，最长简单路径则必须避免重复顶点。这些文字很接近的变化，不保证保留原来的算法。作者先用停机问题说明“不可判定”与“目前没有快算法”之间的边界：若有总能判断任意程序是否停机的程序 H，就构造输入自身时专门反着 H 的判断行动的程序 D，D(D) 的两种结果都矛盾。

P 和 NP 讨论的是判定问题及输入编码长度。P 中的问题可以在多项式时间求解；NP 中每个“是”实例有多项式长度的证书，可在多项式时间验证。NP 不是“非多项式”的缩写。给出一个 Hamiltonian 回路可以迅速检查，它是否有多项式时间的通用求解方法，是另一件事；原书没有证明指数下界。

要证明新问题 B 为 NP 完全，先证明 B∈NP，再从一个已知 NP 完全问题 A 构造 A≤pB，使两个实例的答案完全等价。归约方向是把已知难题放进新题，而不是把新题变成一个难题；后者不能证明新题难。优化问题通常先改为“是否存在代价不超过 K 的解”再讨论 NP 完全，优化版本则称 NP 难。

原题（中文翻译）

可能不同，但两者都合法。它们都只取当前入度为零的点；这样的点没有尚未处理的前驱，先取哪一个都不破坏任何依赖。只有出现多个可选点时，FIFO 与 LIFO 的选择才可能分开。

9.4 · 省去邻接矩阵的逐格初始化

原题（中文翻译）

用标准双重循环初始化邻接矩阵，本身就需要 O(|V|2) 时间。提出一种仍用邻接矩阵存储图的方法，使判断一条边是否存在的时间为 O(1)，同时避免二次方的初始化时间。

本版习题 9.4；印刷页 339／PDF 第 356 页。

解答

令 L=|V|2，把格 (u,v) 编为 x=u|V|+v。预留三个长度 L 的数组 value、where、dense，以及已写过的不同格数 k。value[x] 保存矩阵值，where[x] 声称 x 位于已写格列表中的哪个位置，dense[0…k−1] 保存真正写过的格号。开始只令 k=0，不逐格清零。

valid(x)⟺0≤where[x]<k ∧ dense[where[x]]=x

查询先检查范围，再检查反向对应；不成立就当作没有边。即使未使用的 where[x] 恰好落在范围内，已初始化的 dense 那一格也只会存某个真正写过的格号；若它真等于 x，则 x 本来就是已写格，因此不会产生假阳性。

第一次写 x 时，先令 dense[k]=x、where[x]=k，再令 k 增加 1，最后写 value[x]；以后写同一格只覆盖 value。删边可以把 value 设为“无边”，保留已写标记。两项检查和更新均为常数次操作，建图只初始化实际给出的边。

因此在允许读取任意初始机器字的单位成本 RAM 模型中，逻辑初始化为 O(1)，录入边为 O(|E|)，查询为 O(1)，预留空间仍为 Θ(|V|2)；申请如此大的空间及操作系统的按页清零另属资源成本。

这个模型条件必须保留：可移植 C11 不能把读取 malloc 后未初始化的整数当作已定义操作。若只用普通 C 数组，就须初始化标记、付出相应成本；也可改用散列表得到期望常数查询，但那已改变原题要求的矩阵表示。这里给的是原题的数据结构方法及它成立的明确模型，而不是一段含未定义行为的 C 技巧。

9.6·d 叉堆下的 Dijkstra 界

原题（中文翻译）

解答

使用保存顶点位置的索引 d 叉最小堆，一次降低键值最多沿树高上行，代价 O(logd(|V|+1))；一次删除最小值，每层须比较至多 d 个孩子，代价 O(dlogd(|V|+1))。最多有 |E| 次成功降低键值和 |V| 次删除，另加初始化与扫边。

T(d)=O(|V|+|E|+(|E|+d|V|)logd(|V|+1))

取 2≤d≤max(2,|V|)。稀疏图通常用常数 d；边较多时令 d≈max(2,|E|/|V|)，使扫边的降低键成本与删除成本处于相近量级。对边数至少与顶点数同阶的简单图，可写成 O(|V|+|E|log2+|E|/|V|(|V|+1))；稠密时接近二次方。

这个界依赖“一顶点至多一个堆项”。若只插入新候选而留下旧项，就可能有与边数同阶的删除操作，不能仍按 V 次 DeleteMin 计费。本章索引二叉堆正是 d=2 的版本。

Dijkstra 先确定 s，再把距离 2 的 a 确定，随后才处理 b。如果已确定点不再允许更改，它保留 a=2；实际最短路 s→b→a 的费用为 1。图是 DAG，连环都没有，因此错误完全来自负边破坏了贪心的定点条件。

b. 正确性与最坏界

使用 FIFO 队列，距离改善就入队，并用 in 标志避免同一顶点同时在队列中出现两次。为分析定义“轮”：一轮开始时记下当前队列长度，只处理这批顶点；在它们后面新加入的点留给下一轮。若尚未处理的点发生改善，它的位置仍在当前批中；已经出队的点再次改善，才接到下一轮。每轮每点最多出队一次。

任何有限标签都是某条从 s 出发的实际游走费用，所以不会小于真正的最短距离。按路径边数归纳：第一轮处理 s 后，所有一边路径都已被尝试；若前 r−1 条边的前缀到 u 已在不晚于第 r−1 轮得到所需标签，u 的改善会让它在不晚于第 r 轮被处理，从而尝试第 r 条边。u 若已在本轮处理过，改善便使它进入下一轮；若还在队列中，则本轮就会使用更小的标签。这正是归纳成立的两个情况。

没有可达负环时，每个可达点有一条不重复顶点的最短路：删去游走中的非负环不会增加费用。这样的路径最多有 |V|−1 条边，所以第 |V|−1 轮结束后全部最短标签已经正确；至多再用一轮把最后的队列项清空，不再产生改善。标签是实际游走费用，且已经不大于某条最短路，两边合起来便等于最短距离。

于是每个顶点最多出队 |V| 次，每条边最多在其起点出队时被扫描 |V| 次，总计 O(|V|+|V||E|)，辅助空间 O(|V|)。原题的 O(|V||E|) 写法把初始化忽略，或假定边数至少为 1 且足以覆盖相关顶点；显式保留孤立点时加上 |V| 更准确。

两版negative_paths使用循环 FIFO 队列，严格改善才入队。若某点出队次数超过 N，上述无负环界被违反，便报告可达负环；未从源点到达的负环不会入队，也不会误报。这个证明约束了出队次数，不能把“成功松弛次数超过 N”直接拿来替代判据。

9.8 · 整数边权与单层基数堆

原题（中文翻译）

*假设图中所有边权都是 1 到 |E| 之间的整数。Dijkstra 算法可以实现得多快？

本版习题 9.8；印刷页 340／PDF 第 357 页。

解答

令 n=|V|、m=|E|、C=m。整数性和已确定距离单调上升，可以把比较堆换成单层基数堆，得到 O(m+nlog(C+1))=O(|E|+|V|log(|E|+1))。这里采用 Ahuja、Mehlhorn、Orlin、Tarjan 的单层界，而不把“权重有限”直接等同于线性时间。来源是本章参考文献 [2] 的 Faster Algorithms for the Shortest Path Problem，§3.1。

先说明桶里保存的范围。刚确定的距离记作 μ；所有有限候选键都在 [μ,μ+C] 内，因为它们来自更早确定的点加一条至多 C 的边，且没有小于当前最小值的候选。最短路可取简单路径，因此所有有限候选也有 nC 的统一上界；不可达标记不加入堆。

取 B=⌈log2(C+1)⌉+2 个双向链表桶，每个顶点另存所在桶和链表句柄。桶 i 的区间为 [ui−1+1,ui]。桶 1 宽 1；第 2 至 B−1 桶的最大宽为 si=2i−2，最后一桶容纳剩余范围。初始 u0=−1、ui=2i−1−1（1≤i<B）、uB=nC+1，于是键 0 位于第一桶。

插入从最后一桶向下寻找；降低键值从原桶向下寻找，摘链与接链都是常数时间。删除最小时，第一桶若非空就直接取一项；否则找到最早的非空桶 j，扫描它找出最小键 z，设置 u0=z−1、u1=z，再依次设置下列边界，保持 uj及更高边界不变，最后重新分配桶 j 的项。

ui=min(ui−1+si,uj),2≤i<j

为何重分配一定使桶号下降？若 j 不是最后桶，它的原宽至多 sj，而下面各桶的总最大宽正好为 sj；从最小键 z 重新起算，足以覆盖桶 j 剩余的全部键。若 j 是最后桶，所有候选距 z 不超过 C，而较低各桶的总宽至少 C+1，同样装得下。截断到 uj只制造空桶，不使已有高桶的区间失效。各边界只会上移，降低键值又只向下移动，所以一个顶点的桶号永不增加。

每个顶点最多下降 B−1 次，所有链表重分配与向下搜索可累计为 O(nB+m)：一次更新先付常数成本，额外搜索按桶号下降收费；反复扫描一个非空桶时，它的全部项目随后都会下降，扫描也有同一支付来源。每次删除寻找桶和重设边界另用 O(B)，至多 n 次，故总界为 O(m+nlog(C+1))。键与 nC 须能装进常数个机器字，以上按单位成本整数 RAM 计量。

直接设置 nC 个距离桶并扫描空桶，最坏反而要 nC 的工作；单层基数堆的指数宽区间与摊还分析，正是避免这一代价的部分。m=0 时无边可松弛，只做顶点初始化。

9.10 · 最短路的条数与最少边数

原题（中文翻译）

  1. 解释如何修改 Dijkstra 算法，使其同时计算从 v 到 w 的不同最短路径的条数。
  2. 解释如何修改 Dijkstra 算法，使从 v 到 w 存在多条最短路径时，选择边数最少的一条。

本版习题 9.10；印刷页 340／PDF 第 357 页。

解答

a. 严格正权时的计数递推

先设 ways[v]=1，其他为 0。沿 u→x 松弛时，若找到更小距离，就把 ways[x] 重置为 ways[u]；若找到相等距离，就把 ways[u] 加到 ways[x]。严格正权保证每条最短路的最后一条边都来自距离更小、已经处理完的点，因此每条路线恰好在它的最后一条边处计数一次。

ways[x]=∑(u,x)∈Ed[u]+c(u,x)=d[x]ways[u]

本页shortest_counts先运行 Dijkstra，再按距离非降序扫描“紧边” d[u]+c(u,x)=d[x]，实施同一递推。紧边严格增加距离，构成 DAG，时间仍与堆版 Dijkstra 同阶。平行边按不同边号算不同路径；不可达点为 0，源点的零边路径为 1。计数超过无符号 64 位，两版都明确报错。

原题未说明零权的细节。零权边可连接同距离点，某个点被确定后还可能得到新的条数，因此直接在 Dijkstra 出堆时传播计数会漏算。例如 s→a、s→b 权为 1，b→a 权为 0；若先处理 a，再处理 b，a 的新增条数已无法传播给它的后继。

完整处理规则是先建源点可达的紧边图，再只保留还能到达目标 w 的部分。若把路径理解成允许重复顶点的游走，这部分有环时该环费用为 0，可重复绕行，所以最短游走有无穷多条；无环时按拓扑序使用上式，线性计数即可。若要求简单路径，零权环不会造成无穷，但一般情形须枚举不重复顶点的紧边路径进行精确计数；全零权图已包含一般简单路径计数，不能用“把强连通分量缩成一点”省去分量内部的不同路线。本页的计数接口采用严格正权条件，避免把上述不同问题混成一个计数。

b. 先最小费用，再最少边数

先求非负权图的最短距离 d，仅保留紧边，然后从源点在紧边图上运行 BFS。到达 x 的第一条 BFS 路线具有最少边数；所有紧边路线的费用沿途相消，恰好等于 d[x]。反过来，任何最短路的每条边都必须是紧边，否则其前缀可以被更短路线替换而改善总费用。因此这个 BFS 正好在全部最短路中作第二次优化。

双语fewest_edges实现这一方法，并另存 BFS 前驱与 hops。零权边和零费用环都可处理，因为 BFS 每点只入队一次；辅助 BFS 为 O(|V|+|E|)，总时间仍为 O((|V|+|E|)log(|V|+1))。不可达点 hops=−1，不用它原来的距离前驱冒充答案。

9.14 · 一次增广量最大的路径

原题（中文翻译）

给出一个算法，找到允许最大流量通过的增广路径。

本版习题 9.14；印刷页 341／PDF 第 358 页。

解答

要最大化的是该路径所有残余容量的最小值，即瓶颈，而不是容量总和。令 width[s]=∞，其余为 0；每次确定尚未确定点中 width 最大者 u，沿正残余容量边更新。

width[w]←max{width[w],min(width[u],r(u,w))}

与 Dijkstra 相似，区别是“前缀相加”改成“瓶颈取小”，“取最小距离”改成“取最大瓶颈”。若某条到 u 的路径比刚选的 width[u] 更宽，取路径上第一个未确定点 y；它前面的点已确定，松弛已使 width[y] 不小于整条路径的瓶颈，便应先于 u 被选择，矛盾。

用索引最大堆并记录前驱残余边，时间 O((|V|+|E|)log(|V|+1))，空间 O(|V|)；到 t 的 width 就是这次允许的最大增广量。若 width[t]=0，则没有增广路。

双语augment_path 的 widest 分支以 −width 作为最小堆键，始终只扫描正残余容量。驱动 wideflow 会每轮重新找最宽路并增广，flow 则每轮用 BFS；两者都通过最后的残余可达割证明总流最优。“本次增广量最大”不表示一次就得到最大总流。

9.16 · 负权边是否破坏生成树算法

原题（中文翻译）

边权中存在负数时，Prim 或 Kruskal 算法还能工作吗？

本版习题 9.16；印刷页 341／PDF 第 358 页。

解答

两种算法都能工作。生成树的目标是固定包含 N−1 条边的树的总费用，算法正确性由割交换论证给出：把最轻跨割边换入最优树，费用不增加。该比较只使用大小关系，不需要边权非负；“负边会反复绕圈”也不会发生，因为结果必须无环。

例如三角形边权为 −4、−2、3，最优树选择两条负边，总重 −6。Prim 的 key 是一条边的权重，所以初始化新分量时用 0 只用于选择起点，不能把所有候选强行截到零。Kruskal 直接按带符号权重排序即可。本章两版保留负数，并在断开图上返回最小生成森林。

与之相比，Dijkstra 的确定性证明需要路径后续费用不能变小，所以负边会破坏它。这正说明“贪心算法”不共享同一个正确性前提。

9.17 · 最小生成树可以有多少棵

原题（中文翻译）

证明一个含 |V| 个顶点的图可以有 |V||V|−2 棵最小生成树。

本版习题 9.17；印刷页 341／PDF 第 358 页。

解答

取 n 个有编号的顶点，构造完全图 Kn，把每条边的权重都设为 1。每棵生成树都含 n−1 条边、总重 n−1，所以全部生成树都是最小生成树。下面用 Prüfer 编码证明生成树恰有 nn−2 棵，而不是只引用一个计数公式。

编码：重复 n−2 次，每次删掉当前编号最小的叶子，把它唯一邻点的编号追加到序列。最后只剩两个顶点。序列长 n−2，每项都从 1…n 中选。

解码：统计序列里每个编号的剩余出现次数；每次取剩余顶点中编号最小、出现次数为 0 的点 x，把 x 与序列首项 y 连边，删掉 x 和首项，并将 y 的次数减 1。序列用完后，把最后两个顶点连接。每一步都有这样的 x，因为剩余顶点数总比剩余序列长度多 2。

解码每步把一个新叶子接入尚未删去的部分，不会形成环，最后连通，因而生成一棵树。在树的编码中，某顶点出现次数等于它当前度数减 1，所以解码找到的最小零次数点正是编码会删除的最小叶子；逐步归纳，两种过程互逆。

长度 n−2 的任意编号序列与一棵树一一对应，数目为 nn−2。结论适用于 n≥2；n=2 时空序列对应唯一的一条边，n=1 时只有一棵空边树，单独处理即可。

9.18 · 实现 Kruskal 算法

原题（中文翻译）

编写程序实现 Kruskal 算法。

本版习题 9.18；印刷页 341／PDF 第 358 页。

解答

两版完整实现见kruskal 与并查集，索引堆见共同堆。每个顶点初为一棵集合树；把全部原边线性建堆，依权重和原边号取出；端点根不同时合并并保存边号，否则丢弃。达到 N−1 条后立即停止，避免在已连通图中继续删除无用候选。

自环的两个端点本就在同一集合，被拒绝；平行边分别参选，合适的一条可被接纳；负边正常排序。若候选耗尽仍不连通，输出最小生成森林及实际条数，而不是把少于 N−1 条边叫作生成树。N=0 或 1 时直接得到零条边。

并查集采用按大小合并与路径压缩。建堆为 O(|E|)，最坏选边为 O(|E|log(|E|+1))，并查集另需 O((|V|+|E|)α(|V|+|E|,|V|))；保存结果和索引占 O(|V|+|E|)。正文割交换论证给出正确性，题 9.15 给出有拒绝边和平局的可核对过程。

9.22 · 割点判据的充分必要性

原题（中文翻译）

证明寻找割点的算法正确。

本版习题 9.22；印刷页 342／PDF 第 359 页。

解答

先证明无向 DFS 中没有连接两棵不同孩子子树的边：如果先访问的子树能沿边到达另一端，DFS 会立即把那个尚未访问的点吸收入同一子树；若另一端早已访问，它只能是正在递归的祖先。于是非树边只连接祖先和后代。

Low(v)=min(Num(v),min(v,x) 是回边Num(x),minw 是树孩子Low(w))

这三个来源分别对应“不走边”“直接走一条回边”“先走树边进入孩子子树，再至多走一条回边”，所以后序递推恰好计算定义中的最小序号；不是凭图例猜出的数值。

对于非根 v，若某个孩子 w 满足 Low(w)≥Num(v)，w 的子树没有任何边可接到 v 的严格祖先；又不可能接到其他孩子子树。删去 v 后它与 v 的父亲所在区域分开，因此 v 是割点。

反过来，若每个孩子 w 都满足 Low(w)<Num(v)，每棵孩子子树内都有一条回边通到 v 的严格祖先。删除 v 后，子树中的任一点仍可沿子树路径接到那条回边，再接到祖先区域；v 外部的其他区域也由剩余树边接到祖先区域。因此原连通分量仍连通，v 不是割点。叶子没有孩子，正好落在这一种情况。

对根 r：若至少两个孩子，两个子树没有跨边，删除根会分开它们；若只有一个孩子，删根后整棵孩子子树仍连通；没有孩子则只删掉一个孤立点，不增加分量数。对每个原连通分量分别用这些规则，便找全而且只找到割点。

双语lowlink在孩子返回时合并 Low，在根退出时按树孩子数修正割点标志。每条邻接项常数次访问，时间 O(|V|+|E|)；父边按边号跳过，平行于它的第二条边仍可降低 Low。

9.23 · 删边去环：无向与有向

原题（中文翻译）

  1. 给出算法，求从无向图中至少要删除多少条边，才能使剩余图无环。
  2. *证明对于有向图，这个问题是 NP 完全的。

题干校注：b 问的 NP 完全表述指判定版本“是否能删除至多 K 条边使图无环”；求最少删除条数的优化版本称为 NP 难。

本版习题 9.23；印刷页 342／PDF 第 359 页。

解答

a. 保留生成森林

先用 DFS 或并查集求原图的连通分量数 c，保留每个分量的一棵生成树，删除全部非树边。保留边数是 |V|−c，因此删除条数为 |E|−|V|+c；每点、每边访问一次，时间 O(|V|+|E|)。

任何无环剩余图是森林；删除边不会把两个原来不同的分量合并，所以至少仍有 c 个分量，最多保留 V−c 条边。因此上面的删除数达到下界，确为最小。自环要删，两个点之间多条边最多保留一条，公式仍有效。

b. 从 Vertex Cover 作完整归约

给定无向 Vertex Cover 实例 (G,K)，可先将 K 规范在 0…V：K<0 直接是“否”，K≥V 直接是“是”。其 NP 完全性由原书 §9.7 已知的 Clique 与习题 9.39 的归约得到。构造有向图 H：

  1. 每个原顶点 v 拆成 vin、vout，加一条选择边 vin→vout。
  2. 对每条原边 {u,v}，分别从 uout 到 vin、从 vout 到 uin 各建 K+1 条长度为 2 的路径。每条路径使用一个全新的中间点，因此这些路径互不共用边，构造也是简单有向图。
  3. 删除边预算仍为 K。

若 G 有大小至多 K 的顶点覆盖 S，就删掉 H 中所有 v∈S 的选择边。任何有向环必须反复通过一个顶点的“入→出”选择边，再沿原图某条邻接关系去另一个顶点；但每条原边至少有一个被选端点，其选择边已经删掉，所以不可能组成环。

反过来，设删除至多 K 条边使 H 无环。每个方向有 K+1 条互不共边的二边路径，用 K 次删除无法把任一方向全部截断。若原边 {u,v} 的两条选择边都未删，仍可从 uin→uout→vin→vout→uin 绕一圈，其中两段邻接连接选各自幸存的二边路径，形成有向环，矛盾。因此被删除选择边所对应的原顶点必覆盖每条原边，数量至多 K。

两方向等价。新增顶点、边数为 O(|V|+|E|(K+1))，因 K≤V，构造规模与时间都为多项式。新问题属于 NP：证书为待删边号列表，检查条数后，对剩余图作一次拓扑排序即可验证无环。因此其判定版本为 NP 完全。

9.24 · DFS 交叉边为何从右向左

原题（中文翻译）

证明：有向图的深度优先生成森林中，所有交叉边都从右向左。

原书上下文：“左、右”指把同一顶点的孩子按发现先后从左到右摆放，整片森林的新树也按启动顺序从左到右摆放。任意重新排列绘图位置后，几何上的方向不再是这个命题。

本版习题 9.24；印刷页 342／PDF 第 359 页。

解答

设扫描边 u→w 时，它被判为交叉边。若 w 未访问，DFS 会立即深入它，这条边是树边；若 w 正在递归中，它是 u 的祖先，这条边是回边。因此交叉边的终点 w 已完成。

若 w 是 u 的后代，边应归为前向边；交叉边排除了这个情形，所以 w 在另一个早已完成的分支或更早启动的树内。当前 u 所在分支尚未完成，按发现顺序它位于 w 分支的右边，于是这条边从右向左。

若企图存在一条从较早分支指向尚未启动的右侧分支的边，扫描它时右侧点还是白色，DFS 便会把右侧点吸收成当前分支的后代，无法仍作为独立的右侧分支。这给出同一个结论的直接反证。

9.27 · 实现强连通分量

原题（中文翻译）

本版习题 9.27；印刷页 342／PDF 第 359 页。

解答

双语实现是kosaraju。第一遍在原图中保存 DFS 完成序列；线性建立所有边反向的转置图；按第一遍完成时刻从大到小，在转置图中从尚未归类点启动第二遍 DFS，一次搜索到的所有点赋同一个分量编号。

正确性看缩点 DAG：若两个不同分量 C→D，则 C 的最大完成时刻大于 D 的。先发现 C 时它能搜索并先完成 D；先发现 D 时，D 无法回到 C，否则两者是一个分量，所以 D 先完整结束。两个情况都得到同一不等式。

9.28 · Tarjan：只做一次 DFS

原题（中文翻译）

*给出只使用一次深度优先搜索就能找出强连通分量的算法。采用与双连通性算法类似的方法。

本版习题 9.28；印刷页 343／PDF 第 360 页。

解答

双语tarjan在进入点 u 时赋 num[u]=low[u]，把它放到活跃顶点栈并标 on[u]。这份栈保存已经发现、尚未归入完成分量的顶点；它与保存程序返回位置的 DFS 帧栈分别维护。

  1. 沿树边深入未访问孩子 w；孩子返回后令 low[u]=min(low[u],low[w])。
  2. 遇到已访问且 on[w] 为真的边，令 low[u]=min(low[u],num[w])；若 w 已离开活跃栈，忽略它，因为它属于已经封闭的分量。
  3. 处理完 u 的全部出边后，若 low[u]=num[u]，从活跃栈顶连续弹出直到 u，弹出的点全属于一个新分量；一并清除它们的 on 标志。

关键不变量是：活跃栈中的未封闭点保留通向其尚未封闭较早点的低编号联系；没有这类联系的子树在返回时会自行弹出。树边贡献孩子的 low，指向栈内点的边只贡献那一点的 num，二者所证明的路径来源不同。指向已经弹出分量的边只会走出去，不能把两个分量重新接成互达区域。

证明可按真正强连通分量的完成次序归纳。取分量 S 中最早发现的点 r：DFS 从 r 能到达 S 的所有点，所以它们都在 r 的树子区域内；又因各点能回到 r，S 内比 r 晚发现的点会通过树边返回与栈内边保持低编号联系，不能先于 r 被封闭。若 S 的出边进入另一个分量，该分量不能再回到 S，故在 r 完成之前已作为更早完成的分量弹出；按归纳，它不再影响 S 的 low。

因此 r 完成时，栈上属于 S 的点连续位于 r 及其上方，外出的分量已被除去，且没有指向更早活跃分量的低编号联系；否则那些点和 r 的 DFS 到达路径组成相互可达关系，应属于同一个 S，违背 r 是 S 中最早点。于是 low[r]=num[r]，恰好弹出 S。S 内其他点具有回到更早点的联系，不会错误地成为根。由此每个分量都会被一次且仅一次弹出。

每个点进入、退出两份栈各一次，每条边扫描一次，时间 O(|V|+|E|)，辅助空间 O(|V|)。显式帧实现避免把 C 调用栈或 Python 递归限制加入正确性条件；断开图从每个未访问点继续启动同一趟 DFS 森林。

9.32 · 实现欧拉回路与欧拉路线

原题（中文翻译）

  1. 编写程序，在图存在欧拉回路时找出它。
  2. 编写程序，在图存在欧拉路线时找出它。

本版习题 9.32；印刷页 343／PDF 第 360 页。

解答

完整双语实现见euler。a 选择 circuit=true，b 选择 circuit=false；本页接口还支持有向图。原书的 Euler tour 指不必闭合的逐边一次路线，允许它恰好闭合，不能译成必须开放。

无向图中，忽略孤立点后须连通；回路要求所有点度数为偶数，路线允许 0 或 2 个奇度点。两个奇点时从其中一个出发；全部偶数时从任一有边点出发。指定错误起点会拒绝查询，避免在有开放路线时从内部偶点开始。

算法把当前点及进入它的边号压栈；有未用边就标边已用并走到另一端，当前点没有未用边时弹出，把点和进入边记到逆序答案中，最后反转。栈弹出顺序自动把后发现的闭合段嵌入先前路线，是正文“插入回路”的线性实现。无向边的两条邻接项共用 used[edge]，不能当成两条独立边。

有向开放路线要求一个点出度比入度多 1，另一个点入度比出度多 1，其余相等；全相等时取回路。运行后必须恰好用了 M 条边，才接受答案。这样在度数局部正确但有多片边分量时，也会被拒绝。

每条邻接项被游标跳过至多一次，每条边走一次，时间和含输出的空间均为 O(|V|+|E|)。空边图返回所选单点，零顶点图返回空路线；自环与平行边保留独立边号。验证应按返回的边号逐步查端点、查方向、查每条边恰好出现一次，而不只检查顶点序列长度。

9.33 · 有向欧拉回路的条件与构造

原题（中文翻译）

有向图中的欧拉回路是每条边恰好访问一次的闭合路线。

  1. *证明：有向图有欧拉回路，当且仅当它强连通且每个顶点的入度等于出度。
  2. *给出线性时间算法，在有向图存在欧拉回路时找出它。

题干校注：有边图的“强连通”应限于所有入度或出度非零的点。一个有向环外加一个孤立点，仍可走完全部边，却不满足全顶点强连通；原题通常默认排除了孤立点。无边情形另按零边回路约定处理。

本版习题 9.33；印刷页 343／PDF 第 360 页。

解答

a. 充分必要性

必要性：闭合路线每次进入一个点都要离开，所以入度等于出度；路线访问每条边，也访问每个有边点。从其中任何一点沿闭合路线继续绕行都能到其他点，因此边支撑子图强连通。

充分性：从任一有边点 s 沿未用出边继续走。在其他点 u，每一次先进入都消耗一条入边；入出总数相等，若尚未闭合就不可能先把 u 的出边耗尽，所以第一次无边可走只能回到 s，得到一个闭合段。移去这一段后，各点剩余入出度仍相等。

若还有未用边，强连通性保证已得路线中某个点还有未用出边：否则从已访问区域不能走到任何未用边所在区域，因为跨出区域的第一条原边若已用，其终点也已经被访问，矛盾。由那个点在剩余边上得到新闭合段并插入旧路线；反复插入直到全部边用完，就构成欧拉回路。

b. 线性实现

使用题 9.32 的栈式 Hierholzer 和永久邻接游标，便把上述拼接隐含在逆序输出中，时间 O(|V|+|E|)。两版有向 euler 分支先查度数，再检查用边数是否为 M，这等价地拒绝不连通的边区域，无需重复做一次强连通分量搜索。孤立点不进入路线，也不让合法回路失败。

  3. **证明平面图满足 |E|≤3|V|−6。

题干校注：c 的标准条件为简单、无自环平面图且 |V|≥3；b 要求至少有一个顶点。平行边与自环可任意增加边数，不满足同一个界。图 9.85 位于印刷页 344／PDF 361。

本版习题 9.35；印刷页 343／PDF 第 360 页。

解答

先证明 c：Euler 公式给出边界

对连通平面嵌入，记面数 F，把外部面也算一面。不断删除环上的一条边，它分隔的两面合成一面，E 和 F 同时减 1，而 V 不变；直到剩下树，此时 E=V−1、F=1。由不变量逆推得到 V−E+F=2。

简单无自环图且 V≥3 时，每个面的边界游走长度至少为 3。桥在同一面边界中出现两次，仍按两次计算；连通树的唯一面边界长 2(V−1)≥4，也不例外。每条边在全部面边界中总计贡献 2 次，所以 3F≤2E。将 Euler 公式代入：

3(2−|V|+|E|)≤2|E|⟹|E|≤3|V|−6

若图断开，可在平面嵌入中给分量之间添加不交叉的新边，接成简单连通图，不增加顶点；原图边数不大于新图，仍满足该界。少于三个顶点时单独用 E≤V(V−1)/2，不能套右端可能为负的公式。

a. 图 9.85 的两张图

K5 有 V=5、E=10，而 3V−6=9，矛盾。K3,₃ 有 V=6、E=9，普通三角面界不够强；它是二分图，没有奇环，且每条边都在环上，所以每个面边界至少为 4。于是 4F≤2E，与 Euler 公式合得 E≤2V−4=8，而实际是 9，也矛盾。

b. 一定有不超过五个邻点的顶点

当 V≥3 时，平均度为 2E/V≤6−12/V<6，所以不可能每个点度数都至少 6，至少一个点度数≤5。在简单图中度数就是不同邻点数。V=1 或 2 时结论直接成立，空图则没有可选顶点，属于题干省略的例外。

9.36 · 平行边需要哪些修改

原题（中文翻译）

多重图允许同一对顶点之间存在多条边。本章哪些算法可以不修改地用于多重图？其余算法需要作什么修改？

本版习题 9.36；印刷页 344／PDF 第 361 页。

解答

以邻接表确实保存每条边为前提，算法是否依赖“只有一条 u—v”决定答案。下表区分不变量与数据表示；仅把平行边覆盖掉，不算支持多重图。

算法所需处理
BFS、二分图、拓扑排序、Dijkstra、FIFO 负边、DAG 路径核心规则不变。拓扑排序每条平行边都贡献并抵消一次入度；距离可由各边分别松弛，BFS 的顶点标记防止重复入队。
Prim、Kruskal核心选择与交换证明不变；每条边作为独立候选。已在同一集合的平行边闭环而拒绝，保留更适合的边即可。
Kosaraju、Tarjan仍按有向可达性判断，重复邻接项不改变分量；转置保留所有原边。
无向割点、桥、双连通边块父关系改为精确父边号。只跳过进入当前点的那一条边，第二条平行父边必须当作回边，否则会错误报桥；边栈按唯一边号压入一次。
DFS 边分类树边按父边号判断，不能只比较父顶点。指向同一孩子的其他边是前向边，不全是树边。
欧拉路线每条原边独立标 used；无向的两条邻接项共享原边号。用边数按真实 M 核对，不能把同端点边一起标已用。
最大流容量可按同方向端点合并求总流，但若要输出每条原边流量，还须再分配回原边。本页直接保存独立残余边对，平行与反平行原边均不混淆。
矩阵、路径计数与复杂度矩阵求最短路可取平行边最小权，求流可加容量；若需原边身份则另存边表。计数须说明按边序列还是顶点序列区分；本页按边序列。多重图 E 不受 V2 约束，堆含 E 项时不能无条件把 logE 换成 logV。

自环是另一项需要明示的输入条件：它使二分图失败、使拓扑排序检测到环；非负自环不改善最短距离，负自环可形成负环；生成树拒绝自环；欧拉算法保留它，并让无向度数增加 2。带零权自环的最短游走计数又会无限，按 9.10 的条件处理。本页代码已保存原边身份并执行这些规则。

9.37 · 线性构造强连通定向

原题（中文翻译）

*给定无向图 G=(V,E)。用 DFS 设计线性算法，把 G 的每条边转换成一个有向边，使所得图强连通；若做不到，则判断不可能。

本版习题 9.37；印刷页 344／PDF 第 361 页。

解答

对于至少一个顶点的图，存在这种定向当且仅当原图连通且没有桥。单点无边图以零长度路径视为强连通；多个点中有孤立点则不能忽略，因为此题要求整个 V 强连通。

必要性：原图不连通，改方向不能产生跨分量路径；若有桥，删桥会把图分成两侧，唯一跨边无论朝哪边，反方向都无法通过，所以不能强连通。

算法在一次无向 DFS 中计算 Num／Low。每条树边定向为父→子，每条回边定向为后代→祖先；发现分量数大于 1 或树边 Low[child]>Num[parent] 时报告不可能。平行边按边号区别，第二条父边朝上，因而两条平行边不会被误判为桥。

充分性：根沿定向树边可以到达所有点。对任一非根 v，父边不是桥，故 Low[v]≤Num[parent[v]]；于是 v 子树内存在一条回边接到其严格祖先。v 沿定向树边下行到该回边起点，再沿回边上行，便到达发现编号更小的祖先。重复此过程，编号严格下降，最终到根。所有点都能到根，根也能到所有点，因此任何两点之间都可先到根再出发，所得图强连通。

双语lowlink 的 orient_from／orient_to 与 orient 驱动实现这项构造，每条邻接项常数次处理，时间 O(|V|+|E|)、空间 O(|V|+|E|)。报告不可能时可输出桥作为证据；可行时可用 SCC 检查全部点是否处于同一分量。

9.38 · 拾取杆的几何比较与拓扑排序

原题（中文翻译）

给定 N 根以某种方式相互叠放的杆，每根由两个端点指定；端点为给出 x、y、z 坐标的有序三元组，没有杆是竖直的。只有上面没有其他杆时，才能拾取一根杆。

  1. 解释如何编写接收两根杆 a、b 的例程，报告 a 位于 b 上方、下方还是二者无关。（这一步与图论无关。）
  2. 给出算法，判断是否能拾取全部杆；如果能，给出相应的拾取顺序。

原书上下文：以端点定义的零厚度线段、沿 z 方向向上拾取来建模。题干没有给杆半径；若要处理实际粗杆，遮挡计算须另输入半径。三维相交或重合的杆不满足通常叠放模型，几何例程明确报告该配置不合法，而不随意选一个上下方向。

本版习题 9.38；印刷页 344／PDF 第 361 页。

解答

a. 先比较 xy 投影

投影不相交就无关。设两杆投影为 A0+t·a、B0+u·b，其中 a、b 非零，参数均在 [0,1]。两向量不平行时，记二维叉积 D=a×b，交点参数为：

t=(B0−A0)×ba×b,u=(B0−A0)×aa×b

若任何参数不在 [0,1]，投影线段不交。否则分别按参数线性插值出两杆的 z，高者遮挡低者；高度相等意味着两线段在三维相交，按前述输入模型报告配置不合法。

平行但不共线时无关；共线时选择一个非零投影坐标轴，算出投影重叠区间。如果没有重叠就无关；在重叠区间的两个端点求高度差 Δ，两根杆的高度沿这个坐标都是一次函数，所以 Δ 也是一次函数。两端严格同正号则 a 在上，同负号则 a 在下；出现零或符号相反，表示有三维接触、相交或重合，返回模型输入错误。重叠仅一个投影点时，直接比较该点高度即可。

每对比较只作常数次几何运算。整数或有理端点可用有理参数及交叉相乘精确判断；若用浮点数，误差容限必须是输入约定的一部分，不能把临界结果随意翻成一条依赖边。

b. 上方杆先拾取

每根杆为一个顶点。逐对比较，若 a 在 b 上方，就加 a→b，表示必须先移走 a；无关则不加边，非法几何配置直接返回错误。执行拓扑排序：零入度点当前没有任何上方阻挡，取出它并删除其依赖边，便让下面的杆可能变为可取。

若能排出全部 N 点，按顺序拾取就是合法方案；若排不完，剩余有有向环，环内每根杆都有一个尚未移走的上方阻挡，没有任何一根能作为下一步，故不能全部拾取。环就是不可能的证据。

两两比较与建图为 O(N2)；排序为 O(N+|E|)，而 |E|≤N(N−1)/2，所以总时间 O(N2)，空间最坏同阶。这里的线性几何计算按实数 RAM 或固定精度坐标计；任意大有理数时应另计数值位长。

9.39 · Clique 到 Vertex Cover

原题（中文翻译）

Clique 问题：给定无向图 G=(V,E) 和整数 K，G 是否包含至少 K 个顶点的完全子图？

Vertex Cover 问题：给定无向图 G=(V,E) 和整数 K，是否存在 V′⊆V，满足 |V′|≤K，并且 G 的每条边至少有一个端点属于 V′？证明 Clique 可多项式归约到 Vertex Cover。

本版习题 9.39；印刷页 344／PDF 第 361 页。

解答

构造 G 的补图 G―：顶点不变，对不同的两个点，它们在补图相连当且仅当在原图不相连。把新预算设为 K′=|V|−K。

G 有大小≥K 的 clique⟺G― 有大小≥K 的独立集⟺G― 有大小≤|V|−K 的顶点覆盖

第一步：完全子图内的任意两点在 G 有边，所以在补图没有边，正是独立集；反过来一样。第二步：S 是独立集，当且仅当它的补集 V∖S 覆盖每条边；若有边两端都在 S，就同时违反独立性和覆盖性。集合大小互补，便得到预算的不等式。

检查全部点对、构造补图用 O(|V|2) 时间与空间，预算转换只需一次减法，是多项式归约。若 K≤0，原问题直接为“是”；若 K>V，直接为“否”，可映到固定的同答案实例，或让负预算的覆盖实例按定义为“否”。

原书 §9.7 把 Clique 列为已知 NP 完全问题，这个归约说明 Vertex Cover 为 NP 难；覆盖问题也属于 NP，因为给出候选点集后可以逐边验证覆盖并核对大小，所以它是 NP 完全。这一结论供 9.23 与 9.41 的归约使用。

9.40 · Hamiltonian 回路与最长简单路径

原题（中文翻译）

假设无向图的 Hamiltonian 回路问题是 NP 完全的。

  1. 证明有向图的 Hamiltonian 回路问题也是 NP 完全的。
  2. 证明无权有向图的简单最长路径问题是 NP 完全的。

题干校注：b 的判定版本是“是否存在至少 K 条边的简单有向路径”；求最大长度的优化版本称为 NP 难。原问题可限于至少三个顶点的简单无向图，有限的小规模例外直接判定。

本版习题 9.40；印刷页 344／PDF 第 361 页。

解答

a. 每条无向边换成两个方向

对无向输入 G，把每条 {u,v} 换成 u→v 和 v→u 两条弧，顶点保持不变。原图任一 Hamiltonian 回路选一个绕行方向，便得到新图的有向 Hamiltonian 回路；新图任一有向 Hamiltonian 回路忽略方向，又得到原图回路。构造 O(V+E)，答案双向等价，所以有向问题 NP 难。

证书为顶点排列，检查每点出现恰好一次、相邻两点及最后回到第一点的弧都存在，可多项式验证，所以有向 Hamiltonian 回路问题属于 NP，因而 NP 完全。

b. 把回路切开成为覆盖全部点的路径

从 n 点的有向 Hamiltonian 回路实例 H 中任取一个点 v，拆成起点 vout 和终点 vin；原来从 v 出发的弧改从 vout 出发，原来进入 v 的弧改进入 vin，其余弧不变。新图有 n+1 个点，vout 入度为 0，vin 出度为 0。询问是否有至少 n 条边的简单路径。

H 的 Hamiltonian 回路在 v 处切开，得到 vout→……→vin 的 n 边路径，经过新图全部 n+1 点。反过来，简单路径最多有 n 条边；若达到阈值，必须覆盖全部点。由于 vout 无入边，它只能是起点；vin 无出边，它只能是终点。把这两点重新合成 v，就得到 H 中经过每点一次的 Hamiltonian 回路。

构造时间与规模为 O(n+|E|)，所有弧无权，长度只计边数。证书是一列不同顶点，核对相邻弧与边数≥K 可多项式完成，故判定版本属于 NP；上述归约给出 NP 难性，所以它为 NP 完全。DAG 的线性最长路径不冲突，因为这里的新图允许有环。

9.41 · 卡包收集是 NP 完全问题

原题（中文翻译）

棒球卡收集问题如下：给定卡包 P1,P2,…,PM，每包包含当年全部棒球卡中的某个子集，另给整数 K。是否能够选择至多 K 个卡包，收集齐当年的全部棒球卡？证明棒球卡收集问题为 NP 完全。

本版习题 9.41；印刷页 344–345／PDF 第 361、362 页。

解答

属于 NP：证书为不超过 K 个包的编号，逐项标记它们的卡片并核对是否覆盖全年卡片集合即可，时间按输入卡片总出现数和全集大小计为多项式。全年全集应明确作为输入；若某张卡没有出现在任何包中，立即是“否”。

从 Vertex Cover 实例 (G,K) 归约。每条原边 e 制作一张对应卡片，全年全集就是 E；每个原顶点 v 制作一个包 Pv，里面放所有与 v 相接的边卡。预算 K 不变。孤立点对应空包，不妨保留。

若 S 是至多 K 个点的覆盖，每条边至少一个端点在 S，它对应的卡便出现在这些点的包中，选择这些包可以收齐。反过来，若至多 K 个包收齐所有边卡，每条边卡只在它的端点包中出现，所选包对应的顶点至少覆盖该边的一个端点，因此构成大小至多 K 的顶点覆盖。

构造 M=|V| 个包、|E| 张卡，每张卡总共放入两个包，输入规模 O(|V|+|E|)，构造时间同阶。习题 9.39已给出 Vertex Cover 的 NP 完全依据，这一双向等价归约证明卡包问题 NP 难；加上前面的可验证证书，得到 NP 完全。空边全集可以用 0 个包收齐，K<0 则没有合法选择，这些边界不改变归约。

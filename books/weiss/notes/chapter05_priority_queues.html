第五章：优先队列（堆）

全书地图程序说明上一章：树下一章：排序

一、§5.1–5.2：队列顺序来自问题，而不总是到达时间

作者先谈打印任务：一份 100 页的文件排在若干份 1 页文件前面，按 FIFO 并不一定符合使用者的目标。操作系统调度也有类似问题，短任务和重要任务可能需要更早得到处理。第三章的普通队列只回答“谁最先到达”，优先队列回答的是“当前谁最应该先处理”。这里优先级是一套外部比较规则；本章采用键越小，越先取出的最小优先队列。

图 5.1 的基本接口只有 Insert 和 DeleteMin：前者加入一个元素；后者找到、返回并移除最小元素。FindMin 只观察，不删除。原书提醒 DeleteMin 既返回数据又改变结构，这个副作用必须体现在调用者对接口的理解中。空队列也必须有明确失败结果，不能把某个合法键值偷偷当成“未找到”。

§5.2 先复用已有结构。无序链表在表头插入只需 O(1)，但删除最小元要扫描 O(N)；有序链表把代价移到插入，最小元放在表头时删除只需 O(1)。从空结构开始，成功删除次数不超过插入次数，解释了作者为何倾向先让插入便宜；具体工作负载仍会影响选择。普通 BST 在适当随机输入模型下能取得期望对数操作，AVL 则能保证单次最坏对数，但它同时保存了按键查找等本题尚不需要的能力。

第四章教我们用键序缩小任意查找范围；第五章主动减少所保存的顺序，只保障最小元容易获得。优先队列是 ADT，二叉堆是实现它的一种结构。优先级相同的任务是否按到达先后处理，也不由堆序自动保证；若需要稳定性，可以比较“优先级、递增序号”这一对值。任务记录应有独立 ID，不能把有重复值的优先级当作身份。

二、§5.3.1–5.3.2：形状负责高度，堆序负责根

2.1　图 5.2–5.4：完全二叉树为什么能够放进数组

完全二叉树把上层填满，最后一层从左向右填，不允许中间缺位。非空树高度 h 按边数计算，有 2h≤N≤2h+1−1，所以 h=⌊log2N⌋。高度界由形状得到，与插入键是否有序无关；这正是普通 BST 无法自动获得的保证。

图 5.3 按层序把节点依次存入数组，书中从下标 1 开始：父亲为 ⌊i2⌋，左孩子为 2i，右孩子为 2i+1。孩子下标必须不超过当前规模，根没有父亲。若从 0 开始，公式变为父亲 ⌊i−12⌋、孩子 2i+1 与 2i+2；两套公式不能混用。数组的容量与当前规模也不是一回事：Capacity 决定可用空间，Size 决定哪些槽位属于堆。

2.2　图 5.5：堆序比 BST 的键序弱

最小堆要求每条父子边都满足父键不大于子键。沿根到后代的路径应用传递性，根就是整个堆的最小元；每棵子树也满足同样的堆序。然而左右兄弟、不同分支之间没有比较关系，左子树的键完全可以大于右子树的键。图 5.5 的反例保持了完全树的形状，却在一条边上违反堆序，说明两项约束缺一不可。

“a heap has very little ordering information”

译：堆保存的顺序信息很少。

§5.3.4，印刷页 154。它解释了为何取最小元很快，任意按键查找却仍可能扫描整个堆。

最大键可以出现在叶子中，叶子共有 ⌈N2⌉ 个，因此即使利用这个事实，找最大元仍是线性工作量。重复键是合法的：堆序使用“不大于”，而不是严格小于。树高只有对数，并不意味着所有查询都能在对数时间完成。

三、§5.3.3：先保持形状，再沿一条路径修复堆序

3.1　图 5.6–5.8：上滤移动的是空穴

插入时，新位置只能是数组末尾的下一个槽位，否则完全树形状被破坏。把新键 X 留在局部变量中，把该槽位视为空穴；如果父键比 X 大，就把父键向下搬到空穴，再让空穴向上。循环不变量是：除了空穴及其尚待接入的父子关系，其他子树的堆序仍成立，而且所有旧元素都已保存。找到位置后只写一次 X。

图 5.6–5.7 插入 14：初始层序为 [13, 21, 16, 24, 31, 19, 68, 65, 26, 32]。空穴从 11 开始，31 从 5 搬到 11，21 从 2 搬到 5；遇到根 13 后停止，把 14 放在 2。结果为 [13, 14, 16, 24, 21, 19, 68, 65, 26, 32, 31]。如果上移 d 层，空穴写法搬动 d+1 次；逐层交换通常需要 3d 次赋值。

原书把不大于所有合法键的 MinData 放在 Elements[0]，省去每轮根边界判断。若哨兵没有覆盖键域，新最小元可能一直停在下标 0。下面改为显式检查 i > 1，因此支持整个 int 键域。书中给出的平均比较数属于其随机模型与分析结果；确定性保证仍是单次最坏 O(log(N+1))，升序和逆序输入会表现得很不一样。

3.2　图 5.9–5.12：下滤必须选较小孩子

删除根后，最后一个元素必须退出末尾，以保持完全树；它暂存在局部变量 X，根成为空穴。如果 X 不大于较小孩子，就可以落位；否则把较小孩子提升，空穴沿这一侧下降。选择较大孩子会把较小孩子留在一个比它大的父亲下面，立刻违反堆序。

图 5.9 使用另一棵初始堆：[13, 14, 16, 19, 21, 19, 68, 65, 26, 32, 31]。删除 13，暂存末尾 31，依次提升 14、19、26，最后把 31 放在 9。结果为 [14, 19, 16, 26, 21, 19, 68, 65, 31, 32]。它与插入示例的起点不同，不能把图 5.8 的输出直接当作图 5.9 的输入。

3.3　完整的整数二叉堆教学实现

以下类型与函数可组成同一个 C11 源文件。外部函数接收有效的 Heap *；heap_up 要求只有向上的堆序可能受损，heap_down 要求孩子子树已是堆。输出指针须指向堆存储之外的独立有效整数。成功观察或删除时写入 *out，失败返回 false；返回值与键值分开。heap_build 的输入不能与堆内数组重叠，容量不足或非法输入在改动前失败。

C（C11）
#include <stdbool.h>
#include <stddef.h>
#include <limits.h>
#include <stdlib.h>

#ifndef HEAP_CAPACITY
#define HEAP_CAPACITY 64
#endif

typedef struct {
    size_t size;
    int a[HEAP_CAPACITY + 1]; /* a[0] is unused */
} Heap;

void heap_init(Heap *h) { h->size = 0; }

void heap_up(Heap *h, size_t i, int x) {
    while (i > 1 && x < h->a[i / 2]) {
        h->a[i] = h->a[i / 2];
        i /= 2;
    }
    h->a[i] = x;
}

void heap_down(Heap *h, size_t i, int x) {
    while (i <= h->size / 2) {
        size_t child = 2 * i;
        if (child < h->size && h->a[child + 1] < h->a[child])
            ++child;
        if (x <= h->a[child]) break;
        h->a[i] = h->a[child];
        i = child;
    }
    h->a[i] = x;
}

bool heap_insert(Heap *h, int x) {
    if (h->size == HEAP_CAPACITY) return false;
    heap_up(h, ++h->size, x);
    return true;
}

bool heap_find_min(const Heap *h, int *out) {
    if (!h->size || !out) return false;
    *out = h->a[1];
    return true;
}

bool heap_build(Heap *h, const int *input, size_t n) {
    if (n > HEAP_CAPACITY || (n && !input)) return false;
    /* input must not overlap h->a */
    for (size_t i = 0; i < n; ++i) h->a[i + 1] = input[i];
    h->size = n;
    for (size_t i = n / 2; i > 0; --i)
        heap_down(h, i, h->a[i]);
    return true;
}

bool heap_set_key(Heap *h, size_t i, int x) {
    if (i == 0 || i > h->size) return false;
    if (i > 1 && x < h->a[i / 2]) heap_up(h, i, x);
    else heap_down(h, i, x);
    return true;
}

bool heap_decrease(Heap *h, size_t i, int delta) {
    if (i == 0 || i > h->size || delta < 0 ||
        h->a[i] < INT_MIN + delta) return false;
    return heap_set_key(h, i, h->a[i] - delta);
}

bool heap_increase(Heap *h, size_t i, int delta) {
    if (i == 0 || i > h->size || delta < 0 ||
        h->a[i] > INT_MAX - delta) return false;
    return heap_set_key(h, i, h->a[i] + delta);
}

bool heap_delete_at(Heap *h, size_t i, int *out) {
    if (i == 0 || i > h->size || !out) return false;
    *out = h->a[i];
    int last = h->a[h->size--];
    if (i <= h->size) (void)heap_set_key(h, i, last);
    return true;
}

bool heap_delete_min(Heap *h, int *out) {
    return heap_delete_at(h, 1, out);
}
Python 3
INT_MIN, INT_MAX = -(1 << 31), (1 << 31) - 1
HEAP_CAPACITY = 64

class Heap:
    def __init__(self, values=(), capacity=HEAP_CAPACITY):
        values = list(values)
        if capacity < 0 or len(values) > capacity:
            raise ValueError('capacity exceeded')
        self.capacity = capacity
        self.a = [None] * (capacity + 1)
        self.a[1:len(values) + 1] = values
        self._size = len(values)
        for i in range(self.size // 2, 0, -1):
            self.down(i, self.a[i])

    @property
    def size(self):
        return self._size

    def up(self, i, x):
        while i > 1 and x < self.a[i // 2]:
            self.a[i] = self.a[i // 2]
            i //= 2
        self.a[i] = x

    def down(self, i, x):
        while 2 * i <= self.size:
            child = 2 * i
            if child < self.size and self.a[child + 1] < self.a[child]:
                child += 1
            if x <= self.a[child]:
                break
            self.a[i] = self.a[child]
            i = child
        self.a[i] = x

    def push(self, x):
        if self.size == self.capacity:
            raise OverflowError('full heap')
        self._size += 1
        self.up(self.size, x)

    def minimum(self):
        if not self.size:
            raise IndexError('empty heap')
        return self.a[1]

    def set_key(self, i, x):
        if not 1 <= i <= self.size:
            raise IndexError('invalid position')
        if i > 1 and x < self.a[i // 2]:
            self.up(i, x)
        else:
            self.down(i, x)

    def decrease(self, i, delta):
        if not 1 <= i <= self.size:
            raise IndexError('invalid position')
        if delta < 0 or self.a[i] - delta < INT_MIN:
            raise ValueError('invalid decrease')
        self.set_key(i, self.a[i] - delta)

    def increase(self, i, delta):
        if not 1 <= i <= self.size:
            raise IndexError('invalid position')
        if delta < 0 or self.a[i] + delta > INT_MAX:
            raise ValueError('invalid increase')
        self.set_key(i, self.a[i] + delta)

    def delete_at(self, i):
        if not 1 <= i <= self.size:
            raise IndexError('invalid position')
        result, last = self.a[i], self.a[self.size]
        self.a[self.size] = None
        self._size -= 1
        if i <= self.size:
            self.set_key(i, last)
        return result

    def pop(self):
        return self.delete_at(1)

heap_up、heap_down 用 i <= size/2 再计算孩子，避免在边界判断之前把下标乘 2。size_t 倒序循环必须用 i > 0，若写成 i >= 0 就会在减到 0 后绕回极大值。教学数组的槽位 0 没有语义，空堆也不读取槽位 1。

两版共享 1 起始存储、相等时优先左孩子与固定容量约定。C 失败返回 false；Python 对空堆、非法位置、满容量分别抛出 IndexError、IndexError、OverflowError，增减键的无效差值抛出 ValueError。Python 预先建立容量槽位，实际元素是 h.a[1:h.size+1]，因此后续操作不触发底层扩容；建立空容器的分配成本为容量的线性量级。

四、§5.3.4：已知位置的更新，与一次性建堆

4.1　优先级变化时，先确定失序方向

已知位置 P 时，减小键只可能违反它与父亲的关系，因而上滤；增大键只可能违反它与孩子的关系，因而下滤。任意删除可以拿末尾元素替代 P：若它小于父键就上滤，否则下滤。原书借助“减到负无穷后 DeleteMin”解释删除，本笔记直接替换，避免把数学负无穷误写成有限整数常量，也处理最小键本来就等于 INT_MIN 的情况。

这些操作的 O(log(N+1)) 前提是已经知道位置。如果先在堆中按值找任务，总操作仍可能是 O(N)。更进一步，下标也会随着上滤、下滤失效：系统若用 ID 映射到位置，就必须在每次搬动元素时更新映射。重复优先级需按 ID 定位。这里的 heap_set_key 检查方向，两个按差值更新的函数还检查了整数加减溢出。

4.2　图 5.14–5.18：自底向上的顺序是一个证明条件

把全部 N 个键按任意顺序放进数组，形状已经正确。叶子天然满足堆序，所以从 ⌊N2⌋ 向 1 倒序下滤。处理节点 i 时，两个孩子下标都大于 i，其子树早已处理好；下滤的前提因而成立。反过来从根开始，孩子尚未成为堆，做一次下滤并不能保证整棵树正确。

4.3　为什么不是把每个节点都乘上树高

根可能下滤很多层，但多数节点接近底部。完全树中高度至少 j 的节点数恰为 ⌊N2j⌋，因为节点 i 有深度 j 的后代当且仅当 2ji≤N。把每个节点的高度分层计数，得到：

∑vheight(v)=∑j≥1⌊N2j⌋=N−b(N)<N

定理 5.1 与完全树的高度和

b(N) 是 N 的二进制中 1 的个数。每层最多两次键比较，于是普通 Floyd 建堆比较数不超过 2(N−b(N))≤2N−2（N≥1）。原书定理 5.1 先证明满二叉树的高度和：

S=∑i=0h2i(h−i)=(2h+1−1)−(h+1)

这也足以给出完全树的线性上界；本笔记补充的分层计数把一般 N 的精确高度和写出来。需要注意，这是节点高度的和，不是节点深度的和；后者通常为 Θ(NlogN)。一次性建堆最坏 Θ(N)，逐个插入最坏 Θ(NlogN)，它们最后可以得到不同的合法堆，不能靠数组完全相等判定算法正确。

五、§5.4：堆只保存应用真正需要的候选状态

5.1　选择问题：为什么保留最大的 k 个，却使用最小堆

算法 5A 先对全部输入建最小堆，再删除 k 次，最后取出的元素是第 k 小，成本 O(N+klog(N+1))。要找第 k 大，应该使用最大堆，或在最小堆中取第 N−k+1 小。顺序方向与题目目标必须对应。

算法 5B 回到第一章的问题：流式保留已读数据中最大的 k 个，重复值按出现次数计入。这个候选集合中最需要淘汰的是最小元，所以使用容量 k 的最小堆。先对前 k 项建堆；每读入一项，若不大于根就忽略，否则替换根并下滤。循环不变量是“堆中恰为已读输入最大的 k 个”；输入结束时，根就是第 k 大。

C（C11）
bool kth_largest(const int *input, size_t n, size_t k, int *out) {
    if (!input || !out || k == 0 || k > n || k > HEAP_CAPACITY)
        return false;
    Heap h;
    (void)heap_build(&h, input, k);
    for (size_t j = k; j < n; ++j)
        if (input[j] > h.a[1]) heap_down(&h, 1, input[j]);
    *out = h.a[1];
    return true;
}
Python 3
def kth_largest(values, k):
    values = list(values)
    if not 1 <= k <= len(values) or k > HEAP_CAPACITY:
        raise ValueError('invalid rank')
    h = Heap(values[:k])
    for x in values[k:]:
        if x > h.a[1]:
            h.down(1, x)
    return h.minimum()

例：保留最大的三个元素

例如输入 [7, 2, 9, 4, 9, 1]，k=3：读完前三项时候选为 2、7、9；读 4 淘汰 2；再读 9 淘汰 4；读 1 不变。最后候选为 7、9、9，根 7 是第 3 大。只把候选看成去重集合，会错把重复 9 丢掉。

若成功替换 R 次，更准确的时间为 O(N+Rlogk)，R≤N−k；一般上界写成 O(k+(N−k)(1+logk))，空间 O(k)。保留 1+logk 可覆盖 k=1：这时仍需读完整个输入。第六章会讨论期望线性的选择，第十章讨论最坏线性的选择，因此本章的对数因子不应被误称为选择问题的必然下界。

5.2　事件模拟：两个“队列”拥有不同的键

银行模拟里，等待柜员的顾客按到达先后服务，用普通 FIFO 队列；正在服务的顾客则按预计离开时间组织，用最小优先队列。输入的到达记录已按时间排序，下一个事件是“下一位到达”与“最早离开”二者较早的一项。优先队列存储的是未来事件，而不是等待顾客的全部信息。

逐 tick 推时钟会把运行时间绑在时间单位上：把输入从秒换成毫秒，空转次数就增加。事件驱动模拟直接跳到下一事件时刻，时间跨度很大而事件很少时尤其合适。每次到达若有空柜员就生成一个离开事件；否则入等待队列。每次离开释放柜员，若有人等待，立即开始其服务并产生新的离开事件。

六、§5.5：多一些孩子，就少一些层

图 5.19 把每个节点的孩子数改为 d，依旧保持完全形状和父键不大于子键。高度降为 O(1+logdN)，上滤每层只比较一个父亲；下滤却需要从至多 d 个孩子中找最小元。因此插入和已知位置的减键为 O(1+logdN)，DeleteMin 为 O(d(1+logdN))。最后一层孩子不足 d 时，只扫描实际存在的孩子。

分支数不是越大越好。上滤多、删除少的应用可能受益于较浅的树；删除很多时，扫描孩子的额外比较会抵消高度收益。习题 5.14 将这笔账写为操作次数的函数。原书还把多叉堆与第四章 B 树联系起来：数据在外存或分层存储中时，较少层数可能减少访问代价。它关于非二次幂除法成本、四叉堆实践表现的讨论带有机器与实现背景，本次没有据此宣称某个分支数在当前机器上最快。

原书这一节末尾提出新的困难：如果两批任务都已经成为二叉堆，怎样合并？等规模的数组堆可拼接后线性建堆，但这仍要处理全部元素。接下来的三种结构专门改变形状与表示，以降低合并成本；它们不是单纯再把 d 调大。

七、§5.6：左式堆只保证工作路径短

7.1　图 5.20 与定理 5.2：Npl 不是树高

左式堆继续保留堆序，但不要求完全形状。原书定义空路径长 Npl(X) 为从 X 到一个少于两个孩子的节点的最短距离，约定 Npl(NULL)=−1，因此叶子以及只有一个孩子的节点均为 0。一般递推为 1+min(Npl(L),Npl(R))。

左式约束是每个节点都满足 Npl(L)≥Npl(R)，于是当前节点的 Npl 可写成 1+Npl(R)。它并不表示左子树节点更多，也不表示左边更矮。很长的纯左链仍是合法左式堆；真正受到限制的是根到最右端的路径。

“all the work on the right path”

译：把全部工作安排在右路径上。

§5.6.1，印刷页 162。定理 5.2 给这条工作路径一个对数长度界。

定理 5.2 · 左式堆的右路径

右路径有 r 个非空节点时，至少有 2r−1 个节点。

证明：按右路径长度归纳

证明按 r 归纳：右子树右路径长 r−1；左式约束使左子树的空路径长至少相同，因此左右子树各至少 2r−1−1 个节点，加根得到 2r−1。故 r≤⌊log2(N+1)⌋。控制较短的一侧，已经足以加速合并，无须把整棵树变成 AVL。

7.2　图 5.21–5.28：递归只留下根处的一项修复

合并两个非空堆，先让较小根 a 成为新根，再递归合并 a 的右子堆与另一堆。返回后，新右子堆和原左子堆各自合法，根也小于两边所有元素；现在只需检查根处的左式约束，必要时交换左右孩子，然后重算 Npl。图 5.23 的根左 Npl 为 1、右 Npl 为 2，图 5.24 正是交换后恢复约束。

合并沿两棵树的右路径前进，时间与两条路径长度的和同阶，因而最坏 O(log(n1+1)+log(n2+1))。保持堆序却不维护 Npl，可能仍输出正确的最小元，却失去这项时间保证。Npl 是证明需要的状态，必须与真实结构一致。

图 5.28 的非递归思路先把两条右路径像有序链表那样合并，保留各节点的左子树，再从下向上交换与更新。它帮助理解递归回溯究竟做了什么，却仍需栈、反向链接或其他方法回到父节点；“改成非递归”并不自动意味着没有辅助存储。

7.3　图 5.25–5.30：合并会转移所有权

Insert 是把单节点堆与原堆合并；DeleteMin 是保存旧根的键与两棵子树，合并子树后释放旧根。它们都可能改变根，因此必须接回返回值。原书用宏统一接口，教学代码采用 LNode ** 让根更新直接可见。

typedef struct LNode {

LNode *left_new(int key) {

    if (!t) abort(); /* teaching policy: allocation failure terminates */
    *t = (LNode){key, 0, NULL, NULL};
    return t;
}

LNode *left_merge(LNode *a, LNode *b) {
    if (!a) return b;
    if (!b) return a;
    if (a->key > b->key) { LNode *t = a; a = b; b = t; }
    a->right = left_merge(a->right, b);
    if (npl(a->left) < npl(a->right)) {
        LNode *t = a->left; a->left = a->right; a->right = t;
    }
    a->npl = 1 + npl(a->right);
    return a;
}

    *b = NULL; /* ownership has moved into *a */
    return true;
}

八、§5.7：斜堆为什么能省掉 Npl

斜堆保留堆序，放弃左式结构约束。仍然比较根并递归合并较小根的右子堆，区别在于返回后无条件交换左右孩子，不读取或保存 Npl。遇到空输入直接返回另一棵树，不把返回树的整条尾路径也继续交换；这是自然递归实现的基例。

“the swap is unconditional”

译：交换是无条件的。

LNode *skew_merge(LNode *a, LNode *b) {
    if (!a) return b;
    if (!b) return a;

def skew_merge(a, b):
    path = []
    while a is not None and b is not None:
        if a.key > b.key:
            a, b = b, a
        path.append(a)
        a = a.right
    root = a if a is not None else b
    for node in reversed(path):
        node.right, node.left = node.left, root
        root = node
    return root

一次操作的右路径可能长达 Θ(N)，递归合并的栈也可能线性深。原书把对数保证放在整段操作序列上：从空结构开始的 M 次标准操作，以过程最大规模 N 计，总成本 O(Mlog(N+1))，每次摊还对数。任意非空起始结构还需计初始势能项。这个保证不依赖随机输入，也不等于单次最坏对数；第一遍阅读先理解调整规则，完整势能分析留给第十一章。

第四章的 AVL 与伸展树提供了同样的对照：显式维护一项局部指标，可以取得单次保证；不保存指标而持续调整，则可能用序列保证换取更简单的局部实现。不能因为图 5.33 恰好看起来左式，就把所有斜堆都当成左式堆。

C 用递归回溯，Python 用显式路径列表；处理顺序与树形相同，辅助栈最坏都可能占线性空间。左式堆的合并递归只走右路径，栈深有对数界。两种合并均消耗两棵互不共享节点的输入树，调用者随后只保留结果根。

九、§5.8：把合并变成二进制加法

9.1　图 5.34–5.35：一片森林恰好对应规模的二进制

二项队列不再是一棵树，而是一组满足堆序的二项树。B0 只有一个节点；把两棵同阶 Br−1 的根比较一次，将较大根接为较小根的孩子，得到 Br。因此 Br 高为 r，节点数为 2r，根的孩子恰为 Br−1,Br−2,…,B0。

每个阶最多一棵树，规模 13 的二进制为 1101，对应 B3、B2、B0，没有 B1。这唯一确定树的阶数组合，不唯一确定关键字在树中的排列。根数为 b(N)，至多 1+⌊log2N⌋，扫描根找最小元是最坏对数；若另存最小根指针并在所有更新后维护，FindMin 才可变成常数。

9.2　图 5.36–5.45：为什么三个同阶树不能全部合并

合并时从低阶到高阶，处理原队列 A、B 以及上一阶传来的 Carry。两棵 Bi 联接成一棵 Bi+1，当前位留下 0。三棵 Bi 共含 3·2i 个元素，应该保留一棵在当前阶，联接另外两棵作为进位；若只合并两棵后又把 Carry 与剩下那棵直接联接，就会拿不同阶树错误地操作。

高效 Insert 不应每次都扫描完整的阶数组。它只从 B0 开始向上进位，遇到第一个空阶停止。规模 2r−1 的一次插入会连续联接 r 次，仍然是最坏对数；但从空队列连续插入 N 次，总联接数恰为 N−b(N)，因为每次联接减少一棵树。故总时间线性，插入摊还常数；这条确定性结论比随口说“平均常数”更清楚。

9.3　图 5.46–5.56：删除根以后，孩子重新成为队列

扫描根找到最小元所在的 Br，把它从原森林摘除。移除根后，孩子恰为 Br−1 到 B0，共有 2r−1 个节点，本身可以构成第二个二项队列。原森林减去 2r 个节点，再合并这批孩子，最终规模减少 1。

第三章的“第一孩子／下一兄弟”表示在这里再次出现。图 5.54 联接时把新子树放在孩子链的最前面，因此孩子按阶数递减排列。删除时可以按阶装入根数组，但每个新根的 sibling 必须清空；否则释放一棵树可能顺着旧兄弟链释放另一棵树。普通的一般树表示还不足以说明这些链接的所有权。

/* BQ_RANKS is a teaching capacity, not the current number of roots. */
#define BQ_RANKS 16
#define BQ_CAPACITY (((size_t)1 << BQ_RANKS) - 1)

typedef struct BNode {
    int key;
    size_t rank;
    struct BNode *child, *sibling;
} BNode;

typedef struct {
    size_t size;
    BNode *root[BQ_RANKS];
} BQueue;

BNode *bin_new(int key) {
    BNode *t = malloc(sizeof *t);
    if (!t) abort();
    *t = (BNode){key, 0, NULL, NULL};
    return t;
}

/* Isolated roots of equal rank; returns an isolated root. */
BNode *bin_link(BNode *a, BNode *b) {
    if (a->key > b->key) { BNode *t = a; a = b; b = t; }
    b->sibling = a->child;
    a->child = b;
    ++a->rank;
    return a;
}

bool bin_merge(BQueue *a, BQueue *b) {
    if (!a || !b || a == b || b->size > BQ_CAPACITY - a->size)
        return false;
    size_t total = a->size + b->size;
    BNode *carry = NULL;
    for (size_t i = 0, weight = 1; weight <= total; ++i, weight *= 2) {
        BNode *x = a->root[i], *y = b->root[i];
        unsigned bits = (x != NULL) + 2u * (y != NULL)
                                      + 4u * (carry != NULL);
        switch (bits) {
        case 0: case 1: break;
        case 2: a->root[i] = y; b->root[i] = NULL; break;
        case 4: a->root[i] = carry; carry = NULL; break;
        case 3:
            carry = bin_link(x, y);
            a->root[i] = b->root[i] = NULL; break;
        case 5:
            carry = bin_link(x, carry); a->root[i] = NULL; break;
        case 6:
            carry = bin_link(y, carry); b->root[i] = NULL; break;
        case 7:
            a->root[i] = carry; carry = bin_link(x, y);
            b->root[i] = NULL; break;
        }
    }
    a->size = total;
    b->size = 0;
    return true;
}

bool bin_insert(BQueue *h, int key) {
    if (h->size == BQ_CAPACITY) return false;
    BNode *carry = bin_new(key);
    size_t i = 0;
    while (h->root[i]) {
        carry = bin_link(h->root[i], carry);
        h->root[i++] = NULL;
    }
    h->root[i] = carry;
    ++h->size;
    return true;
}

bool bin_delete_min(BQueue *h, int *out) {
    if (!h->size || !out) return false;
    size_t m = BQ_RANKS;
    for (size_t i = 0, weight = 1; weight <= h->size; ++i, weight *= 2)
        if (h->root[i] && (m == BQ_RANKS ||
                          h->root[i]->key < h->root[m]->key)) m = i;
    BNode *old = h->root[m], *p = old->child;
    *out = old->key;
    BQueue children = {0};
    children.size = ((size_t)1 << m) - 1;
    while (p) {
        BNode *next = p->sibling;
        p->sibling = NULL;
        children.root[p->rank] = p;
        p = next;
    }
    h->root[m] = NULL;
    h->size -= (size_t)1 << m;
    free(old);
    if (!bin_merge(h, &children)) abort(); /* capacity already proved */
    return true;
}

void bin_tree_clear(BNode *t) {
    if (!t) return;
    bin_tree_clear(t->child);
    bin_tree_clear(t->sibling);
    free(t);
}

void bin_clear(BQueue *h) {
    for (size_t i = 0; i < BQ_RANKS; ++i) bin_tree_clear(h->root[i]);
    *h = (BQueue){0};
}

        if total > BQ_CAPACITY:
            raise OverflowError('binomial queue capacity')
        carry, i = None, 0
        while 1 << i <= total:
            a, b = self.root[i], other.root[i]
            bits = bool(a) + 2 * bool(b) + 4 * bool(carry)
            if bits == 2:
                self.root[i], other.root[i] = b, None
            elif bits == 4:
                self.root[i], carry = carry, None
            elif bits == 3:
                carry = bin_link(a, b)
                self.root[i] = other.root[i] = None
            elif bits == 5:
                carry = bin_link(a, carry)
                self.root[i] = None
            elif bits == 6:
                carry = bin_link(b, carry)
                other.root[i] = None
            elif bits == 7:
                self.root[i], carry = carry, bin_link(a, b)
                other.root[i] = None
            i += 1
        self.size, other.size = total, 0

    def push(self, key):
        if self.size == BQ_CAPACITY:
            raise OverflowError('binomial queue capacity')
        carry, i = BNode(key), 0
        while self.root[i]:
            carry = bin_link(self.root[i], carry)
            self.root[i] = None
            i += 1
        self.root[i] = carry
        self.size += 1

    def pop(self):
        if not self.size:
            raise IndexError('empty binomial queue')
        m = min((i for i, t in enumerate(self.root) if t),
                key=lambda i: self.root[i].key)
        old = self.root[m]
        children = BQueue()
        children.size = (1 << m) - 1
        p = old.child
        while p:
            successor = p.sibling
            p.sibling = None
            children.root[p.rank] = p
            p = successor
        self.root[m] = None
        self.size -= 1 << m
        self.merge(children)
        old.child = None
        return old.key

教学代码从 BQueue h = {0} 开始，假定 size_t 至少 32 位，16 个阶的容量为 65535。容量与自合并检查都在修改前进行；合并成功后 B 的根槽清空，B 仍可作为空队列复用。DeleteMin 用“尚未选中根”的标记代替 Infinity，所以最小键恰为 INT_MAX 的队列也能正常删除；拆出的临时队列是局部对象，节点所有权最终都移回主队列。

5.1 · Insert 与 FindMin 能否同时常数时间？

原题（中文翻译）

原书习题 5.1 · 印刷页 180 · PDF 第 197 页。

5.7 · 建堆比较数：2N−2、八元素与 13N8

原题（中文翻译）

  1. 证明：对于二叉堆，BuildHeap 至多进行 2N−2 次元素间比较。
  2. 证明：只进行八次堆元素比较，就能构建一个含八个元素的堆。
  3. 给出一个建二叉堆的算法，只使用 138N+O(logN) 次元素比较。

原书习题 5.7 · 印刷页 180 · PDF 第 197 页。

解答

a 普通 Floyd 建堆的完整计数

每次下降至多两次键比较，节点 i 最多下降自身高度。正文的分层计数给出高度和 N−b(N)，所以 C(N)≤2N−2b(N)≤2N−2，适用于 N≥1。N=0 时没有比较，应单独写 0。只有左孩子时少一次兄弟比较，提前停止也会减少次数，所以这里是上界，不是每个输入都恰好比较这么多次。

b 八个元素只用八次比较的具体构造

先把八元素两两配对，较小者为 a,b,c,d，较大者分别记 A,B,C,D，用 4 次比较。再比较 a 与 b、c 与 d、两组胜者，用 3 次；为叙述方便把胜者连同各自配对关系重新命名，使 a≤b、c≤d、a≤c。此时 a 是总最小，c 支配 d,D,C，b≤B。

最后只比较 b 与 A，令较小者为 p、另一者为 q。p 同时不大于 q 与 B：若 p=b，由已有 b≤B；若 p=A，则 A≤b≤B。把层序排成 [a,c,p,d,C,q,B,D]，每条边都有已经知道的大小关系：特别是位置 4 的 d 不大于位置 8 的 D。合计 4+3+1=8 次，重复值同样成立。该八元素构造本次枚举了全部 40320 个互异键排列核对。

c 从二项树转换到完整二叉堆

本题涉及两个精度不同的规模结论。N=2r, r≥3 时，八元素基例可扩展成 Tr=13·2r/8−r−2；任意 N 时，Gonnet–Munro《Heaps on Heaps》定理 5 的严格余项是 O(logNlog*N)。本版题干写 O(logN)，比所引原定理更强。以下给出原构造的完整版本与计数；一般规模的结论采用原论文的余项。

先用 2r−1 次根比较建立 Br。当 r=0,1,2，已有关系能直接排成完全二叉堆；当 r=3，按 b 的方式再比较一次。对 r≥4，从根取下最大的 Br−1 孩子，递归转成 2r−1 个节点的完全堆。删去它的末尾叶子，得到一棵满堆与一个多余键。把多余键看成 B0，与原根剩余的 B0,…,Br−2 依次联接，只用 r−1 次比较便得到新的 Br−1，再递归转换。

保留原根，将第二次得到的 2r−1 节点完全堆放在左边，第一次留下的 2r−1−1 节点满堆放在右边。这使唯一多出的底层叶子位于全树最左侧，满足完全形状；原根本来就是整个二项树的最小元，故两条新父子边也有堆序。把初始二项树比较一并记入：

Tr=2Tr−1+r,T3=8,Tr=1382r−r−2

一般规模沿最后一个节点到根的路径划分：每个不在路径上的兄弟子树都是满树。若一个兄弟子树含 2r−1 个槽位，借它父亲的键作第 2r 个输入，使用上面的转换；末尾叶子的键归还父亲，其余键填回满子树。这样全数组的元素多重集不变，各旁支已成堆，只剩那条路径需要从下到上修复。修复使用 5.12(c) 的递归检查点，每个高度 h 花 h+O(log*h) 次比较。

设总高度为 H。旁支的阶 r 与其父亲高度最多相差 1，因此旁支构造里的负项 −∑r 抵消路径修复的主要项 ∑h，只剩 O(H) 的差额；至多 H+1 个路径位置的检查点余项合计 O(Hlog*H)。小阶基例只增加每支常数次，因而任意规模得到：

C(N)≤138N+O(logNlog*N)

gm_power_two 返回含槽位 0 的完整数组；gm_build 处理任意规模。C 依赖正文的 Heap 及 BNode、bin_new、bin_link、bin_tree_clear；Python 依赖相应二项树类型和联接函数。C 的 GMHeap.a 由调用者释放，转换时消耗并释放输入树。展示版通过递归数组搬移保持易读性，辅助空间线性、搬移总量上界 O(Nlog(N+1))；上述 13/8 系数专指键比较次数。

void gm_place(int *target, const int *source, size_t limit, size_t i, size_t j) {
    if (i > limit) return;
    target[j] = source[i];
    if (i <= limit / 2) gm_place(target, source, limit, 2 * i, 2 * j);

GMHeap gm_convert(BNode *t, size_t *comparisons) {
    size_t rank = t->rank, n = (size_t)1 << rank;
    GMHeap result = {n, malloc((n + 1) * sizeof(int))};
    if (!result.a) abort();
    int a = t->key;
    if (rank < 4) {
        result.a[1] = a;
        if (rank == 1) result.a[2] = t->child->key;
        if (rank == 2) {
            BNode *b = t->child;
            result.a[2] = b->key; result.a[3] = b->sibling->key;
            result.a[4] = b->child->key;
        }
        if (rank == 3) {
            BNode *c = t->child, *b = c->sibling, *A = b->sibling;
            BNode *d = c->child, *C = d->sibling, *B = b->child, *D = d->child;
            ++*comparisons;
            bool b_first = b->key <= A->key;
            int p = b_first ? b->key : A->key;
            int q = b_first ? A->key : b->key;
            int keys[] = {a, c->key, p, d->key, C->key, q, B->key, D->key};
            for (size_t i = 0; i < 8; ++i) result.a[i + 1] = keys[i];
        }
        bin_tree_clear(t); return result;
    }
    BNode *largest = t->child, *remaining = largest->sibling;
    largest->sibling = NULL; t->child = NULL; free(t);
    GMHeap old_half = gm_convert(largest, comparisons);
    int extra = old_half.a[old_half.size--];
    BNode *roots[sizeof(size_t) * CHAR_BIT] = {0};
    while (remaining) {
        BNode *next = remaining->sibling; remaining->sibling = NULL;
        roots[remaining->rank] = remaining; remaining = next;
    }
    BNode *carry = bin_new(extra);
    for (size_t i = 0; i < rank - 1; ++i) carry = gm_link(roots[i], carry, comparisons);
    GMHeap new_half = gm_convert(carry, comparisons);
    result.a[1] = a;
    gm_place(result.a, new_half.a, new_half.size, 1, 2);
    gm_place(result.a, old_half.a, old_half.size, 1, 3);
    free(old_half.a); free(new_half.a); return result;
}
GMHeap gm_power_two(const int *values, size_t n, size_t *comparisons) {
    if (!n || (n & (n - 1)) || !values || !comparisons ||
        n > (size_t)-1 / sizeof(BNode *) || n > (size_t)-1 / sizeof(int) - 1) abort();
    BNode **roots = malloc(n * sizeof *roots);
    if (!roots) abort();
    for (size_t i = 0; i < n; ++i) roots[i] = bin_new(values[i]);
    size_t count = n;
    while (count > 1) {
        for (size_t i = 0; i < count; i += 2)
            roots[i / 2] = gm_link(roots[i], roots[i + 1], comparisons);
        count /= 2;
    }
    BNode *tree = roots[0]; free(roots); return gm_convert(tree, comparisons);
}

5.8 · 第 k 小元的期望深度为何不超过 log2k？

原题（中文翻译）

证明：一个很大的完全堆中，第 k 小元素的期望深度不超过 logk。可假设 N=2k−1。

原书习题 5.8 · 印刷页 180 · PDF 第 197 页。

解答

先补全概率模型：互异键在一棵固定形状的满二叉树上，所有合法堆序标号等概率；不是对任意确定性堆取一个没有定义的“期望”。题目扫描中的指数与秩都写 k 容易混淆，这里令树规模 N=2h+1−1，目标秩仍为 k。当 k=1，目标在根，深度为 0。

根去掉后，两侧各有 s=N−12 个槽位。给定第 k 小元落在某侧，该侧另外 s−1 个键是其余 2s−1 个键的均匀子集，其中 k−2 个比目标小。因此目标在该子树的局部秩 J 满足：

𝔼J=1+(k−2)s−12s−1≤k2

按树高归纳，条件于局部秩 J，子树内期望深度至多 log2J。利用对数的凹性（Jensen 不等式），加上从全树根走入子树的一条边：

𝔼Dk≤1+𝔼(log2J)≤1+log2(𝔼J)≤log2k

这是给定均匀合法标号模型的完整归纳。确定性地只能先说目标的 d 个祖先都更小，故 d≤k−1；从这个事实直接跳到 d≤log2k 是错误的。例如某个堆的前三小键可以沿根、孩子、孙子形成深度 2 的路径。

5.9 · 阈值枚举、推广与约 3N4 次任意查找

原题（中文翻译）

  1. 给出算法，找出二叉堆中全部小于某个值 X 的节点。算法运行时间应为 O(K)，其中 K 为输出节点数。
  2. 这个算法能否推广到本章讨论的其他堆结构？
  3. 给出算法，在二叉堆中查找任意指定元素 X，比较次数最多约为 3N/4。

原书习题 5.9 · 印刷页 180–181 · PDF 第 197–198 页。

解答

a 用堆序剪掉整棵子树

从根开始；节点键不小于 X 就返回，因为后代更不可能小于 X；否则输出该节点并递归两个真实孩子。每个输出节点引发至多两个孩子检查，另有一次根检查，总时间 O(K+1)。题干的 O(K) 惯例省略了 K=0 仍需检查根的常数。

b 哪些结构仍有输出敏感界？

左式堆与斜堆也是堆序二叉树，同一剪枝得到 O(K+1)；固定 d 的多叉堆为 O(dK+1)，只有把 d 当常数才可化为同阶。二项队列必须先检查所有根，且被输出节点可有对数个孩子，直接算法是 O((K+1)log(N+1)) 的安全上界；不能把一棵二叉树的“每输出一项只引出两个检查”照搬到森林。

c 先在倒数第二层取得排除信息

先考虑满二叉树，最底层为深度 h，其父节点数 m=2h−1=N+14。先对这 m 个父节点与 X 作三路比较：相等就成功；父键大于 X，排除它及两个叶孩子；父键小于 X，排除它及所有祖先，保留两个叶孩子为候选。祖先标记碰到已标记节点即停止，全部标记工作线性。

设父键大于 X 的有 z 个，其余 m−z 个父节点最多还需检查 2(m−z) 个叶子。上部仍未被“小于”标记的内部节点，其所有倒数第二层后代都属于这 z 个节点；这样的满二叉分支内部节点至多 max(0,z−1)。因此未提前相等时，键比较总数不超过 m+2(m−z)+max(0,z−1)≤3m，即约 3N4。

非满的完全树，沿缺失区边界分成满子树，各子树使用同样方法，边界再加 O(logN) 次比较，符合“roughly”的要求。这里每次三路键比较能区分小于、等于、大于；若语言比较器只能一次回答一个布尔问题，需要明确换算，不能把比较模型悄悄更换。

5.10 · 小批量加入 M 项：不要扫描全部旧堆

原题（中文翻译）

提出一个算法，把 M 个节点插入一个原有 N 个元素的二叉堆，运行时间为 O(M+logNloglogN)。证明该时间界。

原书习题 5.10 · 印刷页 181 · PDF 第 198 页。

解答

数组已预留 N+M 个槽位时，可以在 O(M+log(N+2)loglog(N+4)) 时间完成这批加入。关键是利用旧堆中仍然有效的子树。下面给出一个可执行的影子区域构造；它沿用Kuszmaul，NAS−00−003，§6 的“新增节点及其祖先”思路，用线性选择和按旧键排序的顶部映射把具体步骤写全。

M=0 直接返回；旧堆为空或 M>N 时，对全部数组 Floyd 建堆就是 O(M)。其余情况新增位置 N+1,…,N+M 都是最终树的叶子，且最多跨两个深度。对这两个叶子区间逐层取父区间，合并相交范围，便收集到全部影子位置；没有影子的旧子树已经是合法堆。设总高度为 H，把离底部约 log2(M+1)+2 层以内的影子位置记为 S，上部记为 P。

每层最多两个区间，在距叶子 j 层处最多 M/2j+4 个位置，因此 |S|=O(M)、|P|=O(H+1)。把 P∪S 的键取入临时数组，用五元组中位数的确定性选择找出最小的 |P| 个键，只花线性时间；再把这些键排序，并把 P 的原节点按“旧键、原下标”排序。第 k 小的新键填回旧键第 k 小的那个原节点。

这个映射使每个顶部节点的键只会变小或保持：候选池包含全部旧顶部键，所以候选池第 k 小不大于旧顶部第 k 小。顶部的父亲原键不大于孩子，平局时父下标也更小，因此映射保留顶部堆序；未改动的旁支根原来不小于父键，现在仍然成立。剩下的候选键全不小于已放进顶部的键，任意写回 S 后，从大下标到小下标只修复底部影子节点。

底部修复每个距底 j 层的节点花 O(j+1)，合计 ∑j≤O(log(M+1))(M/2j+4)(j+1)=O(M)，因为几何级数收敛，且 log2(M+1)=O(M)。顶部两次排序则花 O(Hlog(H+1))。于是总时间达到题目界，辅助空间 O(M+log(N+1))；整个旧堆无需复制。

def shadow_indices(old, total):
    height = total.bit_length() - 1
    base = 1 << height
    leaves = [(max(old + 1, base), total, height),
              (old + 1, min(total, base - 1), height - 1)]
    cutoff = max(0, height - (total - old).bit_length() - 2)
    path, bottom = [], []
    for depth in range(height + 1):
        ranges = []
        for lo, hi, leaf_depth in leaves:
            if lo <= hi and depth <= leaf_depth:
                shift = leaf_depth - depth
                ranges.append((lo >> shift, hi >> shift))
        ranges.sort()
        merged = []
        for lo, hi in ranges:
            if merged and lo <= merged[-1][1] + 1:
                merged[-1] = (merged[-1][0], max(hi, merged[-1][1]))
            else:
                merged.append((lo, hi))
        target = path if depth < cutoff else bottom
        for lo, hi in merged:
            target.extend(range(lo, hi + 1))
    return path, bottom

    for j, key in enumerate(values, old + 1):
        h.a[j] = key
    h._size = old + m
    if not old or m > old:
        for i in range(h.size // 2, 0, -1):
            h.down(i, h.a[i])
        return
    path, bottom = shadow_indices(old, h.size)
    order = sorted((h.a[i], i) for i in path)
    pool = [(h.a[i], i) for i in path + bottom]
    select_prefix(pool, len(path))
    prefix = sorted(pool[:len(path)])
    for (_, index), (key, _) in zip(order, prefix):
        h.a[index] = key
    for index, (key, _) in zip(bottom, pool[len(path):]):
        h.a[index] = key
    for i in reversed(bottom):
        if 2 * i <= h.size:
            h.down(i, h.a[i])

    while (i > 1 && LESS(x, h->a[i / 2])) {
        h->a[i] = h->a[i / 2];
        i /= 2;

void heap_down(Heap *h, size_t i, int x) {
    while (i <= h->size / 2) {
        size_t child = 2 * i;
        if (child < h->size && LESS(h->a[child + 1], h->a[child]))
            ++child;
        if (LEQ(x, h->a[child])) break;
        h->a[i] = h->a[child];
        i = child;
    }
    h->a[i] = x;
}

class CountHeap(Heap):
    def __init__(self, capacity):
        self.comparisons = 0
        super().__init__((), capacity)

    def up(self, i, x):
        while i > 1:
            self.comparisons += 1
            if x >= self.a[i // 2]: break
            self.a[i] = self.a[i // 2]
            i //= 2
        self.a[i] = x

    def down(self, i, x):
        while 2 * i <= self.size:
            child = 2 * i
            if child < self.size:
                self.comparisons += 1
                if self.a[child + 1] < self.a[child]: child += 1
            self.comparisons += 1
            if x <= self.a[child]: break
            self.a[i] = self.a[child]
            i = child
        self.a[i] = x

        self.a[1:self.size + 1] = values

5.12 · 减少 DeleteMin 的键比较，未必减少搬移

原题（中文翻译）

每次 DeleteMin 在最坏情况下使用 2logN 次比较。

  1. 提出一种方法，使 DeleteMin 只需 logN+loglogN+O(1) 次元素间比较。这不一定意味着更少的数据移动。
  2. 扩展 a 问的方法，使比较次数减为 logN+logloglogN+O(1)。
  3. 这种思想能推进到什么程度？
  4. 比较次数的节省是否足以抵偿算法复杂程度的增加？

原书习题 5.12 · 印刷页 181 · PDF 第 198 页。

解答

a 先确定较小孩子路径，再二分落位

删根后，把空穴沿较小孩子一路下行，暂时不与末尾键 X 比较。路径上原有键单调不减；有 h 层时，选孩子至多比较 h 次，再在这条长度至多 h 的有序路径中二分寻找 X 的位置，用 ⌈log2(h+1)⌉ 次。按路径上移元素再写 X，总比较数为 log2N+log2log2N+O(1)，搬移仍可能线性于路径长。

b 在接近底部的位置设一次检查点

令 L=⌈log2(h+1)⌉，先选孩子下降 h−L 层，再比较该路径键与 X。若 X 不大于它，就在已经选出的前段二分落位，比较至多 h−L+1+⌈log2(h−L+1)⌉=h+O(1)。若 X 更大，答案在剩下至多 L 层中，继续选孩子到叶子，再在这个短尾段二分，比较至多 h+1+⌈log2(L+1)⌉。

两种情况合起来得到 log2N+log2log2log2N+O(1)。当树底部不满或路径提前抵达叶子，使用实际剩余长度；小高度直接交给基础下滤。路径记录可占 O(logN) 辅助空间，也可利用数组下标关系重建，需明确实现选择。

c 递归检查点给出的最坏比较界

把剩余高度记为 h，取 L=⌈log2(h+1)⌉，先沿较小孩子下降 r=max(1,h−L) 层。候选键不大于检查点时，在这段已知有序路径二分；候选键更大时，前段已经确定必须上移，只在剩余至多 L 层继续同一过程。小高度由至多常数次比较处理。

F(h)≤r+1+max{⌈log2(r+1)⌉,F(h−r)}

如果在本轮落位，二分的 logr 被先保留的 L 层预算覆盖，成本是 h+O(1)。若继续，每经过一轮只多收一次检查点比较，剩余高度由 h 降到 O(logh)；反复取对数直到常数只需 log*h+O(1) 轮。因此最坏键比较数为 log2N+log*N+O(1)，移动与总运行时间仍为 O(logN)。路径数组占 O(logN) 空间。

Gonnet–Munro 定理 2、推论 3 还给出相同量级的比较下界，说明在其比较模型内这个余项已达紧界。它针对普通二叉堆的提取与重组，不包含更换数据结构后的优先队列上界。

下面把四种策略放在同一个接口：模式 0 是普通下滤，1 是整条路径后二分，2 是一次检查点，3 是递归检查点。两版均依赖正文 Heap，同值优先左孩子。返回或输出本次取出的键、键比较次数及写入堆槽位的次数；索引与边界判断不计作键比较。

5.13 · d 叉堆在数组中的父子下标

原题（中文翻译）

若 d 叉堆存储在数组中，对于位置 i 的元素，它的父亲与孩子分别位于什么位置？

原书习题 5.13 · 印刷页 181 · PDF 第 198 页。

解答

若根从 1 开始，节点 i 的孩子依次为 d(i−1)+2,…,d(i−1)+d+1；根的孩子就是 2,…,d+1。对 i≥2，其父亲为 ⌊i−2d⌋+1。例如三叉堆的根孩子是 2、3、4，节点 2 的孩子是 5、6、7，节点 7 的父亲仍为 2。

若根从 0 开始，孩子为 di+1,…,di+d，非根父亲为 ⌊i−1d⌋。这些公式描述槽位，不保证孩子存在；必须把上界截到当前规模。要求 d≥2，计算乘加前检查下标能否表示，或先利用规模界排除没有孩子的节点。

5.14 · 上滤与删除的比例，怎样决定分支数？

原题（中文翻译）

假设一个初始有 N 个元素的 d 叉堆，需要执行 M 次 PercolateUp 和 N 次 DeleteMin。

  1. 用 M,N,d 表示全部操作的总运行时间。
  2. 若 d=2，全部堆操作的运行时间是多少？
  3. 若 d=Θ(N)，总运行时间是多少？
  4. 选择什么 d 能使总运行时间最小？

原书习题 5.14 · 印刷页 181 · PDF 第 198 页。

解答

a–c 操作序列的上界

这里 M 次 PercolateUp 指已知位置的上滤修复，不增加节点数；初始规模为 N，随后 N 次 DeleteMin 逐渐清空。以最大规模给出统一上界：

T=O((M+dN)(1+logdN))

d=2 时为 O((M+N)log(N+1))；d=Θ(N) 时树只有常数层，单次上滤常数而一次删除可能扫描线性个孩子，合计 O(M+N2)。若把上滤解释为新插入，规模会增长到 N+M，必须重新计算，不能继续沿用题目的固定规模界。

d 在比较模型下求最优 d

略去取整和低阶项，最小化 f(d)=(M+dN)lnNlnd，令 a=MN。求导后驻点满足：

d(lnd−1)=a

左边在 d≥2 的正值区间单调；a=0 时连续最优值为 e。a>0 时可以用 Lambert W 写成 d=aW(a/e)，实际取附近的整数，并限制在 2≤d≤max(2,N)；N≤1 直接按常数规模处理。也可用二分求这个单调方程，不必实现特殊函数。

只要数量级合适，较易记的选择是 d=max(2,⌈MN⌉)，超过 N 时截断。M≫N 时它让两类工作取得相近量级，但未必是导数给出的最优整数；当 M 很小，二叉、三叉或四叉之间的常数仍需实际比较。这里优化的是“扫描孩子与父键比较”的成本模型，不是当前 CPU 的实测冠军。

5.15 · min-max 堆：交替层如何支持两端删除？

原题（中文翻译）

min-max 堆支持 DeleteMin 和 DeleteMax，每个操作的时间为 O(logN)。结构与二叉堆相同，但堆序规则是：偶数深度节点 X 的键小于父亲而大于祖父；奇数深度节点 X 的键大于父亲而小于祖父，只在相应祖先存在时要求这些关系。见图 5.57。

  1. 怎样找到最小元素与最大元素？
  2. 给出向 min-max 堆插入新节点的算法。
  3. 给出 DeleteMin 和 DeleteMax 算法。
  4. 能否在线性时间内建立 min-max 堆？
  5. 若希望支持 DeleteMin、DeleteMax 和 Merge，提出一种数据结构，使所有操作都具有 O(logN) 时间界。

原书习题 5.15 · 印刷页 181–182 · PDF 第 198–199 页。

解答

a 最小值在根，最大值在根的孩子中

根深度为 0，属于最小层；偶数层节点不大于自己的后代，奇数层节点不小于自己的后代。这由相邻父子关系和同类层的祖孙关系反复推出。非空堆的最小值在位置 1；单节点的最大值也在 1，两个节点在 2，至少三个节点时取位置 2、3 中较大的。图 5.57 的最小值为 6，最大值为 87。

b 插入先跨父层，再沿祖父链

新节点仍追加到末尾。若落在最小层却比父亲大，交换后转为沿最大层上滤；否则沿最小层上滤。若落在最大层却比父亲小，做对称处理。沿同类层时每步跳到祖父，检查“更小”或“更大”是否成立。这既修复相邻层约束，又修复同类层的传递约束，路径长度为对数。

c 删除时为什么还要看孙子？

把末尾键放到被删位置。最小层从实际存在的孩子和孙子中选最小键；若它是孩子，一次交换即完成这一局部修复；若它是孙子，交换后，被推下去的键可能大于它的最大层父亲，必须再与该父亲交换，然后继续沿最小层下行。最大层完全对称。只比较两个孩子，可能遗漏同一最小层上的更小孙子。

d 自底向上仍然线性

从最后一个内部节点倒序调用对应层的下滤，先保证孩子子树已正确。每轮候选至多六个，每次跳一层或两层，代价仍不超过常数倍节点高度。完全树高度和小于 N，因此 BuildHeap 为 O(N)。以下给出独立 C11 与 Python 3 实现，类型和辅助函数完整包含。C 使用预留容量；Python 使用动态列表，追加按摊还计，要求单次最坏界时应预留容量。C 建堆按层切换最小／最大方向，避免给每个位置重新算深度而增加额外对数工作。

class MinMaxHeap:
    def __init__(self, values=()):
        self.a = [None] + list(values)
        for i in range((len(self.a) - 1) // 2, 0, -1):
            self._down(i, self._min_level(i))

    @staticmethod
    def _min_level(i):
        return (i.bit_length() - 1) % 2 == 0

    def _up(self, i, want_min):
        a = self.a
        while i >= 4:
            g = i // 4
            if (a[i] < a[g]) if want_min else (a[i] > a[g]):
                a[i], a[g] = a[g], a[i]
                i = g
            else:
                break

    def push(self, x):
        a = self.a
        a.append(x)
        i = len(a) - 1
        if i == 1:
            return
        p = i // 2
        want_min = self._min_level(i)
        crosses_parent = a[i] > a[p] if want_min else a[i] < a[p]
        if crosses_parent:
            a[i], a[p] = a[p], a[i]
            self._up(p, not want_min)
        else:
            self._up(i, want_min)

    def _down(self, i, want_min):
        a = self.a
        n = len(a) - 1
        while 2 * i <= n:
            candidates = [j for j in (2*i, 2*i+1, 4*i, 4*i+1, 4*i+2, 4*i+3)
                          if j <= n]
            m = (min if want_min else max)(candidates, key=lambda j: a[j])
            improves = a[m] < a[i] if want_min else a[m] > a[i]
            if not improves:
                break
            a[i], a[m] = a[m], a[i]
            if m < 4 * i:                 # A child: this local repair is enough.
                break
            p = m // 2                    # A grandchild: repair the opposite level.
            crosses_parent = a[m] > a[p] if want_min else a[m] < a[p]
            if crosses_parent:
                a[m], a[p] = a[p], a[m]
            i = m

    def minimum(self):
        if len(self.a) == 1:
            raise IndexError('empty min-max heap')
        return self.a[1]

    def maximum(self):
        n = len(self.a) - 1
        if n == 0:
            raise IndexError('empty min-max heap')
        return self.a[1] if n == 1 else max(self.a[2:min(n, 3)+1])

    def _pop_at(self, i, want_min):
        a = self.a
        result = a[i]
        last = a.pop()
        if i < len(a):
            a[i] = last
            self._down(i, want_min)
        return result

    def pop_min(self):
        self.minimum()                    # Check emptiness before indexing.
        return self._pop_at(1, True)

    def pop_max(self):
        n = len(self.a) - 1
        self.maximum()
        i = 1 if n == 1 else (2 if n == 2 or self.a[2] >= self.a[3] else 3)
        return self._pop_at(i, False)

e 加上 Merge：两棵可定位的左式堆

为每个逻辑记录创建两个包装节点：一份按最小键建左式堆，另一份按最大键建左式堆。记录保存两节点的句柄，每节点增加父指针；相同键用记录 ID 打破平局。DeleteMin 从最小堆根取得记录，在两棵堆中分别删除它的已知包装节点；DeleteMax 对称。两个队列合并时，各合并一次同方向左式堆，交接记录的所有权。

已知节点的删除先合并它的左右子堆，把结果接回原父位置，再沿父链修复左右方向与 Npl，Npl 未变便停止。修复链的方向由 r=min(rL,rR)+1 决定：秩降低时，继续变化的父节点新秩等于改变孩子的新秩加 1；秩升高时，继续变化的父节点旧秩等于改变孩子的旧秩加 1。一个孩子的秩变化经 min 传播后保持同一方向，不会忽高忽低。因此分别按新秩或旧秩计费，实际传播链均至多对数，再加末端一次不变检查。子堆合并同阶，于是一次已知节点删除最坏 O(log(N+1))；两端删除及 Merge 都保持此界。

def p_repair(p):
    while p:
        old = p.npl
        p_refresh(p)
        if p.npl == old:
            break
        p = p.parent

def p_unlink(root, x, maximum=False):
    parent = x.parent
    replacement = p_merge(x.left, x.right, maximum)
    if parent is None:
        root = replacement
    else:
        if parent.left is x:
            parent.left = replacement
        else:
            parent.right = replacement
        if replacement:
            replacement.parent = parent
        p_repair(parent)
    x.left = x.right = x.parent = None
    x.npl = 0
    return root

def p_decrease(root, x, key):
    if key > x.key:
        raise ValueError('new key must not increase')
    x.key = key
    parent = x.parent
    if parent is None or not p_before(x, parent, False):
        return root
    if parent.left is x:
        parent.left = None
    else:
        parent.right = None
    x.parent = None
    p_repair(parent)
    return p_merge(root, x)

class DualQueue:
    def __init__(self):
        self.minimum = self.maximum = None
        self.size = 0

    def push(self, key):
        identity = next(_dual_ids)
        a, b = PNode(key, identity), PNode(key, identity)
        a.mate, b.mate = b, a
        self.minimum = p_merge(self.minimum, a)
        self.maximum = p_merge(self.maximum, b, True)
        self.size += 1

    def find(self, maximum=False):
        if not self.size:
            raise IndexError('empty dual queue')
        return (self.maximum if maximum else self.minimum).key

    def pop(self, maximum=False):
        self.find(maximum)
        a = self.maximum.mate if maximum else self.minimum
        b, key = a.mate, a.key
        self.minimum = p_unlink(self.minimum, a)
        self.maximum = p_unlink(self.maximum, b, True)
        a.mate = b.mate = None
        self.size -= 1
        return key

    def merge(self, other):
        if self is other:
            raise ValueError('self merge')
        self.minimum = p_merge(self.minimum, other.minimum)
        self.maximum = p_merge(self.maximum, other.maximum, True)
        self.size += other.size
        other.minimum = other.maximum = None
        other.size = 0

5.18 · 递增插入至 2k−1 时，左式堆是否完美平衡？

原题（中文翻译）

证明或否定：向一个初始为空的左式堆按顺序插入键 1 至 2k−1，会形成一棵完美平衡树。

原书习题 5.18 · 印刷页 182 · PDF 第 199 页。

解答

成立，这里使用“右子树递归合并、仅左秩较小时交换”的标准规则。证明关注插入动态，而不是从总节点数反推形状。记递增插入 n 项所得的形状为 T(n)，空树为 T(0)；键的间隔不改变比较方向，因此任意严格递增子序列得到相同的形状演化。

可用强归纳同时保持以下相位不变量：n≥2 时，在某个 r≥1 下，根左子树是含 2r−1 个节点的满树，右子树是 T(n−2r)，并且：

3·2r−1−1≤n≤3·2r−2,Npl(T(n))=⌊log2(n+1)⌋−1

基例 T(1) 是叶子，n=2 时左叶子、右空，与 r=1 相符。进入一个相位后，只向右子树插入。由归纳，右秩不超过左秩 r−1，一直不交换；当右子树刚增长到 2r+1−1 项时，它已是秩 r 的满树，超过旧左树，交换后新左树成为这棵大满树，新右树是原来的 2r−1 项满树。这恰在新总数 3·2r−1 发生，进入 r+1 相位。

相位内，右子树规模从 2r−1−1 增至 2r+1−2，其秩由 r−2 变到 r−1，根秩因而按 n+1 是否达到 2r+1 分成 r−1 或 r，与取整公式一致；相位切换又保存了满左树与递增插入的右树形状。这给出了基例、相位内增长和切换三部分的强归纳。

现在代入 n=2k−1（k≥2），所在相位为 r=k−1，左右规模都为 2k−1−1。左边由不变量是满树，右边由较小规模归纳也是满树，所以全树高度 k−1，完美平衡。k=1 是单叶基例。中间规模不必满；本次还计算核对了 k=1,…,11，计算是验证示例，归纳才是一般结论的依据。

5.20 · 左式堆如何支持已知位置的 DecreaseKey？

原题（中文翻译）

  1. 左式堆能否高效支持 DecreaseKey？
  2. 若可行，需要作哪些修改？

原书习题 5.20 · 印刷页 182 · PDF 第 199 页。

解答

可以支持最坏 O(log(N+1)) 的 DecreaseKey，但需要父指针或等价的父位置句柄。实现见 p_decrease（C） 和 同名 Python 函数，共享 5.15(e) 给出的完整 PNode、p_merge、p_refresh 与 p_repair。

减小节点 x 的键，和后代的堆序仍然成立。若父键已经不大于它，只更新键。否则切下整棵 x 子堆，将它的父指针置空；旧父节点清除对应孩子，沿父链修复左右方向和 Npl，Npl 没变化就停止。最后把切下子堆与旧根合并。

切除子树只会降低沿途 Npl。对任一继续发生秩下降的父节点，修复后的秩恰等于被改变孩子的新秩加 1：若另一孩子的新秩更小，父节点原来就已由另一侧决定，秩不会再下降。因此，真正连续传播的修复链按新秩严格递增；相邻节点的旧秩则可能相等。节点的秩由其子树规模约束，至多为 O(log(N+1))，所以实际改变的节点数有对数界，外加末端至多一次秩不变检查。再计最后一次同阶 Merge，得到所要求的最坏时间。节点在很深左链上的位置不会要求扫描整条左链，因为有效句柄已经给出位置。

两版分别对 128 个有效句柄做 10,000 次随机减键，逐次核对键集合、父关系、Npl 和堆序。增加键、无效句柄与按值查找属于其他接口前提；本题函数对增加键返回失败或抛出异常，对有效节点保持身份。

5.21 · 懒删除：清理 k 个标记的代价如何计？

原题（中文翻译）

从已知位置删除左式堆节点，可以采用懒惰策略：只将节点标记为已删除。执行 FindMin 或 DeleteMin 时，如果根已标记，就必须实际删除它并找出真正的最小元素，这又可能需要删除其他已标记节点。这个策略中，Delete 的代价为一个单位，而 FindMin、DeleteMin 的代价取决于标记节点的数量。

假设一次 DeleteMin 或 FindMin 后，已标记节点比操作前少了 k 个。

  1. 说明如何在 O(klogN) 时间内执行 DeleteMin。
  2. 提出一种实现并分析，证明 DeleteMin 的时间为 O(klog(2N/k))。

原书习题 5.21 · 印刷页 182–183 · PDF 第 199–200 页。

解答

已知节点的 Delete 只置 deleted=true，为常数；键和结构暂不改变。标记节点可能藏在活节点下面，FindMin 不必清理全部标记，只需要去掉根处挡住真实最小元的那一片。

a 逐个清理根

根有标记时，合并左右子堆，释放这个已删除节点并继续；第一次遇到活根，FindMin 返回它，DeleteMin 还要真正删除它。若此次共清理 k 个标记，FindMin 为 O(klog(N+1)+1)，DeleteMin 为 O((k+1)log(N+1))。题干的 O(klogN) 省略了 k=0 时删除活根的基本成本，应明确补上。

b 把清理产生的森林统一合并

从原根递归展开标记节点：释放标记节点，继续检查其孩子；遇到活节点便停止向下，把整个子堆加入边界森林。FindMin 对森林合并后观察根。DeleteMin 则先确定森林中最小的活根，拆掉它，将它的至多两个孩子加入森林，再统一合并；扫描森林根只需线性于边界大小。若最小活根拆开后露出标记孩子，继续展开，直到这些边界也都为活根。将这次真正清理的标记总数记为 k，边界子堆数 q≤k+2。

用分轮的两两合并，而不是让最大的累计堆依次吞掉所有小堆。各边界子堆节点互不相交，总规模不超过 N。某轮剩 m 棵时，左右堆合并的代价至多其规模和的对数；由对数凹性，该轮合计：

O(mlog(1+Nm))

每轮棵数至少减半。把 m=q,q2,q4,… 相加，利用 ∑j≥02−j=2 与 ∑j≥0j2−j=2，总成本为 O(qlog(1+Nq))；再加展开和扫描，得到：

O((k+1)log(1+Nk+1))

对非空有效操作、1≤k≤N，它等价于题目的 O(klog2Nk)；k=0 的单次 DeleteMin 仍要对数，FindMin 只观察根。若所有节点都有标记，返回空结构而不读取不存在的活根。标记但尚未触达的内部节点继续保留；N 在这里是操作前物理节点数，不能用活节点数代替。

5.22 · 用 FIFO 合并单节点堆，为什么最坏线性？

原题（中文翻译）

左式堆可以用以下方式在线性时间内建堆：先把每个元素视为一个单节点左式堆，全部放入队列；只要队列中不止一个堆，就取出前两个，合并后放回队尾。

  1. 证明这个算法的最坏运行时间为 O(N)。
  2. 为什么它可能比正文介绍的算法更好？

原书习题 5.22 · 印刷页 183 · PDF 第 200 页。

解答

a 先把 N 个单节点堆放入普通队列，反复取出前两棵、合并并放回队尾。除最后跨规模合并的少量边界项，大小为 2j 量级的堆有 O(N2j) 次参与，相应一次合并的最坏代价 O(j+1)。因此：

∑j≥0O(N2j(j+1))=O(N)

更具体地，FIFO 内的规模始终非递减，最大规模不超过最小规模的两倍：初始全是 1；取最小两项 s≤t 后，旧尾部不超过 2s≤s+t，故新结果仍可放在最后，而 s+t≤2t 保持两倍比率。因此每次合并的两子堆规模相差至多两倍；沿任一节点的合并祖先，规模至少按 32 倍增长，同一二次幂区间至多经历常数次合并。每个区间的参与块总体规模为 O(N)，合并数便为 O(N2j)，上面的级数适用于任意 N。队列建立与 N−1 次入出队都是线性，空输入返回空堆。

b 只需已经验证过的 Merge，不必另外从数组搭建完全树、填写 Npl；适合已经得到许多独立小堆的情形。它可能生成与正文底向上构造不同的合法树形。相较从空堆逐项 Insert 的 O(NlogN) 最坏界，配对合并让大量操作发生在很小的堆上。

对应双语程序如下，依赖正文的 LNode、单节点建立与两种 Merge；skew=false 构造左式堆，skew=true 构造斜堆。C 使用容量为输入项数的环形指针队列并在结束后释放队列，节点交由结果树持有；Python 使用 collections.deque。

C（C11）
LNode *fifo_build(const int *values, size_t n, bool skew) {
    if (n && !values) return NULL;
    if (!n) return NULL;
    if (n > (size_t)-1 / sizeof(LNode *)) abort();
    LNode **q = malloc(n * sizeof *q);
    if (!q) abort();
    for (size_t i = 0; i < n; ++i) q[i] = left_new(values[i]);
    size_t head = 0, count = n;
    while (count > 1) {
        LNode *a = q[head]; head = (head + 1) % n; --count;
        LNode *b = q[head]; head = (head + 1) % n; --count;
        q[(head + count) % n] = skew ? skew_merge(a, b) : left_merge(a, b);
        ++count;
    }
    LNode *result = q[head]; free(q); return result;
}

from collections import deque

def fifo_build(values, skew=False):
    q = deque(LNode(x) for x in values)
    merge = skew_merge if skew else left_merge
    while len(q) > 1:
        q.append(merge(q.popleft(), q.popleft()))
    return q[0] if q else None

5.26 · FIFO 配对合并，能否在线性时间建斜堆？

原题（中文翻译）

含 N 个元素的斜堆可以用标准二叉堆算法构建。能否采用习题 5.22 的同样合并策略，在 O(N) 时间内建立斜堆？

原书习题 5.26 · 印刷页 183 · PDF 第 200 页。

解答

FIFO 配对合并从单节点开始，可以在最坏总时间 O(N) 建立斜堆。程序与 5.22 共享 C、Python 的 fifo_build，只需把 skew 设为真。这里给出该结论需要的规模敏感摊还证明。

把一个节点的右孩子称为重孩子，当且仅当右子树比左子树更大；其余右边为轻边，包括空右边。势能 Φ 取所有堆中重右边的个数。Merge 实际访问两棵输入的原右路径，记访问了 H 个带重右边的节点和 L 个带轻右边的节点。

每个访问节点回溯时交换两侧：新的左子树是旧右子树与另一堆的合并，新的右子树是旧左子树。旧右边若重，交换后的右边必轻，势能减少 1；旧右边若轻，新的右边最多增加一份势能。未访问节点的左右子树都没变化。因此 ΔΦ≤−H+L，按每个访问节点的常数工作计费，摊还访问数至多 H+L+ΔΦ≤2L，另加终止的常数工作。

沿一棵输入堆的右路径，每走过一条非空轻边，子树规模至少减半，所以两棵堆合计 L≤log2(s+1)+log2(t+1)+O(1)。合并规模 s,t 的摊还成本因而为 O(1+log(s+t+1))；若单位实际成本为其他常数，将势能乘相应常数即可。

FIFO 的队列规模相差至多两倍，5.22 已证明大小为 2j 量级的合并只有 O(N/2j) 次。按刚得出的规模界相加：

∑j≥0O(N2j(j+1))=O(N)

5.27 · 二项树根的孩子为什么各阶恰好一个？

原题（中文翻译）

原书习题 5.27 · 印刷页 183 · PDF 第 200 页。

解答

对阶数 k 归纳。B0 没有孩子，与空的阶数组合相符。若 Bk−1 的根孩子恰为 B0,…,Bk−2，构造 Bk 时把另一棵完整 Bk−1 接成它的新孩子；旧孩子保留，于是阶数恰为 0,1,…,k−1，各一个，归纳完成。

这说的是子树的阶，不要求它们的根键递增。正文的头插孩子链让物理顺序为 k−1,k−2,…,0，因此删除根时可以按节点记录的 rank 分派到相应槽位。

5.28 · 深度 d 的节点数就是二项式系数

原题（中文翻译）

原书习题 5.28 · 印刷页 183 · PDF 第 200 页。

解答

记 c(k,d) 为 Bk 在深度 d 的节点数。构造时，一半节点保留在第一棵 Bk−1 的原深度，另一半因接到根下，深度增加 1，故：

c(k,d)=c(k−1,d)+c(k−1,d−1)

基例 c(0,0)=1，越界深度为 0。这与 Pascal 递推及其边界完全相同，所以 c(k,d)=(kd)，0≤d≤k。把各层相加，∑d=0k(kd)=2k，与二项树规模交叉核对。

5.30 · 连续插入、少于 N 次比较与批量加入

原题（中文翻译）

  1. 证明：向一个初始为空的二项队列执行 N 次 Insert，最坏总时间为 O(N)。
  2. 给出一个建立含 N 个元素的二项队列的算法，元素比较次数至多为 N−1。
  3. 提出一个算法，将 M 个节点插入已有 N 个元素的二项队列，最坏时间为 O(M+logN)。证明此界。

原书习题 5.30 · 印刷页 183 · PDF 第 200 页。

解答

a、b 总联接数，而不是每次乘 logN

每次 Insert 创造一棵单节点树，每次联接减少一棵树，最后规范森林有 b(N) 棵。因此从空队列插入 N 项，联接恰为 N−b(N) 次，每次一次根键比较。每次还有一个遇到空槽即停的常数检查，总时间 O(N)，键比较不超过 N−1（N≥1）。

b 的具体算法就是正文的 bin_insert：沿连续非空低阶向上进位，遇空阶存入并停止。N=0 没有比较。若每次调用一个扫描全部阶槽的 Merge，即使联接数不变，也可能多出对数个空槽检查，不能据联接数直接证明整个程序线性。

c 新批次先建自己的队列

把 M 项按直接插入构建成独立二项队列，用 O(M)；再与旧 N 项队列合并，用 O(log(N+M+1))。若 M≤N，对数项为 O(log(N+1))；若 M>N，log(N+M+1)=O(M)。所以统一为 O(M+log(N+1))，与题目大规模写法一致。

新增节点的分配计入 M，数组容量或阶槽须能表示新总规模。合并后新批次的控制对象仍由调用者释放或复用为空队列，节点所有权已交给结果。M=0 可以直接返回，不必扫描旧队列。

5.32 · 自合并、提前停止与小队列并入大队列

原题（中文翻译）

对于二项队列：

  1. 调用 Merge(H,H) 会发生什么？修改代码以修正该问题。
  2. 修改 Merge：当 H2 已没有树且 Carry 为空时，提前停止合并。
  3. 修改 Merge：总是将较小的树合并进较大的树。

原书习题 5.32 · 印刷页 184 · PDF 第 201 页。

解答

a 必须在修改前识别自合并

Merge(H,H) 会让同一节点被当作两棵独立树，联接时可能造成自指针，规模也被重复计算；随后销毁可能重复释放。正文 bin_merge 在修改前检查 a == b 并返回失败。也可以把它定义为无操作，但必须明确接口语义。两个不同控制对象若共享子树仍然不合法，单个指针比较无法检测所有别名。

b Carry 为空且来源已空时结束

维护来源队列剩余节点数 remaining；从它移出一棵 Bi 就减去 2i。完成当前阶后，若 remaining == 0 && carry == NULL，后面的目标高阶槽不再受影响，立即结束。仅看当前来源槽是否为空不够，它可能在更高阶还有树。

bool bin_merge_fast(BQueue *a, BQueue *b) {
    if (!a || !b || a == b || b->size > BQ_CAPACITY - a->size) return false;
    size_t total = a->size + b->size, remaining = b->size;
    BNode *carry = NULL;
    for (size_t i = 0; remaining || carry; ++i) {
        BNode *x = a->root[i], *y = b->root[i];
        if (y) remaining -= (size_t)1 << i;
        unsigned bits = (x != NULL) + 2u * (y != NULL) + 4u * (carry != NULL);
        switch (bits) {
        case 0: case 1: break;
        case 2: a->root[i] = y; b->root[i] = NULL; break;
        case 4: a->root[i] = carry; carry = NULL; break;
        case 3: carry = bin_link(x, y); a->root[i] = b->root[i] = NULL; break;
        case 5: carry = bin_link(x, carry); a->root[i] = NULL; break;
        case 6: carry = bin_link(y, carry); b->root[i] = NULL; break;
        case 7: a->root[i] = carry; carry = bin_link(x, y); b->root[i] = NULL; break;
        }
    }
    a->size = total; b->size = 0; return true;
}

bool bin_merge_small_into_large(BQueue *a, BQueue *b) {
    if (!a || !b || a == b || b->size > BQ_CAPACITY - a->size) return false;
    if (a->size < b->size) {
        BQueue old_a = *a;
        *a = *b;
        *b = old_a;
    }
    return bin_merge_fast(a, b);
}

def bin_merge_fast(a, b):
    if a is b:
        raise ValueError('self merge')
    total = a.size + b.size
    if total > BQ_CAPACITY:
        raise OverflowError('binomial capacity')
    remaining, carry, i = b.size, None, 0
    while remaining or carry:
        x, y = a.root[i], b.root[i]
        if y:
            remaining -= 1 << i
        bits = bool(x) + 2 * bool(y) + 4 * bool(carry)
        if bits == 2:
            a.root[i], b.root[i] = y, None
        elif bits == 4:
            a.root[i], carry = carry, None
        elif bits == 3:
            carry = bin_link(x, y)
            a.root[i] = b.root[i] = None
        elif bits == 5:
            carry = bin_link(x, carry)
            a.root[i] = None
        elif bits == 6:
            carry = bin_link(y, carry)
            b.root[i] = None
        elif bits == 7:
            a.root[i], carry = carry, bin_link(x, y)
            b.root[i] = None
        i += 1
    a.size, b.size = total, 0

        raise ValueError('self merge')
    if a.size + b.size > BQ_CAPACITY:
        raise OverflowError('binomial capacity')
    if a.size < b.size:

        a.root, b.root = b.root, a.root

按元素数量把较小队列作为来源，较大队列作为接收方，配合 b 的提前停止，通常可以减少无关高阶工作。若公共接口固定返回结果到第一个参数，可以在修改前交换两个队列头部及其根槽所有权，仍用第一个对象接收，最终清空第二个；也可以在内部使用局部指针选方向，最后把结果头移回公开接收对象。

交换两个变量名本身不会更新调用者的两个控制对象，必须实际转移头部。根数组大小为 O(log(N+1)) 时，交换整个数组仍需同阶；若想保留小批量优势，使用可交换的根表指针或可转交的头部表示。教材这里的“smaller tree”按两个队列规模理解，不应把不同阶二项树直接联接。

上面同一对代码给出 b 的提前停止函数 bin_merge_fast，以及 c 的完整包装函数 bin_merge_small_into_large；两版依赖正文二项队列核心。包装函数先检查自合并与总容量，再按规模交换头部的实际所有权，使较小队列成为来源。合并结果始终位于第一个控制对象，第二个清空且可以重新插入；不复制或共享任何树节点。C 的结构体交换复制固定的 16 个根槽，Python 交换两份根表的引用；若将 C 根表改成随规模增长的内嵌数组，头部转移成本须另计为 O(log(N+1))。

5.33 · 每阶允许两棵树，能把插入变成最坏常数吗？

原题（中文翻译）

把二项队列扩展为每个结构中允许至多两棵相同高度的树。能否使插入的最坏时间为 O(1)，同时保留其他操作的 O(logN) 时间界？

原书习题 5.33 · 印刷页 184 · PDF 第 201 页。

解答

可以。每阶保留 di∈{0,1,2} 棵 Bi，并维持“任意两个 2 之间至少有一个 0”。还要用一条按阶排序的双向链表记录所有 di≠1 的阶槽，头指针直接指出最低的非 1 位；阶槽自身有 higher，只在需要新最高位时新建一个节点。

最低位为 0 时，加入新树并变成 1，从非 1 链表删去这一项。最低位为 2 时，联接原有两树成为下一阶的树，新单节点留在最低位；正规条件保证下一阶原来最多一棵。最低位为 1 时，先读非 1 链表头：若它为 0 或不存在，直接把最低位变成 2；若它为 2，先联接那一阶的两树，留下一个 0，再把进位树加到下一阶，最后最低位成为 2。

这三种变换都保持正规条件：需要联接的 2 后一位最多为 1；把它变成 0 后，新的低位 2 与后面的 2 之间得到这个分隔 0。若下一阶从 1 变成 2，它与更高的旧 2 之间保留了原来的分隔 0。新最高位初始化为 0，普通 0／1 森林也满足约束。

链表维护同样只需常数步。非 1 变成 1 时直接按前后指针摘除；1 变成非 1 的位置只有最低位或刚处理阶的下一位，插入的前驱分别是空指针或刚处理的那个阶槽，不需要搜索。2 变成 0 留在原链表位置。因此一次 Insert 至多一次根比较联接、一次新节点分配、一次新阶分配和常数次指针更新，最坏 O(1)；分配按 RAM 常数成本模型计。

FindMin 扫描至多两倍对数个根。Merge 和 DeleteMin 先把至多两树一阶的森林规范化成普通二项队列，再执行正文操作，最后按阶重建 0／1 根表和定位链表。规范化每次联接使根数少一，原根数只有对数量级，故所有联接和阶扫描合计 O(log(N+1))。这一构造使用显式指针节点，空间线性。

两版依赖正文 BNode、BQueue 及其核心操作。C 使用与正文一致的教学容量，所有权在规范化中转移，来源控制对象随后为空；Python 使用同样的链式阶槽。它们的常数定位直接由代码中的 first_non_one 完成。

    bool before = s->count != 1, after = count != 1;
    if (before && !after) {

bool r_find_min(const RQueue *h, int *out) {

    BNode *best = NULL;
    for (RSlot *s = h->low; s; s = s->higher)

void r_to_binary(RQueue *h, BQueue *result) {
    *result = (BQueue){0}; result->size = h->size;
    RSlot *s = h->low;
    while (s) {
        for (unsigned j = 0; j < s->count; ++j) {
            BNode *carry = s->tree[j]; size_t i = s->rank;
            while (result->root[i]) {
                carry = bin_link(result->root[i], carry);
                result->root[i++] = NULL;
            }
            result->root[i] = carry;
        }
        RSlot *next = s->higher; free(s); s = next;
    }
    *h = (RQueue){0};
}
void r_from_binary(RQueue *h, BQueue *source) {
    assert(h->low == NULL);
    h->size = source->size;
    for (size_t i = 0; source->size && ((size_t)1 << i) <= source->size; ++i) {
        RSlot *s = r_extend(h);
        if (source->root[i]) {
            s->tree[0] = source->root[i];
            r_set_count(h, s, 1, NULL);
        }
    }
    *source = (BQueue){0};
}

            self.low = slot
        self.last = slot
        return slot

    def _normalize_two(self, slot):
        carry = bin_link(*slot.trees)
        self._set_count(slot, 0)
        slot.trees.clear()
        successor = slot.higher or self._extend()
        assert len(successor.trees) <= 1
        self._set_count(successor, len(successor.trees) + 1, slot)
        successor.trees.append(carry)

    def push(self, key):
        if self.size == BQ_CAPACITY:
            raise OverflowError('regular queue capacity')
        if self.low is None:
            self._extend()
        if len(self.low.trees) == 2:
            self._normalize_two(self.low)
        elif len(self.low.trees) == 1:
            first = self.first_non_one
            if first and len(first.trees) == 2:
                self._normalize_two(first)
        self._set_count(self.low, len(self.low.trees) + 1)
        self.low.trees.append(BNode(key))
        self.size += 1

    def minimum(self):
        if not self.size:
            raise IndexError('empty regular queue')
        result, slot = None, self.low
        while slot:
            for tree in slot.trees:
                if result is None or tree.key < result:
                    result = tree.key
            slot = slot.higher
        return result

    def _to_binary(self):
        result, slot = BQueue(), self.low
        result.size = self.size
        while slot:
            for tree in slot.trees:
                i = slot.rank
                while result.root[i]:
                    tree = bin_link(result.root[i], tree)
                    result.root[i] = None
                    i += 1
                result.root[i] = tree
            slot = slot.higher
        self.__init__()
        return result

    def _from_binary(self, ordinary):
        self.size, i = ordinary.size, 0
        while 1 << i <= ordinary.size:
            slot = self._extend()
            if ordinary.root[i]:
                self._set_count(slot, 1)
                slot.trees = [ordinary.root[i]]
            i += 1
        ordinary.size, ordinary.root = 0, [None] * BQ_RANKS

    def pop(self):
        self.minimum()
        ordinary = self._to_binary()
        result = ordinary.pop()
        self._from_binary(ordinary)
        return result

    def merge(self, other):
        if other is self:
            raise ValueError('self merge')
        if self.size + other.size > BQ_CAPACITY:
            raise OverflowError('regular queue capacity')
        ordinary, source = self._to_binary(), other._to_binary()
        ordinary.merge(source)
        self._from_binary(ordinary)

5.34 · 三种装箱策略，如何真正做到每项对数处理？

原题（中文翻译）

给定若干箱子，每个箱子能够承受的总重量为 C；物品 i1,i2,…,iN 的重量分别为 w1,w2,…,wN。目标是在不超出任一箱子容量的前提下装入全部物品，并尽可能少用箱子。例如 C=5、物品重量为 2、2、3、3 时，两个箱子就能装下。

原题指出，这个问题一般很难，没有已知的高效解法。编写程序，高效实现下列近似策略：

  1. 将物品放入第一个能容纳它的箱子；没有任何箱子有足够空间时才创建新箱子。本问及后面的这些策略，在上述例子中都会用三个箱子，未达到最优。
  2. 将物品放入剩余空间最大的箱子。
  3. 将物品放入已经装得最满、但仍能容纳它而不溢出的箱子。
  4. 事先按重量排序物品，是否能够改善这些策略？

原书习题 5.34 · 印刷页 184 · PDF 第 201 页。

解答

用箱号表示创建次序，用剩余容量表示还能容纳多少。教材的 C=5、权重 2、2、3、3，在这三种在线规则下都得到三个箱：第一箱 2+2，第二箱 3，第三箱 3；每箱剩余为 1、2、2。最优两箱则各放 2+3。下面说明的是启发式的高效实现，不把它们当作求最优解的证明。

a First fit：按箱号寻找第一处足够的容量

用区间最大值树保存各箱剩余容量。根最大值小于新权重时才新建箱；否则从根往下，左区间最大值足够就走左边，否则走右边，最终找到最早可用箱。普通按剩余容量排的堆不能回答“最早箱号”。区间树更新一个叶子也为对数。

b Worst fit：最空的箱就是最大堆根

最大堆键为剩余容量。若根都放不下，就没有箱能放下；否则取出根，减去权重再插回。Python 的 heapq 是最小堆，代码使用负剩余容量，箱号在相等时选择较早的箱；已有旧项必须取出，不能留下过时的容量记录。

c Best fit：找不小于权重的最小剩余容量

用 AVL 按“剩余容量、箱号”建立索引，查找 lower_bound((weight,-1))，再删除旧键并插入新键。第四章的平衡约束在这里重新发挥作用：排序数组加 bisect 虽能二分定位，元素搬移仍线性，不能算作对数更新。

三种实现共用整数输入检查，代码完整包含 First fit 的区间树、Worst fit 的堆和 Best fit 的 AVL。返回每项箱号及最后剩余容量，空输入不创建箱；每个零权重项仍要归入某个箱，因此容量为 0 且输入非空时会创建一个零容量箱。算法按 RAM 模型计，整数比较／算术为常数，空间 O(N)，整体最坏 O(Nlog(N+1))；Python 动态列表扩容计入总时间，单次追加按摊还计。

    elif key > t.key:

    if t is None:
        raise KeyError(key)
    if key < t.key:
        t.left = erase(t.left, key)
    elif key > t.key:
        t.right = erase(t.right, key)

            p = p.left
        t.key = p.key
        t.right = erase(t.right, p.key)
    return balance(t)

原题（中文翻译）

希望为堆增加操作 DecreaseAllKeys(Δ)，使所有键都减去 Δ。任选一种堆实现，说明所需修改，使 DecreaseAllKeys 的时间为 O(1)，而其他操作保留原来的运行时间。

原书习题 5.35 · 印刷页 184 · PDF 第 201 页。

解答

选普通二叉堆，增加全局偏移 δ，把实际键解释为“存储键加偏移”。所有键共享同一偏移，大小关系完全不变，所以整体减 A 只做 δ←δ−A，最坏常数，无须重新建堆。

先把目标统一为第 k 大：5A 用最大堆对全量建堆后删除 k 次，5B 用最小堆保留最大的 k 项。按照各自原有流程：

TA=O(N+klog(N+1)),TB=O(k+(N−k)(1+logk))

没有一个上界对所有 k 都更好。k 为常数时，两者都是线性；k 约为 NlogN 时，5A 为 O(N)，5B 的一般上界仍为 O(NlogN)；k=N 时，5A 完成全部删除要 O(NlogN)，5B 只需对全部输入建一次堆，根就是最小值，成本 O(N)。中间比例规模通常同为 O(NlogN)，还要考虑比较、替换次数与空间。

5A 空间 O(N)，5B 工作空间 O(k)，后者适合流式输入；更细的成本是 O(N+Rlogk)，成功替换很少时可以显著好于一般上界。如果允许改造 5A，靠近末端的秩可以改用另一方向的堆，删除 min(k,N−k+1) 次；同样也能让 5B 保留较小的补集秩。这属于改进后的算法，不能混入原流程的比较而不说明。

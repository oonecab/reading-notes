第三章：表、栈和队列

一、作者为什么先谈 ADT，而不是先画链表？

这一章的开头颇值得慢读。Weiss 没有马上拿出一个 struct Node，而是先问：当我们说“一个表”时，到底承诺了什么？它是一串有先后关系的元素，能查找、插入、删除、打印；至于元素是否连在一起、位置到底是数字还是指针，都还没有决定。这个顺序重要，因为现实中的程序不是只写一次、只运行一种实现。

“An abstract data type (ADT) is a set of operations.”

译：抽象数据类型（ADT）是一组操作。

原书 §3.1，印刷页 35–36

这句话很短，却是全章的钥匙。“表”并不等于“链表”，甚至不等于某一份头文件。比如 Find(X,L) 应该查找 X，但是否找到第一次出现的 X、找不到返回什么、Insert(X,L,P) 在 P 之前还是之后插入，都属于操作契约。没有写明契约，就算两份代码的函数名完全一样，也可能互换不了。

书中强调：抽象带来的好处是实现细节集中在少数例程里。换一种存储方式，只改这些例程；调用它们的代码只依赖操作语义。不过在 C 里，这种隔离并不自动成立。书中的 List 和 Position 都是节点指针的别名；如果调用者直接访问 Next，抽象就被穿透了。学习书上的实现时，要同时看到“作者想建立的接口边界”和“C 语言实际能够强制的边界”。

二、数组怎样把我们带到链表

进入 §3.2，作者先给出 A1,A2,…,An 这样一张表。Find 沿着表找一个值；FindKth 找第 k 个元素。这两个名字看起来很像，在数组里却有完全不同的代价：前者可能要逐个比较，后者直接读取下标。

想象已经存了五个数：[34, 12, 52, 16, 12]。如果要在最前面插入 7，不能简单把 7 放在下标 0——34 还在那里。必须先把末尾的 12 往右移，再移 16、52、12、34，最后才能写入 7。删除最前面的元素则反向搬移。数组把“第 k 个在哪里”回答得很快，却把“在这里腾一个位置”变成了搬运工作。

书中还提醒另一个不显眼的限制：即使数组是动态申请的，通常仍要预估它最多有多大。多个规模未知的表如果都预留过大的容量，就会浪费空间。这里引出链表的真正动机：让相邻的逻辑元素不必占据相邻的物理地址。如此一来，在中间插入时不必搬走后面整段元素，只要改变连接关系。

先记住这个代价交换：数组让“访问第 k 项”容易；链表让“已知连接点后改动邻接关系”容易。不能由此推出链表的所有插入删除都比数组快——寻找那个连接点也可能要花 O(N)。

三、跟着图 3.1–3.15 读链表

3.1　箭头画的是地址，不是数据自己会移动

图 3.1 画出一条 A1→A2→…→A5；图 3.2 则把它放回内存现实：这些节点可能位于 1000、800、712、992、692 等互不相邻的地址。第一个节点的 Next 存了第二个节点的地址 800。因此遍历链表不是“把数组下标加一”，而是取当前节点中的地址，再跳过去。

如果要找第 k 个元素，链表没有第 k 个地址的计算公式，只能走过去，所以是 O(k)；最坏 O(N)。但若要连续读取第 2、3、4、6 项，可以记住上一次走到的位置，在一次扫描中完成，而不必四次从头出发。书中在解释性能时特意指出了这种实际使用方式：复杂度是对单次操作的描述，调用序列也值得分析。

3.2　为什么书中要加一个“空壳”节点？

图 3.3 和图 3.4 看起来很轻巧：删除绕过一个节点，插入接上一个节点。但它们隐含一个难题。如果要删除第一个节点，它的前驱是谁？如果表只有一个 L 指向首节点，删除它后还得重新给 L 赋值；如果删除中间节点，又必须找到它前面的那个节点。作者随后在图 3.5 引入 header（头节点、哑节点）：

header 不代表表中的元素；它站在第一个元素前面。于是删除 A1 时，header 就是它的前驱；表头插入也可解释为“在 header 后面插入”。作者承认使用 header 有争议：它多占一个节点，有人宁愿为表头写特殊分支。他在这里选它，是为了让基本指针操作不被各种边界分支遮住。读者不必把 header 奉为唯一正确方案，但应该明白它改变了哪些不变量。

“It is always best to draw a picture first.”

译：最好总是先画一张图。

原书 §3.2.3，印刷页约 39

这是本节最可操作的一句话。读图 3.8 的 IsEmpty 时，只看 L->Next == NULL 是否与空表图一致；读图 3.9 的 IsLast 时，看位置 P 的 Next 是否为 NULL。先让图说明“什么状态叫空、什么节点叫最后”，再让代码检验图，而不是背诵代码。

3.3　找值、找前驱、删除：三个动作不要混成一个

图 3.10 的 Find 从 L->Next 起步；如果节点不为空、值也不是 X，就走到下一个。p != NULL && p->Element != X 的次序有意义：C 对 && 短路求值，p 已为空时便不会读取它的 Element。找不到返回 NULL，找到返回节点位置。

但图 3.11 的 Delete(X,L) 不直接调用 Find。单向链接只记录“我后面是谁”，并不记录“谁指向我”。若找到了 X 所在的节点 T，仍无法直接把前一个节点的 Next 改为 T 的后继。所以图 3.12 的 FindPrevious 从 header 起步，检查 p->Next 是否是 X：

找到前驱后删除 12；表为 header → 34 → 12 → 52 → NULL
步骤位置或操作检查与结果
①p = header后继为 34，继续前进。
②p = [34]后继为 12，前驱已找到。
③t = p->next保存待删节点。
④p->next = t->nextheader → 34 → 52 → NULL。
⑤free(t)12 的节点释放，旧位置失效。

若 X 不存在，搜索会停在尾节点，尾节点的 Next 是 NULL；删除函数检查这一条件后便什么也不做。若 X 有多次出现，则删除第一处。注意成本分两层：查找前驱最坏 O(N)，拿到前驱以后重接链接 O(1)，所以整个 Delete(X,L) 仍是 O(N)。

3.4　插入为什么只有两句赋值，却总让人出错？

图 3.13 规定在合法位置 P 之后插入 X。假设原来 P 指向 Q。新申请的节点 T 要放在二者中间。首先让 T 指向原先的 Q，然后才让 P 指向 T：

阶段指针操作链上的状态
原状态—P→Q
① 接后继T->Next = P->NextP→Q；T→Q
② 接前驱P->Next = TP→T→Q

若先做第二句，P->Next 就变成了 T；再写 T->Next = P->Next，T 会指向自己，而原先的 Q 从这条链上消失。即使代码只有两行，也要在纸上按顺序模拟每一条箭头。

这里的 O(1) 也需要写出条件：调用者已经持有合法位置 P。若任务是“找到值为 52 的节点，然后在其后插入 X”，先找 52 仍要 O(N)。如果要求“在 P 之前插入”，单链表也得先找到 P 的前驱。书中特别说明插入位置的语义是设计选择，写接口时应当明说。

3.5　这一节的真正难处：内存的生命期

图 3.14 和图 3.15 展示了一个非常具体的陷阱：要逐个释放整张表，不能先 free(p)，再用 p->Next 找下一个节点。释放之后地址可能仍然“看起来没变”，但其中的数据已不属于程序，继续读取是未定义行为。要先把下一站记下来；下面两种实现复用 共享 SNode 定义，并保留 header：

C（C11）
/* Uses SNode from the shared definitions below; retain the header. */
static void clear_list(SNode *header) {
    SNode *p = header->next;
    header->next = NULL;
    while (p) {
        SNode *next = p->next;
        free(p); p = next;
    }
}
Python 3
def clear_list(header):
    p = header.next
    header.next = None
    while p is not None:
        following = p.next
        p.next = None
        p = following

“Declaring a pointer to a structure does not create the structure.”

译：声明一个指向结构体的指针，并不会创建那个结构体。

原书 §3.2.4，印刷页约 44

Position p; 只给了一个能放地址的变量，还没有给它所指的节点分配空间。要创建节点需分配 sizeof(struct Node) 字节；书中专门警告 malloc(sizeof(PtrToNode)) 只得到指针大小的内存。反过来，拿一个指针变量沿着已有链表走时，也不应每走一步就 malloc。要区分“创建新节点”和“引用已有节点”。

这一小节读完，可以用三个问题检查每行 C 代码：指针当前指向有效节点吗？这块内存由谁分配、由谁释放？更改链接或释放节点之后，哪些旧的 Position 已经失效？

四、§3.2 后半段：同一个链接思想能走多远

4.1　想要后退？给节点增加 Previous

§3.2.5 的双向链表看似只多一个指针，实际上是在改变可用信息：给定一个节点，现在能直接知道它前面的节点，删除时不再必须沿着链表寻找前驱；但是每个节点多占一个链接，插删也要维护两个方向。到了 §3.2.6 的循环链表，最后一个节点不再指向 NULL，而是回到第一个节点或 header；双向循环链表还能让首节点的 Previous 指向尾节点。此时遍历的停止条件必须跟着改变——不能再一味等 NULL。

4.2　多项式：按最高指数开数组，还是只存存在的项？

原书先给稠密多项式的数组方案：指数 i 对应第 i 个系数，加法逐项相加，乘法逐对相乘并把结果累加到相应指数。这样做在大多数系数非零时自然。但若只有 10x1000+5x14+1，从 0 到 1000 的大部分槽位都没有有用信息。

表示保存的内容
数组系数 [0…1000]；绝大多数项为 0
链表(10, 1000) → (5, 14) → (1, 0)

链表按指数降序存非零项。加两个有序多项式时，可以像合并两列有序卡片：指数高的项先进入结果；指数相同就相加系数，为零则不写入。两个链表分别有 M、N 项时，顺序归并只需 O(M+N) 次节点比较。乘法比加法麻烦：不同项相乘可能得到相同指数，结果必须合并同类项；书中把实现留给练习。这个例子教我们的不是“链表总比数组省空间”，而是表示要匹配数据的稠密程度。

4.3　一个选课记录，可以同时躺在两条链上吗？

大学选课例子有 40,000 名学生和 2,500 门课。若用学生 × 课程的二维表，有一亿个位置；平均每人选三门课，真正发生的选课关系大约只有 12 万条。作者想同时支持两个问题：“C3 有哪些学生？”和“S1 选了哪些课程？”只按学生串起来，查课程就费劲；只按课程串起来，查学生就费劲。

遍历方向所见的记录
课程 C3C3 → [S1,C3] → [S3,C3] → …
学生 S1S1 → [S1,C3] → [S1,C7] → …

加粗的是同一条选课关系，从两种方向都能到达。

图 3.24 中的具体组织方式比这个简图更节省链接：表头与记录组成循环表，有时需要沿另一方向走到表头，才能确定一条记录属于哪个学生或课程。作者随后指出也可以让记录直接指向两边的表头，花更多空间换更直接的定位。稀疏矩阵使用相似结构：一个非零项既在某行的链上，也在某列的链上，同时保存行列号与数值。看到这里，链表不再只是“一根绳子”，而是对关系的多方向索引。

4.4　Cursor：没有指针，也可以有链表

§3.2.8 用游标实现回应了一个有趣的问题：若语言不能直接用指针，链表思想还成立吗？答案是成立。用全局数组 CursorSpace 存节点；让 Next 保存下一个节点的数组下标，约定 0 等价于空指针。数组中的空闲单元也串成一条 freelist，分配时取第一个空闲槽位，释放时把槽位放回空闲表前端。

状态含义
CursorSpace[0]空闲链的表头；其 Next 指向第一个空槽。
CursorSpace[5].Next = 95 号槽链接到 9 号槽。

这里有个作者用来承上启下的观察：最近放回 freelist 的槽位，最先被再分配。这个“后进先出”的次序，正好引出下一节的栈。

五、栈：把自由度收起来，反而得到一种强大的结构

§3.3 把栈定义为只能在一端（top）插入和删除的表。Push 放入栈顶，Pop 移除栈顶，Top 查看栈顶。读这个定义时不妨拿 freelist 回想：刚刚释放的节点在表头，也会第一个被取出。

“Stacks are sometimes known as LIFO (last in, first out) lists.”

译：栈有时也称为后进先出的表。

原书 §3.3.1，印刷页约 56

书中分别用链表和数组实现栈。链表版在 header 后插入和删除，操作本身都是 O(1)，但频繁 malloc/free 会带来开销。数组版用 TopOfStack = -1 表示空栈：Push 时先加一再写入；Pop 时删除栈顶并使下标减一。两者复杂度同为 O(1)，实际常数与容量限制却不同。

“You should always write the error checks.”

译：应当始终写上错误检查。

原书 §3.3.2，印刷页约 61

这句出现在讨论“要不要为极快的栈操作增加边界检查”的地方。空栈上的 Pop、Top 是逻辑错误；数组栈已满时 Push 则碰到实现的容量限制。跳过检查也许省去几条指令，但栈例程通常不是程序耗时主体，错误一旦蔓延却很难追。作者在这里是在教如何权衡工程上的快与可靠。

5.1　括号匹配：为什么仅仅数括号不够？

[(]) 中左、右方括号各一个，左、右圆括号也各一个；数量完全平衡，却不能正确配对。读到右括号 ] 时，最近尚未闭合的是 (，不是 [。因此把左括号压栈；读右括号时弹出最近的一个并比较种类；读完后栈还非空也说明有遗漏。输入只扫一遍，每个符号最多入栈、出栈各一次，时间 O(N)。

5.2　后缀表达式：把优先级问题变成栈操作

看 6 5 2 3 + 8 * + 3 + *。遇数字就压栈；遇运算符就弹出两个数，计算后把结果压回去。扫描到 + 时最近的 2、3 变成 5；随后 5、8 相乘变成 40；再与前一个 5 相加得到 45；加 3 得 48；最后与 6 相乘得到 288。每一步只问“栈顶的两个数是谁”，不再问“乘法比加法先算吗”。

读入片段栈的内容（右侧为栈顶）
6 5 2 3[6,5,2,3]
+[6,5,5]
8 *[6,5,40]
+ 3 +[6,48]
*[288]

倒过来，中缀转后缀时就需要一个运算符栈来暂存尚未输出的符号。对于 a+b·c，读到 + 先暂存，读到 * 因优先级更高也暂存；末尾依次弹出 * 和 +，得到 a b c * +。遇右括号则一直弹到相应左括号；左括号本身不输出。同级运算符还需考虑结合方向：减法是左结合，指数运算通常右结合，不能只看优先级数字。

5.3　函数调用：为什么递归也会“占地方”

作者最后把栈从“自己写的一个数据结构”推进到“程序运行所依赖的机制”：调用一个函数时，要记住从哪里返回、调用者需要保留哪些状态。调用越深入，待恢复的信息越多；返回时最后一次调用先结束，恰是 LIFO。每一层保存的信息称为活动记录或栈帧。

图 3.53 用递归打印链表作为反例：它逻辑上正确，也有停止条件；但一个含 20,000 个节点的表可能积累 20,000 层调用。这里的问题不是结果错，而是为了“走到下一个节点”付出了大量栈帧。图 3.54 演示如何机械地去掉尾递归；实际代码直接用 while 遍历就好。作者没有要求所有递归都改成循环——更一般的递归改写可能更难读，得看栈深度、成本与清晰度。

六、队列：另一种限制，另一种时间顺序

§3.4 的队列也从表出发，但插入发生在 rear，删除发生在 front。新来的排在后面，等待最久的先离开。作者说链表实现并不困难，把笔墨放在数组版的一个细节：为什么明明有空格子，队尾却会“走到头”。

假设数组容量 5，先放入 1、2、3，再出队两次，只剩 3。数组靠前的两个格子虽空了，如果 Rear 只会向右增加，继续入队就会碰到数组末端。解决方式是让下标绕回 0：到达末端后，下一格就是开头。于是物理数组的顺序可以是 [5,6,7,3,4]，逻辑队列的顺序却是 3,4,5,6,7。

出队两次（1、2 离开）3313

3.2 · PrintLots(L,P)

原题（中文翻译）

给定链表 L 和另一个链表 P，P 中保存按升序排列的整数。PrintLots(L,P) 输出 L 中位于 P 所指定位置的元素。例如 P 为 1、3、4、6 时，应输出 L 的第 1、3、4、6 项。编写这个过程，只能使用基本的表操作。过程的运行时间是多少？

原书习题 3.2 · 印刷页 79 · PDF 第 96 页。

解答

L 的位置从 1 开始。保留一个 L 游标和当前位置 i，对 P 中每个升序位置 k，仅把 L 游标向前推进到 k，再输出。若 P 允许重复位置，保持游标即可再次输出；k≤0 或超出长度应报错。下列实现只使用 list_first、list_end、list_retrieve、list_advance 等基本表操作，显式的 End 判断允许检查空位置。

C（C11）
/* Returns false at the first invalid request; output may have a valid prefix. */
static bool print_lots(const SNode *l_header, const SNode *p_header) {
    const SNode *p = list_first(l_header);
    size_t position = 1;
    int last = 0;
    for (const SNode *r = list_first(p_header); !list_end(r); r = list_advance(r)) {
        int k = list_retrieve(r);
        if (k < 1 || k < last) return false;
        while (position < (size_t)k && !list_end(p)) {
            p = list_advance(p); ++position;
        }
        if (list_end(p)) return false;
        printf("%d\n", list_retrieve(p)); last = k;
    }
    return true;
}

为什么只需要一次扫描？

用输入 L=[10,20,30,40,50,60]、P=[1,3,4,6] 检查：L 游标依次到位置 1、3、4、6，累计只走 5 步，输出 10、30、40、60。P 的升序保证不用倒退；相邻请求同为 3 时直接重复输出 30。循环不变量是：处理下一个位置请求前，游标仍指向最后一次已定位的位置。

书中的 IsLast 要求合法节点，不能直接对 NULL 调用。每个请求推进前先拒绝非正位置及下降次序，超过表尾返回失败；因为边扫描边打印，错误出现前可能已经输出有效前缀，失败不会回滚已写出的输出。

3.4 · 两个有序表的交集

原题（中文翻译）

给定两个有序表 L1,L2，仅使用基本的表操作，编写过程计算它们的交集 L1∩L2。

原书习题 3.4 · 印刷页 79 · PDF 第 96 页。

解答

双游标比较：小的一方前进，相等时向新结果尾部追加一份并同时前进。结果尾游标避免每次从头寻找尾部。若题意为集合交集，每次还跳过所有相同值；若为多重集交集则保留 min(f1,f2) 次，其中 f1、f2 是该值在两表的出现次数，须先约定语义。

每个输入游标只前进，Θ(M+N) 时间上界，输出 O(min(M,N)) 空间；输入不变，新节点归结果所有者，失败需释放已建结果。

两种语言的交集实现与并集共用 merge_set：传入两个首数据节点，unite=false／False 得到交集，true／True 得到并集。

3.5 · 两个有序表的并集

原题（中文翻译）

给定两个有序表 L1,L2，仅使用基本的表操作，编写过程计算它们的并集 L1∪L2。

原书习题 3.5 · 印刷页 79 · PDF 第 96 页。

static SNode *merge_set(const SNode *a, const SNode *b, bool unite) {
    SNode header = {0, NULL}, *tail = &header;

        int x; bool in_a, in_b;
        if (list_end(b) || (!list_end(a) && list_retrieve(a) < list_retrieve(b))) {

3.6 · 不破坏输入的多项式加法

原题（中文翻译）

用链表实现两个多项式相加的函数，不得破坏输入。若两个多项式分别有 M 项和 N 项，程序的时间复杂度是多少？

原书习题 3.6 · 印刷页 79 · PDF 第 96 页。

解答

输入项按指数降序。若指数不同，复制指数较大项到新表；相同则相加系数，结果非零才追加，并推进两个输入。最后复制剩余项。每项只看一次，时间 O(M+N)，结果最多 M+N 项。

新建结果节点，不能把输入节点直接摘入结果。处理零多项式、抵消为零与分配失败；系数运算若为任意精度，位运算成本还须计入。

合并过程与实现

3.7 · 多项式乘法的三种复杂度

原题（中文翻译）

用链表实现两个多项式相乘的函数。必须保证输出按指数排序，而且每个幂次最多只有一项。

  1. 给出一个 O(M2N2) 时间的算法。
  2. 编写一个 O(M2N) 时间的乘法程序，其中 M 是项数较少的多项式的项数。
  3. 编写一个 O(MNlog(MN)) 时间的乘法程序。
  4. 上面哪个时间界最好？

原书习题 3.7 · 印刷页 79–80 · PDF 第 96–97 页。

解答

设 M≤N，先明确每对项乘积的指数是指数和。

a O(M2N2)：生成 MN 项，再逐项扫描当前结果链，合并同指数或按指数插入；每次最坏扫描 O(MN)，总 O((MN)2)。

b O(M2N)：较短多项式的第 i 项乘以整个长表，生成有序的 N 项链，再与已有最多 (i−1)N 项的结果做线性归并。求和 ∑i=1MO(iN)=O(M2N)。系数为零的项删除，两个输入不变。

c O(MNlog(MN))：生成全部乘积，用链表归并排序按指数排列，再线性合并同指数项。临时节点 O(MN)。也可用最小／最大堆归并 M 条有序乘积流，得 O(MNlogM)。

d：b 与 c 谁优取决于 M 与 log(MN)；短表只有常数项时 b 为 O(N)，M 较大时 c 往往更好，不能固定说 c 总最快。

3.8 · 求 F(X) 的 P 次幂

原题（中文翻译）

编写程序，输入多项式 F(X)，计算 (F(X))P。程序的复杂度是多少？至少提出一种替代方法，使它在某些合理的 F(X) 与 P 取值下具有竞争力。

原书习题 3.8 · 印刷页 80 · PDF 第 97 页。

解答

P 为非负整数，P=0 返回常数 1（此处采用包含零多项式在内的统一接口约定）。二进制快速幂：R=1、B=F；P 奇数时 R←R·B；随后 P 右移，若仍非零则 B←B2。乘法次数 O(logP)，但多项式越来越大，不能把总时间写成 O(logP)。

精确成本为各次乘法代价之和。若用稠密朴素乘法、F 次数 d，则输出次数 dP，快速幂和逐次乘 F 的最坏算术成本都可界为 O(d2P2)，但常数与稀疏性不同。P 很小可逐次乘；F 是单项式 cXd 时直接得到 cPXdP；二项式也可用二项式系数直接生成结果。链表版应根据实际项数估算每次乘法，不能只看次数。

链表快速幂的具体实现

    value, two = bi_from('1'), bi_from('2')
    for _ in range(exponent):
        value = bi_mul(value, two)
    return value

def power2_distribution(exponent):
    value = bi_pow2(exponent)
    counts = [0] * 10
    for digit in value.digit:
        counts[digit] += 1
    return len(value.digit), counts

这是位表算法，计算过程复用 bi_mul 逐次乘 2；内置整数只在验证时核对最终结果。第 r 次倍增有与 r 同阶的位数，逐次扫描的总代价为 ∑r=1pO(r)=O(p2)。最高位追加应发生在扫描结束后，不能让新位又被本轮倍增一次。

3.10 · Josephus：传 M 次，不是数到 M

原题（中文翻译）

Josephus 问题是下面的游戏。N 个人编号为 1 至 N，围成一圈。从第 1 个人开始传递“烫手山芋”；传递 M 次后，当前持有山芋的人被淘汰，其余人合拢成圈，由被淘汰者后面的人拿起山芋继续游戏。最后剩下的人获胜。例如，M=0,N=5 时，参与者按编号顺序淘汰，5 获胜；M=1,N=5 时，淘汰顺序是 2、4、1、5。

  1. 编写一个程序解决一般 M,N 的 Josephus 问题，尽可能提高效率，并确保释放淘汰者的节点。
  2. 程序的运行时间是多少？
  3. 当 M=1 时运行时间是多少？对于很大的 N（N>10000），free 过程会怎样影响实际速度？

原书习题 3.10 · 印刷页 80 · PDF 第 97 页。

解答

a：循环单链表，cur 为当前持土豆者，prev 为其前驱。剩 r 人时前进 M mod r 步，删除 cur，下一轮从其后继开始；删除前保存后继，最后释放幸存节点。书中 M=0 从当前人直接淘汰，M=1、N=5 顺序为 2,4,1,5，幸存 3。

b：不取模为 O(N(M+1))；取模后 O(N+∑r=2N(Mmodr))，最坏 O(N2)，空间 O(N)。仅求幸存者可用 0 起始递推 j=0; for r=2..N: j=(j+M+1)%r，返回 j+1，O(N) 时间、O(1) 空间；它不输出淘汰顺序。

c：M=1 时链表算法 Θ(N)。free 的实际成本依赖分配器，不存在通用的 10000 人阈值；可比较节点逐次 free 与节点池统一回收的实测常数，不改变算法阶数。

3.11 · 递归与非递归查找

原题（中文翻译）

编写程序，在单链表中寻找某个指定元素。分别采用递归与非递归方法，并比较运行时间。链表需要多长才会使递归版本崩溃？

原书习题 3.11 · 印刷页 80 · PDF 第 97 页。

解答

迭代检查当前节点，相等返回，否则向后；递归空表返回 NULL，相等返回当前，否则调用下一节点。二者最坏 Θ(N) 时间，迭代空间 O(1)，未经尾调用优化的递归空间 Θ(N)。

崩溃长度不是算法常数：栈额度、编译优化、调试插桩和帧大小都会改变结果。近似阈值为可用栈字节数÷每帧字节数；尾调用被优化时可能不会线性增长。实验应固定编译器、优化级与栈限制，独立子进程逐步增大 N，不能在笔记里虚构一个固定长度。

3.12 · O(N) 时间与 O(1) 空间反转

原题（中文翻译）

  1. 编写一个非递归过程，在 O(N) 时间内反转单链表。
  2. 编写一个过程，使用常数额外空间，在 O(N) 时间内反转单链表。

原书习题 3.12 · 印刷页 80 · PDF 第 97 页。

解答

同一迭代解法同时满足 a、b。保持 prev 为已反转前缀，cur 为未处理后缀。必须先保存 next，再修改 cur.Next。header 保留，只更新其 Next。

static void reverse_list(SNode *header) {
    SNode *previous = NULL, *current = header->next;
    while (current) {
        SNode *following = current->next;
        current->next = previous;
        previous = current; current = following;
    }
    header->next = previous;
}

3.13 · 建立稀疏矩阵的十字链表

原题（中文翻译）

编写函数，读入一个稀疏矩阵并建立它的链表表示。

原书习题 3.13 · 印刷页 80 · PDF 第 97 页。

解答

每个非零项节点存 row、col、value、right、down；行头、列头数组分别作为入口。按行列排序读入三元组，维护行尾与列尾，给同一个节点接入两条链。若输入乱序，先按 (row,col) 排序并合并重复位置、去掉零，再尾插；行优先扫描也使各列行号单调。

t 个非零项，排序 O(tlogt)，建链 O(t+R+C)，空间 O(t+R+C)。若输入已按坐标有序，则总 O(t+R+C)。释放时只沿行链释放每个数据节点一次，列头不拥有第二份节点；不能沿行、列两方向都 free。

static int triple_compare(const void *a, const void *b) {
    const Triple *x = a, *y = b;
    if (x->row != y->row) return x->row < y->row ? -1 : 1;
    return (x->col > y->col) - (x->col < y->col);
}
static void triple_sort(Triple *data, size_t n) {
    Triple *tmp = xcalloc(n, sizeof *tmp);
    for (size_t width = 1; width < n;) {
        for (size_t lo = 0; lo < n;) {
            size_t mid = lo + (width < n - lo ? width : n - lo);
            size_t hi = mid + (width < n - mid ? width : n - mid);
            size_t i = lo, j = mid, k = lo;
            while (i < mid || j < hi)
                tmp[k++] = j == hi || (i < mid && triple_compare(&data[i], &data[j]) <= 0)
                    ? data[i++] : data[j++];
            lo = hi;
        }
        if (n) memcpy(data, tmp, n * sizeof *data);
        if (width > n / 2) break;
        width *= 2;
    }
    free(tmp);
}

3.15 · Move-to-front 自调整表

原题（中文翻译）

  1. 用数组实现自调整表。它与普通表相似，但所有插入都在表头进行；通过 Find 访问一个元素时，将该元素移到表头，并保持其他元素的相对顺序。
  2. 用链表实现自调整表。
  3. 假设每个元素都有固定访问概率 pi，证明访问概率最高的元素在期望意义下接近表头。

原书习题 3.15 · 印刷页 80 · PDF 第 97 页。

解答

a 数组：插入前移整段；Find 到下标 i 后保存该项，把 [0,i−1] 右移一格，再写 A[0]。最坏 O(N)。b 链表：记录前驱，找到后先摘节点，再插到 header 后，其他节点相对顺序不变；查找 O(N)，已定位的调整 O(1)。

c：假设访问独立、概率固定且 pi>0，在稳态 i 排在 j 之前，当且仅当二者最近一次访问属于 i，所以概率为 pipi+pj。因此 𝔼[Ri]=1+∑j≠ipjpi+pj。pi 较大者，比较共同第三项与二者互比项，均得到较小期望位置；零概率元素须另外讨论初始次序。

概率结论怎样推出？

只观察 i、j 的访问，其他访问不会改变二者的相对次序。稳态下最后一次命中二者中的哪一个，它就排在前面；条件概率归一化后为 Pr(i 在 j 前)=pipi+pj。用指标变量求期望位置，不需要这些两两事件相互独立：

𝔼[Ri]=1+∑j≠ipjpi+pj.

若 pi≥pj，共同第三项 k 的贡献满足 pkpi+pk≤pkpj+pk，二者互比项也满足同方向的不等式，逐项相加便得 𝔼[Ri]≤𝔼[Rj]。结论是期望更靠前，不是每次都按概率排序。

原题（中文翻译）

  1. Pascal：begin/end、()、[]、{}。
  2. C：/* */、()、[]、{}。
  3. 说明如何输出很可能反映实际错误原因的错误信息。

原书习题 3.18 · 印刷页 81 · PDF 第 98 页。

题干校注：原题把 Pascal 的 {} 与 ()、[] 并列列出。实际 Pascal 方言把 {…} 作为注释；本解按非嵌套注释处理并检查注释是否闭合，注释内的其他括号不参与配对。

解答

a、b：先词法扫描再匹配。栈项保存左符号类型与行列；开符号入栈，闭符号检查栈顶并出栈，结束时栈必须空。Pascal 的 begin/end 要按完整词识别；{…} 是注释形式，内部字符按注释规则处理。C 的 /*…*/ 是词法状态，不可把注释里的括号入栈；字符串、字符常量、转义与 // 注释也需忽略内部符号。不同语言版本的注释嵌套规则需明确。

c：多余闭符号报告当前位置；类型不符报告“期待的闭符号”和栈顶左符号来源；文件末尾报告所有未闭合位置。若要继续找错误，明确采用弹栈或跳过符号的恢复策略。线性时间，栈最坏 O(N)，不是统计各类括号数量。

两个检查器都在首个错误停止。C 模式跳过非嵌套块注释、行注释、字符串与字符常量，再检查三种括号；Pascal 模式按完整词识别 begin/end，栈中以 b/e 编码，并跳过非嵌套的两种注释和含重复引号的字符串。标识符采用 ASCII 字母、数字及下划线。这是词法层的平衡检查，不执行预处理，也不是完整语法分析器。

/* Whitespace-tokenized numbers and four binary operators; IEEE double semantics. */
static bool eval_postfix(const char *const *tokens, size_t n, double *out) {
    double *stack = xcalloc(n, sizeof *stack); size_t used = 0;
    for (size_t i = 0; i < n; ++i) {
        const char *t = tokens[i];
        bool operation = strlen(t) == 1 && strchr("+-*/", t[0]);
        if (!operation) {
            char *end; errno = 0; double value = strtod(t, &end);
            if (!number_token(t) || end == t || *end || !isfinite(value)) { free(stack); return false; }
            stack[used++] = value; continue;
        }
        if (used < 2) { free(stack); return false; }
        double right = stack[--used], left = stack[--used], value;
        if (t[0] == '+') value = left + right;
        else if (t[0] == '-') value = left - right;
        else if (t[0] == '*') value = left * right;
        else {
            if (right == 0) { free(stack); return false; }
            value = left / right;
        }
        if (!isfinite(value)) { free(stack); return false; }
        stack[used++] = value;
    }
    bool ok = used == 1; if (ok) *out = stack[0]; free(stack); return ok;
}

import math as _math

def eval_postfix(tokens):
    stack = []
    operations = {
        '+': lambda a, b: a + b, '-': lambda a, b: a - b,
        '*': lambda a, b: a * b, '/': lambda a, b: a / b,
    }
    for token in tokens:
        if token not in operations:
            if not number_token(token):
                raise ValueError('invalid number token')
            value = float(token)
            if not _math.isfinite(value):
                raise ValueError('invalid finite number')
            stack.append(value)
            continue
        if len(stack) < 2:
            raise ValueError('missing operand')
        right, left = stack.pop(), stack.pop()
        if token == '/' and right == 0:
            raise ValueError('division by zero')
        value = operations[token](left, right)
        if not _math.isfinite(value):
            raise ValueError('nonfinite result')
        stack.append(value)
    if len(stack) != 1:
        raise ValueError('expression must leave one result')
    return stack[0]

原题（中文翻译）

  1. 编写程序，将包含 (、)、+、-、*、/ 的中缀表达式转换为后缀表达式。

3.21 · 两栈共享数组

原题（中文翻译）

仅使用一个数组实现两个栈。只有当数组中所有槽位都已使用时，栈过程才允许报告溢出。

原书习题 3.21 · 印刷页 82 · PDF 第 99 页。

解答

容量 C，top1=−1、top2=C。第一栈向右长，第二栈向左长；仅当 top1+1=top2 才满。Push1 写 A[++top1]，Push2 写 A[--top2]；Pop1 读 A[top1--]，Pop2 读 A[top2++]，各自先检查空条件。全部 O(1)，所有 C 个位置都可用。

3.22 · 常数时间 FindMin 与 DeleteMin 的下界

原题（中文翻译）

  1. 提出一种数据结构，支持栈的 Push、Pop 和第三个操作 FindMin；FindMin 返回结构中的最小元素，三个操作的最坏时间都为 O(1)。
  2. 证明：若增加第四个操作 DeleteMin，用于找到并删除最小元素，则至少一个操作需要 Ω(logN) 时间。此问需参阅第六章。

原书习题 3.22 · 印刷页 82 · PDF 第 99 页。

解答

a：每个栈项保存 value 与入栈至今的 minimum；Push 写 min(x,旧栈顶.minimum)，Pop 摘顶，FindMin 读顶的 minimum。或另设最小值栈，但重复最小值也必须计数／重复压入。固定容量或每节点常数分配模型下，操作最坏 O(1)。

b：若 Push 与 DeleteMin 都为常数最坏时间，把 N 个键 Push 后连续 DeleteMin，就能 O(N) 比较排序，与 Ω(NlogN) 下界矛盾。故这些操作不能全部常数；规模至多 N 时至少一个操作的最坏代价为 Ω(logN)（也可表述为该排序序列中的平均操作代价下界）。

最小值为何能随 Pop 恢复？

依次压入 5、2、2、4，每层的 (value,minimum) 为 (5,5)、(2,2)、(2,2)、(4,2)。弹 4 最小仍为 2，弹一个 2 最小仍为 2，再弹第二个 2 才恢复 5。每层最小值记录的是该层及以下的前缀最小值，Pop 不用重新扫描。

若增加 DeleteMin 且所有操作都常数，则 N 次 Push 与 N 次 DeleteMin 用至多 cN 次比较即可输出排序。这与比较排序下界矛盾；更一般地，设两操作规模不超过 N 时的最坏成本上界为 a(N)、b(N)，则

N(a(N)+b(N))=Ω(NlogN),max{a(N),b(N)}=Ω(logN).

这是至少一种操作的成本下界，不是说每一次 Push 或每一次 DeleteMin 都必须执行对数次比较。

a：固定容量最小栈

重复最小值直接保存在每层记录里。容量在初始化时一次分配，三个操作均为最坏 O(1)，初始化与销毁成本单列。

3.23 · 三栈放进一个数组

原题（中文翻译）

说明如何在一个数组中实现三个栈。

原书习题 3.23 · 印刷页 82 · PDF 第 99 页。

解答

若数组每槽可以是 {value,next} 记录，建立共用 freelist 与三个 top，下标充当链接：Push 从 freelist 摘槽、指向该栈旧顶；Pop 把槽归还 freelist。一个槽只属于一栈或空闲表，真正无空槽时才溢出；每次 O(1)，代价是每槽额外链接。

若要求纯元素数组、不能加每槽链接，则第一栈从左长，第二栈放中间连续段，第三栈从右长。相邻区间冲突而另一侧尚有空位时，搬移中间栈重新分配空隙，再入栈。它同样共享总容量，但一次 Push 最坏 O(N)。题目没有要求三栈都常数时间，不能不说明存储模型就承诺两者兼得。

纯数组方案的状态与搬移规则

用半开区间表示三栈：第一栈 [0,a)、中间栈 [b,c)、第三栈 [d,C)，始终 0≤a≤b≤c≤d≤C。第一栈和中间栈向右长，第三栈向左长。a=b 时若 c<d，把 [b,c) 向右移一格，为第一栈腾槽；c=d 时若 a<b，把中间栈向左移一格，为中间栈或第三栈腾槽。

右移用 memmove 或从右往左复制；左移用 memmove 或从左往右复制，随后同步 b、c。两处空隙均为 0 才是真的全满。例：容量 8，区间 [0,2)、[2,5)、[7,8)，第一栈压入时把中间三项右移至 [3,6)，再写 A[2]，元素数只增加一。

这种每次只搬一格的实现可以频繁搬移中间栈，不额外声称摊还常数；它实现了“有空余空间就能容纳 Push”。

带槽位链接的实现

3.24 · Fibonacci(50) 的栈会先耗尽吗？

原题（中文翻译）

如果运行 §2.4 中计算 Fibonacci 数的递归过程，令 N=50，是否很可能耗尽栈空间？为什么？

原书习题 3.24 · 印刷页 82 · PDF 第 99 页。

本书 §2.4 的初值是 Fib(0)=Fib(1)=1。朴素递归的调用总次数指数增长，但同时存活的最大调用链只有 O(N)；N=50 时只有约几十层，通常不会先耗尽栈。两个子调用依次执行，整棵调用树不会同时存在于调用栈。

若以常见初值 G0=0, G1=1 定义序列，则本书的 Fib(N)=GN+1，因此 Fib(50)=20365011074。真正的问题是指数运行时间；有符号 32 位 int 也容纳不了这个结果。栈限额极小等特殊环境另论。

a：记录 front、rear。Enqueue 分配新尾节点；空时同时设两端，否则链接旧 rear.Next 再更新 rear。Dequeue 保存 front 与后继、取值、更新 front、释放旧首；若队列变空，将 rear 也置 NULL。操作 O(1)。

b：循环数组保留 front、size，队尾写入位置 (front+size)%C；入队前 size<C，出队前 size>0。出队后 front=(front+1)%C、size--。该约定与正文显式 Rear 版本不同，但能使用全部 C 槽；须 C>0。固定容量操作 O(1)，扩容版单次复制不是最坏 O(1)。

typedef struct { SNode *front, *rear; } Queue;
static void enqueue(Queue *q, int value) {
    SNode *p = node(value);
    if (q->rear) q->rear->next = p;
    else q->front = p;
    q->rear = p;
}
static bool dequeue(Queue *q, int *out) {
    if (!q->front) return false;
    SNode *p = q->front;
    *out = p->value; q->front = p->next;
    if (!q->front) q->rear = NULL;
    free(p); return true;
}

C（C11）
typedef struct { int *data; size_t capacity, front, size; } RingQueue;
static RingQueue ring_init(size_t capacity) {
    assert(capacity > 0);
    return (RingQueue){xcalloc(capacity, sizeof(int)), capacity, 0, 0};
}
/* Avoid overflow in (front+offset)%capacity. offset is at most capacity. */
static size_t ring_index(const RingQueue *q, size_t offset) {
    size_t gap = q->capacity - q->front;
    return offset >= gap ? offset - gap : q->front + offset;
}
static bool ring_enqueue(RingQueue *q, int value) {
    if (q->size == q->capacity) return false;
    q->data[ring_index(q, q->size)] = value; ++q->size; return true;
}
static bool ring_dequeue(RingQueue *q, int *out) {
    if (!q->size) return false;
    *out = q->data[q->front]; q->front = ring_index(q, 1); --q->size; return true;
}
static void ring_free(RingQueue *q) { free(q->data); *q = (RingQueue){0}; }

class RingQueue:
    def __init__(self, capacity):
        if capacity < 1:
            raise ValueError('capacity must be positive')
        self.data, self.capacity = [0] * capacity, capacity
        self.front = self.size = 0

def ring_enqueue(q, value):
    if q.size == q.capacity:
        return False
    q.data[(q.front + q.size) % q.capacity] = value
    q.size += 1
    return True

def ring_dequeue(q):
    if q.size == 0:
        return False, None
    value = q.data[q.front]
    q.front = (q.front + 1) % q.capacity
    q.size -= 1
    return True, value

def ring_free(q):
    q.data.clear()
    q.capacity = q.front = q.size = 0
3.26 · 双端队列

原题（中文翻译）

双端队列 deque 是一个元素表，允许以下操作：

操作含义
Push(X,D)将 X 插入双端队列 D 的前端。
Pop(D)删除并返回 D 的前端元素。
Inject(X,D)将 X 插入 D 的后端。
Eject(D)删除并返回 D 的后端元素。

编写这些过程，使每个操作都只需 O(1) 时间。

原书习题 3.26 · 印刷页 82 · PDF 第 99 页。

解答

双向链表加首尾哨兵：Push 在首哨兵后插入，Inject 在尾哨兵前插入；Pop 摘首数据节点，Eject 摘尾数据节点。插入修改四个链接，删除重接两侧再释放，空队列先报错。每次 O(1)，哨兵不作为数据删除。

也可用循环数组 front、size：Push 先令 front=(front−1+C)%C 后写值；Inject 写 (front+size)%C；Pop 读 front 再前移；Eject 读 (front+size−1)%C。固定容量下同为 O(1)，入队先查满、出队先查空。

共享一对双向局部操作

C（C11）
typedef struct { DNode head, tail; } Deque;
static void deque_init(Deque *q) {
    q->head.prev = NULL; q->head.next = &q->tail;
    q->tail.prev = &q->head; q->tail.next = NULL;
}
static void deque_add(Deque *q, int value, bool at_front) {
    DNode *left = at_front ? &q->head : q->tail.prev;
    DNode *right = left->next;
    DNode *p = malloc(sizeof *p);
    if (!p) abort();
    *p = (DNode){value, left, right};
    left->next = p; right->prev = p;
}
static bool deque_take(Deque *q, int *out, bool at_front) {
    if (q->head.next == &q->tail) return false;
    DNode *p = at_front ? q->head.next : q->tail.prev;
    *out = p->value;
    p->prev->next = p->next; p->next->prev = p->prev;
    free(p); return true;
}
static void deque_free(Deque *q) { int value; while (deque_take(q, &value, true)) {} }
Python 3
class Deque:
    def __init__(self):
        self.head, self.tail = DNode(), DNode()
        self.head.next, self.tail.prev = self.tail, self.head

def deque_add(q, value, at_front):
    left = q.head if at_front else q.tail.prev
    right = left.next
    p = DNode(value, left, right)
    left.next, right.prev = p, p

def deque_take(q, at_front):
    if q.head.next is q.tail:
        return False, None
    p = q.head.next if at_front else q.tail.prev
    value = p.value
    p.prev.next, p.next.prev = p.next, p.prev
    p.prev = p.next = None
    return True, value

def deque_free(q):
    while deque_take(q, True)[0]:
        pass

Push/Inject 分别调用 deque_add(q,x,true/false)，Pop/Eject 分别调用 deque_take(q,out,true/false)。哨兵内嵌于 q，从不 free。初始化后的 q 不能按值复制，否则内部链接仍指向原哨兵。销毁时反复 take 到空，再销毁 q 自身；必须测试双端交错操作。

环形数组的双端版本

复用 RingQueue、ring_init 与 ring_free。链式版本复用 DNode；两种版本都有明确的空结构失败返回。

/* Reuses the fixed-capacity ring storage from 3.25. */
static bool ring_push_front(RingQueue *q, int value) {
    if (q->size == q->capacity) return false;
    q->front = q->front ? q->front - 1 : q->capacity - 1;
    q->data[q->front] = value; ++q->size; return true;
}
static bool ring_eject(RingQueue *q, int *out) {
    if (!q->size) return false;
    *out = q->data[ring_index(q, q->size - 1)]; --q->size; return true;
}
/* Push=ring_push_front; Inject=ring_enqueue; Pop=ring_dequeue; Eject=ring_eject. */

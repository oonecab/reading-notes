不只是给程序贴一个复杂度标签，而是找到反复发生的工作，证明它为何发生，并据此改变算法。

一、§2.1：比较增长率，不是比较某一次计时

第一章说明了大输入会暴露算法差异，第二章需要一套不被具体机器牵着走的语言。1000N 在小规模时可能大于 N2，但 N 超过 1000 后就反过来。渐近符号关注的是：越过某个阈值之后，是否能用固定常数倍持续约束另一个函数。

以下假设资源函数最终非负，比较函数最终为正；常数 c、c1、c2、n0 与 N 无关。常见写法 T=O(f) 表示属于一类函数，不是普通数值等式。

符号精确含义应读成
T(N)=O(f(N))∃c>0,∃n0,∀N≥n0: 0≤T(N)≤cf(N)最终的常数倍上界
T(N)=Ω(f(N))∃c>0,∃n0,∀N≥n0: T(N)≥cf(N)≥0最终的常数倍下界
T(N)=Θ(f(N))∃c1,c2>0,∃n0,∀N≥n0: c1f(N)≤T(N)≤c2f(N)上下界匹配、紧确阶
T(N)=o(f(N))∀c>0,∃n0,∀N≥n0: 0≤T(N)<cf(N)任意小的常数倍最终都能压住它

例如 2N2+3N+7=Θ(N2)，也可以写 O(N3)，但后者是更松的保证。O 不是“最坏情况”的别名，Ω 也不是“最好情况”：平均时间、最坏时间各自都可以有上下界。先指定分析的是哪一个函数，再使用符号。

对常见的正函数，如果比值极限存在且为 0、正常数或无穷，就分别得到小 o、Θ 或反向小 o。极限振荡并不自动意味着不能比较：N(2+sinN)=Θ(N)，因为系数始终在 1 与 3 之间。

对原书定义的补充。原书此处把小 o 表述成“大 O 且非 Θ”，对本章常见、增长比稳定的例子可用；对任意振荡函数，它不足以替代上表的量词定义。例如比值在偶数处为 1、奇数处为 1N，可以是 O 而非 Θ，却不趋于 0。这里采用一般数学定义；习题 2.5 正适合检验函数是否真能排成全序。

多项式看最高次项，连续步骤相加时看最大的阶；嵌套工作相乘时则必须核实内层次数是否依赖外层下标。对数的底在固定底大于 1 时只改变常数；但 (logN)2 与 log(N2)=2logN 是不同的函数。

二、§2.2–§2.3：一个单位究竟是什么？

作者选择顺序执行的单位成本模型：定长整数的加法、比较、乘法、赋值等简单操作各按常数计，内存足够。模型刻意略过编译器、缓存和磁盘差异，目的是先比较算法的结构性工作量，不是声称所有机器指令真的同样快。

模型不能把“排序”“任意精度整数乘法”偷放进一个单位。快速幂的乘法次数少，并不表示每次乘法都很便宜；若结果的位数增加，位运算成本也必须增加。B 树讨论外存时又需要另一本页面访问账本，第四章会展示为什么内存模型与 IO 模型不能混用。

令大小为 N 的输入集合为 In，最坏时间是 Tworst(N)=maxx∈INT(x)；平均时间是 Tavg(N)=𝔼x~𝒟N[T(x)]。必须说出分布 Dn，才能说“平均”。有序输入、均匀随机排列和热点访问不是同一种平均。

本书通常默认最坏分析，因为它覆盖所有输入，且平均分布常常难以定义或计算。实测随机输入比最坏上界更快，不足以证明最坏分析错误；还要判断是上界不紧，还是没有抽到坏输入。

三、§2.4.1–§2.4.2：先问语句执行了几次

求立方和的例子，在作者指定的记账规则下得到 6N+4 个单位。最后写 O(N)，并不是先拍脑袋忽略细节，而是在知道计数线性后删掉常数与低阶项。后续无需每次重复精确计数，但不能忽略调用了另一个昂贵函数。

∑i=1Ni3=(N(N+1)2)2.

这个闭式是另一种算法；用它能减少算术操作数，但结果溢出和大整数成本仍需考虑。一般循环分析可以按“每个外层下标对应多少内层工作”写求和；条件分支取测试成本加两分支的最大成本，连续片段则相加。

Fibonacci：合法递归也可能极慢

书中的 Fib 基例为 Fib(0)=Fib(1)=1。朴素实现每次调用两个重叠子问题；Fib(n−1) 已经算过 Fib(n−2)，第二个分支又把它重算。若只数调用次数 Cn，则

C0=C1=1,Cn=Cn−1+Cn−2+1=2Gn+1−1.

这里 G 是标准 0、1 起点的 Fibonacci，故总时间 Θ(ϕn)。同时存活的最大调用链只有线性深度，不能把指数调用总数误当成指数栈空间。记忆化或从小到大迭代能消除重复，单位算术模型下时间线性；若要求精确大整数，结果位数的增长还须计入。

“Don’t compute anything more than once”

译：不要把同一项计算反复做。

§2.4.2，印刷页 18。指可复用的同一子问题，不是禁止循环中必要的不同输入计算。

四、§2.4.3：四种算法逐步拿掉什么重复工作？

本书的 maximum subsequence sum 指连续区间，不是可以跳过中间元素的任意子序列。允许空区间，所以全负数组的答案为 0。例 [−2,11,−4,13,−5,−2] 的答案是 20，对应连续的 11、−4、13。

算法 1：枚举区间，再从头求这个区间的和

选左端 i、右端 j，第三层遍历区间中的 k。枚举没有漏区间，但相邻右端点的两个区间又把共享部分重新相加。最内层加法精确计数为

∑i=0N−1∑j=iN−1(j−i+1)=N(N+1)(N+2)6=Θ(N3).

算法 2：固定左端，右端每走一步只加一个新数

把 ThisSum 留在第二层：从 [i,j−1] 扩展到 [i,j] 只需要加 A[j]。区间数仍是 N(N+1)2，每区间常数工作，因此 Θ(N2)。这次改进来自复用重叠信息，不是简单把 for 改成 while。

算法 3：左、右、跨边界三种情况

把区间拆成两半，最佳区间要么全在左，要么全在右，要么跨过中线。前两项递归求解，第三项必须是“左半最大后缀 + 右半最大前缀”，不能把左右各自的任意最佳区间直接相加。

原书例子左半：4, −3, 5, −2右半：−1, 2, 6, −2
各自最佳4−3+5=62+6=8
接触中线最大后缀为 4最大前缀为 7
全局比较max(6,8,4+7)=11

原书印刷页 20（PDF 第 37 页）区分了两个量：左半内部的最佳区间是 A1…A3，和为 6；跨中线组合必须接触中线，使用的左半最大后缀是 A1…A4，和为 4。右半最大前缀为 7，所以跨中线候选为 11。下面实现用半开区间，使空数组直接返回 0，也避开原驱动程序 N=0 时生成右端 −1 的问题。

T(N)=T(⌊N2⌋)+T(⌈N2⌉)+Θ(N)=Θ(NlogN).

每一层所有子区间合起来只扫描与 N 同阶的数据，共对数层；叶子总数线性。这个递归树论证不要求 N 是二的幂。

算法 4：为什么负前缀可以永久丢掉？

扫描到 j 时，记录以 j 结尾的最佳非负后缀和 Ej，以及目前的全局最大值 Bj：

Ej=max(0,Ej−1+Aj),Bj=max(Bj−1,Ej).

以 j 结尾的非空区间，要么只有当前数，要么由以 j−1 结尾的区间延长；若延长前的和为负，把这个前缀扔掉只会使后续区间更好。这证明了递推，也解释了为什么无需记住更早的元素。每读一个元素都能给出当前前缀的答案，因而是在线算法；输出长度与元素比较按常数计时，时间 Θ(N)、额外空间 O(1)。

四种可比较的双语实现

返回 long long；调用者保证所有区间和及中间加法不溢出。输入只读，数组由调用者拥有，长度 0 时可以传 NULL。辅助空间均不计输入；第三种额外使用对数调用栈。

C（C11）
#include <stddef.h>
static long long maximum(long long a, long long b) { return a > b ? a : b; }
static long long maxsum1(const int *a, size_t n) {
    long long best = 0;
    for (size_t i = 0; i < n; ++i)
        for (size_t j = i; j < n; ++j) {
            long long sum = 0;
            for (size_t k = i; k <= j; ++k) sum += a[k];
            best = maximum(best, sum);
        }
    return best;
}
static long long maxsum2(const int *a, size_t n) {
    long long best = 0;
    for (size_t i = 0; i < n; ++i) {
        long long sum = 0;
        for (size_t j = i; j < n; ++j) {
            sum += a[j]; best = maximum(best, sum);
        }
    }
    return best;
}
static long long divide_sum(const int *a, size_t lo, size_t hi) {
    if (lo == hi) return 0;
    if (hi - lo == 1) return maximum(0, a[lo]);
    size_t mid = lo + (hi - lo) / 2;
    long long left = divide_sum(a, lo, mid), right = divide_sum(a, mid, hi);
    long long suffix = 0, prefix = 0, sum = 0;
    for (size_t i = mid; i > lo;) {
        sum += a[--i]; suffix = maximum(suffix, sum);
    }
    sum = 0;
    for (size_t i = mid; i < hi; ++i) {
        sum += a[i]; prefix = maximum(prefix, sum);
    }
    return maximum(maximum(left, right), suffix + prefix);
}
static long long maxsum3(const int *a, size_t n) { return divide_sum(a, 0, n); }
static long long maxsum4(const int *a, size_t n) {
    long long suffix = 0, best = 0;
    for (size_t j = 0; j < n; ++j) {
        suffix = maximum(0, suffix + a[j]); best = maximum(best, suffix);
    }
    return best;
}

def maxsum3(a):
    def divide(lo, hi):
        if lo == hi:
            return 0
        if hi - lo == 1:
            return max(0, a[lo])
        mid = lo + (hi - lo) // 2
        left, right = divide(lo, mid), divide(mid, hi)

        total = 0

五、§2.4.4：对数来自规模下降，不来自递归这个词

每步做常数工作、剩余规模缩为原来固定比例，就有对数步。每步只减少 1 则通常线性。两次都处理半个输入再加线性合并，则是 N log N，不是 log N；必须数清有几个分支以及每层的附加工作。

二分查找：预排序、已在内存

有序数组允许由中间元素排除一半。循环不变量是：若目标存在且尚未找到，它只能在当前候选区间。下面统一使用 [lo,hi)；每次都去掉已经比较过的中点，空区间自然终止。返回 n 表示不存在，避免 size_t 里塞 −1。

C（C11）
#include <stddef.h>
#include <stdint.h>
static size_t binary_search(const int *a, size_t n, int x) {
    size_t lo = 0, hi = n;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] < x) lo = mid + 1;
        else if (a[mid] > x) hi = mid;
        else return mid;
    }
    return n;
}
static uint64_t gcd64(uint64_t m, uint64_t n) {
    while (n) { uint64_t r = m % n; m = n; n = r; }
    return m;
}
/* 数学幂参考：调用者保证每个乘积可表示；0^0 按接口约定为 1。 */
static uint64_t power_recursive(uint64_t x, unsigned n) {
    if (!n) return 1;
    if (n == 1) return x;
    if ((n & 1u) == 0) return power_recursive(x * x, n / 2);
    return power_recursive(x * x, n / 2) * x;
}

def binary_search(a, x):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if a[mid] < x:
            lo = mid + 1

def gcd64(m, n):
    if not 0 <= m <= 2**64 - 1 or not 0 <= n <= 2**64 - 1:
        raise ValueError('uint64 inputs required')
    while n:
        m, n = n, m % n
    return m

def power_recursive(x, n):
    if x < 0 or n < 0:
        raise ValueError('nonnegative base and exponent required')
    if n == 0:
        return 1
    if n == 1:
        return x
    result = power_recursive(x * x, n // 2)
    return result if n % 2 == 0 else result * x

二分最坏 O(log(N+1))、额外空间常数；线性读取输入和预排序不能藏进这个查询界。静态数组插入仍可能搬移线性个元素，所以这里已经埋下“查找快不等于更新快”的数据结构议题。

Euclid：余数不必每一步都减半

数学不变量是 gcd(M,N)=gcd(N,MmodN)，因为公共因子整除 M、N 当且仅当整除 N 与它们的余数。例 (1989,1590) 的余数序列为 399、393、6、3、0，答案为 3。399 到 393 显然没减半，不能凭直觉说每轮都缩小一半。

对 M>N>0，若 N≤M2，余数小于 N；否则商为 1，余数 M−N<M2。因此以每两次递推为一组，规模至少减半，模运算次数为 O(log(min(M,N)+1))（初始交换至多多一轮）。定长整数模型下才可把一次 % 视作常数成本。gcd(0,n)=n；代码约定 gcd(0,0)=0。

快速幂：少的是乘法次数

偶数指数把 X 平方、指数减半；奇数指数还要补一次乘 X。以 62 为例，得到的幂次是 2、3、6、7、14、15、30、31、62，共九次乘法。习题 2.15 会给更短的加法链，说明“对数阶”并不等于常数已经最优。

这里每层只有一次子调用。如果改成 Pow(X,N/2)*Pow(X,N/2)，相同子问题做两遍，就有 T(N)=2T(N2)+O(1)=Θ(N)。如果把直接的 X·X 也改成调用 Pow(X,2)，指数 2 的情况又请求自己，甚至无法终止。

六、§2.4.5–§2.4.6：数据能检查分析，但不能替代证明

输入翻倍后，线性、二次、三次时间的主项分别约乘 2、4、8；N log N 略大于两倍；log N 增加的是近似常数。另一个视角是画 T(N)f(N)：模型吻合且主项稳定时应趋于正常数。低阶项、计时粒度、缓存和 IO 可以让有限范围偏离它，因此“看起来平”不是一般证明。

图 2.2 的历史结果显示小规模时分治未必占优，但大规模时三次算法已不可用。表不计输入读取；线性算法的实际瓶颈可能已经在读数据。图 2.12–2.13 又把枚举整数对与 Gcd 放在一起，提醒我们：外层二次枚举内部还有模运算，朴素上界是 O(N2logN)，不能只看两层 for 就结束。

对精确效率有意义的实验，记录输入分布、随机种子、规模、编译器与优化选项；排除或注明生成、分配、打印的时间；重复测量，避免优化器删除没有可见结果的循环。最坏分析与随机输入的平均观测分开解释。

2.1 · 按增长率排序，并指出同阶

原题（中文翻译）

将下列函数按增长率排序，并指出哪些函数具有相同的增长率：

N，N，N1.5，N2，NlogN，NloglogN，Nlog2N，Nlog(N2)，2/N，2N，2N/2，37，N2logN，N3。

原书习题 2.1 · 印刷页 29 · PDF 第 46 页。

解答

固定对数底大于 1，从慢到快为：

2N≺37≺N≺N≺NloglogN≺{NlogN, Nlog(N2)}≺N(logN)2≺N1.5≺N2≺N2logN≺N3≺2N2≺2N.

花括号中两项同阶，因为 log(N2)=2log N；其余相邻项是严格小 o 关系。2N 趋于 0，所以在正常数 37 之前；2N2 与 2N 的比值是 2−N2，不能因同属“指数”就说同阶。Nlog2N 指 N(logN)2。

2.2 · 两个上界能推出什么？

原题（中文翻译）

假设 T1(N)=O(f(N)) 且 T2(N)=O(f(N))。下列哪些命题为真？

  1. T1(N)+T2(N)=O(f(N))。
  2. T1(N)−T2(N)=o(f(N))。
  3. T1(N)/T2(N)=O(1)。
  4. T1(N)=O(T2(N))。

原书习题 2.2 · 印刷页 29 · PDF 第 46 页。

解答

a 真：分别取常数 c1、c2，足够大的 N 时相加得到 T1+T2≤(c1+c2)f。b 假：取 f=N、T1=2N、T2=N，差为 N，不是 o(N)。c、d 也假：取 f=N2、T1=N2、T2=N，两者都为 O(f)，但比值为 N，且 T1 不是 O(T2)。

“它们都不超过同一上界”没有保证它们彼此接近；若改成两者都为 Θ(f)，且分母最终正，才有常数阶比值与相互 O 关系。

2.5 · 找到互不为大 O 的函数

2.7 · 三种随机排列：均匀性、期望及最坏

原题（中文翻译）

  2. 与算法 1 相同，但增加一个数组 Used。随机数 Ran 第一次放入 A 时令 Used[Ran]=1；以后只需一步就能判断这个数是否已使用，而不必像算法 1 那样最多检查 i 项。
  3. 先令 A[i]=i+1，再执行下面的交换循环。
for( i = 1; i < N; i++ )
    Swap( &A[i], &A[RandInt(0, i)] );
  1. 证明三种算法都只生成合法排列，并且所有排列出现的概率相同。
  2. 尽可能准确地分析每种算法的期望运行时间，使用大 O 表示。
  3. 分别编写程序，将每种算法执行 10 次以取得较可靠的平均值。算法 1 使用 N=250、500、1000、2000；算法 2 使用 N=2500、5000、10000、20000、40000、80000；算法 3 使用 N=10000、20000、40000、80000、160000、320000、640000。
  4. 将理论分析与实际运行时间比较。
  5. 每种算法的最坏运行时间是多少？

原书习题 2.7 · 印刷页 30–31 · PDF 第 47–48 页。

解答

a· 为什么概率都是 1N!？

算法 1、2 在已有 i 个不同数时，只接受未使用者；均匀重试使每个剩余数的条件概率恰为 1N−i。逐项相乘得到 1N!，且重复不会接纳。算法 3 是前向 Fisher–Yates：第 i 步把新元素与 0…i 的均匀位置交换。对任一目标排列，目标中新元素的位置唯一确定最后一次交换，剩余 i 项按归纳有唯一的前序安排，所以概率为 1(i+1)!。三种均只生成合法排列。

b· 算法 1 的查重不能当成常数

第 i 阶段成功概率为 N−iN，期望尝试 NN−i，期望失败 iN−i。一次成功扫描 i 个旧数；失败数在 i 个旧位置均匀分布，平均检查 i+12 个。因此期望比较数为

i+iN−ii+12.

求和得 Θ(N2logN)：后半阶段 i 与 N 同阶，主项可下界为 N2 乘一段调和和；所有阶段也可用 N2Hn 上界。算法 2 用布尔表常数判重，期望抽样总次数 ∑i=0N−1NN−i=NHN=Θ(NlogN)，加上线性初始化仍同阶。算法 3 恰做 N−1 次交换，时间 Θ(N)。均匀随机整数原语在本题按常数成本计。

typedef struct { uint64_t state; } PermutationRng;
/* SplitMix64：固定种子用于复现；uint64_t 回绕是发生器的设计。 */
static uint64_t permutation_random_word(PermutationRng *rng) {
    uint64_t z = (rng->state += UINT64_C(0x9e3779b97f4a7c15));
    z = (z ^ (z >> 30)) * UINT64_C(0xbf58476d1ce4e5b9);
    z = (z ^ (z >> 27)) * UINT64_C(0x94d049bb133111eb);
    return z ^ (z >> 31);
}
static size_t permutation_rand_below(PermutationRng *rng, size_t bound) {
    _Static_assert(SIZE_MAX <= UINT64_MAX, "size_t must fit uint64_t");
    if (!bound) abort();
    uint64_t b = (uint64_t)bound;
    uint64_t threshold = (UINT64_C(0) - b) % b, x;
    do { x = permutation_random_word(rng); } while (x < threshold);
    return (size_t)(x % b); /* 先拒绝短余块，避免直接取模的偏差。 */
}
static size_t *permutation_storage(size_t n) {
    if (!n) return NULL;
    if (n > SIZE_MAX / sizeof(size_t)) abort();
    size_t *a = malloc(n * sizeof *a);
    if (!a) abort();
    return a;
}

static size_t *permutation1(size_t n, PermutationRng *rng) {
    size_t *a = permutation_storage(n);
    for (size_t i = 0; i < n; ++i) {
        size_t x, j;
        do {
            x = permutation_rand_below(rng, n) + 1;
            for (j = 0; j < i && a[j] != x; ++j) {}
        } while (j < i);
        a[i] = x;
    }
    return a;
}
static size_t *permutation2(size_t n, PermutationRng *rng) {
    size_t *a = permutation_storage(n);
    if (!n) return a;
    if (n == SIZE_MAX || n + 1 > SIZE_MAX / sizeof(bool)) abort();
    bool *used = calloc(n + 1, sizeof *used);
    if (!used) abort();
    for (size_t i = 0; i < n; ++i) {
        size_t x;
        do { x = permutation_rand_below(rng, n) + 1; } while (used[x]);
        used[x] = true; a[i] = x;
    }
    free(used);
    return a;
}
static size_t *permutation3(size_t n, PermutationRng *rng) {
    size_t *a = permutation_storage(n);
    for (size_t i = 0; i < n; ++i) a[i] = i + 1;
    for (size_t i = 1; i < n; ++i) {
        size_t j = permutation_rand_below(rng, i + 1);
        size_t x = a[i]; a[i] = a[j]; a[j] = x;
    }
    return a;
}

#include <stdint.h>
/* 严格递增的 int 数组；一基结果，0 表示没有固定点。 */
static size_t fixed_point(const int *a, size_t n) {
    size_t lo = 0, hi = n;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        uintmax_t index = (uintmax_t)mid + 1;
        if (a[mid] < 0 || (uintmax_t)a[mid] < index) lo = mid + 1;
        else if ((uintmax_t)a[mid] > index) hi = mid;
        else return mid + 1;
    }
    return 0;
}

原题（中文翻译）

  2. 求最小正子序列和。
  3. 求最大子序列乘积。

原书习题 2.12 · 印刷页 31 · PDF 第 48 页。

解答

a· 最小连续区间和

允许空区间时，把最大和的 max 改成 min：Ej=min(0,Ej−1+Aj)，全局同样取 min。时间 Θ(N)，空间常数；全正输入答案 0。若必须非空，用第一个元素初始化，空输入报错。

b· 最小严格正和，O(NlogN)

设 P0=0, Pj=∑t=1jAt。区间和 Pj−Pi 要严格为正，且 i<j；固定 j 时，应找以前出现的、严格小于 Pj 的最大前缀值。用平衡查找树维护已见前缀即可每步对数。不能将所有前缀排序后无视时间次序取相邻差：输入 [5,−1] 的前缀 0、5、4，差 1 对应逆序前缀，实际最小正和是 4。

static void prefix_merge_sort(long long *a, long long *work,
                               size_t lo, size_t hi) {
    if (hi - lo < 2) return;
    size_t mid = lo + (hi - lo) / 2;
    prefix_merge_sort(a, work, lo, mid);
    prefix_merge_sort(a, work, mid, hi);
    size_t i = lo, j = mid;

static void prefix_add(size_t *tree, size_t m, size_t index) {
    while (index <= m) {
        ++tree[index];
        size_t step = index & ((size_t)0 - index);

        index += step;
    }

static size_t prefix_count(const size_t *tree, size_t index) {

        count += tree[index]; index -= index & ((size_t)0 - index);

    return count;

static size_t prefix_kth(const size_t *tree, size_t m, size_t k) {
    size_t index = 0, step = 1;

            index += step; k -= tree[index];

    return index; /* 第 k 小的压缩值：零基下标。 */

#include <stdint.h>
#include <stdlib.h>

static size_t *sieve(size_t limit, size_t *count) {
    *count = 0;
    if (limit <= 2) return NULL;
    size_t capacity = limit / 2;
    if (capacity > SIZE_MAX / sizeof(size_t)) abort();
    unsigned char *marked = calloc(limit, sizeof *marked);
    size_t *primes = malloc(capacity * sizeof *primes);
    if (!marked || !primes) abort();
    for (size_t p = 2; p <= (limit - 1) / p; ++p)
        if (!marked[p])
            for (size_t multiple = p * p; multiple < limit;) {
                marked[multiple] = 1;
                if (p > limit - 1 - multiple) break;
                multiple += p;
            }
    for (size_t i = 2; i < limit; ++i)
        if (!marked[i]) primes[(*count)++] = i;
    free(marked);
    return primes;
}

  2. 当 N 很小（N<100）时，哪个程序对运行时间提供了更好的保证？

2.19 · 多数元素：配对压缩及奇数处理

原题（中文翻译）

大小为 N 的数组 A 中，出现次数超过 N/2 的元素称为多数元素，因此至多有一个。例如，数组 [3,3,4,2,4,4,2,4,4] 的多数元素是 4，而 [3,3,4,2,4,4,2,4] 没有多数元素。如果不存在多数元素，程序应明确指出。

下面给出一个算法概要。先寻找一个候选多数元素；这是较难的部分，而且这个候选是唯一可能成为多数元素的值。再顺序扫描原数组，检查候选是否确实为多数元素。

寻找数组 A 的候选时，建立第二个数组 B。比较 A1,A2：若相等，将其中一个放入 B，否则什么也不做。再以同样方式比较 A3,A4，一直处理完整个数组。递归寻找 B 的候选，并将其作为 A 的候选——为什么这样做成立？

  1. 递归怎样终止？
  2. 当 N 为奇数时如何处理？
  3. 算法的运行时间是多少？
  4. 怎样避免使用额外数组 B？
  5. 编写一个程序计算多数元素。

原书习题 2.19 · 印刷页 32–33 · PDF 第 49–50 页。

解答

为什么偶数配对不会丢掉真实多数？

把两个相同数压成一份、两个不同数丢弃。若多数值为 M，设 M−M 对有 s 个，非 M 的同值对有 t 个，M-其他对有 d 个，其他异值对有 e 个。多数条件是 2s+d>2t+d+2e，从而 s>t+e≥t。压缩后 M 出现 s 次，所有其他保留值总共 t 次，仍是多数。没有多数的原数组则可能留下一个候选，所以必须回原输入验证。

a 基例 n=0 返回“无候选”，n=1 返回唯一值。b 奇数长度时，先在当前数组检查最后一个值是否为多数；若是直接返回，否则去掉该末项，再处理偶数前缀。若真实多数是别的值，删掉一个非多数不会破坏它。不能盲目把末项附到压缩结果，例如 [M,M,x] 压成 [M,x] 会把真实多数变成平票。

c 每层检查与压缩线性，下一层至多一半：T(N)≤T(⌊N2⌋)+cN=O(N)。d 将保留的配对写到同一工作数组的前缀；写位置始终在已读取的范围内，不覆盖未读输入。若不想破坏原输入，保留一份工作副本供压缩；以下实现最后用原数组核验。Python 也只复制一次输入，后续递归按有效前缀长度压缩，不在每层切片。输入值约定为整数；没有多数时 C 返回 false，Python 返回 None。

def majority(a):

2.20 · 定长整数假设为何重要？

原题（中文翻译）

为什么必须假设计算机模型中的整数具有固定大小？

原书习题 2.20 · 印刷页 33 · PDF 第 50 页。

解答

若允许一个寄存器里放任意多位、加乘除还只算一步，就能把线性甚至更多信息打包到一个“整数”中，把数据搬运和处理伪装成常数时间。这会让模型给出不现实的结论。定长字段使简单算术成本不随数值大小无限增加。

                               const char *const *dictionary, size_t count,
                               BinaryWordMatch emit, void *context) {

    for (size_t r = 0; r < rows; ++r)
        if (strlen(board[r]) != cols) return false;
    for (size_t r = 0; r < rows; ++r)

                            (dc < 0 && !cc) || (dc > 0 && cc == cols - 1)) break;

                        if (dc < 0) --cc; else if (dc > 0) ++cc;

                }

2.25 · 三个计数的组合解释

原题（中文翻译）

最大子序列和的三次算法，其最内层代码执行 N(N+1)(N+2)/6 次；二次算法执行 N(N+1)/2 次；线性算法执行 N 次。这些次数呈现了什么规律？能否从组合计数角度解释这个现象？

原书习题 2.25 · 印刷页 33 · PDF 第 50 页。

线性算法每个端点处理一次，有 (N1)=N 次。二次算法的区间由 0≤i≤j<N 确定，映射成二个严格递增的数 (i,j+1)，可从 0…N 中选两个，得到 (N+12)。

三次算法的加法事件是 0≤i≤k≤j<N，映射为 (i,k+1,j+2)，是从 0…N+1 中选出的三个严格递增数；反向减去相应偏移也唯一。因此

N=(N1),N(N+1)2=(N+12),N(N+1)(N+2)6=(N+23).

一般地，d 个弱递增下标各加 0、1、…、d−1，转成严格递增选择，计数为 (N+d−1d)，主项 Ndd!。三种算法在数不同的事件：元素、区间、区间内的一次元素相加；并非它们枚举了相同对象却有三个不同总数。

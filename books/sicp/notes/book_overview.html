全书的问题：怎样让复杂程序仍然可理解

写出一个能得到答案的小程序，与组织一个可以不断扩展的系统，是两种不同的困难。SICP 从前一种能力出发，反复追问：哪些细节应该藏起来？部件之间凭什么可以组合？当状态、求值顺序和机器资源进入模型时，原来的解释还成立吗？全书的主线是建立、使用并重新检查这些抽象。

第 1 章把计算步骤组织成过程，第 2 章把数据的使用与表示分开，第 3 章研究对象随时间变化所带来的代价。第 4 章进一步把“表达式是什么意思”写成求值器，第 5 章再把求值中的调用、返回和存储落到寄存器、栈与机器指令。前面依赖的能力，逐步成为后面研究的对象。

这条线可以概括为三种设计手段：用抽象控制细节，用约定接口组织组合，用新语言表达问题。这是第一版序言明确提出的方法；下面的章节关系和读法是伴读据此作的归纳。来源：xxii–xxiii / PDF 22–23。

理解与补充

抽象需要一条可检查的边界

“隐藏细节”要同时说明对外保证什么。例如有理数的客户只依赖构造器与选择器，但实现仍须满足数值对应关系。省略一段实现与建立一个可靠抽象并不是同一件事。

五章关系：上一层的假设成为下一层的问题

顺读时依次建立共同语言；回读时可以跨章连线：§1.1.5 的代换模型与 §3.2 的环境模型相对照，§2.3 的符号数据支撑 §4.1 的求值器，§3.5 的流通向 §4.2 的惰性求值与 §4.4 的查询系统，§4.1 的求值器最终在 §5.4 显式化控制。

主线并不意味着所有小节都是同等的前提

第二版序言允许有目的地选读。学习第 5 章求值器，需要理解第 4 章的求值过程；却不必先把非确定性计算与逻辑查询的每个扩展全部做完。顺序、先修和拓展应分别判断。

第 1 章章意 · 用过程构造抽象

Building Abstractions with Procedures；pp.1–106 / PDF 29–134。原书习题 1.1–1.46，共 46 题。

把方法作为可以命名、组合和传递的对象。本章先建立表达式、命名、组合式与复合过程的基本规则，再用代换模型解释过程应用。理解语言的基本构造以后，问题从“写了什么”转向“产生什么样的计算过程”：递归与迭代、树形展开和增长阶，说明外观相近的程序可能具有不同的资源行为。最后用高阶过程捕捉求和、求根、不动点等共同模式。

阅读时抓住两处分离：过程的递归写法与计算过程的空间形态分开；一个具体数值与产生数值的方法分开。Newton 求平方根贯穿逐次改进、黑箱边界和高阶抽象，适合反复回看。

  • §1.1 程序设计的基本要素：p.6 / PDF 34
  • §1.2 过程与它们产生的计算过程：p.40 / PDF 68
  • §1.3 用高阶过程形成抽象：p.74 / PDF 102

理解与补充

递归定义不直接决定空间

同一个数学递推可以由不同控制过程实现。第 1 章先建立对过程形态的直觉；第 5 章才把待续工作、栈与尾递归的关系落成机器操作。

第 2 章章意 · 用数据构造抽象

Building Abstractions with Data；pp.107–293 / PDF 135–321。原书习题 2.1–2.97，共 97 题。

让数据的使用方式不依赖内部表示。有理数例子先划出构造器、选择器与客户程序的边界。序对、列表与树随后说明复合对象如何继续参与组合；序列接口和图形语言把数据抽象与高阶过程接在一起。符号求导、集合与 Huffman 编码把对象从数推广到符号和结构。多重表示、带标记数据、数据导向分派与通用算术，进一步讨论系统扩展时改动应该落在哪里。

不要把本章读成数据结构目录。相同的有理数值可以选择不同化简时机，复数可以采用直角或极坐标表示；真正需要追踪的是客户依赖了哪些操作、每层维持什么约定，以及新类型如何加入已有运算。

  • §2.3 符号数据：p.192 / PDF 220
  • §2.4 抽象数据的多重表示：p.229 / PDF 257
  • §2.5 带通用操作的系统：p.254 / PDF 282

理解与补充

两种“闭包”要按上下文分开

§2.2 的 closure property 是组合结果还能继续参与同种组合的性质；过程捕获其定义环境通常也叫闭包。两者在抽象组织上有关联，但讨论的对象和判断条件不同。

第 3 章章意 · 模块化、对象和状态

Modularity, Objects, and State；pp.294–486 / PDF 322–514。原书习题 3.1–3.82，共 82 题。

把变化引进模型，同时付出时间与共享的代价。局部状态使银行账户等对象能够记住历史，也使同一调用不再总有同一结果。代换模型因此让位于环境模型。可变表、队列、表格、电路模拟器和约束传播，展示对象与交互如何形成模块；并发则揭示读取、计算、写回之间的次序会改变结果。流提供另一种组织方式：把随时间出现的值表示成序列，利用延迟求值分离模拟时间与实际计算次序。

本章同时展示收益和代价。对象模型利于把局部历史封装起来，函数式流模型利于描述整段行为；书末没有宣布其中一种能解决全部问题。阅读时要问清楚：状态属于谁、哪些对象共享它、何时发生强制求值、哪些事件需要同步。

  • §3.1 赋值与局部状态：p.296 / PDF 324
  • §3.2 求值的环境模型：p.320 / PDF 348
  • §3.3 用可变数据建模：p.341 / PDF 369
  • §3.4 并发：时间至关重要：p.401 / PDF 429
  • §3.5 流：p.428 / PDF 456

理解与补充

延迟并不会自动消除时间问题

流的元素可以延后计算，但输入、共享状态和观察时机仍可能影响行为。原书在 §3.5.5 回到这一区分，避免把流简单理解成“没有任何时间问题的列表”。

第 4 章章意 · 元语言抽象

Metalinguistic Abstraction；pp.487–665 / PDF 515–693。原书习题 4.1–4.79，共 79 题。

通过修改求值器研究语言选择。元循环求值器把求值分成表达式分类与过程应用，并用环境连接名字和值；程序的数据表示使这种自我描述成为可能。接着改变求值规则，构造惰性语言与支持搜索、回溯的非确定性语言。逻辑程序设计再把关注点移到关系与查询，同时展示模式匹配、合一、流和搜索顺序如何影响答案的取得。

关键跃迁是：不仅能在一种语言里组织程序，也能设计更适合问题的语言。要分别辨认被解释的语言与实现解释器的宿主语言；非确定性选择不是随机抽样，逻辑查询的声明含义也不自动保证操作过程会终止。

  • §4.1 元循环求值器：p.492 / PDF 520
  • §4.2 Scheme 的变形：惰性求值：p.541 / PDF 569
  • §4.3 Scheme 的变形：非确定性计算：p.559 / PDF 587
  • §4.4 逻辑程序设计：p.594 / PDF 622

理解与补充

元循环仍留下宿主提供的机制

用 Scheme 写 Scheme 求值器，并没有从无到有解释全部计算。控制转移、基本操作与存储仍由宿主承担；第 5 章正是把其中一些依赖进一步展开。

第 5 章章意 · 寄存器机器里的计算

Computing with Register Machines；pp.666–833 / PDF 694–861。原书习题 5.1–5.52，共 52 题。

让控制、存储与编译都成为可观察的过程。先从最大公约数等过程设计数据通路与控制器，再用模拟器执行寄存器机器描述。存储部分解释序对如何映射为向量式内存，以及垃圾回收如何支持不断产生新对象。显式控制求值器把第 4 章的求值过程改写为寄存器与栈操作；编译器则直接生成指令序列，并处理目标寄存器、连接方式、词法地址与编译代码/解释执行的衔接。

本章让开头的疑问闭合：过程调用返回到哪里？哪些值必须暂存？尾调用为何不需要累计相同的返回工作？解释与编译之间哪些工作可以提前完成？原书使用教学寄存器机器，不对应某一款 CPU 的完整指令集。

理解与补充

语义相同与成本相同是不同的主张

解释执行与编译执行可以产生相同结果，却经过不同的指令、查找和栈操作。第 5 章的机器模型让这些成本有了具体含义，不能把教学模型的计数直接当作本机 CPU 的时间。

沿同一条表达式，辨认四个解释层次

下面按原书出现的先后列出求值模型。它们逐渐暴露原来被隐藏的机制；后一层的引入有明确的问题背景。表中的比较是伴读归纳，不是四种互不相关的编程语言。

求值模型逐层回答的问题
层次能帮助看清什么暂时隐藏什么原书入口
代换模型把实参带入过程体，追踪表达式的求值赋值、位置和共享对象的机制§1.1.5 / PDF 46
环境模型名字在什么框架中绑定，局部状态如何保留宿主怎样调用、返回及管理机器资源§3.2 / PDF 348
元循环求值器把语言求值规则写成可修改的程序宿主调用机制与底层存储§4.1 / PDF 520
显式控制求值器控制状态、寄存器、栈与返回位置教学机器所假定的基本操作内部细节§5.4 / PDF 769

遇到“为什么结果如此”，先找当前模型承诺解释的那一层。遇到“为什么占用这些空间”，则要继续说明成本单位与实现条件。这也解释了为什么第 1 章可以先使用抽象过程，而不必等待第 5 章的机器设计。

理解与补充

更具体的模型仍有边界

寄存器机器不是对硬件、物理时间和全部系统调用的最终说明。它只把本书所需的控制与存储机制具体化；每次下移一层，都应写清又把哪些操作当作基本操作。

怎样开始、选读与回读

先读引言：前言与两版序言，再顺着第 1、2 章建立共同基础。每读一个例子，先预测表达式的结果或下一步状态，再沿规则手算。对于过程，要能说出输入、输出和产生的计算过程；对于数据，要能说出接口及表示约定。会抄出定义之后，还要检查改变一个条件会发生什么。

到第 3 章，把环境框架、共享对象和事件次序画出来；从“同一个输入”推进到“此前发生过什么”。再进入第 4 章，选一条表达式追过求值和应用两条路径。第 5 章则追踪相同过程在寄存器和栈中的实现。这样读，每次都会带着前一章尚未回答的问题进入下一章。

第二版序言说明一学期难以覆盖全部内容，提到可选略 §4.4 的逻辑程序设计、使用 §5.2 模拟器而暂不研究其实现、仅概览 §5.5 编译。这是作者的课程取舍说明；自学时也可以先读前三章或前四章，再回到机器与编译。来源：xx / PDF 20。

若已读本仓库的 EOPL，可以比较两书怎样用解释器揭示语言机制：SICP 的主线从构造抽象走到语言和机器，EOPL 则围绕一系列小语言展开状态、控制、类型等选择。这里的比较用于安排回读，不能把两书的语法、对象表示和求值规则混用。

理解与补充

用可以回答的问题决定是否继续

学完一个小节后，试着不用运行程序也能预测一个小输入，再运行验证并解释差异。如果结果只是记住某种写法，就回到模型或接口；若已能推演，就可以暂时让底层细节留在下一层。

本页之后怎样使用原书

这份伴读目前提供全书地图与引言两页。五章的正式笔记和习题解答尚在计划中；上面的五个节点是章意入口，各节旁的 PDF 链接可以直接进入本仓库原书阅读。不要将章意摘要当作完整章节。

本批没有另附程序，也没有宣称运行原书解释器、模拟器或编译器。原书以 Scheme 表达程序；读到程序时先辨认语言规则、原书约定与实现专用功能。语言环境与可运行示例将在相应章节展开时集中说明。

可从这里进入 原书目录（PDF 3）、习题列表（PDF 872）、图表列表（PDF 874）和术语索引（PDF 876）。习题列表覆盖全书 356 道原题，不表示本伴读已有这些题的解答。

第八章：不相交集（并查集）

把动态等价关系组织成森林：从代表元的选择、树高控制与路径压缩，走到整个操作序列的摊还成本，再用连通、撤销、删除和最近公共祖先检验这些条件。

一、§8.1–8.2：要维护的是等价类的划分

前面的查找树和散列表用键定位对象；这一章要判断两个对象是否属于同一组。若关系具有自反性、对称性和传递性，它就把全集划分成互不相交的等价类。每个对象只在一个类里，两个类要么相同，要么完全不交。原书的电路连通、同一国家以及双向道路，都是从具体关系进入这一抽象的例子。

自反性保证每个对象与自己相关；对称性允许交换查询的两个对象；传递性允许把局部连接累积成整个类。数的“小于等于”缺少对称性，因此不能直接用并查集维护。单向可达关系也不满足对称性；把有向图的一条边直接当作合并操作，会丢掉方向。

接口只有两个核心动作：Find 返回对象所在类的名字，比较两个名字就能判断关系；Union 把两个不同的类合并。初始时每个对象独占一个类。新关系逐条到达，前一次操作的结果会影响后一次查询，所以作者强调在线处理；把全部输入事先排序再回答，是另一种问题设置。

最直接的二维关系表需要 Θ(N2) 空间。另一种表示是为每个对象保存类号：Find 为 O(1)，但合并后要改写一整组类号。若同时保存成员链表，总把较小组的成员改为较大组的名字，一个对象每次被改号后所在组至少翻倍，因此它最多改号 ⌊log2N⌋ 次。全部合并只需 O(NlogN) 改写，加上 F 次查询，总时间为 O(N+NlogN+F)。

这已经把逐次扫描全集的代价降下来了。接下来作者进一步利用一个自由度：用户需要的是等价类是否相同，代表元的具体编号可以由实现选择。实际对象名可先借助第七章的散列表编号为 1,…,N；本章的数组只处理这些稠密整数编号。

二、§8.3：用森林延迟改写整组成员

把每个类组织成一棵有根树，根就是类的名字。非根对象保存父亲，Find 沿父指针向上走；合并只需要让一个根成为另一个根的孩子，原来指向它的所有成员都会自然归入新类。图 8.1–8.5 先合并 5、6，再合并 7、8，最后把根 7 接到根 5 下，形成下面的森林。

原书用根项不大于 0 表示根，正数表示父亲编号。图 8.8 的 SetUnion 假设参数已经是两个不同的根，因此只改一次指针，时间为 O(1)。若对外接口接收任意两个元素，必须先做两次 Find；这部分代价也应计入 Union。重复合并同一类时保持划分不变，并且不减少类数。

任意合并可以把第二个根接到第一个根下。连续执行 Union(2,1)、Union(3,2)、……，便把森林拉成一条链，Find(1) 最坏要走 N−1 条边。把状态放进数组只降低了表示成本，并没有自动控制树高。原书讨论“随机合并”的几种模型，也是在提醒：均匀选择两个类，与均匀选择两个元素，会给大类不同的被选中概率，平均时间必须附带输入模型。

下面的共享实现把根表示为 parent[x] == x，并把成员数、秩分别保存在数组中，便于同一份程序比较各种策略。它与原书把负数信息嵌入根项的表示等价。相同大小或秩时，第一个参数所属的根获胜；任意合并也采用这一规则。C 的数组由结构拥有，释放函数回收它们；分配失败或越界输入使程序报错退出，Python 对应抛出异常。两版都限制 0≤N≤106，有效对象编号为 1…N；空全集可建立，但没有可查询的对象。

   compression: 0 = none; 1 = full; 2 = halving. */
typedef struct {
    int n, rule, compression, components;
    int *parent, *size;
    unsigned *rank;
    uint64_t hops, writes;
} DSU;
static DSU d_new(int n, int rule, int compression) {
    if (n < 0 || n > 1000000 || rule < 0 || rule > 2 ||
        compression < 0 || compression > 2) fail("bad DSU parameters");
    DSU d = {n, rule, compression, n, NULL, NULL, NULL, 0, 0};
    size_t cap = (size_t)n + 1;
    d.parent = alloc(cap, sizeof *d.parent);
    d.size = alloc(cap, sizeof *d.size);
    d.rank = alloc(cap, sizeof *d.rank);
    for (int i = 1; i <= n; ++i) { d.parent[i] = i; d.size[i] = 1; }
    return d;
}
static void d_free(DSU *d) {
    free(d->parent); free(d->size); free(d->rank);
    *d = (DSU){0};
}
static int d_halve(DSU *d, int x);
static int d_find(DSU *d, int x) {
    vertex(d->n, x);
    if (d->compression == 2) return d_halve(d, x);
    int r = x;
    while (d->parent[r] != r) { r = d->parent[r]; ++d->hops; }
    if (d->compression == 1) {
        while (d->parent[x] != x) {
            int next = d->parent[x];
            if (next != r) { d->parent[x] = r; ++d->writes; }
            x = next;
        }
    }
    return r;
}
static bool d_union(DSU *d, int a, int b) {
    a = d_find(d, a); b = d_find(d, b);
    if (a == b) return false;
    if ((d->rule == 1 && d->rank[a] < d->rank[b]) ||
        (d->rule == 2 && d->size[a] < d->size[b])) {
        int t = a; a = b; b = t;
    }
    d->parent[b] = a; ++d->writes;
    d->size[a] += d->size[b];
    if (d->rule == 1 && d->rank[a] == d->rank[b]) ++d->rank[a];
    --d->components;
    return true;
}

class DSU:
    # rule: 0 = first root, 1 = rank, 2 = size
    # compression: 0 = none, 1 = full, 2 = halving
    def __init__(self, n, rule=1, compression=1):
        if not 0 <= n <= 1000000 or rule not in (0, 1, 2) or compression not in (0, 1, 2):
            raise ValueError('bad DSU parameters')
        self.n, self.rule, self.compression = n, rule, compression
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)
        self.rank = [0] * (n + 1)
        self.components = n
        self.hops = self.writes = 0

    def find(self, x):
        vertex(self.n, x)
        if self.compression == 2:
            return halve(self, x)
        r = x
        while self.parent[r] != r:
            r = self.parent[r]
            self.hops += 1
        if self.compression == 1:
            while self.parent[x] != x:
                nxt = self.parent[x]
                if nxt != r:
                    self.parent[x] = r
                    self.writes += 1
                x = nxt
        return r

    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            return False
        if (self.rule == 1 and self.rank[a] < self.rank[b] or
                self.rule == 2 and self.size[a] < self.size[b]):
            a, b = b, a
        self.parent[b] = a
        self.writes += 1
        self.size[a] += self.size[b]
        if self.rule == 1 and self.rank[a] == self.rank[b]:
            self.rank[a] += 1
        self.components -= 1
        return True

Find 使用迭代，因此链的长度不会转化成语言递归栈深。完整压缩先找根，再沿原路径改写父亲；必须先保存旧父亲才能继续。compression=2 调用习题 8.14 的路径减半函数。hops 记录找根阶段跨过的父边数，完整压缩的第二遍不重复计入；writes 只计实际改变的父指针，包括根的链接。它们是解释工作量的计数，CPU 时间还包含第二遍遍历和元数据更新。

三、§8.4：限制树高，控制一次查找的代价

按大小合并始终把小树挂到大树。一个对象的深度只有在它所在的整棵树被挂到另一棵树下时才增加；此时新树至少是旧树的两倍。从大小 1 出发，深度增加 d 次后，所在类至少有 2d 个对象。于是任何对象的深度至多 ⌊log2N⌋。

原书把根项设为成员数的负值，初始化为 −1；合并时把两个负值相加，再让小根保存大根的编号。成员数是类的真实基数，路径压缩不会改变它。每次对外 Union 或 Find 最坏花 O(logN)，初始化另需 Θ(N)；已知两个根的链接仍为常数时间。

按高度合并保留较高的根。高度不同时，小树挂到大树后不会增加整体高度；高度相同时，合并后的高度加一。要形成高度 h，至少要合并两棵高度 h−1 的树，因而也至少需要 2h 个对象。图 8.12 的 16 个节点、深度 4 的二项树，正是不断合并等高树得到的最坏形状；从 16 个单例组成它需要 15 次成功合并。印刷页 272 写“16 次 Unions”，应按图中的节点数和成功合并数理解。

四、§8.5：压缩查找路径以后，高度变成秩

即使链接策略已经限制树高，对同一路径的重复查找仍会反复付费。完整路径压缩在找到根后，把整条查找路径上的节点都直接挂到根下。以后访问这些节点只需一条父边；不在路径上的节点也可能因为它的祖先被抬高而受益。压缩的效果积累在整个操作序列上。

图 8.12 中最深的 16 沿 16→15→13→9→1 找根。图 8.14 查询的是 15，因此只把 15、13 的父亲改为 1；9 已经直连根。16 并未被直接访问，但它的路径缩短为 16→15→1。这个例子说明，应准确区分“被改写的节点”和“得到间接好处的节点”。

按大小合并依然保存准确的成员数。按高度合并却不再能把原来的计数称为实际高度：压缩会降低树高，若试图每次重新计算真实高度，便会重新扫描整棵树。作者选择保留过去的高度估计，称为 rank（秩）。压缩时不降低秩；只有两个等秩根合并时，获胜根的秩加一。

秩保存的是合并历史提供的平衡证据，仍然是当前高度的上界。父亲的秩严格大于孩子的秩，压缩只是把父亲换成秩更大的祖先，因此这个性质继续成立。单次 Find 仍可能走对数条边；接下来的更强结论说明的是最坏操作序列的总时间，即摊还界。

五、§8.6：为什么总成本接近线性

作者先给出更强的逆 Ackermann 界，再完整证明较弱、较容易追踪的迭代对数界。本版采用下面的函数定义；对不同书里的“α”比较数值时，必须先核对基例、取整和参数顺序。以下对数均以 2 为底，M≥N≥1。

A(1,j)=2j (j≥1),A(i,1)=A(i−1,2) (i≥2)
A(i,j)=A(i−1,A(i,j−1)) (i,j≥2)
α(M,N)=min{i≥1:A(i,⌊M/N⌋)>log2N}

并查集的逆 Ackermann 时间界

按秩或按大小合并，结合完整路径压缩，M 次操作的总时间为 O(Mα(M,N))，初始化为 Θ(N)。在通常可表示的规模内，α 是很小的数；作为无界函数，它仍会增长，不能在数学上把它删掉。这个更强的定理来自本章参考文献 [15]、[18]；习题 8.5 使用它的条件与定义，下面则复现原书 §8.6.1 的计账证明。

log*N 定义为重复取对数直到结果不大于 1 所需的次数。例如 65536→16→4→2→1，因此 log*65536=4。印刷页 275 把它称为“单变量逆 Ackermann 函数”，这个称呼容易误导：迭代对数与逆 Ackermann 函数是两个不同函数。这里分别使用 log*N 和 α，保留两种时间界各自的证明范围。

证明：路径压缩的分组计账

固定合并历史，先得到三个计数事实

把全部成功链接记录成一棵“参考森林”：它保留节点第一次成为非根时的父亲，忽略 Find 的压缩。节点的最终秩沿参考父边严格增加；一个最终秩为 r 的节点，其参考子树至少有 2r 个节点，这是由两个等秩根合并的归纳得到的。压缩后的实际子树可能变小，这里使用的是参考子树。

最终秩都为 r 的节点不可能互为祖先，所以它们的参考子树互不相交，数量至多 N/2r。因此最大秩不超过 ⌊log2N⌋。实际父指针始终指向参考森林的祖先；整个序列中每条实际父边也满足最终秩严格增加。用最终秩分析，避免把中途仍可能增长的根秩当成固定量。

把一次路径访问分摊到查找和节点

令第 0 组只有秩 0；第 g≥1 组包含秩 F(g−1)+1 到 F(g)。对每次 Find，把根、根的直接孩子以及父子秩跨组的节点计入“本次查找账”；其余节点计入“该节点账”。沿路径秩严格增加，跨组至多发生 G 次，因此一条路径记入查找账的次数至多 G+2。

若节点 v 被记入节点账，它的父亲不是根且与它同组。完整压缩会把父亲换成更高秩的根，父亲秩严格上升。只要父亲还在第 g 组，旧父亲秩就只能占用该组的有限个整数；离开这组后，v 再次被访问会归入查找账。故一个第 g 组节点最多承担 F(g)−F(g−1) 次节点账。

Vg≤∑r=F(g−1)+1F(g)N2r≤N2F(g−1)

这组的总节点账至多 NF(g)/2F(g−1)。选择 F(0)=0、F(g)=2F(g−1)，每组的上界就成为 N；边界依次是 0、1、2、4、16、65536、……。覆盖全部秩需要 G=O(1+log*N) 组。

T≤c[N+U+Ffind(G+2)+NG]=O((N+M)(1+log*N))

这里 U≤N−1 是成功根链接数，Ffind 包含对外 Union 内部调用的 Find，且 Ffind=O(M)。完整压缩的两遍只差常数因子。若 M=Ω(N) 且 N≥2，得到原书证明的 O(Mlog*N)。分析没有假设随机输入，也没有把实验速度当成证明。

六、§8.7：每读入一条边，就更新连通分量

计算机之间的双向连接构成无向图。初始化每台计算机为单独一类；每收到一条边 (u,v)，查询两个端点的根，若不同就合并。归纳不变量是：两个点同类，当且仅当它们在已经读入的边构成的图中连通。新边或者完全落在同一分量内，或者恰好连接两个分量，正好对应两种更新。

再维护一个分量数，初始为 N，每次成功合并减一。计数成为 1 时整个非空网络已经连通；单点网络在读边前就连通。自环和重复边不会改变计数。若有 E 条边，包括初始化的时间可以写为 O((N+E)α(N+E,N))，空间为 O(N)。E<N 时不能省略初始化，也不能直接把本版要求 M≥N 的 α 套到 M=E。

本页的更新函数返回网络是否整体连通，并让驱动在每条边之后输出当前分量数。它引用共享 DSU，两版均逐条处理输入。删除一条边可能把一个分量拆成两个，此时仅保存类归属不足以恢复图的路径信息。习题 8.9 的 Remove 是把一个对象移到单例类，语义也与删图边不同。

8.4 · 按高度合并的深度界

原题（中文翻译）

证明：若合并按高度进行，则任何树的深度都是 O(logN)。

本版习题 8.4；印刷页 282／PDF 第 299 页。

解答

对根高度 h 归纳证明成员数至少 2h。初始单例高度 0、成员数 1。合并不同高度的两棵树，较高树高度不变，成员数只增不减；合并同高度 h 的两棵树，新的高度为 h+1，成员数至少 2h+2h=2h+1。不变量成立，因此 2h≤N，即 h≤⌊log2N⌋。

若随后加入路径压缩，这个计数改称秩，压缩不增加任何节点深度。因此实际深度仍不超过秩，以上对数上界继续成立。证明限制的是单次最坏路径长度，未使用摊还分析。

  1. 证明：若 M=N2，则 M 次 Union／Find 操作的运行时间为 O(M)。
  2. 证明：若 M=NlogN，则 M 次 Union／Find 操作的运行时间为 O(M)。
  3. （*）设 M=Θ(NloglogN)，M 次 Union／Find 操作的运行时间是多少？
  4. （*）设 M=Θ(Nlog*N)，M 次 Union／Find 操作的运行时间是多少？

本版习题 8.5；印刷页 282／PDF 第 299 页。

解答

使用 §8.6 的前提：按秩／大小合并并做完整压缩，M≥N；把初始化计入总成本。令 q=⌊M/N⌋，由 α 的定义，只要为每一项找出与 N 无关的 Ackermann 层数上界即可。c、d 的扫描页都是 Θ，允许正的常数因子，因此不能把 q 直接换成恰好相等的表达式。

  1. q=N，且 A(1,q)=2N>logN。故 α=1，总时间 O(M)。
  2. q=⌊logN⌋，故 A(1,q)≥N/2>logN 对充分大的 N 成立；有限的小规模只改变常数。仍有 O(M)。
  3. 令 L=loglogN，存在常数 c>0 使充分大时 q≥cL。A(2,q) 是高度 q+1 的 2 的幂塔；对 q≥2 有 A(2,q)≥22q。因为 2q≥(logN)c，而 (logN)c 最终大于 loglogN，所以 A(2,q)>logN，得到 α≤2。
  4. 令 L=log*N，则 q≥cL。A(3,q)=A(2,A(3,q−1)) 是高度 A(3,q−1)+1 的幂塔；A(3,q−1)≥2q−1。高度至少 2cL−1，充分大时超过 L+1，而 logN 的迭代对数不超过 L。因此 A(3,q)>logN，得到 α≤3。

四项都为 Θ(M)：上界如上，下界来自必须处理 M 条操作。若只使用书中较弱的 O(Mlog*N)，不能直接完成这一题的线性结论；这里需要先陈述的逆 Ackermann 定理。

8.8 · 撤销合并：从回滚到路径减半

原题（中文翻译）

（*）设增加一个操作 Deunion，用来撤销尚未撤销的最近一次 Union。

  1. 证明：若按高度合并，且 Find 不做路径压缩，则 Deunion 很容易实现，M 次 Union、Find 和 Deunion 操作总共花 O(MlogN) 时间。
  2. 为什么路径压缩会使 Deunion 变难？
  3. （**）说明怎样实现所有操作，使 M 次操作总共花 O(MlogN/loglogN) 时间。

本版习题 8.8；印刷页 282／PDF 第 299 页。

解答

a．只保存成功链接的常数份历史

本题的 Union 合并两个不同的类。实现若收到同类参数，返回 false，并且不压入撤销栈；Deunion 撤销最近一次成功合并，空栈返回 false。先 Find 两个根，按秩链接，记录被挂接的根、获胜根、获胜根原有的秩及大小。Find 不改父数组，撤销时恢复这几项即可。栈中最多 N−1 条仍生效的链接，空间 O(N)。

原先的合并归纳在任何撤销后都恢复成立，所以 Find 始终最坏 O(logN)。已知根的链接与撤销均为 O(1)；按元素调用 Union 需两次 Find。含初始化的总时间为 O(N+MlogN)，当 M=Ω(N) 且 N≥2 即为题设的界。

C（C11）
typedef struct { int child, root, old_size; unsigned old_rank; } Change;
typedef struct { DSU d; Change *log; int used; } Rollback;
static Rollback rb_new(int n) {
    Rollback r = {d_new(n, 1, 0), alloc((size_t)n, sizeof(Change)), 0};
    return r;
}
static bool rb_union(Rollback *r, int a, int b) {
    a = d_find(&r->d, a); b = d_find(&r->d, b);
    if (a == b) return false;
    if (r->d.rank[a] < r->d.rank[b]) { int t = a; a = b; b = t; }
    r->log[r->used++] = (Change){b, a, r->d.size[a], r->d.rank[a]};
    r->d.parent[b] = a;
    r->d.size[a] += r->d.size[b];
    if (r->d.rank[a] == r->d.rank[b]) ++r->d.rank[a];
    --r->d.components;
    return true;
}
static bool rb_undo(Rollback *r) {
    if (!r->used) return false;
    Change c = r->log[--r->used];
    r->d.parent[c.child] = c.child;
    r->d.size[c.root] = c.old_size;
    r->d.rank[c.root] = c.old_rank;
    ++r->d.components;
    return true;
}
static void rb_free(Rollback *r) { free(r->log); d_free(&r->d); }

class Rollback:
    def __init__(self, n):
        self.d = DSU(n, 1, 0)
        self.log = []

    def union(self, a, b):
        d = self.d
        a, b = d.find(a), d.find(b)
        if a == b:
            return False
        if d.rank[a] < d.rank[b]:
            a, b = b, a
        self.log.append((b, a, d.size[a], d.rank[a]))
        d.parent[b] = a
        d.size[a] += d.size[b]
        if d.rank[a] == d.rank[b]:
            d.rank[a] += 1
        d.components -= 1
        return True

    def undo(self):
        if not self.log:
            return False
        b, a, old_size, old_rank = self.log.pop()
        self.d.parent[b] = b
        self.d.size[a], self.d.rank[a] = old_size, old_rank

b．压缩会跨过后来需要切开的合并边

合并 1、2，合并 3、4，再把根 3 挂到根 1 下，此时 4→3→1。Find(4) 压缩成 4→1。撤销最近一次合并若只把 3 改回根，4 仍错误地归在 1 的类里。必须恢复或者识别这条跨过已撤销链接的快捷指针。

把所有压缩改写也记入普通回滚日志，虽能保证正确，却达不到 c 的界：先建立深度 logN 的二项树，反复“找最深节点→撤销最后一次合并→重做该合并”。完整压缩产生的所有直达根指针依赖最后那条合并边，每次都被撤销；每个三步循环重新付出 Θ(logN)。

c．按大小合并、路径减半与指针版本栈

采用 Westbrook–Tarjan 的及时清除方式：每个节点保存一个出边栈 P(x)，底层为参考森林的合并边，上层为减半创建的快捷边；每条快捷边记录它依赖的那次 Union。每条 Union 另保存自己创建或使之有效的快捷边列表。Find 读取栈顶边 x→y；若 y 还有父边 y→z，给 P(x) 压入 x→z，归属为 y→z 的 Union，然后从 z 继续。它是路径减半，而不是把整条路径直连根。

依赖的意义是：这条边的目标 z 在参考森林中，哪一次 Union 首先把通往 z 的最后一个分支接到 z 下。x→y 与 y→z 拼接时，x→z 的依赖就是后者的依赖，因此无需扫描参考森林。Deunion 按反向创建顺序弹出该 Union 的全部指针，恢复获胜根的大小；较早的快捷边继续留在各自栈里。栈顶总是当前有效的最远祖先。后创建且依赖更晚合并的边先被撤销，因此清除列表中的指针时，它必在该节点的栈顶。

C（C11）

static Eager e_new(int n) {
    if (n < 0 || n > 1000000) fail("bad N");
    Eager e = {n, 0, alloc((size_t)n + 1, sizeof(int)),
               alloc((size_t)n + 1, sizeof(EPointer *)),
               alloc((size_t)n, sizeof(EUnion))};
    for (int i = 1; i <= n; ++i) e.weight[i] = 1;
    return e;
}
static void e_push(Eager *e, int x, int y, EUnion *u) {
    EPointer *p = alloc(1, sizeof *p);
    *p = (EPointer){x, y, e->top[x], u->head, u};
    e->top[x] = p; u->head = p;
}
static int e_find(Eager *e, int x) {
    vertex(e->n, x);
    while (e->top[x]) {
        EPointer *p = e->top[x];
        int y = p->to;
        if (e->top[y]) {
            EPointer *q = e->top[y];
            int z = q->to;
            e_push(e, x, z, q->owner);
            x = z;
        } else x = y;
    }
    return x;
}
static bool e_union(Eager *e, int a, int b) {
    a = e_find(e, a); b = e_find(e, b);
    if (a == b) return false;
    if (e->weight[a] < e->weight[b]) { int t = a; a = b; b = t; }
    EUnion *u = &e->log[e->used++];
    *u = (EUnion){b, a, e->weight[a], NULL};
    e_push(e, b, a, u);
    e->weight[a] += e->weight[b];
    return true;
}
static bool e_undo(Eager *e) {
    if (!e->used) return false;
    EUnion *u = &e->log[e->used - 1];
    EPointer *p = u->head;
    while (p) {
        EPointer *next = p->next_owner;
        if (e->top[p->from] != p) fail("pointer-stack invariant failed");
        e->top[p->from] = p->previous;
        free(p); p = next;
    }
    e->weight[u->root] = u->old_weight;
    --e->used;
    return true;
}
static void e_free(Eager *e) {
    while (e_undo(e)) { }
    free(e->weight); free(e->top); free(e->log);
}

class Eager:
    def __init__(self, n):
        if not 0 <= n <= 1000000:
            raise ValueError('bad N')
        self.n = n
        self.weight = [1] * (n + 1)
        self.top = [None] * (n + 1)
        self.log = []

    def push(self, x, y, owner):
        # A pointer = [from, to, previous_on_node, next_for_union, owner].
        p = [x, y, self.top[x], owner[3], owner]
        self.top[x] = p
        owner[3] = p

    def find(self, x):
        vertex(self.n, x)
        while self.top[x] is not None:
            p = self.top[x]
            y = p[1]
            if self.top[y] is not None:
                q = self.top[y]
                z = q[1]
                self.push(x, z, q[4])
                x = z
            else:
                x = y
        return x

    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            return False
        if self.weight[a] < self.weight[b]:
            a, b = b, a
        owner = [b, a, self.weight[a], None]
        self.log.append(owner)
        self.push(b, a, owner)
        self.weight[a] += self.weight[b]
        return True

    def undo(self):
        if not self.log:
            return False
        owner = self.log.pop()
        p = owner[3]
        while p is not None:
            nxt = p[3]
            if self.top[p[0]] is not p:
                raise RuntimeError('pointer-stack invariant failed')
            self.top[p[0]] = p[2]
            p[2:] = [None, None, None]  # release cross references
            p = nxt
        self.weight[owner[1]] = owner[2]
        owner[3] = None
        return True

给出时间证明。记参考子树大小为 s(x)，ℓ(x)=⌊log2s(x)⌋。按大小合并保证沿参考父边 ℓ 严格增加，范围为 0 到 ⌊logN⌋。取固定 0<c<1，设 b=cloglogN；新指针 x→y 的级差大于 b 称长，否则称短。

指向根的指针，每次操作至多常数条，计入该操作。非根长指针计入创建它的 Find；减半产生的边组成一条向根的路径，级差总和至多 logN，故每个 Find 至多承担 O(logN/b) 条。非根短指针计入“使目标 y 最近成为非根”的那次 Union。在这次 Union 生效期间，y 的参考子树固定；每个后代 x 至多产生一次归于它的 x→y。再次越过 y 后，快捷父亲已在 y 之上；要重新返回到这一阶段必须先撤销这次 Union。

与 y 的级差至多 b 的后代，按级别 i 的子树互不相交计数，数量不超过 ∑i=ℓ(y)−⌊b⌋ℓ(y)s(y)/2i=O(2b)。因此每次 Union 至多承担 O((logN)c) 条短指针，而 (logN)c=O(logN/loglogN)。每条指针创建一次、销毁一次，所有清除工作也随创建摊还。

T=O(N+M[1+logNloglogN])

对 M=Ω(N)、充分大 N，得到所求时间界；小 N 的操作按常数处理。上述完整实现的空间为 O(NlogN)：每个节点的指针栈只指向参考路径上互异的祖先，路径长为对数。若要求线性空间，可仅从参考子树大小至少 logN 的首个节点开始减半，前面未压缩段只有 O(loglogN) 长；会生成快捷边的节点数为 O(N/logN)，每个至多保存 O(logN) 条。程序采用完整指针栈版本。

8.9 · 把一个对象移到单例类

原题（中文翻译）

（*）设增加操作 Remove(X)，从 X 当前所在的集合中移走 X，并把它放入自己的单元素集合。说明如何修改 Union／Find，使 M 次 Union、Find、Remove 操作的总时间为 O(Mα(M,N))。

本版习题 8.9；印刷页 283／PDF 第 300 页。

解答

不能直接把 X 的父项改成根：如果 X 是别人的祖先，那些成员也会跟着被拆走。把逻辑对象编号与物理树节点分开，使用 id[X] 定位 X 当前的代理。Remove 先查询旧根，减去它的活成员数，再为 X 建立新物理单例，并改 id[X]；旧节点留在森林里作为不含对象的代理。这样每次只改变 X 的归属，即使被移走的是根，也不会改变其他对象的路径。

合并按物理权重进行，权重包含尚在森林里的旧代理，并在 Remove 时保持不变；真实活成员数另存。若拿减小后的活成员数当作平衡证据，历史的倍增论证会失效。集合名可以是物理根编号，调用者比较名字是否相等；Remove 或重建后，不应把旧名字缓存为永久身份。

复杂度参数校注：普通并查集定理中的 N 计入所有 MakeSet 创建的节点。若不断建立新代理，设初始对象数为 N0、实际新建次数为 R，则节点参数应为 K=N0+R；不能仅因活对象始终是 N0，就把 K 换回 N0。题干的 α 写法需要同时说明这个计数范围。

不回收代理的直接方案是一个只做 MakeSet／Union／Find 的普通并查集，共 K 次建单例、至多常数倍 M 次查询与链接。令 T=Θ(N0+M) 为展开后的基本操作数，得到 O(Tα(T,K)) 时间、O(K) 空间；当用 N 表示累计物理节点、基本操作数满足 T=Ω(N) 时，就是题干所用的逆 Ackermann 形式。Remove 已完整归约为常数次已有操作，不需要恢复历史合并。

下面给出适合固定活对象数的有界空间版本：最多保留 2N0 个物理节点，累计新建 N0 个代理后重建。先在不再链接的旧森林里对所有物理节点做完整 Find，依习题 8.11 为线性；随后按每个活对象的旧根分组，以组内首个活编号为新根，直接建立星形树。每次重建 O(N0)，由上一个阶段的 N0 次新建付费。

C（C11）
typedef struct { int n, used; int *parent, *weight, *live, *id; } Removable;
static Removable rm_new(int n) {
    if (n < 0 || n > 1000000) fail("bad N");
    size_t cap = 2 * (size_t)n + 1;
    Removable r = {n, n, alloc(cap, sizeof(int)), alloc(cap, sizeof(int)),
                    alloc(cap, sizeof(int)), alloc((size_t)n + 1, sizeof(int))};
    for (int i = 1; i <= n; ++i) {
        r.parent[i] = i; r.weight[i] = r.live[i] = 1; r.id[i] = i;
    }
    return r;
}
static int rm_physical(Removable *r, int x) {
    int root = x;
    while (r->parent[root] != root) root = r->parent[root];
    while (r->parent[x] != x) {
        int next = r->parent[x]; r->parent[x] = root; x = next;
    }
    return root;
}
static int rm_find(Removable *r, int x) {
    vertex(r->n, x);
    return rm_physical(r, r->id[x]);
}
static void rm_rebuild(Removable *r) {
    int *rep = alloc(2 * (size_t)r->n + 1, sizeof(int));
    int *p = alloc((size_t)r->n + 1, sizeof(int));
    int *w = alloc((size_t)r->n + 1, sizeof(int));
    /* No links during this pass: flattening the frozen forest is linear. */
    for (int x = 1; x <= r->used; ++x) (void)rm_physical(r, x);
    for (int x = 1; x <= r->n; ++x) {
        int root = rm_physical(r, r->id[x]);
        if (!rep[root]) rep[root] = x;
        p[x] = rep[root]; ++w[rep[root]];
    }
    size_t cap = 2 * (size_t)r->n + 1;
    memset(r->parent, 0, cap * sizeof(int));
    memset(r->weight, 0, cap * sizeof(int));
    memset(r->live, 0, cap * sizeof(int));
    for (int x = 1; x <= r->n; ++x) {
        r->id[x] = x; r->parent[x] = p[x];
        r->weight[x] = r->live[x] = w[x];
    }
    r->used = r->n;
    free(rep); free(p); free(w);
}
static bool rm_union(Removable *r, int a, int b) {
    a = rm_find(r, a); b = rm_find(r, b);
    if (a == b) return false;
    if (r->weight[a] < r->weight[b]) { int t = a; a = b; b = t; }
    r->parent[b] = a;
    r->weight[a] += r->weight[b]; r->live[a] += r->live[b];
    return true;
}
static bool rm_remove(Removable *r, int x) {

    if (r->used == 2 * r->n) rm_rebuild(r);

    if (r->live[root] == 1) return false;

}
static void rm_free(Removable *r) {

class Removable:
    def __init__(self, n):
        if not 0 <= n <= 1000000:
            raise ValueError('bad N')
        self.n = self.used = n
        self.parent = list(range(2 * n + 1))
        self.weight = [1] * (2 * n + 1)
        self.live = [1] * (2 * n + 1)
        self.id = list(range(n + 1))

    def physical(self, x):
        root = x
        while self.parent[root] != root:
            root = self.parent[root]
        while self.parent[x] != x:
            nxt = self.parent[x]
            self.parent[x] = root
            x = nxt
        return root

    def find(self, x):
        vertex(self.n, x)
        return self.physical(self.id[x])

    def rebuild(self):
        rep = [0] * (2 * self.n + 1)
        p = [0] * (self.n + 1)
        w = [0] * (self.n + 1)
        for x in range(1, self.used + 1):
            self.physical(x)
        for x in range(1, self.n + 1):
            root = self.physical(self.id[x])
            if rep[root] == 0:
                rep[root] = x
            p[x] = rep[root]
            w[rep[root]] += 1
        self.parent = p + [0] * self.n
        self.weight = w + [0] * self.n
        self.live = self.weight.copy()
        self.id = list(range(self.n + 1))
        self.used = self.n

    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            return False
        if self.weight[a] < self.weight[b]:
            a, b = b, a
        self.parent[b] = a
        self.weight[a] += self.weight[b]
        self.live[a] += self.live[b]
        return True

    def remove(self, x):
        vertex(self.n, x)
        if self.used == 2 * self.n:
            self.rebuild()
        root = self.find(x)
        if self.live[root] == 1:
            return False
        self.live[root] -= 1
        self.used += 1
        fresh = self.used
        self.parent[fresh] = fresh
        self.weight[fresh] = self.live[fresh] = 1
        self.id[x] = fresh
        return True

重建后物理权重重新等于新森林的成员数。整个过程保持“逻辑对象恰有一个当前代理、同一类的代理有同一个根”；Remove 单例时返回 false，Union 同类时返回 false。空间一直为 O(N0)。对每个重建阶段使用普通并查集的单变量上界，得到 O((N0+M)α(N0,N0))；这是这个有界空间版本所证明的界。两参数 α 随操作密度变化，不能把分阶段的分析直接改写成 α(M,N0)。

参数依据：Alstrup 等，Union-Find with Constant Time Deletions（2005），引言将全局 N 明确计为累计 MakeSet 次数。本文的 Remove 还会重新建立单例，因此同时列出累计节点版与固定空间版的准确界。

8.10 · 离线最近公共祖先

原题（中文翻译）

（**）给出一个算法，输入一棵有 N 个顶点的树及 N 对顶点。对每一对 (v,w)，确定 v 与 w 的最近公共祖先。算法运行时间应为 O(Nlog*N)。

本版习题 8.10；印刷页 283／PDF 第 300 页。

解答

用离线 DFS 配合并查集。树必须指定根；节点是自己的祖先。一个节点 u 开始 DFS 时建立单例，并保存 ancestor[Find(u)] = u。每处理完一个孩子 c，就合并 u 与 c 所代表的已完成部分，再把合并后根的 ancestor 改为 u。这个标签与 DSU 根编号分开，因此平衡规则可以自由选择。

节点 u 的所有孩子处理完后，把 u 标为黑色（完成）。对包含 u 的每个查询 (u,v)，若 v 也已黑，就输出 ancestor[Find(v)]。使用两个端点的邻接查询列表，每个查询被查看两次。显式栈模拟 DFS，在孩子返回时立即合并；若延迟到所有孩子返回以后才合并，来自不同兄弟子树的查询会错过正确的 ancestor 标签。

static int *offline_lca(int n, int root, const int *parent, const Pair *pairs, int q) {

    vertex(n, root);
    DSU d = d_new(n, 1, 1);
    int *head = alloc((size_t)n + 1, sizeof(int));
    int *next = alloc((size_t)n + 1, sizeof(int));
    int *ancestor = alloc((size_t)n + 1, sizeof(int));
    int *state = alloc((size_t)n + 1, sizeof(int));
    int *qh = alloc((size_t)n + 1, sizeof(int));
    QueryEdge *qe = alloc(2 * (size_t)q, sizeof *qe);
    Frame *stack = alloc((size_t)n, sizeof *stack);
    int *answer = alloc((size_t)q, sizeof(int));
    for (int i = 1; i <= n; ++i) qh[i] = -1;

        if (i == root) { if (parent[i] != 0) fail("root parent must be 0"); }
        else {
            vertex(n, parent[i]);
            if (parent[i] == i) fail("self-parent");
            next[i] = head[parent[i]]; head[parent[i]] = i;
        }
    }
    for (int i = 0; i < q; ++i) {
        int a = pairs[i].a, b = pairs[i].b;
        vertex(n, a); vertex(n, b);
        qe[2*i] = (QueryEdge){b, i, qh[a]}; qh[a] = 2*i;
        qe[2*i+1] = (QueryEdge){a, i, qh[b]}; qh[b] = 2*i+1;
    }
    int used = 1, visited = 1;
    stack[0] = (Frame){root, head[root]};
    ancestor[root] = root; state[root] = 1;
    while (used) {
        Frame *f = &stack[used - 1]; int v = f->v;
        if (f->child) {
            int c = f->child; f->child = next[c];
            if (state[c]) fail("cycle in tree");
            state[c] = 1; ancestor[c] = c; ++visited;
            stack[used++] = (Frame){c, head[c]};
        } else {
            state[v] = 2;
            for (int k = qh[v]; k != -1; k = qe[k].next)
                if (state[qe[k].other] == 2)
                    answer[qe[k].id] = ancestor[d_find(&d, qe[k].other)];
            --used;
            if (used) {
                int u = stack[used - 1].v;
                (void)d_union(&d, u, v);
                ancestor[d_find(&d, u)] = u;
            }
        }
    }
    if (visited != n) fail("tree is disconnected or cyclic");
    d_free(&d);
    free(head); free(next); free(ancestor); free(state); free(qh); free(qe); free(stack);
    return answer;
}

def offline_lca(n, root, parent, pairs):
    if not 1 <= n <= 1000000 or len(parent) != n + 1 or len(pairs) > 1000000:
        raise ValueError('bad tree size')
    vertex(n, root)
    children = [[] for _ in range(n + 1)]
    queries = [[] for _ in range(n + 1)]
    for i in range(1, n + 1):
        if i == root:
            if parent[i] != 0:
                raise ValueError('root parent must be 0')
        else:
            vertex(n, parent[i])
            if parent[i] == i:
                raise ValueError('self-parent')
            children[parent[i]].append(i)
    # Match C's head insertion order.
    for c in children:
        c.reverse()
    for i, (a, b) in enumerate(pairs):
        vertex(n, a)
        vertex(n, b)
        queries[a].append((b, i))
        queries[b].append((a, i))
    d = DSU(n, 1, 1)
    state, ancestor = [0] * (n + 1), [0] * (n + 1)
    answer = [0] * len(pairs)
    state[root], ancestor[root] = 1, root
    stack, visited = [[root, 0]], 1
    while stack:
        v, pos = stack[-1]
        if pos < len(children[v]):
            c = children[v][pos]
            stack[-1][1] += 1
            if state[c]:
                raise ValueError('cycle in tree')
            state[c], ancestor[c] = 1, c
            visited += 1
            stack.append([c, 0])
        else:
            state[v] = 2
            for other, i in reversed(queries[v]):
                if state[other] == 2:
                    answer[i] = ancestor[d.find(other)]
            stack.pop()
            if stack:
                u = stack[-1][0]
                d.union(u, v)
                ancestor[d.find(u)] = u
    if visited != n:
        raise ValueError('tree is disconnected or cyclic')
    return answer

证明不变量：已处理完、并回到当前 DFS 路径某个祖先 a 的子树，整体属于一个 DSU 类，标签 ancestor 为 a；尚未完成的孩子还保持自己的类。当 (u,v) 的第二个端点完成时，若一端是另一端的祖先，它此时正完成，标签就是它；否则两个端点在最近公共祖先 a 的不同孩子子树中，较早完成的那棵已经合并到 a，当前一端所在的孩子尚未返回，故 Find(较早端点) 的标签恰好为 a。于是答案正确。同点查询在着黑后得到自己。

N 个顶点和 N 对查询的建表、DFS、查询扫描为 O(N)，根链接 N−1 次，Find 为 O(N) 次，由正文计账界得到 O(Nlog*N)；更强 α 定理也给出 O(Nα(N,N))。数组、邻接表、显式栈均为 O(N)。C 返回的答案数组由调用者释放；两版均检查父编号、自环、根的父项以及从根是否访问全部顶点，拒绝非树输入。

8.11 · 先合并后查询的线性界

原题（中文翻译）

（*）证明：若全部 Union 操作都先于 Find 操作，则即使 Union 任意进行，带路径压缩的并查集算法也只需要线性时间。

本版习题 8.11；印刷页 283／PDF 第 300 页。

解答

这里先执行的是已知根的链接，后执行的是 Find；若“Union”接收元素而内部做 Find，那么它们已经与链接交错，不符合题设。链接至多 N−1 次，花 O(N)。链接阶段结束后，森林固定，根不会再变。

考察每次 Find：最后一条到根的边（以及根的检查）计入这次查询，成本为常数。路径上其余每条边的父亲不是根，压缩后，该边的起点永久直接指向最终根，后续不再出现这种非末尾访问。每个节点至多为非末尾边付费一次，因此这部分总和至多 N。压缩第二遍对同样的路径再走一次，只乘常数。

T=Θ(N+U+F)=O(N+F),U≤N−1

“线性”是相对于初始化、链接和查询总数；一次第一次查询仍可能走完整条长链。这个证明也解释了 8.9 重建时，批量压平冻结森林为什么是线性时间。

8.12 · 任意合并加压缩的时间界与题干校注

原题（中文翻译）

（*）证明：若 Union 任意进行，而 Find 使用路径压缩，则最坏运行时间为 Θ(MlogN)。

本版习题 8.12；印刷页 283／PDF 第 300 页。

解答

题干校注：扫描页确实是 Θ。把它当作对任意 M≥N 都成立的两参数紧界，会与查询密集时的线性上界矛盾。可以统一证明 O((M+N)logN)；以下同时给出这个上界和对原题全参数 Θ 表述的反证。

保存忽略查询的最终参考森林。实际查询路径是其中一段祖先链。等价地，在这个固定森林上执行“非根路径压缩”：把一段路径上的节点改为该段末端的父亲；每次操作总成本是压缩改写数加常数。设 f(m,n) 为 m 次这种压缩在 n 个节点上最多改写的父项数。

把参考森林划为祖先封闭的上部 Xt 和下部 Xb。每条路径分为上、下两段；只有非根的那一段需要计入子问题，故 mb+mt≤m。跨上下边界的首次改写每个下部节点至多一次；后续跨界改写可以随上段压缩记账。由此得到分解界：

f(m,n)≤f(mb,nb)+f(mt,nt)+nb+mt,mb+mt≤m

把 n 补到 2 的幂（加入孤立节点至多使 n 翻倍），取上下部各 n/2。对 n 归纳，以 f(m,1)=0 为基例：

f(m,n)≤(mb+n/4)log2(n/2)+(mt+n/4)log2(n/2)+n/2+mt
f(m,n)≤(m+n/2)log2n

加上 Θ(N) 初始化、至多 N−1 根链接和 O(M) 查询常数项，得到 O((M+N)logN)，对 M=Ω(N) 即 O(MlogN)。上述分解引理及归纳见 Seidel–Sharir，Top-Down Analysis of Path Compression，§2–3。

同一分解取 nt=⌈n/k⌉、nb=n−nt，对 ⌈logkn⌉ 归纳，利用 nb≤(k−1)nt，得到更细界（同文 Claim 3）：

f(m,n)≤(m+(k−1)n)⌈logkn⌉,k>1

令题设 M=N2，基本 Find 数 m 为 O(M)，取 k=N+1，右边不超过 m+N2=O(M)；含初始化和链接的总成本也是 O(M)，处理 M 条操作又需 Ω(M)，故此操作密度的最坏时间为 Θ(M)。它严格小于 Θ(MlogN)，所以原题写法缺少操作数量范围，不能作为所有 M、N 的紧界。

8.13 · 按大小合并的迭代对数证明

原题（中文翻译）

证明：若 Union 按大小进行，Find 使用路径压缩，则最坏运行时间为 O(Mlog*N)。

本版习题 8.13；印刷页 283／PDF 第 300 页。

解答

再次固定忽略压缩的最终参考森林，令 s(v) 为 v 的参考子树大小，定义分析用秩 ρ(v)=⌊log2s(v)⌋。这个秩只用于证明，程序仍只保存根的物理大小。节点 x 被挂到根 y 的那一刻，按大小规则保证 y 的原树至少与 x 一样大，因此 y 的新子树至少为 x 的两倍。后来合并只能增大 y 的参考子树，x 成为非根后不再吸收其他参考根。

s(y)≥2s(x)⟹ρ(y)≥ρ(x)+1

因此参考父边、压缩后的实际父边上，分析秩都严格增加；最大秩至多 ⌊log2N⌋。分析秩为 r 的节点，其参考子树至少 2r，同秩节点不会互为祖先，子树互不相交，所以数量至多 N/2r。这恰好满足正文三项计数事实。

沿用正文的连续秩组及两种账：每个 Find 的跨组与末尾访问至多 G+2；同组非末尾访问会让父亲的分析秩严格增加，第 g 组单节点至多承担 F(g)−F(g−1) 次。取 F(0)=0、F(g)=2F(g−1)，每组节点账至多 N，组数 G=O(1+log*N)。总时间为 O((N+M)(1+log*N))；在原章 M=Ω(N)、N≥2 条件下，化为题设界。

8.14 · 路径减半的实现与完整证明

原题（中文翻译）

设在 Find(i) 中采用部分路径压缩：把从 i 到根的路径上每隔一个节点的父指针改为它的祖父（在有意义的地方）。这称为路径减半。

  1. 编写完成这一操作的过程。
  2. 证明：若 Find 使用路径减半，Union 按高度或按大小进行，则最坏运行时间为 O(Mlog*N)。

本版习题 8.14；印刷页 283／PDF 第 300 页。

解答

a．改为祖父以后，从祖父继续

读取 p=parent[x]、g=parent[p]，让 x 指向 g，再令 x=g。若 p 已是根，g=p，直接结束这一段而不做多余写入。这里从新祖父继续，跳过旧父亲；若仍从旧父亲继续，就会把每个节点都改为祖父，那是路径分裂。以下函数使用共享 DSU 的自指根，原书负数根表示需要先确认 p 不是根再访问它的父项。

C（C11）
static int d_halve(DSU *d, int x) {
    vertex(d->n, x);
    while (d->parent[x] != x) {
        int p = d->parent[x], g = d->parent[p];
        ++d->hops;
        if (p != g) {
            ++d->hops;
            d->parent[x] = g;
            ++d->writes;
        }
        x = g;
    }
    return x;
}

b．减半仍会让被记账节点的父秩严格上升

按高度采用历史秩；按大小采用 8.13 的参考子树分析秩。两种情况都满足：沿实际父边秩严格增加、最大秩至多对数、秩 r 的节点数至多 N/2r。对一次减半迭代，只访问 x、父亲 p 及祖父 g，成本至多常数；若 p 是根，归入本次查找账。

若 x 与 p 跨组，也归入查找账，整条实际向根路径上跨组至多 G 次。否则，把这次迭代记到 x 上；由于 p 不是根且 rank(g)>rank(p)，改写后 x 的父秩严格上升。只要父亲仍在 x 的第 g 组，x 最多承担该组宽度次；离组后的访问进入查找账。跳过 p 不会增加同组计费次数。

于是查找账仍是 O(MG)；第 g 组的节点账至多 O(NF(g)/2F(g−1))。采用正文相同的指数边界，每组 O(N)，总界为 O((N+M)(1+log*N))，在 M=Ω(N)、N≥2 下即为所求。这个证明针对普通只增合并的结构；8.8 加入 Deunion 后，必须另外管理快捷边的有效历史，不能直接套用。

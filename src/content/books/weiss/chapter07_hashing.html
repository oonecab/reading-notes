一、§7.1：先问查找是否只能依赖比较

第六章的排序下界约束了比较模型；第四章的平衡树也沿着比较结果选择分支。第七章换了一种提问：键本身若带有可以计算的数值或字符结构，能否先算出它可能所在的位置？散列的平均常数时间从这个模型变化中来，同时也放弃了树所保留的有序关系。

中国改编版先补入插值查找。在递增数组的当前区间 [l,u] 内，用端点连成的直线估计目标 K 的下标：

i′=l+(K−Kl)(u−l)Ku−Kl

若键与下标严格成仿射关系，一次预测就能命中。预测含键值的减法、乘法和除法，因此已经使用了比较以外的信息。分布偏斜时仍需反复修正：例如数组 0,1,…,N−2,N2，寻找 N−2，向下取整的预测可连续落在左端，退化为线性次比较。实际程序还要处理两端键相等、目标越界、算术溢出，并在比较后排除已经探测的位置，保证区间确实缩小。

随后，作者把“计算位置”推广为散列：长度为 m 的表使用下标 0 到 m−1，函数 h 把键映射到这个范围。图 7.2 把 john、phil、dave、mary 放到 3、4、6、7；这些位置保存键及其工资值，查找仍须检查键是否真的相等。

键的取值远多于槽位，两个不同键映射到同一地址是必然可能的。于是全章围绕三个相互关联的选择展开：怎样计算地址、发生冲突后怎样继续、表的容量何时改变。FindMin、区间检索和按序遍历需要额外扫描或另建有序结构，正是这套接口的代价。

二、§7.2：散列函数要面对实际的键分布

整数的 h(x)=xmodm 很便宜，但表长为 10、键都以 0 结尾时，所有键都会挤到同一槽。选择素数有助于避开一些周期，并为后面的探测性质提供条件；它不能保证任何输入都分布均匀。

字符串的三次尝试更能说明作者的思路。图 7.4 把字符码相加：对最多八个 ASCII 字符的键，总和至多 8·127=1016，表长即使取 10007，也只有前 1017 个槽可能被命中，而且交换字符顺序不会改变结果。图 7.5 使用前三个字符 c0+27c1+729c2；书中词典的三字符前缀只有 2851 种，仍只覆盖约 28% 的大表。英文前缀并不是均匀随机的三字母串。

图 7.6 于是把所有字符纳入 Horner 递推。每读一个字符，令 H←32H+c；最终再对表长取余。它与第二章计算多项式的方法相接：

H=c0bℓ−1+c1bℓ−2+⋯+cℓ−1,Hj+1=bHj+cj

原书用基数 32 是因为乘法可以写成左移五位。无符号溢出有确定的模运算语义，但长字符串的早期字符会被移出机器字；把加法换成异或也会改变散列函数，不能只凭指令数量判断分布质量。应把键长、常见前缀和输入模式一起考虑。

本页独立编写的字符串实现采用基数 131、32 位无符号状态，Python 显式截到同样的 32 位；它是可复现的教学约定，与图 7.6 的基数 32 分开记录。整数表保存 uint32_t 键和 int64_t 值，Python 采用相同范围。共同定义还包括素数选择、随机输入和系数越界检查，后面的程序按需引用。

Find 只遍历对应的一条链。Insert 先确认键是否存在，再把新节点接入；若键已存在，本页的映射接口更新其值，集合式用法保持同一值即可。原书图 7.11 采用头插，因而它生成的链顺序会与图 7.7 的尾插结果相反，这个区别不影响查询。

“The average length of a list is λ.”

链的平均长度就是装载因子 λ。

§7.3，印刷页 244／PDF 261。

λ=nm,E[失败查找的节点比较数]=λ

如果每个键独立均匀地选桶，并在全部已有键中均匀选择一次成功查询，那么它前面的其他键平均有 (n−1)/(2m) 个，成功比较数为 1+(n−1)/(2m)；原书写成近似 1+λ/2。这些数只计节点比较，另加计算散列地址的时间。整数键是常数个机器字；字符串还要计散列和相等比较的字符成本。

图 7.8–7.11 把第三章的链表复用到散列表，表头是为简化链表操作服务的。页 242 提到一次分配所有表头时，正确做法还需要保存连续节点块，并把每个桶指针指向相应节点；桶指针数组与节点数组不能当成同一种内存布局。本页用无哨兵链和“指向待修改链接的指针”处理删除，同时把地址计算保留一次。

下面的节点和桶数组都由表拥有。Find 返回借用节点；删除该节点或销毁表后便失效。再散列只重新链接现有节点，所以节点地址保持，但旧链的遍历关系改变。分配新桶失败时保留旧表，销毁时逐个释放节点及桶数组。

typedef struct ChainNode {
    uint32_t key;
    int64_t value;
    struct ChainNode *next;
} ChainNode;

typedef struct { size_t m, n; ChainNode **head; } Chain;

bool chain_init(Chain *t, size_t m) {
    *t = (Chain){0, 0, NULL};
    if (m < 1 || m > UINT32_MAX || m > SIZE_MAX / sizeof *t->head)
        return false;
    t->head = malloc(m * sizeof *t->head);
    if (!t->head) return false;
    t->m = m;
    for (size_t i = 0; i < m; ++i) t->head[i] = NULL;
    return true;
}

ChainNode *chain_find(const Chain *t, uint32_t key) {
    if (!t->m) return NULL;
    ChainNode *p = t->head[key % t->m];
    while (p && p->key != key) p = p->next;
    return p; /* Borrowed pointer; deletion/destruction invalidates it. */
}

bool chain_set(Chain *t, uint32_t key, int64_t value) {
    if (!t->m) return false;
    size_t i = key % t->m;
    for (ChainNode *p = t->head[i]; p; p = p->next)
        if (p->key == key) { p->value = value; return true; }
    ChainNode *p = malloc(sizeof *p);
    if (!p) return false;
    *p = (ChainNode){key, value, t->head[i]};
    t->head[i] = p;
    ++t->n;
    return true;
}

bool chain_delete(Chain *t, uint32_t key) {
    if (!t->m) return false;
    ChainNode **link = &t->head[key % t->m];
    while (*link && (*link)->key != key) link = &(*link)->next;
    if (!*link) return false;
    ChainNode *p = *link;
    *link = p->next;
    free(p);
    --t->n;
    return true;
}

bool chain_rehash(Chain *t, size_t m) {
    Chain newer;
    if (!chain_init(&newer, m)) return false;
    for (size_t i = 0; i < t->m; ++i) {
        ChainNode *p = t->head[i];
        while (p) {
            ChainNode *next = p->next;
            size_t j = p->key % m;
            p->next = newer.head[j];
            newer.head[j] = p;
            p = next;
        }
    }
    newer.n = t->n;
    free(t->head);
    *t = newer;
    return true;
}

void chain_destroy(Chain *t) {
    for (size_t i = 0; i < t->m; ++i) {
        ChainNode *p = t->head[i];
        while (p) { ChainNode *next = p->next; free(p); p = next; }
    }
    free(t->head);
    *t = (Chain){0, 0, NULL};
}

class ChainNode:
    def __init__(self, key, value, next_node=None):
        self.key, self.value, self.next = key, value, next_node


class Chain:
    def __init__(self, m):
        if not 1 <= m <= MASK32:
            raise ValueError("table size")
        self.m, self.n, self.head = m, 0, [None] * m

    def find(self, key):
        p = self.head[key % self.m]
        while p is not None and p.key != key:
            p = p.next
        return p

    def set(self, key, value):
        if not 0 <= key <= MASK32:
            raise ValueError("uint32 key")
        checked_i64(value)
        i = key % self.m
        p = self.head[i]
        while p is not None:
            if p.key == key:
                p.value = value
                return
            p = p.next
        self.head[i] = ChainNode(key, value, self.head[i])
        self.n += 1

    def delete(self, key):
        i, previous = key % self.m, None
        p = self.head[i]
        while p is not None and p.key != key:
            previous, p = p, p.next
        if p is None:
            return False
        if previous is None:
            self.head[i] = p.next
        else:
            previous.next = p.next
        self.n -= 1
        return True

    def rehash(self, m):
        newer = Chain(m)
        for p in self.head:
            while p is not None:
                next_node = p.next
                i = p.key % m
                p.next, newer.head[i] = newer.head[i], p
                p = next_node
        self.m, self.head = m, newer.head

    def destroy(self):
        self.m, self.n, self.head = 0, 0, []

四、§7.4：探测规则决定冲突与后续查找

开放定址把全部元素存进表内。探测序列 hi(x)=(h(x)+F(i))modm 是 Insert 和 Find 的共同路线；如果两者走不同路径，插入成功也不能保证之后找得到。图 7.12、7.14、7.19 对同一输入 89、18、49、58、69 展示三种路线。

线性探测遇到一段连续占用区就继续向后走，新的键又会延长这段区间，形成主聚集。平方探测跳开相邻槽，但起始散列值相同的键仍拥有完全相同的候选位置，这叫次聚集。双散列让步长也依赖键：它能削弱相同起点的相关性，代价是再算一个函数。

随机探测模型中，失败查找遇到空槽的概率约为 1−λ，因此平均探测次数为 1/(1−λ)。成功查询必须按每个元素当初插入时的装载因子取平均，不能直接套用当前表的失败查询成本：

Urandom≈11−λ,Srandom≈1λ∫0λdx1−x=−ln(1−λ)λ

例：装载因子与探测代价

例如装载因子从 0.5 上升到 0.9，线性探测在当前装载下的下一次插入估计由 2.5 次升到 50.5 次；这说明控制空槽比例有实际意义。整段从空表开始的插入实验还要平均早期廉价插入，不能拿 50.5 直接与整段均值比较。

平方探测的保证来自素数与半空表

令 m 为奇素数。候选 h(x)+i2，其中 0≤i≤(m−1)/2，共 (m+1)/2 个。若两个候选相同，就有 (i−j)(i+j)≡0(modm)；素数性质要求 i=j 或 i+j=m，而当前范围内第二种不可能。因此候选互异，已占用槽至多 (m−1)/2 个时，至少有一个候选为空。这就是定理 7.1 的具体保证。

表长不是素数时，保证会消失。模 16 的平方偏移只有 0、1、4、9；双散列则恰好访问 m/gcd(m,h2(x)) 个位置，所以步长非零之外，还要与表长互素。素数表长和 1≤h2(x)<m 提供了这个条件。书中表长 10 的例子只用于演示，习题 7.1 会让失败真实发生。

删除要留下路标，查找却要检查活元素

删除一个造成过冲突的键，不能把槽直接改回 Empty，否则在它后面落位的键会被过早判为不存在。状态应分成 Empty、Live、Dead：只有 Empty 终止未命中查询；Dead 继续探测。插入记住第一个 Dead，但要继续确认后面是否已有同一活键，才能决定更新或复用。

“Don’t switch it!”

不要交换这个检查顺序！

§7.4.2，印刷页 250／PDF 267；指图 7.17 的短路判断。

原书先看 Info 再看 Element，是因为空槽的 Element 尚未初始化。教学实现更明确地只在 Live 状态比较键。Find 返回的定位结果同时包含“找到活键”“可插入位置”和探测次数，避免把一个墓碑当作成功查询。所有循环都设定有限上界；双散列回到起点时立即报告无可用候选。

typedef enum { EMPTY, LIVE, DEAD } CellState;
typedef enum { LINEAR, QUADRATIC, DOUBLE_HASH } ProbeKind;
typedef struct { uint32_t key; int64_t value; CellState state; } OCell;
typedef struct {
    size_t m, n, used, r;
    ProbeKind kind;
    OCell *cell;
} OpenTable;
typedef struct { size_t pos, probes; bool found; } ProbeResult;

bool open_init(OpenTable *t, size_t m, ProbeKind kind) {
    *t = (OpenTable){0, 0, 0, 0, kind, NULL};
    if (m < 3 || m > UINT32_MAX || m > SIZE_MAX / sizeof *t->cell)
        return false;
    t->cell = calloc(m, sizeof *t->cell);
    if (!t->cell) return false;
    t->m = m;
    t->r = m - 1;
    while (!prime_size(t->r)) --t->r;
    return true;
}

    size_t first_dead = SIZE_MAX;
    if (!t->m) return (ProbeResult){SIZE_MAX, 0, false};
    size_t h = key % t->m, step = t->r - key % t->r;

            t->kind == QUADRATIC ? (uint64_t)i * i : (uint64_t)i * step;
        size_t p = (size_t)(((uint64_t)h + offset) % t->m);
        if (i && t->kind == DOUBLE_HASH && p == h)
            return (ProbeResult){first_dead, i, false};
        if (t->cell[p].state == EMPTY)

            return (ProbeResult){p, i + 1, true};

            first_dead = p;

    return (ProbeResult){first_dead, t->m, false};
}

    def __init__(self, m, kind):
        if not 3 <= m <= MASK32:
            raise ValueError("table size")
        self.m, self.n, self.used, self.kind = m, 0, 0, kind
        self.r = m - 1
        while not prime_size(self.r):
            self.r -= 1
        self.cell = [[0, 0, EMPTY] for _ in range(m)]

    def probe(self, key):
        first_dead = None
        h, step = key % self.m, self.r - key % self.r
        for i in range(self.m):
            offset = (i if self.kind == LINEAR else
                      i * i if self.kind == QUADRATIC else i * step)
            p = (h + offset) % self.m
            if i and self.kind == DOUBLE_HASH and p == h:
                return first_dead, i, False
            k, _, state = self.cell[p]
            if state == EMPTY:
                return (first_dead if first_dead is not None else p,
                        i + 1, False)
            if state == LIVE and k == key:
                return p, i + 1, True
            if state == DEAD and first_dead is None:
                first_dead = p
        return first_dead, self.m, False

    def set(self, key, value):

            raise ValueError("uint32 key")

            return False, probes

                self.used += 1

        return True, probes

六、§7.6：目录可以增长，记录只在目标桶里分裂

如果记录在磁盘上，内存里的一次探测可能变成一次块读取。普通开放定址或链式冲突会触及多个块，全表再散列还可能迁移大量记录。可扩展散列把一个浅目录放在上层，每个叶桶最多保存 M 条记录；目录按散列值的前导位选择桶。

本版采用前导位。目录深度 D 表示使用多少位，因此有 2D 个入口；桶的局部深度 d 表示它已经区分了多少位，满足 d≤D。一个桶恰好被 2D−d 个目录入口引用。这是共享同一个桶，不能复制成多份独立记录。

插入 100100 时，10 桶已经满，而且其局部深度等于目录深度。先把目录由四入口扩为八入口，再把这个桶按第三位分成 100、101；其他桶只是多了一个引用，记录不动。

接着插入 000000，00 桶同样已满，但它的 d=2 小于当前 D=3。现有目录已能区分第三位，只需分成 000、001 并改相应指针。

一次分裂未必已经把新键所在的子桶分空。若多个键有很长的共同前缀，应再次检查并继续分裂；完全相同的散列位串也不能靠增加目录位数分开。本页集合接口把相同键视为重复，忽略再次插入；一般记录系统还需要为“不同记录、相同完整散列值”保留溢出桶或附加链。

bool eh_insert(Extendible *t, uint32_t key) {
    if (!t->size || !eh_key_valid(t, key)) return false;
    if (eh_find(t, key)) return true; /* Set semantics: duplicates are ignored. */
    for (;;) {
        EHBucket *b = t->dir[eh_index(t, key)];
        if (b->n < t->capacity) { b->key[b->n++] = key; ++t->n; return true; }
        if (b->depth == t->bits || b->depth == 20) return false;
        unsigned d = b->depth + 1;
        EHBucket *right = eh_bucket(t->capacity, d, 2 * b->prefix + 1);
        if (!right) return false;
        if (b->depth == t->depth) {
            EHBucket **dir = malloc(2 * t->size * sizeof *dir);
            if (!dir) { free(right); return false; }
            for (size_t i = 0; i < t->size; ++i)
                dir[2 * i] = dir[2 * i + 1] = t->dir[i];
            free(t->dir);
            t->dir = dir;
            t->size *= 2;
            ++t->depth;
        }
        b->depth = d;
        b->prefix *= 2;
        size_t left_n = 0;
        for (size_t i = 0; i < b->n; ++i) {
            uint32_t x = b->key[i];
            if ((x >> (t->bits - d)) & 1U) right->key[right->n++] = x;
            else b->key[left_n++] = x;
        }
        b->n = left_n;
        size_t run = (size_t)1 << (t->depth - d);
        size_t start = (size_t)right->prefix * run;
        for (size_t i = 0; i < run; ++i) t->dir[start + i] = right;
        /* Retry: the relevant child may still be full. */
    }
}

bool eh_delete(Extendible *t, uint32_t key) {
    if (!t->size || !eh_key_valid(t, key)) return false;
    EHBucket *b = t->dir[eh_index(t, key)];
    size_t i = 0;
    while (i < b->n && b->key[i] != key) ++i;
    if (i == b->n) return false;
    b->key[i] = b->key[--b->n];
    --t->n;
    while (b->depth) {
        size_t run = (size_t)1 << (t->depth - b->depth);
        EHBucket *other = t->dir[(size_t)(b->prefix ^ 1U) * run];
        if (other->depth != b->depth || other->n > t->capacity - b->n)
            break;
        EHBucket *keep = (b->prefix & 1U) ? other : b;
        EHBucket *drop = keep == b ? other : b;
        for (size_t j = 0; j < drop->n; ++j) keep->key[keep->n++] = drop->key[j];
        --keep->depth;
        keep->prefix >>= 1;
        size_t count = 2 * run, start = (size_t)keep->prefix * count;
        for (size_t j = 0; j < count; ++j) t->dir[start + j] = keep;
        free(drop);
        b = keep;
    }
    while (t->depth) {
        bool halve = true;
        for (size_t j = 0; j < t->size; j += 2)
            if (t->dir[j] != t->dir[j + 1]) { halve = false; break; }
        if (!halve) break;
        for (size_t j = 0; j < t->size / 2; ++j) t->dir[j] = t->dir[2 * j];
        t->size /= 2;
        --t->depth;
        /* The allocated directory buffer is reused; logical size is halved. */
    }
    return true;

            return True

七、总结：用精确键查询解决具体任务

符号表按标识符查询声明；图的真实名称可在读入时映射成连续整数；游戏的置换表缓存再次遇到的局面；拼写检查只问一个词是否属于词典。它们都不要求按键顺序输出，因而很适合散列表。缓存局面时也要保留足够的状态来辨认真实局面，地址相同本身并不代表状态相同。

树与散列表的选择由这些操作决定。平衡树给有序接口和最坏 O(logn) 的查找；散列表在良好的散列分布、受控装载和机器字键成本下给期望常数时间。普通未平衡二叉搜索树会被顺序输入压成链，良好的散列不会因为“已经按字典序排列”就自动变慢；但特制冲突输入仍能使散列表退化。原书关于散列最坏情况多由实现错误造成的经验判断，应与这些实际存在的冲突路径一起理解。

最后，作者回到第一章的字谜。在 R×C 网格上，从每个起点沿八个方向逐步形成候选串，在词典中查找。假设最大词长 L 是小常数，建含 W 个词的表为期望 O(W)，扫描为期望 O(RC)，总成本为 O(W+RC)。这比逐个词扫描网格的 O(RCW) 少了一个词典规模因子。

若 L 随输入增长，就应把字符成本恢复：普通实现从头散列每个候选，沿一条射线的计算和为 1+2+⋯+L，扫描可到 O(RCL2)；读词典至少要付总字符数。7.13 将前缀加入查询结构，遇到非前缀即停；再把散列值随追加字符更新，减少重复计算。完整字符串的相等判断和输出仍有成本，不能只看到一次整数哈希更新。

void basic_from_stdin(uint32_t first, uint32_t delta) {
    char **lines = NULL; size_t n = 0, capacity = 0;
    for (;;) {
        TextBuffer line = {NULL, 0, 0}; int c;

            require_ok(c != 0, "NUL byte in BASIC input");
            char ch = (char)c; require_ok(text_append(&line, &ch, 1), "read line");
            if (c == '\n') break;
        }
        if (!line.n) { free(line.s); break; }
        require_ok(n < 1000000, "too many BASIC statements");
        if (n == capacity) {
            capacity = capacity ? 2 * capacity : 16;
            char **p = realloc(lines, capacity * sizeof *lines);
            require_ok(p != NULL, "line array"); lines = p;
        }
        lines[n++] = line.s;
        if (c == EOF) break;
    }
    require_ok(!ferror(stdin), "input error");
    char **result;
    require_ok(basic_renumber((const char *const *)lines, n, 1000000, first, delta, &result), "invalid BASIC program or number range");
    for (size_t i = 0; i < n; ++i) { fputs(result[i], stdout); free(result[i]); free(lines[i]); }
    free(result); free(lines);
}

7.4 · 用 2 与 0.5 两个阈值留出扩缩间隔

原题（中文翻译）

原书习题 7.4 · 印刷页 260 · PDF 第 277 页。

解答

取缩容阈值 λ≤1/2，把容量 m 缩到约 m/2；最小容量不再缩。缩容后装载回到约 1，与扩容阈值 2 之间有固定间隔。扩大后容量约 2m、元素约 2m，装载也回到约 1。取下一素数和整数取整只影响常数与边界。

从一次扩容后的装载 1 到缩容阈值 0.5，需要删除新表容量的约一半元素；从缩容后的装载 1 到扩容阈值 2，则需要插入新容量数量级的元素。一次重建为期望 O(m+n)，而两次方向相反的重建之间有 Ω(m) 次更新，可以用每次更新的常数信用支付。

更一般地，任何固定缩容阈值 a<1 都能留出线性数量级的更新间隔；a=1/2 是清楚、对称的选择。若在装载刚低于 1 就缩，稍作插入便可能重新到 2，一删一插会反复付重建成本。实现操作用 chain_rehash，自动策略应同时保留最小表长和上述阈值。

7.5 · 随机位移排列、期望模型与 Fisher–Yates

原题（中文翻译）

另一种冲突处理策略定义偏移序列 F(i)=ri，其中 r0=0，r1,r2,…,rN 是前 N 个整数的随机排列，每个整数恰好出现一次。

  1. 证明在这种策略下，只要表未满，冲突就总能解决。
  2. 预期这种策略能消除聚集吗？
  3. 若装载因子为 λ，一次插入的期望时间是多少？
  4. 若装载因子为 λ，一次成功查找的期望时间是多少？
  5. 给出一个在理论和实际中都高效的算法生成该随机序列。说明对序列的选择规则为什么重要。

题干校注：原题给 r0 加上 N 个非零偏移，共 N+1 项；解答用表长 m=N+1 统一模数和项数。

原书习题 7.5 · 印刷页 260 · PDF 第 277 页。

解答

a、b：排列保证覆盖，共享排列仍保留相关性

令表长 m=N+1，偏移 0,r1,…,rN 覆盖 0,1,…,m−1，那么 (h(x)+ri)modm 也恰好覆盖全表。没有满表就一定碰到空槽。若以 m 为表长书写，则把 1 到 m−1 洗牌并把 0 放在开头；长度和模数须一致。

随机位移避免了线性探测总往相邻槽延长的主聚集，但所有键共享同一位移排列时，初始地址相同的键仍走同一条路线，所以次聚集保留。排列必须在插入与后续查找之间固定；每次查询重洗会改变路线并漏掉已有键。

c、d：先说明期望取自什么分布

在理想均匀探测模型中，当前 n 个占用槽相对待查键的随机顺序无偏，m−n 个空槽的最早排名期望为 (m+1)/(m−n+1)。可以把空槽之间的 m−n+1 个间隔视为对称，平均分配 n 个占用槽，于是第一个空槽前平均有 n/(m−n+1) 个占用槽。

E[插入探测]=m+1m−n+1≈11−λ

对从空表依次插入的元素，均匀选择一次成功查询，查询路线等于当初插入路线；对当时的占用数取平均：

E[成功探测]=m+1n∑t=0n−11m−t+1=m+1n(Hm+1−Hm−n+1)≈−ln(1−λ)λ

这里 Hj=∑i=1j1/i，空表没有“均匀成功查询”，n=0 时只讨论插入成本 1。固定装载小于 1 时，两种理想模型成本均为常数量级，另计键散列成本。

共享随机排列本身并不保证上述分布。反例是 n 个不同键都映射到地址 0：不论排列怎样洗，下一次插入必查 n+1 个槽，已有键的均匀成功查询平均为 (n+1)/2。因此题目的常数期望结论还需要良好主散列及均匀探测近似；该策略无条件保证的是最多 m 次探测，不是仅由装载因子决定的常数期望。

e：只洗非零偏移

从数组 0、1、…、m−1 开始，对 i=m−1 到 2，均匀选 j∈[1,i] 并交换。每一种非零偏移排列恰好对应一组选择，概率相等；0 固定为第一项。生成时间与保存空间均为 O(m)。从整数源取随机下标时采用拒绝采样，避免简单取余造成偏差。

C（C11）
uint32_t random_below(uint32_t *state, uint32_t bound) {
    /* Values random_u32()-1 range over [0, 2^32-2]. */
    uint64_t limit = UINT32_MAX - (uint64_t)UINT32_MAX % bound;
    uint64_t x;
    do { x = (uint64_t)random_u32(state) - 1; } while (x >= limit);
    return (uint32_t)(x % bound);
}

bool probe_permutation(size_t m, uint32_t *state, size_t **out) {
    *out = NULL;
    if (!m || m > UINT32_MAX || m > SIZE_MAX / sizeof(size_t) || !*state)
        return false;
    size_t *p = malloc(m * sizeof *p);
    if (!p) return false;
    for (size_t i = 0; i < m; ++i) p[i] = i;
    for (size_t i = m - 1; i > 1; --i) {
        size_t j = 1 + random_below(state, (uint32_t)i);
        size_t x = p[i]; p[i] = p[j]; p[j] = x;
    }
    *out = p; /* Caller frees p; p[0] remains zero. */
    return true;
}

        raise ValueError("table size or seed")

驱动以固定 xorshift 状态复现同一排列；理论上的均匀性证明假定独立均匀随机选择。一次洗牌在建表时完成，不是每个 Insert 都额外洗整张表。允许重复偏移可能永远找不到某些空槽，允许首次偏移非零则改变约定的主地址，修改排列则破坏查找的重放路径。

7.6 · 冲突处理策略的代价对照

原题（中文翻译）

各种冲突处理策略分别有哪些优点和缺点？

原书习题 7.6 · 印刷页 260 · PDF 第 277 页。

解答

策略主要收益代价与边界
分离链接删除直接改链；装载可以大于 1；容量受节点数量自然调节节点分配、指针与随机内存访问；坏散列使长链退化；键的顺序没有保留
线性探测规则最简单；连续槽具有局部性；互异键且表未满就能找到空槽主聚集；高装载下长尾增长；删除须墓碑或正确搬移
平方探测打散连续主聚集；只需一个主散列函数相同起点仍次聚集；素数半空保证；超过半满可找不到空位
双散列步长与键相关，接近随机探测的行为第二函数成本；步长须非零且与容量互素；删除须保存探测路线
固定随机位移排列全排列保证覆盖；避免连续线性聚集保存并生成一张排列；相同起点仍次聚集；随机访问降低局部性

选策略时把键的散列成本、装载控制、删除历史和内存访问一起算。再散列可以调整容量和清理墓碑，但一次重建仍需完整迁移；它是配合这些策略的容量管理方法。常数期望依赖散列分布和装载条件，最坏输入仍可能让单次操作线性。

7.7 · 先按指数聚合同类项，再排序输出

原题（中文翻译）

两个稀疏多项式 P1,P2 分别有 M,N 项，均用链表表示，每个节点包含系数、指数和 Next 指针（习题 3.7）。逐项相乘会产生 MN 个乘积。一个办法是排序这 MN 条记录后合并同类项，但在小内存环境下可能很昂贵。另一办法是每产生一项就合并，最后只排序结果。

  1. 编写程序实现后一种策略。
  2. 如果输出多项式约有 O(M+N) 项，两种方法各需要多少运行时间？

原书习题 7.7 · 印刷页 260 · PDF 第 277 页。

解答

用指数作为散列表键、累计系数作为值。对每一对输入项，计算指数和与系数积，把乘积加到对应键；处理完全部项后去掉零系数，导出链表并按指数递增归并排序。共同定义和 链式映射是依赖，下面给完整的项结构、排序、乘法与释放。

C（C11）
typedef struct Term {
    int64_t coefficient;
    uint32_t exponent;
    struct Term *next;
} Term;

void poly_destroy(Term *p) {
    while (p) { Term *next = p->next; free(p); p = next; }
}

Term *poly_merge(Term *a, Term *b) {
    Term *head = NULL, **link = &head;
    while (a && b) {
        Term **source = a->exponent <= b->exponent ? &a : &b;
        *link = *source;
        *source = (*source)->next;
        link = &(*link)->next;
    }
    *link = a ? a : b;
    return head;
}

Term *poly_sort(Term *p) {
    if (!p || !p->next) return p;
    Term *slow = p, *fast = p->next;
    while (fast && fast->next) { slow = slow->next; fast = fast->next->next; }
    Term *right = slow->next;
    slow->next = NULL;
    return poly_merge(poly_sort(p), poly_sort(right));
}

bool poly_multiply(const Term *a, const Term *b, Term **out) {
    *out = NULL;
    Chain sums;
    if (!chain_init(&sums, 17)) return false;
    bool ok = true;
    for (const Term *p = a; p && ok; p = p->next)
        for (const Term *q = b; q && ok; q = q->next) {
            int64_t product, total;
            if (p->exponent > UINT32_MAX - q->exponent ||
                !mul_i64(p->coefficient, q->coefficient, &product)) { ok = false; break; }
            uint32_t exponent = p->exponent + q->exponent;
            ChainNode *old = chain_find(&sums, exponent);
            if (!add_i64(old ? old->value : 0, product, &total)) { ok = false; break; }
            if (!old && sums.n >= 2 * sums.m) {
                size_t m = sums.m <= UINT32_MAX / 2 ? next_prime(2 * sums.m) : 0;
                if (!m || !chain_rehash(&sums, m)) { ok = false; break; }
            }
            if (!chain_set(&sums, exponent, total)) ok = false;
        }
    Term *result = NULL;
    for (size_t i = 0; i < sums.m && ok; ++i)
        for (ChainNode *p = sums.head[i]; p; p = p->next)
            if (p->value) {
                Term *q = malloc(sizeof *q);
                if (!q) { ok = false; break; }
                *q = (Term){p->value, p->key, result};
                result = q;
            }
    chain_destroy(&sums);
    if (!ok) { poly_destroy(result); return false; }
    *out = poly_sort(result);

class Term:
    def __init__(self, coefficient, exponent, next_term=None):

    tail = dummy
    while a is not None and b is not None:
        if a.exponent <= b.exponent:
            tail.next, a = a, a.next
        else:
            tail.next, b = b, b.next
        tail = tail.next
    tail.next = a if a is not None else b
    return dummy.next

        return p
    slow, fast = p, p.next
    while fast is not None and fast.next is not None:
        slow, fast = slow.next, fast.next.next
    right, slow.next = slow.next, None

    p = a
    while p is not None:

        while q is not None:
            exponent = p.exponent + q.exponent

设 Q 为运算中出现的不同指数数，K 为最后的非零项数。哈希分布良好且扩容控制链长时，MN 次乘加期望 O(MN)，扫描累计项 O(Q)，输出排序 O(Klog(K+1))。因为 Q≤MN，总时间为期望 O(MN+Klog(K+1))。当 K=O(M+N)，得到期望 O(MN+(M+N)log(M+N))。

先存全部乘积再排序，需要 O(MNlog(MN)) 时间和 O(MN) 条中间记录。立即聚合的空间为 O(Q+K+M+N)；最终仅有 O(M+N) 项，并不能排除计算过程中较多指数后来相消，所以不能仅由输出规模断言中间空间也为 O(M+N)。模数散列若遇到集中指数，期望时间前提失效；直接比较全部链的代价应另算。

7.9 · 一位词典：确定的否定与约 9.5% 的漏报概率

  1. 如果一个词散列到值为 0 的位置，该词不在词典中。
  2. 如果一个词散列到值为 1 的位置，该词在词典中。
  3. 假定表长为 300007，需要多少内存？

a 成立：只要词典构建与查询使用同一函数，词典中的词一定把对应位设成 1，所以 0 可以确定不在词典中。b 不成立：另一个词的冲突也会把该位设成 1，查询值 1 仅表示“可能在词典中”。对拼写检查来说，这是假阳性成员判断，也就是漏掉一个真实错词；正确词不会被误报为错词。

c：300007 位压成字节需要 ⌈300007/8⌉=37501 字节，约 36.62 KiB，加少量表头。必须采用位存储；若使用每元素一个字节的数组，空间就是 300007 字节，已经换了表示。

d：沿用 7.8 的 30000 词，假设它们和词典外查询词的散列位置独立均匀。一个固定槽未被任何词命中的概率为 (1−1/m)30000，所以词典外词被误判为词典成员的概率为：

q=1−(1−1300007)30000≈1−e−30000/300007≈0.0951606

这是条件于被查词确实不在词典中的概率，不是每个文件词的统一出错率。已知真实错词比例为 3/500 时，单词级漏报率约为 (3/500)q≈0.000571。

e：每页平均漏掉 3q≈0.2855 个错词，发现约 2.7145 个。在错词查询近似独立时，一页至少漏掉一个的概率约 1−(1−q)3≈25.92%。允许少量漏报时可以用它节约空间；要求准确检测全部错词时，值为 1 还要用完整词典核验。位数组的空间优势与上述明确漏报率一起评估。

7.10 · 用触及位置清单避免逐槽初始化

原题（中文翻译）

描述一个以额外内存为代价、避免初始化散列表的过程。

原书习题 7.10 · 印刷页 261 · PDF 第 278 页。

解答

采用带初始数组语义的 word-RAM 模型：每个已分配机器字可以读到某个任意值，读取本身有定义。除槽值数组 V 外，再分配长度 m 的稀疏索引 S、密集清单 D，只把“已触及数” z 初始化为 0；两个索引数组无需逐槽写初值。

槽 i 已初始化，当且仅当读取 j=S[i] 后，先检查 0≤j<z，再检查 D[j]=i。只有通过两步检查，才允许读取 V[i]；否则按空槽或默认值返回。第一次写入 i 时令 S[i]=z、D[z]=i、V[i]=v，然后递增 z。已初始化槽只改 V[i]。

正确性由不变量 D[0..z−1] 恰好记录已触及位置保证。所有这些 D 项都在加入清单时写过；一个未触及位置即使在 S[i] 中恰好读到范围内的随机索引，D[j] 也只会是别的已触及位置，第二步排除它。z=0 时，范围检查使所有槽都被视为空。将 z 重置为 0 即可逻辑清空整表，旧索引同样经过交叉检查。

逻辑初始化、查询和一次首次赋值都是 O(1)，额外空间为两个 m 字的数组。删除信息仍在 V 中按碰撞策略处理，不能用“从清单删掉位置”破坏开放定址的墓碑路线。

该模型允许读取任意初始机器字，标准 C 的未初始化对象不自动满足这个前提，不能直接把 malloc 内存读成 size_t 后宣称安全。实际实现可使用具有已定义初值、由系统按需清零的映射或专门的初始数组原语，后台首次触页成本也要计入。Python 普通列表构造和 C 显式逐槽清零仍付线性初始化成本。本题的省初始化过程与它依赖的存储模型已经分别给定。

7.11 · 滚动指纹、线性最坏保证与跳跃查找

原题（中文翻译）

要在很长的输入串 A1A2⋯AN 中寻找模式串 P1P2⋯Pk 的第一次出现。可以先对模式求散列值 HP，再依次与窗口 A1⋯Ak、A2⋯Ak+1，直到 AN−k+1⋯AN 的散列值比较。散列值相等时逐字符核实；真匹配则返回它在输入中的位置，假匹配则继续。

  1. （*）已知 Ai⋯Ai+k−1 的散列值，证明 Ai+1⋯Ai+k 的值可在常数时间算出。
  2. 证明运行时间为 O(k+N) 加上排除假匹配的时间。
  3. （*）证明假匹配的期望数量可以忽略。
  4. 编写程序实现这个算法。
  5. （**）描述一个最坏时间为 O(k+N) 的算法。
  6. （**）描述一个平均时间为 O(N/k) 的算法。

原书习题 7.11 · 印刷页 261 · PDF 第 278 页。

解答

a、b：窗口交接只去掉一端、加入另一端

用字符码作系数，选择素数 q>255、基数 1≤b<q，定义 Hi=∑j=0k−1Ai+jbk−1−jmodq，预先计算 B=bk−1modq。相邻窗口满足：

Hi+1=((Hi−AiB)b+Ai+k)modq

减去离开窗口的最高位，乘基数腾出一个字符位，再加入新字符。初始模式、窗口和 B 共用 O(k) 工作；之后每个窗口一次常数个模运算，合计 O(N)。寻找第一次出现时，真匹配最多验证一次并立即终止；若有 F 个假指纹命中，字符核验最多另付 O(kF)，总时间为 O(N+k+kF)。

c：把“几乎不冲突”变成一个明确的概率界

固定文本和模式，再独立均匀地随机选基数 b∈{1,…,q−1}。任一不同窗口与模式之差是一个非零的次数至多 k−1 的多项式；因 q>255，至少一个不同字符系数在模 q 后仍非零。在素数域上，次数 d 的非零多项式最多有 d 个根：若找到一个根就能除掉一次因子，归纳到常数多项式即可证明。

Pr[Hi=HP∣Ai⋯Ai+k−1≠P]≤k−1q−1,E[F]≤(N−k+1)(k−1)q−1

期望的线性性不需要不同窗口事件互相独立；同一上界也通过并集界控制“至少一次假匹配”的概率。取 q−1≥(N−k+1)(k−1)/ε 就使期望假匹配数至多 ε。例如 N=106、k=20、q=1000000007 时，上界约 0.019，额外核验比较的期望上界约 0.38。若还要直接控制额外核验时间，就把 k 因子一起用于选择模数。

这些界要求随机基数独立于输入，而且模运算采用可承载参数的机器字。参数若要用大整数，另计位复杂度。驱动为了复现固定使用基数 257；它的样本结果与上述随机化定理分开，固定参数的恶意输入仍可频繁指纹碰撞。逐字符核验保证最终返回位置始终正确。

d、e：Rabin–Karp 与 KMP 的完整实现

下面两版均接收字节串，返回零基下标；C 用输出参数并以 SIZE_MAX 表示未找到，Python 用 −1。与原题的一基位置对应时加 1。空模式返回 0，模式比输入长则未找到；显式长度允许字符值为 0。Rabin–Karp 归一化减法余数后再乘基数，C 用 64 位无符号中间量。

最坏线性算法选 KMP。预处理 π[j]，记录模式前缀 P[0..j] 的最长真前后缀长度；失配时把已匹配长度 j 改为 π[j−1]，文本下标不退。每次回退使 j 减少，而增加只发生在新字符成功比较后，所以全部回退次数由全部增加次数支付。预处理和搜索同样分析，得到最坏 O(k+N) 时间、O(k) 辅助空间。结构与界对应本书参考 [12] 的 Knuth–Morris–Pratt 原论文。

bool rk_first(const unsigned char *a, size_t n, const unsigned char *p, size_t k,
              uint32_t q, uint32_t base, size_t *out, size_t *false_matches) {
    *out = SIZE_MAX;
    *false_matches = 0;
    if (q < 257 || !base || base >= q) return false; /* q is a prime chosen by caller. */
    if (!k) { *out = 0; return true; }
    if (k > n) return true;
    uint64_t hp = 0, h = 0, power = 1;
    for (size_t i = 0; i < k; ++i) {
        hp = (hp * base + p[i]) % q;
        h = (h * base + a[i]) % q;
        if (i + 1 < k) power = power * base % q;
    }
    for (size_t i = 0;; ++i) {
        if (h == hp) {
            if (memcmp(a + i, p, k) == 0) { *out = i; return true; }
            ++*false_matches;
        }
        if (i == n - k) break;
        uint64_t remove = (uint64_t)a[i] * power % q;
        h = (h + q - remove) % q;
        h = (h * base + a[i + k]) % q;
    }
    return true;
}

bool kmp_first(const unsigned char *a, size_t n, const unsigned char *p,
               size_t k, size_t *out) {
    *out = SIZE_MAX;
    if (!k) { *out = 0; return true; }
    if (k > n) return true;
    if (k > SIZE_MAX / sizeof(size_t)) return false;
    size_t *pi = malloc(k * sizeof *pi);
    if (!pi) return false;
    pi[0] = 0;
    for (size_t i = 1, j = 0; i < k; ++i) {
        while (j && p[i] != p[j]) j = pi[j - 1];
        if (p[i] == p[j]) ++j;
        pi[i] = j;
    }
    for (size_t i = 0, j = 0; i < n; ++i) {
        while (j && a[i] != p[j]) j = pi[j - 1];
        if (a[i] == p[j]) ++j;
        if (j == k) { *out = i + 1 - k; break; }
    }
    free(pi);
    return true;
}

size_t horspool_first(const unsigned char *a, size_t n,
                      const unsigned char *p, size_t k) {
    if (!k) return 0;
    if (k > n) return SIZE_MAX;
    size_t shift[256];
    for (size_t c = 0; c < 256; ++c) shift[c] = k;
    for (size_t j = 0; j + 1 < k; ++j) shift[p[j]] = k - 1 - j;
    size_t start = 0;
    while (start <= n - k) {
        size_t j = k;
        while (j && a[start + j - 1] == p[j - 1]) --j;
        if (!j) return start;
        size_t step = shift[a[start + k - 1]];
        if (step > n - k - start) break;
        start += step;
    }
    return SIZE_MAX;
}

f：从窗口末端比较，并写清平均输入模型

本书参考 [1] 指向 Boyer–Moore 原论文：从右向左比较，用坏字符和已匹配后缀的信息跳过不可能的起点。上面给出它的末字符移位简化形式 Horspool，下面为这个具体可执行版本给出达到题中平均搜索界的充分条件。

令字符表大小为 σ，文本字符独立均匀，模式固定，且 σ≥2k。预处理时把每个字符的移位设为 k；扫描模式的前 k−1 个字符，用其最右出现的位置改为 k−1−j。模式末字符不参与这个表，所有移位至少为 1。每次从窗口末端向左核实，失配后按窗口原末字符的表值移动。

若末字符不在模式前 k−1 个字符里，移动 k 位是安全的：更近的任何新起点都会把已知末字符对准一个它不可能匹配的模式位置。若它出现，距离表给出最近可能对齐；更小位移同样与最右出现位置矛盾。移位按原末字符而不是失配位置的字符决定，保证复现程序的正确路线。

每次新窗口的末端位置都严格超过此前所有被查看的位置，其字符是新的独立样本。模式最多包含 k 种字符，所以新末字符落在模式外的概率至少 1−k/σ≥1/2；一次位移的条件期望至少 k/2。累计位移最多跨过 N 个字符加一个窗口边界，因而期望窗口检查数为 O(N/k+1)。

一次检查先比较末字符；只有它等于模式末字符才会继续，概率为 1/σ，即便之后最坏比较全部剩余字符，条件期望成本也至多 1+(k−1)/σ≤1.5。对各次检查累加，查询阶段期望时间为 O(N/k+1)；另计模式及移位表预处理，总界为 O(k+σ+N/k)。原题只写 O(N/k)，需要这个搜索阶段口径与输入分布前提，模式本身的读取不能省去。

本页字节实现的 σ=256，上述简单充分条件覆盖 k≤128；更长模式仍可正确查找，但本证明不再给出同一平均界。固定小字符表和高度重复的文本可能频繁短移位，Horspool 最坏可达 O(Nk)。算法作者的说明也指出小字符表会限制经典 Boyer–Moore 的跳跃距离；不能把教材的平均界当成所有字符串分布的保证。

7.12 · 两遍扫描与 32 位行号映射

原题（中文翻译）

一个 BASIC 程序由按行号递增排列的语句组成。控制转移通过 goto 或 gosub 和一个语句行号实现。编写程序读取合法的 BASIC 程序并重编号：第一条行号为 F，其后每条比前一条大 D。可假定语句数上限为 N，但输入行号可能大到 32 位整数。程序必须在线性时间内运行。

原书习题 7.12 · 印刷页 261 · PDF 第 278 页。

解答

先按语句顺序建立“旧行号→新行号”的映射，再扫描每条语句，改写开头的行号和 GOTO／GOSUB 的数字目标。前向跳转必须等映射完整之后改写，不能在第一次读到跳转时猜目标。

散列表在好分布下可给期望线性总时间；为了满足题目的线性时间保证，下面用固定 32 层的二进制基数树保存映射。每次映射插入或查询最多走 32 步，不依赖行号数值间距和散列冲突。设输入总字符数为 S、实际语句数为 n≤N，两遍文本扫描与 O(32n) 的建映射合计 O(S+n)；若每条语句长度有固定上界，就简写为 O(n)。

扫描器按题干给出的直接数字 GOTO／GOSUB 语法处理，也支持 ON…GOTO／GOSUB 的逗号目标列表。字符串字面量、REM／单引号注释和 DATA 字段中的数字与文字按原样复制。关键字匹配不区分大小写，但不会把变量名中的 GOTO 子串当成跳转；未声明目标、非递增行号或输出行号越界都会失败。该语法约定明确了应改写的位置，其他 BASIC 方言的额外行号引用须由相应语法规则识别。

typedef struct BasicNode {
    struct BasicNode *child[2];
    uint32_t number;
    bool assigned;
} BasicNode;
typedef struct { char *s; size_t n, capacity; } TextBuffer;

bool text_append(TextBuffer *b, const char *s, size_t n) {
    if (n > SIZE_MAX - b->n - 1) return false;
    size_t need = b->n + n + 1;
    if (need > b->capacity) {
        size_t cap = b->capacity ? b->capacity : 64;
        while (cap < need) cap = cap > SIZE_MAX / 2 ? need : 2 * cap;
        char *p = realloc(b->s, cap);
        if (!p) return false;
        b->s = p; b->capacity = cap;
    }
    if (n) memcpy(b->s + b->n, s, n);
    b->n += n; b->s[b->n] = '\0';
    return true;
}

bool text_number(TextBuffer *b, uint32_t number) {
    char s[11];
    int n = snprintf(s, sizeof s, "%" PRIu32, number);
    return n > 0 && text_append(b, s, (size_t)n);
}

bool basic_put(BasicNode *root, uint32_t key, uint32_t number) {
    for (int bit = 31; bit >= 0; --bit) {
        unsigned side = (key >> bit) & 1U;
        if (!root->child[side]) root->child[side] = basic_node();
        if (!root->child[side]) return false;
        root = root->child[side];
    }
    if (root->assigned) return false;
    root->number = number; root->assigned = true;
    return true;
}

bool basic_get(const BasicNode *root, uint32_t key, uint32_t *number) {
    for (int bit = 31; bit >= 0 && root; --bit) root = root->child[(key >> bit) & 1U];
    if (!root || !root->assigned) return false;
    *number = root->number;
    return true;
}

    if (!p) return;
    basic_destroy(p->child[0]); basic_destroy(p->child[1]); free(p);
}

    uint32_t v = 0;
    while (ascii_digit(s[*i])) {
        unsigned digit = (unsigned)(s[(*i)++] - '0');

        v = v * 10 + digit;

    *number = v;
    return true;
}

bool basic_rewrite(const char *line, const BasicNode *map, char **out) {
    TextBuffer b = {NULL, 0, 0};
    *out = NULL;
    size_t i = 0;
    while (basic_space(line[i])) ++i;
    if (!text_append(&b, line, i)) goto fail;
    uint32_t old, number;
    if (!basic_u32(line, &i, &old) || !basic_get(map, old, &number) ||
        !text_number(&b, number)) goto fail;
    while (line[i]) {
        if (line[i] == '\'' ) {
            if (!text_append(&b, line + i, strlen(line + i))) goto fail;
            break;
        }
        if (line[i] == '"') {
            size_t start = i++;
            while (line[i]) {
                if (line[i++] == '"') {
                    if (line[i] == '"') ++i; else break;
                }
            }
            if (!text_append(&b, line + start, i - start)) goto fail;
            continue;
        }

            if (!text_append(&b, line + i++, 1)) goto fail;
            continue;

解答

a：只存完整词，从每个起点按八个方向逐字符延长候选，直到出界或达到词典最长词长，每一步都做成员查询。b：表项增加 PREFIX 与 WORD 两个标记；真实词同时是自己的前缀，短词若还能继续成长为长词，也继续扫描。查不到前缀立即终止这条射线，只输出有 WORD 标记的候选。

    size_t p = hash % t->m;

小例网格为 THIS／WATS／OAHG／FGDT，词典为 THIS、TWO、FAT、THAT。四种方式都找出 THIS(0,0;0,1)、TWO(0,0;1,0)、FAT(3,0;−1,1)、THAT(3,3;−1,−1)；坐标为零基，分号后是方向增量。一字符词按题目的“起点、方向、长度”约定可在八个方向重复报告，程序保留全部位置而不是只输出一个词名。

设不同前缀记录数为 P、最长词长为 L，真实前缀总字符量为 B。存全部不同前缀需 O(P+B)，最坏 P≤∑w|w|、B≤∑w|w|(|w|+1)/2；共享前缀可能节约很多，但不是所有词典都保证“几乎不增加”。容量按上述条目数上界预留，空词典、空网格可直接结束；输入约定为矩形的大写 ASCII 网格和非空大写词。

最长词长固定时，散列表版本扫描仍是期望 O(RC)，二分版本最坏有 O(RClogP) 次记录比较。L 可变时，增量散列只把求指纹成本从每射线 O(L2) 减为 O(L)；成功前缀相等比较、碰撞验证和输出字符的成本仍需保留。

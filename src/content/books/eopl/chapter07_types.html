7.1 值与类型：安全契约的范围

原书 §7.1，印刷 p.235 / PDF 258。

第三章解释器要到运行时才知道一个值是整数、布尔还是过程。第七章把这个问题提前：不执行程序，仅看语法和变量使用方式，能否保证每个操作都拿到适当种类的值？类型不是给变量贴一个方便的名字，而是描述一组允许运算的契约。

本章“安全”具体指：变量已绑定；减法的两个操作数及 zero? 的操作数为数值；if 的条件为布尔；调用的操作符为过程。安全并不意味着终止，也不排除除零、空表访问等更细的错误。一个安全过程可以一直递归。相反，一个程序这次恰好没有走到错误分支，不等于它在所有输入上都安全。

只记录“这是一个过程”还不够。f 可能是 int→int，也可能是 bool→int；只有知道它接受和返回什么，才能预测 (f 1) 的合法性。基本类型结构因此是 int、bool 和有限嵌套的过程类型。

Type ::= int | bool | (Type -> Type)

定义 7.1.1 · 表达值具有某类型

数值具有 int，布尔值具有 bool。一个过程值具有 a→b，当且仅当把任意 a 类型实参交给它后：要么返回 b 类型值，要么不终止，要么发生本章未列为类型错误的其他错误；不能产生类型错误。这里按有限类型结构归纳定义，安全条件则在类型定义之前独立给出。

例如 proc(x) if x then 11 else 22 是 bool→int；proc(x)x 对任意类型 a 都是 a→a。proc(x) if x then 11 else zero?(11) 无法用本节简单类型描述：条件要求 bool，但两种布尔输入会给出不同基本类型的结果。

原书 p.236 的嵌套过程例 proc(x)proc(y) if y then x else 11 的类型写为 int→(bool→int)，这个类型是对的；相邻英文解释却说先给布尔值。应先给整数 x，再给布尔 y。此处按程序、类型和实际执行说明该顺序。

阅读注解
语义与分析

值的契约不是一次测试结果

过程类型对所有合适实参负责；有限测试只能给见证，不能证明全称性质。习题7.1的第13式用有限近似解释语义安全，习题7.12则显示相同语法不在简单类型算法的接受集合中。

保守性

拒绝不等于执行一定出错

一个健全分析器可以拒绝实际安全的程序。if zero?(0) then 11 else zero?(1) 总返回11，但本章规则仍检查两支并因类型不一致而拒绝。健全性保证的是接受后安全，不是安全就一定接受。

习题 7.2 · ★★

原题

按照定义 7.1.1，是否存在恰好具有两种类型的表达值？

印刷 p.238 / PDF 261

解答与执行

在本节纯 LETREC 和有限简单类型语言中，不会恰好只有两种：没有类型、只有一种或有无限多种都可能。数值和布尔值各只有自己的基本类型；过程若只有一个完全确定的输入/输出类型，也可只有一种，例如 proc(x) -(x,1)。

关键是“至少两种”不能靠列出两个例子就结束。对过程的契约从外到内比较两种不同类型：算术可观察的位置必须固定为 int，条件可观察的位置必须固定为 bool，应用可观察的位置必须是具有相应参数/结果结构的过程。它们不允许一个位置只取 int、bool 两者却排除其余全部结构。剩余能够不同的位置只能作为同一个不透明类型参数被传递或忽略；保持其各次出现一致，可以把它替换成任意有限类型。例如依次取 int、bool、int→int、int→(int→int) 等，得到无限多个不同实例。若一个调用在所有相应实参上均不返回，则结果类型也不受限制，同样有无限多个。

这里使用的是本节构造的语义可观察性：没有类型测试、联合类型或专门的类型分派原语。加入这些能力后要重新论证，不能沿用结论。也不能单用后面的“主类型有自由变量”来证明本题，因为定义 7.1.1 的语义类型与算法可推出的类型并不相同。

习题 7.3 · ★★

原题

对于 LETREC 语言，给定表达值 val 和类型 t，判断 val 是否具有类型 t 是可判定的吗？

印刷 p.238 / PDF 261

解答与执行

不可判定。固定任意机器 M 及输入 w，在 LETREC 中用只进行合法整数操作的递归过程模拟它。构造闭包 v：

proc (unused)
  let ignored = simulate-M-on-w
  in -(zero?(0),1)

创建 v 不执行模拟。调用它时，若 M(w) 不停机，调用也一直运行，因而符合定义 7.1.1 对 int→int 的许可；若 M(w) 停机，后面的减法把布尔值当整数，产生类型错误，v 就不具有 int→int。若能决定 v 是否具有该类型，就能决定 M(w) 是否不停机，进而决定停机问题，矛盾。

构造中的模拟器可由整数编码的寄存器机给出，测试、加减和递归本身都不越过类型边界。因此困难确实来自是否会走到最后的错误，而非模拟器事先出错。CHECKED/INFERRED 决定的是其有限规则可否给出类型推导，接受集合是一个可判定的安全子集。

7.2 给表达式赋类型：规则与类型环境

原书 §7.2，印刷 p.238 / PDF 261。

运行环境把名字关联到值或位置；类型环境 Γ 把名字关联到类型。类型分析沿语法递归，遇到绑定就扩展类型环境，却不去计算变量的运行值。

Γ⊢e:τ

这读作“在 Γ 的假设下，e 具有类型 τ”。若运行环境确实满足 Γ，则 e 返回时给出 τ 类型值，或不终止，或发生不属于本章类型错误的错误。这正是分析器与运行解释器之间的联系。

语法要核对什么结果
nn是整数常量int
x查Γ(x)，不能漏掉未绑定检查Γ(x)
-(e1,e2)两个子式均为intint
zero?(e)e为intbool
if c then a else bc为bool，两支同型tt
let x=e in body先用旧Γ求e类型t，再用Γ[x:t]分析bodybody类型
(f arg)f为a→b，arg为ab

真正缺的信息在 proc：只看到参数名 x，并不知道它应取哪种类型。检查方案让程序员给出参数类型，推导方案则先放一个未知量，再从使用位置约束它。二者使用相同类型规则，主要差别是缺失信息从哪里来。

作用域仍完全沿用第三章。例如 let x=zero?(0) in let f=proc(y:int) if x then y else 0 in let x=3 in (f 4)，检查 f 的正文时 x:bool；后来的 x:int 不改写这个环境。执行时 f 保存的也是早先 x 的值，所以类型环境与闭包环境在绑定关系上相对应。

阅读注解
两种环境

类型环境也遵循词法作用域

类型环境不是运行环境的快照，也不含当前整数200或位置4。它保存的是“这个绑定的值必须满足哪种契约”。进入过程时扩展参数绑定，离开局部作用域后恢复外层绑定。

规则读法

横线上方是前提

应用规则既要求操作符为过程，也要求实参匹配其参数类型。只检查“这是过程”会漏掉把bool传给int→int；只把两者分别分析而不比较，也没有完成应用规则。

习题 7.4 · ★

原题

用本节规则，仿照原书 p.5 的推导，为 proc (x) x 和 proc (x) proc (y) (x y) 分别写出类型推导。每个项至少赋予两种类型。这些表达式的值是否具有相同的那些类型？

印刷 p.240 / PDF 263

解答与执行

令 a、b 为任意类型。第一式的推导只有变量规则和过程规则：

Γ,x:a ⊢ x:a
------------------- proc
Γ ⊢ proc(x)x : a -> a

取 a=int 和 a=bool，分别得到 int→int、bool→bool。第二式先在含 x、y 的环境里使用应用规则，再连续抽掉两个参数：

Γ,x:(a->b),y:a ⊢ x:(a->b)     Γ,x:(a->b),y:a ⊢ y:a
---------------------------------------------------------------- app
Γ,x:(a->b),y:a ⊢ (x y):b
---------------------------------------------------- proc y
Γ,x:(a->b) ⊢ proc(y)(x y):a->b
---------------------------------------------------- proc x
Γ ⊢ proc(x)proc(y)(x y):(a->b)->(a->b)

例如取 (a,b)=(int,int) 与 (bool,int)，得到 ((int->int)->(int->int)) 和 ((bool->int)->(bool->int))。相应值确实具有这些类型：第一式原样返回实参，第二式把正确类型的实参交给正确类型的过程。二者各自的表达式类型与值的语义契约吻合；不是说这两个不同表达式具有相同的类型集合。

7.3 CHECKED：按标注检查程序

原书 §7.3，印刷 p.240 / PDF 263。

CHECKED 保持 LETREC 的求值语义，增加参数标注和递归过程的返回标注。返回标注只描述过程体的结果：double 的结果类型为 int，double 这个值的类型则为 int→int。

letrec int double(x : int) =
  if zero?(x) then 0 else -((double -(x,1)),-2)
in (double 3)
位置类型环境或结果
先安装递归签名Γrec = Γ[double : int->int]
进入过程体Γbody = Γrec[x:int]
条件zero?(x)x:int，因此条件bool
递归调用x−1:int；double接受int，结果int
两支与返回声明0:int；递归结果加2仍int，等于声明int
in正文double(3):int，执行得到6

先安装签名，才可能在检查 double 时认识 double 自己。签名是假设，随后必须检查正文确实兑现它；若跳过这一步，程序员写一个假的 bool 返回标注就能骗过检查器。

阅读注解
递归假设

签名先用，正文后验

递归类型检查不靠执行一次递归来猜结果。它把声明当作待验证假设，再检查每个返回路径；这与递归程序规格中使用归纳假设的结构相似。

模型边界

标注不会改变运行值

求值器忽略类型标注，仍按原来的闭包和参数绑定求值。类型检查失败时应停止进入正常执行入口，不能指望标注在运行时把布尔自动转换成整数。

7.3.1 检查器：从规则到递归程序

原书 §7.3.1，印刷 p.242 / PDF 265。

实现时每条规则对应一个递归分支。常量和变量直接返回类型；算术和条件先分析子式，再做结构相等检查；过程在扩展的类型环境里分析 body；调用拆开过程类型并逐一比较实参。完整实现是本页程序区的 checked-type。

类型以 int/bool/void 原子或带标签的树表示。相等是完整结构相等，int→bool 与bool→int不能只比较最外层“过程”标签。发生错误时同时保存出错 AST 结点和类别，便于区分条件、未绑定变量、参数个数和普通类型冲突。

随着习题加入复合数据，序对保存两个可以不同的分量类型，表保存共同的元素类型，引用保存位置内容的类型。运行时可能有多个名字共享一个位置，静态分析也必须让这些使用点约束同一内容类型。

阅读注解
错误顺序

先检查条件再检查两支

先检查测试的类型可以更早报告根本问题；不会因此跳过一个类型正确条件的任一分支。习题7.7实际比较两个错误顺序。

信息隐藏

void不是万能类型

void表示写入操作不暴露有用返回信息，不是可以代替int或bool的顶类型。写入动作的目标和值仍须严格配型，void结果不能进入减法或if条件。

习题 7.5 · ★★

原题

扩展检查器，使其支持一个 let 中的多个声明、多参数过程及一个 letrec 中的多个声明。为了支持多参数过程，需要增加形如 (t1 * t2 * ... * tn -> t) 的类型。

印刷 p.243 / PDF 266

解答与执行

多元过程类型保存参数类型列表与结果类型。应用要求实参数量相同，并逐项核对；不能用 zip 截断多出的参数。并行 let 的每个右侧都在旧环境检查，全部完成后再同时扩展正文环境。letrec 则先把整组过程的签名装入一个环境，再逐个检查正文；检查某个过程时，只额外加入它自己的形参。

letrec int even(x:int)=if zero?(x) then 1 else (odd -(x,1))
       int odd(x:int)=if zero?(x) then 0 else (even -(x,1))
in (odd 13)

直接检查结果 int，执行结果 1。实现见 checked-type 的 let/rec/call 分支。(proc(x:int,y:bool) if y then x else 0 4 zero?(0)) 为 int，执行得4；少参数、多参数、重复形参和重复递归名字都明确报错。

习题 7.6 · ★

原题

扩展检查器，使其支持赋值（§4.3）。

印刷 p.243 / PDF 266

解答与执行

赋值的目标必须已在类型环境中，右侧类型须等于该变量既定的类型；赋值不会改变类型环境。沿用第四章的哨兵返回值27，赋值表达式的类型为 int：

Γ(x)=t     Γ ⊢ e:t
--------------------------
Γ ⊢ set x=e : int

let x=0 in begin set x=4; x end 检查为 int，执行得4；单独 set x=4 执行得27。把 x 改写成布尔值会被拒绝。到多态扩展时，具有全称量化类型方案的 let 名字不允许再赋值；可赋值变量只持有一个单态类型，避免通过更新破坏所有使用点的契约。

习题 7.7 · ★

原题

修改 if-exp 的检查代码：若测试表达式不是布尔类型，就不再检查另外两个表达式。给出一个表达式，使新旧检查器表现不同。

7.4 INFERRED：把未知类型变成约束

原书 §7.4，印刷 p.248 / PDF 271。

原书这一节开头的 even/odd 示例把 odd 的返回类型标成 bool，但两个过程的基例与递归分支实际都返回整数0或1。按程序应将该返回标注改为 int；这与把过程参数 x 的类型改成 bool 是两回事。习题7.5/7.15的运行版本采用 int 返回，输入13得到1。

INFERRED 把缺省标注写成 ?。每一处 ? 先获得独立类型变量；相同程序变量的多次出现则使用同一个类型表达式。类型变量表示“尚未解出的类型”，不是运行时值，也不是可以随意同时当整数和布尔的动态类型。

贯穿例子取原书的 proc(f) proc(x) -((f 3),(f x))。给 f、x、两个过程、减法及两次调用分别命名，再按规则列方程：

t0 = tf -> t1           外层过程
t1 = tx -> t2           内层过程
t3 = int, t4 = int      减法的两个操作数
t2 = int                减法结果
tf = int -> t3          调用(f 3)
tf = tx -> t4           调用(f x)
处理步骤已经确定的信息
先处理减法t2=t3=t4=int
应用到第一次调用tf=int->int
把第二次调用的tf替换掉(int->int)=(tx->int)
分解箭头的对应位置tx=int，结果int=int
回填内层、外层过程t1=int->int; t0=(int->int)->(int->int)

这里的回填不能省略：当 tx 从未知变成 int 时，之前已经保存的 t1、t0 也要反映这一事实。若一直打印早先那棵未解释的树，会把本已确定的类型显示成未知。

两类失败必须分开理解。proc(x) if x then -(x,1) else 0 强制同一变量既是 bool 又是 int，是构造子冲突。proc(f) zero?((f f)) 强制 α = α -> int，则不是两个基本类型不等，而是要求一个有限类型树包含自身。

阅读注解
鲜变量

同一个问号、同一个绑定

每处缺省独立分配，绑定后重复使用共享。若每次读变量都新建未知量，int/bool冲突就会被掩盖；若所有问号共用一个量，又会错误地把独立参数绑在一起。

多态边界

未知类型还不是let多态

proc(x)x 得到a→a只表示整段表达式有一族实例。基本INFERRED把let名字绑定到一个共享的类型表达式；要让同一名字每次使用都有独立实例，还需类型方案和实例化。

7.4.1 替换：保存已经得到的信息

原书 §7.4.1，印刷 p.260 / PDF 283。

替换 σ 是类型变量到类型表达式的有限映射。对复合类型递归应用它，对未知变量查它。例如先有 a -> b，后来确定 b=int，得到的不是两条互不相干的记录，而是一份能把 a 解释成 int 的替换。

原书采用积极回填：加入新绑定时，立即把它作用到所有旧右侧。因此任何已绑定变量都不会残留在任一右侧，apply 时查一次就够。链式表示把工作移到查询时，允许 a→b→int，查询需递归跟随。两种表示的外部含义相同，更新与查询成本不同。

查看实现 · substitution-core
(define (apply-one t variable replacement)
  (cond [(equal? t variable) replacement]
        [else (map-type (lambda (x) (apply-one x variable replacement)) t)]))
(define (apply-eager t subst)
  (cond [(tv? t) (cond [(assoc t subst) => cdr] [else t])]
        [else (map-type (lambda (x) (apply-eager x subst)) t)]))
(define (extend-eager subst variable replacement)
  (cons (cons variable replacement)
        (for/list ([binding subst])
          (cons (car binding) (apply-one (cdr binding) variable replacement)))))
;; Lazy bindings may mention previously bound variables. They must remain acyclic.
(define (apply-lazy t subst #:memo? [memo? #f] #:visits [visits (lambda (_) (void))])
  (define memo (make-hash))
  (define active (mutable-set))
  (define (walk t)
    (cond
      [(tv? t)
       (cond [(and memo? (hash-has-key? memo t)) (hash-ref memo t)]
             [else
              (when (set-member? active t) (type-error 'occurs t "cyclic substitution at ~a" t))
              (visits t) (set-add! active t)
              (define answer (cond [(assoc t subst) => (lambda (p) (walk (cdr p)))] [else t]))
              (set-remove! active t) (when memo? (hash-set! memo t answer)) answer])]
      [else (map-type walk t)]))
  (walk t))

本章实现提供 eager、lazy、memo、walk、global、vector 六个入口。它们是替换/合一的表示选择，不是六种不同类型规则。关联表查找随绑定数量线性增长；备忘与路径压缩减少重复追链；向量提供直接索引，完整类型遍历仍与结构大小有关。

阅读注解
不变量

强规范形与无环不是一回事

eager保存完全回填的右侧；lazy可保存指向其他已绑定变量的链。前者的强无出现不变量在后者中不成立，但后者仍需要无环，才能给出有限类型和终止的解引用。

7.4.2 合一：求解有限类型树

原书 §7.4.2，印刷 p.262 / PDF 285。

合一器把一个新方程加入当前解。先用当前替换解释两边，再分情况：相同则删除；一边是未知变量则检查并绑定；两边是相同构造则逐分量合一；不同构造或参数个数不符则拒绝。

α=α→β

该方程不能通过有限类型求解：右侧包含左侧整棵树再加箭头和结果树，大小严格更大。发生检查因此要穿过整个候选右侧，而且应先解释旧替换；a=b、b=(a→int) 也是环，不能因 b 没有直接出现在表面右侧就放过。

查看实现 · unifier-core
  (define (unify! a b [context #f])
    (count! 'equations)
    ;; 'walk' and 'vector' dereference only a root variable, then recurse.
    (define left ((if (memq engine '(walk vector)) root resolve) a))
    (define right ((if (memq engine '(walk vector)) root resolve) b))
    (cond
      [(equal? left right) (void)]
      [(tv? left)
       (when (occurs? left (resolve right))
         (type-error 'occurs context "occurrence check: ~a in ~a" left right))
       (bind! left right)]
      [(tv? right) (unify! right left context)]
      [(and (ty? left) (ty? right) (eq? (ty-tag left) (ty-tag right))
            (= (length (ty-parts left)) (length (ty-parts right))))
       ;; Every later child uses the substitution updated by earlier children.
       (for ([x (ty-parts left)] [y (ty-parts right)]) (unify! x y context))]
      [else (type-error 'mismatch context "cannot unify ~a and ~a" (external left) (external right))]))

箭头分解的先后关系同样关键：统一参数得到新替换，再用它统一结果。(a->a)=(int->bool) 应拒绝；若结果检查读旧替换，就可能分别接受 a=int 与a=bool，掩盖共享位置的矛盾。

a=a 是平凡方程，直接删除；不能把它当成发生检查失败。a=(a→b)才要求自包含的有限树。算法分支的顺序因此有语义作用。

原题

多态与效果的相互作用很微妙。考虑以下程序开头：

  2. 限制 let 右侧表达式对存储没有效果，避免这个问题。这称为值限制。

(define unsafe-reference
  "let p = newref(proc (x : ?) x)
   in begin
     setref(p,proc (x : int) -(x,1));
     (deref(p) zero?(0))
   end")

若把 p 泛化为 ∀a. refto(a->a)，写入点可把它实例化为 refto(int→int)，读取点又可实例化为 refto(bool→bool)。推导器于是声称最后调用返回 bool。但运行时 p 只有一个位置，里面已被换成对整数做减法的过程；再传入 zero?(0) 的布尔值就出现 runtime-type 错误。不是运行时真的生成了两份引用，而是类型分析错误地准许同一位置拥有彼此独立的内容类型。

infer unsafe-reference #:polymorphism 'w #:value-restriction? #f 的实际结果是 bool，单独 evaluate 则报 runtime-type；启用默认值限制后推导报 mismatch。因而第二问的修复确实阻止了反例，不只是改变显示的类型名。

实现使用非扩张右侧作为“不会分配/修改存储”的保守可判定近似：常量、变量、过程、空表，以及由非扩张分量构成的不可变数据可泛化；newref、赋值和未知过程调用不泛化，参数和环境共享的未知变量始终不泛化。可变序对模式下 newpair 也视为分配效果。同时，已泛化 let 名字禁止再赋值；否则即使初始右侧是纯恒等过程，也能通过替换该绑定破坏契约。某些无副作用的调用也会被保守拒绝；这是该语法近似的边界，不是声称精确决定所有程序的存储效果。

(define (make-solver [engine 'eager])
  (unless (memq engine '(eager lazy memo walk global vector))
    (error 'make-solver "unknown engine ~a" engine))
  (when (eq? engine 'global) (set! global-substitution '()))
  (define subst '())
  (define cells (make-vector 16 #f))
  (define stats (make-hasheq '((lookups . 0) (bindings . 0) (equations . 0))))
  (define (count! key) (hash-update! stats key add1 0))
  (define (alist) (if (eq? engine 'global) global-substitution subst))
  (define (capacity! n)
    (when (>= n (vector-length cells))
      (define next (make-vector (max (add1 n) (* 2 (vector-length cells))) #f))
      (vector-copy! next 0 cells) (set! cells next)))
  (define (binding v)
    (count! 'lookups)
    (if (eq? engine 'vector)
        (begin (capacity! (tv-id v)) (vector-ref cells (tv-id v)))
        (cond [(assoc v (alist)) => cdr] [else #f])))
  (define (root t)
    (if (tv? t)
        (let ([b (binding t)])
          (if b
              (let ([r (root b)])
                (when (eq? engine 'vector) (vector-set! cells (tv-id t) r)) r)
              t)) t))
  (define (resolve t)
    (cond [(eq? engine 'eager) (apply-eager t subst)]
          [(memq engine '(lazy memo global))
           (apply-lazy t (alist) #:memo? (eq? engine 'memo)
                       #:visits (lambda (_) (count! 'lookups)))]
          [else (define r (root t)) (map-type resolve r)]))
  (define (bind! v t)
    (count! 'bindings)
    (case engine
      [(eager) (set! subst (extend-eager subst v t))]
      [(vector) (capacity! (tv-id v)) (vector-set! cells (tv-id v) t)]
      [(global) (set! global-substitution (cons (cons v t) global-substitution))]
      [else (set! subst (cons (cons v t) subst))]))
;; BEGIN unifier-core
  (define (unify! a b [context #f])
    (count! 'equations)
    ;; 'walk' and 'vector' dereference only a root variable, then recurse.
    (define left ((if (memq engine '(walk vector)) root resolve) a))
    (define right ((if (memq engine '(walk vector)) root resolve) b))
    (cond
      [(equal? left right) (void)]
      [(tv? left)
       (when (occurs? left (resolve right))
         (type-error 'occurs context "occurrence check: ~a in ~a" left right))
       (bind! left right)]
      [(tv? right) (unify! right left context)]
      [(and (ty? left) (ty? right) (eq? (ty-tag left) (ty-tag right))
            (= (length (ty-parts left)) (length (ty-parts right))))
       ;; Every later child uses the substitution updated by earlier children.
       (for ([x (ty-parts left)] [y (ty-parts right)]) (unify! x y context))]
      [else (type-error 'mismatch context "cannot unify ~a and ~a" (external left) (external right))]))
;; END unifier-core
  (define (snapshot)
    (if (eq? engine 'vector)
        (for/list ([b (in-vector cells)] [i (in-naturals)] #:when b) (cons (tv i) b))
        (alist)))
  (solver unify! resolve snapshot (lambda () (hash-copy stats))))
(define (external t #:canonical? [canonical? #t])
  (define table (make-hash))
  (define (go t)
    (match t
      [(tv n) (if canonical?
                  (hash-ref! table t (lambda () (string->symbol (format "a~a" (hash-count table)))))
                  (string->symbol (format "ty~a" n)))]
      [(ty 'proc children)
       (define args (drop-right children 1))
       (append (if (null? args) '() (add-between (map go args) '*)) (list '-> (go (last children))))]
      [(ty tag children) (cons tag (map go children))]
      [_ t]))
  (go t))
(define (type-alpha=? a b) (equal? (external a) (external b)))

9.1 面向对象编程：把状态与操作放在一起

原书 §9.1，印刷 p.326 / PDF 349。

第四章的计数器闭包把一个位置和一种操作连在一起；现在希望同一份状态有多种协同操作。对象把这些位置称为字段，把能够访问它们的过程称为方法。类描述一类对象使用的字段布局和方法集合，new 则按这份描述创建一个具体对象。

图 9.1 · 两个字段共同维护一个不变量

原书程序图 9.1，印刷 p.327 / PDF 350。

展开原书讲解程序
class c1 extends object
 field i
 field j
 method initialize (x)
  begin
   set i = x;
   set j = -(0,x)
  end
 method countup (d)
  begin
   set i = +(i,d);
   set j = -(j,d)
  end
 method getstate () list(i,j)
let t1 = 0
    t2 = 0
    o1 = new c1(3)
in begin
    set t1 = send o1 getstate();
    send o1 countup(2);
    set t2 = send o1 getstate();
    list(t1,t2)
   end

初始化把 i/j 设为 3/-3；第一次 getstate 构造列表值 (3 -3)。countup(2) 把原位置中的数分别改为 5/-5；第二次 getstate 构造新的列表。旧列表并不是对字段的活动视图，所以 t1 不会随字段修改而变化。

((3 -3) (5 -5))

两个字段维持 i=−j。客户端需要一个能同时更新二者的方法，单独暴露字段写入会允许破坏该约定。同类对象共享方法，字段位置却应各自独立；有两个计数器不意味着它们的计数自动相同。

图 9.2 · 同一条 sum 消息进入两种方法

原书程序图 9.2，印刷 p.328 / PDF 351。

展开原书讲解程序
class interior-node extends object
  field left
  field right
  method initialize (l, r)
   begin
    set left = l;
    set right = r
   end
  method sum () +(send left sum(),send right sum())
 class leaf-node extends object
  field value
  method initialize (v) set value = v
  method sum () value
let o1 = new interior-node(
          new interior-node(
           new leaf-node(3),
           new leaf-node(4)),
          new leaf-node(5))
in send o1 sum()

根对象是 interior-node，先向左右子树发送 sum。内部节点把两个返回值相加，叶节点直接返回 value；最左内部节点得到 3+4=7，根再得到 7+5=12。调用位置不必先写“如果是叶子就怎样”，方法选择交给接收对象的实际类。

原书例子 · self 支持方法互递归

印刷 p.329 / PDF 352。

展开奇偶互递归程序
class oddeven extends object
 method initialize()1
 method even(n) if zero?(n) then 1 else send self odd(-(n,1))
 method odd(n) if zero?(n) then 0 else send self even(-(n,1))
let o1=new oddeven() in send o1 odd(13)

odd(13) 向同一个 self 发送 even(12)，再交替发送到参数 0。此时 odd/even 不需要作为普通变量互相捕获；它们通过接收对象的方法表相互访问。self 在每次调用中仍是原来的对象。

状态不变量

对象的价值在于协调多个位置

图9.1的两个字段必须总是互为相反数。方法把两次写入放在同一个操作中，客户通过方法访问状态；类只是共享方法的描述，并不让两个实例自动共享字段。

9.2 继承：字段遮蔽、方法覆盖与分派

原书 §9.2，印刷 p.329 / PDF 352。

继承复用父类的字段和方法，再加入子类的增量。CLASSES 采用单继承：父类必须先声明，所有类最终到达没有字段和方法的根类 object。因为 object 没有 initialize，基本语言不能直接 new object()。

图 9.3 · 彩色点复用点的移动行为

原书程序图 9.3，印刷 p.330 / PDF 353。

展开原书讲解程序
class point extends object
 field x
 field y
 method initialize (initx, inity)
  begin
   set x = initx;
   set y = inity
  end
 method move (dx, dy)
  begin
   set x = +(x,dx);
   set y = +(y,dy)
  end
 method get-location () list(x,y)
class colorpoint extends point
 field color
 method set-color (c) set color = c
 method get-color () color
let p = new point(3,4)
    cp = new colorpoint(10,20)
in begin
    send p move(3,4);
    send cp set-color(87);
    send cp move(10,20);
    list(send p get-location(),     % returns (6 8)
         send cp get-location(),    % returns (20 40)
         send cp get-color())       % returns 87
   end

point 实例有 x/y；colorpoint 实例还多一个 color。子类没有覆盖 initialize，因此 new colorpoint(10,20) 使用继承的 point.initialize；颜色由随后发送的 set-color 设为 87。两个对象分别移动，互不改动对方的位置。

阅读注解
两个绑定时机

字段看定义处，普通消息看实际对象

子类声明同名字段会增加一个位置，而不是覆盖父位置。父方法保持原字段视图；普通方法发送则先查实际类的新方法。把这两条规则混合会错误地让父方法读到子字段。

super

固定查找起点，保留真实 self

super从方法宿主的父类开始找方法，但调用时仍传入原对象。父方法内部再次发送普通self消息时，可以回到更深子类的方法；静态起点和动态接收者可以同时存在。

9.3 语言：对象仍建立在隐式引用之上

原书 §9.3，印刷 p.334 / PDF 357。

图 9.7 在 IMPLICIT-REFS 上加入 class/method 声明和 new、send、super、self。表达值在整数、布尔、过程、列表之外加入对象，普通变量的可指称值仍是引用。类是类环境中的描述，不是基本语言中可以任意赋给变量的值；闭包对象和原型是后面习题选择的另一种设计。

Program ::= ClassDecl* Expression
ClassDecl ::= class Name extends Parent FieldDecl* MethodDecl*
MethodDecl ::= method Name (Parameter,...) Expression
Expression ::= new Class (Argument,...)
             | send Expression Method (Argument,...)
             | super Method (Argument,...)
             | self

创建对象有三个阶段：求实参，按类的完整布局分配字段位置，调用 initialize。new 丢弃 initialize 的返回值，返回对象本身。发送消息则取得接收对象的类、找到方法、为每个参数分配新位置，再运行方法体。begin 从左到右执行并返回最后一项；多声明 let 的右侧都在原环境中求值。

因此对象作为参数传递有两层身份：形参变量的位置是新的，里面保存的对象却可能与调用者共享。set 参数名只是重绑形参，fieldset 或通过字段方法更新才会改变共享对象。

阅读注解
位置与值

对象参数按值传递，状态仍可共享

实参对象作为一个值放入新的参数位置，所以重绑形参不重绑调用者变量；双方仍可能指向同一对象及其字段位置，字段写入因此能被调用者观察。

观察边界

构造结果是对象，初始化结果被丢弃

initialize可返回整数或void，但new返回的是刚创建的对象。若把方法返回值当作new的值，就会使随后发送消息的接收者变成数字。

9.4 解释器：先确定对象，再应用方法

原书 §9.4，印刷 p.336 / PDF 359。

程序开始先建立类环境，然后求主表达式。求值器的四个新分支承担不同工作：self 读取当前接收对象；send 按真实类找方法；super 按宿主父类找方法；new 分配字段并调用初始化方法。方法的应用把实参值与对象状态接起来，这一步不能复用调用者的普通局部环境。

表达式方法选择或结果调用时的 self
self直接返回当前接收对象保持
send obj m(args)obj 的实际类中查 mobj
super m(args)当前宿主类的父类中查 m原接收对象
new C(args)C 的 initialize；最终返回新对象新分配对象

阅读注解
求值顺序

有副作用时必须固定操作数顺序

原书send分支以Scheme的let并列计算实参与接收者。伴读明确按实参从左到右、再接收者执行；这是一项实现约定，不能从所有Scheme实现的let推导相同顺序。

词法状态

调用环境不能替代方法的字段环境

方法参数使用新位置，字段使用对象已有位置。若把字段值复制进新位置，initialize和set看似执行了赋值，对象自身却没有更新；回归专门检出这种错误。

9.4.1 对象：类身份与字段位置

原书 §9.4.1，印刷 p.339 / PDF 362。

对象保存实际类身份与一组字段位置。原书把祖先字段排在前面，单继承每次只向右追加新字段，所以祖先方法需要的位置在子类对象中仍处于原下标。图 9.9 的五格依次属于 c1.x、c1.y、c2.y、c3.x、c3.z，初始化后为 11、12、22、31、32。

每次 new 为这些声明分别创建新位置，初值是不可当作合法表达值读取的哨兵。对象别名共享同一组位置，不同对象各自分配。伴读还允许直接保存类记录的替代表示；多重继承扩展则按声明身份映射位置，以处理菱形共享。

阅读注解
字段身份

同名不等于同一个存储位置

c1.y与c2.y各有声明身份。单继承下祖先布局是子类布局的前缀；多重继承若选择菱形共享，则需要显式身份去重和位置映射，不能继续依赖同一前缀。

初始化

先分配不是已经得到合法值

原书把每格置为未初始化哨兵。类型正确的方法仍可能在初始化之前读取它；类型检查基本版不解决这件事，习题9.40另加字段初始化和可见性顺序。

9.4.2 方法：接收者与宿主各司其职

原书 §9.4.2，印刷 p.340 / PDF 363。

原书方法记录保存参数、方法体、宿主父类与字段名列表。伴读采用习题 9.5 的宿主记录表示，再从它取得父类。应用时从内到外建立参数帧、宿主字段帧、宿主静态成员帧；self 与宿主放在独立的调用上下文。方法体中创建的普通过程闭包再捕获这个环境与上下文，保证嵌套过程中的 self/super 仍指向原来的对象/宿主。

(define (invoke-method method receiver values caller)
  (define d (rmethod-decl method)) (define host (rmethod-host method))
  (require-access! (mdecl-visibility d) host caller (mdecl-name d))
  (unless (= (length values) (length (mdecl-params d))) (oo-error 'arity (mdecl-name d) "method argument count mismatch"))
  (unless (is-a? (object-class* receiver) host) (oo-error 'receiver (mdecl-name d) "receiver is not an instance of method host"))
  (count! 'method-calls)
  (event! (list 'invoke (rclass-name (object-class* receiver)) (rclass-name host) (mdecl-name d)))
  (define env (list (make-frame (map car (mdecl-params d)) values)
                    (object-field-frame receiver (field-bindings host))
                    (static-frame (static-bindings host))))
  (evaluate (rmethod-body method) env (rclass-classes host) (context receiver host)))

字段帧装入的是对象已有位置，而不是把字段值复制到新位置。图 9.10 中参数 u/v 的位置保存 7/8，字段视图只有 c2 可见的三个前缀名字，原对象却有五个字段；多出来的位置不会因列表更长就自动进入词法范围。

原书用鲜名字把较早的同名字段隐藏起来，例如 c2 的视图写作 (x y%1 y)。本实现使用不可由源程序伪造的鲜身份完成同样目的，继承的父方法仍保存父视图。

阅读注解
两份类信息

宿主类与实际类可能相距多层

宿主决定字段、private/protected权限和super起点；实际类决定普通消息分派。方法记录被子类继承时不能改写宿主，否则同一个方法会随调用对象改变词法含义。

闭包比较

方法不是普通自由变量闭包

本章CLASSES方法使用参数、字段、self/super与静态成员；不会自动捕获主程序的普通局部变量。习题9.27的闭包对象和9.29的原型模板才显式保存普通词法环境。

9.4.3 类与类环境：把共享结构建好

原书 §9.4.3，印刷 p.342 / PDF 365。

类描述符记录父类、全部字段、当前可见视图和方法环境。处理 class 时先找已声明父类，继承布局，再加入本地字段和方法。类环境以名字找到描述符；对象可以共享这个描述符而拥有自己的字段位置。

图 9.11 的三个类不是三个互相无关的大对象：未覆盖的方法记录可以共享，方法也能共享宿主的字段视图。子类重建自己的名字视图和方法表，却不能改写父类的方法记录。伴读把环境作为可保存的显式对象，让局部类能够离开定义表达式后仍保持原身份。

父类先声明与方法互相引用并不冲突。先建立全部全局类描述符和方法签名，再翻译/执行方法体，方法可以创建后面声明的类的实例；它不需要在类声明处理时就运行那个方法。静态成员初始化则有独立的从左到右执行顺序，见习题 9.15。

阅读注解
构建次序

父类先于子类，方法体可以互相引用

布局要从已知父类构造，因此extends有次序要求；方法体则在整个全局类环境建立后才执行，可以引用稍后声明的类。把这两种前向引用混为一谈会过度拒绝合法程序。

类与对象

共享描述符不共享实例状态

习题 9.1 · ★

原题

使用本节的语言实现以下内容：

  1. 一个队列类，具有 empty?、enqueue 和 dequeue 方法。
  2. 扩展这个队列类，增加计数器，记录当前队列已执行的操作次数。
  3. 再次扩展队列类，增加计数器，记录该类的全部队列已执行的操作总次数。提示：可以在初始化时传入一个共享的计数器对象。

印刷 p.347 / PDF 370

解答与执行

用两个列表保存队列：front 的头是下一个出队值，rear 逆序保存新入队值。入队只把新值放到 rear 的头；出队时若 front 为空，就反转 rear 作为新的 front，再清空 rear。每个元素至多跨越两个列表一次，所以空判断和入队为常数步，连续出队的摊销成本也是常数步；一次触发反转的出队仍可能是线性步。空队列出队在本实现报告空表访问错误。

计数扩展保留父队列实现。每个公开的 empty?、enqueue、dequeue 调用先调用一次 tick，再用 super 执行队列操作；父实现直接操作字段，不再次调用这三个公开方法，所以不会重复计数。count 记录当前对象的请求数，total 指向单独的计数器对象；把同一对象交给所有队列就得到跨队列总数。初始化和两个计数观察方法不计入操作数。

习题 9.11 · ★★

原题

扩展 CLASSES，允许把每个方法指定为以下三种访问级别之一：private 只能从宿主类内部访问，protected 只能从宿主类及其后代类访问，public 可以从任何地方访问。许多面向对象语言都提供某种形式的这一特性。

印刷 p.348 / PDF 371

解答与执行

在方法声明中保存访问级别及声明宿主。每个调用同时携带调用位置的词法宿主：public 总允许；private 要求调用宿主与声明宿主相同；protected 要求调用宿主等于声明宿主或是其后代。程序主表达式没有宿主，因此只能调用 public 方法。判断依据是调用处的类，而不是接收者的实际类。

 protected method middle()23

class B extends A

let b=new B() in list(send b reveal(),send b inherited-access())
(17 23)

A.reveal 能调用 A 的 private secret；B.inherited-access 能调用 A 的 protected middle。顶层直接发送 secret 或 middle 都报访问错误。方法经继承、super、named-send 或编译为直接方法引用后仍经过相同的入口检查。有类型版本还禁止把继承的公开方法覆盖成更窄的访问级别，避免原来合法的客户调用失效。

习题 9.28 · ★★★

原题

给习题 9.27 的语言增加继承。

印刷 p.352 / PDF 375

解答与执行

增加 newobject extends parent ... endnewobject。复制父对象的方法映射，再用本地同名方法覆盖；继承的闭包保留原来的状态环境。但 getmethod 返回绑定方法时必须把 self 设为当前子对象，而不是固定成父对象，否则父方法内部的相互调用看不到子方法覆盖。

完整程序与调用
let make=proc()
 let x=0 in newobject
  get=proc()x
  inc=proc()set x=+(x,1)
  m=proc()(getmethod(self,n))
  n=proc()1
 endnewobject
in let parent=(make)
in let child=newobject extends parent n=proc()2 endnewobject
in begin (getmethod(child,inc));
 list((getmethod(parent,get)),(getmethod(child,get)),(getmethod(parent,m)),(getmethod(child,m))) end
(1 1 1 2)

父子闭包对象共享父环境中的 x，因此 child.inc 后双方 get 都为 1；父对象的 m 经自身 n 返回 1，子对象继承的 m 经子对象覆盖的 n 返回 2。这是一种明确的共享状态继承/委托设计；如果希望复制状态，必须另行定义位置复制规则，不能只复制闭包列表就宣称状态独立。

习题 9.29 · ★★★

原题

设计并实现一种没有显式类的面向对象语言，让每个对象包含自己的方法环境；这种对象称为原型（prototype）。用一个没有字段或方法的原型对象替代类 object。向它的原型增加字段和方法，以得到扩展后的新原型。因此，可以写 let c2 = extend c1 ...，替代 class c2 extends c1 ...。用操作 clone 替代 new；它接受一个对象，直接复制其方法与字段。此语言的方法出现在词法作用域中，所以应当像通常情况那样访问词法可见变量，同时也能访问字段变量。如果父原型的字段变量与外层词法作用域中的变量同名，应采用何种遮蔽关系？

印刷 p.352 / PDF 375

解答与执行

原型包含字段身份到位置的映射、可见字段视图及方法模板。extend 复制父原型的字段值到新位置，加入新字段和新方法；clone 同样复制字段位置并共享方法模板。方法模板保存声明时的词法环境与字段视图，调用时再把模板中的字段身份关联到当前接收原型的位置。

完整程序与调用
let object=emptyobject x=100 z=7
in let parent=extend object field x=3 method get()+(x,z) method inc()set x=+(x,1) endextend
in let a=clone parent b=clone parent
in begin send a inc();list(send parent get(),send a get(),send b get()) end
(10 11 10)

词法变量 z=7 被方法捕获，父原型的 x=3 遮蔽外层 x=100；clone 得到的 a/b 分别有自己的 x 位置。a.inc 只改变 a，故三次 get 分别为 10、11、10。规则为参数/方法局部变量优先，其次为方法声明时可见的字段，再其次是外层词法变量；因此题目所问的祖先字段也优先于同名外层词法变量。子原型同名字段另分配身份，不会改变继承方法已经绑定的祖先字段。

这里的复制是浅复制：字段位置新建，字段中若存对象仍共享那个对象；被闭包捕获的外层变量位置也仍共享。单独复制字段不能递归复制整个对象图。

9.5 有类型的语言：对象可以拥有多个类型

原书 §9.5，印刷 p.352 / PDF 375。

TYPED-OO 给字段、参数和方法结果加上类型，再加入接口、子类型、cast 和 instanceof。一个对象只有一个实际创建类，却可以属于多个类型：本类、祖先类，以及本类或祖先显式实现的接口。类共享实现，接口描述一组能够安全发送的消息；两者不能混作同一条继承链。

定义 9.5.1 · 对象值具有某个类型

若 C 是类，值具有 C 类型当且仅当它是 C 或其后代类的实例。若 I 是接口，值具有 I 类型当且仅当它是某个实现 I 的类的实例；类在自身声明 implements I，或从某个祖先继承这一声明，就实现 I。其他类型继续采用定义7.1.1的规则。

因此“实际类相同”比“能用于同一个类型位置”更严格。对象可以有多个类型，不等于一次创建了多个对象，也不等于运行时会根据变量声明类型改变其实际类。

9.6 类型检查器：签名、子类型与安全调用

原书 §9.6，印刷 p.358 / PDF 381。

检查器首先收集全部类与接口的名义关系、字段类型、方法签名，再检查每个方法体和接口履约，最后检查主表达式。原书图 9.14/9.17 分别给对象表达式与三类调用规则；图 9.18–9.22 展示静态类环境的构造和方法声明验证。检查阶段不执行方法，也不通过试运行判断类型。

类型名字可以在方法签名中前向引用后声明的类；继承边则必须先验证父类或父接口已按允许的顺序声明、种类正确。先为所有名字收集头部，再验证整张继承关系，最后才能用祖先查询比较签名。否则，后面一个非法的自继承可能在前面接口的前向类型比较中导致无限循环；这种声明应报告类错误。

调用规则先确定目标方法的过程类型，检查实参个数，再要求每个实参类型是对应参数类型的子类型。new 还要求目标为具体类，并用所建类的 initialize 签名检查实参，结果类型为所建类；send 则只允许静态类/接口中承诺存在的方法。

子类型关系包括类继承、类实现接口以及过程类型。过程的实参方向与结果方向相反：

A2<:A1,B1<:B2⇒(A1→B1)<:(A2→B2)

客户只会提供 A2 的实参，能够接受更一般 A1 的过程当然能处理；它返回更具体 B1 的结果，也满足客户期待的 B2。这就是图 9.15/9.16 的理由。若把参数方向也写成协变，就会允许子方法要求父类型客户无法提供的更具体实参。

(define (subtype? a b classes)
  (or (equal? a b)
      (and (nominal? a classes) (nominal? b classes) (nominal-below? a b classes))
      (match* (a b)
        [((list 'proc as ar) (list 'proc bs br))
         (and (= (length as) (length bs))
              (for/and ([expected bs] [accepted as]) (subtype? expected accepted classes))
              (subtype? ar br classes))]
        [(_ _) #f])))

方法体实际类型须是声明结果类型的子类型；覆盖方法的完整过程类型须是父方法过程类型的子类型；实现接口时则逐个核对全部要求的方法。initialize 的覆盖签名被特别豁免，以允许子类有不同构造参数，但每个构造器自身的方法体仍要符合结果声明。

这项豁免使基本检查器对显式 initialize 调用的保证有限。伴读保留 textbook 模式供复现，并提供 new-only 模式禁止所有显式初始化调用。字段未初始化、总不终止、奇偶方法返回错误整数等，也不是基本类型规则能全部排除的问题；相应扩展或行为证明在习题中分别处理。

此外，原书运行期方法环境从 empty-env 构造，而图 9.20 的静态方法环境底部写 init-tenv。伴读让两者都只以参数、字段与静态成员为底，避免仅因主程序初始环境有某个名字，就接受运行时实际未绑定的自由变量。

阅读注解
安全范围

通过类型检查不保证表示不变量或终止

错误的even仍可能返回合法整数，递归也可能不终止。基本检查器不验证字段已初始化，initialize还有特殊覆盖规则；额外安全性质应使用相应扩展并说明条件。

可替换性

覆盖方法不能要求更多、承诺更少

习题 9.33 · ★

原题

扩展类型检查器，保证以下安全性质：instanceof 与 cast 绝不作用于非对象值，其目标类型也绝不是非类类型。

印刷 p.367 / PDF 390

解答与执行

分别检查两端：操作数类型必须是已登记的类或接口类型，保证其值为对象；目标名字必须存在且对应具体类描述符，不能只是一个同名接口、int 或未知名字。原书图 9.14 主要检查操作数的 class-type 构造，没有把“名字确实指向类”全部写出来。

(unless (nominal? operand-type classes)
  (oo-error 'object expression "operand must be object"))
(static-class classes target-name #t) ; #t 要求具体类

接口类型可以作为操作数，因为实现该接口的值仍是对象；接口不能充当本语言 cast/instanceof 的目标，运行器沿的是类继承关系。本实现默认包含这项扩展，非对象、接口目标、原始类型目标和未知名字都实际拒绝。

习题 9.34 · ★

原题

只有当 e 的类型是 c 的后代或祖先时，表达式 cast e c 才可能成功。为什么？扩展类型检查器，保证只有满足这一性质时程序才会执行转换表达式；相应扩展 instanceof 的检查。

印刷 p.367 / PDF 390

解答与执行

对两个具体类类型，结论来自单继承树：若某对象同时属于 A 和 C，它的唯一祖先链必须同时经过二者，因此 A/C 必有祖先关系；两个不相关的兄弟类不存在共同实例。related 模式据此要求源类类型与目标类类型至少有一个方向的继承关系，cast 和 instanceof 使用同一检查。

(check program #:options (hash 'casts 'related))

源类型若是接口，原题的“祖先或后代”说法不能直接照用。例如接口 I 被类 A 实现，参数 x 的静态类型是 I，而实际对象来自 A；cast x A 可以成功，尽管 I 不在 A 的类父链上。伴读对此保留运行时检查，不因为“不是类祖先”而错误拒绝。反例、向上/向下转换、兄弟类拒绝以及会失败的运行时转换均已执行。instanceof 只给出布尔结果，本语言没有自动流式缩窄类型，后续专有方法访问仍需要 cast。

习题 9.35 · ★

原题

扩展类型检查器，保证 initialize 方法只能从 new-object-exp 内部调用。

印刷 p.367 / PDF 390

解答与执行

给方法调用检查增加构造器名字门禁：send、named-send 和 super 只要显式调用 initialize 就拒绝；new 在自己的专门分支中检查实参与实际构造器的签名。

(check program #:options (hash 'initialization 'new-only))

这修补了 initialize 的特殊覆盖规则留下的缺口：A.initialize 可以收一个整数，B.initialize 可以改成零参数；若普通客户把 B 对象当 A 传入，按 A 的签名显式调用 initialize，运行时却会动态找到 B 的零参数版本。原书基本规则可能接受该调用，运行时仍因参数个数出错；new-only 模式在执行前拒绝它。严格按题意时，构造器里的 super initialize 也属于显式调用，因此同样禁止。

习题 9.36 · ★

习题 9.37 · ★★

原题

TYPED-OO 使用动态分派。另一种设计是静态分派：方法的选择取决于对象的类型，而不是对象的实际类。考虑下面的例子：

class c1 extends object
 method int initialize () 1
 method int m1 () 11
 staticmethod int m2 () 21
class c2 extends c1
 method void m1 () 12
 staticmethod int m2 () 22
let f = proc (x : c1) send x m1()
    g = proc (x : c1) send x m2()
    o = new c2()
in list((f o), (g o))

调用 f 和 g 时，x 的类型为 c1，但绑定的是 c2 对象。m1 使用动态分派，因此调用 c2 的方法，返回 12；m2 使用静态分派，因此对 x 发送 m2 会调用与 x 的类型 c1 关联的方法，返回 21。修改第 9.5 节解释器以支持静态方法。提示：考虑在环境中保留类型信息，使解释器能在 send 中确定目标表达式的类型。

印刷 p.368 / PDF 391–392

解答与执行

题面中的 method void m1 () 12 与整数 12 的方法体不一致，也不满足父类 int 返回类型；原写法应被检查器拒绝。下面只把该处 void 改为 int，保留其余程序，从而验证题目希望讨论的分派。

仅修正返回标注后的静态分派程序
class c1 extends object
 method int initialize () 1
 method int m1 () 11
 staticmethod int m2 () 21
class c2 extends c1
 method int m1 () 12
 staticmethod int m2 () 22
let f = proc (x : c1) send x m1()
    g = proc (x : c1) send x m2()
    o = new c2()
in list((f o), (g o))
(12 21)

检查 send 时，先按目标表达式的静态类型找到方法声明。普通 m1 保留动态 send；staticmethod m2 则改写为包含静态类名的 static-send。在 f/g 的体内，x 的类型都是 c1，因此 g 选定 c1.m2；对象本身仍是 c2，f 的普通调用找到 c2.m1。

习题 9.38 · ★★

原题

为什么必须先把类的信息加入静态类环境，再检查方法？提示：考虑方法体调用 self 上的方法时会发生什么。

印刷 p.371 / PDF 394

解答与执行

检查方法体需要知道所有被调用方法的签名，尤其 self 上尚未检查、或写在后面的其他方法。若一边看到声明一边立即查体，A.f 调用后面声明的 A.g 就会被误判为不存在；A 的方法构造稍后声明的 B 对象也有同样问题。

因此分两阶段：先登记类/接口、父关系、字段类型和全部方法签名，再逐个检查方法体、覆盖兼容和接口履约，最后检查主表达式。这类似 letrec 先把整组函数的已声明类型加入环境，再检查每个函数体。签名收集不执行方法，也不等于已经认可方法体；后续仍必须逐项验证。前向 self 调用和跨类调用都有实际通过用例。

习题 9.39 · ★★

原题

使类型检查器阻止对 initialize 的所有调用，只允许 new 内部的隐式调用。

解答与执行

习题 9.40 · ★

原题

修改语言设计，使每个字段声明都包含一个用于初始化该字段的表达式。这种设计的好处是：通过检查的程序将绝不会引用未初始化的值。

印刷 p.371 / PDF 394

解答与执行

字段声明增加初始化表达式，例如 field int x=3。new 先为所有字段分配位置，再按祖先到子类、同类从左到右求各初始化表达式，写入对应位置，最后调用 initialize。

完整程序与调用
class A extends object
 field int x=3
 field int y=+(x,4)
 method int initialize()1
 method int get()+(x,y)
let a=new A() in send a get()
10

单纯“有一个表达式”仍不够保证安全：x 的表达式若读取尚未初始化的 y，或经 self 调用方法间接读取 y，照样会出错。本实现的 field-initializers? 模式要求每个字段都有表达式，且检查该表达式时只提供当前宿主中已经初始化的前序字段及静态成员，不提供 self/super，也不提供后续字段。每个表达式的类型必须是声明字段类型的子类型。

对这一受限设计，可沿字段顺序归纳：每一步只读取已经建立正确值的位置，写入的新值又满足字段类型；若某步不终止或报告其他运行错误，就不会进入后续方法调用。所有表达式正常返回时，不存在仍为未初始化哨兵的实例字段。前向读和 self 间接读的拒绝用例都已实际运行。

习题 9.41 · ★★

原题

按习题 9.8 扩展类型检查器，使其处理 fieldref 与 fieldset。

印刷 p.371 / PDF 394

解答与执行

先检查目标表达式为具体类类型，再在这个静态类的字段视图中找声明。读取的类型就是该声明类型；设置要求右侧类型是字段类型的子类型，表达式结果为 void。可变字段不能因为“装的是子类对象”就允许写入不相容的父类值。

习题 9.42 · ★★

原题

类型检查器对静态方法的处理与普通方法相同，只有一个例外：静态方法不能被动态方法覆盖，动态方法也不能被静态方法覆盖。扩展检查器，使其处理静态方法。

印刷 p.371 / PDF 394

解答与执行

静态类环境的方法条目除了完整过程类型，还保存 static/dynamic 标志。覆盖检查先比较标志，二者必须一致；然后像普通方法一样检查新签名是父签名的子类型，并检查方法体的结果满足声明类型。接口要求的普通动态方法不能仅用一个 staticmethod 来充数。

(unless (eq? (mdecl-static? new-method)
             (mdecl-static? inherited-method))
  (oo-error 'dispatch new-method "static/dynamic method kind changed"))
(require-subtype! (signature new-method)
                  (signature inherited-method) classes new-method)

例如把父 static m 改成子 method m，或反过来，均在声明检查时拒绝；父子都为 static 时，调用点仍按接收表达式静态类型选择各自声明。否则同一个以父类型检查过的调用节点，在子对象上会突然改变“固定目标还是动态消息”的含义。原题 9.37 的修正版、两种非法改变和字段初始化中的静态调用均已实际运行。

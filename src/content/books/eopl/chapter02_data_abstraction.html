2.1 先规定观察结果，再选择表示

原书 §2.1，pp.31–35 / PDF 54–58。

第 1 章把文法映射成递归结构；第 2 章把“一个值是什么意思”与“它在内存里长什么样”分开。以自然数为例，客户需要零、判零、后继、前驱四个操作。可以用整数，也可以用 #t 的列表或一串数位；只要操作满足同一组关系，遵守接口的客户就能继续工作。

自然数接口的规格

用 ⌈n⌉ 表示自然数 n 的某种实现值；这里的上角括号表示“数据的表示”。接口满足以下方程：

  • (zero)=⌈0⌉。
  • (is-zero?⌈n⌉)=#t⇔n=0；其他合法自然数返回 #f。
  • (successor⌈n⌉)=⌈n+1⌉。
  • 当 n>0 时，(predecessor⌈n⌉)=⌈n−1⌉。

零的前驱不在这组接口方程规定的范围内。

客户加法可以这样推导：若第一个数为零，结果就是第二个数；否则先将第一个数减一，把递归加法的结果加一。程序只需要四个接口操作，不需要知道列表长度、数位顺序或宿主整数运算。下面沿用原书的过程调用顺序推演 plus；上角括号中的数字表示抽象数值，每一行都说明上一行怎样继续求值：

(plus⌈3⌉⌈2⌉)=(successor(plus⌈2⌉⌈2⌉))=(successor(successor(plus⌈1⌉⌈2⌉)))=(successor(successor(successor(plus⌈0⌉⌈2⌉))))=(successor(successor(successor⌈2⌉)))=⌈5⌉

接口方程还支持等价的尾递归写法：把一单位从第一个参数移到第二个参数，直到第一个为零。习题的计时代码采用这一形式，避免把尚未完成的 successor 全压在返回链上。它仍是逐单位加法，因此不会自动获得宿主大整数乘法的效率。

数据抽象首先是一条程序依赖原则；表示透明与否还取决于语言和封装机制。本书在当时的 Scheme 背景下主要依靠客户遵守接口约定。我们的 Racket 模块为教学导出实现，便于比较与测试，不能把这种组织说成已经证明所有客户都无法观察表示。

阅读注解
表示与数值

先确认“代表什么”，再检查操作

读接口方程时，可以在草稿上给每个实现值标一个“它所代表的数”。例如基数 16 的 (15) 表示 15，后继返回 (0 1)，它表示 16；一元表示则从十五个 #t 变成十六个。两段过程改变的数据形状不同，但都把所代表的数增加 1。证明时应检查输入是否合法、输出是否仍合法，以及输出所代表的数是否满足方程。

这也解释了差分树题为何强调“任意合法表示”：(diff (one) (one)) 与更大的零值差分树都应使 is-zero? 返回 #t。只认出一种零的外形，无法满足这条观察器规格。

递归的依据

加法递归沿抽象数值下降

证明正文的 plus 时，归纳参数是第一个输入所代表的自然数。为零时直接返回第二个输入；为正时，predecessor 使这个数减少 1，因而可以使用归纳假设，再由 successor 把一单位补回。

这个证明不要求某种表示的列表长度每次都减小。bigits 从 16 减到 15 时数位数会变化，许多相邻数却保持相同位数；差分树的前驱甚至可以增加节点。抽象数值严格下降，才是这个客户递归终止的共同依据。

习题 2.1 · ★

原题

为 bigits（大整数数位）表示实现所需的四个操作：zero、is-zero?、successor、predecessor。然后用你的实现计算 10 的阶乘。参数改变时，执行时间怎样变化？基数改变时，执行时间怎样变化？解释产生这些变化的原因。

题目沿用本节的大整数表示（p.34 / PDF 57）：选择基数 N，把数写成由 0 到 N−1 的数位组成的列表，最低有效位在表头。零表示为 ()；对非零自然数，若 n=qN+r,0≤r<N，则表头为余数 r，表尾递归表示商 q。例如基数为 16 时，33 表示为 (1 2)，258 表示为 (2 0 1)。四个操作须满足自然数接口的规格。

印刷 p.34 / PDF 57

解答与执行

选择基数 N≥2，最低位放在表头。零唯一表示为 ()；非零数的最高位必须非零，避免 (0)、(0 0) 这样的伪零。successor 遇到小于 N−1 的位就加 1 并共享剩余尾部，遇到 N−1 则写 0 并向后进位。predecessor 遇到 0 就写 N−1 并向后借位；从单独的 (1) 减一必须得到 ()，以保持规范形式。

以 N=16 为例，255 的 (15 15) 加一变成 (0 0 1)；256 的 (0 0 1) 减一，借位链返回 (15 15)。10! 的十进制结果为 3628800，十六进制 bigits 是 (0 0 15 5 7 3)。encode/decode 只用于建立输入与检查结果；阶乘客户程序只调用题目指定的四个操作。

下面的实测表来自本机 Racket 8.17，先预热一次，再在每次计时前回收垃圾，取三次单调时钟测量的中位数。加法使用尾递归形式把 x 的单位逐个移给 y，乘法重复加法，阶乘重复乘法；这不是高效大整数乘法。

(struct number-api (zero zero? succ pred encode decode) #:transparent)
;; Canonical little-endian base-N digits; zero is (). N >= 2.
(define (make-bigits base)
  (unless (and (exact-integer? base) (>= base 2)) (error 'make-bigits "base >= 2 required"))
  (define (successor ds)
    (cond [(null? ds) '(1)]
          [(= (car ds) (- base 1)) (cons 0 (successor (cdr ds)))]
          [else (cons (+ 1 (car ds)) (cdr ds))]))
  (define (predecessor ds)
    (cond [(null? ds) (error 'predecessor "zero is outside the contract")]
          [(zero? (car ds)) (cons (- base 1) (predecessor (cdr ds)))]
          [(and (= (car ds) 1) (null? (cdr ds))) '()]
          [else (cons (- (car ds) 1) (cdr ds))]))
  (define (encode n)
    (if (zero? n) '() (cons (remainder n base) (encode (quotient n base)))))
  (define (decode ds)
    (if (null? ds) 0 (+ (car ds) (* base (decode (cdr ds))))))
  (number-api (lambda () '()) null? successor predecessor encode decode))
;; Clients use only the four abstract operations. The loops are tail calls.
(define (nat-plus a x y)
  (if ((number-api-zero? a) x) y
      (nat-plus a ((number-api-pred a) x) ((number-api-succ a) y))))
(define (nat-times a x y)
  (let loop ([k x] [acc ((number-api-zero a))])
    (if ((number-api-zero? a) k) acc
        (loop ((number-api-pred a) k) (nat-plus a y acc)))))
(define (nat-factorial a n)
  (let loop ([k n] [acc ((number-api-succ a) ((number-api-zero a)))])
    (if ((number-api-zero? a) k) acc
        (loop ((number-api-pred a) k) (nat-times a k acc)))))
习题 2.2 · ★★

原题

逐一、审慎地分析本节提出的各个表示方案。它们在多大程度上满足这个数据类型的规格？哪些地方成立，哪些地方不成立？

这里的三个方案来自 p.33–34 / PDF 56–57，均应对照自然数接口的四条方程：

  1. 一元列表表示：自然数 n 用含有 n 个 #t 的列表表示，例如 0 为 ()，1 为 (#t)，2 为 (#t #t)。zero 返回空表，is-zero? 用 null? 判定，successor 用 cons 在表头加一个 #t，predecessor 取 cdr。
  2. Scheme 数表示：直接用 Scheme 整数 n 表示自然数 n；四个操作依次是返回 0、用 zero? 判零、加 1、减 1。
  3. bigits 表示：以 N 为基数，用最低有效位在前的数位列表表示自然数；表示规则和例子见 习题 2.1 的题面。

印刷 p.34 / PDF 57

解答与执行

四条接口方程只约束合法自然数表示，且 predecessor 的参数必须非零。第一种一元列表表示能满足这些方程；数字越大，空间越多，解码长度为线性，但加一和删表头可为常数时间。第二种宿主整数表示也满足方程；本次 Racket 的精确整数会自动扩展，不能以固定机器字溢出批评这份实际实现。如果换成固定宽度整数，越过上界才会破坏无界自然数规格。

第三种 bigits 表示在 N≥2、数位合法、最高位非零的规范域内满足规格，空间按位数增长；进位和借位的最坏时间随位数增加。若允许 (0) 进入表示域，却用 null? 判断零，就会失败，因此合法表示域是证明的一部分。

三者都没有仅凭接口约定阻止客户窥看内部。抽象意义上的等价要求客户只使用接口；透明打印、car 或直接算术可能区分表示。predecessor(0) 不在书中契约内，返回 −1 或报错都不能单凭这一点判定实现不符合原规格。

习题 2.3 · ★★

原题

用差分树（diff-tree）表示所有整数，包括负整数和非负整数。差分树是由下列文法定义的列表：

                      Diff-tree ::= (one) | (diff Diff-tree Diff-tree)

列表 (one) 表示 1。若 t1 表示 n1，t2 表示 n2，那么 (diff t1 t2) 表示 n1−n2。因此，(one) 和 (diff (one) (diff (one) (one))) 都表示 1；(diff (diff (one) (one)) (one)) 表示 −1。

  1. 证明：在这个表示系统中，每个整数都有无穷多个表示。
  2. 按照 p.32 / PDF 55 的接口规格编写 zero、is-zero?、successor、predecessor，把这一整数表示变成可用的实现；现在表示范围还包括负整数。过程必须接受某个整数的任意合法表示。例如，把 1 的无穷多个合法表示中的任何一个交给 successor，都应得到 2 的某个合法表示。允许 1 的不同合法表示产生 2 的不同合法表示。
  3. 编写过程 diff-tree-plus，在这一表示下完成加法。应针对差分树表示进行优化，使运行时间为常数，与输入大小无关；特别地，该过程应当是非递归的。

印刷 p.34–35 / PDF 57–58

解答与执行

① 任意树 t 都可以改写为 (diff t z)，其中 z= (diff (one) (one)) 表示零。每做一次都增加节点数而保持数值，因此得到无限多个不同的有限树。所有整数都可从 one 经有限次加一/减一到达，所以论证适用于每个整数。

② zero 返回 z；is-zero? 递归计算树值后比较零，不能只比较它是否长得像 z。令 neg-one = (diff z (one))；(successor t) = (diff t neg-one)，(predecessor t) = (diff t (one))。对任何合法表示，取值方程分别给出 value(t)+1 和 value(t)−1，所以不需要先规范化输入。

③ a+b=a−(0−b)，因此只构造 (diff a (diff z b))。代码不递归，也不复制输入树，只保留对 a、b 的引用；构造节点数是常数。随后打印或计算整棵树的数值仍可能很贵，不能把“加法构造常数时间”误解为所有观察操作都常数时间。共享输入形成的实际对象图也可能比展开后的打印树小得多。

查看实现 · ex-2-3
;; DiffTree = (one) | (diff DiffTree DiffTree); may represent any integer.
(define (dt-zero) '(diff (one) (one)))
(define (dt-value t)
  (if (eqv? (car t) 'one) 1 (- (dt-value (cadr t)) (dt-value (caddr t)))))
(define (dt-zero? t) (zero? (dt-value t)))
(define (dt-succ t) (list 'diff t (list 'diff (dt-zero) '(one))))
(define (dt-pred t) (list 'diff t '(one)))
(define (diff-tree-plus a b) (list 'diff a (list 'diff (dt-zero) b)))

2.2 环境：一套方程，多种实现

原书 §2.2，pp.35–42 / PDF 58–65。

环境把有限个变量名关联到值。它是一个有限函数；查询已绑定变量返回对应值，查询未绑定变量报告失败。(extend-env var val env) 产生一个新环境：查 var 得 val，查其他名字则沿用 env。这个“先比较当前名字，否则交给旧环境”的方程，同时决定了链表实现与闭包实现的行为。

查询 y 时，旧 y 为什么不会被读到

E0 = empty-env()
E1 = extend-env(y,14,E0)
E2 = extend-env(x,7,E1)
E3 = extend-env(y,8,E2)
E4 = extend-env(d,6,E3)

apply-env(E4,y): d ≠ y → E3
apply-env(E3,y): y = y → 8
apply-env(E2,y): x ≠ y → E1 → 14

新环境中的 y 是 8，旧环境 E2 中的 y 仍是 14。扩展没有修改 E2；遮蔽改变的是从哪一端开始查。抽象环境只看当前可见映射，具体的链式表示可以保留那些已经被遮蔽的旧绑定。

带标签的数据表示把 empty-env 和 extend-env 的构造历史直接保存成记录。apply-env 读标签、取字段、再决定下一步，这就是原书的解释器模式。过程表示把这些判断移到构造时：empty-env 返回一个总是报未绑定的过程；extend-env 返回一个闭包，保存 saved-var、saved-val、saved-env，查询时比较名字，失败则调用旧闭包。

这两个表示都在解释同一套环境方程。数据表示让结构可直接遍历，过程表示让查询成为一次函数调用。要比较它们，应用相同客户：扩展 x 为 7，再扩展 x 为 99；新环境查 x 得 99，旧环境查 x 仍得 7。绑定值为 #f 时，“值是假”与“根本没绑定”必须由不同观察器区分。

本节代码的 env-api 只是在 Racket 中把同名操作装成一组，方便同一测试切换实现；原书的抽象思想不依赖这个辅助结构。所有展示的列表、ribcage、闭包及 define-datatype 环境都采用持久式扩展，后续章节引入可变存储时才会增加另一类语义问题。

阅读注解
观察行为

环境的等价由查询决定

考虑先绑定 x 为 7、再绑定同名变量为 99 的环境。关联表可以保存两条记录，不可变映射也可以只保存当前可见的 99。只要从新环境查 x 得到 99、其他名字仍按原环境查询，它们就实现了同一个可见映射。若还持有旧环境，从旧环境查询 x 应继续得到 7。

比较实现时要分别检查新环境和旧环境，并把“缺少绑定”作为独立结果。尤其当合法值为 #f 时，apply-env 返回假值并不能回答绑定是否存在；has-binding? 必须检查名字是否命中。

复杂度前提

肋骨式把哪一步变成常数时间

若变量表、值表已经建立并满足等长前提，extend-env* 只需把这两条表配成一肋，再把这一肋接到旧环境前面。它保存已有表的引用，因此新增的点对数与这一批变量的数量无关。

若把逐项检查两表等长也计入调用成本，就必须遍历这一批元素；题目中的常数时间结论针对满足接口前提的构造步骤。查找仍可能逐个比较肋中的变量，再进入下一肋，因此扩展变快并不同时给出常数时间查询。

习题 2.4 · ★★

原题

考虑由值组成的栈这一数据类型，其接口包含 empty-stack、push、pop、top、empty-stack?。仿照上文环境接口给操作写规格的方式，为这些栈操作写出规格。其中哪些操作是构造器，哪些是观察器？

印刷 p.37 / PDF 60

解答与执行

令 ε 表示空栈，P(v,s) 表示把 v 压入 s。接口方程是 (empty-stack) =ε；(push v s) =P(v,s)；(top (push v s)) =v；(pop (push v s)) =s；(empty-stack? (empty-stack)) = #t；(empty-stack? (push v s)) = #f。top、pop 对空栈的结果须另行约定，本答案统一报错。

按本章“返回抽象类型值”的分类，empty-stack、push、pop 是构造器，top、empty-stack? 是观察器。pop 虽然不一定新分配节点，仍返回一个栈；构造器的分类不等于内存分配行为。列表实现直接对应这些方程，后三种程序表示也应接受同一组栈客户测试。

查看实现 · ex-2-4
;; Stack equations: top(push(v,s))=v; pop(push(v,s))=s;
;; empty?(empty)=#t; empty?(push(v,s))=#f. Empty top/pop are errors here.
(define (empty-stack) '())
(define (push v s) (cons v s))
(define (empty-stack? s) (null? s))
(define (top s) (if (null? s) (error 'top "empty stack") (car s)))
(define (pop s) (if (null? s) (error 'pop "empty stack") (cdr s)))
习题 2.5 · ★

原题

只要一种数据结构能区分空环境与非空环境，并且能从非空环境中取出它的各个组成部分，就可以用它表示环境。请实现环境接口，采用如下表示：空环境由空表表示，extend-env 构造的环境具有下方原题指针图所示的结构。

图中外层点对的 car 指向保存 saved-var 与 saved-val 的点对，cdr 指向 saved-env。这种表示称为 a-list，也就是关联表（association list）表示。

习题 2.11 · ★★

原题

上一题中，extend-env* 的朴素实现需要与变量个数 k 成正比的运行时间。可以采用另一种环境表示，使 extend-env* 只需要常数时间：空环境仍表示为空表，非空环境则采用下方原题图中的数据结构。

一般构造中的 saved-vars、saved-vals 分别是对应的变量列表和值列表，saved-env 是后续环境。图中给出一个这样的环境实例：三肋依次将 (a b c) 与 (11 12 13)、(x z) 与 (66 77)、(x y) 与 (88 99) 配对，并连接到其余环境。

这称为肋骨式（ribcage）表示。环境是由称为“肋”（rib）的点对组成的列表：每条左肋是变量列表，每条右肋是对应的值列表。使用这种表示实现环境接口，其中应包括 extend-env*。

印刷 p.39–40 / PDF 62–63

解答与执行

一个 rib 保存变量列表与值列表的指针，整个环境是 rib 的列表。extend-env* 只做两次 cons：一次把两条现成列表配成 rib，一次把 rib 接到旧环境前面，因此在输入已满足“有限正规列表（proper list）、长度相等”的契约时为 O(1)。若同时遍历输入做长度检查，构造器就不再是常数时间，故这里把长度条件列为前提。

查询先在当前 rib 中同步推进变量表和值表；命中返回同位置的值，当前 rib 用尽才去外层。原图中查询 x 会跳过 (a b c) 那一肋，在 (x z) 找到 66，最外层 (x y) 的 88 被遮蔽。普通 extend-env 用长度 1 的 rib 即可。空 rib 不含绑定；扩展空的变量/值列表后，empty-env? 仍应报告真。

构造的 O(1) 与查找的时间是两回事；最坏查询仍需检查全部绑定。原图和本实现都共享已有列表，假定客户不对它们做破坏性修改。

  (cond [((lc-api-var? a) e) (eqv? v ((lc-api-name a) e))]
        [((lc-api-lam? a) e) (and (not (eqv? v ((lc-api-bound a) e)))

为什么回到父节点需要保存兄弟

普通树节点只包含向下的孩子，进入左孩子后，如果没有上下文，就不知道父值和右兄弟是什么。保存“父值、右兄弟、来自左侧”三项，等于保留了一个缺左孩子的父节点。向上时把当前焦点填入这个空位即可。

焦点： (13 (12 () ()) (14 () ()))；上下文：()
向左： 焦点 (12 () ())；上下文 ((L 13 (14 () ())))
插入： 焦点 (12 () (99 () ()))；上下文不变
向上： 焦点 (13 (12 () (99 () ())) (14 () ()))；上下文 ()

如果保存的只是原父节点并原样返回，就会丢失插入的 99。上下文保存的是“如何重建其余结构”，当前焦点则保存已经修改的部分。双向序列是同一思想的较简单形式：用反向左表保存已走过的元素。

接口的使用条件

提取器依赖已经识别出的变体

调用 lambda-exp->body 之前，算法应先知道当前值满足 lambda-exp?。这条条件使提取器可以只负责取字段；自由变量算法的三个分支，恰好为各自的提取器建立前提。

移动要保全整条序列

原题

我们通常把一串值表示为列表。在这种表示中，从一个元素移动到下一个元素很容易；如果没有上下文参数的帮助，从一个元素回到它的前一个元素则很困难。请按下列文法所提示的表示，实现非空的整数双向序列：

  > (number->sequence 7)
  (7 () ())
  > (current-element '(6 (5 4 3 2 1) (7 8 9)))
  6
  > (move-to-left '(6 (5 4 3 2 1) (7 8 9)))
  (5 (4 3 2 1) (6 7 8 9))
  > (move-to-right '(6 (5 4 3 2 1) (7 8 9)))
  (7 (6 5 4 3 2 1) (8 9))
  > (insert-to-left 13 '(6 (5 4 3 2 1) (7 8 9)))
  (6 (13 5 4 3 2 1) (7 8 9))
  > (insert-to-right 13 '(6 (5 4 3 2 1) (7 8 9)))
  (6 (5 4 3 2 1) (13 7 8 9))

解答与执行

把状态写成 (current reversed-left right)。向左移动时，从 reversed-left 弹出新焦点，把旧焦点压入 right；向右则完全对称。左边逆序存储，使紧邻焦点的前驱就在表头，所以两种移动都只改常数个 cons。

查看实现 · ex-2-23

cases 中写 leaf-node 或 interior-node，是按已声明变体拆解；字段变量按声明次序绑定。这里的 else 只是未列变体的后备分支，不意味着任意损坏的非该类型对象都成为合法输入。嵌套或互递归的数据类型仍需分别定义；list-of 把单元素谓词提升为整个正规列表（proper list） 的谓词，空表自然通过逐元素检查。

构造与递归

声明字段以后，递归仍需自己安排

习题 2.25 · ★★

原题

使用 cases 编写 max-interior。它接收 习题 2.24 所定义的整数叶子二叉树，要求树中至少有一个内部节点；返回某个内部节点所关联的符号，该节点下方所有叶子数值之和应当最大。

  > (define tree-1
      (interior-node 'foo (leaf-node 2) (leaf-node 3)))
  > (define tree-2
      (interior-node 'bar (leaf-node -1) tree-1))
  > (define tree-3
      (interior-node 'baz tree-2 (leaf-node 1)))
  > (max-interior tree-2)
  foo
  > (max-interior tree-3)
  baz

最后一次调用 max-interior 也可以返回 foo，因为 foo 和 baz 两个节点的叶子和都等于 5。

印刷 p.50 / PDF 73

解答与执行

只向上返回“最优标签”会丢掉计算祖先总和所需的信息。因此 walk 同时返回当前树的叶子总和，以及子树内最佳内部节点的 (标签 . 和)。叶子贡献自己的整数，总和可能为负，但没有内部候选，记为 #f。

内部节点先拿到左右总和与最佳候选，自己的总和等于两边之和；随后在自己、左候选、右候选中取最大。不能把初始最大值设成 0，否则全负数树会没有合法赢家。这里并列时按“当前、左、右”优先，故 tree-3 返回 baz；原题允许同和的 foo。

每个节点只计算一次，时间线性。递归过程把“给父节点使用的总和”和“本子树内已经找到的最佳答案”分开，这是本题的关键。

;; walk returns subtree leaf sum and either #f or (key . best interior sum).
;; Ties choose current, then left, then right. Negative maxima are valid.
(define (max-interior t)
  (define (better a b) (if (and b (> (cdr b) (cdr a))) b a))
  (define (walk t)
    (cases bintree t
      (leaf-node (n) (values n #f))
      (interior-node (k l r)
        (let-values ([(ls lb) (walk l)] [(rs rb) (walk r)])
          (define sum (+ ls rs))
          (values sum (better (better (cons k sum) lb) rb))))))
  (let-values ([(sum best) (walk t)])
    (if best (car best) (error 'max-interior "requires an interior node"))))

2.5 从具体语法得到可计算的树

原书 §2.5，pp.51–55 / PDF 74–78。

具体语法决定程序写出来的样子，抽象语法决定分析程序时要保留哪些信息。(lambda (x) (f (f x))) 与 proc x => f(f(x)) 可以表达同样的构造层次。AST 保存 lambda 的绑定名和 body、应用的两个子树、变量的名字；用于分组的括号不必再作为独立字段存进去。

Scheme reader 先把带括号文本读成 S-expression；parse-expression 再判断它是否属于 LcExp，并为每个构造建立对应 AST。解析 '(lambda (x) (f x)) 时，外层先确认 lambda 形状，保存绑定名 x；body 是二项列表，于是递归构造 app-exp；两项符号各成为 var-exp。由内而外返回后，整个 lambda-exp 才完整。

解析和求值处在不同阶段

输入值：'(lambda (x) (f x))
构造：  lambda-exp('x,
          app-exp(var-exp('f), var-exp('x)))
回写：  '(lambda (x) (f x))

这里没有查 f 的值，也没有调用 f。解析阶段只解释“文本形状对应哪种语法构造”；下一章解释器才会规定这些构造如何产生运行结果。

解析器必须消费完整的预期结构。单参数应用只允许两项；多参数版本另有文法，不能把第三项默默忽略。前缀 token 语法又不同：子表达式边界不靠每层括号给出，需要让辅助过程返回“已解析树 + 剩余输入”。这些差别都来自输入文法，复用同一段 car/cadr 代码并不能自动获得正确解析。

对合法 S-expression，可检查 (unparse-expression (parse-expression s)) 返回 s；对任意合法 AST，也可检查 (parse-expression (unparse-expression t)) 保留构造与字段。这是表示转换的性质，不表示任何字符串都合法，也不证明另一套有歧义的文法存在唯一解析。习题 2.28 会专门指出这个边界。

阅读注解
消费输入

局部解析与完整输入各守一条约定

前缀解析的辅助过程只解析一个表达式。例如输入 (- 8 3 99)，读到 - 后依次解析 8 和 3，便能返回相应的 diff-exp 与剩余列表 (99)。剩余部分让外层递归继续寻找下一个操作数。

最外层入口承担另一条条件：一个 Prefix-list 只包含一个 Prefix-exp，所以完整输入解析结束后必须没有剩余项。对这个例子，入口应指出多余的 99；对 (- 8)，辅助过程则应在寻找第二个操作数时指出输入已结束。

转换的契约

往返检查要说明比较哪一种对象

从 S 表达式构造 AST，再把 AST 转回同一套 S 表达式，可以比较列表结构和符号是否恢复；若输入是字符串，空格与换行通常不保存在 AST 中，就不能据此要求逐字符恢复原文本。

对另一套 proc 字符串文法，还要检查文法是否允许唯一解析。习题 2.28 的输出满足该文法，但不同树可能产生同一字符串。若要建立“先打印再解析恢复原树”的性质，必须先让分组与优先级规则足够明确。

习题 2.29 · ★

原题

具体语法中出现 Kleene 星号或加号时（p.7 / PDF 30，分别表示零次或多次、一次或多次重复），构造抽象语法树时，最方便的做法是用一个列表保存相应的各棵子树。例如，假设 λ 演算表达式文法如下；每条产生式下方同时标明变体名和字段名：

                 Lc-exp ::= Identifier
                             var-exp (var)
                        ::= (lambda ({Identifier}∗ ) Lc-exp)
                            lambda-exp (bound-vars body)
                        ::= (Lc-exp {Lc-exp}∗ )
                            app-exp (rator rands)

那么，bound-vars 字段的谓词可以是 (list-of identifier?)，rands 字段的谓词可以是 (list-of lc-exp?)。请按这种方式为该文法编写 define-datatype 声明和解析器。

印刷 p.54 / PDF 77

解答与执行

把单个 bound-var 改成变量列表，把单个 rand 改成表达式列表；相应字段谓词用 (list-of identifier?) 与 (list-of multi-exp?)。解析 lambda 时检查长度为 3，第二项是合法标识符列表，再解析 body；解析应用时，car 是操作符，cdr 经 map 变为操作数列表。

星号允许零项，所以 (lambda () x) 与 (f) 都是这个文法的合法语法；空表本身缺少操作符，仍非法。重复形参也没有被这份文法禁止，解析器保留它们，实际绑定语义须在定义语言时再决定。

原题

上文定义的 parse-expression 很脆弱：它不能发现若干可能的语法错误，例如 (a b c)；对于另一些表达式，例如 (lambda)，它又会以不恰当的错误消息中止。请修改它，使它足够健壮：接受任意 S 表达式作为输入，并在输入不代表 λ 演算表达式时给出适当的错误消息。

(define parse-expression
  (lambda (datum)
     (cond
        ((symbol? datum) (var-exp datum))
        ((pair? datum)
         (if (eqv? (car datum) 'lambda)
           (lambda-exp
              (car (cadr datum))
              (parse-expression (caddr datum)))

              (parse-expression (car datum))

习题 2.31 · ★★

原题

有时，把具体语法规定为由括号围住的一串符号和整数很有用。例如，可以这样定义前缀列表集合：

 Prefix-list ::= (Prefix-exp)
 Prefix-exp ::= Int
            ::= - Prefix-exp Prefix-exp

于是，(- - 3 2 - 4 - 12 7) 是一个合法的前缀列表。这种记法有时称为波兰前缀记法，以其发明者 Jan Łukasiewicz 的国籍命名。请编写解析器，把前缀列表转换为如下抽象语法：

  (define-datatype prefix-exp prefix-exp?
    (const-exp
      (num integer?))
    (diff-exp
      (operand1 prefix-exp?)
      (operand2 prefix-exp?)))

上面的例子应当产生与下列构造器调用序列相同的抽象语法树：

  (diff-exp
    (diff-exp
      (const-exp 3)
      (const-exp 2))
    (diff-exp
      (const-exp 4)
      (diff-exp
        (const-exp 12)
        (const-exp 7))))

提示：可以先写一个过程，它接收一个列表，同时产生一个 prefix-exp 和由尚未使用的列表元素构成的剩余列表。

印刷 p.55 / PDF 78

解答与执行

辅助过程解析“恰好一个表达式”，同时返回尚未消费的 token。遇整数，构造 const-exp 并返回 cdr；遇减号，先从余下输入解析左操作数，再把左侧留下的 rest1 交给右侧，最后返回 diff-exp 与 rest2。读到结尾却仍期待表达式时报告截断错误。

原例先消费 - 3 2 形成左树，再消费 - 4 - 12 7 形成右树，最终没有剩余项。其值是 (3−2)−(4−(12−7)) = 1−(−1) = 2。顶层包装器检查剩余列表为空，因此 (3 4) 会因多余 token 而失败，不能仅返回第一个常量。

每个 token 被读一次；用返回剩余尾部的方式避免反复截取/计算整个列表长度。源码还提供按 AST 回写 token 的过程，独立核对解析后的形状与先后顺序。

(struct number-api (zero zero? succ pred encode decode) #:transparent)
;; Canonical little-endian base-N digits; zero is (). N >= 2.
(define (make-bigits base)
  (unless (and (exact-integer? base) (>= base 2)) (error 'make-bigits "base >= 2 required"))
  (define (successor ds)
    (cond [(null? ds) '(1)]
          [(= (car ds) (- base 1)) (cons 0 (successor (cdr ds)))]
          [else (cons (+ 1 (car ds)) (cdr ds))]))
  (define (predecessor ds)
    (cond [(null? ds) (error 'predecessor "zero is outside the contract")]
          [(zero? (car ds)) (cons (- base 1) (predecessor (cdr ds)))]
          [(and (= (car ds) 1) (null? (cdr ds))) '()]
          [else (cons (- (car ds) 1) (cdr ds))]))
  (define (encode n)
    (if (zero? n) '() (cons (remainder n base) (encode (quotient n base)))))
  (define (decode ds)
    (if (null? ds) 0 (+ (car ds) (* base (decode (cdr ds))))))
  (number-api (lambda () '()) null? successor predecessor encode decode))
;; Clients use only the four abstract operations. The loops are tail calls.
(define (nat-plus a x y)
  (if ((number-api-zero? a) x) y
      (nat-plus a ((number-api-pred a) x) ((number-api-succ a) y))))
(define (nat-times a x y)
  (let loop ([k x] [acc ((number-api-zero a))])
    (if ((number-api-zero? a) k) acc
        (loop ((number-api-pred a) k) (nat-plus a y acc)))))
(define (nat-factorial a n)
  (let loop ([k n] [acc ((number-api-succ a) ((number-api-zero a)))])
    (if ((number-api-zero? a) k) acc
        (loop ((number-api-pred a) k) (nat-times a k acc)))))

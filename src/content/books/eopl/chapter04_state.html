4.1 计算效果：把状态纳入结果

原书 §4.1，pp.103–104 / PDF 126–127。

第三章用环境回答“这个名字绑定什么值”。同一变量在同一环境里被查询，答案不会改变。加入计数器、输入、输出或赋值之后，只有返回值已经不能描述程序发生了什么：一次调用可能返回 1，同时把某个位置从 0 改成 1，后续调用因而得到不同结果。第四章研究的主要效果就是对内存位置的赋值。

先把三个对象分清：位置是可以存值的抽象单元；引用是指向该位置的数据；存储是“位置到当前内容”的有限映射。一个变量名如何找到位置由环境决定，位置现在装什么由存储决定。原书把可存入位置的值称为 storable values；是否与表达值相同，是语言设计的选择。

环境回答绑定，存储回答当前内容

用 ρ 记环境，用 σ 记存储。隐式引用模型中，环境把名字映射到位置，存储把位置映射到表达值；读变量的结果是 σ(ρ(x))。建立新绑定扩展环境；给已有变量赋值，通常只更新原位置的内容，不把环境中的名字重新连到一个新位置。

原书也把引用称为左值（L-value），用来强调赋值左侧需要找到可写的位置；表达式产生的内容称为右值（R-value）。这两个角色不能混用：读取 x 得到数值 3，并不因此获得“把 3 写回 x”的目标位置。

设 x 绑定位置 0，存储中该位置为 3。执行 let y = x 时，先读出 3，再给 y 建一个新位置 1；执行 set y = 4 后，x 仍为 3。若采用后面的 letref y = x，两个名字都指向位置 0，更新 y 后 x 也读到 4。数值相同与位置相同是两回事。

赋值的效果可能跨越相距很远的过程调用，但并不是所有过程都自动看得见所有位置。能观察一个修改，需要能通过环境或对象取得该位置。这一点连接了状态、信息隐藏与闭包：一个位置可以被闭包保留，既跨调用存活，又不暴露给外部名字。

阅读注解
绑定身份

同名不是同一个位置

比较两个读取是否会互相影响，要追踪它们最后找到的位置。同名变量在不同词法层可以对应不同位置；不同名的形参和实参也可能对应同一位置。把变量名直接当成内存格，会同时误判遮蔽和别名。画图时把名字放在环境一侧，把位置及其内容放在存储一侧，赋值的箭头就不容易画错。

效果的范围

共享需要一条可达路径

原书说赋值的效果可能是全局的，是指它可以被后续无直接调用关系的计算观察，而不是说局部状态一定公开。计数器闭包可以成为唯一保留该位置的对象；外部只能通过过程接口让它变化。位置可达性解释了为什么局部名字离开作用域后，状态仍能活在闭包里。

4.2 EXPLICIT-REFS：显式管理引用

原书 §4.2，pp.104–113 / PDF 127–136。

EXPLICIT-REFS 把引用作为可传递的表达值。值域为 ExpVal = Int + Bool + Proc + Ref(ExpVal)，DenVal = ExpVal。let 和形参的绑定方式仍像第三章：直接绑定表达值；只有程序明确执行 newref 才分配位置，明确 deref 才读取引用内容，明确 setref 才更新。

4.2.1 存储传递规格

有了状态，求值结果必须同时描述值与存储。写作 ⟨e,ρ,σ0⟩⇓⟨v,σ1⟩，表示表达式在给定环境和初始存储下返回 v，留下可能改变的存储。常量和过程创建返回原存储；复合表达式要明确把哪份存储交给下一步。

eval(e1, env, s0) = Answer(v1, s1)
eval(e2, env, s1) = Answer(v2, s2)
eval(-(e1,e2), env, s0) = Answer(num(v1)-num(v2), s2)

环境在两个操作数之间相同，存储却从 s0 变成 s1 再变成 s2。条件先求测试，再只在测试留下的存储中求被选分支。不能把“两个操作数用相同环境”误读成“它们用相同的旧存储”。

4.2.2 显式引用操作的规格

操作在操作数结束后做什么返回值
newref(e)选一个尚未分配的新位置，放入 e 的值新引用表达值
deref(e)检查结果为引用，从当前存储读其内容该位置的表达值
setref(e1,e2)先求 e1 再求 e2，用 e2 的值覆盖 e1 指向的位置原书任取数值 23

新位置必须相对于操作数留下的最终存储选择，因为求操作数本身可能已经分配。引用是表达值，因此位置里也能放引用：newref(newref(0)) 先分配装 0 的位置 0，再分配装引用 0 的位置 1；外层变量直接持有引用 1。两次 deref 才能读到最初的数值。

伴读例：计数器怎样跨调用记住次数

原书 p.105 私有状态例的逐步展开

let g = let counter = newref(0)
        in proc(dummy)
             begin
               setref(counter,-(deref(counter),-1));
               deref(counter)
             end
in let a = (g 11)
   in let b = (g 11)
      in -(a,b)

newref 在创建 g 的闭包之前执行，只分配一个位置。闭包保存 counter 到该引用的绑定；以后每次调用的 dummy 虽不同，保存的 counter 绑定相同。第一次把 0 改成 1，第二次把 1 改成 2，最终 a=1、b=2，返回 −1。

步骤闭包中 counter 指向位置内容本步结果
闭包创建前位置 00引用 0
第一次调用位置 011
第二次调用位置 022
计算差值位置 02−1

原书的 even/odd 共享计数位置 x：每次把 x 减一再调用对方，直到 x 为 0，用当前过程身份给出奇偶结果。对 13 调用 odd 得 1。共享状态替代显式参数传递，但也让每次调用依赖前面的写入；推演时必须把当前位置内容一并列出。

4.2.3 实现

原书用宿主 Scheme 的全局变量保存存储表，让源语言的一次更新对应宿主的一次更新，便于实现；位置用表下标表示。这个实现策略与前面显式传递存储的规格应表达同一顺序，但接口不同：全局版本只返回值，纯版本返回 Answer。

本伴读提供两条可执行路径：chapter04_explicit.rkt 是纯存储传递版，用不可变列表返回新存储，完成习题 4.12；chapter04.rkt 的 store 接口提供原书链表、固定容量向量与可增长向量三种后端，用参数化存储隔离每次 run，供后续隐式引用语言使用。它们都不借用宿主 eval 来替代源语言求值。

(define (apply-store sigma loc)
  (unless (and (exact-nonnegative-integer? loc) (< loc (length sigma)))
    (error 'apply-store "invalid location"))

(define (update-store sigma loc v)
  (apply-store sigma loc)
  (let replace ([xs sigma] [i loc])
    (if (zero? i) (cons v (cdr xs)) (cons (car xs) (replace (cdr xs) (sub1 i))))))

阅读注解
闭包与时间

环境可保存，内容仍会改变

闭包保存的是定义处的绑定关系。counter 绑定到的引用没有变，引用所指位置却从 0 变成 1、2；因此闭包不等于冻结创建时的全部数值。若在过程体内才分配 counter，每次调用建立新位置，两次结果都为 1，差变成 0。把分配移动进或移出过程体，是可观察的语义变化。

规格与实现

把状态串起来才能固定求值次序

纯存储传递不是把一个 store 参数加到每个函数签名就结束。减法、实参列表、条件和 begin 都必须使用前一步返回的存储。最容易漏掉的是先求运算符再求实参，以及 newref 的操作数本身分配位置的情形。源码用 Answer 类型强迫调用者显式接收结果和新状态，避免只取值而遗失效果。

习题 4.1 · ★

原题

如果把前面的私有计数器程序改成下面这样，会发生什么？

let g = proc (dummy)
         let counter = newref(0)
         in begin
             setref(counter, -(deref(counter), -1));
             deref(counter)
            end
in let a = (g 11)
   in let b = (g 11)
      in -(a,b)

印刷 p.106 / PDF 129

解答与执行

结果为 0。g 的闭包只保存其定义环境，创建闭包时还没有创建 counter 的位置。第一次调用进入过程体，分配位置 0，存 0，再改为 1，返回 1；第二次进入过程体，另分配位置 1，同样返回 1。于是 -(a,b) 是 1-1。原例把 let counter = newref(0) 放在 proc 外，只分配一次，两次调用共享同一位置，返回 1、2，差为 −1。决定状态寿命的是分配动作发生的位置，不是变量名是否相同。

chapter04_explicit.rkt 实际运行两例，存储末态分别有 1 个、2 个位置；程序结果分别为 −1、0。

习题 4.2 · ★

原题

写出 zero?-exp 的存储传递语义规格。

印刷 p.108 / PDF 131

解答与执行

先求操作数，保留其产生的新存储，再把取出的数值判零；判零本身不再改变存储。若 ⟨e,ρ,σ0⟩⇓⟨v,σ1⟩，且 num(v) 成功，则：

⟨zero?(e),ρ,σ0⟩⇓⟨num(v)=0,σ1⟩

结论中的布尔值在实现里包成 bool-val。非数值应报错；不能因为判零没有写入，就把操作数产生的效果丢掉。

习题 4.3 · ★

原题

写出 call-exp 的存储传递语义规格。

印刷 p.108 / PDF 131

解答与执行

先在调用者环境求运算符，得到闭包和新存储；再在同一个调用者环境求实参，但使用运算符留下的存储。最后在闭包保存的定义环境上绑定形参，并把实参留下的存储交给过程体。显式引用的形参直接绑定表达值，不自动分配位置：

eval(rator, caller, s0) = Answer(Closure(x, body, saved), s1)
eval(rand, caller, s1) = Answer(arg, s2)
eval(body, extend(saved, x, arg), s2) = Answer(result, s3)
---------------------------------------------------------
eval(Call(rator, rand), caller, s0) = Answer(result, s3)

这里的 saved 决定自由变量对应哪个绑定；s2 决定共享位置此刻装的是什么。闭包保存环境，不保存创建时整份存储快照。多参数版按实参出现顺序继续串接存储。

习题 4.4 · ★★

原题

写出 begin 表达式的语义规格。其文法为 Expression ::= begin Expression {; Expression}* end。一个 begin 含一个或多个用分号分隔的子表达式；按顺序求值，返回最后一个的值。

印刷 p.108 / PDF 131

解答与执行

设子表达式依次为 e1,…,en，且至少一个。从输入存储开始，每次把前一个子表达式的输出存储作为下一个的输入；所有子表达式都使用同一环境。

eval(e1,env,s0)=Answer(v1,s1)
eval(e2,env,s1)=Answer(v2,s2)
...
eval(en,env,s[n-1])=Answer(vn,sn)
eval(Begin(e1,...,en),env,s0)=Answer(vn,sn)

上式的下标约定可直接读作“第 i 步输入，下一步状态”；整个 begin 返回最后的值和最后的存储。它不建立新绑定层，前面的返回值可以丢弃，效果必须保留。实现见习题 4.10。

习题 4.5 · ★★

原题

为习题 3.10 的 list 写存储传递规格。该构造接收任意个表达式，依次求值，并返回由这些值构成的列表；零个实参时得到空表。

印刷 p.108 / PDF 131

解答与执行

空表构造返回 List([]) 和原存储。非空情形先求第一项，得到的存储用于余下各项；把所有值按原顺序收集，最后输出最后一项留下的存储。

eval-list([], env, s) = Answer([], s)
eval(e, env, s0) = Answer(v, s1)
eval-list(rest, env, s1) = Answer(vs, s2)
------------------------------------------------
eval-list(e :: rest, env, s0) = Answer(v :: vs, s2)

构造列表不会撤回元素的效果。例如三项依次为“把 r 改为 1 并读 r”“把 r 改为 2 并读 r”“读 r”，结果是 (1 2 2)。不能把三个表达式都放进同一份旧存储求值。

习题 4.6 · ★

原题

修改本节给出的规则，使 setref-exp 返回右侧表达式的值。

印刷 p.109 / PDF 132

解答与执行

保持“求引用→求右值→写入”三步及其存储传递不变，仅把返回的 num-val(23) 换成右侧得到的表达值。

eval(e1, env, s0) = Answer(Ref(l), s1)
eval(e2, env, s1) = Answer(v, s2)
eval(SetRef(e1,e2), env, s0) = Answer(v, update(s2,l,v))

习题 4.7 · ★

原题

修改本节给出的规则，使 setref-exp 返回目标位置原先的内容。

印刷 p.109 / PDF 132

解答与执行

这里明确把“原先”解释为最终写入发生之前的内容：两个操作数都求完后，在输出存储里读取旧值，再覆盖。沿用上一题的记号，返回 Answer(apply-store(s2,l), update(s2,l,v))。若右侧也写了同一位置，读取时必须反映这次副作用。

let r = newref(0)
in setref(r, begin setref(r,9); 7 end)

在这一约定下返回 9，最后存 7；右值返回策略返回 7，原书策略返回 23，三者最后存储相同。如果选择“开始执行外层赋值前的值”，需要另行规定更早的读取时点；那是不同的语义。实际实现的 'old 分支测试了右侧重入写同一位置的情况。

原题

准确指出本书存储实现中的哪些位置使这些操作需要线性时间，而不是常数时间。所指代码为图 4.1（p.111 / PDF 134）及图 4.2（p.112 / PDF 135）。

习题 4.9 · ★

原题

用 Scheme 向量表示存储，把存储操作实现为常数时间。使用这种表示会失去什么？

印刷 p.112 / PDF 135

解答与执行

先分配固定容量向量，用独立的 used 计数下一个空槽。newref! 写 vector[used] 后加一；deref!、setref! 检查引用在已分配范围后直接索引。三个操作均为常数时间，但需要预先选择容量，耗尽时必须报错，不能像链表那样继续增长。初始化整个向量本身仍与容量成正比。

;; list is the textbook model; fixed is exercise 4.9; vector grows geometrically.
(struct store (cells size backend) #:mutable #:transparent)
(define current-store (make-parameter #f))
(define metrics (make-parameter #f))
(define event-log (make-parameter #f))
(define (bump! key) (when (metrics) (hash-update! (metrics) key add1 0)))
(define (event! kind loc value)
  (when (event-log)
    (set-box! (event-log) (cons (list kind loc value) (unbox (event-log))))))
(define (make-store [backend 'vector] [capacity 16])
  (unless (memq backend '(list fixed vector)) (error 'store "unknown backend"))
  (unless (exact-positive-integer? capacity) (error 'store "positive capacity required"))
  (store (if (eq? backend 'list) '() (make-vector capacity 'uninitialized)) 0 backend))
(define (valid-location! loc)
  (unless (and (exact-nonnegative-integer? loc) (< loc (store-size (current-store))))
    (error 'store "invalid location: ~s" loc)))
(define (newref! value)
  (define s (current-store)) (define next (store-size s))
  (cond [(eq? (store-backend s) 'list)
         (set-store-cells! s (append (store-cells s) (list value)))]
        [else
         (when (= next (vector-length (store-cells s)))
           (when (eq? (store-backend s) 'fixed) (error 'store "capacity exhausted"))
           (define grown (make-vector (* 2 (vector-length (store-cells s))) 'uninitialized))
           (vector-copy! grown 0 (store-cells s)) (set-store-cells! s grown))
         (vector-set! (store-cells s) next value)])
  (set-store-size! s (add1 next)) (bump! 'allocations) (event! 'allocate next value) next)
(define (deref! loc)
  (valid-location! loc) (define s (current-store)) (bump! 'reads)

4.3 IMPLICIT-REFS：变量背后的可变位置

原书 §4.3，pp.113–124 / PDF 136–147。

IMPLICIT-REFS 把常见的分配和解引用收进语言规则中。ExpVal = Int + Bool + Proc，DenVal = Ref(ExpVal)：引用不再直接作为普通表达式结果，而由变量绑定持有。读 x 自动执行“查环境得到位置→从存储读当前值”；set x = e 则把 e 的结果写入已有位置。

4.3.1 规格

变量读取为 ⟨x,ρ,σ⟩⇓⟨σ(ρ(x)),σ⟩。赋值先取得 x 的位置，再求右侧并使用其新存储更新，返回原书任取的数值 27。这里的赋值左侧是标识符，不是普通的变量表达式；若把左侧也自动解引用，就会失去要更新的位置。

按值调用中，先求实参得到表达值，再给形参分配新位置。let y = x 也是先读 x，再给 y 分配；它没有复制环境指针。初始环境、let、过程调用、letrec 都产生绑定，因此都需要明确如何取得位置。

伴读例：外层调用结束后，参数位置为什么还在

原书图 4.8 的轨迹释读

let f = proc(x) proc(y)
          begin set x = -(x,-1); -(x,y) end
in ((f 44) 33)

初始 i、v、x 分别占位置 0、1、2；let 为 f 分配位置 3。调用 (f 44) 时为形参 x 新建位置 4，存 44，并返回保存该绑定的内层闭包。外层调用结束后，内层闭包仍保留位置 4。再调用内层过程，为 y 分配位置 5，存 33；赋值把位置 4 从 44 改成 45，差为 12。

0、1、2初始 i=1、v=5、x=10否
3f 的闭包否
4外层形参 x：44→45是
5内层形参 y：33否

把第三章的变量分支改成读取位置，把 let 和调用的参数绑定改成 newref，初始环境也建立三个位置。letrec 还要让每个闭包看见整个递归组；本章默认先分配全部占位槽，再建立所有闭包，最后填入。这样递归名字的槽位身份稳定，每个闭包只建一次。

阅读注解
按值的含义

新参数槽隔离的是变量赋值

按值调用建立的是形参自己的位置，因此 set 形参不覆盖实参槽。不过位置中存的表达值可以是指向共享对象的描述符；下一节的可变序对正会展示这一点。判断一次写入能否被调用者看见，要继续追踪写的是形参槽、对象字段槽，还是闭包中的自由变量槽，不能只看“按值”二字。

递归环境

先有位置，再把闭包放进去

闭包需要整个递归环境，环境又需要绑定闭包；可变占位槽把这条循环拆开。先建立稳定位置，闭包就能保存包含这些位置的环境，再补全内容。若每次查询才新建位置，同名递归过程会不断获得新身份，既浪费空间，又无法可靠地给这个过程名赋值。

习题 4.16 · ★

原题

变量可变以后，可以用赋值构造递归过程。例如下面的 letrec 程序可替换成后面的程序。请手工跟踪并验证该翻译有效。

letrec times4(x) = if zero?(x)
                    then 0
                    else -((times4 -(x,1)), -4)
in (times4 3)
let times4 = 0
in begin
    set times4 = proc (x)
                  if zero?(x)
                  then 0
                  else -((times4 -(x,1)), -4);
    (times4 3)
   end

印刷 p.121 / PDF 144

解答与执行

let 先为 times4 分配位置 L，内容为 0。创建 proc 时，闭包保存的环境中已有 times4 → L；随后赋值只把 L 的内容替换成这个闭包，环境和 L 的身份都不变。调用时读取 L 得闭包，过程体中的递归名字仍沿保存环境找到同一个 L，所以不会读到最初的数值 0。

调用链为参数 3→2→1→0；参数 0 返回 0，然后每层执行“减去 −4”，依次返回 4、8、12。letrec 版本与赋值版本均实际返回 12。必须在创建闭包前先建立名字到槽位的绑定；若闭包创建于 let times4 外，就没有可回指的绑定。

in let a = begin set x = 7; 1 end
       b = x
   in b

习题 4.20 · ★★

原题

本节语言像 Scheme 一样，所有变量都可变。另一选择是同时允许可变与不可变绑定：ExpVal = Int + Bool + Proc，DenVal = Ref(ExpVal) + ExpVal。变量赋值只能用于可变绑定；当指称值是引用时，读取变量隐式解引用。修改语言，让 let 像以前一样引入不可变变量，而可变变量由以下文法引入：Expression ::= letmutable Identifier = Expression in Expression。

印刷 p.121 / PDF 144

解答与执行

用带标签的两类指称值区分位置和直接值，不能仅用“是不是宿主整数”区分，因为语言整数也会以宿主数据表示。本实现的可变绑定是位置下标，不可变绑定包为 immutable(value)。读变量时前者读取存储，后者直接取值；赋值必须取得可变位置，否则报错。

in letmutable y = 2
   in begin set y = 3; -(y,x) end

习题 4.21 · ★★

原题

此前用赋值让一个过程向远处的过程传递信息，从而不要求中间过程了解该信息。很多时候这种赋值应是临时的，只持续一个过程调用。请增加“动态赋值”（dynamic assignment，又称 fluid binding）：Expression ::= setdynamic Identifier = Expression during Expression，抽象语法为 setdynamic-exp(var,exp1,body)。它把 exp1 的值暂时赋给已有绑定的 var，求 body，再恢复 var 原值，并返回 body 的值；var 必须已经绑定。例如下面 p 中的自由变量 x 在 (p 22) 时为 17，之后恢复为 11，整个式子应为 5-2=3。

let x = 11
in let p = proc (y) -(y,x)
   in -(setdynamic x = 17 during (p 22),
        (p 13))

印刷 p.122 / PDF 145

解答与执行

查已有位置并保存进入本构造时的旧内容；求临时右值，写入同一位置；求体，保存其结果；恢复该位置旧内容，再返回保存的结果。其他位置在体中产生的改变继续保留。临时赋值没有建立新的词法环境，因此 p 的闭包仍查原来那一个位置，只是该位置此刻内容为 17。

(define old (deref! loc))
(define v (value-of rhs env))
(dynamic-wind (lambda () (setref! loc v))
              (lambda () (value-of body env))
              (lambda () (setref! loc old)))

  (s:tick!)
  (cases statement stmt
    (st-assign (v e)
      (define loc (s:mutable-location env v))
      (s:setref! loc (value-of-expression e env)))
    (st-print (e) (displayln (s:datum (value-of-expression e env))))
    (st-read (v)

      (define val (parameterize ([read-accept-reader #f] [read-accept-lang #f]
                                 [read-accept-compiled #f]) (read)))
      (unless (exact-nonnegative-integer? val) (error 'read-statement "nonnegative integer required"))
      (s:setref! loc (s:num-val val)))
    (st-sequence (stmts) (for ([st stmts]) (result-of st env)))
    (st-if (t y n) (result-of (if (s:bool (value-of-expression t env)) y n) env))
    (st-while (test body)
      (let loop ()
        (when (s:bool (value-of-expression test env)) (result-of body env) (loop))))
    (st-do (body test)
      (let loop () (result-of body env) (when (s:bool (value-of-expression test env)) (loop))))

  (s:unique! names)

4.4 MUTABLE-PAIRS：共享对象与连续区域

原书 §4.4，pp.124–130 / PDF 147–153。

第三章的列表不能原地改 car/cdr；MUTABLE-PAIRS 在隐式引用语言中增加可变序对。值域扩为 ExpVal = Int + Bool + Proc + MutPair，DenVal = Ref(ExpVal)，MutPair = Ref(ExpVal) × Ref(ExpVal)。变量位置保存一个序对值，序对值再指向左右两个可独立更新的位置。

4.4.1 实现

最直接的表示是左右位置的二元组。构造 pair(a,b) 先按顺序求 a、b，再连续分配两格；left/right 读相应格，setleft/setright 写相应格，原书分别返回 82、83。为形参新建的变量槽只复制这个二元描述符，不复制那两个字段单元。

伴读例：新形参槽为什么仍能改调用者的序对

原书图 4.11–4.12 的共享轨迹

let glo = pair(11,22)
in let f = proc(loc)
             let d1 = setright(loc,left(loc))
             in let d2 = setleft(glo,99)
                in -(left(loc),right(loc))
   in (f glo)

glo 的变量槽和 loc 的形参槽是两个位置，但都装着指向同一对字段的序对值。先读 left(loc)=11，并把共享的右字段改成 11；再经 glo 把共享左字段改成 99。因此 loc 最后读到 99、11，差为 88。若把 setleft(loc,99) 换成 set loc = pair(99,11)，改变的只是形参槽，glo 仍保存原序对值。

4.4.2 可变序对的另一种表示

两个字段总在一次构造中连续分配，因此只保存左字段基址，右字段位置用基址加一取得。客户程序仍只经 make-pair/left/right/setleft/setright 访问，因此更换表示不影响结果；源码 #:pairs 'two 和 'base 都把上例求成 88。关键前提是两次字段分配之间不能插入别的分配，且所有访问仍经过同一个接口。

共享对象不等于共享变量

可把每次写入画成两种不同箭头：set loc 改变 loc 变量槽中的描述符；setleft(loc,v) 沿描述符改对象的左字段。按值参数隔离前一种写入，保留后一种对象共享。许多语言里“修改参数对象被外面看见，重新给参数赋值却看不见”的行为，都可以用这两层位置解释。

表示与边界

基址不能代替区域大小

当数组后面恰好还有其他已分配对象时，base+i 可能仍是合法存储地址，却已经不是这个数组的合法元素。检查整个 store 的范围不能保护对象边界。数组描述符必须保存长度，并在解引用前验证下标属于本数组；底层向量边界与语言层数组边界承担不同职责。

4.5 参数传递：位置、求值时机与缓存

原书 §4.5，pp.130–138 / PDF 153–161。

过程体中的形参总要得到某种指称值；参数传递机制决定它从实参怎样产生。第三章把表达值直接作为指称值，原书称 natural parameter passing；本章的按值调用把表达值装进新位置；接下来改变的是调用时是否共享位置、何时求实参，以及是否记录第一次结果。自由变量依旧由闭包的定义环境解析。

4.5.1 CALL-BY-REFERENCE

let p = proc(x) set x = 4
in let a = 3
   in begin (p a); a end

按值传参，新槽 x 初值为 3，更新为 4 后 a 的原槽仍为 3。按引用传参，实参 a 是变量，直接把它的位置交给 x，更新后 a 读到 4。若实参为 -(a,0)，即使结果也是 3，仍需建临时槽，因为这个表达式本身不是可更新的变量位置。

调用策略程序结果本次 run 分配位置数
按值36
按引用45

这里的分配数包括三个初始绑定、p 和 a；按值额外为 x 分配一槽，按引用直接复用 a 的槽。数字来自上面这个固定输入的 run/details，不代表一般程序的分配上界。

位置选择要在调用点完成，因为那里仍看得见实参 AST 是变量还是其他表达式。apply-closure 只接收已形成的形参位置或负责调用 operand-location；不能等实参已经变成裸数值后再猜它来自哪个变量。普通 let 仍按值分配，以保留显式选择独立绑定的能力。

4.5.2 惰性求值：CALL-BY-NAME 与 CALL-BY-NEED

急切调用在进入体前求出每个实参。惰性调用把尚未求值的实参表达式及其调用者环境打包成 thunk，只有读到形参才求它。若体根本不读该形参，一个无限递归或错误表达式也不会被求值。原书 p.136 的 infinite-loop 示例意在展示此点；本书具体调用文法要求括号，运行版使用 (infinite-loop -(x,-1))，原页的那行写法另作校注。

letrec infinite-loop(x) = (infinite-loop -(x,-1))
in let f = proc(z) 11
   in (f (infinite-loop 0))

按名和按需都得到 11。thunk 保存环境以保持词法绑定，不能在强制时改用过程体此刻的环境；但它不保存旧存储快照，强制时应使用当前状态。原书方案还规定：变量实参直接复用原位置，其余实参才放进含 thunk 的新位置；普通 let 此时仍急切。

按名每次读到 thunk 都重新求值；按需第一次求出后把表达值写回同一位置，以后直接读取，称为记忆化。没有效果时，这两者对终止计算的值一致；有赋值时，重复执行次数会改变结果，习题 4.39 的计数器把差别显式展示出来。

有状态以后，单凭替换后的文字已经不足以判断结果：一个实参展开几次、在哪个时点读取位置，都可能改变后续状态。按名的重复强制与按需的首次缓存，因而必须分别给出规则，不能只当作相同结果下的速度优化。

策略形参得到什么什么时候求非变量实参结果或状态会怎样返回
按值装有实参值的新位置调用前一次形参赋值不覆盖实参槽
按引用变量/数组元素的原位置；否则新位置非左值在调用前一次体中直接写共享位置
按值结果装初值的新位置，另记实参位置调用前一次正常返回时复制回去
按名变量原位置；否则装 thunk 的新位置每次读取可能重求不缓存 thunk 结果
按需变量原位置；否则装 thunk 的新位置首次读取时把首次结果写回槽

源码给各实验统一前端以便比较，不表示原书把全部扩充同时加入一个语言：默认 run 是按值隐式引用，#:mode 选择引用、值结果、按名或按需；显式引用的纯语言使用独立入口。每个题解说明新增语法与值域，避免把实现方便造成的联合语法误当成原书各语言共同的规则。

阅读注解
两份环境

thunk 和闭包分别保存哪一边

闭包保存过程定义处的环境，决定体里的自由变量；thunk 保存实参出现处的环境，决定被推迟表达式里的自由变量。例如调用者 x=7，体中再 let x=99，实参 -(x,1) 强制时仍应得到 6。惰性只改变求值时机，不能让形参表达式自动改用体内的同名绑定。

有状态的惰性

记忆化保存的是第一次结果

若 thunk 首次求值得到一个数值，后来的读取复用该数值，即使其依赖的某个源变量已改变；若结果是共享对象，则缓存的是同一对象描述符，后续对该对象字段的更新仍能被观察。把“缓存表达值”和“冻结对象内容”区分开，才能判断按需程序里的赋值到底作用在哪一层。

原题

解答与执行

习题 4.37 · ★★

原题

按值结果传参（call-by-value-result）是按引用传参的一种变体：实参必须是变量。调用时像按值传参一样，给形参绑定一个新引用，初值是实参当前的值，正常执行过程体；但在过程返回时，把该新位置中的值复制回实参变量的位置。这样可能改善内存局部性，从而比按引用更有效率。实现这种策略，并写一个在值结果与按引用下得到不同答案的程序。

印刷 p.135 / PDF 158–159

解答与执行

调用前记录每个实参原位置，创建独立形参槽；正常执行体，保存返回值；取得所有形参最终值，再写回记录的原位置，最后返回已保存的结果。体抛错时本实现不执行写回；多个形参对应同一实参时明确按从左到右写回，后者覆盖前者。题目未规定这两种边界，必须声明。

let x = 3
in let f = proc(y) begin set x = 4; y end
   in begin (f x); x end

按引用时 y 就是 x，体先把共享槽写成 4，返回后 x 为 4。按值结果时 y 的新槽初值为 3，体通过自由变量把原 x 改成 4，返回前又把 y 的 3 写回原 x，因此结果为 3。两者已实际执行。不要用只交换两个独立变量的程序作区分例，因为两种策略在那种简单场景可能相同。

习题 4.38 · ★

原题

下例是习题 3.25 的一个变体，它在按需求值下可以工作。原习题 3.25 的程序在按需求值下能否工作？若把下例放在按值解释器中运行会怎样，为什么？

                     proc (x)
                       if zero?(x)

印刷 p.138 / PDF 161

习题 4.39 · ★

原题

没有副作用时，按名与按需总给出相同答案。构造一个有副作用的例子，使两者得到不同答案。

印刷 p.138 / PDF 161

解答与执行

let c = 0
in let f = proc(x) -(x,x)
   in (f begin set c = -(c,-1); c end)

按名每次读取 x 都重新执行 thunk：第一次 c 变为 1、x 得 1；第二次 c 变为 2、x 得 2，相减为 −1。按需第一次读取把结果 1 写回 x 的 thunk 槽，第二次直接读取 1，结果为 0，c 最终为 1。实际统计的强制次数分别为 2、1。

这说明“同样的表达式结果可以缓存”在有状态时是语义选择。按需缓存的是第一次强制得到的表达值，不是以后每次都去读取某个源变量的最新内容；而本书对变量实参直接传位置的特殊规则仍会形成别名。

习题 4.40 · ★

原题

修改 value-of-operand，避免为常量和过程创建 thunk。

印刷 p.138 / PDF 161

解答与执行

常量求值不产生效果，结果可立即放进新槽；过程表达式只创建闭包，不执行体，使用此刻的调用者环境创建它也不会提前执行体中副作用。因此这两类实参可直接存表达值，其余非变量实参保留 thunk，变量仍复用原位置。

           (cases expression exp
             (const-exp (n) #t)
             (proc-exp (k ps b) #t)
             (else #f)))
      (value-of exp env)
      (begin (bump! 'thunks) (thunk exp env))))

习题 4.41 · ★★

原题

写出按名与按需的语义规格。

印刷 p.138 / PDF 161

解答与执行

两者的指称值都是 Ref(ExpVal + Thunk)。调用仍先求运算符；实参是变量时直接传已有位置，其他实参在新位置中存 Thunk(expression,caller-env)，不求实参。体在闭包的保存环境加上形参到该位置的绑定后执行。

  l = env[x]
  w = s0[l]
  if w is ExpVal: return Answer(w,s0)
  if w = Thunk(e,saved):

    by-name: return Answer(v,s1)
    by-need: return Answer(v,update(s1,l,v))

把字符分成 token，把 token 组织成语法树，再沿树解释优先级、结合性、变量和一元负号。

B.1 扫描：先确定字符如何分组

原书印刷 p.379 / PDF 402。

输入程序最初只是字符序列。扫描器先去除按词法规范允许忽略的空白与注释，再把其余字符分为标识符、数字、关键字和标点。解析器稍后才决定这些 token 如何组成语句或表达式。图 B.1 的 foo bar %here is a comment 与下一行的标点，说明这两次组织的任务不同。

正则表达式从单字符、连接、选择、Kleene 星号及“除某字符外的一个字符”构成。星号允许零次，因此 (ab)* 也匹配空串；选择和连接的优先级必须写清，ab*|cd 表示 a(b*)|cd。这类规则描述局部分组，不能单独表达任意深度括号的嵌套关系。

原书机制例 · 关键字与标识符边界

原书印刷 p.380 / PDF 403。

(map cadr (scan-statement "while whilex := 3 % ignored
foo"))
("while" whilex ":=" 3 foo)

while 与标识符规则同长时按关键字处理；whilex 是更长的完整标识符。百分号后的内容被忽略，下一行的 foo 仍被扫描。显示的数据只是token的一部分，完整token还带类别和行号。

阅读注解
分组规则

最长匹配先于同长优先级

whilex 比 while 更长，先形成完整标识符；只有同样长时，关键字的字符串规则才胜过标识符规则。

阶段边界

token保存类别、数据和位置

数字的文本可转换成数字数据；关键字和标点可以保留字符串。位置信息用于报告来源，不能替代后续语法关系。

B.2 解析：从 token 构造抽象语法树

原书印刷 p.382 / PDF 405。

一个非终结符对应一种数据类型；同一左侧的各条产生式对应不同变体；右侧的非终结符、标识符和数字产生字段。第一个字段应保存哪个子树，由文法右侧的顺序确定。具体标点帮助识别分支，通常不保存成独立字段。

原书例 · 复合语句的树形结构

原书印刷 p.383 / PDF 406。

(statement-datum
 (parse-statement "{x := foo; while x do x := (x - bar)}"))
(block (assign x (var foo))
       (while (var x) (assign x (- (var x) (var bar)))))

最外层恰有两条语句：一次赋值与一个循环。循环又有测试表达式和赋值语句；减法表达式有两个变量子树。这里用伴读formatter显示树的角色，实际输入仍是SLLGEN生成的类型实例。

阅读注解
抽象语法

标点参与识别，不必成为字段

右侧的非终结符、标识符和数字贡献语义字段；括号、关键字等字面串通常由构造器选择所体现。

检查范围

解析器只保证指定的语法结构

并行赋值两侧长度相等、变量已绑定或对象具有方法，都还需要后续阶段检查。

B.3 SLLGEN 中的扫描器与解析器

原书印刷 p.383 / PDF 406。

SLLGEN 将词法规范和文法规范分别写成 Scheme 数据。文法中的字面串会自动进入扫描器，因此不必手工重复声明 while、括号等每个关键字和标点。下面沿原书四个无编号小标题依次说明生成过程。

阅读注解
生成与执行

先生成工具，再用工具处理输入

规范描述怎样识别输入；生成的扫描器/解析器是可反复调用的过程。解释器随后读取生成的AST。

复用接口

同一套语法树支持不同前端

字符串入口和流入口都产生树；求值器可以共用，但输入边界和错误恢复要分别设计。

扫描器规范与最长匹配

原书印刷 p.383 / PDF 406。

词法规则由类别名、正则表达式序列和动作组成。序列在顶层连接；or 表示选择，concat 表示连接，arbno 表示零次或多次重复，not 只否定一个字符。预定义测试包括 letter、digit、whitespace 和 any。

(define scanner-spec
  '((white-sp (whitespace) skip)
    (comment ("%" (arbno (not #\newline))) skip)
    (identifier (letter (arbno (or letter digit))) symbol)
    (number (digit (arbno digit)) number)))

动作 skip 不发出token；symbol、number 和 string 分别转换缓冲区内容并发出相应数据。先取最长匹配；同长时字符串动作优先于符号动作，所以文法关键字能够胜过普通标识符。

本机 eopl 扫描器对 1@2 可只返回合法前缀 1。伴读算术公开入口先用 check-characters 核对全部字符，确保这类输入拒绝；百分号注释直到行尾或输入结尾，其内部字符不作算术检查。这个入口校验与原书的词法规范分开实现。

阅读注解
词法负号

减号由语法区分一元与二元用途

若扫描器贪心把-2当作一个数字token，3-2可能丢失减法运算符。本附录数字规则只收数字，负号作为独立标点。

输入覆盖

完整输入不能只剩一个合法前缀

本机SLLGEN可在未识别字符前停止扫描。伴读算术入口先核对全部字符，注释范围内则允许任意内容。

文法规范与 LL(1) 选择

原书印刷 p.385 / PDF 408。

每条产生式包含左侧非终结符、右侧项目列表和变体名。第一条产生式的左侧是开始符号。右侧字符串表示需要匹配的字面串，符号表示非终结符或已由扫描器识别的数据项。

(define statement-grammar
  '((statement ("{" statement ";" statement "}") compound-statement)
    (statement ("while" expression "do" statement) while-statement)
    (statement (identifier ":=" expression) assign-statement)
    (expression (identifier) var-exp)
    (expression ("(" expression "-" expression ")") diff-exp)))

SLLGEN 使用 LL(1) 预测：知道当前要识别的非终结符和下一个token，就应能选定产生式。两个候选若具有相同开头，需要先提取共同前缀或改变文法；普通的左递归算术文法不能直接交给它。习题 B.1用非空首项配合 arbno 的后缀序列，避免左递归并保留优先级层次。

阅读注解
开始符号

首条产生式决定整次解析的目标

同一组非终结符若以statement开头，入口解析语句；若以expression开头，入口解析表达式。

预测选择

重复的退出也需要可判定的边界

对arbno既要知道何时继续，也要知道何时交给后续部分；重复体为空或与后继token冲突都可能破坏LL(1)。

生成数据类型、解析器与交互循环

原书印刷 p.386 / PDF 409。

图 B.2 把生成步骤放在一起：sllgen:make-define-datatypes 建立变体，sllgen:list-define-datatypes 返回其说明，sllgen:make-string-scanner 生成扫描过程，sllgen:make-string-parser 生成从字符串到AST的过程。字段的自动名字可能改变；程序应通过构造器与 cases 使用它们。

(sllgen:make-define-datatypes scanner-spec unary-grammar)
(define raw-parse-unary
  (sllgen:make-string-parser scanner-spec unary-grammar))
(define raw-scan-arithmetic
  (sllgen:make-string-scanner scanner-spec unary-grammar))

流版本持续处理字符，向求值回调交付一棵棵语法树。原书 p.386 写输出为token流，但图B.2和下一页说明要求把解析后的树交给求值器；本机SLLGEN的流实现也这样工作。词法扫描器输出token，语法解析器输出AST，这个边界应保持清楚。

伴读提供 arithmetic-repl：输入 5; 与 2+3; 时，两次都输出5。分号是这个交互入口明确增加的表达式终结符，字符串算术入口不使用它。本机SLLGEN在干净EOF仍报告开始符号错误，伴读先用流端口逐字符检查输入，避免未知字符被底层扫描器当作结束，再只把这一确切EOF情况作为正常结束；缺失运算对象或终结符仍报错。

阅读注解
树与token

流解析器的输出也应是AST

原书p.386把输出写为token流；结合后面的求值回调及本机实现，应理解为语法树流。

流边界

换行是否结束输入属于文法约定

算术表达式可继续接运算符，单靠换行不提供结束标记。伴读交互入口用分号收束一式，并只处理干净EOF。

arbno 与 separated-list 的字段结构

原书印刷 p.388 / PDF 411。

arbno 重复整个项目序列，每个有数据的项目各产生一列列表。例如 (arbno identifier "=" expression) 重复两次，得到两个名字和两个右侧表达式，而非交替混在一个列表里。

原书例 · 一次重复，字段分别累积

原书印刷 p.389 / PDF 412。

(bindings-datum (parse-bindings "let x = y u = v in z"))
(let (x u) ((var y) (var v)) (var z))

原书机制例 · 分隔与终结的差别

原书印刷 p.388 / PDF 411。

(block-datum (parse-terminated "{x:=y;z:=t;}"))
(block-datum (parse-separated "{x:=y;z:=t}"))
((x y) (z t))
((x y) (z t))

两种结构的字段可以相同，具体字符串却不同。前者把分号放进重复体，每条语句后都有；后者只在相邻项之间分隔。两种都接受空块，后者拒绝尾分号，前者拒绝漏掉最后的分号。

原书例 · 嵌套重复增加列表层次

原书印刷 p.390 / PDF 413。

(parallel-datum
 (parse-parallel "{x,y := u,v ; z := 4; t1,t2 := 5,6}"))
(((x y) (z) (t1 t2))
 ((u v) (4) (5 6)))

外层对应三条并行赋值，内层对应同一条赋值的多个名字与表达式。这个文法允许两侧长度不同，甚至允许内部空列表；若执行并行赋值，还须另外检查逐条长度相等并先在旧环境算完全部右侧。

阅读注解
平行列表

重复一次产生一组对应字段

arbno中的identifier与expression各形成一列，位置对应；嵌套重复再给每列增加一层列表。

分隔符

分隔在两项之间，终结符跟在每项之后

separated-list允许空表，但不允许最后多一个分隔符；arbno若把分号写进重复体，则最后一项也需要分号。

原书印刷 p.391 / PDF 414。

习题 B.1 · ★

原题

下面这个普通算术表达式的文法内建了算术运算符通常的优先级规则：

Arith-expr ::= Arith-term {Additive-op Arith-term}*
Arith-term ::= Arith-factor {Multiplicative-op Arith-factor}*
Arith-factor ::= Number
             ::= ( Arith-expr )
Additive-op ::= + | -
Multiplicative-op ::= * | /

这个文法说明：每个算术表达式都是一个非空项序列的和；每个项都是一个非空因子序列的积；每个因子是常数或加括号的表达式。

编写 SLLGEN 词法规范和文法，按这个文法扫描并解析字符串。验证文法正确处理优先级，例如将 3+2*66-5 正确分组为 3+(2*66)-5。

印刷 p.391 / PDF 414

解答与执行

数字使用无符号数字规则，运算符由文法作为独立标点识别。表达式先取一个项，再收集加减后缀；项先取一个因子，再收集乘除后缀。括号递归回到完整表达式。完整规则如下，使用的是实际SLLGEN而非手写替代解析器。

(define base-grammar
  '((arith-expr (arith-term (arbno additive-op arith-term)) an-expr)
    (arith-term (arith-factor (arbno multiplicative-op arith-factor)) a-term)
    (arith-factor (number) number-factor)
    (arith-factor ("(" arith-expr ")") group-factor)
    (additive-op ("+") plus-op) (additive-op ("-") minus-op)
    (multiplicative-op ("*") times-op) (multiplicative-op ("/") divide-op)))
(arithmetic-datum (parse-base "3+2*66-5"))
(expr (term 3 () ()) (+ -)
      ((term 2 (*) (66)) (term 5 () ())))

乘法留在第二个term内部，外层加减仅看到三个项3、132和5，因此层次给出先乘除再加减。AST还保存运算符列表；只存三个项会丢掉减号，无法正确求值。

习题 B.2 · ★★

原题

为什么习题 B.1 中的文法不能用 separated-list 来写？

印刷 p.391 / PDF 414

解答与执行

separated-list 的分隔符位置要求一个固定字面字符串，而加减层的分隔位置是非终结符 Additive-op，要在加号与减号之间选择并保存选择结果；乘除层同理。若固定写成加号，就无法识别减法；即使只接受一个符号并丢掉它，也不能恢复每一步究竟用哪个运算。

可以另写一个“首项后接运算符和下一项的重复序列”，这正是 arbno 方案。理论上能通过改写或扩充生成器支持更一般的分隔结构，但那已改变了当前 separated-list 的语法和字段规则。非空要求也必须由首项单独保证。

习题 B.3 · ★★

原题

定义一个解释器，接收习题 B.1 的解析器产生的语法树，并把它作为算术表达式求值。解析器已经处理了通常的算术优先级，但解释器还必须处理结合性：保证同一优先级的运算，例如加法与减法，按从左到右执行。因为这些表达式中没有变量，解释器不需要环境参数。

印刷 p.391 / PDF 414

解答与执行

在每一层把首项值放进累积器，再按保存的运算符与后续值从左到右更新。每次更新后，累积器等于已经处理完的那个前缀的值；循环结束就得到整层结果。这一不变量同时说明减法和除法为什么采用左结合。

查看实际求值器
(define (eval-arithmetic tree [env '()])
  (define (lookup name)
    (cond [(assq name env) => cdr]
          [else (error 'unbound "unbound arithmetic variable ~a" name)]))
  (define (add op a b)
    (cases additive-op op (plus-op () (+ a b)) (minus-op () (- a b))))
  (define (mul op a b)
    (cases multiplicative-op op
      (times-op () (* a b))
      (divide-op () (when (zero? b) (error 'division "division by zero")) (/ a b))))
  (define (expr e)
    (cases arith-expr e
      (an-expr (first ops rest)
        (for/fold ([acc (term first)]) ([op ops] [t rest]) (add op acc (term t))))))
  (define (term t)
    (cases arith-term t
      (a-term (first ops rest)
        (for/fold ([acc (factor first)]) ([op ops] [f rest]) (mul op acc (factor f))))))
  (define (factor f)
    (cases arith-factor f
      (number-factor (n) n)
      (group-factor (e) (expr e))
      (variable-factor (name) (lookup name))
      (negative-factor (f) (- (factor f)))))
  (expr tree))
(calculate "20-5-3" #:mode 'base)
(calculate "48/4/3" #:mode 'base)
(calculate "1/2+1/3" #:mode 'base)
12
4
5/6

若改为右结合，前两项分别成为18和36，已经改变语义。无变量版本只走数字和分组分支，传入的空环境不被访问；完整共享实现为后续两题保留可选环境。整数及分数均为Racket精确数，除零明确拒绝。

习题 B.4 · ★★

原题

扩展习题 B.3 的语言和解释器，加入变量。这个新解释器将需要一个环境参数。

印刷 p.391 / PDF 414

解答与执行

给因子增加 (arith-factor (identifier) variable-factor)，并让求值器接收环境。遇到变量时按名字查找；遇到数字、分组、运算符时沿用已有规则。环境采用从近到远的关联表，因此同名时第一项生效，未找到则报告未绑定。

(calculate "x-y*3" '((x . 7) (y . 2)) #:mode 'variables)
(calculate "x+x" '((x . 3) (x . 100)) #:mode 'variables)
1
6

新增变量不会改变优先级和结合性。伴读要求环境值是精确有理数，使算术分支保持同一数域；本题没有引入绑定表达式或赋值，环境由调用者提供。

习题 B.5 · ★

原题

在语言和解释器中加入一元负号，使 3*-2 这样的输入也能得到正确处理。

印刷 p.391 / PDF 414

解答与执行

让因子增加 (arith-factor ("-" arith-factor) negative-factor)，其值为内部因子值的相反数。负号在因子层递归，优先级高于乘除；连续负号也有明确结构。扫描器仍只把无符号数字识别为数字，所以同一减号可以由语法位置区分为二元或一元运算。

(calculate "3*-2")
(calculate "--2")
(calculate "-(3+2)*4")
(calculate "3--2")
-6
2
-20
5

例如 3*-2 扫描为3、乘号、负号、2；因子负号先构造 (neg 2)，再作为乘法右侧。基本模式仍拒绝一元负号，变量模式只增加变量，完整模式才同时支持两项扩展。

运行附录程序

将 appendix_b.rkt 与 test_appendix_b.rkt 放在同一目录，使用 Racket 8.17、eopl 与 rackunit。扫描器、解析器和数据类型确由SLLGEN生成；算术求值器直接遍历AST，使用精确整数/有理数。

racket appendix_b.rkt

主程序依次显示分层语法树、130、12、4、1与-6。parse-base只接受基本算术，parse-variables增加变量，parse-unary再增加一元负号；calculate默认完整模式。字符覆盖校验、未绑定和除零各自明确失败。

;; The installed SLLGEN scanner can stop at an unsupported character. Guard the
;; entire arithmetic input so a valid prefix is never silently accepted.
(define (check-characters text)
  (for/fold ([comment? #f]) ([c (in-string text)])
    (cond [(char=? c #\newline) #f] [comment? #t] [(char=? c #\%) #t]
          [(or (char-whitespace? c) (char-alphabetic? c) (char-numeric? c)
               (memv c '(#\( #\) #\+ #\- #\* #\/))) #f]
          [else (error 'scanner "unsupported arithmetic character ~s" c)]))
  text)

(define (parse-unary text) (raw-parse-unary (check-characters text)))
(define (parse-arithmetic text #:mode [mode 'unary])
  ((case mode [(base) parse-base] [(variables) parse-variables] [(unary) parse-unary]
     [else (error 'parse-arithmetic "unknown mode ~a" mode)]) text))
;; BEGIN arithmetic-fold
(define (eval-arithmetic tree [env '()])
  (define (lookup name)
    (cond [(assq name env) => cdr]
          [else (error 'unbound "unbound arithmetic variable ~a" name)]))
  (define (add op a b)
    (cases additive-op op (plus-op () (+ a b)) (minus-op () (- a b))))
  (define (mul op a b)
    (cases multiplicative-op op
      (times-op () (* a b))
      (divide-op () (when (zero? b) (error 'division "division by zero")) (/ a b))))
  (define (expr e)
    (cases arith-expr e
      (an-expr (first ops rest)
        (for/fold ([acc (term first)]) ([op ops] [t rest]) (add op acc (term t))))))
  (define (term t)
    (cases arith-term t
      (a-term (first ops rest)
        (for/fold ([acc (factor first)]) ([op ops] [f rest]) (mul op acc (factor f))))))
  (define (factor f)
    (cases arith-factor f
      (number-factor (n) n)
      (group-factor (e) (expr e))
      (variable-factor (name) (lookup name))
      (negative-factor (f) (- (factor f)))))
  (expr tree))
;; END arithmetic-fold
(define (calculate text [env '()] #:mode [mode 'unary])
  (unless (and (list? env) (andmap (lambda (p) (and (pair? p) (symbol? (car p)) (rational? (cdr p)) (exact? (cdr p)))) env))
    (error 'environment "expected symbol/exact-rational bindings"))
  (eval-arithmetic (parse-arithmetic text #:mode mode) env))
(define (arithmetic-datum tree)
  (define (a op) (cases additive-op op (plus-op () '+) (minus-op () '-)))
  (define (m op) (cases multiplicative-op op (times-op () '*) (divide-op () '/)))
  (define (e x) (cases arith-expr x (an-expr (first ops rest) (list 'expr (t first) (map a ops) (map t rest)))))
  (define (t x) (cases arith-term x (a-term (first ops rest) (list 'term (f first) (map m ops) (map f rest)))))
  (define (f x) (cases arith-factor x (number-factor (n) n) (variable-factor (x) x)
                         (group-factor (x) (list 'group (e x))) (negative-factor (x) (list 'neg (f x)))))
  (e tree))

(define (checked-arithmetic-port source)
  ;; make-input-port buffers peeks for us. Validate characters as the scanner
  ;; consumes them, retaining interactive streaming and arbitrary comment text.
  (define comment? #f)
  (define pending #"")
  (make-input-port
   'checked-arithmetic
   (lambda (dest)
     (when (zero? (bytes-length pending))
       (define c (read-char source))
       (unless (eof-object? c)
         (cond [(char=? c #\newline) (set! comment? #f)]
               [comment? (void)] [(char=? c #\%) (set! comment? #t)]
               [(or (char-whitespace? c) (char-alphabetic? c) (char-numeric? c)
                    (memv c '(#\( #\) #\+ #\- #\* #\/ #\;))) (void)]
               [else (error 'scanner "unsupported arithmetic character ~s" c)])
         (set! pending (string->bytes/utf-8 (string c)))))
     (if (zero? (bytes-length pending)) eof
         (let ([n (min (bytes-length dest) (bytes-length pending))])
           (bytes-copy! dest 0 pending 0 n)
           (set! pending (subbytes pending n))
           n)))
   #f void))

  ;; Only that exact boundary is normal completion; incomplete expressions fail.

                       (raise e)))])

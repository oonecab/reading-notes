11.1 · 一次请求与响应，把资源变成服务The Client-Server Programming Model

来源：印刷 954—955 页 / PDF 955—956 页

第10章使程序能够从描述符读取和写出字节；本章进一步问：另一端如何知道这些字节要它做什么？客户端先发送请求，服务器解释请求并操作它管理的资源，再返回响应，客户端最后解释响应。一次网页访问中，资源可能是磁盘上的HTML；一次动态加法请求中，资源可能是运行计算程序的能力。真正把“字节通信”变成“服务”的，是双方对消息格式和处理含义的约定。

原文伴读 · 角色属于进程

It is important to realize that clients and servers are processes and not machines, or hosts as they are often called in this context.

中文：应当认识到，客户端和服务器是进程，而不是机器；这里常把机器称为主机。

因此127.0.0.1上的本地实验同样是在做网络编程。一个server进程也能为了取得数据而成为另一个server的client。

来源：印刷 955 页 / PDF 956 页

书中称这四步为transaction（事务），但没有赋予它数据库事务的原子性。服务器可能已写入文件而响应途中断线；客户端看到失败并不自动证明操作没有发生。这里只建立交互框架，重试、去重、事务提交需要应用另行设计。请求方主动开始交互、服务方等待请求，是本章client/server的角色约定。

阅读注解
角色

进程承担服务角色

同一主机可同时有多个client和server；一个进程在不同交互中也可承担两种角色。

语义

一次交互不承诺原子性

本章transaction描述请求到响应的步骤，并没有自动加入数据库的ACID性质。

11.2 · 封装让异构链路承载同一种通信Networks

来源：印刷 955—960 页 / PDF 956—961 页

从主机看，网络适配器是一种I/O设备。CPU通过内核组织数据，网卡通常借DMA在设备与主存之间搬运字节。网络把许多主机连接起来，但每一种链路的帧格式、寻址和带宽可能不同：原书先用集线器把比特复制到同段各端口，再用网桥选择性地转发帧，最后用路由器连接不同LAN/WAN。图中100Mb/s与1Gb/s是原书示意条件，不应被当作当前网络速率上限。

集线器重复比特，网桥依据学习到的链路地址选择端口，路由器依据网络层目的地址选择下一跳；三者工作的层次不同。一个IP分组的目的主机在远处时，本段以太网帧的目的地址可以是本地路由器。路由器收到后取出IP分组，换上下一段链路需要的帧头再发送。统一命名和统一分组格式，把各段不同的物理技术藏在网络层之下。

阶段外层链路帧内层分组与数据
A发往路由器LAN1头：下一跳为路由器IP目的B；载荷为应用字节
路由器转发去掉LAN1头，建立LAN2头查看目的IP以选择接口；IP头的部分字段可能改变
B交给服务器去掉LAN2头及协议头内核把字节复制到服务器读取缓冲区

原图11.7的八步是：用户A调用系统调用；A内核加网络头与LAN1帧头；网卡送出；路由器接收；路由软件选择LAN2并重新封装；LAN2网卡发送；B接收；B内核在server读取时交付载荷。先抓住“内部数据被装入外部容器”，再看MTU、分片、重传与路由更新；后几项被原书有意省去。

一条write调用传入3000字节，并不等于网上出现一个3000字节帧，也不保证对端一次read正好收到3000字节。TCP分段、内核缓冲和调度都会改变分批交付方式。后面的程序以返回字节数推进读取位置，正是为了让协议独立于这些分批方式。

阅读注解
分层

目的IP与下一跳不同

跨路由器后链路帧头会更换；目的IP描述最后要到的主机，下一跳只描述本链路接收者。

边界

图是封装模型

原书把分段、重传、MTU等细节省去；一次write不是一个以太网帧。

11.3 · 程序看见地址、名字与连接The Global IP Internet

来源：印刷 960—968 页 / PDF 961—969 页

原书把复杂的TCP/IP内部机制压缩成三个应用可用的服务：地址命名、域名映射和进程间连接。IP提供尽力交付的分组，TCP在其上提供字节流；UDP属于另一种报文接口，本章不展开。原书印刷960页把UDP展开成“Unreliable Datagram Protocol”，标准名称是User Datagram Protocol，不能把描述性“不可靠”当作正式名称。

原书2015年的IPv6采用率和“最新HTTP版本”等陈述属于出版时背景。下面继续使用IPv4与HTTP/1.x解释机制，并在接口处明确如何扩展，避免把历史数据变成当前互联网的断言。

11.3.1 · 把数值、字节序与显示格式分开IP Addresses

来源：印刷 961 页 / PDF 962 页

本章的IP地址特指IPv4的32位值。struct in_addr.s_addr保存网络字节序；端口用16位网络字节序。对128.2.194.242，依次取四个字节80、02、C2、F2（十六进制），得到数学上的32位地址0x8002C2F2。把一个十进制点分字符串直接按C字符串发送，与发送这四个地址字节，是两种完全不同的编码。

原文伴读 · 网络顺序保持大端

Addresses in IP address structures are always stored in (big-endian) network byte order, even if the host byte order is little-endian.

中文：IP地址结构中的地址总以大端网络字节序保存，即使主机采用小端字节序。

这里转换的是对象表示。不要把htons返回的本机数值打印结果误认为“网络的十进制表示”。

来源：印刷 961 页 / PDF 962 页

接口输入→输出宽度/返回判断
htons / ntohs主机16位整数 ↔ 网络16位表示端口等16位字段
htonl / ntohl主机32位整数 ↔ 网络32位表示IPv4字段；l不表示宿主long宽度
inet_pton文本 → 网络二进制地址1成功，0非法文本，−1接口错误
inet_ntop网络二进制地址 → 文本返回目标缓冲区或NULL

以端口1024为例，主机数学值是0x0400；网络内存中从低地址到高地址必须是04 00。小端机器里，若把这两字节作为本机uint16_t读取，得到0x0004；这并不改变协议里的端口1024。只有在需要本机整数参与算术或格式化时调用ntohs。重复转换两遍在小端机器上会恢复原排列，恰好破坏了发送所需的顺序。

11.3.2 · 名字解析返回候选地址集合Internet Domain Names

来源：印刷 963 页 / PDF 964 页

域名按点分的层级命名，但不能从名字推断IP地址。DNS把名字映射到资源记录，常见地址记录包括IPv4的A和IPv6的AAAA。一个名字可能给出多个地址，多个名字也可指向相同地址；有的合法域名只有其他类型记录而没有主机地址。书中用“名字与地址的等价类”帮助理解多对多关系，实际DNS不保证正反向映射对称，也不保证查询一直返回同一列表。

程序调用getaddrinfo时，结果可能来自DNS、hosts文件或本机的名称服务配置。因此“函数成功”只说明获得了候选地址，不保证每个地址上的指定服务都能连接。书中twitter和大学主机的解析结果是当时的样例，本页不把它们写成实时事实。默认实验仅使用数值127.0.0.1，不依赖公网DNS。

原书称localhost总映射到127.0.0.1，适用于它的IPv4讲解。实际名称服务也可提供IPv6回环::1。学习地址无关接口时应保留AF_UNSPEC与候选遍历；需要确定IPv4实验时显式使用AF_INET或数值IPv4地址，而不是根据第一次解析结果猜协议。

11.3.3 · 连接由两个端点共同标识Internet Connections

来源：印刷 965 页 / PDF 966 页

TCP向应用提供有序、双向的字节流。一个socket是一个通信端点，端点地址含IP与16位端口；在这里固定TCP协议时，两端IP/port组成的四元组区分连接。服务器通常在约定端口等待，客户端由内核选择临时端口。原书的实例是(128.2.194.242:51213, 208.216.181.15:80)，客户端再建立第二条连接时通常得到另一个临时端口。

连接客户端端点服务端端点
A127.0.0.1:51001127.0.0.1:42000
B127.0.0.1:51002127.0.0.1:42000

两条连接共享服务器端口42000，内核仍能把到达字节分送到不同connfd。端口不是永久独占地标识一个进程：一个进程可持有许多socket，父子也可共享一个打开的socket。端口与协议、地址和连接状态一起才构成准确描述。

可靠传输表示协议在连接正常工作的条件下处理丢失、重复和顺序。它不保证对端应用已经执行请求；write成功往往只表示字节进入本地发送路径。对端崩溃或网络故障仍可让操作失败。应用若要确认“加法已计算”或“文件已提交”，需要读取有约定含义的响应。

把两条连接的四元组分别写全，就能看出服务器端口为何可重复：(127.0.0.1,51001,127.0.0.1,42000) 与 (127.0.0.1,51002,127.0.0.1,42000) 在客户端端口这一项不同，内核能区分它们。服务器的 connfd 是本进程引用其中一个连接的编号，不是网络上传输的端口号；fd=4 也完全可能对应服务端端口 42000。

阅读注解
先猜

0x0400的网络字节

数值1024写成大端字节是04 00；小端主机将这两字节当本地整数读，会看到4。

校注

地址长度随协议而定

本章32位指IPv4；IPv6为128位。DNS地址结果及原书2015年统计不能当当前事实。

11.4 · 沿一个连接的生存期理解接口The Sockets Interface

来源：印刷 968—984 页 / PDF 969—985 页

11.4.1 · 地址结构描述协议，描述符表示对象Socket Address Structures

来源：印刷 969 页 / PDF 970 页

sockaddr_in包含AF_INET、网络序端口和网络序地址。应用从系统头文件取得结构定义，不手写图11.13的布局：原图描述Linux，而Darwin等系统还可能包含长度字段。把具体结构指针转成struct sockaddr *，是旧式通用接口的调用约定；不会把IPv4地址“转换成另一种协议”。

接收未知地址族时可用sockaddr_storage，它提供足够的大小和合适对齐；实际长度另放在socklen_t变量中。传给accept前把它置为容量，返回后它变成实际地址长度。不要把inet地址结构大小固定写死，也不要把原书印刷972页的int *addrlen当作本机声明：使用头文件中的socklen_t *。

原文伴读 · 端点通过描述符呈现

From the perspective of a Linux program, a socket is an open file with a corresponding descriptor.

中文：从Linux程序的角度看，socket是一个带有对应描述符的打开文件。

因此连接建立后可以使用read/write，dup2也能把标准输出指向连接；但socket不支持普通磁盘文件的所有操作，例如不能用lseek随意回退字节流。

来源：印刷 969 页 / PDF 970 页

11.4.2 · 先申请端点对象，还没有建立连接The socket Function

来源：印刷 970 页 / PDF 971 页

socket(AF_INET, SOCK_STREAM, 0)申请IPv4流socket。成功返回非负fd，失败返回−1并设置errno；fd=0也可能是合法返回值，所以不能用“是否大于0”判断成功。此时没有对端，不能把“socket创建成功”称为“已经连上服务器”。地址无关代码则把getaddrinfo返回的ai_family/ai_socktype/ai_protocol原样传入。

int fd = socket(p->ai_family, p->ai_socktype, p->ai_protocol);
if (fd < 0) { /* try the next candidate */ }

本章讨论TCP流，默认协议0让内核为给定family/type选择协议。数据报socket有不同的连接与消息语义，不能把这里“连接之后再读写”的步骤无限推广到所有socket类型。

11.4.3 · 把主动端点接到服务器地址The connect Function

来源：印刷 970 页 / PDF 971 页

connect(fd, addr, addrlen)发起连接。阻塞socket一般等到成功或错误才返回；成功后内核已确定本地地址和临时端口，程序可用getsockname检查本地端点、getpeername检查对端。调用返回成功不必等server用户代码已经从accept返回，内核的连接队列会衔接两边。

一个域名可返回多个候选地址。每个候选先socket，再connect；失败后关闭这个fd再试下一项。保留失败fd重复当作全新端点使用，会把状态和所有权弄混。非阻塞connect的EINPROGRESS属于另一条状态机，需要等待就绪并查询SO_ERROR；本页echo使用小型loopback阻塞连接，HTTP收发则明确设置有界等待。

11.4.4 · 把服务端socket绑定到本地地址The bind Function

来源：印刷 971 页 / PDF 972 页

bind把socket与本地地址/端口关联。固定端口使客户端知道去哪里找服务；端口0则要求内核分配空闲端口，再用getsockname取回实际值。绑定127.0.0.1只接受本机IPv4回环访问；通配地址0.0.0.0可以覆盖多个本地接口，两者开放范围不同。

原书open_listenfd用AI_PASSIVE和NULL主机生成通配地址。本页实验明确绑定127.0.0.1和端口0，避免冲突，也使测试不依赖外部网络。SO_REUSEADDR常用于服务重启时的地址复用，具体行为由平台决定；它不等于允许任意两个活动服务器无条件占用同一个监听地址。

11.4.5 · 监听对象维护待接受连接The listen Function

来源：印刷 971 页 / PDF 972 页

listen把已绑定的流socket变成被动监听对象。backlog描述待处理连接排队的容量请求，实际队列、上限和含义由系统实现约束；它既不是线程数，也不是服务器一生最多能服务的客户端数量。默认测试只有一个客户端，所以backlog=1足以表达这个实验。

监听fd通常随服务器进程长期存在。客户端慢慢发送HTTP头时，它占用的是已经accept出来的连接；增加backlog并不能让迭代服务器同时处理这些连接的数据。要解决这个阻塞，需要第12章的进程、事件驱动或线程调度。

11.4.6 · 一次接受，产生一个新的连接fdThe accept Function

来源：印刷 972 页 / PDF 973 页

accept在listenfd上等待，返回connfd并可选地填入客户端地址。listenfd继续保持监听状态；connfd才是这次客户端字节流的端点。在原书图11.14中listenfd=3、connfd=4只是示意，操作系统可以返回任意可用非负fd。

时刻listenfdconnfd客户端fd
socket/bind/listen完成接受连接的入口尚不存在可能尚不存在
客户端connect，server accept仍是原监听对象新建连接端点连接完成后可读写
请求处理完关闭connfd仍可接受下一次连接释放本次引用读完最后字节后见EOF

常见错误是拿listenfd去read：它不代表某一条已建立连接。另一种错误是fork后忘记关闭多余connfd引用，导致另一端迟迟看不到EOF。第10章的“描述符是引用，不等于唯一所有者”在这里直接决定连接什么时候结束。

11.4.7 · 候选链表把地址族细节封装起来Host and Service Conversion

来源：印刷 973 页 / PDF 974 页

getaddrinfo(host, service, &hints, &list)把主机/服务文本转换成候选链表。hints先整体清零，再设置family、socktype和flags；每个节点已经带好socket、connect或bind需要的参数。使用完毕调用freeaddrinfo，即使连接失败也要释放。返回值是EAI_*错误码，用gai_strerror解释；它不是统一的−1/errno接口。

字段或flag作用实验中的选择
AF_UNSPEC / AF_INET不限制地址族 / 仅IPv4hostinfo题沿原书用AF_INET
SOCK_STREAM限制为流socket候选排除数据报和原始socket候选
AI_NUMERICHOST / AI_NUMERICSERV拒绝把输入当名字查询纯数字实验不依赖DNS或服务数据库
AI_PASSIVE + NULL host用于服务器通配本地地址本实验改用明确回环地址
NI_NUMERICHOST / NI_NUMERICSERV把地址/端口显示成数字日志不会为反向解析额外等待

getnameinfo做相反方向的显示转换，能依据sockaddr中的地址族自动选择格式；inet_ntop需要先确定family并取得对应结构中的地址字段。练习11.4故意用较低层接口，让我们看清被高级接口隐藏的强制转换和结构成员选择。

例：从地址信息建立连接

11.4.9 · 收到多少字节，就按同样长度回送Example Echo Client and Server

来源：印刷 980 页 / PDF 981 页

原书echo client逐行读取stdin，用rio_writen发出，再用rio_readlineb读回一行；server循环接受一个client，直到该client EOF才接下一个。行协议依赖换行字符作为边界，TCP本身不知道“行”。如果双方都先等对方发送一行，就会互相等待；如果client发送未换行的最后片段又等待完整行，server也可能仍在等换行。

原文伴读 · EOF不是一个特殊字符

First, we need to understand that there is no such thing as an EOF character.

中文：首先要明白，不存在一个所谓EOF字符。

read返回0表达流结束状态；它不占一个字节。TCP半关闭可结束发送方向，同时保留接收响应的能力。

来源：印刷 984 页 / PDF 985 页

实验ch11_echo发送11个字节：ab\nx\0y\ntail。client故意分两次写，随后shutdown(SHUT_WR)；server每次最多读3字节并按实际n回写，读到0后也关闭发送方向；client继续读到EOF并逐字节比较。内嵌NUL和最后无换行的tail都保持原样，因为我们不用strlen决定二进制载荷长度。

状态client发送方向server动作client接收方向
写入11B开放read可得到不同分块仍开放

server完成echo并半关闭已结束总字节计数必须为11读完echo后得到0

这个小实验让两种角色在同一进程按顺序执行，11字节足以放入内核缓冲；它验证真实TCP接口、短块处理与半关闭语义，不是大流量服务器。大数据若“全部发完才读回复”，可能因为双方缓冲区填满而死锁，必须交错收发或引入并发。

半关闭结束的是一条方向

一个 TCP 连接可同时看成“客户端→服务端”和“服务端→客户端”两条字节方向。客户端执行 shutdown(fd,SHUT_WR) 后，承诺自己不会再发送新字节，但仍保留读取回复的能力。服务端读完此前排队的所有字节后，正长度 read 才返回 0，知道请求输入结束；它仍可把处理结果写回另一个方向。若客户端此时直接 close 唯一 fd，就同时放弃了这个读取入口，无法再用它收取 echo。

11.5.3 · 先定消息边界，再解释字段HTTP Transactions

来源：印刷 986 页 / PDF 987 页

一次请求以method SP request-target SP version CRLF开始，后面每条首部也以CRLF结束，空行CRLF结束首部。请求正文是否存在及其长度由协议字段决定，不能把“读完首部”当作“整个请求读完”。响应也先有状态行和首部，然后才是正文。

POST /cgi-bin/adder HTTP/1.1
Host: 127.0.0.1
Content-Type: application/x-www-form-urlencoded
Content-Length: 7

a=2&b=3

这里正文恰为7字节。假设一次read取回“首部空行加a=2”，下一次取回“&b=3”，解析器必须保留首次多读的3字节，再补4字节；不能丢掉已进入用户缓冲区的内容。若连接在6字节时EOF，是截断请求；若收到两个互相矛盾的Content-Length，必须拒绝，不能由不同层各自挑一个解释。

HTTP/1.0 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 17
Connection: close

<p>2 + 3 = 5</p>

正文<p>2 + 3 = 5</p> 为17个ASCII字节。Content-Length不包括响应头，也不包括头与正文之间的空行；若正文有中文，应先UTF−8编码再计数。HEAD保留GET本应发送的长度，但实际不发送body，所以不能机械地要求所有响应都跟着Content-Length字节正文。

首部值两端的OWS只包括SP与HTAB；例如Content-Length: 7 \t仍表示7字节，Content-Type: application/x-www-form-urlencoded\t仍是相同媒体类型。C与Python都先剔除首尾这两种字节，保留值内空白；Content-Length : 7在字段名与冒号之间插入空白，仍须拒绝，控制字符也不作为普通空白放行。此处依据RFC 9112 §5.1。本页拒绝Transfer-Encoding、Expect和过大的请求；不实现chunked、持久连接、流水请求、Range或TLS。它对一个连接只生成一个响应。遇到Expect: 100-continue时，客户端可能只发送请求头，然后等待服务器决定是否接收正文。本实验先验证完整首部、消息长度语法与HTTP/1.1的Host要求：缺失、空值或重复Host返回400；只有通过这些检查的Expect请求才立即返回417并关闭连接；如果先等待Content-Length指定的正文，客户端与服务器就会互相等待。普通POST仍须收到完整正文才处理。原书引用RFC2616来解释HTTP/1.1，是教材的历史标准入口；题解使用其字段语义，同时不沿用“HTTP/1.1是当前最新版本”的出版时陈述。

显示成空行的边界，线上实际是四字节 \r\n\r\n，即 0d 0a 0d 0a：前两个结束最后一个首部，后两个表示一条空首部行。正文从紧随其后的字节开始。解析器必须能在不同 read 之间保留未完成边界，例如第一次只读到 \r\n\r，下一次的首字节 \n 才把它补齐；一次读取结束不是协议边界。

11.5.4 · CGI把请求信息转为环境和标准流Serving Dynamic Content

来源：印刷 989 页 / PDF 990 页

CGI定义服务器与子程序之间的约定。GET查询通常放进QUERY_STRING；POST数据放在标准输入，CONTENT_LENGTH说明应读多少字节，CONTENT_TYPE说明格式，REQUEST_METHOD说明方法。子程序把类型、长度等CGI响应头和内容写到stdout。服务器可直接把stdout连到socket，也可以先用pipe收集结果，再组成最终HTTP响应。

原书Tiny在fork后的child里setenv，再dup2(connfd, STDOUT_FILENO)，最后execve执行adder。exec替换程序映像，未设置close-on-exec的打开描述符仍可继承，因此adder的printf会进入socket。原书parent调用wait回收child；其他回收策略在练习11.8和第12章展开。

缓冲输入使POST比GET更微妙：若RIO已经把正文预读进自己的缓冲区，直接dup2原socket到stdin会让child读不到这些预读字节。本页Python实现先从同一解析器取得精确正文，再通过subprocess的stdin管道交给固定CGI程序，收集stdout后核对CGI长度。这样也能在child失败时返回502，而不是先发送200再发现失败。

网页表单默认发送a=15000&b=213，原书adder只接受裸15000&213并用atoi。完整伴读实现接受两种明确格式，表单方式检查键名与重复键、百分号编码、整数范围，保留正负号并拒绝垃圾尾缀；两个操作数都限制在±1000000，和自然落在±2000000内。

11.6 · 沿doit走完静态与动态两条路径Putting It Together: The Tiny Web Server

来源：印刷 992—1000 页 / PDF 993—1001 页

Tiny最值得学习的是函数分工：main持有监听fd并接受连接；doit读请求、判方法、解析URI、检查对象，再分派静态或动态处理；clienterror生成错误响应；read_requesthdrs找首部边界；parse_uri把请求映射到受控资源；serve_static发送文件，serve_dynamic运行CGI。每个连接处理结束后，main关闭connfd并回到accept。

静态例子先打开文件并fstat，普通文件长度n确定后申请n字节（空文件单独处理），循环read到n，再统一形成响应并write_all。原书版本用mmap，关闭源fd后映射仍然有效；最后还要munmap。读入malloc版本增加一次数据复制，但不再依赖映射区域的生命周期，正好对应11.9。两者都要求文件在读取/映射过程中不会被并发截短或替换成不同内容。

逐段读C核心时，先看request_size：它寻找CRLFCRLF，只按十进制解析Content-Length，限制首部8192B、正文4096B，并拒绝重复长度和Transfer-Encoding。request_ready另外判断当前字节是否足以生成最终响应：请求尚未完整时继续等输入，头部已完整且能拒绝Expect时立即响应；request_size仍只表示消息长度是否完整，供代理等调用者使用。再看read_asset：用打开的root目录和openat定位单层文件，ONOFOLLOW拒绝最终符号链接，fstat确保普通文件与64 KiB上限。最后build_response集中计算长度，HEAD只抑制正文，handle负责socket读写而不关闭调用者的fd。

C的build_response动态分支直接计算adder，供第12章不同调度模型复用；第11章另有实际的--serve-cgi入口：dispatch_cgi验证请求后fork，child把已读POST正文接到stdin、把连接接到stdout，再exec同一二进制的--cgi模式；父进程关闭自己的连接引用并继续accept，由SIGCHLD处理器回收。Python的--serve通过subprocess.run同步等待CGI并收集stdout，是另一条便于观察管道转交的参考路径。第11.8题的异步接入由C主循环实现；Python CGI程序也能由该C主循环异步exec，两者在回归中分别运行。

原书Tiny有多处为了紧凑而省略的边界：sscanf的%s无宽度限制；路径直接拼接；反复sprintf把目标缓冲区同时当%s输入造成重叠对象问题；头部EOF可能使循环不结束；空文件的零长度mmap不适用；adder缺少&时可能解引用空指针，atoi也不能报告格式或溢出。这里保留其函数组织来讲机制，运行代码使用有界解析、定长长度与失败返回。

static int handle(int fd, const char *root) {
    char request[CH11_REQUEST_LIMIT]; size_t n = 0;
    int flags = fcntl(fd, F_GETFL), rc = -1;
    if (flags < 0 || fcntl(fd, F_SETFL, flags | O_NONBLOCK)) return -1;
    long long end = now_ms() + 2000;
    while (n < sizeof(request)) {
        if (!io_ready(fd, POLLIN, end)) { errno = ETIMEDOUT; goto done; }
        ssize_t k = read(fd, request + n, sizeof(request) - n);
        if (k < 0 && (errno == EINTR || errno == EAGAIN || errno == EWOULDBLOCK)) continue;
        if (k <= 0) break;
        n += (size_t)k;
        if (request_ready(request, n)) break;
    }
    char *response; size_t len;
    if (build_response(request, n, root, &response, &len)) goto done;
    rc = write_all(fd, response, len); free(response);
done: {
        int saved = errno;
        if (fcntl(fd, F_SETFL, flags)) return -1;
        errno = saved; return rc;
    }
}
static volatile sig_atomic_t reaped, reap_max_batch;
static void child_handler(int sig) {
    (void)sig; int saved = errno; pid_t p; sig_atomic_t batch = 0;
    do { p = waitpid(-1, NULL, WNOHANG); if (p > 0) { ++reaped; ++batch; } }
    while (p > 0 || (p < 0 && errno == EINTR));
    if (batch > reap_max_batch) reap_max_batch = batch;
    errno = saved;
}
static int reaper_test(void) {
    sigset_t block, old, suspend_mask; sigemptyset(&block); sigaddset(&block, SIGCHLD);
    struct sigaction action = {0}; action.sa_handler = child_handler;
    sigemptyset(&action.sa_mask); action.sa_flags = SA_RESTART;
    if (sigaction(SIGCHLD, &action, NULL) || sigprocmask(SIG_BLOCK, &block, &old)) return 1;
    reaped = 0; pid_t child = fork();
    if (child == 0) _exit(0);
    if (child < 0) { sigprocmask(SIG_SETMASK, &old, NULL); return 1; }
    suspend_mask = old; sigdelset(&suspend_mask, SIGCHLD);
    if (sigprocmask(SIG_SETMASK, &suspend_mask, NULL)) return 1;
    long long deadline = now_ms() + 2000;
    while (!reaped && now_ms() < deadline) {
        struct timespec pause = {0, 10000000}; nanosleep(&pause, NULL);
    }
    int failed = !reaped;

    return sigprocmask(SIG_SETMASK, &old, NULL) != 0 || failed;
}

/* Returns 1 when this connection was transferred to a CGI child, 0 when the
 * parent served it, and -1 on an I/O/setup failure. Caller always closes fd.
 * Single-threaded, with exclusive ownership of every child in this server. */
static int dispatch_cgi(int fd, int listener, const char *root, const char *program) {
    char request[CH11_REQUEST_LIMIT + 1]; size_t n = 0;
    long long end = now_ms() + 2000;
    while (n < CH11_REQUEST_LIMIT) {
        if (!io_ready(fd, POLLIN, end)) return -1;
        ssize_t got = read(fd, request + n, CH11_REQUEST_LIMIT - n);
        if (got < 0 && errno == EINTR) continue;
        if (got <= 0) break;
        n += (size_t)got;
        if (request_ready(request, n)) break;
    }
    request[n] = 0;
    char *response = NULL; size_t length = 0;
    if (build_response(request, n, root, &response, &length)) return -1;
    char method[16] = "", target[2048] = "";
    (void)sscanf(request, "%15s %2047s", method, target);
    char *query = strchr(target, '?');
    if (query) *query++ = 0;
    if (length < 15 || memcmp(response, "HTTP/1.0 200 OK\r", 15) || strcmp(target, "/cgi-bin/adder")) {
        int rc = write_all(fd, response, length); free(response); return rc ? -1 : 0;
    }
    free(response);
    char *body = strstr(request, "\r\n\r\n") + 4;
    /* GET/HEAD use QUERY_STRING; their already-consumed HTTP bodies do not
     * become CGI stdin. Only POST transfers its declared body through pipe. */
    size_t body_size = !strcmp(method, "POST") ? n - (size_t)(body - request) : 0;
    int input[2];
    if (pipe(input)) return -1;
    pid_t child = fork();
    if (child < 0) { close(input[0]); close(input[1]); return -1; }
    if (child == 0) {
        close(listener); close(input[1]);
        if (dup2(input[0], STDIN_FILENO) < 0 || dup2(fd, STDOUT_FILENO) < 0) _exit(126);
        if (input[0] != STDIN_FILENO) close(input[0]);
        if (fd != STDOUT_FILENO) close(fd);
        char count[32]; (void)snprintf(count, sizeof(count), "%zu", body_size);
        if (setenv("REQUEST_METHOD", method, 1) || setenv("QUERY_STRING", query ? query : "", 1) ||
            setenv("CONTENT_LENGTH", count, 1) ||
            setenv("CONTENT_TYPE", !strcmp(method, "POST") ? "application/x-www-form-urlencoded" : "", 1) ||
            setenv("CSAPP_FULL_HTTP", "1", 1)) _exit(126);
        struct sigaction default_action = {0}; default_action.sa_handler = SIG_DFL;
        sigemptyset(&default_action.sa_mask);
        if (sigaction(SIGCHLD, &default_action, NULL) || sigaction(SIGALRM, &default_action, NULL)) _exit(126);
        sigset_t mask; sigemptyset(&mask);
        if (sigprocmask(SIG_SETMASK, &mask, NULL)) _exit(126);
        alarm(5);
        execlp(program, program, "--cgi", (char *)NULL);
        const char failure[] = "HTTP/1.0 502 Bad Gateway\r\nContent-Length: 11\r\nConnection: close\r\n\r\nBad Gateway";
        (void)write_all(STDOUT_FILENO, failure, sizeof(failure) - 1); _exit(127);
    }
    close(input[0]);
    int rc = write_all(input[1], body, body_size), saved = errno;
    close(input[1]);
    /* A CGI may reject POST early, close stdin, then send its own response.
     * EPIPE is not permission to kill that response. Other transfer failures
     * cancel this child; the handler owns it in either case, and alarm bounds
     * its remaining lifetime even when it elects not to consume stdin. */
    if (rc && saved != EPIPE) (void)kill(child, SIGKILL);
    return 1;
}

    sigset_t block, old_mask, running;
    struct sigaction action = {0}, old_action;
    sigemptyset(&block); sigaddset(&block, SIGCHLD);
    action.sa_handler = child_handler; sigemptyset(&action.sa_mask); action.sa_flags = SA_RESTART;
    if (sigprocmask(SIG_BLOCK, &block, &old_mask)) return 1;
    if (sigaction(SIGCHLD, &action, &old_action)) {
        (void)sigprocmask(SIG_SETMASK, &old_mask, NULL); return 1;
    }
    running = old_mask; sigdelset(&running, SIGCHLD);
    reaped = 0; reap_max_batch = 0;
    int listener = socket(AF_INET, SOCK_STREAM, 0), accepted = 0, spawned = 0, failed = 0;
    struct sockaddr_in address = {0}; address.sin_family = AF_INET;
    address.sin_addr.s_addr = htonl(INADDR_LOOPBACK);

            close(fd); /* Child owns the remaining connected socket reference. */
            if (rc > 0) ++spawned;
            else if (rc < 0) failed = 1;
        }
    }
    if (listener >= 0) close(listener);

    return failed || accepted != limit;
}

def sum_body(args):

def read_request(conn, log=None, state=None):
    deadline = time.monotonic() + 2
    data = bytearray()
    while b'\r\n\r\n' not in data:
        conn.settimeout(max(0.001, deadline-time.monotonic()))
        if time.monotonic() >= deadline:
            raise RequestError(408)
        part = conn.recv(1024)
        if not part:
            raise RequestError(400)
        data.extend(part)
        if state is not None and data.startswith(b'HEAD '):
            state[0] = 'HEAD'
        if len(data) > HEADER_LIMIT + BODY_LIMIT:
            raise RequestError(413)
    head, body = bytes(data).split(b'\r\n\r\n', 1)
    if len(head) + 4 > HEADER_LIMIT or b'\0' in head:
        raise RequestError(400)
    lines = head.decode('ascii').split('\r\n')
    if log is not None:
        log.write('\n'.join(lines) + '\n\n')
        log.flush()
    fields = lines[0].split(' ')
    if len(fields) != 3 or not all(fields):
        raise RequestError(400)
    method, target, version = fields
    if state is not None:
        state[0] = method
    if version not in ('HTTP/1.0', 'HTTP/1.1'):
        raise RequestError(505)
    headers = {}
    for line in lines[1:]:
        name, sep, value = line.partition(':')
        if not sep or not re.fullmatch(r'[A-Za-z0-9-]+', name):
            raise RequestError(400)
        if any((ord(c) < 32 and c != '\t') or ord(c) == 127 for c in value):
            raise RequestError(400)
        name, value = name.lower(), value.strip(' \t')
        if name in headers:
            raise RequestError(400)
        headers[name] = value
    if version == 'HTTP/1.1' and not headers.get('host'):
        raise RequestError(400)
    if 'transfer-encoding' in headers:
        raise RequestError(501)
    length = headers.get('content-length', '0')
    if not re.fullmatch('[0-9]{1,10}', length) or int(length) > BODY_LIMIT:
        raise RequestError(413)
    n = int(length)
    if method == 'POST' and 'content-length' not in headers:
        raise RequestError(411)
    if 'expect' in headers:
        raise RequestError(417)
    while len(body) < n:
        remaining = deadline - time.monotonic()
        if remaining <= 0:
            raise RequestError(408)
        conn.settimeout(remaining)
        part = conn.recv(n-len(body))
        if not part:
            raise RequestError(400)
        body += part
    if len(body) != n:
        raise RequestError(400)
    return method, target, headers, body


def asset(root, name):

        sum_body(args)  # Validate before starting the fixed, trusted executable.
        environment = {'REQUEST_METHOD': 'GET' if method == 'HEAD' else method,
                       'QUERY_STRING': parts.query, 'CONTENT_LENGTH': str(len(body)),
                       'CONTENT_TYPE': headers.get('content-type', '')}
        result = subprocess.run([sys.executable, str(Path(__file__).resolve()), '--cgi'],
                                input=body, stdout=subprocess.PIPE, stderr=subprocess.PIPE,
                                env=environment, timeout=2, check=False)
        if result.returncode or len(result.stdout) > BODY_LIMIT:
            raise RequestError(502)
        cgi_headers, payload = result.stdout.split(b'\r\n\r\n', 1)
        if cgi_headers != (b'Content-Type: text/html; charset=utf-8\r\n'
                           + f'Content-Length: {len(payload)}'.encode()):
            raise RequestError(502)
        return 'text/html; charset=utf-8', payload
    if method == 'POST':
        raise RequestError(405)
    return asset(root, 'home.html' if parts.path == '/' else parts.path[1:])


def handle(conn, root, log=None):
    """Caller closes conn. Returns status; peer-close errors affect this client only."""
    status, method = 200, ''
    state = ['']
    try:
        method, target, headers, body = read_request(conn, log, state)
        kind, payload = route(method, target, headers, body, root)
    except RequestError as error:
        status = error.status
    except (UnicodeError, ValueError):
        status = 400
    except (TimeoutError, socket.timeout):
        status = 408
    except (OSError, subprocess.SubprocessError):
        status = 500
    method = state[0]
    reasons = {200: 'OK', 400: 'Bad Request', 403: 'Forbidden', 404: 'Not Found',
               405: 'Method Not Allowed', 408: 'Request Timeout', 411: 'Length Required',
               413: 'Content Too Large', 415: 'Unsupported Media Type',
               417: 'Expectation Failed', 500: 'Internal Server Error',
               501: 'Not Implemented', 502: 'Bad Gateway', 505: 'HTTP Version Not Supported'}
    if status != 200:
        payload = reasons[status].encode()
        kind = 'text/plain; charset=utf-8'
    response = (f'HTTP/1.0 {status} {reasons[status]}\r\nContent-Type: {kind}\r\n'
                f'Content-Length: {len(payload)}\r\nConnection: close\r\n\r\n').encode()
    try:
        conn.settimeout(2)
        conn.sendall(response + (b'' if method == 'HEAD' else payload))
    except OSError:
        pass
    return status


def exchange(root, request):
    errors = []
    with socket.socket() as listener:
        listener.bind(('127.0.0.1', 0))
        listener.listen(1)
        listener.settimeout(3)
        def worker():
            try:
                connection, _ = listener.accept()
                with connection:
                    handle(connection, root)
            except BaseException as error:
                errors.append(error)
        thread = threading.Thread(target=worker)
        thread.start()
        try:
            with socket.create_connection(listener.getsockname(), timeout=3) as client:
                for offset in range(0, len(request), 7):
                    client.sendall(request[offset:offset+7])
                client.shutdown(socket.SHUT_WR)
                output = b''
                while part := client.recv(4096):
                    output += part
        finally:
            thread.join(5)
        if thread.is_alive() or errors:
            raise RuntimeError('server did not finish cleanly')
    return output

11.5 · CGI的stdout如何到达客户端

原题（中文翻译）

来源：印刷 990 页 / PDF 991 页

假设CGI程序需要把动态内容发送给客户端。通常CGI把内容写到标准输出；解释这些内容是如何发送到客户端的。

解答与推导

server先fork。child继承connfd，再执行dup2(connfd, STDOUT_FILENO)，让fd1引用同一连接；随后execve装入CGI程序。CGI看到的stdout仍对应fd1，因此printf/fflush最终沿socket送给client。dup2改变的是描述符引用，exec改变的是程序映像，保留下来的描述符把两者接起来。

/* In the child; check all return values in a complete program. */
if (dup2(connfd, STDOUT_FILENO) < 0) _exit(127);
if (connfd != STDOUT_FILENO) close(connfd);
execve(cgi_path, cgi_argv, cgi_env);
_exit(127);

parent应关闭自己不再使用的连接引用并回收child。若stdout是缓冲stdio，CGI须在正常结束或显式fflush时提交缓冲；调用_exit不刷新stdio。本页Python CGI通过pipe把stdout先交给parent验证再转发，这是另一种合法路径，不能把“parent不介入”同时套在两种实现上。

可以沿一次输出追踪：CGI 执行 printf，先写自己的 stdout 用户缓冲；刷新时，库对 fd 1 发出 write；fd 1 的内核引用已被 dup2 接到连接对象，因此字节进入客户端方向。exec 换掉了旧程序的用户内存，但保留的描述符关系仍把新程序输出接在原连接上。这就是 CGI 无需知道 connfd 原编号也能返回结果的原因。

原题（中文翻译）

可能出现的请求首部解释
Host目标主机名及可选端口；HTTP/1.1必须有
User-Agent客户端软件标识；可被客户端自行设置
Accept客户端可接受的媒体类型及偏好
Accept-Language语言偏好，不是内容已经采用的语言
Accept-Encoding可接受的内容编码，如gzip；本实验发送未压缩正文
Connection本次连接的逐跳选项，如keep-alive或close
Cache-Control / Pragma缓存控制指令；no−cache不等价于完全禁止存储
Referer发起请求的来源URI，拼写沿历史字段名
Content-Type / Content-LengthPOST正文媒体类型及字节数

下面补齐现代浏览器可能随表单/导航发送的字段。它们来自较新的独立规范；原题RFC2616没有定义这些名字。

首部具体含义与示例
Sec−Fetch-Site发起者与目标的站点关系；同源表单常为same-origin，直接地址栏导航可为none
Sec−Fetch-Mode请求模式；整页导航为navigate
Sec−Fetch-Dest响应将用作什么；页面为document，视频为video
Sec−Fetch-User导航是否带用户激活；?1表示是，并非每种请求都发送
Sec−CH−UA浏览器品牌与主要版本列表；可含防止固定解析假设的额外品牌项
Sec−CH−UA−Mobile是否偏好移动设备体验；?0表示否，?1表示是
Sec−CH−UA−Platform客户端平台提示，如macOS；不是处理器指令集字段
Upgrade-Insecure-Requests值1表示客户端支持并偏好将适用的不安全请求升级；单独出现不证明这条连接已使用HTTPS
Origin发起请求的源（scheme、host、port）；与可能含路径的Referer不同

字段依据分别为W3C Fetch Metadata、User-Agent Client Hints、Upgrade Insecure Requests和RFC6454的Origin。这些字段描述请求上下文和客户端声明，不替代服务端鉴权。本次题解于2026-10-14核对规范，并把教材历史字段与后续扩展分开。

11.8 · 在SIGCHLD处理器中回收CGI

原题（中文翻译）

来源：印刷 1002 页 / PDF 1003 页

修改Tiny，在SIGCHLD处理器内回收CGI子进程，不再显式等待它们结束。

解答与推导

在server启动前安装sigaction；处理器保存errno，用waitpid(-1,NULL,WNOHANG)循环回收所有已结束child，最后恢复errno。不能仅调用一次wait：标准信号可能合并，一次通知可能对应多个退出。处理器不printf、不malloc、不调用非异步信号安全的日志函数。

C / POSIX：回收 CGI 子进程
static void reap_cgi(int sig) {
    (void)sig;
    int saved = errno;
    pid_t p;
    do {
        p = waitpid(-1, NULL, WNOHANG);
    } while (p > 0 || (p < 0 && errno == EINTR));
    errno = saved;
}
/* Install before accepting clients and before creating children. */
struct sigaction action = {0};
action.sa_handler = reap_cgi;
sigemptyset(&action.sa_mask);
action.sa_flags = SA_RESTART;
if (sigaction(SIGCHLD, &action, NULL) < 0) { /* report startup failure */ }

serve_dynamic的parent删除Wait，返回main并关闭自己的connfd；child保留继承的引用继续写，完毕退出时触发回收。child还应关闭无用listenfd，避免它额外延长监听对象的生命周期。若server以后又创建需要同步waitpid的其他子进程，不能让全局处理器与它们争抢回收权；应设计统一子进程表或把处理器收窄到它拥有的PID。

完整实现见serve_cgi → dispatch_cgi → cgi_main。父进程在fork及spawned记账时屏蔽SIGCHLD，然后恢复允许递送的掩码再接收下一个请求，避免child先退出、计数尚未登记的竞争。动态请求验证后，已读取的POST正文经pipe交给child；GET/HEAD使用QUERY_STRING，HTTP层消费完它们可能携带的正文后，不再转交给CGI stdin。child关闭listenfd和管道写端，dup2后关闭原始fd，用固定CGI环境exec；父进程关闭管道和自己的connfd。程序只接受操作者指定的可信可执行文件，URL不能选择本地程序。退出服务时，父进程先关闭listener，再用sigsuspend等待尚未回收的子进程数量归零（reaped达到spawned）；正常回收的waitpid调用只发生在处理器内，最后恢复原SIGCHLD处理器与掩码。

mkdir -p tmp/csapp/cgi-root
printf '<p>static page</p>\n' > tmp/csapp/cgi-root/home.html
clang -std=c11 -Wall -Wextra -Werror -pedantic \
  books/csapp/code/ch11_http.c -o tmp/csapp/cgi-server
tmp/csapp/cgi-server --serve-cgi tmp/csapp/cgi-root 3

服务打印随机回环端口，接收3个连接；向该端口依次发送GET /cgi−bin/adder?a=2&b=3、HEAD及POST即可。CGI自身生成完整HTTP首部，HEAD仍报告17字节表示长度而不写正文。父进程默认exec同一二进制，也可在最后提供可信CGI程序路径；该程序应接受--cgi、读取标准CGI环境，并按本实验约定输出完整HTTP响应。Python cgi_main遇到CSAPP_FULL_HTTP=1时使用这一约定，原同步管道入口仍只产生CGI首部。

一次并发实验让三个 CGI 同时等待，期间静态请求先完成；随后暂停父进程并释放这三个child，客户端仍收到完整正文及EOF，说明父进程已关闭连接引用。恢复父进程后，一次处理器调用回收至少三个退出，验证通知合并时必须循环waitpid。还检查child只保留stdout连接、服务结束无剩余子进程且描述符数及SIGCHLD状态恢复；GET、POST、HEAD、客户端提前断开和exec失败都有实际请求。exec失败生成完整502。CGI可以提前关闭POST stdin并生成自己的错误响应；父进程遇到EPIPE时只结束管道转交，保留child完成响应的机会，不能把EPIPE当作杀掉child的理由。其他管道传输错误会取消该child。超时CGI由五秒alarm终止并被回收，此时连接关闭，可能只有部分或没有响应，不把它当作200成功。另一组实验安排 child 先关闭stdin再继续父进程，覆盖GET/HEAD的有效请求正文及POST由CGI自行返回400的路径。原书静态文件读取和请求解析仍可能阻塞，所以这里实现的是CGI重叠执行。

11.9 · 用malloc和稳健读写发送静态文件

原题（中文翻译）

来源：印刷 1002 页 / PDF 1003 页

修改Tiny，在服务静态内容时，用malloc、rio_readn和rio_writen把请求文件复制到连接描述符，不再使用mmap与rio_writen。

解答与推导

先open/fstat得到长度n；申请n字节，rio_readn必须返回恰好n，否则视为文件变化或I/O失败；完成后再发响应头与n字节正文；每条失败路径close/free。零长度文件不必依赖malloc(0)的特殊返回值。下面是以原书csapp.h为上下文的替换核心，完整独立版本见read_asset + write_all。

/* srcfd was opened and fstat validated a stable regular file of n bytes. */
char *data = malloc(n ? n : 1);
if (data == NULL) { close(srcfd); return; }
ssize_t got = rio_readn(srcfd, data, n);
close(srcfd);
if (got < 0 || (size_t)got != n) { free(data); return; }
/* Send the 200 header only after preparation has succeeded. */
if (send_headers(connfd, n, filetype) == 0)
    (void)rio_writen(connfd, data, n); /* caller handles a failed connection */
free(data);

片段中的send_headers代表原书已展示的响应头构造，不是新的POSIX接口。维护源不依赖csapp.h：循环read等价实现rio_readn的短读/EINTR处理，write_all处理短写。为避免单个请求申请任意大内存，实验限64 KiB；更大文件可改成固定缓冲流式发送，但若发头后源读取失败，就只能结束连接，不能再伪造第二个HTTP错误响应。

11.11 · HEAD保留GET的响应头，省略正文

原题（中文翻译）

来源：印刷 1002 页 / PDF 1003 页

扩展Tiny，使它支持HTTP HEAD方法。用telnet作为Web客户端检查。

解答与推导

先按GET相同规则定位资源并计算状态、类型和表示长度，发出相同必要首部；若method=HEAD，发送阶段跳过正文。不能把Content-Length改成0，因为它应描述相应GET本来会有的表示长度。错误响应也必须抑制正文。对于动态内容，若要知道长度，可先运行CGI并收集结果，再只发送头；不能让未修改的CGI直接把正文写到socket。

telnet 127.0.0.1 本次端口
HEAD /hello.txt HTTP/1.1
Host: 127.0.0.1

hello.txt若为12字节hello\0world\n，应看到Content-Length: 12及空行，随后连接结束而无正文。C build_response以payload=0保留n=12，Python handle亦如此；默认loopback自测检查实际body为空。telnet只用作本机明文协议工具，此处不涉及远程登录凭据。

11.12 · POST正文通过stdin传给CGI

原题（中文翻译）

来源：印刷 1002 页 / PDF 1003 页

扩展Tiny，使它可以服务由HTTP POST方法请求的动态内容。使用你常用的Web浏览器检查。

解答与推导

FORM中的第二个表单使用method=post。client发送Content-Type: application/x−www−form-urlencoded与Content-Length，再在空行后发送a=2&b=3。server先检查长度、类型和范围，从同一个缓冲解析器取得精确7字节，然后设置REQUEST_METHOD=POST、CONTENT_LENGTH=7与CONTENT_TYPE，将正文送到CGI标准输入。

完整实现见read_request → route → cgi_main：subprocess.run(input=body)把已经读取的正文写入child stdin管道，child准确读n字节；stdout包含CGI首部与动态结果，再由parent封装HTTP响应。小正文上限与两秒超时使读取、子进程执行都有明确边界。

直接dup2(connfd,0)只在server没有预读正文时才足够；原书RIO预读可能已从内核拿走一段正文，child换了流之后看不见它。这里的管道转交解决这一具体问题。未给长度返回411，超过上限返回413，不支持的正文类型返回415，截断/重复长度拒绝；chunked不在本实验范围。默认回归验证POST结果5；本次真实浏览器填写12和30后提交POST，页面显示12+30=42，服务记录正文Content-Length为9，对应a=12&b=30。

正文 a=2&b=3 按字节编号为 a,=,2,&,b,=,3，共 7 个 ASCII 字节。若旧缓冲已有前 3 个、内核还剩后 4 个，服务器要先从旧缓冲取 3，再从 socket 补 4，组成完整的 7 字节后交给管道。直接更换描述符只改变“从哪里读取”，不会自动把旧用户缓冲中的前三字节搬到新 CGI 的 stdin。

11.13 · SIGPIPE与EPIPE只能结束当前连接

原题（中文翻译）

来源：印刷 1002 页 / PDF 1003 页

修改Tiny，使它在向提前关闭的连接write时，能够妥善处理SIGPIPE信号和EPIPE错误，而不会终止服务器。

解答与推导

进程启动时用sigaction把SIGPIPE设为SIG_IGN；每次写入继续检查返回值，EINTR重试，EPIPE或ECONNRESET停止该连接并释放资源，主循环继续accept。若仍调用原书遇错exit的大写Rio_writen，忽略SIGPIPE后也会因包装器退出进程，所以必须沿整个调用链改成返回错误。

struct sigaction ignore = {0};
ignore.sa_handler = SIG_IGN;
sigemptyset(&ignore.sa_mask);
if (sigaction(SIGPIPE, &ignore, NULL) < 0) { /* startup failure */ }
/* In the write loop: */
ssize_t k = write(fd, data, n);
if (k < 0 && errno == EINTR) { /* retry */ }
else if (k < 0) { /* end this connection; do not exit the server */ }

原书“第一次write正常、第二次产生SIGPIPE”的描述是典型情景，不是所有平台和时序的保证：FIN/RST到达、内核缓冲和应用调度会改变第几次调用看到EPIPE或ECONNRESET。正确实现检查每次调用，不预设计数。C默认socketpair回归关闭对端后真实得到EPIPE并继续完成child回收测试，证明本进程存活；TCP断开路径在服务回归另测。

原创自测：先预测，再展开

原创自测 1 · 两次write就会有两次read吗？

client先write("AB",2)，再write("CDE",3)。server一次read缓冲大小为4。它一定先收到AB再收到CDE吗？

不一定。TCP只保证字节序ABCDE；合法分块包括ABCD/E、AB/CDE、A/BCDE等。server需累计返回字节数，并用应用的长度或分隔规则判定消息完整。

原创自测 2 · POST首部后的字节去了哪里？

RIO读首部时预读了正文前三字节a=2。server随后dup2(socket,0)并exec CGI，CGI期望7字节正文，会怎样？

新CGI只能从socket读取仍在内核中的&b=3四字节，预读的a=2留在旧进程用户缓冲。它可能等待或得到截断正文。应从同一个RIO实例读足正文再用pipe交给child，或逐字节无预读读取首部。

原创自测 3 · HEAD的长度20，但正文0是矛盾吗？

HEAD响应Content-Length:20，空行后服务器关闭连接，没有发送20字节正文。是否截断？

对HEAD不是截断：该字段描述相应GET的表示长度，HEAD按语义不带正文。若相同响应是普通GET且没有其他特殊状态，少于宣告长度则是截断。

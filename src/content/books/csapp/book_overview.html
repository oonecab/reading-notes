这本书始终围绕一个对象：正在被编写、翻译、执行并与外部交互的程序。数字表示决定“值是什么”，指令与硬件决定“如何完成一步”，操作系统决定“在什么环境中运行”，I/O和并发决定“怎样与其他活动协作”。从这条线进入，厚书便有了可以不断回看的骨架。

Part I · Program Structure and Execution · 印刷 65 页 / PDF 66 页

Our exploration of computer systems starts by studying the computer itself, comprising a processor and a memory subsystem. At the core, we require ways to represent basic data types, such as approximations to integer and real arithmetic. From there, we can consider how machine-level instructions manipulate data and how a compiler translates C programs into these instructions. Next, we study several methods of implementing a processor to gain a better understanding of how hardware resources are used to execute instructions. Once we understand compilers and machine-level code, we can examine how to maximize program performance by writing C programs that, when compiled, achieve the maximum possible performance. We conclude with the design of the memory subsystem, one of the most complex components of a modern computer system.

译文。我们从计算机本身开始研究计算机系统，其中包括处理器和存储器子系统。最基本的问题，是如何表示基本数据类型，例如整数和实数算术的近似表示。在此基础上，再考虑机器级指令怎样操纵数据，以及编译器怎样把 C 程序翻译成这些指令。接着研究实现处理器的几种方法，以理解硬件资源怎样用于执行指令。理解编译器和机器级代码之后，就可以考察如何编写经编译后尽可能高效的 C 程序。最后讨论存储器子系统的设计，它是现代计算机系统中最复杂的组成部分之一。

这段开篇直接给出第 2—6 章的因果链：表示确定运算语义，指令表达状态变化，处理器安排执行，优化改变工作组织，存储层次决定数据供应。第 5 章的“快”因此同时受第 2 章的正确性约束、第 3—4 章的执行机制约束和第 6 章的数据访问约束。上面的章节表用于找位置，后一节的数组例子用于沿这条链来回阅读。

第一部分解释指令怎样执行、数据怎样流过存储层次。第二部分把镜头拉到一次完整的运行：独立编译的文件先组成程序，内核再为它建立进程和地址空间，运行过程中随时可能出现系统调用、信号和缺页。三个章节分别回答“名字和地址怎样接起来”“控制权何时交给谁”“地址对应的内存从哪里来”。

Our exploration of computer systems continues with a closer look at the systems software that builds and runs application programs.

译文。我们继续探索计算机系统，进一步观察负责构建和运行应用程序的系统软件。

本部分开篇随后把链接器、操作系统和硬件放到一起：链接器组合程序的不同部分，操作系统与硬件协作，让并存的程序各自获得处理器和主存的使用视图。学习的落脚点是自己能写出 shell 和动态内存分配器。

这里有三种容易混淆的地址：目标文件内的相对位置、链接后程序中的虚拟地址、页表翻译得到的物理地址。链接器处理前两者的关系，运行时装载和重定位还会参与；CPU 的 MMU 和操作系统共同管理后两者。把每次地址变化的执行者写出来，重定位、装载和缺页就能接成同一条路径。

读第8章时，先画父子两条控制流及必须满足的先后关系，再列可能输出；读信号时，分别标出生成、pending、解除阻塞和执行处理函数。读第9章时，先固定页大小、位宽和访问权限，再算位段及状态。每章的题解与程序都沿这些可核查的中间状态展开。

第二部分给程序准备了运行环境；第三部分让它开始与外界交互。考虑一个接收浏览器请求的服务器：它从连接中读入字节，按 HTTP 规则识别请求，读取文件或运行计算，再把响应送回去。另一个客户到来时，服务器还要决定谁继续执行、谁等待，以及共享状态怎样保持正确。第10章解决字节怎样可靠地进出，第11章把这些字节组织成跨程序的协议，第12章安排同时存在的多条活动。

Part III · 印刷 923 页 / PDF 924 页

However, in the real world, application programs use services provided by the operating system to communicate with I/O devices and with other programs.

译文。然而在现实世界中，应用程序使用操作系统提供的服务，与 I/O 设备以及其他程序通信。

原书接着把 Unix I/O、Web 客户端与服务器、并发服务和多核加速连在一起。它们共同要求我们弄清一次操作的单位、状态归谁所有，以及什么事件使等待者继续运行。

多个工作者修改同一计数会怎样？两个工作者都先读到 0、各自写回 1，会丢失一次更新；将读改写作为受保护的整体后，结束值才为 2。12.5 同步

先分清三种边界再动手：文件描述符是进程中的句柄，连接提供字节传输，应用协议规定消息；它们的边界并不重合。一次 write 对应的数据可能经多次 read 才收齐，两个请求也可能一起进入接收缓冲。可靠读写负责保存已完成的字节数，协议解析负责判断当前消息是否结束，并发设计则负责保存每条活动尚未完成的状态。

并发和并行也有不同目标。并发服务器可以在一个客户等待网络时处理另一个客户；这有助于响应性，即使只有一个核心也有意义。把矩阵乘法分给多个核心才是在争取计算加速，还要计入线程启动、同步、访存和不能并行的部分。第12章把正确性与性能分开分析，再回到第5、6章的优化和局部性。

阅读注解
主线

跟踪每一步还欠什么

I/O 记剩余字节，协议记未完成消息，并发记等待条件和资源所有者。同一个请求的状态能贯穿三章。

推演

先构造一次不利的交错

让输入分两次到达，让另一个工作者插在读和写之间，或让一个客户提前关闭连接，再检查程序怎样结束和释放资源。

按章推进时，要分清各章所用的模型。第4章的五级教学流水线给出“重叠执行仍须保存语义”的具体机制，第5章再用更高层的现代处理器模型分析依赖与吞吐；两者相关，但不能把Y86的固定停顿数字直接当成实际CPU计时。第6章又加入数据到达时间，解释为什么寄存器内的快速计算会被存储拖慢。

跨部分的回路也很重要：第7章的链接要联系第3章指令地址；第9章同时使用第6章缓存思想和第8章异常机制；第11章的网络字节序回到第2章的数据表示，第12章的线程共享又回到对象布局与存储可见性。

与Weiss一起读时，可以先用算法分析确定工作量随规模怎样增长，再用CS:APP检查每份工作怎样落到机器上。两个算法同为线性时间，也可能因依赖链、常数成本和局部性而相差很多；反过来，微观优化也不能挽救错误的渐近复杂度。

阅读注解
理解

复杂度与机器成本互补

算法决定做多少工作，执行模型解释这些工作怎样重叠、等待和搬运。两层都需要明确输入规模与假设。

边界

教学模型不能直接相乘成实机性能

缓存、流水和系统活动互相影响。先用模型提出解释，再在明确机器与输入上核对。

怎样安排第一轮阅读和回读How to Read the Book · Course Paths

原书：印刷 20 页 / PDF 21 页

第一轮按序言、第1章、第2—6章推进，再沿第二部分进入第7—9章，最后沿第三部分完成第10—12章。每章先抓住一个主问题，再读相关小节、图和程序。第2章遇到定理式推导时先算一个小位宽例子，随后补一般式；第3章先追踪一条路径，再整理指令类别；第4章先完整执行一条指令，再让几条指令重叠；第5、6章把同一计算在不同组织下的成本算出来。

第二轮选一个跨章例子回读，例如矩阵转置或数组内积。保留同一输入与数值模型，分别检查算术、地址、依赖和访问顺序。这样能够发现“一个章节看似成立的建议”附带什么前提：浮点重结合需要数值许可，循环交换需要独立性，缓存分块需要工作集与映射条件。

原书的课程组合允许不同重心。若优先系统编程，可以在掌握位表示、机器级程序和基本存储后进入第7—12章，同时把第4章作为理解处理器机制的深入路线。这里仍保留第一部分的完整顺序，便于读优化时回查硬件依据。

读代码时，可以把每个名字先翻成一个具体对象。例如第 5 章的指针别名例子从一个初值为 2 的变量出发：先认出谁保存地址、谁保存数，再跟踪每一句读了什么、写了什么，最后判断改写能否保留结果。同样的方法也适用于第 3 章的栈、第 6 章的缓存行和第 12 章的共享计数器。遇到公式，则先把每一项翻成一段时间、一组字节或一个事件，再进行代入。

阅读注解
方法

每轮都留下一个可检查的结果

位图、地址表、状态轨迹或输出都可以。留下具体结果，回读时才知道是哪一个假设发生变化。

理解

展开题解之前先固定条件

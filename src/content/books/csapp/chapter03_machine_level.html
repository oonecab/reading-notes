第2章回答“位模式表示什么”，本章把问题推进一步：程序的这些位模式怎样在处理器中被读取、计算和保存？目标不是记住一份指令字典，而是拿到一段汇编后，能写下某条指令执行前后的寄存器、内存和下一条指令地址。只要这三类状态连起来，C中的表达式、分支、函数与数据结构就可以沿同一条线理解。

x86从16位8086，经32位IA32扩展到x86-64，因此同一寄存器留下ax、eax、rax几代名字。“word”仍是16位，“double word”是32位，“quad word”才是64位；它们不是随处理器位数一起变化的口语“一个机器字”。x86-64增加了寄存器并扩大地址和数据能力，同时保留大量早期编码。历史解释为什么接口不整齐，实际解题仍必须依据当前指令的精确定义。

3.2.1 · 机器级代码暴露哪些状态Machine-Level Code

经典表述 · ISA 与虚拟内存两种抽象

First, the format and behavior of a machine-level program is defined by the instruction set architecture, or ISA, defining the processor state, the format of the instructions, and the effect each of these instructions will have on the state.

Second, the memory addresses used by a machine-level program are virtual addresses, providing a memory model that appears to be a very large byte array.

机器级程序建立在两种抽象上：ISA 规定可见状态、指令格式和状态变化；虚拟内存提供按字节寻址的巨大数组。前者让读者能逐条推演指令，后者让同一个地址表达式具有稳定的程序含义。

伴读：处理器内部可以并行执行指令，内存也由多级硬件和操作系统实现；沿本章状态表阅读时，先以这两项程序可见约定为依据。 接着看本节例子。

源变量名不会直接出现在普通机器指令中。处理器看见的是程序计数器%rip、整数寄存器、条件码、向量寄存器与按字节寻址的内存。C中的“long *p”到了机器级通常只是一组地址位；是否按8字节读取、是否将结果作有符号比较，要由随后使用它的指令决定。优化后同一寄存器可以先装地址、再装整数，同一变量也可能在不同位置之间迁移。

ISA常以顺序状态变换来规定行为：每条指令把旧状态变成新状态。第4章会看到硬件可以并行处理多条指令，但它必须维持程序可观察的正确依赖。虚拟地址在本章可先看作字节数组索引；某个地址是否有效、怎样映射到物理存储，由操作系统与第9章的虚拟内存机制进一步决定。64位寄存器能容纳64位地址，不表示每一种64位模式都可访问。

3.2.2 · 编译、汇编、链接分别补全什么Code Examples

long mult2(long, long);
void multstore(long x,long y,long *dest) {
    long t=mult2(x,y);
    *dest=t;
}
multstore:
    pushq %rbx
    movq %rdx,%rbx
    call mult2
    movq %rax,(%rbx)
    popq %rbx
    ret

前两个参数x、y已经在rdi、rsi；第三参数dest原在rdx，但mult2可破坏rdx，所以multstore先保存旧rbx，再把dest放入被调用者保存的rbx。call返回后，rax含乘积，movq把它写到dest，最后恢复rbx。这六条指令同时解释了“局部变量消失”和“为了调用多出栈操作”：t直接就是rax的值，而rbx的保存用于遵守跨函数约定。

3.2.3 · 怎样整理汇编而不改变含义Notes on Formatting

阅读时可以把.file、.cfi等工具信息与实际执行指令分开，保留标签、数据常量和影响段/对齐的伪指令。AT&T写法通常“源在前、目的在后”，寄存器前有%、立即数前有$；Intel写法通常目的在前。把一种语法里的注释粘到另一种语法会直接把减法和比较读反。

本章的注释先写数据流，诸如“rax←旧rax−rsi”，再把它命名成源变量。不要先认定rax永远叫result。编译器版本不同可以生成不同但等价的程序；编译探针提供小函数用于重新观察，生成的Linux x86-64汇编是静态目标证据，宿主程序另行执行。

3.3 · 宽度是每一次读写的组成部分Data Formats

来源：印刷213页起 / PDF 214页起

先确定数据宽度，才能追踪值。书中LP64模型规定char、short、int、long的尺寸为1、2、4、8字节，对象指针为8字节，float和double为4、8字节。普通整数指令后缀b/w/l/q对应8/16/32/64位；指令后缀l的“long”是历史上的double word，不能误认为C的64位long。

C对象（本章LP64）字节数整数操作后缀/寄存器例

int / unsigned4l/%eax
long / unsigned long / 对象指针8q/%rax

double8标量浮点sd / %xmm0低64位

rax、eax、ax、al是同一寄存器的不同视图。写al只改低8位，写ax只改低16位，而写eax除了改低32位还把高32位清零。这个特殊规则提供免费的32到64位零扩展。内存没有这种附带效果：movl %eax,(%rdi)只写4字节，不会把紧接着的4字节清零。

普通char究竟有无符号、long是否8字节不是C语言跨平台保证。本章给定模型下讨论布局，实验开头检查宿主尺寸；遇到不符合LP64的环境应重新设定模型，不能让一份碰巧通过的地址表代表所有平台。

易混点

地址宽度与数据宽度分开

movb (%rax),%dl使用64位地址但只读1字节；地址计算中的scale也不能替代指令的数据尺寸。

推导

32位写为什么能做零扩展

movl生成的高32位按ISA清零，所以无符号32位转64位通常不需要独立movzlq指令。

3.4.1 · 三种操作数与有效地址Operand Specifiers

经典表述 · 操作数决定取值的路径

Operands can denote immediate (constant) values, register values, or values from memory.

操作数可以直接给出常数、指定寄存器内容，或通过地址从内存取值。一般内存形式 Imm(rb,ri,s) 的有效地址为：

EA=Imm+R[rb]+sR[ri],s∈{1,2,4,8}.

在本节的 x86-64 寻址模型中，基址和索引使用 64 位寄存器；指令的数据宽度再决定从这个地址读取或写入多少字节。

伴读：立即数 8、地址 8、地址中保存的值是三个不同对象；下方先算有效地址再读取四字节的过程把它们逐个分开。 接着看本节例子。

第三版 Global Edition，§3.4.1；原书未编号表述；印刷 217 页 / PDF 218 页。

立即数给出数本身，寄存器给出当前位置的位模式，内存操作数则先计算地址再读取那里的字节。若rdi=0x1000、rsi=3，$8就是8，%rdi是0x1000，8(%rdi,%rsi,4)的有效地址是0x1014，movl会读取那里连续4字节。

EA=D+R[rb]+S·R[ri]

S只能是1、2、4、8，可省略位移、基址或索引。没有寄存器括号也可能是绝对内存地址，如0x104；只有加$才变立即数。若内存0x1014..0x1017的字节依次为78、56、34、12，小端movl得到0x12345678，再由eax写规则清空rax高部。

把地址和值分两步读

设 %rdi=0x1000、%rcx=3，内存地址 0x1014 开始的 4 字节存着整数 42。操作数 8(%rdi,%rcx,4) 先算 0x1000+3×4+8=0x1014；movl 8(%rdi,%rcx,4),%eax 才去该地址读取 4 字节，使 %eax=42。若换成 leaq 8(%rdi,%rcx,4),%rax，结果是地址数值 0x1014，不会读取 42。括号里的寄存器提供地址计算所需的数；指令决定是否访存、访存多宽。

经典表述 · 四字节寄存器结果会清零高半部

This technique takes advantage of the property that an instruction generating a 4-byte value with a register as the destination will fill the upper 4 bytes with zeros.

3.4.4 · 栈顶是一个地址，压栈改变它Pushing and Popping Stack Data

普通pushq先令rsp减8，再把源值写到新rsp；普通popq先读旧rsp的8字节，再使rsp加8。以rsp=0x108、rax=0x123开始，pushq %rax后rsp=0x100且M8[0x100]=0x123；popq %rdx后rdx=0x123、rsp又为0x108。内存0x100的字节没有自动清除，只是脱离活动栈顶。

从栈中间读取仍用普通地址式：movq 8(%rsp),%rdx读第二个8字节槽。将push写成sub加mov只是在一般操作数条件下解释效果；若源或目的涉及rsp自身，必须按指令规定的求值顺序处理，不能机械替换。

3.5.1 · lea算地址式，但不访问内存Load Effective Address

经典表述 · 有效地址计算也能表达算术

Its first operand appears to be a memory reference, but instead of reading from the designated location, the instruction copies the effective address to the destination.

lea 使用内存操作数的地址计算形式，把算出的地址值写入目的寄存器。它不读取该地址上的对象，所以也能表达基址、比例项和常数项组成的算术。

伴读：将 7(%rdi,%rdi,2) 按地址式展开就是 7+x+2x=3x+7。能计算这个数，不要求它此时是可访问的对象地址。 接着看本节例子。

第三版 Global Edition，§3.5.1；原书未编号表述；印刷 228 页 / PDF 229 页。

leaq 7(%rdi,%rdi,2),%rax
ret

若rdi=x，rax得到7+x+2x=3x+7；即使这个数不是合法地址也可以计算，因为lea不读取其所“指向”的内容。它也不改条件码。常量乘法可拆成合法比例，例如12z先用lea得到3z，再左移2位；任意两个变量相乘仍要imul，不能把变量塞进scale位置。

3.5.2 · 一元、二元运算与读改写Unary and Binary Operations

addq %rsi,%rax读取旧rax和rsi，写回它们之和；subq %rsi,%rax写旧rax−rsi。inc/dec加减1，neg取补码相反位模式，not逐位翻转。内存目的如addq $1,(%rdi)是一次读、计算、写回的指令语义；它不自动成为线程间的原子同步操作。多数算术会更新条件码，但not与lea不更新，inc/dec保持CF。

3.7.4 · 为什么有些局部变量必须落到内存Local Storage on the Stack

3.7.5 · 谁负责保存寄存器Local Storage in Registers

rbx、rbp、r12—r15是本章通常使用的callee-saved寄存器。callee若修改它们，必须先保留旧值，并在返回前恢复。其他常用整数临时/参数寄存器属于caller-saved，调用者若需要其旧值活过call，应自己另存。caller把x放入rbx不是“因为rbx不会变”，而是因为每个callee都承担了恢复责任；caller自身也同样要恢复上层的B。

在调用链上，保存责任可以逐层复合。若x只在call之前使用，无需保存；如果需要同时保留多个临时量且六个callee-saved不够，剩余值可以放栈。3.34通过完整push序列、六个寄存器与两个栈槽演示这一点。

3.11 · 浮点值进入XMM寄存器与浮点条件Floating-Point Code

来源：印刷329页起 / PDF 330页起

整数寄存器中的64位模式与XMM中的低64位可以装相同字节，但指令如何解释它们完全不同。这里关注标量float/double：ss表示单精度标量，sd表示双精度标量；packed指令可以同时作用于多组数据，而本章经常只关心最低一个元素。AVX常采用三操作数形式，读两源写一目的，减除方向仍须按AT&T顺序确认。

3.11.1 · 移动位模式与转换数值Floating-Point Movement and Conversion Operations

3.11.2 · 混合参数分到两个寄存器队列Floating-Point Code in Procedures

通常最多八个浮点标量参数按顺序放xmm0—xmm7，整数/指针仍按rdi、rsi等独立分配，浮点返回值在xmm0，XMM寄存器属于caller-saved。对double f(int x,double y,long z)，x=edi、y=xmm0、z=rsi；把y挪到参数列表第一位并不会让整数队列空出一个槽。

3.11.5 · 绝对值与取反可以只改符号位Using Bitwise Operations in Floating-Point Code

把double与0x7fffffffffffffff按位与，清符号位即可实现绝对值；与0x8000000000000000异或，翻转符号位即可取负。这些指令不会重新计算有效数字或改变舍入。自身异或产生+0.0，不能泛化为x−x，因为无穷与NaN在浮点算术中有特殊规则。3.56保留了三个原常量表及完整位解释。

3.11.6 · NaN使比较增加第四种结果Floating-Point Comparison Operations

经典表述 · NaN 对应比较的无序结果

浮点比较为什么要多看“无序”

static uint16_t reverse16(uint16_t x)
{
    uint16_t out = 0;
    for (unsigned i = 0; i < 16; ++i) {
        out = (uint16_t)((out << 1) | (x & 1u));
        x >>= 1;
    }
    return out;
}

static void product128(uint64_t a, uint64_t b, uint64_t *hi, uint64_t *lo)
{
    const uint64_t mask = UINT32_MAX;
    uint64_t a0 = a & mask, a1 = a >> 32;
    uint64_t b0 = b & mask, b1 = b >> 32;
    uint64_t w0 = a0*b0;
    uint64_t t = a1*b0 + (w0 >> 32);
    uint64_t w1 = t & mask, w2 = t >> 32;
    w1 += a0*b1;
    *lo = (w1 << 32) | (w0 & mask);
    *hi = a1*b1 + w2 + (w1 >> 32);

    if (a >> 63) *hi -= b;
    if (b >> 63) *hi -= a;
}

原题（中文翻译）

decode1:
 movq (%rdi), %r8
 movq (%rsi), %rcx

 movq %rcx, (%rdx)

解答

  1. 前三条把进入函数时的 x、y、z 全部保存，后面的写入不会改变这些快照。

def decode2_bits(x,y,z):
    mask=(1<<64)-1
    t=(y-z)&mask

生成掩码时只保留差值的最低位：在较小的 8 位模型里，最低位为 1 的值左移 7 位得到 10000000，再算术右移 7 位得到 11111111；最低位为 0 则得到全 0。题中用 64 位的 63 次移位做同一件事。因此最后与掩码异或时，偶数差保留乘积的位，奇数差翻转乘积的所有位。这里描述的是机器位运算；可移植 C 模型用无符号运算表达这些步骤，避免把负数左移写成合法的 C 运算。

给定union ele。A. 求e1.p、e1.y、e2.x、e2.next的字节偏移。B. 总长是多少？C. 根据汇编补 up->____=*(____)-____;。要求不使用强制转换、不违反类型约束，原题提示只有一个满足条件的答案。

union ele {
    struct { long *p; long y; } e1;
    struct { long x; union ele *next; } e2;
};
void proc(union ele *up) {
    up->____ = *(____) - ____;
}
movq 8(%rdi),%rax
movq (%rax),%rdx
movq (%rdx),%rdx
subq 8(%rax),%rdx
movq %rdx,(%rdi)
ret

Global Edition · 课后题 3.70 · 印刷 358—359 页 / PDF 359—360 页

解答

  1. A. 两个结构从union起点重叠：e1.p=0、e1.y=8、e2.x=0、e2.next=8；B. 两个候选结构均为16字节且按8对齐，所以union总长16。
  2. C. 首读偏移8后作地址使用，故是up−>e2.next而非long y；次读偏移0后又作地址使用，故是next->e1.p；再解引用得long值。减去next偏移8的long y，最后写up偏移0的long x。
  3. 完整式为 up->e2.x=*(up->e2.next->e1.p)-up->e2.next->e1.y;。设next->e1.p指向20且next->e1.y=7，结果up−>e2.x=13；相关指针须有效，且差可表示。
3.71 · 任意长一行的分块回显

原题（中文翻译）

写good_echo，从标准输入读取一行并写到标准输出，输入行长度可任意大。可以使用fgets，但必须在一行超过缓冲容量时仍正确；检查错误条件，遇错返回。请参考标准I/O函数定义。

Global Edition · 课后题 3.71 · 印刷 359 页 / PDF 360 页

解答

  1. 使用固定缓冲反复fgets，每次最多读容量减一字节，再fputs原样输出。只有看到换行才结束本行；遇EOF时，已经读到的末行片段仍应输出。空间O(1)，总时间与本行长度成正比。
  2. 下列C接口返回0表示本行或EOF正常结束，3表示输入/输出错误；fgets失败后用ferror区分EOF。fputs失败立即返回。最后fflush使缓冲中的写错误也能被观察。
  3. Python按同样分块文本模型读取；本題定义文本行，不包含嵌入NUL。实际测试覆盖空输入、单独换行、长度255/256/257/10000以及无末尾换行，并确认第二行不被读取。完整维护源见实验区的good_echo程序。
C（C11）
#include <stdio.h>
#include <string.h>
int good_echo(void)
{
    char buf[256];
    while (fgets(buf,sizeof buf,stdin) != NULL) {
        if (fputs(buf,stdout) == EOF) return 3;
        if (strchr(buf,'\n') != NULL)
            return fflush(stdout)==EOF?3:0;
    }
    if (ferror(stdin)) return 3;
    return fflush(stdout)==EOF?3:0;
}
Python 3
def good_echo(src, dst):
    try:

                break

            if chunk.endswith("\n"):
                break
        dst.flush()
        return 0
    except (OSError, ValueError):
        return 3
3.72 · alloca 的16字节对齐余量

原题（中文翻译）

图3.54将vframe中的VLA换为alloca；局部p自动随函数返回释放。按3.49记号，s1在第4行之后、s2在第7行之后、p在第9行之后，e2=p−s2，e1=s1−(p+8n)。A. 数学解释s2。B. 数学解释p。C. 找到使e1最小及最大的n、s1。D. 保证什么对齐？

#include <alloca.h>
long aframe(long n,long idx,long *q) {
    long i; long **p=alloca(n*sizeof(long *));
    p[0]=&i;
    for(i=1;i<n;i++) p[i]=q;
    return *p[idx];
}

andq $-16,%rax
subq %rax,%rsp             # s2

andq $-16,%r8              # p

解答

原题（中文翻译）

原题（中文翻译）

ISO C99支持complex类型。下面函数及gcc汇编给出double complex的例子。A. 复数实参如何传递？B. 复数返回值如何返回？

#include <complex.h>
double c_imag(double complex x) { return cimag(x); }
double c_real(double complex x) { return creal(x); }
double complex c_sub(double complex x,double complex y) {
    return x-y;
}
c_imag:
 movapd %xmm1,%xmm0
 ret
c_real:
 rep; ret
c_sub:
 subsd %xmm2,%xmm0
 subsd %xmm3,%xmm1
 ret

Global Edition · 课后题 3.75 · 印刷 360—361 页 / PDF 361—362 页

解答

  1. A. x实部在xmm0、虚部在xmm1；y实部在xmm2、虚部在xmm3。c_imag把xmm1复制到普通double返回寄存器xmm0，c_real无需移动。
  2. B. double complex结果的实部由xmm0返回，虚部由xmm1返回。c_sub分别做x.real−y.real、x.imag−y.imag，保留两个结果。

自测 3-1 · 地址与读取

问题

leaq 16(%rdi,%rsi,8),%rax 与同样操作数的 movq 有什么不同？

解答

lea 得到地址表达式 16+rdi+8·rsi 本身，movq 从这个计算出的地址读取八字节内容。前者可用于算术，后者要求对应内存有效；rax 最终保存的含义不同。

自测 3-2 · 调用后的活跃值

问题

调用另一个函数后还要使用旧 rdi 中的值，为什么不能默认它还在？

解答

普通参数寄存器 rdi 属于 caller-saved 范围，被调用函数可以使用并改变它。调用者应把仍活跃的值保存在合适的栈位置或正确使用的 callee-saved 寄存器中，再按约定恢复。

自测 3-3 · 二维地址

问题

在 4 字节元素的 a[4][5] 中，a[2][3] 距数组起址多远？若对象换成 int ** 能沿用同一公式吗？

解答

连续行优先数组的偏移为 (2·5+3)·4=52 字节。int ** 需先读取行指针，行存储可能分散；不能将指针对象的起址直接代入连续二维数组公式。

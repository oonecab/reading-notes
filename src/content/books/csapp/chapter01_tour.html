§1.1 · Information Is Bits + Context · 印刷 39 页 / PDF 40 页

The representation of hello.c illustrates a fundamental idea: All information in a system—including disk files, programs stored in memory, user data stored in memory, and data transferred across a network—is represented as a bunch of bits. The only thing that distinguishes different data objects is the context in which we view them. For example, in different contexts, the same sequence of bytes might represent an integer, floating-point number, character string, or machine instruction.

译文。hello.c 的表示说明一个基本思想：系统中的所有信息，包括磁盘文件、内存中的程序与用户数据，以及网络上传输的数据，都表示为一串位。不同数据对象之间的区别，取决于我们在什么上下文中观察它们。例如，在不同上下文里，同一串字节可以表示整数、浮点数、字符串或机器指令。

这里的“上下文”包括类型、编码规则和执行这次读取的指令。内存中字节相同，解释结果仍可不同；例如 8 位模式 11111111 按无符号解释为 255，按 8 位补码解释为 −1。改变解释规则并没有改变这些位。这个区分是第 2 章类型转换的出发点。

接着读：无符号与补码表示 · 字节怎样成为指令

作者从一个可以运行的 hello 程序出发。源文件、编译后的指令、运行时的字符串，最终都由位组成；它们的差别在于谁按什么规则解释这些位。理解系统的第一步，是把“存着什么位”与“这些位被当成什么”分开。

例：同一字节的两种解释

例如 ASCII 字符 A 的编码是十进制 65，即十六进制 0x41、二进制 01000001。如果把同一字节当作无符号整数，它的值就是 65；如果按字符编码读取，显示的是 A。文件里的字符 1 对应字节 0x31，并不是整数 1 的单字节表示 0x01。一个字节序列本身不会附带“我是文本”这样的标签。

观察对象实际字节（十六进制）解释
ASCII 字符 131字符编码；数值大小为49
一个字节保存整数101按无符号整数读取为1
文本串 1031 30两个字符，解析后才得到十进制10
C字符串结束标记00表示字符串终止，文件并不自动带这个结束标记

原书图 1.2 把 hello.c 展开为 ASCII 字节：开头的 # 为 35，换行为 10。源码里写下的反斜杠与字母 n 是两个源文件字符；编译器识别字符串转义 后，运行时字符串里才出现换行字节。这正是一次解释把一种表示转换成另一种表示。

后续所有章节都在扩大这个问题：第 2 章给位串指定整数或浮点解释，第 3 章给字节串指定指令解释，第 6 章将地址拆成标记、组索引与块内偏移。读例子时先写出位宽、编码和观察层次，往往就能避免看似神秘的错误。

为什么两个字符“10”还需要解析？按十进制位值规则，解析程序先把字符编码 0x31 识别为数字 1，把 0x30 识别为数字 0，再算 1×10+0=10。内存里的两个字节没有自行完成这次乘加；是读取它们的程序选择了十进制规则。这也解释了为什么同一份字节必须连同编码一起理解。

阅读注解
理解

相同的位可以承载不同对象

内存不因为程序声明了 int 就只存整数；类型约束、编码规则和执行的指令共同决定如何读写这些字节。

边界

字节和字符不是同一个计量单位

本例只用ASCII字符，一字符一字节。中文等Unicode字符经UTF−8编码通常需要多个字节，字节长度不能直接当作字符个数。

Here, the gcc compiler driver reads the source file hello.c and translates it into an executable object file hello. The translation is performed in the sequence of four phases shown in Figure 1.3. 这四条是分别观察各阶段的命令，产物写在自己的实验目录。它们使用当前编译器的目标平台；在 ARM 主机上得到的汇编不会自动变成书中的 x86-64。调试一份目标代码时，还应记录编译器、优化选项和目标体系结构。

理解

链接器处理名字与位置

函数名在源码里便于人理解，机器跳转需要地址。符号解析与重定位把这两种描述连接起来。

1.3 理解工具链怎样帮助判断程序It Pays to Understand How Compilation Systems Work

原书：印刷 42 页 / PDF 43 页

本节回答“应用程序员为什么还要知道这些”。作者给出的联系很具体：性能优化、链接错误、以及底层执行方式造成的安全问题。三者都要求我们跨过源代码表面，追踪实际发生的工作。

例如在循环条件里写 i < strlen(s)，人可能只看见一次比较，机器却可能每轮重新扫描字符串。能否把长度计算移到循环外，取决于循环是否可能改变 s 的内容，以及编译器能否证明这一点。第 5 章会用具体代码比较重复调用、局部累积和独立运算链。

再看“函数已经在头文件声明，为什么链接还失败”。声明只允许编译器检查调用形式；如果所有链接输入都没有提供该符号的定义，链接器仍然不能完成工作。把编译期和链接期分清，排查方向才能收敛到实现文件、库和链接方式。

最后，越界写入不仅可能改变一个数据值，还可能覆盖函数返回所需的保存状态。要解释它为什么会改变后续控制流，必须先知道栈和过程调用怎样组织。这里不要求记住某种固定栈布局；本章建立问题，第 3 章才用具体机器状态回答。

阅读注解
读法

先确认观察的是哪一层

编译报错、链接报错和运行崩溃分别发生在不同边界。保存命令、输入和出错阶段，比只记录“程序不工作”更有用。

边界

优化需要语义依据

人认为某个调用“应该没有副作用”，不等于语言或接口已经保证。第5章从这类差距展开。

1.4.1 硬件组织：每个部件在搬什么

总线在部件之间搬运信息；主存保存正在使用的程序与数据；处理器解释指令；I/O 设备把字节带进和带出系统。处理器内部还要分清三种角色：PC 给出将要取指的位置，寄存器文件保存少量操作数，ALU 做算术与逻辑计算。一次机器指令可以从内存取数、进行计算、写回结果，也可以改变下一条指令的位置。

1.5 快速计算为什么还要等待数据Caches Matter

原书：印刷 47 页 / PDF 48 页

原书摘录局部性为什么能同时接近大容量与高速度

§1.5 · Caches Matter · 印刷 49 页 / PDF 50 页

The idea behind caching is that a system can get the effect of both a very large memory and a very fast one by exploiting locality, the tendency for programs to access data and code in localized regions. By setting up caches to hold data that are likely to be accessed often, we can perform most memory operations using the fast caches.

译文。缓存背后的思想是利用局部性，也就是程序倾向于访问局部区域中的数据和代码，从而让系统同时获得近似大容量存储与高速存储的效果。把可能经常访问的数据放入缓存，就能让大多数存储器操作使用快速缓存完成。

结论依赖于“大多数访问命中”这个条件。若工作集过大、步长浪费块内数据，或多个热块不断争用同一位置，程序就无法获得同样收益。下面先用访问序列理解局部性，第 6 章再把容量、映射和替换策略放进可计算的模型。

接着读：时间局部性与空间局部性 · 命中、失效和替换

上一节把hello的路径连起来后，一个事实变得突出：系统花很多工作搬数据。处理器寄存器容量很小，但访问快；主存大得多，却不能以同样速度持续供应每一次访问。若每条指令都等待远处数据，算术单元再快也没有用。

缓存把最近或附近会使用的数据副本放在较快的层级。时间局部性指刚访问过的对象可能再次访问；空间局部性指附近地址可能随后访问。循环反复使用同一计数器表现出前者，顺序扫描数组表现出后者。空间局部性解释了为什么搬运通常以一块连续字节为单位，而不只拿一个刚请求的字节。

访问序列可以利用什么判断时还缺什么
a[0],a[1],a[2],a[3]相邻元素可能落在同一缓存块元素大小、块大小、对齐
a[0],a[0],a[0]同一位置的重复使用副本是否仍在缓存、是否发生替换
a[0],a[1024],a[2048]空间邻近性较弱步长、映射组、容量；不能只据下标断言全部失效

可以先做一个带条件的估计：若快层命中花1单位，未命中额外花100单位，命中率99%，平均代价为1+0.01×100=2单位。虽然只有1%的访问失效，它已把平均时间从1翻倍。这个例子说明高命中率为什么重要，也提醒我们比较百分比时要带上失效的代价。第6章再给出真正的组、行、标记和替换过程。

上面的平均代价可换成 100 次访问来算：100 次都要先花 1 单位尝试快层，共 100；其中平均 1 次未命中，再多花 100，共 200。除以 100 次，得到每次 2 单位。所以式中的 0.01 是未命中比例，乘的 100 是在已经尝试快层以后额外付出的时间；若给的是一次未命中的总时间，则不能再次重复计入快层成本。

阅读注解
推导

平均代价的口径要一致

这里100是未命中的额外代价，所以写1+失效率×100。如果100已经包含查找时间，必须改用命中/未命中的加权平均。

理解

缓存存的是副本

上层只保留部分下层数据；有限容量与映射冲突决定一个副本能留多久。

1.6 存储层次把容量和速度组合起来Storage Devices Form a Hierarchy

原书：印刷 50 页 / PDF 51 页

原书摘录相邻层次之间的缓存关系

§1.6 · Storage Devices Form a Hierarchy · 印刷 50 页 / PDF 51 页

The main idea of a memory hierarchy is that storage at one level serves as a cache for storage at the next lower level. Thus, the register file is a cache for the L1 cache. Caches L1 and L2 are caches for L2 and L3, respectively. The L3 cache is a cache for the main memory, which is a cache for the disk.

译文。存储器层次结构的主要思想是：某一层的存储设备充当下一层的缓存。因此，寄存器文件是 L1 缓存的缓存；L1 和 L2 分别是 L2 和 L3 的缓存；L3 是主存的缓存，而主存又是磁盘的缓存。

原书在这里用“缓存”概括把较远层的数据保留在较近层以便重用这一共同思想。实现机制仍有区别：编译器和指令显式安排寄存器中的值，硬件缓存按地址自动查找与替换，主存和磁盘之间的换页由硬件与操作系统共同支持。不能由这个类比推出寄存器也使用标签、缓存组和 LRU。

接着读：存储层次的通用缓存概念 · 寄存器与过程调用约定

缓存并非只是一块孤立硬件。作者把寄存器、若干级缓存、主存、本地磁盘和远程存储放进一个层次：靠近处理器的一侧快、小、单位存储成本高；远离处理器的一侧容量大、访问代价高。一个层次可以把下一层的数据作为来源，并充当它的缓存。

分层不是给每个变量永久指定一个“家”。数组的完整存储可能由主存承载，访问中的几块进入缓存，参与当前加法的值再进入寄存器。程序员看到的是一次源代码访问，系统完成的是跨层协作。

局部性让这种组合可行：如果每次都随机访问一个远大于快层容量的对象集合，快层会频繁替换，性能接近较慢层的约束。因此“存得下”与“工作集能留在快层”是两个不同问题。第5章先分析数据已在缓存的运算，第6章再逐渐放宽这个前提。

阅读注解
理解

程序全部数据很大，也可能每次只反复使用一个小块。分块算法正是通过安排工作集利用快层。

边界

1.7.1 进程：正在执行的程序及其状态

原书摘录进程把一次运行呈现为独占机器

§1.7.1 · Processes · 印刷 51 页 / PDF 52 页

A process is the operating system’s abstraction for a running program. Multiple processes can run concurrently on the same system, and each process appears to have exclusive use of the hardware. By concurrently, we mean that the instructions of one process are interleaved with the instructions of another process.

译文。进程是操作系统对正在运行的程序提供的抽象。同一系统上可以并发运行多个进程，而每个进程看起来都独占硬件。这里的并发，指一个进程的指令与另一个进程的指令交错执行。

原书此处先用单 CPU 的切换模型建立直觉。独占是受操作系统和硬件共同支持的运行视图；执行位置与寄存器需要保存、恢复，地址空间也需要隔离。程序文件本身不包含某次运行已打开的文件和当下执行位置，因此“文件存在”和“进程正在运行”是两个不同状态。

接着读：并发与并行的联系 · 第 8 章：进程与执行环境 · 第 9 章：虚拟内存与地址翻译

一个可执行文件可以先后运行多次，每次形成不同的进程。进程需要的不只是代码字节，还包括执行位置、寄存器、地址空间和已打开的资源。操作系统切换进程时保存必要上下文，之后恢复，程序才能从此前的位置继续。程序是可保存的描述，进程是这份描述的一次活动执行。

时间片活动主体状态关系

②请求运行hello内核安排新执行环境，选择接下来运行的上下文
③hello输出hello/内核hello在自己的地址空间执行并请求I/O
④hello结束内核/shellshell得到继续执行的机会，重新显示提示符

1.7.2 线程：同一进程内的多条执行流

原书摘录线程共享进程中的代码和全局数据

§1.7.2 · Threads · 印刷 53 页 / PDF 54 页

Although we normally think of a process as having a single control flow, in modern systems a process can actually consist of multiple execution units, called threads, each running in the context of the process and sharing the same code and global data.

译文。虽然通常把一个进程看成只有一条控制流，但现代系统中的一个进程实际上可以包含多个称为线程的执行单元；每个线程都在这个进程的上下文中运行，并共享相同的代码和全局数据。

共享并不等于所有状态相同：各线程仍有自己的执行位置、寄存器状态和调用栈。正因为多个线程可以访问同一个全局对象，程序还必须规定访问的同步关系；单线程中正确的“读、加一、写回”，放到两个线程中就可能丢失更新。后续第 12 章将展开这种共享带来的问题。

接着读：线程级并发与其他并行层次 · 一条控制流中的调用栈

线程共享进程的代码和许多数据，却各自需要执行位置和调用栈。这让共同处理一个任务更加直接，也带来共享变量的协调问题。两个线程都执行“读计数、加一、写回”，如果交错发生，可能把两次更新变成一次；第12章会把这件事拆成具体状态并引入同步。

1.7.4 文件：统一的字节输入输出接口

1.9.1 Amdahl定律：先把原来的时间分清

原书摘录Amdahl 定律及其上限

§1.9.1 · Amdahl’s Law · 印刷 58—59 页 / PDF 59—60 页

The main idea is that when we speed up one part of a system, the effect on the overall system performance depends on both how significant this part was and how much it sped up.

One interesting special case of Amdahl’s law is to consider the effect of setting k to ∞. That is, we are able to take some part of the system and speed it up to the point at which it takes a negligible amount of time.

译文。加速系统中某一部分时，对整体性能的影响既取决于这部分原来有多重要，也取决于它加速了多少。一个特殊情形是令局部加速倍数趋于无穷大，即把那部分耗时降低到可以忽略。

两段原文分别位于印刷 58、59 页。原书以原耗时 Told 为基准，把可改进部分的比例记作 α，把局部加速倍数记作 k，得到以下关系；右侧保留原书公式编号。

Tnew=(1−α)Told+αToldk
S=ToldTnew=1(1−α)+αk(1.1)
S∞=11−α(1.2)

条件与边界。固定同一任务，原耗时为正；可改进部分原占比满足 0≤α≤1，局部加速时 k≥1，其余部分耗时保持不变，且没有额外开销。式 (1.2) 的有限上限要求 α<1；若全部耗时都可改进，整体加速比就是 k。这里的比例取自改进之前。

先加速、再重新计时，会改变两部分在新总时间中的占比。因此不能把加速后的占比直接代回原公式。下面把时间分成两段，并用原书的 60% 例子算出这一限制。

1.9.2 并发与并行：三个不同尺度

原书摘录并发和并行在本章中的用法

§1.9.2 · Concurrency and Parallelism · 印刷 60 页 / PDF 61 页

We use the term concurrency to refer to the general concept of a system with multiple, simultaneous activities, and the term parallelism to refer to the use of concurrency to make a system run faster. Parallelism can be exploited at multiple levels of abstraction in a computer system.

译文。作者用“并发”表示系统同时存在多个活动这一一般概念，用“并行”表示利用并发使系统运行得更快。计算机系统可以在多个抽象层次上利用并行性。

结合前面的单 CPU 交错模型，“同时存在多个活动”可以是多个活动在一段时间内共同推进。要获得加速，还要有真正可重叠的工作和足够资源：多核可以运行不同线程，处理器内部可以重叠多条指令，SIMD 可以让一条指令处理多个数据元素。依赖、同步与内存等待会限制收益。

接着读：流水线中的重叠执行 · 用独立累积器缩短依赖链

多个活动在时间上交错推进，可以形成并发；多个计算真正重叠执行，则提供并行机会。单核切换进程能让多个应用看起来同时工作，多核可以让不同线程同时运行。线程级并行需要分配工作并协调共享状态；指令级并行则由处理器在同一线程中寻找独立指令；SIMD把一条运算作用于一组数据元素。

尺度可重叠的工作限制来自哪里
线程级不同任务或同一任务的分块共享数据、同步、不可并行部分
指令级独立算术、载入与其他操作数据依赖、功能单元、取指与访存
数据级 SIMD多个同类数据元素数据布局、向量宽度、分支与尾部

这些尺度会相互作用，但不能把“有更多核心”“每周期发射更多指令”“一次向量处理更多元素”当成同一倍数。最终还是要回到实际总时间，检查哪部分获得了多少收益。

1.9.3 抽象：按接口理解，同时知道实现代价

原书摘录顺序的指令语义与并行的内部实现

§1.9.3 · The Importance of Abstractions · 印刷 63 页 / PDF 64 页

With this abstraction, a machine-code program behaves as if it were executed on a processor that performs just one instruction at a time. The underlying hardware is far more elaborate, executing multiple instructions in parallel, but always in a way that is consistent with the simple, sequential model. By keeping the same execution model, different processor implementations can execute the same machine code while offering a range of cost and performance.

译文。在指令集体系结构这一抽象下，机器代码程序的行为就像由一个每次只执行一条指令的处理器执行。底层硬件复杂得多，会并行执行多条指令，但仍须与这个简单的顺序模型保持一致。保持同一种执行模型，使不同处理器实现能够执行相同机器代码，同时提供不同的成本与性能。

这里讨论的是单个程序的指令语义视图。硬件可以改变内部完成工作的次序，却不能任意改变程序可观察到的结果。第 4 章用转发、停顿与气泡维护这一要求，第 5 章再从依赖链分析还能有多少重叠空间。多线程对共享内存的观察还需要额外的内存模型与同步规则。

接着读：流水实现怎样保存指令语义 · 依赖与现代处理器模型

文件统一I/O，虚拟内存统一地址视图，指令集描述处理器能做的状态变换。好的抽象让程序员暂时省略实现细节；本书训练的是当正确性或性能需要时，能够沿接口往下展开。例如 C 数组语法隐藏了地址运算，缓存又使相同语法的不同访问顺序具有不同代价。第3章和第6章分别解释这两层。

并发可以先看一颗核心上的两个任务：A 发出磁盘读取后等待，核心转去执行 B，数据到达后再回来执行 A。两件事都在推进，但任何瞬间核心只执行一条指令流。若两颗核心分别执行 A、B 的计算，才有同时执行的并行。这里争取的收益不同：前者利用等待时间，后者让计算工作重叠；都要按最终总耗时判断效果。

把时间分量写进程序

下面程序把α和k保持在调用点，speedup函数只实现已推导的公式。循环列出同一原始比例下不同k的结果；最后反解整体四倍目标所需的局部加速，并检查目标是否存在有限正解。

下载 C11 源码 · 下载 Python 3 源码

C（C11）
#include <stdio.h>

static double speedup(double fraction, double factor) {
    return 1.0 / ((1.0 - fraction) + fraction / factor);
}

int main(void) {
    const double fraction = 0.6;
    const double factors[] = {1.0, 1.5, 3.0, 10.0};
    for (size_t i = 0; i < sizeof factors / sizeof factors[0]; ++i)
        printf("alpha=%.1f k=%.1f speedup=%.6f\n",
               fraction, factors[i], speedup(fraction, factors[i]));
    printf("limit=%.6f\n", 1.0 / (1.0 - fraction));
    const double target = 4.0, improved_fraction = 0.9;
    const double denominator = 1.0 / target - (1.0 - improved_fraction);
    if (denominator <= 0.0) return 1;
    printf("required-k=%.6f\n", improved_fraction / denominator);
    return 0;
}

    raise ValueError("Target has no finite positive solution")
print(f"required-k={improved_fraction / denominator:.6f}")

alpha=0.6 k=1.0 speedup=1.000000
alpha=0.6 k=1.5 speedup=1.250000
alpha=0.6 k=3.0 speedup=1.666667
alpha=0.6 k=10.0 speedup=2.173913
limit=2.500000
required-k=6.000000

最后一行使用α=0.9、整体目标S=4，先算1/S−(1−α)=0.15，再得k=0.9/0.15=6。若这个分母为零，只能在局部耗时趋零的极限达到；若为负，目标超过该模型的整体上限。

习题解答 · 1.1—1.2

1.11.2

本章原书有两道随文练习，按本版题号排列。先独立列时间关系，再展开对照。

1.1 · 分段行车与整体加速

原题（中文翻译）

卡车将土豆从Boise运到Minneapolis，全程2500 km。按限速平均100km/h行驶，预计25h。其中1500 km位于Montana。

A. 若这一段取消限速，卡车能以150km/h行驶，整段旅程加速多少倍？B. 若可购买不同增压器，要求全程达到1.67倍加速，则Montana路段需达到多大速度？

原书：印刷 58—59 页 / PDF 59—60 页

解答

  1. 原来的两段时间分别为1500/100=15h和1000/100=10h，所以可改进比例α=15/25=0.6。

  2. A：新时间为1500/150+10=20h，加速比25/20=1.25。也可代入k=150/100=1.5，得到1/(0.4+0.6/1.5)=1.25。

  3. B：按题面的1.67为精确值，新总时间为25/1.67≈14.97006h，Montana允许时间约4.97006h，因此速度1500/4.97006≈301.20482km/h。

  4. 原书解答把1.67近似为5/3，取总时间15h，得速度300km/h。300对应的实际加速比是25/15=1.666…，四舍五入为1.67；精确目标和近似目标的区别应保留。

A 中的 10h 为什么保留？全程还有 2500−1500=1000 km 不在可提速路段，仍按 100km/h 行驶，所以这段的 1000/100=10h 没有改变。B 则倒着算：整体加速比是“旧时间÷新时间”，因此先用 25/1.67 求新的总时间，再扣除不可改变的 10h，剩下的才是 Montana 路段可用的时间。

1.2 · 由整体目标反解局部改进

原题（中文翻译）

一家汽车制造商承诺下一版发动机性能提高到原来的4倍。你判断只有90%的部分能改进；在本题使用的Amdahl耗时模型下，这部分必须提高多少倍k才能实现整体目标？

原书：印刷 59 页 / PDF 60 页

解答

  1. 把可改进的90%解释为原始耗时比例α=0.9。新总时间相对旧时间为0.1+0.9/k；整体四倍要求它等于1/4。

  2. 0.1+0.9k=0.25⇒k=0.90.15=6

  3. 代回：未改进部分0.1，加速后的部分0.15，总计0.25，整体恰为4倍；上限为1/0.1=10倍，所以该目标可达。

题干校注：原书书后首行将4=1/[(1−0.9)+0.9/k]排成缺少分母整体括号的形式；后续计算与k=6对应上述完整分母。这里保留其正确耗时模型。

取原来总共 100 分钟更直观：其中 10 分钟不能改，90 分钟可以改。整体快四倍意味着只允许花 25 分钟；先预留固定的 10 分钟，可改部分只剩 15 分钟。原来 90 分钟的工作压到 15 分钟，所以局部必须快 90/15=6 倍。这里的 0.15 来自“目标总时间扣除固定时间”，不是题目直接给出的比例。

自测 1-1 · 位模式的解释

问题

一个字节 0xff 为什么既能表示 255，也能表示 −1？

解答

无符号权值全为正，八个 1 相加为 255；8 位补码最高位权值是 −128，其余七位合计 127，所以得到 −1。上下文选择解释，字节本身没有变。

自测 1-2 · 加速的上限

问题

占原总时间 80% 的工作加速 4 倍，总加速比是多少？

解答

新相对时间为 0.2+0.8/4=0.4，总加速比 2.5。把这部分完全消掉后的上限是 5；不能把局部 4 倍直接当作全程序 4 倍。

按原耗时 100 单位计，20 单位保持，80 单位变成 80/4=20，新总耗时 40，故 100/40=2.5。即使那 80 单位工作瞬间完成，仍留下 20，所以最大也只有 100/20=5 倍。

自测 1-3 · 目标文件与可执行文件

问题

已经有机器码的 hello.o 为什么还要链接？

解答

机器码可以仍引用外部符号，地址也可能需要重定位。链接负责组合对象、解析引用和安排地址；“包含机器码”和“已完成运行所需绑定”是两个条件。

12.1 · 用进程隔开每个客户Concurrent Programming with Processes

来源：印刷 1009—1012 页 / PDF 1010—1013 页

第11章迭代echo在accept之后一直服务同一客户。客户A只连上却不发完一行，客户B即使已经准备好也无法得到服务。本章从这个具体困难出发：让A等待I/O的时间与B的处理重叠。并发是逻辑流在时间上重叠；并行还要求它们确实在不同计算资源上同时执行。

12.1.1 · 让每条连接有一个进程A Concurrent Server Based on Processes

来源：印刷 1010 页 / PDF 1011 页

父进程保留listenfd=3，accept得到connfd=4。fork后两张描述符表都引用同一个连接文件表项；父关4、子关3，子独占服务职责。第二次accept可以复用父进程的4，它与第一个孩子的4属于不同描述符表，数值相同不冲突。孩子服务后close并exit，父进程持续accept。

服务器必须用waitpid循环回收所有已退出孩子，因为标准信号可能合并，一次SIGCHLD不对应恰好一个孩子。处理函数保存恢复errno，只调用异步信号安全的waitpid。12.35的维护源在父进程安装回收函数，孩子关闭监听描述符，父关闭已接入描述符；有限连接实验结束时再等待尚在运行的孩子。

12.1.2 · 隔离让共享必须显式发生Pros and Cons of Processes

来源：印刷 1011 页 / PDF 1012 页

两个孩子各有自己的可写虚拟空间，局部计数器不会自然合成总数；需要管道、共享内存或其他IPC。好处是一个孩子写错用户空间通常不直接覆写另一个孩子的堆；代价是进程创建、调度与IPC。共享的是文件表等内核对象，不是“fork后父子任何东西都私有”。

本版12.2把删除父进程Close(connfd)称为不会泄漏，与本节正文冲突。父进程长期运行时每条连接都留下引用，孩子退出也无法让引用归零；只有父进程最终退出时内核才回收。这一条件在题解保留并明确校注。

父子各关自己的一份

fork复制描述符表项；底层连接引用仍共享。父进程关连接，子进程关监听，才能把各自责任落实。

边界

回收是持续工作

有限实验在结束前回收；长期服务器还须及时回收，不能等待父进程退出。

12.2 · 让一次就绪只推进有限一步Concurrent Programming with I/O Multiplexing

来源：印刷 1013—1021 页 / PDF 1014—1022 页

select把“先等键盘还是先等新连接”改成“等任意一个可读事件”。fd_set是输入输出参数：输入集合表示感兴趣的fd；返回集合只保留本次已就绪fd，所以每轮必须从持久read_set重新复制。第一个参数是最大fd+1，而不是集合中的fd数量；EOF也属于可读，因为read可立即返回0。

例：select 的输入与输出集合

例如兴趣集合为 {0,4,9}，本轮只有 4 可读，select 返回的就绪集合便为 {4}。若下轮直接沿用这个结果作为输入，0 和 9 就被无意间取消监听；所以要从持久兴趣集合重新复制。参数应是 9+1=10，因为内核需要检查编号 0 到 9 的位置，而不是只检查集合中有几个元素。

每个连接至少保存fd、已收字节、解析位置、待发字节与发送偏移。A发“he”后没有换行：状态变成输入缓冲2 字节，回到select；B发“ok\n”后马上完成一行并进入输出状态。下次A发“llo\n”时，把它拼成“hello\n”。socket可读只保证某次读取能推进，不保证rio_readlineb能收齐整个应用层消息。

原书图12.11先把clientrio[i]复制到局部rio，却没有写回它；RIO预读缓冲的消费位置会丢失。另外，多行已进入RIO用户缓冲而socket暂时不可读时，单靠select不会发现剩余行。本页echo实现直接维护持久字节缓冲；每轮最多发送一个客户的一行，并在准备fd集合前处理已缓冲完整行。read/write都使用非阻塞fd并保存短写进度，连接fd达到FD_SETSIZE会拒绝，避免FD_SET越界。

12.2.2 · 显式调度提高控制，也增加状态负担Pros and Cons of I/O Multiplexing

来源：印刷 1021 页 / PDF 1022 页

同一线程完成一段状态更新后才轮到下一个连接，因此这些回调之间无需再为普通局部表加线程锁；它也能决定轮询次序与每轮预算。代价是栈上的“函数调用到一半”必须转成显式状态。若一个回调做阻塞磁盘读取、长计算或阻塞写入，其他连接仍会停住。

单线程事件循环只能在一个核上执行这一条CPU控制流；多事件循环进程、线程池或异步I/O可以进一步组合。本页select HTTP模式将网络读写拆成非阻塞状态，内容生成仍同步读取最多64 KiB本地普通文件，所以它能让慢网络客户之间交错推进，磁盘文件读取仍可能阻塞整个事件循环。

12.3 · 共享进程，但单独管理执行与回收Concurrent Programming with Threads

来源：印刷 1021—1028 页 / PDF 1022—1029 页

线程像进程一样由内核调度，又像同一事件循环里的流一样共享地址空间。它省下显式IPC的同时，也把“哪个线程可以写这个对象、谁负责结束它的生存期”变成应用必须回答的问题。

12.3.1 · 线程之间是同伴关系Thread Execution Model

来源：印刷 1022 页 / PDF 1023 页

线程有自己的寄存器现场、程序计数器和栈，但共享整个进程的地址空间及打开的文件描述符。创建者不天然拥有子线程的全部生命周期权限：可join的线程由指定同伴回收，所有线程都必须遵守对象访问约定。原文把TID说成整数是Linux教学视角；可移植Pthreads的pthread_t是抽象类型，应以pthread_equal比较，不能假定可用%d打印。

12.3.2 · 先从创建与等待配对开始Posix Threads

来源：印刷 1023 页 / PDF 1024 页

最小程序的关键顺序是create → peer执行 → join返回 → main结束。线程入口类型是void *(*)(void *)；多个参数放在结构体中，返回值也可以指向明确由接收者释放的堆对象。Pthreads多数函数直接返回错误码，不能把非零返回值一律当作errno已设置。实验中的check(error)用返回码构造诊断。

12.3.3 · 发布参数前完成初始化Creating Threads

来源：印刷 1024 页 / PDF 1025 页

pthread_create成功后，新线程可能在创建者从该函数返回前就运行。先填写args[i].id，再把&args[i]传入；直到join后才回收数组。这给每个线程稳定且不同的对象，避免共享循环变量i。create失败时根本没有新线程接管参数，调用者必须清理；服务器源中失败分支close并free连接对象。

12.3.4 · 结束线程与结束进程不同Terminating Threads

来源：印刷 1024 页 / PDF 1025 页

线程入口return或pthread_exit只结束调用线程；exit以及main中的return结束整个进程及其所有线程。因此创建后立即exit会让尚在sleep的同伴没机会输出。pthread_exit不是主线程等待其他线程再退出：调用线程当即结束，进程在仍有线程时继续运行；最后一个线程结束后进程结束。

pthread_cancel是取消请求，何时响应取决于取消状态、类型和取消点，不能当作立即强杀。取消可能留下应用锁或资源，必须设计cleanup。本文的有界服务器和tfgets采用协作结束、join及明确回收，避免依赖异步取消。

12.3.5 · join既等待也回收Reaping Terminated Threads

来源：印刷 1025 页 / PDF 1026 页

pthread_join(tid,&result)指定一个joinable线程，成功后才能安全读取它已完成写入的结果并回收参数区；不要同时让两个线程join同一个tid，也不要join自身。没有“任意一个线程”的Pthreads join接口，工作队列常用条件变量通知完成，再由拥有者明确回收。

12.3.6 · 自动回收不代替资源所有权Detaching Threads

来源：印刷 1025 页 / PDF 1026 页

detached线程结束时线程资源自动回收，不能再join。detach不会自动close连接或free用户分配的参数；它也不保证main会等待。原文说detached线程不能被其他线程“killed”不宜等同为禁止pthread_cancel：取消能力与join/detach状态不是同一个开关，而且只能对仍有效的tid操作。有限实验保留joinable线程，在交付结果前逐一join，便于证明所有请求已完成。

12.3.7 · 把共享初始化也同步起来Initializing Threads

来源：印刷 1026 页 / PDF 1027 页

pthread_once_t once=PTHREAD_ONCE_INIT；每个调用者先执行pthread_once(&once,init)。同一控制对象保证初始化例程只完成一次，其他调用者等初始化完成才继续。单独写if(!initialized){init(); initialized=1;}会让两个线程同时初始化互斥量；只把标志改volatile也不修复。静态PTHREAD_MUTEX_INITIALIZER则适用于本页固定的锁。

12.3.8 · 把连接描述符的所有权交给线程A Concurrent Server Based on Threads

来源：印刷 1027 页 / PDF 1028 页

主线程不能把反复被accept覆盖的connfd地址交给多个线程；即使数值是整数，指针指向的仍是同一个可变存储。原书为每个连接malloc一个int，线程先复制值再free参数，最后close连接。线程共享描述符表，所以主线程在移交后不能像fork方案那样再close同一个fd，否则工作线程会失去它或误碰复用后的连接。

本页C服务器把fd、root和proxy标志装入单独的connection；create成功后线程唯一负责close与free，失败则主线程负责。这个成功/失败分界就是所有权转移点。

对比 fork 与线程的 close：fork 后父 fd 4 与子 fd 4 是两张表中的两条引用，父删掉自己那条，子那条还在；线程则共用一张表，主线程和工作线程说的 fd 4 指同一条表项，主线程 close 会直接删掉工作线程要用的引用。把连接交给线程，是移交这条引用的处理责任，不是像 fork 那样多得到一份可各自关闭的引用。

阅读注解
生存期

参数不是只传一个地址

地址对应的对象必须活到线程用完。create返回不能证明新线程已经读取参数。

回收

join与detach二选一

join负责明确收回；detach负责退出时自动回收。二者不替应用关闭socket或free参数。

12.4 · 先找到对象，再判断是否需要同步Shared Variables in Threaded Programs

12.4.1 · 私有栈不意味着别人不能通过指针访问Threads Memory Model

来源：印刷 1029 页 / PDF 1030 页

每个线程栈通常由它自己使用，但栈位于共享的虚拟地址空间。main里char *msgs[2]若通过全局ptr发布给同伴，同伴就间接读到main的局部数组。只要对象存活且访问被正确同步，这种访问可以合法；如果main先pthread_exit，依赖其局部对象继续存活就不可靠。教学实现将数组保留到join之后。

12.4.2 · 按存储期枚举实例Mapping Variables to Memory

来源：印刷 1030 页 / PDF 1031 页

全局变量ptr只有一个实例；线程函数内static int cnt也只有一个实例，作用域限制名称在哪段代码可见，不会为每次调用复制存储。自动变量myid在每次线程调用里有独立实例；main的i只有main自己的那一个。把变量名与对象实例分开，才能讨论到底是哪两次访问发生冲突。

12.4.3 · 多个线程引用同一个实例才叫共享Shared Variables

来源：印刷 1031 页 / PDF 1032 页

原文伴读 · 共享的判据是实例

We say that a variable v is shared if and only if one of its instances is referenced by more than one thread.

中文：当且仅当变量v的某个实例被多于一个线程引用时，称v为共享变量。

“所有全局都共享、所有局部都私有”只是常见情况，不是这个定义。对每个实例画出引用者，就能解释12.6的msgs为何共享。

来源：印刷 1031 页 / PDF 1032 页

C11边界还要继续检查：若两个线程冲突访问同一非原子对象、至少一个为写且没有happens-before，构成数据竞争，行为未定义。原书badcnt的load/update/store用于解释一种机器交错；不能据此声称实际有数据竞争的C程序只会在1或2中选结果。本页错误交错由单线程状态模型穷举，真正pthread程序对共享计数加锁。

“局部”说明名字的作用域或自动对象的建立位置，不说明访问权限。若 main 有 int value=7; 并把 &value 传给线程，线程参数中保存的地址仍指向 main 的那个对象；通过它读取就是共享访问。只读且保持 value 存活可以安全，若 main 同时无同步地写 value，就发生冲突。判断对象是否共享，要像第 5 章别名例子一样沿指针找到同一个存储位置。

12.5 · 同步必须保护不变量并安排等待Synchronizing Threads with Semaphores

来源：印刷 1031—1048 页 / PDF 1032—1049 页

两个线程各做cnt++并不等于一次不可分割的更新。先在明确定义的机器模型中把它拆成L（读cnt到寄存器）、U（寄存器加1）、S（写回）。从cnt=0出发，L1,L2,U1,U2,S1,S2让两个寄存器都变成1，最终cnt=1；修复的目标是禁止导致丢失更新的交错。

12.5.2 · 许可计数与阻塞必须原子结合Semaphores

来源：印刷 1037 页 / PDF 1038 页

P(s)等待s>0后原子减1；V(s)加1并允许等待者继续。s初值1可作二元互斥许可，初值0可表示还没有生产出的数据。只有计数非负这个不变量不够：检查s和减1若拆成两个未同步操作，两个线程可能同时拿到最后一个许可。POSIX sem_wait还可能被信号中断，封装需在EINTR时重试。

macOS不支持本章使用的进程内未命名sem_init，因此本页实际队列使用pthread_mutex与pthread_cond。互斥量保护count/数组/游标；条件变量只唤醒等待者，不能代替持久count。pthread_cond_wait原子释放锁并等待，返回时重新持锁；while循环应对虚假唤醒以及别的线程先消费资源。

条件变量等待要用 while，还可看两个消费者的例子：A 等待时释放了锁，生产者放入一个元素并唤醒 A；A 真正重新获得锁之前，B 可能已经取走它。A 醒来时 count 又是 0，必须再等，不能把“曾经被通知”当成“现在仍有一个属于我的元素”。判断 count、决定等待及实际出队都围绕同一把锁，才能让这条规则在各种调度下成立。

/* Sequential C11 state model. It never executes a C data race or blocks on locks.
 * P(x) consumes an available token; V(x) returns it. Explore reachable states.
 * Input is fixed textbook programs: finite binary locks, at most three threads. */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct { int pc[3]; unsigned tokens; } state;
static unsigned char visited[7][7][7][8];
static const char *program[3];
static int threads, lengths[3], deadlocks, finishes;
static void explore(state s) {
    if (visited[s.pc[0]][s.pc[1]][s.pc[2]][s.tokens]) return;
    visited[s.pc[0]][s.pc[1]][s.pc[2]][s.tokens] = 1;
    int enabled = 0, complete = 1;
    for (int t = 0; t < threads; ++t) {
        if (s.pc[t] == lengths[t]) continue;
        complete = 0;
        char op = program[t][s.pc[t]];
        unsigned bit = 1u << (unsigned)((op >= 'a' ? op-'a' : op-'A'));
        int take = op >= 'a';
        if (take && !(s.tokens & bit)) continue;
        if (!take && (s.tokens & bit)) { fputs("non-binary release\n",stderr); exit(1); }
        state next = s; next.pc[t]++;
        next.tokens = take ? s.tokens & ~bit : s.tokens | bit;
        enabled = 1; explore(next);
    }
    if (complete) finishes++;
    else if (!enabled) deadlocks++;
}
static void locks(const char *name, const char *a, const char *b,
                  const char *c, unsigned initial, int expected) {
    program[0]=a;program[1]=b;program[2]=c;threads=c?3:2;
    for (int i=0;i<threads;++i) lengths[i]=(int)strlen(program[i]);
    memset(visited,0,sizeof(visited));deadlocks=finishes=0;
    explore((state){{0,0,0},initial});
    if ((deadlocks>0)!=expected) exit(1);
    printf("%s deadlocks=%d completed=%d\n",name,deadlocks,finishes);
}

"""Finite interleaving model; no Python threading/GIL conclusions are inferred."""
from functools import lru_cache


def count_updates():
    outcomes = [0, 0, 0]
    def step(pc, registers, value):
        if pc == (3, 3):
            outcomes[value] += 1
            return
        for t in range(2):
            if pc[t] == 3:
                continue
            p, r = list(pc), list(registers)
            new = value
            if p[t] == 0:
                r[t] = value
            elif p[t] == 1:
                r[t] += 1
            else:
                new = r[t]
            p[t] += 1
            step(tuple(p), tuple(r), new)
    step((0, 0), (0, 0), 0)
    return outcomes


def lock_states(programs, tokens):
    """lowercase acquires, uppercase releases; return distinct terminal states."""
    dead, done = set(), set()
    @lru_cache(None)
    def visit(pc, free):
        enabled = False
        if all(i == len(p) for i, p in zip(pc, programs)):
            done.add((pc, free))
            return
        for t, p in enumerate(programs):
            if pc[t] == len(p):
                continue
            op = p[pc[t]]
            bit = 1 << (ord(op.lower()) - ord('a'))
            if op.islower() and not free & bit:
                continue
            if op.isupper() and free & bit:
                raise ValueError('release without ownership')
            nxt = list(pc)
            nxt[t] += 1
            enabled = True
            visit(tuple(nxt), free ^ bit)
        if not enabled:
            dead.add((pc, free))
    visit((0,) * len(programs), tokens)
    return dead, done


def main():
    outcomes = count_updates()
    if outcomes != [0, 18, 2]:
        raise RuntimeError(f'counter outcome mismatch: {outcomes}')
    print(f'counter schedules={sum(outcomes)} final1={outcomes[1]} final2={outcomes[2]}')
    cases = [
        ('12.15-original', ('aAbB', 'aAbB'), 1, True),
        ('12.15-fixed', ('aAbB', 'aAbB'), 3, False),
        ('12.28-case1', ('abAB', 'abAB'), 3, False),
        ('12.28-case2', ('abAB', 'abBA'), 3, False),
        ('12.28-case3', ('abBA', 'abAB'), 3, False),
        ('12.28-case4', ('abBA', 'abBA'), 3, False),
        ('12.29', ('abBcCA', 'cbBC'), 7, False),
        ('12.30', ('abBcCA', 'cbBCaA', 'cCbaAB'), 7, True),
    ]
    for name, programs, initial, expected in cases:
        dead, done = lock_states(programs, initial)
        if bool(dead) != expected:
            raise RuntimeError(f'lock outcome mismatch: {name}')
        print(f'{name} deadlocks={len(dead)} completed={len(done)}')


if __name__ == '__main__':

def read_all(sock):
    data = b''
    while True:
        chunk = sock.recv(65536)
        if not chunk:
            return data
        data += chunk
        if len(data) > 200000:
            raise AssertionError('unbounded response')


def check_complete_home_response(answer):
    header, separator, body = answer.partition(b'\r\n\r\n')
    require(separator, answer)
    lines = header.split(b'\r\n')
    require(lines[0] == b'HTTP/1.0 200 OK', lines[0])
    lengths = [line.split(b':', 1)[1].strip() for line in lines[1:]
               if line.split(b':', 1)[0].lower() == b'content-length']
    require(len(lengths) == 1 and int(lengths[0]) == len(body), (lengths, body))
    require(body == b'<h1>Concurrent Tiny</h1>\n', body)


def connect(port):
    s = socket.create_connection(('127.0.0.1', port), timeout=6)
    s.settimeout(6)
    return s


def launch(binary, mode, root, count, extra=()):
    p = subprocess.Popen([str(binary), '--serve', mode, str(root), '0', str(count), *map(str, extra)],
                         stdout=subprocess.PIPE, stderr=subprocess.PIPE, text=True)
    line = p.stdout.readline().split()
    if line[:2] != ['LISTEN', '127.0.0.1']:
        raise AssertionError((mode, line, p.communicate(timeout=3)))
    return p, int(line[2])


def finish(p):
    out, err = p.communicate(timeout=12)
    require(p.returncode == 0, (p.returncode, out, err))
    require('Sanitizer' not in err and 'runtime error:' not in err, err)
    return err

def check_window_cases(binary, root):
    """Keep one accepted client alive across window expiry, then drain it."""
    results = []
    for mode, stalled in [('select', False), ('echo', False), ('select', True)]:
        p, port = launch(binary, mode, root, 2)
        client = connect(port)
        started = time.monotonic()
        try:
            prefix = b'partial' if mode == 'echo' else b'GET / HTTP/1.0\r\n'
            client.sendall(prefix)
            time.sleep(.95)
            require(p.poll() is None, (mode, 'accepted client discarded at window expiry'))
            try:
                late = socket.create_connection(('127.0.0.1', port), timeout=1)
            except ConnectionRefusedError:
                pass
            else:
                late.close()
                raise AssertionError((mode, 'listener still accepts after its window'))
            if not stalled:
                client.sendall(b' line\n' if mode == 'echo' else b'Host: localhost\r\n\r\n')
                if mode == 'echo':
                    client.shutdown(socket.SHUT_WR)
                answer = read_all(client)
                if mode == 'echo':
                    require(answer == b'partial line\n', answer)
                else:
                    check_complete_home_response(answer)
            else:
                answer = read_all(client)
                require(answer == b'', answer)
                require(2.5 <= time.monotonic()-started <= 6, 'client deadline lost')
            out, err = p.communicate(timeout=5)
            # Expiry before the requested count remains a partial-run result.
            require(p.returncode == 1, (p.returncode, out, err))
            require(not err, err)
            results.append({'mode': mode, 'stalled': stalled,
                            'seconds': round(time.monotonic()-started, 3),
                            'late_connection_refused': True, 'returncode': p.returncode})
        finally:
            client.close()
            if p.poll() is None:
                p.kill()
            p.communicate(timeout=5)
    return results

12.39 · 会过滤、记录并并发转发的Web代理

原题（中文翻译）

来源：印刷 1071—1072 页 / PDF 1072—1073 页

Web代理位于Web服务器和浏览器之间：浏览器先联系代理，由代理转发请求并把服务器响应交回浏览器。编写一个能过滤并记录请求的简单代理。A. 首先接受请求、解析HTTP、转发给服务器并把结果返回浏览器；把所有请求的URL写入磁盘日志，并阻止磁盘过滤文件中包含的URL。B. 随后升级为每个请求创建独立线程，使等待一个远程服务器响应时仍能处理另一个浏览器的待办请求。用真实Web浏览器检查代理。

解答与推导

完整实现为proxy_handle、blocked_and_log与proxy-serial/proxy模式。proxy-serial顺序处理对应A，proxy按连接创建thread对应B；解析绝对形式GET http://host:port/path，检查请求边界、版本与字符，再按原URL精确匹配过滤文件；日志记录ALLOW/BLOCK及URL。被过滤请求返回403，不建立上游连接；允许请求转换为origin-form GET /path并设置Host及Connection: close，收完整有限响应后写回。

./tmp/csapp/part3/ch12/servers --serve proxy . 0 128 filter.txt proxy.log

本地可重复实验限定明文HTTP GET和环回上游，便于真实浏览器经代理访问同一回环地址上运行的Tiny；不支持TLS/CONNECT、任意公网主机、认证透传、缓存或通用HTTP分帧转换。它实现题中的过滤、日志、串行到线程并发主机制，范围属于可检验的本地代理，不宣称可替代日常公网代理。协议驱动已实测两种模式的允许/拒绝与日志。浏览器实验时，把HTTP代理设为程序输出的监听地址，依次访问允许与过滤的回环URL，核对页面正文、403状态和日志；须确认浏览器没有绕过本地地址的代理。所列运行结果来自协议驱动，真实浏览器经代理的路径尚未实测；前述四种 Tiny 的表单结果来自直接访问。复现代理实验时使用专用浏览器配置，将回环地址的代理绕过规则关闭：允许URL须显示上游正文并产生ALLOW日志；过滤URL须显示403、产生BLOCK日志且上游没有对应请求；慢上游尚未返回时，另一页面的快速请求应先完成。这三项分别观察代理转发、过滤与并发处理。

原创自测：先判断谁拥有资源

原创自测 1 · 线程能照抄fork后的close吗？

自测题

主线程accept得fd=7，create工作线程后立即close(7)，工作线程稍后read(7)。为何这与fork版不同？

解答

线程共享同一描述符表，主线程close撤销的就是工作线程要用的引用；号码还可能被另一accept复用。fork复制描述符表，父子各有一份引用，因此各close自己那份才正确。

原创自测 2 · 条件变量通知早到了会丢数据吗？

自测题

生产者在消费者执行wait之前已经put一个元素并signal。消费者后来是否必然睡死？

解答

正确实现先在mutex下检查count。此时count>0便直接take，不会wait；通知不是数据本身，受锁保护的谓词才记住事实。若不检查谓词就直接wait，才会丢失唤醒效果。

原创自测 3 · 20条轨迹能证明实际badcnt只有两个结果吗？

自测题

模型枚举20条L/U/S交错，结果只有1和2。能否据此宣称所有C编译器上的未加锁cnt++都只会输出1或2？

解答

不能。模型前提是给定三条原子指令且保留线程内顺序；C非原子数据竞争属于未定义行为，优化器不受这套枚举结论约束。实际执行用同步，错误模型用顺序模拟。

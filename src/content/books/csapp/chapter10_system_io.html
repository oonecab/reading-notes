10.1 · 把外设访问统一为描述符上的操作Unix I/O

来源：印刷 926—927 页 / PDF 927—928 页

前两部分主要解释程序怎样在 CPU 和内存里运行；第三部分开始追踪数据怎样离开进程，进入磁盘、终端和网络。Unix I/O 的关键抽象很小：程序保存一个非负整数描述符，内核保存被打开对象的状态，程序用 read/write 在对象与内存之间复制字节。它统一了调用方式，但没有承诺每种对象都能定位、都有固定长度，或一次 read 恰好对应一次 write。

原文精选 · EOF 是返回状态，不是藏在文件末尾的字符

There is no explicit “EOF character” at the end of a file.

中文释读。常规文件读到当前位置之后已无数据，read 返回 0 表示 EOF。文件末尾无需保存特别字节；0x00、0x04 或 0xff 都可能是普通文件中的真实内容。

来源：印刷 927 页 / PDF 928 页

设常规文件为六个字节 foobar，当前偏移 k=0。请求读 4 字节成功后得到 foob，k 变为 4；再请求 4 字节只剩 ar，返回 2，k 变为 6；第三次正长度读取返回 0。这里每一步都按实际返回计数更新状态，不能按请求长度增加偏移。对于管道或 socket，“暂时没有数据”在阻塞模式下通常意味着等待，只有写端生命周期或连接状态满足 EOF 条件时才返回 0。

步骤调用请求返回数据/计数常规文件偏移
打开open("sample",O_RDONLY)描述符，如 30
第一次读read(3,buf,4)foob / 44
第二次读read(3,buf,4)ar / 26
第三次读read(3,buf,4)无 / 06
关闭close(3)成功返回 0描述符 3 可再次分配

shell 通常使新程序继承标准输入 0、标准输出 1、标准错误 2；它们对应 STDIN_FILENO、STDOUT_FILENO、STDERR_FILENO。这是启动环境约定，不是每个进程永远保持三者打开的定律。重定向可以把 0 接到文件、1 接到管道；程序仍使用同样的整数，而不必根据外设类型重写主算法。第 8 章的 fork/exec 由此与 I/O 接上：继承的是描述符关系，用户空间的缓冲和程序映像另有生命周期。

阅读注解
对象

统一接口不等于统一能力

lseek 可移动常规文件位置，却不能把一个网络连接倒带。后面使用 Rio 前仍须说明对象类型、阻塞方式和消息边界。

边界

read(fd,buf,0) 的 0 不证明 EOF

只有正长度读取返回 0 才可在正常读取流程中判断已到末尾；零字节请求可以直接返回 0 而不读取任何数据。

10.2 · 文件类型、目录与路径是不同层次Files

来源：印刷 927—929 页 / PDF 928—930 页

普通文件保存任意字节；“文本”是应用怎样解释字节的约定，内核不会因文件扩展名自动改变读取方式。文本行通常以 LF（十六进制 0a）结束，CRLF 则是 0d、0a 两个字节。比如 A\r\nB 占四字节，读行时连同 LF 返回前三个字节；若协议要求 CRLF，就不能为了显示方便擅自删掉 CR。原书提到 Windows/HTTP，是提醒读者把文件格式或协议与当前系统的终端习惯分开。

原文精选 · 文本与二进制的区别由应用解释

To the kernel there is no difference between text and binary files.

中文释读。在本章的 Linux 文件模型中，两者同为字节序列。遇到二进制中的 0a 不能自动把它解释成应用记录的结束；遇到 00 也不能用 strlen 推断数据长度。

来源：印刷 927 页 / PDF 928 页

目录将文件名映射到文件对象；一个目录项提供“从这个目录出发，怎样找到对象”的信息，而不是把文件内容嵌在目录里。socket 用于通信；符号链接、管道与设备文件是其他类型。文件名、文件对象和一次打开产生的状态要区分：多个名字可以指向同一对象，同一对象也可以被多次打开而拥有不同的偏移。

若当前目录是 /home/droh，./hello.c 指向目标；若当前位置是 /home/bryant，则用 ../droh/hello.c。原书校注：印刷 929 页在第二种情形写 ../home/droh/hello.c；按它自己的图 10.1，该路径先到 /home，再走 home，实际变成 /home/home/droh/hello.c，因此多了一个 home 分量。这里保留原写法及其错误原因，再给出按图修正的路径。

路径解析还可能遇到符号链接、访问权限和并发重命名；不能把所有含 .. 的路径都仅当作字符串删掉前一段来做安全验证。本章只用稳定目录解释查找；程序需要针对正在打开的对象取元数据时，后面将优先说明 fstat。

阅读注解
表示

文件的长度按字节计算

UTF−8 的一个可见汉字通常占多个字节。st_size 与 read 返回的是字节数，不是显示字符数或文本行数。

命名

一个名字与一个打开对象不是同一件事

文件打开后，描述符定位已打开的对象；稍后路径被改名，并不意味着描述符也自动改指向新的同名文件。

10.3 · 打开创建状态，关闭释放一条引用Opening and Closing Files

来源：印刷 929—931 页 / PDF 930—932 页

open 把路径查找和访问意图组合起来，成功返回一个描述符，失败返回 −1 并设置 errno。访问模式是 ORDONLY、OWRONLY、ORDWR 三选一；OCREAT、OTRUNC、OAPPEND 等附加标志再按位或进去。OCREAT 只表示不存在时创建；OTRUNC 才表示把可写打开的已有普通文件长度截成零。把它们混为一谈，会使“打开一个现有文件准备追加”误变成清空文件。

原文精选 · 描述符使用最小可用编号

The descriptor returned is always the smallest descriptor that is not currently open in the process.

中文释读。如果 0、1、2 已打开且其他都空闲，第一次 open 返回 3。关闭 3 后，它又是最小空位；下一次打开即使是另一文件，也会复用 3。整数只在其有效生命周期内表示这次打开关系。

来源：印刷 929 页 / PDF 930 页

int in = open("input.txt", O_RDONLY);
int out = open("output.txt", O_WRONLY | O_CREAT | O_TRUNC, 0666);
int log = open("events.txt", O_WRONLY | O_CREAT | O_APPEND, 0666);
/* 每次检查 fd < 0；使用结束后分别检查 close(fd)。 */

第三个参数只在创建等需要 mode 的情形提供；原书把接口写成三个固定参数并在只读例子传 0，实际 POSIX 声明使用可变参数。这里跟随系统头文件，不自行重声明 open。数字 0666 是八进制权限，owner/group/others 各得到 rw；若 umask 为 0022，则创建的普通文件权限为 0644。按位计算是 0666 & ~0022 = 0644，不是普通减法；默认 ACL 等文件系统规则另有影响，此例沿书中普通模式位模型。

位组读/写/执行本例 0666掩去 0022 后
所有者0400/0200/0100读写读写
所属组0040/0020/0010读写只读
其他用户0004/0002/0001读写只读

OAPPEND 让每次内核 write 在写入前定位到末尾；它不能保证由多次 write 拼成的整条日志记录不被另一写者插入。缓冲层的一次打印也未必正好对应一次 write。close 释放当前描述符的一条引用；若 dup/fork 留下另一引用，打开状态仍可存活。关闭失败应报告，不能无条件重试同一整数：描述符复用以及不同平台对中断关闭的规定，可能使重试影响后来打开的对象。维护例子不在 close 上套 EINTR 重试循环。

umask 的含义是“清除指定权限”，所以应按位算，不能把本例恰好相等的减法当规则。例如请求权限 0444 本来就没有写位，掩码 0022 再去掉组/其他用户写位，仍是 0444；普通八进制减法却得 0422，反而把不应有的位算了出来。每位独立清除，才能保持“掩码只删权限，不增加权限”的含义。

阅读注解
寿命

整数重用使陈旧描述符危险

fd=3 关闭后若再打开文件，旧变量仍等于 3，却可能操作新对象。多线程代码要维护所有权，不能用“这个数以前开过”代替当前状态。

权限

umask 只影响创建时被屏蔽的权限位

它不会自动改变所有已有文件。程序若暂时改变进程 umask，应考虑它影响同进程其他创建操作，不能将其当成单次 open 的局部参数。

10.4 · 请求长度与实际传输量必须分别保存Reading and Writing Files

来源：印刷 931—933 页 / PDF 932—934 页

ssize_t read(int fd, void *buf, size_t n);
ssize_t write(int fd, const void *buf, size_t n);

size_t 表示非负的请求大小；ssize_t 能表示传输计数以及 −1 错误。必须先把返回值留在有符号类型中检查，再在确定非负后转为 size_t；若直接存进无符号变量，−1 会变成很大的正数，使随后指针推进越界。原书 x86-64 示例的类型宽度为 64 位，本章代码依赖系统定义而不硬编码 long 的位数；请求总量限定不超过 SSIZE_MAX。

原文精选 · 短计数本身不是错误

Such short counts do not indicate an error.

中文释读。返回值满足 0<实际计数<请求计数时，这次调用已经成功转移了那部分数据。调用者必须保留进度，再决定是继续凑满固定长度、把现有字节交给解析器，还是在 EOF 结束。

来源：印刷 931 页 / PDF 932 页

书中例子是文件只余 20 字节而请求 50：先返回 20，再次正长度读返回 0。终端的规范模式可能在一行可用后交出这行；socket 或管道当前只有一部分数据可供读取，也会返回正的短计数。网络字节流尤其不能依靠一次 read 的边界分割消息：发送端写 100 字节，接收端可能读成 40+60，也可能与下一次发送合并。

结果这次发生了什么固定长度读取的处理
k>0得到恰好 k 字节done +=k，指针推进 k，再读余量
k==0，请求 > 0到达该输入对象的 EOF 条件返回已获得的总数，可能不足目标
−1，errno=EINTR调用在未报告字节前被中断重试相同未完成区间
−1，其他 errno本次调用失败报告；先前循环已完成部分不会自动撤销

原书边界校注：印刷 932 页称实际中普通磁盘文件除 EOF 外不会短读、写入不会短写。这是常见教学场景的经验，不能作为接口保证。当前 Linux read(2) 明确允许短读，write(2) 说明空间不足、资源限制或中断等可导致部分写入。因此通用复制程序仍处理短计数；写入成功也不表示已持久落盘。读取内存映射、磁盘缓存和物理持久化是不同层次。

若使用非阻塞描述符，EAGAIN/EWOULDBLOCK 需要交还事件循环等待就绪；把它当成 EINTR 原地重试会忙等。本章实现明确针对阻塞描述符，只对 EINTR 重试，其余错误返回。向已无读者的管道/socket 写入还可能递交 SIGPIPE；是否捕获或屏蔽它应由应用设定，Rio 循环本身不能保证进程一定有机会观察 EPIPE。

请求写出 ABCDEF，若第一次返回 2，就有两个变量要一起改：下一字节从 A 改成 C，剩余长度从 6 改成 4。第二次应是 write(fd,buf+2,4)。只减长度会重复发送 AB 开头的内容，只移指针而不减长度又会越过原来的六字节区间。短计数循环的指针与剩余量是同一段未完成后缀的两种表示。

阅读注解
不变量

已经传出的字节不应再次传出

若写 6 字节先成功 2，再次调用必须传 buf+2、长度 4。仍从 buf 开始会重复前缀，仍请求 6 会越过原缓冲。

失败

−1 不意味着整个高级操作毫无副作用

先写 2 字节再发生磁盘错误，writen 可返回 −1，但外部文件已改变。需要事务语义时必须在更高层设计，不能误用重试掩盖重复写入。

10.5 · Rio 把传输进度与缓冲状态显式化Robust Reading and Writing with the Rio Package

来源：印刷 933—939 页 / PDF 934—940 页

Rio（Robust I/O）不是另一套内核接口；它是围绕 read/write 的小型用户态封装。它解决两个不同问题：短计数使调用者反复维护“还差多少”，逐字节解析又容易产生过多系统调用。无缓冲 n 字节接口把多次传输凑在一起；带缓冲输入则一次向内核取一批字节，在用户态按行或按块消费。理解这两类状态，就能读懂后面网络服务的输入代码。

10.5.1 · 循环保持已经完成的前缀Rio Unbuffered Input and Output Functions

原文精选 · 固定长度读遇到 EOF 才成功返回短计数

The rio_readn function can only return a short count if it encounters EOF.

中文释读。在请求范围和缓冲有效、阻塞输入且没有最终错误的条件下，readn 会继续读取，直到得到 n 字节或遇到 EOF。若发生非 EINTR 错误，它返回 −1，不把部分进度当成成功短计数。

来源：印刷 933 页 / PDF 934 页

设目标是 6 字节 A 00 B 0a C D，底层依次报告 EINTR、2、1、3。初始 done=0；EINTR 不改变 done；后面三次把 done 更新为 2、3、6。readn 或 writen 的核心不变量是：缓冲前 done 字节已完成，下次只操作区间 [done,n)。若读取目标改为 9，六字节之后又遇 EOF，就返回 6；若第三字节前发生 EIO，则返回 −1，但前两个字节已经读入，文件位置也已前进。

10.5.2 · 让读行和读块消费同一批预取字节Rio Buffered Input Functions

原书 rio_t 保存 fd、未读字节数 rio_cnt、下一个字节的指针以及 8192 字节数组。rio_readinitb 只建立空缓冲，不马上读取。内部 rio_read 在 count=0 时调用 read 补充数据，再复制 min(请求量,count) 字节，推进指针并减少 count。外层 rio_readlineb 每次从这个缓冲取一个字节检查换行；rio_readnb 则反复取块。逐字节的用户态读取通常不会逐字节陷入内核。

原文精选 · 带缓冲读取必须共享同一套位置状态

However, calls to these buffered functions should not be interleaved with calls to the unbuffered rio_readn function.

中文释读。读行已经预取但尚未交给应用的字节只在 rio_t 中。绕过它直接读取同一打开状态，会从更靠后的内核位置开始，使应用观察到跳过或乱序的数据。

来源：印刷 934 页 / PDF 935 页

以上例子在读完 hi\n 后，应用逻辑位置是 3，内核位置却是 8。此时若直接 read(fd,buf,4)，只会得到最后的 Q；中间五个字节仍在 Rio 缓冲里，后续再回到 Rio 就出现错序。即使换成 dup 得到的另一个 fd，由于它共享同一打开文件位置，问题依然存在。正确做法是对这条输入流保留唯一缓冲状态，文本头用 readlineb，定长二进制体用 readnb。

readlineb 最多转移 maxlen−1 字节，并额外写一个 NUL，返回值不包含这个结尾 NUL，包含实际读取到的换行。若行是 abcde\n 而容量为 4，先返回 abc，再返回 de\n；“截断”是本次输出片段被限制，余下输入仍可继续读，并非丢弃了后半行。若一行最后无换行，EOF 前已有的字节仍返回一次；下一次才返回 0。维护版要求容量至少 2，使返回 0 保持“没有数据”的含义；原书 maxlen=1 会返回 0 而未消费输入，maxlen=0 不在安全调用范围。

原书称 Rio 带缓冲例程 thread-safe，是因为缓冲属于调用者的 rio_t，没有一个所有调用共享的静态数组。它不允许多个线程无锁修改同一个 rio_t；不同 rio_t 若包装同一共享偏移，仍会发生预取与消费关系的问题。线程同步及流的所有权须由第 12 章的应用设计保证。二进制字节中的 NUL 不妨碍按返回计数复制，但通常不应使用“读到 LF”为二进制消息定界。

阅读注解
进度

成功计数与附加终止符分开

readlineb 返回 3 的 hi 需要四字节空间，第四字节是函数补的 NUL。发送时用返回值 3，不发这个额外的 NUL。

边界

固定 n 字节读取可能等待

网络对端只发了 3 字节却保持连接时，readn(10) 会继续等，不会因暂时无数据自动返回 3。协议必须告诉应用要读多少，或采用明确的行界。

10.7 · 目录读取的末尾和失败共享一个返回值Reading Directory Contents

来源：印刷 941—942 页 / PDF 942—943 页

opendir 返回 DIR* 目录流；readdir 每次返回下一项 struct dirent*，closedir 释放流及相关资源。返回项中的 dname 是当前目录内的名字，不是完整路径；若要查询它，需要相对该目录解析或使用相应的目录描述符接口。目录枚举顺序不承诺字母序，结果也不是一个自动冻结的目录快照。

DIR *dir = opendir(path);
if (dir == NULL) { perror("opendir"); return 1; }
for (;;) {
    errno = 0;
    struct dirent *entry = readdir(dir);
    if (entry == NULL) {
        if (errno != 0) { /* 读取失败 */ }
        break; /* errno 为 0 表示正常流末尾 */
    }
    /* 在下一次 readdir 前使用 entry->d_name，需长期保存则复制。 */
}
if (closedir(dir) < 0) { /* 报告关闭失败 */ }

readdir 用 NULL 同时表示读完和错误，因此检查 errno 之前必须先清零。原书图 10.11 在整个循环之前清一次，循环内仅打印名字；更稳妥的可组合写法是在每次 readdir 前清零，因为循环体以后可能调用会改变 errno 的函数。正常读完不会替调用者清除一个与 readdir 无关的旧错误。

原书把 dname 画成 256 字节数组、把 dino 称为文件位置。按当前 readdir(3)，不应依赖 dname 的固定数组大小；dino 是 inode 编号，既不是磁盘物理字节地址，也不是单凭它就能跨文件系统唯一定位文件的完整标识。下一次调用可能复用内部存储，不能收集一组指针后误以为保存了所有独立名字。

ch10_files --list DIR 输出目录项，每次调用前清 errno，并检查打印、closedir 和最终刷新。测试只核对已知名字存在于结果集合，不依赖遍历顺序。它不递归跟随符号链接，也不需要修改传入目录。

阅读注解
错误

errno 只有在接口规定的失败结果后才有意义

成功的库调用不保证把 errno 清成 0。因此先看返回值，再按该接口规则解释 errno；不能每调用一次函数就无条件判 errno。

寿命

借用的目录项与拥有的字符串不同

readdir 给出库内部结构。需要排序或跨下一次调用保留名称时，复制 dname 的实际内容，再为自己的副本负责。

10.8 · 看清三张表，才能判断偏移是否共享Sharing Files

来源：印刷 942—945 页 / PDF 943—946 页

教材用三层关系解释打开文件：每个进程有自己的描述符表；描述符表项指向打开文件表项，保存当前偏移等一次打开的状态；再指向 v−node 层的文件对象元数据。这是帮助推理的内核抽象，不要求 Linux 内部结构恰好就用三张固定数组和这些名字实现。推题时最关键的是中间一层：偏移属于打开文件描述，而不直接属于路径名或某个整数。

原文精选 · fork 复制描述符表，共享打开状态

Parent and child share the same set of open file tables and thus share the same file position.

中文释读。父子拥有各自的描述符表项，但指向相同打开文件描述。子进程读一个字节后，共享偏移已推进；父进程随后读取得到下一字节。

来源：印刷 943 页 / PDF 944 页

两次独立 open("foobar.txt") 各得 k=0。fd1 先读 f，把 A.k 变为 1，B.k 仍为 0；fd2 再读还是 f。这是 10.2。换成打开一次后 fork，子进程读 f 把共享 k 改为 1，父进程 wait 子退出后再读 o，这是 10.3。wait 的作用是保证先后顺序；若去掉等待，谁先拿到第一个字节不再确定，不能仅由源代码在父分支的位置断言结果。

对同一打开描述的 close 只移除一条描述符引用；最后一条引用消失后，内核才可释放相应打开状态。子进程退出会关闭它的描述符，但不会因此关闭父进程对应整数。文件对象本身也不能仅因一次 close 就推断从磁盘消失：目录链接与打开引用承担不同的生命周期作用。

还要把用户态 FILE/Rio 缓冲与这三层区分。fork 的地址空间副本会复制用户态尚未刷出的缓冲，内核打开偏移却共享；父子都 exit 刷新同一批旧输出可产生重复内容。本章宿主实验在 fork 前不留下待输出日志，孩子用 _exit 返回状态，并由父亲 wait 后核对读数，避免输出缓冲干扰偏移观察。

这里与指针别名有相同的结构：两个整数 fd 可以通过两条表项引用同一个“含偏移的对象”。dup2 共享这个对象，所以经一方读取会改变另一方下一次读取的位置；两次 open 则创建两个不同的打开状态，即使底层文件相同也各有偏移。判断共享时应追踪两条引用是否汇合到同一个打开状态，不能只比较变量的名字或数值。

阅读注解
判据

问“是否同一次打开状态”，比问“文件名是否相同”更有效

同名两次 open 通常偏移独立；不同描述符由 dup2 或 fork 指向同一打开描述时共享。从表项箭头追到中间层即可判断。

并发

共享偏移不等于共享应用缓冲

两个进程各持一份预取缓冲时，每个应用的逻辑位置还受自己的缓冲影响。跨进程分块处理应设计分工，不能只依赖 fd 看起来相同。

10.9 · 重定向改变表项关系，复制循环不变I/O Redirection

来源：印刷 945—946 页 / PDF 946—947 页

执行 ls > foo.txt 时，shell 在子进程中把标准输出 1 接到目标文件，再 exec 程序。ls 仍然向 stdout 写，接收者却已换成文件。关键调用 dup2(oldfd,newfd) 使 newfd 指向 oldfd 的打开文件描述；若 newfd 原本打开，会在同一操作中替换其原引用。不能用先 close(newfd) 再 dup(oldfd) 来等价代替原子地占用指定编号。

原文精选 · 复制的是描述符表项

The dup2 function copies descriptor table entry oldfd to descriptor table entry newfd, overwriting the previous contents of descriptor table entry newfd.

中文释读。oldfd 提供原有打开关系，newfd 是要改变的编号。dup2(4,1) 改的是标准输出 1；返回后 4 和 1 共享位置、打开状态和目标对象。

来源：印刷 945 页 / PDF 946 页

int fd = open("foo.txt", O_WRONLY | O_CREAT | O_TRUNC, 0666);
if (fd < 0) { /* 报告并终止该次执行 */ }
if (fd != STDOUT_FILENO) {
    if (dup2(fd, STDOUT_FILENO) < 0) { /* 处理失败 */ }
    if (close(fd) < 0) { /* 处理失败 */ }
}
/* 随后 exec；被执行程序继续向编号 1 输出。 */

为什么有 fd!=1 判断？若进程启动时 1 本来关闭，open 可能正好返回 1；这时它已经就位，若复制后再无条件 close(fd)，反而关闭了刚建立的标准输出。对输入重定向也一样：先 open 输入，再 dup2(fd,0)，最后只关闭不等于 0 的临时引用。习题 10.10 的“保留同一个复制循环”正是这个抽象的用途。

在文件 foobar 上，fd2 已读一个 f，偏移为 1；再 dup2(fd2,fd1)，fd1 放弃自己的旧打开状态并共享 fd2 的 k=1。下一次通过 fd1 读取返回 o。dup2 不复制文件内容，也不把偏移重置为 0。oldfd 无效时操作失败，不能继续当作重定向成功；在真实程序中还应协调用户态已缓存的标准 I/O，避免旧缓冲在重定向后被送往意料外的目的地。

阅读注解
方向

oldfd 是来源，newfd 是要占用的名字

将标准输入接到已打开的 5，应 dup2(5,0)。口语“重定向到”容易混淆，直接画 0 的箭头最终应指向谁。

所有权

复制后多出的是引用，不是文件数据

新引用可以独立 close，但仍共享打开位置。原始临时 fd 关闭后，标准输入/输出的复制引用会继续保持目标打开。

10.10 · 标准 I/O 在描述符上增加流与格式Standard I/O

来源：印刷 947 页 / PDF 948 页

标准 I/O 用 FILE* 表示流，提供 fopen/fclose、fread/fwrite、fgets/fputs 和 printf/scanf 等接口。FILE* 不是文件描述符整数，stdin/stdout/stderr 也不是 0/1/2 的指针写法；流内还保存缓冲、EOF/错误状态及实现所需信息。在本章 Unix 环境里，流建立在底层描述符上，缓冲减少系统调用，格式化函数则负责把对象值与文本相互转换。

原文精选 · 流把描述符与缓冲连起来

A stream of type FILE is an abstraction for a file descriptor and a stream buffer.

中文释读。读者调用 getc 可以每次得到一个字符，库却可能一次从内核预取一大块。程序观察的逻辑进度与底层描述符位置并不总相同。

来源：印刷 947 页 / PDF 948 页

假设文件是 abcdef，getc 第一次触发库读取六字节，返回 a，随后几次 getc 直接消费缓冲。此时裸 read 同一 fd 很可能已在内核 EOF，而流仍有 bcdef。这个现象与 Rio 的预取完全同源。输出也类似：printf 先把字符放入用户态缓冲，fflush/fclose 或缓冲策略触发实际 write；printf 返回并不证明终端或远端已看见全部字节，更不证明磁盘落盘。

接口返回量/结束条件易混点
fread(ptr,size,n,fp)完整元素数不是总字节数；size=1 可按字节统计
fwrite(ptr,size,n,fp)成功写入的元素数可能失败；最终刷新也须检查
fgets(buf,cap,fp)指针或 NULL，最多 cap−1 字符保留读到的换行并补 NUL；必须区分 EOF/error
getc(fp)unsigned char 转 int 或 EOF不能先存 char 再与 EOF 比较
fflush(fp)0 成功，EOF 失败刷新用户态输出，不等于 fsync

对于普通文本处理，标准 I/O 的格式化和错误状态通常更方便。使用它时仍要遵守流规则：不要未经协调把 stdio 与裸 read/write 混在同一打开状态上；fread 返回不足要检查 feof/ferror；关闭或刷新写流的失败应处理。原书使用小型输入输出片段解释机制，维护程序把错误分支显式化。

getc 的返回类型为何是 int，可用文件中的字节 0xff 理解：在常见 8 位字节系统中，它是合法数据值 255，此外接口还需要一个区别于所有字节值的 EOF 标记。先存 int，才能分清 255 与 EOF；若先缩成有符号 char，0xff 可能变成 −1，与常见 EOF 值混淆。判断完不是 EOF，再按需要转成字符。

阅读注解
计数

二进制 fread 常用 size=1

fread(buf,1,n,fp) 的返回值直接是读取字节数；若 size=4，返回的是完整四字节元素的个数，不能不换算就拿去 write。

刷新

缓冲、内核与设备各有完成点

fflush 处理 C 流缓冲；底层 write、文件系统缓存与设备持久化是后续层次。每层成功的含义要按接口解释。

10.11 · 按对象与协议选择合适的输入输出层Putting It Together: Which I/O Functions Should I Use?

来源：印刷 947—949 页 / PDF 948—950 页

原书建议：普通磁盘/终端尽量用标准 I/O；二进制数据按字节计数读取；本书的网络例程使用 Rio。这里选择的是哪一层帮我们维护状态。元数据和描述符重定向要用 Unix/POSIX 接口；普通文本文件可交给 stdio；网络协议一旦交替“文本头＋定长二进制体”，就适合让同一个 rio_t 保存全部预取状态。

标准 I/O 的读写更新流有方向切换规则：输出后转输入，需要先 fflush 或定位；输入后转输出，需要先定位，除非输入已遇到 EOF。普通文件可定位，socket 却不能 lseek，因此直接拿一个双向 FILE* 套住 socket 会遇到限制。C11 委员会草案 N1570 §7.21.5.3¶7 明确规定了这两个方向的切换条件。格式化本身仍可保留：先 snprintf 到有限内存，确认返回长度未截断，再按字节计数发送；接收则先读一行，再解析字段并验证完整性。

教材提出给同一 socketfd 建读、写两个 FILE*，接着指出各 fclose 都关闭同一个整数：第二次关闭会失败，若期间该整数已被另一个线程复用，甚至会关闭错误对象。这个问题来自所有权冲突。通过 dup 得到独立描述符并分别包装可以避免同一编号被重复关闭，但缓冲、关闭和协议结束方式仍需完整设计；它不改变本书示范网络 I/O 时使用 Rio 的建议，也不能据教材简化讨论断言所有网络库都禁止使用 stdio。

二进制文件可含任意数量 0a，所以 getline/scanf/readlineb 的“行”不自动等于一条应用记录。维护例子的 --lines 按实际计数原样写回，因而也能复制内嵌 NUL 等字节；这只是证明复制不会丢字节，不把读行作为一般二进制消息解析方案。协议给定长度 N 时用 readnb(N) 并核对返回 N；协议给定行界时则处理超长行分段，不能将首段误认为完整命令。

阅读注解
协议

网络读取成功不表示应用消息完整

read 返回一个正数只证明得到这些字节。消息完整性来自长度字段、分隔符或关闭约定，应由解析层明确验证。

等待

Rio 不提供截止时间

阻塞 readn 的循环会等够目标或 EOF/error。请求超时、取消和慢速客户端限制须另加机制，不能因函数名 Robust 就假定已有。

10.12 · 把一次请求从描述符追到应用缓冲Summary

来源：印刷 949—950 页 / PDF 950—951 页

从一个具体流程收束本章：进程先 open 文件得到 fd；read 把部分字节从内核交给 Rio 缓冲；readlineb 只把第一行交给应用；readnb 接着消费同一缓冲中的二进制正文；writen 按返回计数逐段写出；最后 close 释放本进程的一条打开引用。任何一步出错，都要分清哪部分数据已经传输，哪个状态仍由谁拥有。

下一章会把文件描述符换成连接描述符，但这条线仍成立。新问题是如何得到连接、怎样编址、如何判断一条请求的边界；并发章再让多个执行流同时运行这条线，要求为共享状态和资源寿命建立同步。本章的短计数不变量、唯一缓冲所有权、打开描述共享关系，是这两章共同需要的基础。

短计数循环和同一 Rio 缓冲的读行/读块

先看 readn/writen：done 只在正计数时推进，EINTR 保持状态重试，EOF 只结束读取，其他错误返回。再看 buffered_read：pos+count 描述尚未消费的缓冲尾部；只有 count=0 才补充。readlineb 在调用者提供的容量内保留 NUL 位置，达到容量限制就返回当前片段，不吞掉后续输入。

为了确定地重现错误，函数接收底层读写回调；真实 CLI 使用 read/write 回调，自测使用 Script 注入 EINTR、短块、EIO 和零进度写。这是对循环分支的执行验证，不能作为真实信号调度的证据。selftest 用显式 require 而非 assert，关闭断言也不会跳过验证；一个真实 pipe 用例另核对六字节中的 NUL 和换行及写端关闭后的 EOF。

/* C11 + POSIX. Blocking descriptors; valid storage of at least n bytes.
 * Default: deterministic injected I/O plus a real pipe check.
 * --copy [FILE]: binary copy; --lines [FILE]: line-buffered byte copy.
 * EINTR injection checks the loop, not host signal delivery. */

typedef ssize_t (*reader)(void *, void *, size_t);
typedef ssize_t (*writer)(void *, const void *, size_t);
typedef struct { reader get; void *ctx; size_t pos, count; unsigned char buf[8]; } Rio;

static ssize_t fd_read(void *p, void *b, size_t n) { return read(*(int *)p, b, n); }
static ssize_t fd_write(void *p, const void *b, size_t n) { return write(*(int *)p, b, n); }

static ssize_t readn(reader get, void *ctx, void *buf, size_t n) {
    unsigned char *p = buf;
    size_t done = 0;
    if (n > (size_t)SSIZE_MAX) { errno = EINVAL; return -1; }
    while (done < n) {
        ssize_t k = get(ctx, p + done, n - done);
        if (k < 0) { if (errno == EINTR) continue; return -1; }
        if (k == 0) break;
        done += (size_t)k;
    }
    return (ssize_t)done;
}

static ssize_t writen(writer put, void *ctx, const void *buf, size_t n) {
    const unsigned char *p = buf;
    size_t done = 0;
    if (n > (size_t)SSIZE_MAX) { errno = EINVAL; return -1; }
    while (done < n) {
        ssize_t k = put(ctx, p + done, n - done);
        if (k < 0) { if (errno == EINTR) continue; return -1; }
        if (k == 0) { errno = EIO; return -1; }
        done += (size_t)k;
    }
    return (ssize_t)done;
}

static ssize_t buffered_read(void *ctx, void *buf, size_t n) {
    Rio *r = ctx;
    if (n == 0) return 0;
    while (r->count == 0) {
        ssize_t k = r->get(r->ctx, r->buf, sizeof r->buf);
        if (k < 0) { if (errno == EINTR) continue; return -1; }
        if (k == 0) return 0;
        r->pos = 0;
        r->count = (size_t)k;
    }
    if (n > r->count) n = r->count;
    memcpy(buf, r->buf + r->pos, n);
    r->pos += n;
    r->count -= n;
    return (ssize_t)n;
}

static ssize_t readlineb(Rio *r, void *buf, size_t capacity) {
    unsigned char *p = buf;
    size_t done = 0;
    /* Unlike the textbook, reject capacities that cannot transfer a byte. */
    if (capacity < 2 || capacity - 1 > (size_t)SSIZE_MAX) { errno = EINVAL; return -1; }
    while (done < capacity - 1) {
        ssize_t k = buffered_read(r, p + done, 1);
        if (k < 0) return -1;
        if (k == 0) break;
        if (p[done++] == '\n') break;
    }
    p[done] = 0;
    return (ssize_t)done;
}

typedef struct {
    const unsigned char *src;
    size_t length, offset;
    const int *steps;
    size_t nsteps, next, calls;
    unsigned char output[64];
} Script;

static ssize_t scripted(void *ctx, void *buf, size_t n) {
    Script *s = ctx;
    ++s->calls;
    int k = s->next < s->nsteps ? s->steps[s->next++] : 64;
    if (k < 0) { errno = -k; return -1; }
    if (n > (size_t)k) n = (size_t)k;
    if (n > s->length - s->offset) n = s->length - s->offset;
    memcpy(buf, s->src + s->offset, n);
    s->offset += n;
    return (ssize_t)n;
}

static ssize_t scripted_write(void *ctx, const void *buf, size_t n) {
    Script *s = ctx;
    ++s->calls;
    int k = s->next < s->nsteps ? s->steps[s->next++] : 64;
    if (k < 0) { errno = -k; return -1; }
    if (n > (size_t)k) n = (size_t)k;
    if (n > sizeof s->output - s->offset) { errno = ENOSPC; return -1; }
    memcpy(s->output + s->offset, buf, n);
    s->offset += n;
    return (ssize_t)n;
}

    s = (Script){bytes, 6, 0, again, 1, 0, 0, {0}};

    s = (Script){(const unsigned char *)"abcde\n", 6, 0, NULL, 0, 0, 0, {0}};
    r = (Rio){scripted, &s, 0, 0, {0}};
    if (!require(readlineb(&r,b,4)==3 && !memcmp(b,"abc",3) && readlineb(&r,b,4)==3 && !memcmp(b,"de\n",3),"long line chunks")) return 1;
    if (!require(readlineb(&r,b,1)==-1 && errno==EINVAL, "capacity boundary")) return 1;
    printf("long-line fragments=abc|de\\n capacity1=EINVAL\n");

    printf("host-pipe binary=6 EOF=observed\n");
    return 0;

static int copy(int lines, const char *filename) {
    int in = STDIN_FILENO, out = STDOUT_FILENO;
    if (filename) {
        int fd = open(filename,O_RDONLY);
        if (fd < 0) { perror("open"); return 1; }
        if (fd != in) {
            if (dup2(fd,in)<0) { perror("dup2"); close(fd); return 1; }
            if (close(fd)<0) { perror("close"); return 1; }
        }
    }
    Rio r = {fd_read,&in,0,0,{0}};
    unsigned char buf[8192];
    ssize_t n;
    while ((n = lines ? readlineb(&r,buf,sizeof buf) : readn(buffered_read,&r,buf,sizeof buf)) > 0)
        if (writen(fd_write,&out,buf,(size_t)n)<0) { perror("write"); return 1; }
    if (n<0) { perror("read"); return 1; }
    return 0;
}

#!/usr/bin/env python3
"""Byte-count reference model; injected errors are not OS signal execution."""
import errno


class Script:
    def __init__(self, data=b"", steps=()):
        self.data, self.steps = data, iter(steps)
        self.offset = self.calls = 0
        self.output = bytearray()

    def limit(self, n):
        self.calls += 1
        k = next(self.steps, 64)
        if k < 0:
            raise OSError(-k, "injected")
        return min(n, k)

    def read(self, n):
        k = min(self.limit(n), len(self.data) - self.offset)
        b = self.data[self.offset:self.offset + k]
        self.offset += k
        return b

    def write(self, b):
        n = self.limit(len(b))
        self.output.extend(b[:n])
        return n


def readn(get, n):
    result = bytearray()
    while len(result) < n:
        try:
            b = get(n - len(result))
        except InterruptedError:
            continue
        if not b:
            break
        result.extend(b)
    return bytes(result)


def writen(put, data):
    done = 0
    while done < len(data):
        try:
            n = put(data[done:])
        except InterruptedError:
            continue
        if n == 0:
            raise OSError(errno.EIO, "zero write")
        done += n
    return done


class Rio:
    def __init__(self, get):
        self.get, self.buffer = get, b""

    def read(self, n):
        if n == 0:
            return b""
        while not self.buffer:
            try:
                self.buffer = self.get(8)
            except InterruptedError:
                continue
            if not self.buffer:
                return b""
        b, self.buffer = self.buffer[:n], self.buffer[n:]
        return b

    def line(self, capacity):
        if capacity < 2:
            raise OSError(errno.EINVAL, "capacity")
        result = bytearray()
        while len(result) < capacity - 1:
            b = self.read(1)
            if not b:
                break
            result.extend(b)
            if b == b"\n":
                break
        return bytes(result)


def check(value, message):
    if not value:
        raise RuntimeError(message)


def main():
    data = b"A\0B\nCD"
    steps = (-errno.EINTR, 2, 1, 3)
    s = Script(data, steps)
    check(readn(s.read, 9) == data and s.calls == 5, "short read")
    print("readn short+EINTR+EOF bytes=6 calls=5")
    check(readn(s.read, 0) == b"" and s.calls == 5, "zero read")
    w = Script(steps=steps)
    check(writen(w.write, data) == 6 and w.output == data and w.calls == 4, "write")
    print("writen short+EINTR bytes=6 calls=4")
    s = Script(data, (2, -errno.EIO))
    try:
        readn(s.read, 6)
        raise RuntimeError("expected EIO")
    except OSError as e:
        check(e.errno == errno.EIO and s.offset == 2, "partial error")

        try:
            action()
            raise RuntimeError("expected failure")
        except OSError as e:
            check(e.errno == expected, "wrong error")
    print("errors partial=2 zero-write=EIO nonblocking=EAGAIN")

    finally:

原创自测 1 · 预取以后为什么裸读跳过数据

题目

缓冲容量 8，文件字节是 hi\n00X\nYZQ，其中 00 表示一个 NUL。readlineb 先返回 hi∖n，此时内核已成功读入前 8 字节。若接着裸 read(fd,buf,4)，得到什么？怎样才能按顺序拿到接下来的四字节？

解答

内核位置为 8，所以裸 read 只能拿到第九字节 Q；Rio 中还保留 NUL、X、LF、Y、Z 五字节。用同一 Rio 的 readnb(4)，才按顺序得到 NUL、X、LF、Y，并留 Z 给后续读取。问题是两层位置不一致，换一个 dup 出来的整数仍共享同一内核位置，不能消除它。

原创自测 2 · 失败以后重发整块是否安全

题目

writen 要发送 ABCDEF，第一次 write 成功 2，第二次返回 −1/EIO。调用者看到 −1 后立即从 A 重发全部六字节，是否能保证最终外部数据恰好为 ABCDEF？

解答

不能。第一次成功意味着 AB 已产生副作用；重发可能得到 ABABCDEF，也可能再次失败。函数返回 −1 不承诺回滚此前传输。应用若需要恢复或去重，必须设计记录编号、已确认进度或事务协议；仅靠重新调用字节复制函数不够。

原创自测 3 · 关闭标准输入的边界

题目

程序原先关闭了 fd0，只保留 1 和 2。它 open 输入文件取得 fd0，然后执行 dup2(fd,0); close(fd);，再开始 read(0)。会怎样？

解答

原题（中文翻译）

来源：印刷 944 页 / PDF 945 页

磁盘文件 foobar.txt 由六个 ASCII 字符 foobar 组成。下面程序输出什么？

#include "csapp.h"

{

    char c;
    fd1 = Open("foobar.txt", O_RDONLY, 0);

10.3 · fork 之后先子后父读取

原题（中文翻译）

来源：印刷 944—945 页 / PDF 945—946 页

仍假定 foobar.txt 含六个 ASCII 字符 foobar。下面程序输出什么？

#include "csapp.h"
int main()
{
    int fd;
    char c;
    fd = Open("foobar.txt", O_RDONLY, 0);
    if (Fork() == 0) {
        Read(fd, &c, 1);
        exit(0);
    }
    Wait(NULL);
    Read(fd, &c, 1);
    printf("c = %c\n", c);
    exit(0);
}

解答

输出 c = o。fork 复制描述符表，但父子的 fd 都指向原打开文件描述。子读第 0 字节 f，共享偏移变为 1；子退出，父的 Wait 才返回；父再读取第 1 字节 o，偏移变为 2。父子的局部变量 c 则处于私有地址空间，子进程赋给自己的 c 并不会直接写父亲的 c。

因此“共享的是什么”有两个答案：共享内核打开状态，不共享普通 C 局部对象。wait 提供本题的顺序；删除它后就不能保证父打印 o。宿主程序检查孩子正常退出，再读取并核对 o。

把两类状态并列跟踪：子读完后，孩子的 c 是 f，父的 c 仍是父原来的局部值，而共同打开描述的偏移已经是 1。父下一次 read 并不是“拿到孩子的 c”，而是自己去共享文件位置 1 读出 o，再写进自己的 c。这条路径同时解释了私有内存与共享偏移为何能共存。

10.5 · 复制表项同时接过已有偏移

原题（中文翻译）

来源：印刷 946 页 / PDF 947 页

#include "csapp.h"

{

    char c;

输出 c = o。两次 open 起初偏移都是 0；Read(fd2) 得 f 后，fd2 的偏移为 1。Dup2 把 fd1 原来的表项替换成对 fd2 打开状态的引用，因此 fd1 下一次读取也从 1 开始，得到 o。它不会重新打开路径，不会复制一个独立的 k=1，也不会重置到 0。

10.7 · 按 MAXBUF 字节复制标准输入

原题（中文翻译）

来源：印刷 950 页 / PDF 951 页

修改图 10.5 的 cpfile，使用 Rio 每次最多 MAXBUF 字节，将标准输入复制到标准输出。原程序如下：

#include "csapp.h"

{

    rio_t rio;
    char buf[MAXLINE];

    Rio_readinitb(&rio, STDIN_FILENO);

解答

#include "csapp.h"
int main(void)
{
    ssize_t n;
    rio_t rio;
    char buf[MAXBUF];
    Rio_readinitb(&rio, STDIN_FILENO);
    while ((n = Rio_readnb(&rio, buf, sizeof buf)) > 0)
        Rio_writen(STDOUT_FILENO, buf, (size_t)n);
    return 0;
}

保持同一 rio_t，用 Rio_readnb 替换读行，缓冲改成 MAXBUF。每轮按实际返回 n 写出，最后一轮不足 MAXBUF 也必须写；若改成只有 n==MAXBUF 才写，就丢失尾部。字节中出现 0 或 0a 不改变这个循环。教材大写包装在错误时终止；若改用返回 −1 的小写函数，还要在循环后检查 n<0 并报告。

例如输入长 8193B，缓冲为 8192B：第一轮返回 8192 并写出这一整块；第二轮读到末尾前最后 1B，返回 1，仍须写出；第三轮才返回 0 结束。循环条件 n>0 保留了尾块，写入长度用 n 保证不把缓冲里上一轮留下的旧字节重新输出。

原题（中文翻译）

来源：印刷 951 页 / PDF 952 页

修改图 10.5 的 cpfile，使其接受一个可选命令行参数 infile。给出 infile 时从该文件复制到标准输出，否则仍从标准输入复制。两个分支必须使用原来的复制循环（原图第 9—11 行）。只允许插入代码，不允许改动原代码。图 10.5 为：

#include "csapp.h"
int main(int argc, char **argv)
{
    int n;
    rio_t rio;
    char buf[MAXLINE];

    Rio_readinitb(&rio, STDIN_FILENO);
    while((n = Rio_readlineb(&rio, buf, MAXLINE)) != 0)
        Rio_writen(STDOUT_FILENO, buf, n);
}

解答

在 Rio_readinitb 之前插入参数检查和描述符重定向。下面完整主函数保留原声明及原来的三行复制循环：

int main(int argc, char **argv)
{
    int n;
    rio_t rio;
    char buf[MAXLINE];

    /* 新插入的部分 */
    if (argc > 2) {
        fprintf(stderr, "usage: cpfile [infile]\n");
        return 2;
    }
    if (argc == 2) {
        int fd = Open(argv[1], O_RDONLY, 0);
        if (fd != STDIN_FILENO) {
            Dup2(fd, STDIN_FILENO);
            Close(fd);
        }
    }
    /* 原有代码，保持不变 */
    Rio_readinitb(&rio, STDIN_FILENO);
    while((n = Rio_readlineb(&rio, buf, MAXLINE)) != 0)
        Rio_writen(STDOUT_FILENO, buf, n);
}

无参数时不改变 0；有文件时把 0 的表项改指向文件，后面的 Rio 初始化和循环无需知道数据来自哪里。重定向一定在 Rio_readinitb/首次读取之前完成，避免遗留旧输入缓冲。fd==0 时不能关闭它，这个分支覆盖初始标准输入关闭的边界。

ch10_cpfile.c 给出全部标准库头文件、Rio 实现复用及大写出错包装；从根目录编译时同目录的 ch10_rio.c 也需存在。CLI 验证分别覆盖 stdin 和文件参数、无换行尾部、长行、空文件，以及 open 正好返回 0；比较完整输出字节，不只比较显示文本。

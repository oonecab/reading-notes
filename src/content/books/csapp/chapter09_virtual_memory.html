9.1 · CPU 给出的地址为何还要翻译Physical and Virtual Addressing

来源：印刷 839—840 页 / PDF 840—841 页

前两章已经知道，可执行文件包含代码与数据，进程也各有自己的执行现场。现在追问一个具体问题：两个进程都执行对地址 0x1004 的 load，为什么不会必然读到同一个字节？答案在 MMU：CPU 给出的虚拟地址先用“当前进程的页表”解释，才变成发往物理存储系统的地址。地址数值之外，还存在地址空间这个上下文。

在原书图 9.2 的例子中，虚拟地址 4100 翻译成物理地址 4。若页大小为 4096B，这可以理解为虚拟第 1 页映射到物理第 0 页，页内偏移仍为 4。页表由内核维护，MMU 按它查找；程序员既不必在每次 load 前手写换算，也不能凭一个物理地址数值在用户态绕过权限。

原文伴读 · 翻译是一道运行时映射

The task of converting a virtual address to a physical one is known as address translation.

中文：把虚拟地址转换成物理地址的任务称为地址翻译。

这不是链接时把符号换成地址的重定位。链接器确定程序中的虚拟布局，MMU 在每次实际访存时落实到当前物理驻留位置。

来源：印刷 840 页 / PDF 841 页

阅读注解
视角

地址是名字

两个进程的数值相同的虚拟地址，可以指向不同物理页；同一物理页也可有多个虚拟名字。

边界

MMU 不认识 C 对象

MMU 检查页权限；数组边界、对象生存期和 malloc 块边界由语言与程序负责。

9.2 · 把地址空间与实际存储容量分开Address Spaces

来源：印刷 840—841 页 / PDF 841—842 页

一个线性地址空间是连续非负整数的集合。n 位虚拟地址给出 0 到 2n−1 共 2n 个名字；m 位物理地址最多能表达 2m 个物理字节地址。地址的可表示范围、进程已映射范围和当前驻留 DRAM 的范围是三件事：64 位指针既不保证机器实现 64 位虚址，也不意味着每个可表示地址都已分配。

N=2n,M=2m,P=2p

下面统一按字节编址。若 n=14、m=12、p=6，虚址空间为16 KiB、物理地址空间为4 KiB、页为64B，因而有256个虚拟页和64个物理帧。一页中的第23个字节在两边都偏移23；页表只需决定整页住在哪个帧。一个物理字节可以有多个虚拟名字，例如两个进程共享一页库代码。

阅读注解
单位

数地址还是数位

字节编址下，2n 个地址对应 2n 字节；最大地址是 2n−1。

推导

页号数量

2n 个字节每 2p 个划一页，页号只需要 n−p 位。

9.3 · 从驻留、缺页到工作集VM as a Tool for Caching

来源：印刷 841—847 页 / PDF 842—848 页

原文伴读 · 缺页的缓存解释

In virtual memory parlance, a DRAM cache miss is known as a page fault.

中文：在虚拟内存的术语中，DRAM缓存未命中称为缺页。

这句话解释本节需求分页模型。硬件页异常还可表达权限冲突，后文会区分“异常原因”与“内核最终处理结果”。

来源：印刷 844 页 / PDF 845 页

9.3.1 · 把缺页代价纳入缓存设计DRAM Cache Organization

来源：印刷 842 页 / PDF 843 页

把 DRAM 看成“更慢后备存储的缓存”有助于理解虚存，但两级缓存的代价差距很大：从磁盘取一页比在 SRAM 层级移动一行慢得多。因此页通常较大，物理帧可放任意虚拟页（全相联的放置自由），替换策略由软件决定，并且采用写回以避免每次 store 都写磁盘。页大能摊销 I/O，代价是读入未用字节、内部浪费以及更粗的保护粒度。

“整个虚拟空间是磁盘数组”是本节概念模型。未分配页没有内容，文件页可从原文件读取，匿名页可首次清零；实际系统不会为每个可能虚址预先分配同等大小的磁盘位置。

9.3.2 · PTE 记录的是页的状态Page Tables

来源：印刷 842 页 / PDF 843 页

原书图9.4有8个虚拟页、4个物理页。VP1、VP2、VP4、VP7驻留，VP3和VP6已分配但不驻留，VP0和VP5未分配。简化 PTE 的 valid=1 表示地址字段为物理帧；valid=0时，后备位置与空值区分已分配和未分配。真实 PTE 位域与后备位置管理依体系结构及内核而定，不能把图中的“磁盘地址字段”机械视作每台机器的硬件字段。

状态抽象 PTE本次访问需要什么
未分配valid=0，无后备对象内核判断是否有合法区域；无则拒绝
已分配、未驻留valid=0，有后备来源取文件页、换入或按需清零
驻留valid=1，PPN 有效权限允许后拼接物理地址

9.3.3 · 页命中只说明数据已经驻留Page Hits

来源：印刷 844 页 / PDF 845 页

读 VP2 时，MMU 定位 PTE2，valid=1，得到 PP1。以64B页和偏移7为例，物理地址为1×64+7=71。此时“页命中”还没回答L1是否命中；所需字节可能仍要从 DRAM 进入处理器缓存。TLB命中也只说明翻译有缓存，不能直接推得数据就在L1。

9.3.4 · 先恢复映射，再重启同一条指令Page Faults

来源：印刷 844 页 / PDF 845 页

读尚未驻留的VP3，MMU不能构造可用物理地址，于是触发异常。原书选择PP3中的VP4为牺牲页：若它脏，先保存修改；把VP4的PTE改成不驻留，再把VP3装入PP3，更新PTE，最后返回并重新执行导致异常的指令。指令第二次访问才走命中路径。被替换页相关的缓存翻译也需同步失效，否则旧VPN仍可能指向已改装的帧。

并非每次缺页都要找牺牲页或进行磁盘 I/O：有空闲帧时直接使用；匿名首次触摸可以清零；COW可能复制内存。这里的“换出再换入”是需要替换的后备存储例子。

9.3.5 · 分配虚拟页与分配物理帧分两步Allocating Pages

来源：印刷 846 页 / PDF 847 页

在图9.8里，系统为原先未分配的VP5建立后备来源，把PTE指向它，并不立即让VP5驻留。这样，一个进程可以先取得很大的合法虚拟区域，再随实际访问逐页获得物理帧。malloc成功也不等价于所有返回范围已驻留；分配器还可能从此前已经获得的堆中切块，完全不用向内核再申请页。

9.3.6 · 性能取决于活跃页能否留在内存Locality to the Rescue Again

来源：印刷 846 页 / PDF 847 页

程序在一段时间内反复触及的页形成工作集。顺序处理一个大型文件时，完整文件可大于DRAM，当前窗口仍可能很小；反之，在大量页间循环只读一个字节，工作集会很大。若多个进程活跃页总量超过可用帧，刚换入的页很快被换出，再次访问又缺页，形成 thrashing（抖动）。

例如只有3个帧而循环访问4个页 A、B、C、D，LRU在暖机后仍可能每次都缺页；把计算分成“多次处理 A、B、C，再处理 D”的阶段，可让时间局部性真正发挥作用。缓存友好的访问不仅节省 cache line，也可能节省昂贵的页级迁移。

阅读注解
判断

缺页不等于读磁盘

首次匿名页可能只需清零；COW 可能只需复制已有物理页。

局部性

工作集必须装得下

局部性使活跃页数小于整个地址空间；活跃页仍超过内存时会抖动。

9.4 · 连续空间是页表提供的服务VM as a Tool for Memory Management

来源：印刷 847—848 页 / PDF 848—849 页

每个进程的页表把自己的虚拟布局映射到物理帧。它同时解决四件事：分配连续虚拟区域时不必寻找连续物理空洞；多个进程可以共享同一份只读代码；程序装载时只需建立映射并按需取页；相同代码可在各进程的统一虚拟位置运行而落在不同物理帧。

进程虚拟页0虚拟页1程序眼中的关系
A物理帧8物理帧2两页连续
B物理帧5物理帧2第1页与A共享

上表中A的两页物理上不连续，却能支持一个跨页数组；A/B第1页也可在不同虚拟地址出现，只需各自PTE指向帧2。允许共享的是页映射和权限的组合。可写全局变量通常需要进程私有语义，不能因为代码来自同一个可执行文件就把所有数据直接共享。

这也给第7章的“装入共享库”和第8章的 execve 补上了机制：加载器主要建立对象与虚拟区域的关系，程序真的触摸代码或数据时再满足驻留需求。ASLR 改变虚拟布局也不改变“页表决定实际物理位置”这个层次。

阅读注解
链接

连续虚址无需连续实址

重定位和装载可以使用统一虚址，页表把各页映到任意可用帧。

共享

一份代码，多份页表

库代码可在物理内存只存一份，进程各有自己的可写私有状态。

9.5 · 同一次翻译同时回答能否访问VM as a Tool for Memory Protection

来源：印刷 848—849 页 / PDF 849—850 页

仅有独立地址空间还不够。一个进程也不能随意改自己的代码，更不能访问内核的私有页。因此PTE除了帧号，还带用户/内核、可写、可执行等权限属性。访问是否合法由指令种类、当前权限级别与映射权限共同决定。原书简图使用 SUP、READ、WRITE 三个位；它是通用解释，不是逐位复制 x86 PTE。

访问区域语义应有的处理
合法区域中尚未驻留的可读页读允许准备物理页并重试
对真正只读的代码页写入写禁止拒绝访问，通常向进程送SIGSEGV
对私有COW区域写入区域可写，当前PTE暂只读复制页、改映射与权限后重试
落在未映射空洞没有合法区域拒绝访问

原书校注。印刷849页把页权限违反称为“general protection fault”。对x86分页而言，页不在与页级权限违反都可产生 #PF，错误码的P位区分“不在”与“保护违反”；#GP是另一类异常。故本章把 protection fault 用作保护冲突的概念名称，不把它统一等同于向量13。依据 Intel SDM Vol.3A §4.7、§6.15。

另一层边界也容易被忽略：同一可写页里两个malloc块之间越界，硬件可能完全不报错，因为页权限仍允许写。页保护不能代替对象边界和生存期检查。

阅读注解
分层

硬件异常与进程信号

#PF 是 CPU 异常；SIGSEGV 是内核处理后对进程采取的动作，两者并非一一对应。

安全

权限随访问检查

TLB 还缓存权限；切换或更新映射时需保持 TLB 与页表一致。

9.6 · 一条访存从虚址走到返回字节Address Translation

来源：印刷 849—861 页 / PDF 850—862 页

先把所有运算固定下来：VPN=VA向右移p位，VPO为VA低p位，若PTE有效则PA=PPN×2p+VPO。对单级页表，PTE本身的物理地址为PTBR+VPN×PTE大小；这一次读取页表与随后读取目标数据是两次逻辑访问，实际可由缓存合并或加速。

VA=VPN·2p+VPO,PA=PPN·2p+VPO

页号被换掉，页内位置为什么保留

分页按整页建立对应关系：虚拟页里的第 0 个字节对应物理帧里的第 0 个字节，第 23 个对应第 23 个。以 64B 页为例，虚址 2×64+23=151 拆成 VPN=2、VPO=23；若页表把 VPN=2 映到 PPN=5，实址就是 5×64+23=343。只换页号而保留低 6 位，恰好保持了页内各字节的相对顺序；并不是页表逐个存了 64 条字节映射。

查页表的地址也要和目标地址分开：若单级页表基址为 0x1000、每项 8B，VPN=2 的项放在 0x1010。先从这里读出 PPN=5，再去实址 343 读用户所要的字节；0x1010 是“保存翻译记录的位置”，不是用户数据的位置。

9.6.1 · 页表读取同样可以命中缓存Integrating Caches and VM

来源：印刷 853 页 / PDF 854 页

物理寻址的cache把物理地址分成tag、set、offset。不同进程虚址相同但实址不同，不会误共享一条缓存线；多个虚址映到同一物理页，则自然共享该页的缓存内容。PTE也存在内存，所以MMU读PTE时可命中层级缓存；“TLB miss要读内存”不能直接解释成“必定访问DRAM”。

9.6.2 · 把页号映射缓存起来Speeding Up Address Translation with a TLB

来源：印刷 853 页 / PDF 854 页

TLB保存近期翻译和权限。设TLB有T个组，用VPN的低t=log2T位选组，其余高位为TLB tag；在组内所有路中找有效且tag相同的项。只要命中，就不用遍历页表；未命中先查页表，如果页已驻留，补充翻译即可，根本不发生需求缺页。上下文切换与映射修改必须避免旧翻译跨进程或跨版本误用，实际系统可使用地址空间标识及适当失效操作。

本章小机器16项、4路，因此只有4组：TLBI占2位，不是4位。VA低6位是页内偏移，TLBI取的是VA第7—6位。若把VA低2位送进TLB索引，会让同一页的不同字节误走不同组。

9.6.3 · 按需创建页表的树枝Multi-Level Page Tables

来源：印刷 855 页 / PDF 856 页

单级页表为每个可能VPN留槽，即使进程只用很小区域也占空间。32位虚址、4 KiB页、4B PTE时有220项，需4 MiB页表。改成10位一级索引、10位二级索引、12位偏移：一级表4 KiB，每个二级表4 KiB，只有用到对应4 MiB虚拟范围才建立二级表。若只映射一个4 KiB页，页表开销从4 MiB降为8 KiB；若整个空间都映射，表层级反而增加一级的4 KiB。原书图9.17把前2048页用作代码和数据，另在编号8（从0起算，即第9个）的4 MiB区域末页放栈：VP 9215=8×1024+1023，因此只需1张一级表加3张二级表，共16 KiB；中间未分配的大片区域不必建立叶子表。

VA=0x12345678的字段计算结果
一级索引VA >> 220x048 = 72
二级索引(VA>>12) & 0x3ff0x345 = 837
页内偏移VA & 0xfff0x678

设一级表物理基址0x1000，条目宽4B：读0x1000+72×4=0x1120；它指向二级表0x9000。再读0x9000+837×4=0x9d14；叶子项给PPN=0xabc，于是最终PA=0xabc678。两次页表读取都使用物理地址；不能把“二级表所在物理地址”再当待翻译的用户地址，陷入无限递归。

k级页表最坏要先读k个PTE再取目标数据，但实际TLB和页表遍历缓存能省掉大量工作。这里仅计逻辑依赖，不把它直接换成k+1次DRAM延迟。

9.8.1 · 共享与私有写时复制Shared Objects Revisited

来源：印刷 869 页 / PDF 870 页

MAP_SHARED映射让写入反映到共享对象；不同进程映同一对象的相应页，可以共享物理帧。MAP_PRIVATE允许各自修改而不把修改写回原对象。实现私有语义无需立即复制整个对象：最初PTE指同一物理页并清写权限；某进程第一次写入时，内核分配新帧、复制原页、改该进程PTE为可写，然后重试store。

若帧7中原值为10，子进程写20后，子读到20、父仍读到10；共享映射则应看到共享对象上的更新。COW是页粒度，改1B也可能复制整页。共享可见性并不自动提供互斥、原子复合操作或立即落盘，跨进程协议仍需同步。

COW 的一次写入可分成三次观察：写之前父子页表都指向帧 7，其中值为 10；孩子触发写保护异常时，目标 store 尚未成功，原帧仍为 10；内核复制到帧 9 并只修改孩子映射后，重试 store 才把帧 9 的值写成 20。父的映射仍指帧 7，所以父读 10。异常是用来兑现“允许写但写入应私有”的语义，不能仅凭 PTE 当前只读就判断必须终止。

9.8.2 · 复制地址空间语义，延迟复制内容The fork Function Revisited

来源：印刷 872 页 / PDF 873 页

fork创建新的进程身份与内核管理结构，父子拥有各自页表和独立私有地址空间的语义。私有可写映射可通过COW共享物理内容：父写父的副本，子写子的副本。已明确建立的共享映射继续共享，不能把书中的“把每页都标成只读”概括句理解为所有映射无条件转成私有。

这解释了fork后立即exec通常无需复制整个父进程物理工作集：子尚未写过的私有页始终可共享，exec替换映射时即可释放子对它们的引用。复制页表仍有成本，COW也需要引用和权限管理。

9.9.1 · 先把申请、所有权与释放契约说清The malloc and free Functions

来源：印刷 876 页 / PDF 877 页

malloc(n)成功返回至少n字节的可用块，内容未初始化；失败返回NULL。calloc提供零字节初始化，realloc可改变大小而且可能搬移。free只接受NULL或当前仍分配、由匹配分配器返回的块起点。重复free、释放中间指针以及继续使用已释放块都违反契约。free返回不表示内核一定收回对应物理页；分配器可把它保留供后续请求复用。

原书例子用4B word、8B double word，并假设8B对齐；现实C分配接口需要满足相应标准的基本对齐要求。C11本身不保证失败时设置errno，书中errno描述属于它采用的Unix环境。realloc应先存临时指针：成功才替换旧指针，否则旧分配仍有效（零大小另按接口版本约定处理）。

9.9.2 · 把输入长度变成经过检查的字节数Why Dynamic Memory Allocation?

来源：印刷 879 页 / PDF 880 页

若只知道运行时n，固定上限数组既浪费又会拒绝本可处理的输入。动态分配把容量与实际请求联系起来，但“n×元素大小”必须先检查溢出，负输入也必须在转size_t前拒绝。分配成功后逐个读入仍需检查输入转换，并在退出路径释放。

if (n > SIZE_MAX / sizeof *array) { /* reject */ }
array = malloc(n * sizeof *array);
if (n != 0 && array == NULL) { /* allocation failed */ }
/* Initialize and use array[0] ... array[n-1]. */
free(array);

这里是说明性片段，n已是检查过的非负size_t；它没有把一次malloc失败当成所有程序都必须崩溃的唯一处理方法。零长度是否申请由调用者显式约定。

9.9.4 · 把块内浪费与块间空洞分开Fragmentation

来源：印刷 882 页 / PDF 883 页

申请9B、头4B、按8B对齐形成16B块，则块中7B不是用户载荷，这是内部碎片（含该计量口径下的管理开销）。若空闲块为24、24B，中间隔着活块，申请需要40B块时，即使空闲总量48B也不能满足，这是外部碎片。只统计空闲字节总和不能判断一次请求能否成功。

9.9.13 · 只遍历空闲块，需要付出指针空间Explicit Free Lists

9.9.14 · 用大小类缩短搜索，再看是否允许合并Segregated Free Lists

来源：印刷 899 页 / PDF 900 页

简单分离存储为一个大小类保留固定尺寸块，不分裂也不合并，分配/释放可非常快。但若某阶段大量用16B类，下一阶段改用32B类，前一类空闲空间可能再也不能满足新的请求，外部碎片严重。分离适配则允许类内不同大小，找到块后可分裂，释放后可合并并重新放入合适类别，能更灵活地利用空洞。

伙伴系统把块大小约束为2的幂。以相对arena基址的偏移o表示，大小2k块的伙伴为o XOR 2k；只有同大小且空闲的伙伴才能合并。请求刚超过2k−1时需要2k块，浪费接近已分配块的一半；可用空间也可能被仍占用的伙伴分隔，所以它仍可能有外部碎片。

9.10 · 让引用图决定何时释放Garbage Collection

来源：印刷 901—906 页 / PDF 902—907 页

9.10.1 · 垃圾的可执行判据是不可达Garbage Collector Basics

来源：印刷 902 页 / PDF 903 页

把分配块看成图节点，块内指针形成边；寄存器、栈和全局变量中的指针是根。从任何根能沿指针到达的块都必须保留。程序今后实际上不会使用的块，若仍被根引用，追踪式收集器也通常不能推断其“意图上已经无用”。因此可达性是一个保守且可计算的存活判据。

原书例子根指向4，4指向3和6，3再指向1，于是1、3、4、6存活，2、5是垃圾。若2和5互相指向但没有根到它们的路径，仍然都是垃圾；这正是追踪式回收能处理不可达环的原因。

9.10.2 · 先遍历引用图，再遍历堆Mark&Sweep Garbage Collectors

来源：印刷 903 页 / PDF 904 页

mark阶段从根出发：先检查输入能否解析成活块，再检查是否已经标记，首次到达时先设标记再递归/入栈扫描指针字段。先标再扩展防止遇环无限递归。sweep阶段顺序走所有块，把未标记且已分配者释放，把已标记者的标记清除，为下一轮做准备。

work = list(roots)
marked = set()
while work:
    node = work.pop()
    if node in graph and node not in marked:
        marked.add(node)
        work.extend(graph[node])
garbage = set(graph) - marked

上面是有精确信息的图模型，graph显式给出每条引用，不扫描真实C进程。根={4}、边4→{3,6}、3→{1}、2↔5时，marked={1,3,4,6}，garbage={2,5}。真实sweep调用合并式free时要保存或重新计算遍历的下一个有效块头，不能沿被合并吞掉的旧边界继续。

按图一步步做 mark：根 4 入栈，弹出后标记 4 并加入 3、6；处理 3 时再加入 1；这几个节点处理完，待办栈为空，遍历结束。2 与 5 虽然互相指向，却从未有一条已到达的边把它们加入待办栈，所以不会仅靠相互引用获得存活资格。“被别的块指着”与“能从根走到”是不同的条件。

9.10.3 · 无法区分整数与指针时宁可多保留Conservative Mark&Sweep for C Programs

来源：印刷 905 页 / PDF 906 页

C内存通常不携带足够的运行时类型标签。一串比特若恰好落在某活块内部，保守收集器会把它当潜在指针，连该块一起保留；它可能实际只是整数。原书用按地址排序的平衡树找包含地址的块，支持内部指针，而不是只接受精确块起点。

可靠性以能找到真实根和可识别的指针表示为前提；任意把指针隐藏在压缩、异或或外部存储中，不能仍无条件承诺保守扫描会识别它。误认整数的代价是漏收垃圾，漏认真实指针则会释放活对象。移动对象还会改变未知指针，因此本节选择不移动的mark&sweep。

阅读注解
图论

环不妨碍追踪式回收

不可达的相互引用环没有根路径，mark 不会到达它们，因此 sweep 可以回收。

保守

误留与误删不对称

看似指针的整数导致误留垃圾；漏掉真实指针会误删活对象，后者破坏正确性。

9.11 · 从页权限回到对象生命周期Common Memory-Related Bugs in C Programs

来源：印刷 906—911 页 / PDF 907—912 页

9.11.1 · 地址错误不一定立刻崩溃Dereferencing Bad Pointers

来源：印刷 906 页 / PDF 907 页

scanf("%d", &val)需要对象地址；误写scanf("%d", val)会把值错当指针参数。编译器的格式告警应在运行前阻止这种调用。即使某个错误地址恰好位于可写页，硬件也无法知道它不是目标对象，程序可能覆盖无关内容后很久才失败。此处坏式仅用来解释错误，不作为实验运行。

9.11.2 · malloc不提供累加器初值Reading Uninitialized Memory

来源：印刷 907 页 / PDF 908 页

矩阵向量乘法中，新分配y后直接y[i] += A[i][j] * x[j]会读取未初始化值。应在每行循环前设置y[i]=0，或使用合适的初始化分配方法。bss对象的零初始化不能推广到malloc块；“调试时碰巧是零”不构成契约。计算本身还需保证有符号乘加不溢出。

9.11.3 · 输入边界必须先于写入Allowing Stack Buffer Overflows

来源：印刷 907 页 / PDF 908 页

原例64B栈数组调用gets，长度不受控制。使用fgets(buf, sizeof buf, stdin)限制写入后仍需检查返回值，并决定如何处理没有读到换行的长行；截断策略要由业务决定。gets已不在C11中，不能为了重现旧例去引入它。动态分配也不会自动防止越界，传给读取函数的容量仍必须正确。

9.11.4 · sizeof跟随目标对象Assuming That Pointers and the Objects They Point to Are the Same Size

来源：印刷 908 页 / PDF 909 页

申请n个int指针却写malloc(n * sizeof(int))，在8B指针/4B int环境只申请了一半字节。稳妥写法是int **a = malloc(n * sizeof *a)；每行再按m * sizeof *a[i]申请，并检查每一步失败与乘法上界。逐行分配失败时要释放此前成功的行和外层指针表。

9.11.5 · 数组合法下标是半开区间Making Off-by-One Errors

来源：印刷 908 页 / PDF 909 页

n个元素合法下标为0到n−1。原例循环i <= n写了n+1个指针，正好多出的那个可能破坏后块头部。字符串还必须把结尾零计入容量。边界测试至少涵盖n=0、n=1及恰好容量，且不能先构造越界指针再期望硬件替自己检查。

9.11.6 · 把语法树写出来Referencing a Pointer Instead of the Object It Points To

来源：印刷 909 页 / PDF 910 页

原例意图递减所指整数，却写*size--。正确语法分组为*(size--)，递减的是指针；需要的是(*size)--。原书同页说两个运算符优先级相同，这个理由不准确：后缀--属于postfix-expression，比一元解引用*绑定更紧。结论正确，理由应按 C11 N1570 §6.5.2、§6.5.3 的语法修正。

在int values[2]={7,9}; int *q=&values[1];这一合法数组范围内，单独执行q--;后q指第0项但两元素没变；执行(*q)--;才会把第0项由7变6。这比通过无效指针运行原坏例更能说明机制。

9.11.7 · 指针加法已经带着元素尺寸Misunderstanding Pointer Arithmetic

来源：印刷 909 页 / PDF 910 页

int指针p加1向后走一个int，通常4B；p += sizeof(int)则向后走sizeof(int)个int，通常16B。原书搜索例子应使用p++，但零值哨兵还要求数组确实包含终止零。更一般的接口同时传长度n，用i < n限界，并明确未找到时返回NULL。

9.11.8 · 地址仍映射不表示对象仍存活Referencing Nonexistent Variables

来源：印刷 910 页 / PDF 911 页

返回自动局部变量地址后，该变量的生命周期已结束。后续函数可能复用同一段栈空间；即使页仍映射，解引用也不合法。应返回值本身，或者让调用方提供存储；需要延长生存期时使用具有明确所有权的动态对象。static局部变量也可延长存储期，但会引入共享状态与并发语义，不能无条件替换。

9.11.9 · free改变的是使用权Referencing Data in Free Heap Blocks

来源：印刷 910 页 / PDF 911 页

释放x后再分配y，分配器完全可能让y复用x的地址。此时y[i] = x[i]++不是某种可移植的复制技巧，x已失效且两区域可能重叠。正确顺序是在x仍存活时分配并复制到y，成功后再free(x)。把单个指针置NULL只能防它再次误用，无法自动清除所有别名。

若 p 和 q 原来都指向同一活块，执行 free(p); p=NULL; 只修改变量 p。q 仍保存旧地址，却已经没有解引用该块的权利；之后分配器把地址给另一个对象，也不会自动把 q 变成新对象的合法所有者。管理释放需要追踪对象及其所有别名，而不只是把调用 free 的那个变量清零。

9.11.10 · 每条退出路径都要有所有权归宿Introducing Memory Leaks

来源：印刷 911 页 / PDF 912 页

函数malloc后丢掉唯一指针且不free，会留下无法再访问的活分配块。短命程序可能由进程退出回收全部地址空间，长期服务则会累积。资源管理应说明“谁创建、谁接管、谁释放”，把错误返回与提前结束也纳入同一规则。泄漏检测报告是一种实际路径证据，有限运行未发现泄漏不等于所有路径都正确。

(c) 只在内存耗尽时收集。
(d) 不释放组成循环链表的块。

解答与推导

答案依次为1(a)、2(d)、3(b)。伙伴块取2的幂，请求略高于块大小一半时，浪费占已分配块的比例趋近50%；若以请求字节为分母则趋近100%，两个比例不能混淆。best fit选最小的足够大块，大小递增时first fit恰好做到这一点。

边界标记通过物理相邻边界找前后块，不要求空闲链表地址有序；伙伴块也可被活伙伴隔开而产生外部碎片。保守回收涉及指针识别精度，与何时触发GC、何时合并无关；不可达环仍可被mark&sweep回收。

/* Exercise 9.20, Darwin-specific, single-threaded reserved-heap comparison.
 * H counts block-storage regions, including free space and in-region metadata.
 * H excludes out-of-region controllers for both backends, and is not RSS.
 * A private libc scalable zone isolates the workload from runtime allocations;
 * this does not measure default malloc's nano/xzone dispatch policy.
 * Compile without ASan: intercepting libc would change the measured backend. */
#define ARENA_ALIGNMENT 16384
#define main allocator_example_main
#include "ch09_allocator.c"
#undef main

#ifdef __APPLE__
#include <mach/mach.h>
#include <unistd.h>

typedef struct { uintptr_t start, end; } interval;
typedef struct { interval ranges[128]; size_t count, page; bool failed; } regions;
typedef struct {
    size_t peak_payload, max_heap, final_heap, operations, samples;
} measurement;

static void record_regions(task_t task, void *context, unsigned type,
                           vm_range_t *ranges, unsigned count) {
    (void)task;
    regions *r = context;
    if (!(type & (MALLOC_PTR_REGION_RANGE_TYPE | MALLOC_ADMIN_REGION_RANGE_TYPE))) {
        r->failed = true;
        return;
    }
    for (unsigned i = 0; i < count; ++i) {
        uintptr_t start = ranges[i].address;
        size_t bytes = ranges[i].size;
        if (!bytes) continue;
        if (r->count == 128 || bytes > UINTPTR_MAX - start ||
            start + bytes > UINTPTR_MAX - (r->page - 1)) {
            r->failed = true;
            return;
        }
        r->ranges[r->count++] = (interval){start / r->page * r->page,
            (start + bytes + r->page - 1) / r->page * r->page};
    }
}

/* Page union, rather than a sum: admin/data ranges can share boundary pages. */
static size_t region_bytes(malloc_zone_t *zone, size_t page) {
    regions r = {.page = page};
    kern_return_t rc = zone->introspect->enumerator(mach_task_self(), &r,
        MALLOC_PTR_REGION_RANGE_TYPE | MALLOC_ADMIN_REGION_RANGE_TYPE,
        (vm_address_t)zone, NULL, record_regions);
    require(rc == KERN_SUCCESS && !r.failed);
    for (size_t i = 1; i < r.count; ++i) {
        interval v = r.ranges[i]; size_t j = i;
        while (j && r.ranges[j - 1].start > v.start) {
            r.ranges[j] = r.ranges[j - 1]; --j;
        }
        r.ranges[j] = v;
    }
    size_t total = 0;
    uintptr_t end = 0;
    for (size_t i = 0; i < r.count; ++i) {
        interval v = r.ranges[i];
        uintptr_t begin = v.start > end ? v.start : end;
        if (v.end > begin) total += v.end - begin;
        if (v.end > end) end = v.end;
    }
    return total;
}

static void sample(measurement *m, malloc_zone_t *zone, size_t page, size_t payload) {
    size_t h = CAP;
    if (zone) {
        malloc_statistics_t s = {0};
        malloc_zone_statistics(zone, &s);
        h = s.size_allocated;
        /* Fail rather than relabel a platform whose two region accounts differ. */
        require(h == region_bytes(zone, page));
    } else require(check());
    require(h % page == 0 && payload <= h);
    if (payload > m->peak_payload) m->peak_payload = payload;
    if (h > m->max_heap) m->max_heap = h;
    m->final_heap = h;
    ++m->samples;
}

static void measure(unsigned mode, unsigned count, size_t page) {
    void *p[512] = {0};
    size_t lens[512] = {0}, payload = 0;
    measurement m = {0};
    malloc_zone_t *zone = NULL;
    if (mode == 2) {
        zone = malloc_create_zone(0, 0);
        require(zone != NULL && zone->introspect != NULL &&
                zone->introspect->enumerator != NULL);
    } else init(mode == 1, false);
    sample(&m, zone, page, payload);
    for (unsigned i = 0; i < count; ++i) {
        lens[i] = 8u + (13u * i) % 120u;
        p[i] = zone ? malloc_zone_malloc(zone, lens[i]) : toy_malloc(lens[i]);
        require(p[i] != NULL);
        memset(p[i], (int)(i % 251u), lens[i]);
        payload += lens[i]; ++m.operations;
        sample(&m, zone, page, payload);
    }
    /* Free evens then odds, checking every payload byte before each release. */
    for (unsigned parity = 0; parity < 2; ++parity) {
        for (unsigned i = parity; i < count; i += 2) {
            for (size_t j = 0; j < lens[i]; ++j)
                require(((unsigned char *)p[i])[j] == i % 251u);
            if (zone) malloc_zone_free(zone, p[i]); else toy_free(p[i]);
            p[i] = NULL; payload -= lens[i]; ++m.operations;
            sample(&m, zone, page, payload);
        }
    }
    require(payload == 0 && m.max_heap > 0);
    if (zone) malloc_destroy_zone(zone);
    printf("{\"backend\":\"%s\",\"blocks\":%u,\"page_bytes\":%zu,"
           "\"peak_payload\":%zu,\"max_heap\":%zu,\"final_heap\":%zu,"
           "\"operations\":%zu,\"samples\":%zu,\"peak_utilization\":%.9f}\n",
        mode == 0 ? "toy-first" : mode == 1 ? "toy-next" : "libc-private-zone",
        count, page, m.peak_payload, m.max_heap, m.final_heap, m.operations,
        m.samples, (double)m.peak_payload / m.max_heap);
}

int main(void) {
    long raw_page = sysconf(_SC_PAGESIZE);
    require(raw_page > 0 && CAP % (size_t)raw_page == 0 &&
            (uintptr_t)heap.b % (size_t)raw_page == 0);
    for (unsigned count = 64; count <= 512; count *= 8)
        for (unsigned mode = 0; mode < 3; ++mode) measure(mode, count, (size_t)raw_page);
    return 0;
}

# P074 · 规范复查与合并计划

1. 按用户能力审查：定位书籍和原书、复现检查/构建、从干净Git克隆取得完整来源、提交推送。
2. 先保存元数据篡改、书架数量、无时区数据库CLI与来源历史可达性的实际失败。
3. 实施最小修复：纯函数来源检查与回归、书架/canonical文档联动、可注入时刻的构建编号、来源历史合并门禁。
4. 根本地全书检查、Node回归、WSL可用的POSIX发布测试、正式构建、parity/预算/CSP和受影响阅读路径分层验证。
5. 复核暂存差异、敏感信息、忽略输出与来源对象；将SICP快照合并入提交历史，再将工作分支合入main，普通推送并核对远端SHA。

Web经验仅采用E33（2026-10-08：按读者任务检验入口）与E42（2026-09-28：静态接口相同不证明实际路径兼容）的归纳建议；E06（2026-09-22）用于复核现有缓存键/协商边界。不会据此迁移平台或修改未证实有缺陷的缓存实现。
